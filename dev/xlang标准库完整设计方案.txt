当前标准库口径以《xlang第五版增强标准库标准表.txt》和《xlang第五版增强标准库支持覆盖率.txt》为准。

================================================================================
  xlang 完整标准库设计方案
  基于 xrt 库 API + CRT 函数覆盖
  版本 : 1.0
  日期 : 2026-04-13
================================================================================

说明
----

本方案基于以下资料编写 :
  1. xrt 库全部公共头文件 ( D:\git\xrt\lib\*.h )
  2. xlang demo5 已有标准库模块 ( D:\git\x-lang\demo5\src\runtime\ )
  3. CRT 标准函数 ( xrt 未重复实现的部分 )

目标 :
  - 将 xrt 库的所有公共 API 纳入 xlang 标准库
  - 将 CRT 已有但 xrt 未重复实现的关键函数也纳入
  - 使 xlang 成为功能完整的编程语言

本方案仅包含函数签名，标注每个函数的 xlang 名、参数类型、返回类型和底层 xrt/CRT 映射。


设计原则
--------

1. 模块化 : 按功能域划分 std.* 模块，每个模块通过 import std.xxx 引入
2. 命名规则 : xlang 侧使用 snake_case 命名，与语言整体风格一致
3. 类型映射 : xrt C 类型映射到 xlang 类型如下 :
     int64/int    -> int        float/double -> float
     bool         -> bool       const char*  -> string
     xtime        -> time       void*        -> point
     xvalue       -> var        xfunction    -> function
     xparray      -> array      xlist        -> list
     xavltree(set)-> set        xdict        -> dict
     xrand        -> point      xbuffer      -> point
     size_t       -> int        uint32       -> int
4. 返回值约定 : C 侧返回指针 ( str/ptr ) 的函数，xlang 侧返回 string/point
5. 不纳入标准库的 xrt API : 纯内部函数、以 __ 开头的函数、静态函数、inline 工具函数
6. 网络模块 ( xnet/xhttp/xws/xurl ) 暂列为第二阶段扩展，本轮不纳入核心标准库

    w = 星期数       ww = Mon  www = Monday
    q = 季度

================================================================================
设计说明
================================================================================

1. 底层实现方式
   - 优先使用 xrt 库函数作为底层实现
   - xrt 未覆盖的 CRT 函数 ( math.h, stdlib.h, stdio.h, string.h ) 通过 extern native 桥接
   - 某些高级操作 ( 如 array.map/filter/reduce ) 需要函数值支持，依赖 xlang 的 function 类型

2. 类型系统约束
   - 部分函数使用 var 类型，需要 xlang 的 var 动态类型支持
   - point 类型函数需要 xlang 的 point ( 原始指针 ) 类型支持
   - function 类型函数需要 xlang 的 function<Ret(Params)> 类型支持

3. 重载策略
   - xlang 已支持函数重载，同一个函数名可以有多个参数类型版本
   - 标注 "5 种类型重载" 的函数，实际注册 int/float/string/bool/error 五个版本
   - 部分 container 操作 ( len/has/append 等 ) 使用内建方法而非 std 模块函数

4. 模块加载
   - 所有 std.* 模块通过 xl_native_registry 注册
   - 用户使用 `import std.math` 引入
   - std.core / std.io 的 print/println/len 等基础函数建议注册为全局可见

5. 与 demo5 spec 冻结规则的关系
   - 本文档是设计方案，不修改 demo5/spec.md
   - 实际实现时应创建新的 spec phase 文件管理进度
