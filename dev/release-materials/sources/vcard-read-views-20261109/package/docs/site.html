扩展库 / vcard

vcard

常用联系人字段的 vCard 3.0/4.0 读写。

UTF-8、重复字段、转义与按字节折行，结果由调用方独立持有。

2026-10-30：修复先校验 UTF-8 后展开折行的顺序错误，3.0/4.0 的 336 合法、352 非法、224 实际 OOM 与活动内存/独立所有权通过；两平台同一回归旧解析器各 208 条断言失败归零。两实际 C 原型/错改负例、新双语黄金输出及各五份正常 AOT 通过，Linux 包含 ASan/UBSan。API、ABI、XRT 和主线未改，未承诺零性能影响。

API

接口用途
vcard.parse(text)单张 3.0/4.0 名片转字段映射
vcard.build(card)字段映射生成同版本文本

范例

import vcard
var contact = vcard.parse("BEGIN:VCARD\r\nVERSION:3.0\r\nFN:王小明\r\nEND:VCARD\r\n")
string text = vcard.build(contact)
println(contact["fn"])

这是值映射，不保留属性参数、未知字段或原始格式；3.0 允许缺少 N，不能当作完整 RFC 校验器。4.0 要求 VERSION 紧随 BEGIN:VCARD，3.0 仍允许晚置 VERSION。3.0 的 VERSION 不允许参数；4.0 可读 VERSION;VALUE=text:4.0，重新生成时参数不会保留。其他属性的参数也仅校验名称、等号、引号和分隔位置，不映射语义；引号值可包含逗号、分号和冒号。分组 VERSION 不能替代整卡版本；分组 BEGIN/END 也不能作为普通未知字段绕过包络校验。item1.EMAIL 等普通分组字段仍可读取值，但不保留分组名；分组名和属性名只接受 ASCII 字母、数字、连字符，未知合法字段仍可忽略。URL、IMPP、PHOTO、LOGO、GEO 按原始 URI/线值保存；FN、NOTE 等按 TEXT 转义。TEL 按默认 TEXT 处理，VALUE=uri 参数不往返。解析与生成拒绝非法 UTF-8、内嵌 NUL 和非法 ASCII 控制字符；TEXT 内存换行会被转义。生成结果超过 4 MiB 时 C 接口报告 XERR_RANGE，不会截断。C 接口、输入限制与发布验收状态见包内 README。

解析输入超过 4 MiB 时在读取内容前报告 XERR_RANGE；XLang 的 parse/build 对超限抛 RangeError，空输入和格式错误仍属值错误。

包内 folded_contact.xl 与 folded_contact_c.c 展示同功能的折行姓名、分组邮箱、TEXT 备注恢复与规范写回；五条语言/引擎路径检查固定输出和完整字节。默认不写文件，传路径时才保留输出。发送端应保持多字节字符连续；读取端会恢复被折行拆开的有效 UTF-8，展开后仍非法的内容继续拒绝。

当前 Windows 默认 44 项前 43 项符合要求，最后原中央用例在语言字典 build 的 M1 失败；Linux 同样保留红项，独立 JIT/AOT 最小源也先原生写回成功再语言字典失败。下方历史结果和原生对象写回均不替代整包发布验收，未执行的后续旧完整范例阶段不作通过承诺。
