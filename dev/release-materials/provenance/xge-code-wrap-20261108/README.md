# 构建输出行尾重复修复

根因在 XGE CodeEdit，与 Terminal LF/VT 设置无关。折行计算在整行已经放得下时仍退回最后一个分隔符；绘制又未限制到当前视觉行的字节范围，导致行尾在下一行重复。现在仅在溢出时选择断点，并按当前视觉行裁剪文本与语法颜色区间。未折行模式保留原有完整塑形及水平裁剪路径。

原 DLL 的 CPU 专项与真实 IDE 输出窗口均复现失败；新版本通过 942 项字节绘制/几何断言、自动折行专项、共享查找 29 项、终端换行 79 项及 IDE 输入、查找、真实管道输出和本次输出窗口验收。Windows/Linux 的 Cgen、JIT、静态链接及独立运行通过。公开头和 ABI 保持相同，IDE EXE 无需重编；本地 SDK 和两平台动态/静态扩展包已同步。未触碰线上 ver2。

两个旧综合夹具仍失败：xui_code_edit_test 的 find scope result table columns；xui_code_edit_long_line_test 的 insert must update document length。相同测试对修复前后 DLL 的失败输出一致，已保留对照日志；不将其计为通过，也不宣称全仓回归通过。

精确源码、构建输入、截图、历史 SDK 材料保留检查及安装摘要见 receipt.json/evidence.zip。release 继续由 Git 忽略。并发进行的语义及语言服务器开发未纳入本次提交。

同步验收还修复了 XGE 静态构建的跨目录缓存问题：父构建的依赖必须映射到新源码目录并校验当前字节，旧格式缓存不再自动信任。旧缓存错误地复用了修复前的 Linux CodeEdit 对象，造成新专项断言失败；修复工具后实际只重编了 CodeEdit 和配置合同，静态运行复测通过。缓存工具新增回归覆盖源码变更、缺失依赖、系统头变更与跨目录等价复用。
