--------------------------------
二、原生桥接
--------------------------------

2.1 已有状态
- ☑ `sys.loadlib(path)` 已有 parser / sem / cgen / runtime
- ☑ `lib.proc(name)` 已返回 `point`
- ☑ `lib.close()` / `lib.path()` / `lib.loaded()` 已可用
- ☑ `function<...>(lib.proc(...))` 已打通 parser / sem / cgen
- ☑ `function<...>(point)` runtime 可调用桥接已覆盖 int/bool/point、多签名、var 交互与 close-after-proc pin 语义

2.2 定版语义
- `sys.loadlib(string path)` 返回动态库句柄对象
- `lib.proc(string name)` 返回 `point`
- `function<sig>(pointValue)` 构造一个原生桥接函数值
- 该函数值在语言层表现为普通 `function<sig>`
- 该函数值可：
  - 直接调用
  - 赋值给 `function<...>`
  - 赋值给 `var`
  - 作为参数传递
  - 作为返回值传递

2.3 runtime 桥接模型
- 运行时为 `function<sig>(pointValue)` 生成 native thunk
- thunk 内部保存：
  - 原始函数地址
  - 目标签名
  - 调用约定信息
  - 返回值/参数拆装箱策略
- 调用该 thunk 时：
  - 从 xlang 参数解包
  - 转为 native ABI 参数
  - 调用原始地址
  - 将结果重新装箱回 xlang

2.4 第一阶段 ABI 范围
- 平台：Windows x64
- 后端：TCC / GCC 路径都必须支持
- 调用约定：首版按 Windows x64 默认约定
- 首版支持的参数/返回类型：
  - `bool`
  - `int`
  - `int32`
  - `uint32`
  - `int64`
  - `uint64`
  - `float`
  - `float32`
  - `float64`
  - `string`
  - `point`
  - `void`

2.5 第一阶段桥接签名白名单
- `function<int()>`
- `function<int(int)>`
- `function<int(string)>`
- `function<bool()>`
- `function<bool(int)>`
- `function<bool(string)>`
- `function<string()>`
- `function<string(string)>`
- `function<void()>`
- `function<void(int)>`
- `function<void(string)>`
- `function<point()>`
- `function<point(point)>`

2.6 `var` 交互
- 桥接后的原生函数值可赋给 `var`
- `var` 中的桥接函数值可动态调用
- 行为应与普通 `function` 在调用层保持一致

2.7 `lib.close()` 规则
- 首版规则定为：
  - `lib.close()` 只关闭库句柄对象本身
  - 已通过 `lib.proc()` 取得的函数地址会 pin 住底层动态库到进程结束
  - `lib.close()` 后 `lib.loaded()` 返回 `false`
  - `lib.close()` 后该库对象不可继续 `proc()` 新符号
  - `lib.close()` 后已取出的 `point/function<...>` 仍可继续调用
  - 已关闭对象再次 `close()` 返回 `false`
- 该规则优先保证“不 silent crash”，代价是已解析符号所在库首版不会在进程结束前真正卸载

2.8 验收样例
- ☑ `runtime.sys_loadlib_func_basic`
- ☑ `runtime.sys_loadlib_func_var_basic`（由 `sys_loadlib_func_basic` 样例覆盖）
- ☑ `runtime.sys_loadlib_func_multi_sig_basic`
- ☑ `runtime.sys_loadlib_close_after_proc_basic`
- ☑ `runtime.sys_loadlib_close_idempotent_basic`
- ☑ `msvcrt.dll -> atoi`
- ☑ `kernel32.dll -> GetCurrentProcessId` 等同类无参整型返回 API
- ☑ 至少一个 `bool` 返回 API
- ☑ 至少一个 `string/point` 返回 smoke case（当前已验证 `point` 返回）

--------------------------------
三、extern 体系
--------------------------------

3.1 设计目标
- 让 `extern` 成为语言层正式 native 互操作入口
- 与 `#link / #libpath / #incpath / #loadlib` 协同
- 与 `sys.loadlib()` 动态桥接形成互补

3.2 extern func
- 语法：
  - `extern func foo(...) as int`
  - `extern "symbol" func foo(...) as int`
- 首版仅允许模块级声明
- 按 native ABI 解析
- 可用于直接绑定已知外部符号

3.3 extern var
- 语法：
  - `extern var errno as int`
  - `extern "symbol" var errno as int`
- 首版仅允许模块级声明
- 首版支持：
  - 读取
  - 写入
  - 基础标量类型
  - `point`
- 是否支持 `string` / class ABI，首版可暂缓到第二批
- update 2026-04-21: 已新增 `extern var ... as point` 的 DLL data symbol 回归，覆盖读取、写入 `null`、写入函数返回 `point`、恢复原值；Windows/TCC 下非 CRT data symbol 使用 `XL_EXTERN_VAR` / `__declspec(dllimport)` 声明，CRT `_fmode` 保持普通 `extern` 以避免内置导入符号冲突。

3.4 extern type
- 语法：
  - `extern type DWORD = uint32`
  - `extern type HANDLE = point`
- 首版语义：
  - native 类型别名
  - 作为 ABI 对齐与可读性增强入口
- #binding 已补齐常见 C struct / typedef / enum 导入，并可生成 plain class 参与 extern func / extern var ABI；完整复杂 C 头文件零人工绑定仍后置

3.5 与指令系统的关系
- `#link`
- `#libpath`
- `#incpath`
- `#loadlib`

这些指令在本阶段视为已定版基础设施，需与 extern / runtime 桥接统一协作。

3.6 extern 阶段目标
- ☑ `extern func` 首版已可用
- ☑ `extern type` 首版 alias 已可用（基础类型、point、container generic、function signature alias 已覆盖）
- ☑ `extern var` 完整可用（已覆盖 int CRT data symbol 与 point DLL data symbol 的读写）
- ☑ extern 与 runtime 桥接统一验收（当前已覆盖 `int / bool / point` 返回与 close-after-proc）
- ☑ 旧 `extern atoi` 回归已升级为标准 `#loadlib "msvcrt.dll" + extern func` 写法，避免裸 extern 隐式依赖宿主符号表

--------------------------------
四、class 第一阶段
--------------------------------

4.1 定位
- `class` 第一阶段是“增强结构体模型”
- 编译期确定布局
- 默认值语义
- 支持字段、方法、构造、析构、运算符重载、单继承、内嵌 union
- plain class 默认不做虚表和运行时类对象
- object/custom 的动态派发已由对象系统主线完成，不改变 plain class 的值语义定位

4.2 语法定版
```xl
class Name extends Base
    union Data
        // 共用体成员
    end

    create(param)
        // 构造
    end

    destroy()
        // 析构
    end

    // 字段 / 方法 / 运算符重载
end
```

4.3 extends
- 使用 `extends` 表示继承
- 不使用 `:`
- 首版只支持单继承
- 未写 `extends` 则无基类
- `extends object` 已作为进入 object 引用语义和动态派发体系的明确入口

4.4 union
- `union` 只允许出现在 `class` 内部
- `union` 成员共享同一段内存
- `union Name` 的名字用于语义标识和调试
- 首版不单独形成独立类型系统
- 成员默认直接并入当前 class 成员域访问

示例：
```xl
class Value
    var kind as int

    union Data
        var i as int
        var f as float
        var p as point
    end
end
```

访问：
```xl
v.i = 1
v.f = 3.14
```

4.5 字段布局
- 字段声明顺序即布局顺序
- 基类子对象布局在最前面
- `union` 占用其最大成员大小
- 不做字段重排
- 不注入隐藏 vtable 指针
- 第一阶段要求布局可稳定映射 native ABI

4.6 对象语义
- 默认值语义
- 赋值为整体复制
- 传参默认复制
- 返回值默认复制
- 首版不做隐式堆分配

4.7 create
- `create(...)` 为构造函数固定名
- 支持重载
- 支持默认参数
- `TypeName(...)` 绑定到 `create(...)`
- 若类中未声明任何 `create`，编译器生成默认零值构造
- 若类中声明了任意 `create`，则不再自动生成默认构造

4.8 destroy
- `destroy()` 为析构函数固定名
- 不可重载
- 不带参数
- 局部对象离开作用域自动调用
- 成员对象自动逆序析构
- 继承下先析构子类，再析构基类

4.9 方法
- 类方法内允许使用隐式 `self`
- `obj.method(...)` 本质 lower 为对应静态方法调用
- 首版不做虚派发
- 子类同签名方法可静态覆盖父类方法

4.10 运算符重载
- 首版只支持固定函数名映射
- 建议映射：
  - `+` -> `op_add`
  - `-` -> `op_sub`
  - `*` -> `op_mul`
  - `/` -> `op_div`
  - `%` -> `op_mod`
  - `**` -> `op_pow`
  - `==` -> `op_eq`
  - `!=` -> `op_ne`
  - `<` -> `op_lt`
  - `<=` -> `op_le`
  - `>` -> `op_gt`
  - `>=` -> `op_ge`
  - 一元 `-` -> `op_neg`
  - `[]` -> `op_index`
  - `[]=` -> `op_index_set`
  - `()` -> `op_call`
  - 文本化 -> `op_string`

4.11 继承规则
- 单继承
- 子类继承基类字段与方法
- 构造顺序：
  - 先基类
  - 再本类
- 析构顺序：
  - 先本类
  - 再基类
- plain class 继承保持静态分发；object/custom 基类引用指向子类后的动态派发已由对象系统主线完成

4.12 与 `var`
- ☑ 首版允许 `var` 持有 class 值
- 首版保证：
  - ☑ 可存储
  - ☑ 可赋值
  - ☑ 可传参
  - ☑ 可返回
- ☑ 初始化时静态可知的 `var = Class(...)` 会在同步作用域退出前调用 class `destroy()`
- ☑ 初始化时静态可知的 `var = [Class(...)]` / `var = array<SomeClass>` 局部容器会在同步作用域退出前逐元素调用 class `destroy()`
- ☑ `var` 上 plain class 方法、索引、运算符 dispatch 已有回归覆盖
- ☑ object/custom runtime 对象方法系统已由对象系统主线完成首版

4.13 与容器
- ☑ 允许 class 值进入 `array/list/dict/set`
- ☑ 容器中的 class 值按值存储
- ☑ class 值写入容器时 copy hook 已覆盖
- ☑ array/list/set/dict 替换、remove、clear 和作用域退出时的 class destroy hook 已覆盖

- ☑ 成员对象构造/析构链（普通 class 字段零参构造链与析构链已可用：`create` 入口先构造成员，再执行字段默认初始化表达式，用户 `destroy()` 后逆序析构成员 class 字段；union 布局、标量成员读写、方法内访问与共享内存语义已有 sem/cgen/runtime 回归；union 内 class 成员首版按原始共用体处理，不自动构造/析构重叠 class 成员，避免无活跃成员追踪时重复析构；显式 union active tag 语义待后续对象模型阶段设计，不计入本阶段阻塞项）
- ☑ 基类构造/析构链（零参基类构造链与基类析构链已可用：`create` 入口先构造 base view 并回填前缀字段；子类 `destroy()` 与成员析构后，按前缀布局拷贝 base view 并调用基类 `destroy()`；子类 `create` 内 `base(args...)` 显式带参基类构造已可用）
- ☑ union 布局 codegen（已覆盖 union C 布局、标量成员读写、方法访问、共享内存行为，以及 union 内 class 成员不自动析构的生命周期边界）
- ☑ 运算符重载 lowering / cgen / runtime（二元 class 运算符、一元 `op_neg`、`op_index/op_index_set/op_call` 已 lowering 为绑定函数调用并通过 runtime 用例）

5.4 runtime
