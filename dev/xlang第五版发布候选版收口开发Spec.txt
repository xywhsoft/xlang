xlang 第五版发布候选版收口开发 Spec

说明
- [x] 已实现并通过验证
- [~] 已部分实现，或主链路已通但仍需发布级收口
- [ ] 尚未实现

目标
- 将 demo5 从验证版推进为 xlang 发布候选版。
- demo5 必须验证正式 xlang 的全链路设想：语言核心、标准库、C 混编、模块/package/xle、诊断、class 第一阶段。
- 本 spec 只收口高价值、低扩散的发布候选能力；暂缓项不重新拉回实验期。

总原则
- 优先完成能显著改善开发体验、工程化能力、性能和发布稳定性的任务。
- 不引入 namespace/using、语言级 include、宏系统、channel select 等仍暂缓项。
- runtime dynamic class、GC、虚表/动态派发、new/delete 已在对象系统主线完成首版落地，不再作为本 spec 的未实现阻塞项。
- 每个大项完成后必须补齐 parser / sem / lower / cgen / runtime 覆盖测试中适用的层级。
- 文档状态以本 spec、xlang第五版语言标准支持覆盖率.txt、xlang第五版原生桥接、extern与class第一阶段开发Spec.txt 为准。

1. 泛型静态单态化

1.1 目标
- [x] 将当前基于 var 擦除的泛型函数升级为静态单态化泛型。
- [x] 每个实际类型组合生成独立函数实例。
- [x] 调用点调用具体实例，不再通过 xvalue/var 泛型返回包装完成类型恢复。
- [x] 生成稳定 ABI 符号名，服务 package/xle/调试/缓存。

1.2 定版语法与语义
- [x] 支持泛型函数：`func id<T>(T value) as T ... end`
- [x] 支持多个类型参数：`func pair<T, U>(T a, U b) as ...`
- [x] 支持显式调用类型参数：`id<int>(123)`
- [x] 支持自动类型推导：`id(123)` 推导为 `id<int>`
- [x] 支持泛型类型方法：`func list<T>.first(list<T> self) as T`
- [x] 泛型实例 ABI 名按完整类型签名稳定生成，不能使用临时编号作为 ABI。

1.3 类型推导范围
- [x] 直接占位符推导：`T`
- [x] 嵌套泛型推导：`array<T>` / `list<T>` / `set<T>` / `dict<T>`，并覆盖 `array<array<T>>`。
- [x] function 类型推导：`function<T(int)>`、`function<int(T)>`
- [x] 多参数一致性检查：`func same<T>(T a, T b)` 中 `T` 必须一致。
- [x] 返回类型替换：`array<T>`、`list<T>`、`dict<T>` 等返回类型按实例替换。
- [x] 无法推导时允许显式类型参数补足，例如 `zero<int>()`。

1.4 实现任务
- [x] 建立语义层泛型类型树/替换模型，不能只依赖字符串相等。当前使用通用泛型类型 splitter + 递归实参绑定模型。
- [x] 建立泛型函数原型表，保存原始 AST、类型参数、参数类型、返回类型。
- [x] 建立泛型实例表，按 `原型 + 类型实参` 缓存实例。
- [x] 调用解析阶段完成类型推导和实例选择。
- [x] 实例化时在具体类型环境下重新检查函数体。当前已覆盖实例返回值、局部声明、赋值、二元/一元/三元表达式、调用参数复查、嵌套索引链。
- [x] Lower/MIR 为每个泛型实例生成独立函数。
- [x] C codegen 输出静态 C 函数签名。
- [x] 调用点改为调用具体实例 ABI。
- [x] 保留 var fallback 仅用于明确 var 类型路径，不作为泛型主实现。

3. module / package / xle 工程化闭环

3.1 目标
- [x] 让 xlang 可以表达真实项目结构。
- [x] `xl5 build` 能基于项目入口构建应用或包。
- [x] package/xle 的元信息、导出、版本、搜索路径形成稳定首版。

3.2 项目文件
- [x] 引入 `xlang.json` 作为项目/包描述文件。
- [x] 当前不引入 TOML。
- [x] `xlang.json` 允许描述 app/package 两类项目。

3.3 建议 app 配置
```json
{
  "name": "hello",
  "version": "0.1.0",
  "type": "app",
  "main": "src/main.xl",
  "source": ["src"],
  "links": ["shell32"],
  "libpath": ["lib"],
  "incpath": ["include"]
}
```

3.4 建议 package 配置
```json
{
  "name": "pkg.math",
  "version": "0.1.0",
  "type": "package",
  "source": ["src"],
  "exports": ["math"]
}
```

3.5 模块映射规则
- [x] `import foo.bar` 映射到 `foo/bar.xl`。
- [x] 当前文件所在目录优先用于相对模块。
- [x] 项目 `source` 路径参与搜索。
- [x] import 包搜索路径统一收紧为两类 `libs` 包根：程序目录 `AppPath\libs`，以及脚本/项目目录 `ScriptPath\libs`。
- [x] `packages`、`libs\packages`、`XLANG_PACKAGE_PATH`、`XLANG_HOME`、用户目录 `.xlang` 与父目录递归探测均不再参与 import 包搜索。
- [x] `std.*` 固定优先内置标准库，不允许用户包覆盖。
- [x] 字符串 import 保留路径直连能力：`import "local/file.xl"`。

5. C 混编体验打磨

5.1 目标
- [x] 让 C ABI 互操作从“能跑”进入“好用”。
- [x] 提升 #link / extern / 动态库加载的稳定性和诊断。

5.2 定版规则
- [x] `#link shell32` 允许自动补平台扩展名。
- [x] Windows 下 `shell32` 可解析到 shell32/lib/dll 相关策略。
- [x] Linux 下 `foo` 可解析为 `-lfoo` / `libfoo.so` 相关策略。
- [x] TCC 默认根目录固定为程序目录下的 `tcc` 子目录，即 `AppPath\tcc`。
- [x] TCC 默认 include/lib 路径只来自 `AppPath\tcc` 下的固定子目录；额外路径只来自 `#incpath`、`#libpath`、`xlang.json` 的 `incpath` / `libpath`，以及 XLE 元信息显式注册的 native artifact。
- [x] extern 失败只输出明确原因，不额外提供建议。

5.3 动态库 API 命名
- [x] 标准 API 定为 `sys.dlopen`
- [x] 标准 API 定为 `sys.dlsym`
- [x] 标准 API 定为 `sys.dlclose`
- [x] 旧 `sys.loadlib/getproc` 如已存在，可作为阶段性兼容别名，后续降级或移除。

5.4 示例
```xl
auto lib = sys.dlopen("shell32")
auto fn = sys.dlsym<function<int(point, string, string, string, string, int)>>(lib, "ShellExecuteA")
fn(null, "open", "notepad.exe", "", "", 1)
sys.dlclose(lib)
```

5.5 暂不纳入
- [~] 从 .h 自动生成 binding：首版支持 `#binding "header.h"`，可从简单 C 函数原型和 `extern` 全局变量生成 xlang `extern func/var`；支持当前文件相对路径、`#incpath` 与 `xlang.json` 的 `incpath` 搜索；支持找不到 header 时输出明确 binding error 并中止编译；支持 binding header 内递归 `#include "file.h"` / `#include <file.h>`，并复用同一 typedef/const/type 上下文，避免父 header 无法识别子 header 类型；支持 C++ 头文件常见的 `extern "C"` 单声明与 `extern "C" { ... }` 包裹块清洗；支持轻量条件编译与 include guard（`#if 0/1`、`#ifdef`、`#ifndef`、`#elif`、`#else`、`#endif`、`defined(NAME)`、空宏登记、`#undef`、未知宏按 0、比较/逻辑表达式）；支持 `#pragma` 安全忽略、active `#warning` 非致命跳过、active `#error` 转为 binding error 并中止编译，inactive `#error` 被条件编译跳过；支持简单 typedef 别名、typedef 多别名/指针别名展开（如 `typedef int A, *PA;`）、函数指针 typedef 到 `function<...>` 的类型映射、单行与多行 `typedef struct { ... } Name;` -> xlang class 映射；支持 `struct Name { ... };` 映射；支持 `struct Foo;` 前置声明作为 opaque `point`，支持 `enum Foo;` 前置声明作为 `int`；支持 struct 字段中的简单多 declarator 展开（如 `int x, y;`、`const char *name, *label;`）；支持 struct 字段中的单个函数指针 declarator 映射为 `function<...>` 字段（如 `int (*cb)(int, const char*)`、`void (CALLBACK *done)(void)`）；支持 `typedef struct Tag { ... } Alias;` 的 tag/alias 类型映射；支持 `typedef struct Foo Foo;` 这类 opaque struct 前置声明映射为 `point`，用于 `Foo*` handle API；支持 `typedef enum` 与普通 `enum` 常量导入为 xlang `const int`，enum 类型在函数签名中映射为 `int`；支持多行函数原型合并；支持反斜杠续行的多行 `#define` 拼接；支持简单对象式 `#define` 常量导入为 xlang `const`；支持整数表达式宏求值（`+ - * / % << >> & | ^ ~ ! == != < <= > >= && ||`、括号、字符常量、C cast、前序宏/enum 常量引用、`NULL`/`TRUE`/`FALSE`）；支持函数式 int 表达式宏生成 xlang `func`（参数和返回值固定为 `int`，覆盖算术/位运算/比较/逻辑/单层三元 `?:`/前序常量引用、`NULL`/`TRUE`/`FALSE`，并将 C `!expr` 按整数语义转换为 `expr == 0`；三元条件需是比较/逻辑表达式，不承诺 C 裸 int 条件语义）；支持 C 行注释与块注释清洗，且不会误删字符串/字符字面量中的 `//` 或 `/* */`；支持常见调用约定/声明修饰词/参数注解清洗（`__cdecl`、`__stdcall`、`__fastcall`、`WINAPI`、`CALLBACK`、`APIENTRY`、`PASCAL`、`NTAPI`、`inline`、`restrict`、`__declspec(...)`、`__attribute__((...))`、`DECLSPEC_IMPORT`、`DECLSPEC_EXPORT`、`_In_`/`_Out_` 等 SAL 注解）；支持常见 C/Windows 类型别名兜底映射（如 `DWORD`/`UINT`、`WORD`/`BYTE`、`HANDLE`/`HWND`、`PCSTR`/`LPCSTR`）；支持 `XL_BINDING_TRACE=1` 输出 binding 导入统计与跳过原因；native callback ABI 调用、完整 C 预处理表达式、复杂函数式宏、bitfield/inline array 字段、复杂嵌套 struct 后续扩展。
- [x] `#binding` opaque union 安全首版：支持 `union Foo;` 前置声明和 `typedef union Foo Foo;` 映射为 `point`，可用于 `Foo*` handle API；完整 C union layout / active member 语义仍后续扩展。
- [x] `#binding` 无名多词参数兼容：支持 `unsigned int`、`signed char`、`unsigned long long` 等省略参数名的 C 原型，不再把末尾基础类型词误删为参数名。
- [x] `#binding` 函数参数数组退化：支持 C 原型参数中的 `T name[N]` / `T name[]` 按 C ABI 衰减为指针形态导入；`char[]`/`unsigned char[]` 映射为 `string`，其它数组参数映射为 `point`；struct 字段 inline array 仍暂缓。
- [x] `#binding` 指针宽度整数别名：支持 `intptr_t` / `uintptr_t` / `ptrdiff_t` / `SSIZE_T` / `INT_PTR` / `UINT_PTR` / `DWORD_PTR` 等常见 C/Windows 头文件别名映射到 `int64` / `uint64`。
- [x] `#binding` typedef struct 多 alias：支持 `typedef struct Tag { ... } Name, *PName;`，第一个非指针 alias 生成 xlang class，`*PName` 等指针 alias 映射为 `point`，可用于后续函数签名。
- [x] `#binding` typedef struct/union 多 value alias：支持 `typedef struct Tag { ... } A, B, *PB;` 中后续非指针 alias `B` 映射为 `A` 的 xlang 类型别名；`typedef union ... A, B, *PB;` 中所有 value/pointer alias 均安全映射为 opaque `point`。
- [x] `#binding` typedef enum 多 alias：支持 `typedef enum Tag { ... } A, B, *PB;` 中多个 enum value alias 映射为 `int`，enum pointer alias 映射为 `point`，可用于后续 C 函数原型导入。
- [x] `#binding` 类型限定符位置兼容：支持 `char const *`、`unsigned int const`、`volatile DWORD` 等前置/中置/后置 `const` / `volatile` 类型写法，按 ABI 等价基础类型导入。
- [x] `#binding` opaque typedef 后续完整定义升级：支持 `typedef struct Tag Alias;` 先作为 `point` 前置可用，后续遇到 `struct Tag { ... };` 时自动将 `Alias` 升级为生成的 plain class，可参与按值 extern func ABI。
- [x] `#binding` 嵌套 plain struct 字段：支持已定义 `struct Inner` 作为后续 `struct Outer { struct Inner inner; ... }` 字段类型导入，并可参与按值 extern func ABI。
- [x] `#binding` sizeof 宏常量求值：支持对象式与函数式宏中的 `sizeof(基础 C 类型/指针类型)` 预折叠，覆盖 `sizeof(int)`、`sizeof(void*)`、`sizeof(char const *)` 等常见 SDK 宏写法。
- [x] `#binding` 函数式宏三元整数条件兼容：支持 `((x) ? a : b)` 这类 C 裸 int 条件三元宏，导入时转换为 xlang 可类型检查的 `(x != 0) ? a : b`；已有比较/逻辑条件保持原样。
- [x] `#binding` 对象式宏三元常量求值：支持 `#define X (COND ? A : B)` 这类 C 整数常量表达式，条件按非 0 为真求值，可复用前序宏/enum 常量和 `sizeof(...)` 结果。
- [x] `#binding` struct unsupported layout 安全降级：遇到 bitfield 或 inline array 字段时不再生成缺字段 class，改将该 struct/typedef 映射为 opaque `point`，保证 handle/pointer API 可用但不承诺按值布局 ABI。
- [x] `#binding` typedef union layout 安全导入：遇到 `typedef union Tag { ... } Alias, *PAlias;` 时不解析 union 字段布局，统一映射为 opaque `point`，保证 value alias / pointer alias / `union Tag` 可用于 handle API；完整 C union ABI 仍后置。
- [x] `#binding` named union layout 安全导入：遇到 `union Name { ... };` 时不解析 union 字段布局，导入 `Name` / `union Name` 为 opaque `point`，避免后续 handle API 因类型未知被跳过。
- [x] `#binding` 字符串宏兼容增强：支持对象式 `#define` 中的括号包裹字符串、相邻 C 字符串字面量拼接，以及 `u8"..."` / `L"..."` / `u"..."` / `U"..."` 前缀字符串按 xlang `string` 常量导入。
- [x] `#binding` 字符串宏别名：支持 `#define B A` 且 `A` 是前序 string define 时导入为 xlang `const string B = A`，覆盖 SDK/项目头文件中的字符串常量别名。
- [x] `#binding` 浮点宏别名：支持 `#define B A` 且 `A` 是前序 float define 时导入为 xlang `const float64 B = A`，覆盖 SDK/项目头文件中的浮点常量别名链。
- [x] `#binding` 整数宏别名：支持 `#define B A` 且 `A` 是前序 int/uint define 时导入为 xlang `const int/uint64 B = A`，覆盖 SDK/项目头文件中的整数常量别名链；`NULL`/`TRUE`/`FALSE` 仍折叠为数字常量。
- [x] `#binding` 指针空值宏：支持 `#define X ((void*)0)`、`#define X ((HANDLE)NULL)`、`#define X ((LPVOID)0)` 这类明确 cast 为 pointer/handle 且值为 0/NULL 的对象式宏导入为 xlang `const point X = point(null)`；非空哨兵指针仍不自动承诺。
- [x] `#binding` 字符常量宏兼容增强：支持对象式 `#define` 和整数常量表达式中的常见 C 转义字符（如 `'\n'`、`'\x2a'`、`'\052'`），导入时统一折叠为 xlang `int` 常量。
- [x] `#binding` 带前缀字符常量宏兼容：支持 `L'...'` / `u'...'` / `U'...'` / `u8'...'` 字符常量及其在整数常量表达式中的使用，按首版单字符整数语义导入。
- [x] `#binding` 数值宏兼容增强：支持对象式 `#define` 和整数常量表达式中的二进制整数 `0b...` / `0B...`，以及数字分隔符 `'`，导入时统一折叠为十进制 xlang 常量。
- [x] `#binding` 八进制数值宏兼容：支持对象式 `#define` 和整数常量表达式中的 C 八进制整数字面量（如 `052`、`040 | 012`），导入时统一折叠为十进制 xlang 常量。
- [x] `#binding` char 指针层级 ABI 修正：单层 `char*` / `const char*` 仍映射为 `string`，二级及以上 `char**` / `const char**` 等输出参数或字符串数组统一映射为 opaque `point`，避免误当普通字符串传递。
- [x] `#binding` typedef 多 declarator 指针归属修正：支持 `typedef int *P, I;` 这类 C 声明中 `*` 只绑定当前 declarator，避免后续 alias 被误解析为指针类型；与 struct 字段多 declarator 语义保持一致。
- [x] `#binding` Windows SAL 注解增强清理：支持 `_In_range_(...)`、`_In_reads_(...)`、`_Out_writes_(...)`、`_Outptr_result_maybenull_` 等常见带参/扩展 SAL 注解按 ABI 无关信息移除，提升 Windows SDK 头文件导入兼容性。
- [x] `#binding` 声明修饰宏清理：支持 `#define API __declspec(dllexport)`、`#define API extern`、`#define API` 后续用于 `API int foo(...)` 这类函数/变量声明前缀时按 ABI 无关修饰清除；也支持 `#define API2 API` 这类声明修饰宏别名链，提升 SDK/项目导出宏兼容性。
- [x] `#binding` 函数式宏 typedef 整数 cast：支持 `typedef int MYINT; #define F(x) ((MYINT)(x))` 这类 SDK/项目头文件常见写法，导入函数式 int 宏时按 binding 类型表识别并剥离整数/布尔 C cast；指针/string/class cast 不自动剥离。
- [x] `#binding` 零参数函数式宏：支持 `#define FOO() 42` 这类无参数 C 函数式宏导入为 xlang `func FOO() as int`。
- [x] extern async func：支持 `extern "symbol" async func f(...) as T`，语义返回 `future<T>`，运行时由 native 返回值包装为 ready future。
- [x] 类型方法形式 extern：支持 `extern func int.name(int self) as int` 与 `extern "c_symbol" func int.name(int self) as int`，方法名与 C 符号名分离。
- [~] class ABI 直通：plain class / plain struct ABI 已支持 extern func 按值传参、按值返回、extern var data symbol、#binding struct 导入和 sys.dlsym plain class 动态 ABI；非常规对齐、显式 pack/alignment、带 destroy/union active tag/非平凡生命周期的跨 C ABI 仍后置。

7. extern var string / class ABI

7.1 价值
- [x] 增强 C 全局变量互操作。

7.2 建议时机
- [x] string ABI 首版已稳定为 `const char*` 数据符号互操作。

7.3 范围
- [x] `extern var name as string`
- [x] `extern var name as bool` / `extern var name as float64`
- [x] `extern var name as int32` / `extern var name as uint64` 等精确数值类型 data symbol 读写。
- [x] class/struct data symbol 映射：首版支持 plain class 与 C struct 同布局的全局数据符号读写。
- [x] 读写规则：按 C ABI 指针值读写，xlang 读取得到 string，赋值会把 `const char*` 指针写回数据符号。

9. 更完整 native function signature thunk

9.1 价值
- [x] 减少 extern/sys.dlsym 限制，让 C 生态接入更自然。

9.2 范围

- [x] return/assign 支持 move。
- [x] 容器字面量 / append / index assign 支持 move，容器内 boxed class 成员访问可正确解包。
