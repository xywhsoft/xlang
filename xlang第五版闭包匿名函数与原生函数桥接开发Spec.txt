xlang 第五版闭包、匿名函数与原生函数桥接开发 Spec

说明
- `☑` 已实现并通过 parser / sem / cgen / runtime 验证
- `◐` 已部分实现，或主链路已通但仍有收尾项
- `☐` 尚未实现

目标
- 一次性做完整匿名函数 + 闭包能力
- 打通 `function / var / auto / async / generator` 与闭包模型
- 打通 `sys.loadlib() / lib.proc() / function<...>` 原生函数桥接

一、当前总体状态
- ☑ 匿名函数基础能力已完成
- ☑ 闭包基础能力已完成
- ☑ 多返回值函数值主链路已完成
- ☑ 匿名函数进入 `array / dict / var` 并动态调用已完成
- ☑ 多行容器字面量中放置匿名函数已可用
- ◐ `point -> function<...>` 的 parser / sem / cgen 已完成，runtime ABI 桥接未完成
- ◐ parser 为支持多行容器字面量做了扩展，但 Lemon conflict 从 `28` 升到 `103`，功能可用，语法冲突仍需整理

二、已完成能力

2.1 匿名函数
- ☑ `func(...) as Ret ... end`
- ☑ `func(...) as Ret => expr`
- ☑ 匿名函数赋值给 `auto`
- ☑ 匿名函数赋值给 `function<...>`
- ☑ 匿名函数赋值给 `var`
- ☑ 匿名函数作为参数传递
- ☑ 匿名函数作为返回值传递
- ☑ 匿名函数放入 `array`
- ☑ 匿名函数放入 `dict`
- ☑ 从容器取出匿名函数后调用
- ☑ 匿名函数通过 `var` 动态调用

2.2 闭包
- ☑ 捕获外层局部变量
- ☑ 捕获外层参数
- ☑ 闭包共享同一个 captured cell
- ☑ 外层返回后闭包继续存活
- ☑ 闭包修改 captured 值
- ☑ 嵌套闭包共享状态
- ☑ 闭包进入容器并经 `var` 调用

2.3 多返回值函数值
- ☑ 匿名函数 `as int, string`
- ☑ 匿名函数 `return a, b`
- ☑ `auto a, b = fn()`
- ☑ `auto a, _ = fn()`
- ☑ `function<int,string()>` 显式函数值类型
- ☑ 多返回值函数值作为参数传递
- ☑ 多返回值函数值作为返回值传递
- ☑ 多返回值函数值存入 `var` 后动态调用

2.4 generator / async generator 与闭包
- ☑ generator 闭包捕获
- ☑ generator `resume(value)` 与 closure cell 协同
- ☑ async generator 闭包捕获
- ☑ async generator `resume(value)` 与 closure cell 协同

五、当前结论
- 闭包与匿名函数主线已经基本完成，可以认为“语言能力主链路已通”
- 当前最大未完成块，不在匿名函数/闭包，而在“原生函数 runtime ABI 桥接”
- 如果下一步继续开发，优先级建议：
  1. `point -> function<...>` runtime 桥接
  2. 原生桥接样例与回归
  3. parser conflict 回收
  4. 文档总表同步
