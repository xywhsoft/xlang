xlang demo5 发布目录、libs 与 TCC 路径规范

一、目标

demo5 的 release 目录作为正式发布目录使用。
xl.exe / xldbg.exe 应该可以在任意机器、任意位置直接运行，不依赖仓库源码树的相对路径推导。

二、发布目录标准布局

最小推荐布局：

release/
    xl.exe
    xldbg.exe
    xl5_test.exe
    xlang.dll
    tcc/
    libs/
    cgen/
    dump/
    tmp/
    trace/

说明：

1. xl.exe、xldbg.exe 所在目录本身就是 AppPath。
2. TCC 固定定位到：
   AppPath\\tcc
3. 运行时自动输出目录固定定位到：
   AppPath\\cgen
   AppPath\\dump
   AppPath\\tmp
   AppPath\\trace

三、import 搜索规则

import 只使用两类 libs 目录作为包根：

1. 程序公共 libs
   AppPath\\libs

2. 脚本/项目私有 libs
   ScriptPath\\libs

ScriptPath 的含义：

1. 直接运行 .xl 文件时，ScriptPath 是该脚本文件所在目录。
2. 通过 xlang.json 运行项目时，ScriptPath 是 xlang.json 所在的项目目录。

不再参与 import 包搜索的路径：

1. packages
2. libs\\packages
3. lib\\xlang\\packages
4. XLANG_PACKAGE_PATH
5. XLANG_HOME
6. 用户目录 .xlang
7. 沿父目录递归探测出的 packages / libs\\packages

四、推荐包布局

1. 纯 XLE 源包

libs/
    pkg.math/
        package.json
        src/
            math_pkg_impl.xl

2. native shared 包

libs/
    pkg.probe/
        package.json
        bin/
            pkg_probe.dll

3. native static 包

libs/
    pkg.clock/
        package.json
        lib/
            pkg_clock.a

脚本直接导入：

import pkg.math

五、TCC include / lib 搜索规则

TCC 编译链路不从 libs 推导 include / lib 目录。
它只使用程序目录下 tcc 子目录的固定路径，以及编译指令或项目文件显式注册的路径。

默认 TCC 根目录：

AppPath\\tcc

默认 include 路径：

AppPath\\tcc\\include_win
AppPath\\tcc\\include_win\\winapi
AppPath\\tcc\\support\\common
AppPath\\tcc\\support\\runtime
AppPath\\tcc\\include

默认 lib 路径：

AppPath\\tcc\\lib

额外 include 路径只能来自：

1. 源码中的 #incpath
2. xlang.json 中的 incpath
3. XLE 包元信息中显式注册的 C 源/头文件编译输入

额外 lib 路径只能来自：

1. 源码中的 #libpath
2. xlang.json 中的 libpath
3. XLE 包元信息中显式注册的 static/native artifact

相对路径解释规则：

1. #incpath / #libpath 的相对路径按声明该指令的模块文件目录解释。
2. xlang.json 的 incpath / libpath 相对路径按 xlang.json 所在项目目录解释。
3. TCC 默认路径始终按 AppPath\\tcc 解释。

六、建议

1. 发布包自带的 XLE 依赖放 AppPath\\libs。
2. 项目局部 XLE 依赖放 ScriptPath\\libs。
3. native 头文件和库文件不要放进 libs 后期待 TCC 自动扫描；需要使用 AppPath\\tcc 的固定布局，或通过 #incpath / #libpath / xlang.json 注册。
4. 不建议把用户包散放到 tcc 目录中；tcc 目录只承载 TCC toolchain 与其固定 include/lib/support 文件。
