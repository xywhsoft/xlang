扩展库 / zip

zip

创建、读取和修改 ZIP/ZIP64 归档，支持内存与文件入口、二进制条目和资源限制。

版本 1.0.0 · C / xlang · 依赖 _libzip

快速开始

import zip

zip.ZipArchive writer = zip.create()
writer.add("hello.txt", "你好")
Buffer packed = writer.finish()

zip.ZipArchive reader = zip.open(packed)
println(reader.readText("hello.txt"))
reader.close()

输出 你好。二进制数据使用 add(name, Buffer) 与 read(name) as Buffer；不要将二进制内容交给 readText。

接口

入口用途
create / open(Buffer) / open(path, mode)创建内存归档，或打开内存/文件归档；文件模式为 r、w、a、x。
ZipArchive.add / addFile / mkdir加入文本、Buffer、磁盘文件或目录条目。
contains / names / info / read / readText查找、读取条目与元数据；ZipInfo 可显式声明。
remove / rename / setComment / setEntryComment修改归档内容或注释。
extractAll(destination, overwrite = false)检查归档路径、已有链接与输出限额后解压；目标目录须由应用控制。
close / finish关闭归档；内存归档使用 finish() 取走独立 Buffer。

工厂限额要求为正；条目数、大小、压缩比和输出量由 XRT ZIP 后端约束。条目名、文件路径、注释与解压目标拒绝内嵌 NUL；归档条目内容仍允许任意二进制字节。解压会拒绝目标目录已有父级、根目录和下级中已存在的链接，但尚不能抵御其他进程并发替换目录；不要把不可信或可并发修改的目标目录当作安全沙箱。

C 对照

#include "xrt_zip.h"

int main(void)
{
    xrtziparchive* archive = xrtZipArchiveCreate(NULL);
    if (archive == NULL) return 1;
    const char text[] = "hello";
    if (!xrtZipArchiveAdd(archive, "hello.txt", text, sizeof(text) - 1u,
        false, XRT_ZIP_METHOD_DEFAULT, -1) || !xrtZipArchiveClose(archive)) {
        xrtZipArchiveDestroy(archive);
        return 2;
    }
    xbuffer* packed = xrtZipArchiveTakeBuffer(archive);
    xrtZipArchiveDestroy(archive);
    if (packed == NULL) return 3;
    xrtBufferDestroy(packed);
    return 0;
}

公共头为 extlibs/zip/include/xrt_zip.h。C 选项用 xrtZipOptionsInit 初始化；ZIP 只执行输入、输出、单项、条目数及压缩倍率限额，节点数、深度、资源标志和保留字段必须为零，尺寸/版本必须匹配。完整双语对照范例位于 examples/extlibs/zip.xl 与 examples/extlibs/zip_c.c；C 返回的 xbuffer 由调用方销毁。C 范例依赖多份 ZIP 封装源和 _libzip，从 demo6 目录使用 tools/run_extlib_c.ps1 -Package zip -Source release/examples/extlibs/zip_c.c 按包清单运行；单独 xl run zip_c.c 不会自动链接这些源。

2026-10-25 使用 Python 标准库 zipfile 与 C 接口双向交换 ZIP，验证 UTF-8 文件名、DEFLATE/STORED、二进制正文及损坏时的 CRC 拒绝；可运行 python release/extlibs/zip/test/interop.py 复验。此前发布版的包级 C/XLang/AOT 门禁曾通过，但当前新构建的 XLang 导入受共享 TCC VFS 头文件路径问题阻断，本次不能签收 JIT/AOT。危险路径、缺失条目等失败由包装层抛出 ArchiveError；原生内存故障仍保留 MemoryError。

自定义 C Writer 的流式条目输出区分内存故障和普通 I/O；文件提取的 Writer 阶段也有写入、刷新、关闭与复合失败的注入回归，保留最先失败阶段的错误类别。Linux C ASan/UBSan 与符号链接专项曾通过，但本次包更新尚未在 Linux XLang 发布版复验。真实文件句柄的操作系统刷新/关闭失败仍未注入；包外私有构造器和并发修改目标目录的安全边界仍未签收，不能视为最终发布签收。
