扩展库/snappy

snappy

压缩归档
v1.0.0C 混编0 依赖ABI 1

标准 Snappy framed stream 压缩。纯 C codec 与 xlang API 提供二进制安全的 Buffer 一次性、文件及 update → drain → finish 增量流式处理；输出可与遵循官方 framing 格式的工具互通。

典型场景

大数据管道实时流压缩缓存压缩RPC 载荷日志压缩进度回显传输

快速开始

quick_start.xl
import snappy

func main(...) as int
    Buffer packed = snappy.compress("hello snappy")
    println(snappy.decompressText(packed))   // hello snappy

    auto enc = snappy.compressor()
    enc.update("part1 ")
    enc.update("part2")
    enc.finish()
    Buffer blob = enc.drain()

    auto dec = snappy.decompressor()
    dec.update(blob)
    dec.finish()
    println(dec.drain().text())           // part1 part2
    return 0
end

核心特性

2026-10-28：C 桥接头可单独或与核心/XRT 头按任意顺序包含，不改变宿主的模块选择。Windows/Linux 的四种严格 C 编译与基础 C/XL 范例 JIT/AOT 同输出通过；本次只调整声明，未重复完整算法和压力门禁。

  • 标准 framing — 产出符合 Google Snappy framed stream 格式的 .sz 数据
  • 块校验 — 使用 masked CRC32C；损坏的块会被拒绝
  • 二进制安全 — 输入输出统一 Buffer
  • 三种粒度 — 一次性内存、文件级、增量流式（SnappyCompressor/SnappyDecompressor）
  • 真流式输出 — drain() 随时取走已产出字节
  • 分段输入 — 压缩按 64 KiB 原文块处理；解压的大输入分段解析，可跳过 chunk 不缓存主体
  • 进度回显 — inputBytes/outputBytes 字节计数器
  • 串联流 — members 统计 stream identifier；C 选项的 iMaxEntries 限制其数量，finished 表示 finish() 成功
  • 文件原子写 — 临时文件 + 原子重命名

export func compress(Buffer data, ...) as Buffer export func decompress(Buffer data, ...) as Buffer export func compressFile(...) / decompressFile(...) export func compressor(...) as SnappyCompressor export func decompressor(...) as SnappyDecompressor

提供一次性、文件级、增量流式三种接口。流式类提供 update/drain/finish + inputBytes/outputBytes/finished/members。framing 没有结束标记：不完整的末尾 chunk 会报错，但无法检测完整 chunk 边界处的提前终止。

文件接口末尾支持可空 onProgress(inputBytes, totalBytes, outputBytes)。含 NUL 的源/目标路径报 ValueError；返回 false 删除临时输出并抛 CancelledError；回调异常原样传播。C 层对应 xrtprogressproc + void* userData。C 流式接口的进度从 Reader 当前读取位置起算；无法同时取得总长和当前位置时不设置 TOTAL_KNOWN。
Snappy 为固定策略算法，无级别/质量参数，因此也不导出调优常量；数据损坏抛 CompressionError。

教学范例

完整源文件：examples/extlibs/snappy.xl

1. 一次性 + 流式

snappy.xl
import snappy

Buffer packed = snappy.compress("xlang snappy")
assert snappy.decompressText(packed) == "xlang snappy"
println("引擎版本: ", snappy.version())

auto encoder = snappy.compressor()
Buffer streamPacked = Buffer()
encoder.update("hello ")
streamPacked.append(encoder.drain())
encoder.update("stream")
streamPacked.append(encoder.drain())
encoder.finish()
streamPacked.append(encoder.drain())

auto decoder = snappy.decompressor()
decoder.update(streamPacked)
decoder.finish()
assert decoder.drain().text() == "hello stream"

2. 高冗余数据压缩率

压缩率
Buffer redundant = Buffer()
int i = 0
while i < 256
    redundant.append("snappy-snappy-")
    i = i + 1
end
Buffer packed = snappy.compress(redundant)
println(redundant.size(), " -> ", packed.size(), " 字节")   // 3584 -> 202
assert snappy.decompress(packed) == redundant

测试覆盖

测试文件：extlibs/snappy/test/file_ops.xl、extlibs/snappy/test/test_snappy.c，以及中央 test/cases/extlib_snappy.xl 和 extlib_snappy_progress.xl。C 接口先校验选项和资源限制结构的版本、长度与保留字段，无效选项不会消费文件流输入；资源配置只接受有效限额，串联流成员数按 iMaxEntries 检查。2026-10-26 当前 Windows 默认包门禁、Python Snappy 0.7.3 framed 双向互通，以及 Linux C ASan/UBSan、语言 JIT/七条独立 EXE AOT 和双语输出对照通过。旧项目根目录 VFS 和 Linux cstring 阻断不再复现；32 位、TSan 与长期压力尚未验收。

test/test_allocations.c 和 test/allocations.xl 验证 XRT 分配失败时的空结果、释放平衡、恢复和语言层 MemoryError 分类；不覆盖上游 Snappy 内部 allocator。

  • 一次性二进制往返（含 NUL / 0xFF）
  • 流式往返 + members 计数
  • 分块收集 + inputBytes 计数器 + finished
  • 高冗余数据压缩后显著更小
  • 串联多成员流
  • 损坏数据抛 CompressionError
  • 文件级往返 + overwrite 拒绝
  • 文件进度回调、取消清理及限额失败时的既有目标保护
  • 可选 Python Snappy 0.7.3 双向 framed 互通：二进制、重复数据及跨 64 KiB 分块
