# 可空原生键的语言接入

2026-10-13。`SlotMapKey?` 的变量、复制、置空、传参、返回和退出清理
已接通原生拥有值记录。`Stack<SlotMapKey>` 的 `tryPop`、`tryPeek` 和
`tryPeekAt` 已通过实际语言运行，包括空栈、非消费读取及清空后的值
寿命。本批复用此前原生底座，不新增公开 API 或库算法。

## 统一表示和生命周期

统一 IR 为可空原生键登记独立 ABI、语言类型身份、槽和 checked 结果
载体，复用 native-value 的复制、释放、比较及装箱／解箱合同。类型
验证同时核对可空配方与精确元素，不凭结构体名称、相同大小或指针
布局取得能力。已有 native-value 和槽编号不变。

可空提升转移一个已取得的拥有值，不能直接把借入键放入新拥有记录。
解包只观察已锚定可空记录的载荷；需要独立拥有值时走既有 checked
复制。存在位独立于载荷，普通可空复制不创建堆装箱。函数返回值在
finally 将形参置空之后仍有效，已有值不受原 SlotMap 或 Stack 清空
影响。动态投影使用已有认证的可空原生解箱，不开放任意外国记录。

## 精确结果和生成调用

原 try-result 合同只接受标量或指针可空结果，现在也验证封闭原生
可空配方。统一 IR 给出结果是否需要独立存在位；Cgen 机械地将原生
键写入结果的 `.value`，再发布返回状态对应的 `hasValue`，不把 16 字节
键写到整个可空记录的开头。

收窄名称的比较使用已登记的实际值 TypeId，而不是原来的可空存储
TypeId。生成代码调用原生键的 Equal，不输出非法的 C 结构体 `==`。
Cgen 只增加物理载体适配，算法、错误处理和类型语义仍由已有运行时
与统一 IR 合同提供。

## 双平台验收

Windows 318、Linux 317 个完整源码编译单元通过。语言专项分别通过
116、143 个阶段；每端 O0／O2 共 38 次完整调用线程分配失败前缀，
故障后清理并重试成功。每个优化等级执行 100 次模块生命周期，检查
分配、释放、存活数量及字节平衡。实际公共 JIT、module 和 AOT 通过，
不是只对生成 C 做语法检查。

一个可空原生类型、8 个借入载荷视图和 8 项类型／布局篡改通过核对。
错误 IR 被验证器、C／header 输出和原生计划拒绝。四个实际编译链接的
坏实现均被拒绝：遗漏可空配方、把拥有记录标为 POD、把载荷视图误标
为拥有值、以及丢失 try-result 载荷字段。最后一项检查实际生成输出，
不以 IR 验证代替生成器验证。

相邻回归每端 243 阶段／160 次分配位置检查通过；整批声明／严格 C

驻留目录仍为 279 个组件、1445 个精确导出和 13 个拒绝对照。

所选源码、编译输入、产物与日志经最终提交证书逐项核对。证据位于
`E:/xlang-validation/stdlib53-b247-*` 及 Linux 的
