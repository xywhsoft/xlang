## 4. 必须统一的内部边界

### 4.1 值传递

编译器内部为类型记录以下能力：

- 是否平凡复制。
- 是否允许复制或移动。
- 是否需要 retain/drop。
- 是否允许装箱/拆箱为 xvalue。
- 是否包含 vtable 或协议函数值。
- 是否拥有 native 资源。

函数参数、单返回、多返回、属性、索引、闭包、异步帧、全局变量和 C ABI 必须使用同一套能力判断。

### 4.2 表达式临时化

需要语句级处理的 class 构造、动态 var 运算、属性复合赋值、协议调用和资源返回，必须先物化为具名临时值，
再进入普通表达式生成。接收方和索引表达式只能求值一次。

### 4.3 native 资源

native-backed class 必须明确 owned、borrowed 或 shared 语义。具名局部资源返回允许安全移动；
extern `string` 返回值必须复制为 xlang 拥有的字符串；XRT 自有对象优先使用 XRT retain/release。

### 4.4 线程共享

文件作用域容器和进入线程、异步任务或回调的 xvalue 必须在发布前进入 XRT shared 模式。
不得依赖某个回调入口临时修补共享状态。

## 5. 验收标准

- 15 个高危问题全部关闭，不接受保留绕过方案。
- 每个确认 BUG 至少包含最小正向或负向回归，并接入对应分类测试套件。
- cgen 问题同时检查生成 C 形态并使用 TCC 编译运行。
- XRT 问题先有 C 测试，再同步 singlehead 和 demo6 XRT 快照。
- 适用能力覆盖 `xl run`、`xl build`、`xl.dll`、`xlc.dll` 路径。
- TCP 覆盖首发、立即关闭、优雅关闭、半关闭、并发关闭和循环连接。
- 性能问题必须有修改前后同构基准，单位操作成本不得随累计对象数持续线性增长。
- dev 工具中的原始复现必须在修复后恢复正常写法，不继续保留临时绕过作为默认实现。
- `BUGS.md` 中每个条目最终具有明确的设计行为、待修复、待确认或已修复状态。
