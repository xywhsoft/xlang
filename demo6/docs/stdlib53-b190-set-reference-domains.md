# Set 的递归引用类型域

原生 Set 可以作为 Array、Stack、List、Set、Tree 和并发队列值域中的引用元素。
XLIR 使用独立的 Set 引用配方验证完整子域，Cgen 只构造元数据 witness 并调用
驻留工厂。基础值内容键、可变引用身份键和 Future 身份键的规则保持不变。

## 元数据与拥有权

可选的 Set schema 组件将真实子 owner 的布局与完整逻辑准入保存到已有的
驻留引用域接口。用于构造的子集合在成功、失败和错误作用域进入失败时均被
消费；schema 不保留它的存储或 wrapper，也不保存模块借用指针和生成回调。
实际插入的集合引用另行保留，修改其内容不会改变 Set 中的键身份。

相同类型 ID 和物理槽不足以证明两个域相等。匹配包含 owner 身份、独立值域
身份、元素身份、所有权、native descriptor、boxed 身份与逻辑准入；独立构造
的等价域可以互认，较宽域、wire Set、List 或外来句柄不能冒充 Set。

Array、Stack、List 与 Set 共用 64 层递归元数据预算。nullable 引用的默认值
为空，非 nullable 扩容不能自行制造子集合。元数据比较不分配内存，也不消费
调用者已有的错误。失败只交付 checked 结果，不能覆盖首错或漏掉无诊断失败。

## IR 与按需组件

`SET_REFERENCE_V1` 验证子 Set 的完整值域和键合同，使用与其他容器相同的
递归预算。未封闭域继续拒绝；伪造后代键合同和自引用类型图不能通过配方、
C 输出或依赖计划。Cgen 与组件解析从同一配方取得工厂，不读取类型名字。

SET_SCHEMA 是独立组件，按需依赖 Set 存储与已有引用域支撑；不用 Set 的
程序不会仅因类型表里出现 Set 而带入它。真实 Array 和 Stack 可以构造空的
Set 引用域，但这不授权旧语言 Set 的 wire 生产者，也不完成 Set 的持久化迁移。

## 验收与剩余工作

`check_stdlib_set_schema.py` 使用真实供应方存储检查四种父容器、完整域、
字符串内嵌 NUL、bytes、Future、引用身份、消费输入和 nullable 默认值。
严格 O0/O2 验证五条完整分配失败前缀，并拒绝三个成功编译的错误实现。
Linux ASan/UBSan 覆盖选定原生闭包，不代表整个编译器或发布库的总验收。

Set 和相邻 List 的配方测试覆盖真实源码构建、后代合同篡改、目标 C、完整
分配与作用域进入失败前缀。新增语言夹具验证 Array 与 Stack 的 Set 引用域
及 Tree 构造在严格 C 和 JIT 中运行；组件目录核对实际定义与按需依赖。
嵌套与根 Tree 构造的作用域进入失败改为 checked 传播，不再直接 abort；
失败时释放尚未发布的结果，嵌套目标的逐点进入失败前缀覆盖这条路径。

证据保存在 `E:/xlang-validation/stdlib53-b190-*` 和 Linux 对应目录。
语言 Set 工厂、方法、动态分发、复制、迭代、导入、持久化及 Dict 和总验收
继续；DEV-XRT-53 保持进行中。CRT 0 项、XRT 19 个未决策组和对象池最后的
安排不变。
