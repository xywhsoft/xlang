# TaskGroup 原生取消与退役

原生父取消、同步父绑定、任务失败传播与模块退役并行时，收集器现在区分
真实在途操作和永久准入拒绝。回调仍在执行时返回可重试的 BUSY，不记录
永久清理失败；未知回调、无效图和不可描述的拥有者仍按原合同拒绝。

## 精确暂态能力

收集器在完整拥有图冻结后，先匹配不可变描述符的 `Ops` 身份，再调用
`Busy`。查询只读取原生状态，不加锁、分配、修改引用或执行用户策略。
`Busy == false` 仍须经过原有生命周期适配器和物理 Count／Trace 检查。

| 节点 | 在途状态 |
|---|---|
| 语言 TaskGroup 包装 | 普通操作与同步父绑定 |
| XRT TaskGroup | 原生通知、取消传播、私有 Start 槽与监听发布 |
| XRT 活动项 | 完成通知的 Calling 尾部及所属组操作 |
| XRT Future／Promise | 唯一终态预留及自身取消令牌的原生分发 |
| XRT Cancel | 活动请求或其原生链表中正在分发的观察者 |
| XRT CancelWatch | 正在回调、分发或回调内延迟释放 |

TaskGroup、NativeFuture 与 ProcessRunOptions 的独立拥有域按需登记相同
的基础描述符身份。没有按类型名称猜测布局，没有把 StateError 等错误改成
重试，也没有增加 Cgen 专用语义分支或语言标准库函数。

## 私有启动与发布

Start 的预留槽属于正在执行的原生调用，不是可由用户长期保存的 opaque
票据。提交把 Future 写入活动项后，必须完成监听挂接才结束在途状态。
这一窗口由明确的 Busy 计数覆盖，不用链表不一致推断“暂态”，避免掩盖
真正无效的图。

提交操作还独立持有一个真实组引用，直到在途状态退出后才释放。同步完成
可能调用观察者并销毁公共组拥有者；操作尾部不能借用已经返回的拥有权。
原有 Count／Trace 拒绝条件没有放宽，所有临时引用仍参与物理根判断。

## 回归范围

原生专项覆盖 80 个带屏障的真实窗口：父取消、同步父绑定、原生组取消、
失败通知触发同组取消，以及 Future 的终态预留。检查活动状态返回 BUSY、
冻结探测不分配、计划不保留失败快照、回调退出后恢复正常准入和完整内存账本。

宿主专项覆盖 24 次真实模块生存期。其中新增的 6 次在没有语言 CodeScope
的原生父取消回调中暂停，释放外部输出根后请求模块退役，要求非阻塞 checked
排空返回 `ready=false, ok=true`，代码镜像保持常驻。放行回调后要求生成的
catch／finally 各执行一次，checked 排空成功并释放代码镜像。

专项继续覆盖 Windows／Linux、严格 C、JIT、模块、独立 AOT、源码 CLI，
以及 Linux 的 ASAN／UBSAN 原生路径。XRT 的模块化与单头测试另检查私有
预留、监听发布和取消分发；这些结果不替代全部 53 模块、发布 DLL、VFS
及 RC0 的最终验收。对象池最后处理，未决策范围不变。
