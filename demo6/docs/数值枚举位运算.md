# 数值枚举位运算

数值枚举支持同一枚举类型的 `&`、`|`、`^` 和一元 `~`。结果保持该枚举的名义类型，不降为底层整数；类型别名不产生新的枚举身份。不需要额外的 flags 标记。

```xlang
enum Access as uint8
    none = 0
    read = 1
    write = 2
end

auto access = Access.read | Access.write
access &= ~Access.write
assert access == Access.read
```

组合结果不必对应已声明的成员。`~` 翻转底层整数宽度内的全部位，并非仅翻转已命名的位：`uint8` 枚举中 `~1` 为 `254`；有符号枚举中 `~1` 为 `-2`。如果只需要已知标志，应再与显式的允许掩码相与。

`&=`、`|=`、`^=` 遵循同一规则，目标仍须满足已有的可写性和复合赋值规则。常量表达式、函数参数及返回值、容器中的枚举保持同一类型合同。可空值须先通过已有的非空收窄或显式投影取得枚举值。

以下行为不开放：

- 不同枚举相互运算，即使底层类型和成员值相同。
- 枚举与整数字面量、整数变量或动态变量混合位运算。
- 枚举的算术、移位以及对应的复合赋值。
- 带载荷枚举使用这些内置位运算。

已有的比较和显式数值转换规则不变。`int(access)` 是显式取出数值，不代表可以把 `access | 1` 当作合法表达式。

两边均为 `var` 时，驻留运行时要求两者携带完全相同的枚举身份和整数域；`&`、`|`、`^`、`~` 的结果保留身份、位宽和有符号性。不同枚举、枚举与普通整数混用，以及动态枚举的算术／移位／一元正负均抛出 checked `TypeError`。静态枚举与 `var` 直接混用仍不开放，须显式装箱两边或先通过 `as Access` 恢复静态类型。这不额外开放 `var` 的复合赋值语法；可使用 `a = a | b`。

## 编译合同

语义层决定是否为同一数值枚举；Typed XLIR 同时校验操作数、逻辑结果和物理结果的名义 TypeId；降低后的标量指令要求精确的操作数及结果类型。篡改为普通整数、其他枚举、算术或移位时应拒绝输出 C 和声明头。

运算本身无分配、无异常且不阻塞，不产生语言包装函数。Cgen 无枚举专用运算实现，只序列化标量指令。`uint8/16/32` 枚举目前使用 i64 物理寄存器，故其 `~` 在降低时固定为与 `255/65535/4294967295` 异或；这保证宽度语义，不依赖 C 的整数提升。其他宽度使用直接的按位运算。

上述无分配／无异常合同仅适用于静态标量运算。动态操作借用输入、返回一个拥有的 xvalue，可能分配或失败，必须保留立即检查的错误边界。`XVALUE_ENUM_BIND` 是独立的 consuming IR 操作，记录精确枚举 TypeId 和 integerTarget，只接受同枚举标量的全新装箱结果；不得改用裸 TypeId 绑定。Cgen 只调用 `xl6ValueEnumBindTakeV1`、`xl6ValueNumericBinaryV1` 和 `xl6ValueNumericUnaryV1`，不生成这些算法的函数体。

基础整数、C 标量和枚举采用独立的不可变标量域。容器的拥有策略携带域标签，复制、快照和擦除投影时保留；首次绑定在元素移交快照前完成。未知的“只有 TypeId、没有域”值不能被猜成枚举或普通整数。数组迭代的计数／位置始终为规范 int64，不得复用窄整数或枚举元素类型。

验证入口为 `tools/check_numeric_enum_bitwise.py`，输入真实源码构建的 `build.json`。覆盖八种整数宽度、名义返回值、常量、复合赋值、数组、动态装箱、类字段、别名、可空投影、函数值、生成器与 async，并运行错误源码及两级 IR 篡改用例；执行 JIT、模块、独立 AOT、严格 C 编译和依赖裁剪检查。此入口不创建网络端点，也不代替发布库验收。
