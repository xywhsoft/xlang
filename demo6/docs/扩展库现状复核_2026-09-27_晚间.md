## 结论与范围

扩展库已经形成明显厚于早期目录骨架的实际能力，但当前主要缺口是语言绑定、
运行库与发布物的一致性，以及真实场景验收，不能把整个生态标为 RC 完成。

本轮重新读取全部活动包清单，复核近期实现、测试及本地官网；只做分析和运行
现有测试，没有修改编译器或扩展库实现，没有同步 XRT、重新构建或替换发布程序。
工作区此前存在未完成修改，本报告不会把这些源码改动当成已通过的二进制修复。

## 能力重新分层

### 有专项证据的基础库

已有较完整、范围明确的专项记录的 16 个包：

`aho_corasick`、`argon2`、`bloom`、`blake2`、`blake3`、`sqlite`、`xxhash`、
`crc32`、`md5`、`murmur3`、`sha3`、`siphash`、`mqtt`、`gzip`、`brotli`、`bz2`。

这 16 个包的本轮选定发布版 JIT 测试都通过。既有专项涵盖的 C/XL、回调、
分配失败、线程或跨平台范围各不相同，不能解释为本轮重新执行了所有专项。
尤其 gzip/Brotli/BZ2 的文件故障收口及完整专项通过来自隔离候选，正式发布
产物没有替换；基础 JIT 通过不能覆盖发布运行库尚未同步的文件故障修复。

因此更准确的状态是“有专项基线，可优先进入统一发布验收”，而非无条件生产认证。

| SSH | 原生 wire/packet/KEX/auth/connection/session/client 代码；语言层 5 个类 | 完整会话、认证、通道与异步客户端均已成为 xlang 对象 API |
| GUI / 图形 | XUI 活跃 XL 源码中有 64 个公开类，XGE 有 9 个；已有控件、事件桥接与 OOP 表层 | import 测试能代替窗口、事件回调、资源释放、渲染和输入法验收 |

XUI/XGE 在 manifest 中各自只登记一个 import 用例，项目其他地方可能另有
测试，但仅该登记入口显然不能证明其完整交互能力。本轮没有启动 GUI 或设备测试。

上述库不能继续按“占位、需要从零实现”估算；应先完成接入合同和真实场景验收。

### 实现或公开范围有限，不能按库名推断能力

- `mysql` 当前语言入口和聚焦用例主要是命令/类型名称、状态、转义、DSN 等辅助能力，
  没有据此验收连接、认证、查询、事务及连接生命周期。
- `faiss` 当前聚焦用例是索引/度量名称及标量向量计算，不是索引构建、批量查询和持久化验收。
- `nats` 当前入口侧重协议名称、subject 匹配和 URL 等辅助能力，不是完整连接、订阅和 JetStream 客户端。
- `xbot` manifest 只接入 `OpResult/Size/Pixel/Ratio` 四个基础类；`xbot.agent`
  是独立的离线工具体系。完整自动化栈仍保存在 `dev/deferred/xbot.full`，不在
  当前 `xbot` 包的编译范围内。基础模型测试通过不能代替 Agent/设备/视觉验收。

本轮这三个辅助型库和 xbot 基础用例均通过，但不据此提升整个同名领域的成熟度。

## 本轮运行结果

正式 `release/xl.exe`：29 个选定 Windows JIT 入口，45 秒单项上限，
**20 通过、8 失败、1 超时**。这是抽样，不是全生态通过率。

对其中 9 个未通过入口，再使用既有隔离候选
`build/test/extlib-runtime-final-20260927/runtime/xl.exe` 复测。
HTTP client 上限放宽至 90 秒，其余 45 秒：**9 个均未通过，没有超时**。
两轮测试输入哈希稳定，结束后也未发现新增源码输入。正式三个发布程序哈希未变。
候选不是最新工作区源码的重新构建，不包含尚未构建验收的 native 字段初始化修改。

| 包/入口 | 正式发布程序 | 既有隔离候选与判断 |
| --- | --- | --- |
| CSV | 运行时 TypeError | 同样失败；与 native-backed class 的 XL 字段初始化边界有关。工作区已有修补及回归用例，但不能计作受测产物已修复 |
| ONNX Runtime | `ort_available_native` 原型冲突 | 仍存在；C 返回 `int`，XL 声明为语言 `int`，物理类型不一致 |
| RapidOCR | `rapidocr_vis_image_native` 原型冲突 | 仍存在；同族 C `int`/XL `int` 声明问题，不能只修第一个报错符号 |
| xregex | 捕获文本触发 BufferError | 已越过旧 RegexSet 声明冲突；native matcher 保存输入借用视图，语言传入的 C 字符串却仅在调用期间有效，需修复整个保留输入的对象边界 |
| xmail | DEFLATE 的 feature 依赖检查失败 | 越过 feature 检查后缺少 `xl6ExtlibTlsLeaseRelease`；应统一 TLS lease 的声明、实现和运行时符号提供 |
| xhttp URL | form-urlencoded 的 feature 依赖检查失败 | 越过检查后是错误分类预期不一致：相对路径 target 抛 ValueError，而用例只捕获 RuntimeError；不能据此认定 URL 解析算法错误 |
| xhttp.body_file | XLIR 可达未终结块 | 候选仍失败，属于编译链阻断，尚未进入文件正文行为验收 |
| xhttp.client Request | 45 秒超时 | 约 75 秒后得到依赖 `xhttp.protocol` 的 `headers_destroy` 原型冲突；不能把第一次超时直接叫作网络死锁 |
| xssh | packet/random_secure feature 依赖检查失败 | 越过检查后 `xssh_code_name` 原型冲突：C 参数 `int` 与语言 `int` 不一致 |

CSV/正则不能只通过修改测试期待值收口。前者应验证所有原生类字段初始化及
失败回滚；后者应让需要跨调用保存输入的对象拥有稳定存储，而不改变 C 底层
明示的借用契约，也不能关闭 NUL 检查掩盖悬空指针。

相对 URL 的情况不同：[原生输出路径](../release/extlibs/xhttp/src/url/url.c:1064)
明确设置值错误，[测试](../release/extlibs/xhttp/test/xhttp_url_test.xl:40)捕获的却是
RuntimeError。应先统一错误合同，再复跑，而非增加一套兼容异常映射。

## 文档与官网差距

- 218 个公共包中，有 35 个在本地官网既无独立详情页，也无 generated 清点页，
  其中包含 `xhttp.*`、xmail、xregex、xssh、xws 及一批已经有源码的小型工具。
- generated 中有 31 个页面不能对应当前公共活动包，其中 2 个是内部包，
  29 个在当前活动包集合中不存在。这些页面应归档、迁移或标明状态，不能继续
  作为现行生态入口；本轮未删除或发布任何页面。
- 16 份包内维护型页面与官网文件哈希一致，这是交付同步证据，不是运行正确性证据。
- 旧表中的“116 个已压实”、52 个超预算、36 个平台暂缓等不能照搬。
  116 是测试登记数量，其余旧标签是待审候选队列，并没有完成逐包新增成本证明。

## 下一阶段顺序

1. **先清共享阻断。** 完整审计 C/XL 物理类型、const、析构返回值、容器 ABI；
   统一 SDK feature 暴露与 TLS lease 符号；完成 native-backed 字段初始化和
   借用期修复；压实 XLIR 控制流。避免逐包仅修改第一个报错声明。
2. **将 16 个基础库变成固定发布批次。** 同一组源码与产物执行 C/XL、JIT/AOT、
   Windows/Linux 和文件/取消/OOM 边界门禁，通过后再更新 release。
3. **接通高价值已有实现。** CSV、xregex、HTTP 客户端、邮件优先；SSH 补语言
   会话对象；AI 使用固定小模型成功样本；GUI 补实际事件和生命周期测试。
4. **按用户目标评估剩余包。** 区分实质实现、有限辅助层、真占位和环境待验。
   10000 行预算只评估占位库还需要新增的代码，不约束已有 ONNX/xbot/RapidOCR
   等实现的总规模；不能按单文件数量或旧名单自动跳过。
5. **官网随验收同步。** 显示实际可用 API、平台、依赖、最后验证构建与尚未覆盖
   的范围，补齐双语范例，并处理失效包名入口。

本轮没有复跑全生态 C/AOT、Linux、外部服务、模型成功推理或设备门禁，也没有
将本轮结果合并到早先的 132、153、28 项测试中。不同构建与不同选样不计算
一个混合“完成百分比”。
