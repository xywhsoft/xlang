# 普通 union 的原生容器存储与可空值合同

普通无标签 union 现在可以通过封闭 XLIR 配方进入 Array、List 和 Dict。
既有安全索引、索引赋值两个失败程序恢复运行，可空值、嵌套数组及
动态值往返也通过。接收接口继续按用户确认的 `(status, T?)` 规则迁移：
成功、空、关闭、超时由状态区分，复制及资源错误仍进入语言异常。

## 语言布局与容器布局分开描述

union 的调用 ABI 仍是现有 trivial C union。容器配方明确选择拥有型
`xvalue*` 槽与 `union-value-v1` 编解码，不把 union 地址解释成 Value
指针，也不改写 union 的全局 native slot。字节载体必须同时满足
XVALUE_BYTES 标签、精确 nominal TypeId 和 `sizeof(C union)`。

可空 union 保留语言层 `hasValue` 和 union 负载。存在值按原有 union
字节表示装箱，缺省值成为 canonical null；生成器不再尝试套用整数
或实数的固定可空结构。完整模块布局和 nullable 形状在 IR 边界验证，
错误 codec、槽、传输、默认值与字段布局不能进入 C 输出。

常驻准入策略只保存独立拥有的类型身份、大小和 nullable 信息，没有
来自生成程序的回调或借用元数据。非可空扩容由常驻代码创建全零的
union 字节表示；可空扩容产生空值。克隆共享不可变准入元数据，同时
独立拥有存储；原对象释放后，克隆的读取与擦除投影继续有效。

这沿用已有 union 装箱表示，不是新的内联 union 数组优化。每个装箱
仍有 Value／字节块成本，不能据此声称达到原生连续 C union 数组的
性能。无标签 union 没有活跃字段合同，因此本批不赋予 Set 的内容
相等／哈希能力，也不把填充字节作为语言键语义。Stack、SlotMap 和
消息传输的独立物理合同仍须单独授权，不由集合配方自动放行。

## 按需原生组件

准入实现位于独立 `ARRAY_UNION_ADMISSION` 组件，复用 XRT 的 typed
存储与 Sequence 拥有模型。Cgen 输出所选常驻工厂和既有投影调用，
没有添加容器算法、wire Array 回退或 ANY 准入兜底。普通标量程序不
选择该组件；原生符号目录、源码构建清单和私有 SDK 声明同步更新。

## 双端专项验证

Windows 307、Linux 306 个翻译单元从隔离的选择性源码构建。
两端各 64 个 union 专项阶段包括 O0／O2 严格 C、真实 JIT、独立
AOT 及导入检查、3 个源码用例的 912 个完整分配失败前缀。原生
准入与默认扩容在两种优化下各完成 18 个分配前缀，保持拥有值平衡。

同类型错误大小、不同类型相同大小、空值、错误 role、默认扩容、
克隆后释放原对象、擦除读写，以及 pending error 的透明准入检查
通过。26 项损坏 IR 检查拒绝配方及整个 C／头文件输出。刻意删去
字节大小检查的真实坏实现触发原来的错误大小断言；不以任意崩溃
代替因果拒绝。真实 Set 源码拒绝未经授权的 union 键配方。

既有 9 项容器批量回归在每端保持 156 个阶段、7490 个完整分配失败
前缀通过。原生目录在每端核对 268 个组件、1414 个精确导出与 13
项坏目录拒绝；编译后 RuntimeOp／拥有值合同 O0／O2 回归通过。
证据保存在 `E:/xlang-validation/stdlib53-b230-union-win-final2`
与 `/var/tmp/xlang-stdlib53-b230-union-linux-final2`，各相关回归目录
和最终消费者快照共同核对实际输入、SDK、对象、产物及日志。

## 后续验收范围

本批关闭上述 union 构造与索引回归，不代表所有 union 容器方法或
53 模块发布验收完成。成对迭代、WaitQueue 独立拓扑与后端、其他
压力场景和 shipping DLL／SDK 总门继续。CRT 未决策 0、XRT 19 个
未决策组保持，对象池最后；不扩大已批准功能范围。
