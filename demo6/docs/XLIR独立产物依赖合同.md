## 边界与职责

`xl6ArtifactRuntimePlanBuild` 只接受已验证 Lowered XLIR，以及明确的产物入口
ABI。它不是新的语义 IR 层，也不接收 AST 或生成的 C 文本。根依赖来自模块
ABI、可达指令、物理类型及已解析调用目标；类型工作队列包含 nullable、产品
和 callable 的嵌套载荷，不根据源类型名决定拥有关系或调用行为。

fragment、checked module 和 executable 的入口身份分别记录。独立产物的
checked init/run/fini 边界需要错误作用域，即使用户函数没有可抛出操作。
语言效果和产物包装器要求不能混为一谈。

`xl6_artifact_runtime.h` 定义 23 个常驻组件及产物清单。组件描述表持有源码、
直接常驻依赖与 XRT/xruntime 根模块。固定点闭包完整处理互相依赖的组件，
随后按稳定次序输出唯一源码和原生根模块；源码编译器按清单装配，不再通过
链接报错选择下一段源码，也不整包引入所有常驻组件。

`xl6_artifact_runtime_symbols.inc` 是精确的 C 链接所有者注册表。它只匹配
已经解析出的调用目标 C 名称，不扫描字符串常量、源函数名前缀或生成文本。
当前 172 项与 23 个真实组件对象的导出一一核对；各对象的未解析私有符号
还必须位于声明的组件闭包内。此检查防止宿主已经链接全量运行时而掩盖缺项。

常驻源码和内联适配器都可能带来原生依赖。UTF-8 scalar count/at 的明确
RuntimeOp 选择 Unicode text 根模块，不能把它当作普通字节串存储。v205 将
这些要求统一接入 C 实现需求描述，不再在产物计划中另写 UTF-8 特例。原生根
模块传入 XRT 产品构建器，由 XRT 自身的模块规则展开内部依赖。

## v205：统一 C 实现需求与无扫描装配

`xl6_ir_cgen_needs.inc` 为 244 项现有实现需求声明字段类型和原生依赖组。
`xl6IrCgenBuildNeeds` 先验证 Lowered XLIR，再执行同一组实现选择分析；
生成 C 与 `xl6IrCgenVisitNativeModules` 共同使用这份结果。54 个组是后端
实现库的显式元数据，不是第二个语义 IR，也不是对生成文本做统计或猜测。
JSON/XSON 等实现的模式位直接选择对应读写模块；网络公共生命周期需求
独立表达，避免只有 TLS 操作时遗漏已经发出的 engine/resolver/DNS 支持体。

产物计划另外声明公开 `xlValueRetain/Release/Clone/IsNull/Data` ABI 的固定
基础依赖；这与可选常驻组件的空根闭包分开，原 529 个双根组合合同不变。
通用 value 打印实现会发出整数、无符号数和浮点格式化支持，因此其实现
组明确要求 NUMBER_FORMAT，而不是根据某次输入是否打印数字推断依赖。
组对应当前发出的完整支持组件，不承诺每个程序的最终原生代码全局最小。

`xl6XrtTrimBuildImplementationSourceFromArtifact` 仅接收明确包需求和原生
模块清单；不接收 AST 或 C 文本，也不隐式补入旧 keep 标记。要求 TCC、语言
运行时、编译器或未声明 C 源模块的包仍按明确策略选择完整产品。普通 XLIR
分支使用此入口，历史扫描只隔离保留在 legacy 分支，尚未删除旧后端。

17 个独立程序同时核对生成对象、所选常驻对象的真实未定义原生符号，以及
所选 XRT 实现对象的真实定义；不能用已经全量链接的开发宿主掩盖缺项。
实际 AOT 保存的 `xl6_xrt_impl.c` 还必须与计划生成的实现逐字节一致。
新适配器门包括 48 个明确程序，严格编译网络/TLS/HTTP/WS、文件/路径、
编解码、容器与持久化适配器。这里的网络程序只编译，不执行网络服务。

## v205：C 返回 ABI 与求值拥有事务

调用目标新增 `resultCAbi`，与逻辑返回类型、物理布局和所有权转换正交。
12 个规范路径函数的原生签名为可写 `char*` 返回、只读字符串参数；Lowering
解析后记录该 ABI，验证器核对调用种类、参数数量、借用方式、返回存储与
转换。Cgen 只消费验证后的字段输出 `char*`，不按函数名修补 C 声明。
32 项反例覆盖错误 ABI、名字和参数借用方式；字符串接管仍由显式 TAKE_CSTR
完成。此目录只覆盖这 12 个规范声明，不等于任意 FFI 签名体系已经验收。

共享 HTTP/WebSocket 支持体使用显式后端 ABI 模板参数：XLIR 的析构函数
返回真实 C `void`，legacy 保持原整数哨兵约定。两者共享函数体，不通过
生成文本替换修正返回类型，也不为每个失败符号增加生成端特判。

持久化专项还暴露了真实语言生命周期缺口：临时字符串装箱失败时，旧
Lowering 只在成功路径释放源字符串。修复将拥有源加入统一求值事务，并
将装箱结果保护到后续参数求值和 stringify 调用结束；分配失败、后续参数
抛错、成功返回共用 IR 清理规则，未放宽拥有图验证器或向 Cgen 增加补丁。
独立运行时探针共 192 项：64 个真实分配失败、64 个后续参数错误及 64 个
成功，逐次检查活跃对象、字节数、分配/释放平衡和非法释放，全部通过；
它证明该求值事务，不代替整个网络拥有图。

## 失败边界和验证

失败时清单必须全零；Typed、损坏的物理 ABI、未知入口 ABI 或工作区资源
不足不能留下部分可用清单。当前测试包括：

- 独立传递闭包算法核对全部 529 个双根组合，源码/原生根去重。
- 17 个真实程序的 Typed 和损坏 Lowered IR 拒绝，以及清单重建一致性。
- 9 个分配预算：8 个真实资源失败、1 个成功；精确内存平衡和非法释放检查。
- 含 `xl6Future`、`xl6TaskGroup`、`xl6Channel` 字符串和近似函数名的反例。
- 23 个实际组件对象、172 个真实导出和传递私有链接依赖核对。
- 原五个样例生成 C 与 v202 完全相同；修复发生在独立产物依赖合同而非 Cgen。

入口：`tools/check_xlir_artifact_runtime.ps1`，要求当前源码构建目录和全新输出
目录。v205 另加 `tools/check_xlir_native_adapters.ps1`；全部原 37 项保留，
当前统一批次为 38 项。

## 原生链接身份目录

### v204 原生链接身份

`gen_xrt_linkage_catalog.py` 从当前产品单头、原生及 xruntime 模块清单生成
精确链接目录。真实预处理负责展开函数宏、平台分支和功能条件；诊断来源
标记将定义关联到单头中的原始实现节。不依赖函数前缀，也不把“声明在某个
头文件”或“定义在某个源码文件”误当作唯一模块归属。

全产品的 3484 个公共声明与实际定义一致；402 个可选择根模块及无选择核心
分别预处理，按实际启用功能集合的包含关系求出能提供定义的最小根。两个
独立最小提供者仍同时保留，不任意挑选；当前有两项双提供者，51 项由无选择
核心提供。`channel_cancel` 没有独立源码却启用 `channel.c` 内的取消函数；
`xrtEncodingUnitSize` 属于 CHARSET，而不是从名字推断的 encoding 大组。
内存调试接口也不能因与普通分配器处于同一文件而误列为无条件核心。

`xl6_artifact_native_symbols.inc` 只记录外部链接身份与模块根，编译器以二分
查询消费。只有可达的 EXTERN_C 目标加入计划；未调用的声明、字符串中出现
的名字和相近名字都不能成为计划依赖。Typed/损坏 IR 仍在计划生成前拒绝。
模块根去重，容量失败清空计划并报告错误，不返回可用的半份清单。

目录已与当前源码构建的真实完整原生对象逐项核对：3484 个公共导出无缺项；
另有共享源码、附加功能、无条件核心等七项归属断言，所有链接名字的精确
查询与 3484 个近似名字拒绝，以及独立解析反例。原 v203 CLI 在新增程序上
Cgen/JIT 成功、AOT 缺 `xrtEncodingUnitSize`；接入目录后实际 AOT/EXE 成功，
生成 C 也通过 GCC 严格编译。该修复不是给失败符号增加手写特判。

目录表示函数定义的最小链接要求，不替代原生调用 ABI 或语言语义合同，也
不自动开启某个 API 的全部可选行为（例如调试或额外格式能力）；附加能力
须由明确的操作/桥接合同或包模块声明提出。3484 个目录条目不等于已经验收
3484 项语言 API。预处理来源记录按输入哈希缓存并写入验收证据，当前为
Windows GCC 目标；并未因此证明 Linux 或其他平台执行。

原 14 个程序生成 C 逐字节不变，Cgen 仍为 5080139 LF 字节。链接目录是新增
的编译器元数据，当前开发 CLI 比 v203 增加 143521 字节；不是 Cgen 源码或
发布 xlc.dll 的缩减。本批未更新发布物。最终证据入口为
`build/tmp/xlir_launch_v204_evidence/results.json`；目录的 Python 输入及全部
404 份预处理记录在最终复核中单独重验，不仅依赖批次的源码文件指纹。

### 仍开放的迁移范围

XLIR 装配调用链已脱离历史 AST/生成 C 扫描，当前全部实现需求字段有明确
依赖组。但 48 个适配器程序并非全部语言和可选功能组合；仍需继续验证组合
边界、更多 FFI 物理签名，以及实际 native/network 与混合对象生命周期。

legacy 后端暂时仍使用独立隔离的旧选源函数，待其整体退出。当前测试使用
开发目录、明确的 TCC provider 以及已部署的私有源码/声明头，不代表已验证
共享发布 xlc.dll、隔离部署、Linux 或全部语言。发布二进制本批未更新；
native/network 混合对象生命周期、完整语言/平台/发布和旧路径退役仍然开放。
