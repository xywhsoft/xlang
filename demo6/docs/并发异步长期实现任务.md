# DEMO6 并发、异步与生成器长期实现任务

本文档记录本轮长期任务的实现边界，避免开发过程中混入 DEMO5 的旧口径。

## 总原则

1. 并发基础能力必须建立在 XRT 之上。
2. xlang 不在编译器中私造 future、task、channel、thread 的运行时。
3. C 与 xlang 混编仍是第一原则，所有并发对象必须能用 C API 独立解释。
4. 第一版优先完成稳定、清晰、可测试的语义，不追求一次性加入所有高级并发表达式。

## XRT 基础设施

优先使用 XRT 已有能力：

- `xrtThreadCreate` / `xrtThreadWait` / `xrtThreadStop`
- `xrtMutex*` / `xrtCond*` / `xrtRWLock*` / `xrtSem*`
- `xrtCo*` / `xrtCoSched*` / `xrtCoEvent*`
- `xFuture*` / `xPromise*` / `xTaskRunThread` / `xTaskRunCo` / `xTaskGroup*`

如需补齐 channel 或值传递规则，应先在 XRT 实现，再同步单头文件到 demo6。

## xlang 类型

本轮新增或完善以下内置类型：

- `future<T>`：异步结果句柄，实现 Awaitable。
- `task<T>`：任务句柄或任务相关 API 的语义类型，实现 Awaitable。
- `thread`：系统线程句柄。
- `mutex`、`cond`、`rwlock`、`sem`：同步原语。
- `channel<T>`：线程安全通道。
- `generator<T>`：同步生成器。

## 语法

本轮启用保留字：

- `async func`
- `await expr`
- `yield expr`

约束：

- `await` 只能出现在顶层脚本或 `async func` 中，普通同步 `func` 内禁止使用。
- `await` 的对象必须实现 Awaitable。
- `yield` 只能出现在声明返回 `generator<T>` 的函数中。
- 第一版不实现 `async generator<T>`。

## 运行时语义

- `async func foo() T` 的调用结果是 `future<T>`。
- `await future<T>` 的结果是 `T`。
- `throw` 在 async 函数中将 future 置为失败状态。
- `await` 失败 future 时重新抛出异常。
- 取消不是普通返回值，应保留为 future/task 状态。

## 实现顺序

1. 确认 XRT 单头文件包含现有 future/task/coroutine 能力。
2. 在 demo6 建立并发 runtime 薄封装，避免 cgen 直接散落 XRT 细节。
3. 注册并发相关类型和协议。
4. 实现 `thread`、`future`、`task` 的基础库调用。
5. 实现 parser/AST/sem 中的 `async`、`await`、`yield`。
6. 实现 async 函数代码生成。
7. 实现 generator 代码生成。
8. 补齐测试、范例和稳定性验证。
