# Typed HIR 与后端边界

本文档规定 DEMO6 语义阶段与代码生成阶段之间的唯一类型口径。

## 1. 编译阶段

DEMO6 当前编译主线为：

1. Flex 词法分析。
2. Lemon 语法分析，产生 AST。
3. import 与标准库展开。
4. 语义检查、重载解析与泛型推断。
5. typed HIR 收口。
6. C 代码生成与 TCC 后端。

typed HIR 使用“AST 节点 + 语义类型覆盖层”的紧凑表示，不复制第二棵结构相同的语法树。每个确定产生单值的表达式节点都拥有规范化 `inferredType`，其生命周期由 AST 统一管理。这样既保留源码位置和语法结构，又避免额外的节点、字符串和类型树分配。

## 2. 完整性约束

`src/ir/xl6_hir.c` 在语义检查成功后执行最终验证。以下确定产生单值的节点必须具有静态类型：

- 整数、浮点、字符串、时间、布尔和 null 字面量。
- 普通字符串插值、匿名函数。
- 索引、安全索引、条件表达式。
- 一元、二元、`is`、运行时 `as` 和 `await` 表达式。
- array、list、set、dict 和带类型容器字面量。

函数调用可能无返回值或产生多返回值，因此不能只用单一 `inferredType` 表达；其返回元组继续由已解析函数签名承担。函数名、成员名和泛型实例也可能只作为 callee，不强制伪造运行时值类型。

缺少必需类型会在 `hir` 阶段直接报错，不允许静默进入后端。

## 3. 后端规则

- cgen 通过 `xl6HirExprType()` 读取语义阶段的权威类型。
- 泛型实例化时，只对 HIR 类型执行当前类型参数替换和别名规范化。
- cgen 自己创建的协议探测节点、重载匹配节点和表达式替换节点没有源码 HIR，此时才允许使用后端局部推断。
- 源码表达式不能因为 cgen 无法处理某种 AST 形状而从静态类型降级为 `var` 或动态容器。
- `auto` 的 C 存储由 HIR 类型决定；例如 `array<int>` 必须使用 `xtarray`，不能再次按初始化表达式形状猜测。

## 4. 容器类型推断

同质容器字面量在语义阶段形成静态泛型类型：

```xlang
auto a = [1, 2]          // array<int>
auto b = {1, 2}          // set<int>
auto c = {"x": 1}       // dict<int>
```

异质字面量保留动态容器类型。静态泛型容器可以显式或按声明目标装箱为同类动态容器；动态容器导入静态泛型容器时必须逐项验证。不同容器种类、不同静态泛型参数之间不做兼容匹配。

## 5. 验收

- 核心容器、闭包、OOP、泛型、异步、任务和语义负例套件必须通过。
- `xl check` 成功后 `XL6_CompileUnit.hirReady` 必须为真。
- cgen 不得再次改变源码表达式的静态类型和存储类别。
