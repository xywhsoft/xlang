# Process 异步等待

本页描述三组标准库长期任务 B26 的已实现合同，不是整个 process 组或
53 模块的完成证明。基础 live Process/流/同步等待沿用 B23。

## 公开入口

```xlang
auto p = process.startFile(program, arguments)
future<ProcessExitStatus> waiting = p.waitAsync()
auto status = await waiting
```

`waitAsync()` 不阻塞调用线程，返回结构化退出状态，不返回退出码布尔值。
非零退出码是正常退出状态，不等价于等待失败。已结束进程可重复等待；
每次成功生成独立的 `ProcessExitStatus`，原 Process 释放或被替换后仍有效。
后台等待错误和内存失败按既有异常路径传播，不用伪造的退出码表示错误。

异步帧拥有 receiver 到状态构造完成；不捕获借用的 OS 句柄，也不要求用户
手动延长变量作用域。流仍是 B23 的唯一 owned Reader/Writer。

## 取消边界

`waiting.cancel()` 请求协作取消，只中断本次语言等待。挂起帧的正常取消
边抛出 `CancelledError`，沿既有 CFG 执行 catch/finally 和作用域清理；
不内联执行脚本，不跳过 finally，不自动 kill/terminate 进程。

XRT 的 `xrtProcessWaitAsync` 返回进程唯一共享终态 Future。resident 层
仅用普通 `xrtFutureThen` 转换为精确 `bool` readiness，禁止 CancelSource。
取消一个等待者不取消该共享源，其他等待者继续等待真实进程终态。
原生 Then 自身的取消令牌仍遵守原生协作语义，不虚构立即终态；语言外层
的及时取消由通用 continuation 生产者/Watch 退役合同实现。

取消请求与源完成/后继发布竞争时，正常激活只受理一次。主动取消期间
await-in-finally 仍允许等待清理结果，重复 cancel 不再次打断该清理。
本批只验证显式 Future.cancel；原始 token/父 token 传播不声称具备同一
即时唤醒保证。完整 TaskGroup/跨线程组合与模块卸载继续列入总验收。

## 声明、ABI 与裁剪

公开方法是短语言组合：await 私有 readiness，再构造 status；Cgen 不包含
进程算法。私有桥 `xl6ProcessWaitReadyAsyncV1` 声明为 `future<bool>`，
nonblocking、may-raise、非 pure，借入由 `xl6ProcessDestroyV1` 管理的句柄。
XLIR 精确校验 Future carrier、元素 bool、空值/所有权/效果及 receiver owner。
resident payload 使用物理 `bool` 盒子及实际常驻所有权 policy。

只在使用 waitAsync 时增加 PROCESS_FUTURE resident 组件及
PROCESS_FUTURE/FUTURE_CONTINUE 原生模块。基础 Process wait/status
不增加它；流入口另外增加 IO。pipeline/file/terminal 不随等待带入。
测试检查实际装配与规划一致，不仅检查声明或函数名是否存在。

## 验证范围

正式语言夹具覆盖非零退出、重复等待、独立状态、父变量提前释放、同一
进程两个等待者及取消后先返回异常、再关闭 stdin 的确定性场景。
四个非法声明覆盖错误 Future 元素、nullable 元素、错误效果与 owner。

原生测试使用真实 XRT/process/mapper/payload：完整 mapper/pending/terminal
分配前缀、ambient error、重复发布、取消隔离、父对象释放及 heap ledger。
账本测试保留私有原生观察者，显式 join waiter 尾部；公共 wait/await
只保证终态，不伪称等待线程已退役。B27 另验证三个同步 live 生成程序
路径的完整当前线程 OOM 前缀；不能代替 generated Future 语言 OOM、
其他线程的故障注入、卸载与跨组总验收。具体冻结记录见长期任务 B26/B27。
