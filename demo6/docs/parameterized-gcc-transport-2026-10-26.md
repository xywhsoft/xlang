# 参数化场景的 GCC 参数传输与复测：2026-10-26

本批修复首轮发现的 16 项 Windows 命令行超限前置，不改变语言、Cgen、
驻留实现、XRT、时间 ABI 或发布产物。不删对象／源文件，不以 O0 对象
替代原本要求真正 O2 编译驻留源的测试。

## 实现和约束

在现有原生进程助手新增 `Invoke-XlirGccToLog`，仅为 GCC 提供明确入口：

- 参数为逻辑 argv；调用方的 C 字符串宏显式使用 `-RawArgument`。
- GCC 响应文件逐项引用、转义反斜杠和引号，不把所有值当路径替换斜杠。
- 拒绝 NUL／CR／LF、嵌套响应文件和覆盖已有日志／响应文件／命令回执。
- 直接启动真实 GCC，异步读取两条流，保存真实退出码；PS5 不会因 stderr
  先抛异常而丢失代码和后续诊断。成功时的 stderr 也保留。
- 回执记录完整 argv、工作目录、响应文件、助手及编译器哈希，并做事后
  复核。结构化返回使用真实 stdout／stderr／exitCode，不提供替代 compiler。
- 编译有限超时并清理本次进程树；原有 Check 封装的 120 秒上限保留。

16 份 worker 的 GCC 调用迁移到此入口，原失败断言和测试集合保留。
缺少正式 `release`／`release/include` 搜索路径的相应源编译同时补齐；
已有正确路径的不重复添加。原生进程旧入口不改行为。

## 已完成的验证

PS5／PS7 合计 20 次真实编译：18 个正常构建、2 个预期 `#error` 负例；
18 次程序实际核对 C 字符串字节。覆盖空值、空格、尾空格、反斜杠、内部
引号、Unicode、嵌入 NUL、成功 stderr 和失败码。两端超长用例的逻辑命令
各 130,058 字符，使用 4,000 个宏并检查末端未被截断。

另有 10 次拒绝用例、原参数传输 24 项旧回归；74-worker 库存、每端 194
项角色和 70 项路径赋值检查继续通过。PS5 首轮守卫用默认 ANSI 读取 UTF-8
JSON，导致 Unicode 路径比对失败；只修守卫的显式 UTF-8 读取，原日志保留。

两个隔离坏助手分别故意改写反斜杠、吞掉编译失败码。在两端的 26 次真实
编译中，守卫准确在 C 字节／失败状态见证处拒绝；不是依靠源哈希不同拒绝。
它们只是验证工具本身的负例，不计入标准库覆盖，没有替换任何生产 provider。

另从前后脚本 AST 核对 16 项调用迁移：32 处直接参数记录及 3 个 Check
封装记录保留原逻辑配方、日志目标和失败断言。只允许上述声明头搜索路径
补充，并明确规范化 GCC 等价的 `-I .`／`-I.` 拼写。此为参数元数据验证，
不能冒称对应 worker 已实际通过。
