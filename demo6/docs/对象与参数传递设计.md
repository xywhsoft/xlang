# 对象与参数传递设计

本文固定 DEMO6 的对象身份、参数模式、复制能力、继承多态和 C ABI 口径。

## 1. 核心原则

- `class` 是堆上受管理对象，具有稳定身份和明确生命周期。
- xlang 不提供公开 `struct` 语句；C 值布局由生成的 payload `struct` 和 `union` 承担。
- `union`、标量、`time`、`point<T>` 和 `type` 使用值语义。
- class、容器和 function 是受管理引用；赋值、返回和默认参数传递不复制对象主体。
- `byval` 对受管理引用复制句柄，不复制其指向的对象；被调函数内重新绑定参数不会替换调用方变量。
- `byref` 和 `out` 绑定调用方变量槽，必须在调用点显式标记。
- 对象复制只能通过显式 `copy()` / `clone()` 和对应能力协议发生。
- 不提供 `ref<T>`、公开指针解引用、指针算术或旧值语义兼容分支。

## 2. class 对象模型

普通 class、泛型 class、object 派生 class 和 native-backed class 共用受管理句柄模型：

```xlang
class Node
    Node? next = null
    int value

    create(int value)
        self.value = value
    end
end

Node head = Node(1)
head.next = Node(2)
assert head.next.value == 2
```

规则：

- `Node? next` 保存一个显式可空对象句柄，不在 payload 内递归嵌入完整 `Node`。
- `Node` 默认非空；非空 class 变量和字段必须在读取前确定赋值，不能用隐式
  `null` 补位。需要空状态时必须写 `Node?`。
- `Node()` 或其他匹配的 `create(...)` 才创建对象。
- 对象由 XRT class type descriptor 和 `xvalue` 句柄管理；最后一个引用释放时，析构恰好执行一次。
- 对象句柄自创建起使用 shared 引用计数。shared 只保证句柄生命周期可跨线程保留，不表示成员读写自动线程安全。
- class 字段接收动态容器、静态泛型容器或其他 class 句柄时立即进入 XRT shared 存储；对象发布到全局、闭包、线程、任务或其他共享边界前还会进行防御性发布。
- 捕获闭包的环境使用 XRT 原子引用计数；同一个闭包可被多个 thread/task 同时保留和释放，环境只在最后一个引用释放时销毁。

生成的 C 仍保留透明 payload 布局：

```c
typedef struct XL_Class_Node {
    xvalue next; /* nullable Node handle */
    int64_t value;
} XL_Class_Node;
```

payload `struct` 是编译器和 C 互操作布局，不是 xlang 的第二套公开复合类型。C 可以检查字段布局；对象创建、保留、释放、继承检查和动态派发仍通过 XRT/xlang ABI 完成。

## 3. 继承与多态

```xlang
class Base
    virtual func value() as int
        return 1
    end
end

class Child extends Base
    int number

    create(int value)
        self.number = value
    end

    override func value() as int
        return self.number
    end
end

Child child = Child(42)
Base base = child
array<Base> values = [child, Child(7)]

assert base.value() == 42
assert base is Child
Child checked = base as Child
```

- `Derived` 可安全拓宽为 `Base`，不复制 payload，不发生对象切片。
- `type(value)` 保留精确动态类型；`is` 查询继承关系，`as` 执行 checked downcast。
- virtual 调用根据对象的动态类型派发。
- class 默认相等比较对象身份；`__eq__` 等协议可以提供值比较。

## 4. 自然语义矩阵

| 类型类别 | 默认参数 / 赋值 / 返回 | `byval` | `byref` / `out` |
| --- | --- | --- | --- |
| 标量、`time`、`point<T>`、`type` | 复制值 | 复制值 | 绑定变量槽 |
| `union` | 复制完整值 | 复制完整值 | 绑定变量槽 |
| class / native-backed class / object | 保留同一对象句柄 | 保留同一对象句柄 | 绑定句柄变量槽 |
| array / list / set / dict | 保留同一容器句柄或 backing | 保留同一容器句柄或 backing | 绑定容器变量槽 |
| function | 保留 callable 和闭包环境 | 保留 callable 和闭包环境 | 绑定函数值变量槽 |

对受管理引用而言，默认模式和 `byval` 的对象身份相同。两者的差别只在参数模式元数据和调用约束；都允许修改对象内容，也都只在函数内重新绑定局部参数变量。

## 5. 参数模式

### 5.1 默认与 byval

```xlang
class Box
    int value

    create(int value)
        self.value = value
    end
end

func mutate(Box box)
    box.value = 20
end

func mutateByval(byval Box box)
    box.value = 30       // 仍修改同一对象
    box = Box(40)        // 只重新绑定局部参数
end

Box item = Box(10)
mutate(item)
mutateByval(item)
assert item.value == 30
```

`byval` 不是对象克隆语法。需要独立对象时，调用方或函数体必须显式使用 `copy(value)` 或 `clone(value)`。

### 5.2 byref

`byref` 绑定调用方已有、已初始化、可写的变量槽：

```xlang
func reset(byref int value)
    value = 0
end

func replace(byref Box value)
    value = Box(99)
end

int number = 42
Box box = Box(1)
reset(byref number)
replace(byref box)
```

调用点必须显式写 `byref`，因此变量替换副作用在代码中可见。

### 5.3 out

```xlang
func parse(string text, out int value) as bool
    if text == "42" then
        value = 42
        return true
    end
    value = 0
    return false
end

int result
bool ok = parse("42", out result)
```

- `out` 进入函数后，在完成赋值前不得读取。
- 每个正常 `return` 和函数体正常落空路径都必须已赋值。
- 分支按所有正常出口的赋值交集计算；循环不能单独证明循环后的赋值状态。
- `throw` 等异常出口不要求赋值。
- 继续传给另一个 `out` 参数可完成赋值；传给 `byref` 不视为完成赋值。

### 5.4 共同限制

- `byref`、`out` 参数不能设置默认值。
- 参数模式不能用于 `...` 或 `***` 可变参数。
- `byref`、`out` 不能被闭包捕获，也不能跨 async、generator、线程或任务边界。
- 调用点模式必须与形参一致；普通实参不能隐式匹配 `byref/out`。
- `out` 实参必须是可写变量槽；常量、字面量、临时值和只读属性均不合法。

## 6. 显式复制

```xlang
class Snapshot
derive copy
derive clone

    int value
end

Snapshot source = Snapshot()
Snapshot shallow = copy(source)
Snapshot deep = clone(source)
```

- 普通 class 不因字段看似简单而自动成为可复制对象。
- `derive copy`、`derive clone` 或合法的 `__copy__` / `__clone__` 明确开放复制能力。
- `copy()` 建立浅复制对象；`clone()` 建立深复制对象。
- XRT type ops 为 `copy` 与 `clone` 提供相互独立的操作槽；深复制不会回退为浅复制。
- 自定义 `__copy__` / `__clone__` 返回受管理 class 引用，XRT 将协议结果的 payload 写入新的 record；`return self` 通过 `xvoGetRecordOwner()` 找回当前 payload 的受管理外壳，不制造悬空句柄。
- native-backed class 默认不可复制，禁止通过裸指针 `memcpy` 伪造第二个资源所有者。
- `derive moveOnly` 与复制能力互斥。
- 参数传递、赋值、返回、闭包捕获和容器存储不调用复制协议，只保留受管理引用。

## 7. point 与 point<T>

```xlang
class ImageTag
end

point raw = null
point<ImageTag> image = null
```

- `point<T>` 是静态 opaque pointer 标签，C ABI 与 `point` 一样为 `void*`。
- 标签只用于编译期类型检查，不改变指针大小或运行时数据布局。
- `point<A>` 不能隐式赋值给 `point<B>`；两者都可以保存 `null`。
- xlang 不提供解引用、指针算术和任意标签转换。需要操作指针指向的数据时，通过 extern 函数或 native-backed class 协议进入 C/XRT。

## 8. union 值聚合

`union` 是当前唯一公开的 C 风格值聚合：

```xlang
union NumberBits
    int64 integer
    float64 real
end
```

`union` 使用 C 兼容布局，按值复制和传递，不支持继承、virtual、动态字段和 class 生命周期协议。需要稳定身份、递归关系或资源生命周期时使用 class；需要完整 C 结构体值布局时由 C 定义，并通过 native-backed class 或 extern ABI 暴露。

## 9. 函数签名与元数据

参数模式属于函数签名：

```xlang
func(byref int) setter
func(out int) producer
```

- `byref` 与 `out` 参与重载区分。
- `byval` 与默认模式不能仅凭模式形成重载。
- ABI dump、package 元数据、函数值和闭包调用必须保留参数模式。

## 10. C ABI

| xlang 参数 | C ABI |
| --- | --- |
| 默认/byval 标量或 `point<T>` | 对应 C 标量或 `void*` |
| byref/out 标量或 `point<T>` | 对应 C 指针 |
| 默认/byval class | `xvalue` |
| byref/out class | `xvalue*` |
| 默认/byval union | 对应生成的 C union 值 |
| byref/out union | 对应生成的 C union 指针 |

默认和 `byval` class wrapper 都只保留同一 `xvalue` 对象引用，不调用 `__copy__`。C 侧可以通过 XRT type descriptor、record data、retain/unref 和 class relation API 检查与管理对象。可选参数导出到 C 时默认值失效，但参数模式仍进入元数据。

## 11. 验收要求

- class 赋值、参数、返回、闭包、字段和容器保持对象身份，析构恰好一次。
- 自引用 class 字段使用显式 nullable 句柄，不递归构造、不栈溢出；裸 `Node next`
  必须由初始化器或每条构造路径完成赋值。
- `Base = Derived`、virtual 派发、`is/as` 和 `array<Base>` 全链路通过。
- 默认和 `byval` class/容器参数的成员修改可见，局部重新绑定不可见。
- `byref/out` 覆盖标量、class、容器、function 和 `point<T>` 变量槽。
- `copy/clone` 仅对显式声明能力的 class 生效；native-backed class 不允许裸指针复制。
- `point<A>` / `point<B>` 严格区分，且都接受 `null`。
- XAPI/ABI、生成头文件、C 宿主和 xlang 函数值对参数模式给出一致结果。
