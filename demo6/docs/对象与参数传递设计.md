# 对象与参数传递设计

本文固定 DEMO6 的对象身份、值语义、参数模式、继承多态和 C ABI 口径。

## 核心原则

- `class` 表示有对象身份和生命周期的对象，默认使用受管理引用语义。
- `struct` 表示 C 兼容的值聚合，默认按值复制和传递。
- 容器是有共享存储身份的运行时对象，默认使用引用语义。
- 标量、`time`、`point`、`type`、`struct`、`union` 默认使用值语义。
- 参数默认采用类型的自然语义；只有需要覆盖自然语义时才写 `byval`、`byref` 或 `out`。
- 不提供额外的公开引用包装类型，也不保留历史兼容语法。

## class 引用语义

普通 class、泛型 class、object 派生 class 和 native-backed class 使用同一套受管理句柄：

```xlang
class Base
    virtual func value() as int
        return 1
    end
end

class Child extends Base
    int number

    create(int value)
        self.number = value
    end

    override func value() as int
        return self.number
    end
end

Child child = Child(42)
Base base = child
array<Base> values = [child, Child(7)]

assert base.value() == 42
assert base is Child
Child checked = base as Child
```

赋值、默认参数传递、函数返回、字段保存、闭包捕获和容器存储都保留同一个对象身份。`Derived` 可安全拓宽为 `Base`，不发生对象切片。对象由引用计数管理，最后一个拥有者释放时执行一次析构。

class 句柄发布到全局、线程、异步任务或其他共享边界前，编译器会把对象拥有的动态容器和静态泛型容器提升为 XRT shared 模式。动态值使用 `xvoMoveToShared`，静态容器分别使用 `xrtTypedArrayMoveToShared`、`xrtTypedListMoveToShared`、`xrtTypedSetMoveToShared`、`xrtTypedDictMoveToShared`。已经共享的容器保持原句柄，本地容器只在发布时创建共享副本，避免每次字段访问重复复制。

## 自然语义矩阵

| 类型类别 | 默认赋值/传参 | `byval` | `byref` / `out` |
| --- | --- | --- | --- |
| 标量、`time`、`point`、`type` | 复制值 | 与默认相同 | 绑定调用方变量槽 |
| `struct`、`union` | 复制完整值 | 与默认相同 | 绑定调用方变量槽 |
| class / native-backed class / object | 共享对象 | 按复制协议建立独立对象 | 绑定保存对象句柄的变量槽 |
| array / list / set / dict | 共享容器存储 | 独立浅副本 | 绑定保存容器句柄的变量槽 |
| function | 共享 callable/闭包环境 | 复制 callable 句柄 | 绑定函数值变量槽 |

容器 `byval` 的浅复制只分离外层容器；其中保存的 class、function 或嵌套容器仍按各自引用语义保留身份。需要递归复制内容时使用标准库 `clone()`。

## 参数模式

### 默认模式

未写模式时采用自然语义：

```xlang
func setNumber(int value)       // int 按值
end

func mutate(Box value)          // Box 共享对象
    value.number = 10
end
```

### byval

`byval` 强制创建独立语义副本：

```xlang
func mutateCopy(byval Box value)
    value.number = 10
end
```

class 必须具备 `derive copy`、`derive clone` 或合法的 `__copy__` 协议。move-only 或仅管理外部资源且未声明复制协议的 class 不能作为 `byval` 参数。

### byref

`byref` 绑定调用方已有、已初始化、可写的变量槽：

```xlang
func reset(byref int value)
    value = 0
end

int number = 42
reset(byref number)
```

调用点必须显式写 `byref`。这使函数对调用方变量的替换行为在代码审阅时可见。

### out

`out` 是写出参数：

```xlang
func parse(string text, out int value) as bool
    if text == "42" then
        value = 42
        return true
    end
    value = 0
    return false
end

int result
bool ok = parse("42", out result)
```

- 进入函数后，在完成赋值前不得读取 `out` 参数。
- 每个正常 `return` 和函数体正常落空路径都必须已赋值。
- `if/elseif/else` 按所有分支的赋值交集计算。
- 循环体可能一次也不执行，因此不能单独证明循环后的赋值状态。
- `throw` 等异常出口不要求先赋值。
- 将参数继续传给另一个 `out` 参数可完成赋值；传给 `byref` 不视为完成赋值。

## 限制

- `byref`、`out` 参数不能设置默认值。
- `byval`、`byref`、`out` 不能用于 `...` 或 `***` 可变参数。
- `byref`、`out` 不能被匿名函数或闭包捕获。
- 带 `byref`、`out` 的函数不能声明为 async 或 generator，也不能跨线程/任务边界。
- 调用点标记必须与形参完全一致；普通实参不能隐式匹配 `byref/out`，反之亦然。
- `out` 实参可以是未初始化变量，但必须是可写变量槽；常量、字面量、临时值和只读属性均不合法。

## struct 值聚合

```xlang
struct Pair
    int x
    int y

    union
        int flags
        uint rawFlags
    end
end
```

`struct` 采用 C 兼容布局和值语义，不支持继承、virtual、动态字段、class 协议或 class 生命周期。字段不能使用需要独立生命周期管理的类型。函数可以按值接收和返回 struct，也可以通过 `byref/out` 映射为 C 指针。

## 函数类型、重载与元数据

参数模式属于签名：

```xlang
func(byref int) setter
func(out int) producer
```

- `byref` 与 `out` 参与重载区分。
- `byval` 与默认模式不能仅凭模式形成重载，因为对标量二者 ABI 等价，且对引用类型仅影响函数入口复制行为。
- XAPI、ABI dump 和 package 元数据必须持久化每个参数的模式。
- 闭包与函数值调用必须执行与命名函数相同的调用点标记和变量槽校验。

## C ABI

| xlang 参数 | C ABI |
| --- | --- |
| 默认/byval 标量 | 对应 C 标量 |
| byref/out 标量 | 对应 C 标量指针 |
| 默认/byval class | `xvalue` |
| byref/out class | `xvalue*` |
| 默认/byval struct/union | 对应生成的 C 值类型 |
| byref/out struct/union | 对应生成的 C 类型指针 |

class 的 `byval` wrapper 在进入 xlang 函数前调用复制协议，C 侧仍传入 `xvalue`。可选参数导出到 C 时默认值失效，但参数模式不会失效。

## 验收要求

- class 赋值、参数、返回、闭包、字段和容器保持身份一致且析构恰好一次。
- `Base = Derived`、virtual 派发、`is/as` 和 `array<Base>` 全链路通过。
- 四类容器均覆盖默认共享、`byval` 浅复制、`byref` 重新绑定和 `out` 写出。
- `out` 的分支、循环、提前返回、异常出口、转发和读前写负例完整覆盖。
- struct 覆盖布局、字段、内联 union、参数、返回、`byref/out` 和生成头文件。
- 命名函数、函数值、XAPI、package 和 C ABI 对参数模式给出一致结果。
