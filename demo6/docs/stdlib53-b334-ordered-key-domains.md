# OrderedMap 原生键域与泛型合同

OrderedMap 的 C ABI 标量键保留实际槽宽度，bytes 键按完整字节内容排序。
两者复用 XRT typed tree 的存储与平衡算法；Cgen 只渲染已经闭合的 IR 布局，
不生成比较算法，也不按源码拼写回推键类型。

## 统一键分类

`xl6IrOrderedKeyAbi` 是直接操作、嵌套 Sequence 配方、lowering 和验证器共用的
键域分类。C 标量使用其实际原生描述符，包括 Windows 与 Linux 宽度不同的
long、wchar 和指针宽度整数；不能用 int64 读取较窄的键槽。
浮点描述符沿用 XRT 的规范全序。

bytes 使用独立的按需原生 codec。私有 Tree 布局升级为 `XL6_TreeLayoutV2`，
把逻辑 Array 准入域与有序键存储 codec 明确分开。codec 必须验证非空 bytes
准入域，不能用 ANY、nullable bytes、字符串或带其他名义身份的二进制值替代。
普通整数树没有该 codec 的原生工厂依赖。
这是发布前的私有 ABI 改版：旧生成 C／模块须重新编译，不保留 V1 布局别名。

## bytes 值与拥有关系

XRT bytes Value 是不可变原子，xlang 的索引写入创建新值并替换绑定。
树键和查询／投影结果可 O(1) 共享不可变 Value；这不暴露语言层引用，也不
允许外部修改已存键的内容。原生比较按无符号字节词典序处理 NUL、前缀和
0xff，不调用 strlen，不创建字符串转接。

树的拥有图同时追踪实际 bytes 键槽与引用值槽。克隆、查询、keys 投影、
清空和分阶段退役都保留相同的拥有合同；没有逐键投影临时分配。

## 泛型与多返回值

开放模板保留精确的逻辑方法签名，不能冒充有本地槽 ABI 的物理操作。
普通 Tree 成员与键／值投影共用逻辑签名，查询保留既有结果合同；实例化后
重新验证真实键域、传输、错误与所有权信息。

模板中的 `(K, V)` 尚无 C 载体时，多变量声明仍有两个逻辑绑定。
作用域与清理规划按这些绑定处理，物理 product 及其清理由实例化后重建；
不能把它误当成 symbol 为零的单个变量。

## 验收边界

前端诊断使用隔离 IR 对象核对全部 322 项清单，仅用于集中发现问题。
正式验收要求真实双平台产品、JIT／模块／迁移目录后的独立 AOT、严格 C、
原生故障前缀、IR 拒绝对照及按需闭包证明，不能用诊断编译器替代。
完整 53 模块任务与其他键域仍须独立完成，对象池继续放在最后。
