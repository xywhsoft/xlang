## 总体判断

这段时间的推进是实质性的：图算法、CSV、正则、压缩、HTTP、邮件、SSH、GUI 和 AI
已有不同程度的真实实现。**当前主要问题已经不是包数量不足，而是语言声明、原生后端、
编译器、运行库、测试和交付资料没有在同一个发布构建上一起收口。**

不能继续把已有 HTTP/邮件/SSH 后端当作占位重写；也不能因为一个包有源码、import
成功或名称查询测试通过，就将它算作完整可用产品。

本报告按三个维度区分状态：实际实现范围、当前构建运行结果、专项验收范围。
下面的分层存在交集，不应相加为完成数量，更不能直接换算全生态完成率。

反复创建释放测试，并统一手写 XRT 声明与内存管理路径。

## 优先处理的共性问题

1. **C/XL 原型。** 明确 C int、长整型、size_t、bool、指针 const、返回值和析构签名。
   ONNX 的 C int 被声明为 XL int，color 的 long long 被声明为 bool，HTTP 原生析构
   有返回值而语言析构没有。应把实际生成原型与公开 C 头一起编译验证，不能关掉检查或强转隐藏。
2. **所有权。** chardet 的静态名称被 takeCstr 释放问题已经修复，不能继续算作当前失败。
   还需横向核查其他库的 borrowed/owned 字符串、回调和析构合同；color、semver、units
   的静态环形结果缓冲是待验证的并发/保留期风险，不以单线程用例通过代替验证。
3. **错误合同。** CSS/HCL 的 validate(false) 带出 XRT error；FIX/PKCS 等异常类型与
   测试预期不同。先统一“正常 false / 无结果 / 协议无效 / 系统失败”，不能吞掉 OOM 和资源超限。
4. **运行库桥与 XLIR。** os.args、time、TLS lease 的缺符号，以及 HTTP 的可达未终结块、
   async 挂起结果 ABI，属于编译器/运行库联动问题，不能全部归类为包未实现。
   CSV 暴露的默认参数异常清理及泛型实例化已在当前源码完成扩展补测；
   正式程序未包含修复，两个构建的结果必须分开跟踪，其他共享缺口不能据此结案。
5. **字节与文本。** LZ4/LZMA/miniz/Snappy 的文本长度声明已改用 byteLen，不能继续列为未修改。
   共享的含 NUL 字符串截短、class 字段迭代问题仍存在。join、chars/bytes 和文本桥在此前源码专项中
   已接通，正式程序尚未更新；不能因字符串常规用例通过而忽略长度和拥有权问题。
   统一补中文、二进制、Buffer、分块测试。
6. **真实客户端与 Agent 边界。** Memcached 用一次 recv 当完整应答，空值/未命中混同；
   Agent 工作区仅文本前缀判断，读限额在整文件读取后按字符截断。辅助函数通过不能覆盖这些风险。

## 建议推进顺序

1. 首先完成全生态 C/XL 原型、所有权、错误和共享桥接一致性检查；修复时联动同类库，
   但逐包验证，不能假定一个声明修正就自动让整个依赖族达标。

   等受共享 NUL/字段迭代边界影响的部分，补 cString/floatEnv 的登记与平台/线程边界。
3. 恢复 BSON 的运行库桥，完成 LZMA/miniz/Snappy/Zstd 的标准格式互操作及 Unicode/二进制、
   回调、取消、OOM、文件事务和双语范例专项；LZ4 按其剩余供应链/平台边界继续验收，
   不重复列为尚未接入标准 Frame。
