# 动态方法的精确标量与绑定签名合同

本批把动态方法的标量参数及返回字段接到已有函数桥接编解码。
支持语言标量、char、float32、平台 C 标量、type 和对应可空载体；
不增加公开标准库函数或语言语法。

## 统一 IR 合同

每个标量形参登记一个闭合 codec，每个返回字段保留一个明确的
codec 槽位；非标量字段以显式空槽保留原有拥有合同。单返回和
多返回共用同一字段规则，不把多返回包装成隐式 Array。

codec 记录源类型、实际值类型、presence、读入、装箱、整数域、
原生平台 profile 和销毁规则，复用函数桥接的计划构造及 C 发射器。
旧的标量 getter／boxing 分支已移除；Cgen 不从源码名字反推类型。
IR 验证器检查完整 arena 顺序、槽位数量、类型域和签名，坏合同
不得输出 C 或头文件。

原生标量的候选匹配使用纯检查接口，不分配、不修改线程错误，
不把有损转换当成匹配。真正读入复用已有 checked 接口，失败不
发布输出。C long、wchar 等宽度及符号性以目标平台实际 ABI 为准。
float32 动态读入保持无损规则，不替代显式 float32(x) 的舍入语义。

可空标量支持默认 null、显式 null 及 checked 默认程序；presence
与底层身份分离。结果字段逐一装箱，原有字符串、bytes、Future、
函数和引用 owner 在成功／失败边界继续按既有合同退役。

## 绑定方法的身份

同一运行时接收者类型下只有一个声明的方法，登记完整公开函数
签名，并在绑定值上附着其精确身份。命名参数、默认值、变长形式
及返回表示仍来自验证过的 IR；异步公开签名仍返回 Future。

重载组不猜测某个具体签名，原生集合的泛化绑定也保持 erased。
它们继续按实际调用帧分派；恢复为一个确定的 typed 函数时 checked
拒绝。单声明方法同样拒绝错误目标签名，拒绝前不得进入方法体。

创建绑定值失败时清理新装箱值、closure 与尚未转移的接收者环境，
保留首个 checked 失败，包括没有诊断对象的失败；不以新的
MemoryError 覆盖原失败。

驻留声明和组件依赖由各自精确 need 选取，不依赖旁边是否存在
boxed callable adapter。动态 Stack 使用共享标量 codec，原生集合
绑定显式保持 erased 身份，不引入假的确定签名。

## 验收范围

Windows、Linux 普通与 Linux 指定插桩通道各完成 322 个阶段，
包含严格 C O0／O2、JIT、模块、AOT、确定性生成、独立裁剪产物
及既有 Future／函数／默认值／Stack 回归。1322 个坏 IR 反例均在
C／头文件输出前拒绝；故意删除绑定身份的实现被运行负控检出。

O0／O2 各完成普通标量 102、可空标量 27、错误边界 48 个同步
分配前缀，首次未命中点分别为 101、26、47。所有命中须以
MemoryError 失败，无宽松恢复例外，正常、失败及退役后账本平衡。
原生纯匹配覆盖 21 个平台 profile，在 fail-after-zero 下零分配并
保留原错误；读取同时验证非对齐输出。方法体前拒绝错误值、
错误函数签名及不确定重载绑定；正常重载仍按实际调用帧分派。

双平台各 310 个三组夹具通过严格编译，驻留目录各验证 306 个
组件、1512 个精确导出、93636 对依赖闭包及 23 个拒绝负控。
双平台另各完成 6 个 Typed／Lowered JSON 阶段，核对参数 codec、
返回字段、空槽及绑定签名引用；Typed 阶段不伪造 lowered 元数据。
三份独立裁剪产物通过构建、运行及符号核对；标量程序不引入无关
process／regex／file 模块，数组展开程序排除 Dict 提供方。

插桩仅覆盖生成 C 和测试宿主，不代表所有驻留提供方插桩。
冻结源码证据位于 `E:/xlang-validation/stdlib53-b293-*` 及 Linux
对应目录；失败的早期诊断报告不作为验收或发布证明。

## 范围与剩余工作

异步多返回值按用户决定继续由语义检查禁止，保留专门负例，留作
后续语言结果载体设计，不属于本轮标准库接入的阻塞项。

动态 C 标量结果再经 c_int(var) 等显式原生构造的路径仍待接入；
本批验证的是方法参数、动态装箱结果和确定签名绑定，不把该缺口
冒充完成。其余动态／Native 组合、工作线程／对象图故障、模块
组合／真实卸载、时区及 CLI／DLL／VFS／RC0 发布总验收继续。
53 模块目标不结项，CRT 0、XRT 19 组未决策与对象池最后不变。
