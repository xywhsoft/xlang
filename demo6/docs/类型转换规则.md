# 类型转换规则

本文档是 DEMO6 类型转换的正式口径。后续实现和重构必须以本文档为准，不从 DEMO5 或早期兼容写法继承额外转换规则。

## 总原则

- 普通赋值、函数实参匹配、返回值匹配只允许精确类型匹配、明确的安全拓宽转换、安全的 class 向上转换、`null -> point`、以及生命周期允许的装箱到 `var`。
- 可能丢失信息、改变语义或依赖解析规则的转换，必须显式写成类型构造/转换函数，例如 `int(x)`、`float(x)`、`string(x)`。
- `as` 是运行时检查转换语法，用于 `var` 取出具体类型和 class checked downcast，不承担数字转换职责。
- `xvoGetInt`、`xvoGetFloat`、`xvoGetText` 等 XRT getter 是宽松取值 API，不等于 xlang 的隐式转换规则。
- 编译器语义检查、重载解析、代码生成和 XRT 层转换 API 必须保持同一套边界。

## 转换分类

### float32 显式缩窄

`float32(x)` 的浮点缩窄正常舍入；有限值超出目标范围抛 `RangeError`，
NaN 与正负 Infinity 保留。普通 double、`c_double`、动态浮点值和
字符串解析使用同一缩窄规则。字符串按实际字节长度解析，内嵌 NUL
不截断，非法数字文本抛 `ValueError`。动态显式标量转换复用 XRT，
不把非标量或 bytes 当作数字文本。typed callable／容器读取仍要求
精确类型与无损值，不以显式转换代替准入校验。

### 精确匹配

源类型与目标类型完全一致时允许通过，包含：

- 基础类型：`bool`、`int`、`int8`、`uint8`、`int16`、`uint16`、`int32`、`uint32`、`int64`、`uint64`、`char`、`float`、`float32`、`float64`、`string`、`bytes`、`time`、`point`。
- C ABI 类型：`c_int`、`c_uint`、`c_long` 等同名精确匹配。
- 函数类型：签名完全匹配。
- 容器类型：泛型参数完全匹配。
- class/native-backed class/union：同一声明类型匹配。

### 安全拓宽转换

安全拓宽表示目标类型能够无损表达源类型的所有合法值。

整数规则：

- 有符号整数到有符号整数：目标位宽大于或等于源位宽。
- 无符号整数到无符号整数：目标位宽大于或等于源位宽。
- 无符号整数到有符号整数：目标位宽必须严格大于源位宽。
- 有符号整数到无符号整数：不作为普通隐式转换。
- `bool` 可以安全拓宽到整数和浮点类型。
- `char` 保存 Unicode scalar。`char -> int/uint32/int64/uint64` 可以无损读取其码点；与整数进行比较时也比较码点，所以 `'A' == 65`。
- 整数进入 `char` 是受检查转换：合法 scalar 成功，负数、surrogate 和大于 `0x10ffff` 的值抛 `RangeError`。这是语言为 `char` 特设的校验边界，不是任意 `uint32` 到 `char` 的无条件位复制。
- 包含 `char` 的算术表达式返回普通 `int` 或 `float`，不会从算术结果直接制造未经检查的 `char`。

浮点规则：

- `float32` 可以安全拓宽到 `float64` / `float` / `c_double`。
- `float64` / `float` / `c_double` 不可隐式缩窄到 `float32` / `c_float`。

整数到浮点：

- 普通隐式转换不允许整数到浮点。
- 原因是 `int`/`int64` 到 `float`/`float64` 不能保证所有整数精确表示。
- 需要时使用显式转换：`float(x)`。

C ABI 类型：

- `c_*` 类型按当前目标 C ABI 的 `sizeof(type) * CHAR_BIT` 和符号性参与安全拓宽判断。
- `c_long`、`c_size`、`c_ptrdiff`、`c_intptr` 等平台相关类型不硬编码 Windows 或 Linux 宽度。
- `c_wchar` 按目标 C ABI 的 `wchar_t` 宽度和符号性判断。

字面量例外：

- 整数字面量可以进入任意整数目标类型，但必须能在编译期判定位于目标类型范围内。
- 没有无符号目标上下文时，整数默认按有符号 `int64` 解释；`auto` 和 `var` 不会把超出 `INT64_MAX` 的字面量静默提升或环绕。
- `uint64 value = 18446744073709551615` 这类具有明确无符号目标的声明合法；超出目标类型范围仍在语义阶段报错。
- 例如 `int8 a = -8`、`uint8 b = 255` 合法；`uint8 c = -1`、`int8 d = 128` 非法。
- 整数字面量进入 `char` 时必须在编译期就是合法 Unicode scalar。
- 浮点字面量可以进入浮点目标类型；后续可继续补充浮点范围诊断。

### 数值表达式的公共类型

- `<<`、`>>` 的结果类型固定为左操作数的整数类型；右操作数只表示移位数量。
- 其他算术和位运算优先将可在编译期证明范围合法的整数字面量归入另一侧整数类型。
- 非字面量操作数只在其中一侧能够安全拓宽到另一侧时形成公共类型，结果采用拓宽后的类型。
- 双方不存在安全公共类型时必须显式转换，不因表达式上下文放宽本章的转换规则。
- 因此 `int64Value + 1`、`uint64Value & 0xFF` 合法，而 `int64Value + floatValue` 仍需调用者显式选择目标类型。

### 空值转换

- `null -> point` 允许作为普通隐式转换，表示空指针。
- `null` 到数字、字符串、时间等类型不作为普通隐式转换。
- 显式转换中可以按目标类型默认值处理，例如 `int(null)`、`string(null)`。

### 装箱到 var

`var` 是动态值类型。普通匹配允许符合生命周期规则的值装箱到 `var`：

- 基础值类型可以装箱。
- `char` 在 `var` 中保留独立动态类型；`bytes` 作为带显式长度的受管理二进制值装箱，不转换为 `string`。
- 容器、函数、class、native-backed class 需要遵守各自的生命周期和所有权规则。
- `var` 到具体类型不会自动发生；必须使用 `as` 或显式转换。

### class 继承转换

- `Derived -> Base` 是安全的隐式向上转换，适用于赋值、实参、返回值、字段和静态泛型容器元素。
- 转换只调整受管理句柄的静态视图，保留对象的真实动态类型、身份和 virtual 派发，不复制或切片对象主体。
- `Base -> Derived` 不会隐式发生；必须使用 `as Derived` 执行 checked downcast。

### 显式构造转换

显式转换使用类型名调用：

```xlang
int a = int("42")
float b = float(3)
string c = string(123)
time d = time("2026-06-18")
char e = char(0x4f60)
```

显式转换可以包含解析、格式化、截断、默认值等语义，因此必须由调用者写明意图。

## XRT 层统一 API

XRT 提供统一转换 API，供 C 和 xlang 共同使用：

```c
#define XRT_TYPE_CONVERT_EXACT       0x00000001u
#define XRT_TYPE_CONVERT_SAFE_WIDEN  0x00000002u
#define XRT_TYPE_CONVERT_EXPLICIT    0x00000004u

bool xrtTypeCanWiden(const xrt_type_desc* src, const xrt_type_desc* dst);
bool xrtTypeCanConvert(const xrt_type_desc* src, const xrt_type_desc* dst, uint32 flags);
bool xrtTypeConvertValue(const xrt_type_desc* dstType, ptr dst, const xrt_type_desc* srcType, const ptr src, uint32 flags);
bool xrtValueConvertTo(xvalue value, const xrt_type_desc* dstType, ptr dst, uint32 flags);
```

API 语义：

- `xrtTypeCanWiden`：只判断 XRT 运行时基础类型的安全拓宽。
- `xrtTypeCanConvert`：按策略位判断精确匹配、安全拓宽、显式转换是否允许。
- `xrtTypeConvertValue`：在 C 对象和 C 对象之间转换，调用前会检查策略。
- `xrtValueConvertTo`：从 `xvalue` 转换到 C 对象，调用前会检查策略。

XRT 的运行时类型只有规范基础类型，例如 `int` 表示 `int64`，`float` 表示 `double`。`int8`、`uint16`、`float32` 等 xlang 静态宽度类型由 xlang 编译器在语义层判断，再映射到生成 C 代码。

## 禁止的隐式转换

以下转换不允许作为普通隐式转换：

- `string -> int/float/bool/time`。
- `string <-> bytes`；文本编码和二进制解码必须使用显式 API。
- `int/float/bool/time/point -> string`。
- `float -> int`。
- `int64/int -> float/float64`。
- `float64/float -> float32`。
- 有符号整数到无符号整数。
- 位宽缩窄，例如 `int64 -> int8`、`uint32 -> uint16`。
- `uint64 -> int64/int`。
- `var -> concrete`。
- 容器元素类型自动转换，例如 `array<int>` 自动变为 `array<float>`。
- class 对象切片和隐式 downcast。

## 与重载解析的关系

重载解析按匹配成本排序：

- 精确匹配优先。
- 安全拓宽次之。
- class 继承距离越短，向上转换成本越低。
- 装箱到 `var` 成本更高。
- 显式转换不参与普通重载解析，必须由用户写在调用点。

这可以避免 `foo(int8)`、`foo(int64)`、`foo(var)` 等重载在存在宽松转换时产生不可预测选择。
