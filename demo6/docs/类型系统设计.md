# xlang DEMO6 class 与 native-backed class 设计

本文档记录 DEMO6 当前阶段的 `class` 与 native-backed class 设计。

当前阶段不设计动态对象基类，不引入动态字段、缺失字段元方法、反射式成员查找、统一动态 header 或 method table。

## 1. 总原则

`class` 与 native-backed class 必须服从 DEMO6 第一绝对原则：xlang 能够和 C 完美混编。

因此：

- `class` 是 xlang 自有结构体类型，用来扩展 C 语言的结构体与方法语义。
- native-backed class 是使用 `class`、`native point handle` 和 `extern` 成员声明表达的 C 黑盒句柄类型，用来把 C API 零成本映射成 xlang 的 OOP 调用外观。
- 二者都不默认承担动态对象开销。
- 方法调用必须尽量 lowering 到普通 C 函数调用。
- 类型布局、生命周期、C 符号映射都必须显式、稳定、可检查。

## 2. DEMO5 可参考点

DEMO5 中可保留为参考的点：

- `class Name ... end` 是 DEMO6 唯一的类声明入口；旧 `custom Name ... end` 不再是语言语法。
- `extends` 可以表达单继承。
- `create` / `destroy` 能表达构造和析构。
- 方法写在类型体内，调用写成 `value.method(...)`，符合 xlang 预期。
- 原 custom 的 extern 绑定思想很适合表达 C API 绑定，但 DEMO6 语法归入 native-backed class。

DEMO5 中不建议沿用的点：

- custom 与动态对象 runtime 绑定太深。
- custom 暴露 `payload` 字段，导致黑盒 C 句柄变成可随意读写的动态状态。
- class、native-backed class、动态字段、引用计数、弱引用、循环收集混在一起，稳定性成本高。
- DEMO5 中让普通结构体类继承动态对象基类的写法，会把简单 class 也拖入动态对象体系。

DEMO6 的取舍：

- class 回到结构体模型。
- native-backed class 回到黑盒句柄模型。
- 动态对象能力后续单独设计，不进入当前 class/native-backed class 方案。

## 3. class 定位

`class` 表示 xlang 自有结构体类型。

核心能力：

- 字段。
- 方法。
- 单继承。
- 构造函数。
- 析构函数。
- C 兼容布局。

不包含：

- 动态字段。
- 反射式方法查找。
- 运行时 method table。
- 自动装箱。
- 默认引用计数。
- 默认 GC 或循环收集。

示例：

```xlang
class Vec2
    int x = 0
    int y = 0

    create(int x, int y)
        self.x = x
        self.y = y
    end

    func length2() as int
        return self.x * self.x + self.y * self.y
    end
end

auto v = Vec2(3, 4)
auto n = v.length2()
```

## 4. class 字段

字段使用 DEMO6 统一的类型前置声明。

```xlang
class User
    int id = 0
    string name = ""
end
```

规则：

- 字段语法为 `Type name` 或 `Type name = default`。
- 字段名不能与同一 class 内的字段、方法、构造/析构入口冲突。
- 字段默认值必须能赋给字段类型。
- 第一阶段建议默认值只允许静态表达式。
- 没有显式默认值时，使用类型默认值初始化。

不采用 DEMO5 的成员字段写法：

```xlang
var x as int
```

## 5. class 方法

class 方法写在 class 体内。

```xlang
class Counter
    int value = 0

    func add(int step) as int
        self.value += step
        return self.value
    end
end
```

规则：

- 方法声明使用普通 `func` 语法。
- 方法体内自动注入 `self`。
- `self` 表示当前实例。
- `self` 不能重新赋值。
- 方法调用 `a.add(1)` 静态解析为已声明方法。
- 找不到方法时编译期报错，不做动态查找。

期望 lowering：

```xlang
a.add(1)
```

```c
xl_class_Counter__add(&a, 1);
```

其中 C 函数名只是示意，最终名称必须服从 DEMO6 的 C 符号稳定编码规则。

## 6. class 构造

构造函数使用 `create`。

```xlang
class Point
    int x
    int y

    create(int x, int y)
        self.x = x
        self.y = y
    end
end

auto p = Point(1, 2)
```

规则：

- `Type(...)` 表示构造该类型。
- `create(...)` 没有返回类型。
- 可以重载多个 `create`，重载规则与普通函数一致。
- 如果没有声明 `create`，编译器生成默认构造：按字段默认值初始化。
- 字段初始化先执行，再执行用户 `create` 体。

不引入 `new` 作为第一阶段 class 构造方式。

## 7. class 析构

析构函数使用 `destroy`。

```xlang
class Buffer
    point handle

    destroy()
        // 释放 handle
    end
end
```

规则：

- `destroy()` 没有参数，也没有返回类型。
- 拥有 `destroy` 的 class 需要编译器生成离开作用域时的清理调用。
- 清理必须覆盖正常离开、`return`、`break`、`continue` 等路径。
- 错误处理设计完成后，清理规则还必须覆盖异常路径。
- 第一阶段不引入 `delete` 作为用户手写释放语句。

复制规则：

- 没有 `destroy` 且字段都可复制的 class，默认允许按值复制。
- 有 `destroy` 的 class，默认视为不可复制。
- 含有不可复制字段的 class，默认也不可复制。
- 如果后续需要复制资源，必须显式设计 `clone` 或 copy 构造，不做隐式猜测。

## 8. class 继承

DEMO6 第一阶段只支持单继承。

```xlang
class Point2
    int x
    int y
end

class Point3 extends Point2
    int z
end
```

期望 C 布局：

```c
typedef struct XL_Class_Point2 {
    int64_t x;
    int64_t y;
} XL_Class_Point2;

typedef struct XL_Class_Point3 {
    XL_Class_Point2 base;
    int64_t z;
} XL_Class_Point3;
```

规则：

- 父类布局必须是子类布局前缀。
- 子类可以直接访问继承字段，例如 `p.x`。
- 子类构造时，如果父类存在无参 `create`，可自动调用。
- 如果父类构造需要参数，子类 `create` 内必须显式调用 `base(...)`。
- 析构顺序为：先执行子类 `destroy`，再执行父类 `destroy`。
- 第一阶段不设计虚方法和 late dispatch；下一批 `virtual` 动态派发口径见 `class_object协议设计.md`。

示例：

```xlang
class Base
    int seed

    create(int seed)
        self.seed = seed
    end
end

class Child extends Base
    int value

    create(int seed, int value)
        base(seed)
        self.value = value
    end
end
```

## 9. class 与 C

`class` 的生成方向应尽量是可读 C struct。

建议生成：

```c
typedef struct XL_Class_Vec2 {
    int64_t x;
    int64_t y;
} XL_Class_Vec2;

static int xl_class_Vec2__create(XL_Class_Vec2* self, int64_t x, int64_t y);
static int64_t xl_class_Vec2__length2(XL_Class_Vec2* self);
```

规则：

- class 方法 C 侧第一个参数是实例指针。
- class 构造 C 侧第一个参数也是实例指针。
- class 析构 C 侧第一个参数也是实例指针。
- 不默认把 class 作为 C ABI export 类型。
- 如果要暴露给 C，应通过 `export "c_symbol" func ...` 写明确 wrapper。

## 10. native-backed class 定位

DEMO6 已把原 `custom` 的零成本 C opaque handle 能力并入 `class`。

公开语言模型中只有一套 class：

- 普通 class：由 xlang 定义字段布局和方法。
- object class：普通 class 继承标准库 `object` 后获得动态字段能力。
- native-backed class：普通 class 内声明 native 资源，并把 C 函数绑定为成员函数或协议函数。

`custom` 不再作为独立用户侧类型系统继续扩展，也不再提供用户语法入口；历史文档中出现的 custom 只表示旧设计来源，新设计以 native-backed class 为准。

示例 C API：

```c
typedef struct image image;

xptr image_open(const char* path);
int64_t image_close(xptr self);
int64_t image_width(xptr self);
int64_t image_resize(xptr self, int64_t w, int64_t h);
```

对应 xlang：

```xlang
class Image
    native void* handle

    extern "image_open" func __create__(string path)
    extern "image_close" func __destroy__()
    extern "image_width" func width() as int
    extern "image_resize" func resize(int w, int h) as int
end

auto img = Image("a.png")
auto w = img.width()
img.resize(320, 240)
```

期望 lowering：

```c
XL_Class_Image img;
img.handle = image_open("a.png");
w = image_width(img.handle);
image_resize(img.handle, 320, 240);
image_close(img.handle);
```

## 11. native 结构

native-backed class 仍是 class，可以同时拥有 xlang 字段和 native 资源字段。

建议生成：

```c
typedef struct XL_Class_Image {
    xptr handle;
    xstring path;
} XL_Class_Image;
```

规则：

- `native` 字段表示 C 侧资源句柄或 C 暴露的数据指针。
- native 字段可以是 `void*`、`point`、C ABI 指针类型或后续明确支持的 typed pointer。
- native 字段参与 class 布局，但默认不建议向 xlang 普通代码直接暴露。
- 需要公开底层指针时，应提供显式方法，例如 `handle()`、`detach()`、`valid()`。
- native-backed class 可以声明普通 xlang 字段、普通方法、属性、协议方法和静态成员。
- native-backed class 可以继承普通 class；如果继承涉及 native 资源，析构顺序必须明确。

## 12. native-backed 生命周期

构造和析构统一使用 class 协议函数。

```xlang
class File
    native void* handle

    extern "file_open" func __create__(string path, string mode)
    extern "file_close" func __destroy__()
end
```

C ABI 方向：

```c
xptr file_open(const char* path, const char* mode);
int file_close(xptr self);
```

规则：

- extern `__create__` 对应的 C 函数返回 native 句柄或初始化实例。
- extern `__destroy__` 对应的 C 函数接收 native 句柄或实例指针。
- 如果声明了一个或多个 `__create__`，`Type(...)` 参与构造重载解析。
- 如果完全没有声明 `__create__`，可通过显式 native 绑定规则接收已有 C 指针。
- 如果声明了 `__destroy__`，变量离开生命周期时，编译器对非空 native 资源调用析构。
- 如果没有声明 `__destroy__`，xlang 不释放 native 资源，也不猜测释放方式。
- 有 native 资源且有 `__destroy__` 的 class 默认不可复制。
- 需要复制时必须显式提供 `derive copy`、`derive clone` 或对应协议，并保证 C 资源复制语义正确。

空句柄策略：

- native 资源的默认初始化值是空句柄。
- 空句柄可以作为可表示值存在。
- 编译器插入 `__destroy__` 时必须先判断 native 资源非空。
- 普通方法调用不自动做空句柄检查，编译器只把句柄传给 C 函数。
- 如果某个 C API 不接受空句柄，应该通过映射文档、显式 `valid()` 方法或错误处理机制表达。

## 13. native-backed 方法

extern 成员函数的 xlang 参数列表不写隐藏 receiver。

```xlang
class Bag
    native void* handle

    extern "bag_create" func __create__()
    extern "bag_destroy" func __destroy__()
    extern "bag_add" func add(int value) as int
    extern "bag_count" func count() as int

    func empty() as bool
        return self.count() == 0
    end
end
```

C ABI 方向：

```c
xptr bag_create();
int64_t bag_destroy(xptr self);
int64_t bag_add(xptr self, int64_t value);
int64_t bag_count(xptr self);
```

规则：

- C 函数第一个参数固定接收 native 句柄或实例指针。
- 编译器负责把 `a.add(1)` lowering 为 `bag_add(a.handle, 1)`。
- 该调用不能发生装箱、动态查找或额外分配。
- xlang helper 方法和 extern 方法共享 class 方法表、重载解析、访问控制、XAPI 和文档系统。

## 14. native-backed 所有权

native-backed class 不内置复杂所有权系统，生命周期完全由 `__create__` / `__destroy__` 和显式协议决定。

规则：

- 有 `__create__` 且有 `__destroy__`：构造返回的 native 资源由当前实例持有，离开生命周期时自动析构。
- 有 `__create__` 但没有 `__destroy__`：xlang 可以创建资源，但不会自动释放。
- 没有 `__create__` 但有 `__destroy__`：通过已有指针初始化后，离开生命周期时自动析构，表示映射作者把该指针交给 xlang 管理。
- 没有 `__create__` 且没有 `__destroy__`：class 只保存并传递指针，xlang 不额外管理内存。
- native-backed class 可以作为字段；外层 class 的清理必须按字段声明顺序的反序清理拥有析构的字段。
- 有析构的 native-backed class 不建议作为普通函数按值参数或按值返回，除非后续 move 语义已经明确。

第一阶段不设计主动提前释放语法。

如果 C API 需要手动关闭，应该声明普通方法；但编译器不会因为调用了该方法就自动把句柄置空或取消后续 `__destroy__`。后续如需支持“提前释放且防双释放”，必须设计专门的 `close/detach/move` 规则。

后续再设计：

- borrowed native。
- attach/detach。
- move。
- raw handle 显式借用。
- 与 `var` 的装箱规则。

## 15. class 统一边界

建议边界：

- 用普通字段表达 xlang 自己拥有的数据。
- 用 `native` 字段表达 C 已经拥有布局、xlang 只持有句柄或指针的数据。
- 需要动态字段时，继承标准库 `object`。
- 需要零成本 C API OOP 外观时，使用 native-backed class。

native-backed class 不应破坏 class 的统一模型：

- 不另设动态 method table。
- 不另设独立对象系统。
- 不绕开 class 生命周期。
- 不绕开协议、XAPI、文档和 ABI 元数据。

## 16. 与 var 的关系

`var` 未来可以持有 function、class、native-backed class，但第一阶段先不开放完整装箱能力。

第一阶段规则：

- function 不默认装入 `var`。
- class 不默认装入 `var`。
- native-backed class 不默认装入 `var`。
- 当前 XRT 的 class value 只有裸结构体数据块，缺少 xlang 具体类型身份和 typeops。
- 当前 XRT xvalue 没有第一阶段约定好的 function 承载格式。
- 如果后续需要 `var` 持有 function/class/native-backed class，必须先设计完整的 typeops：copy、move、destroy、trace、type id。

这避免为了 `var` 兼容而重新造出动态对象 runtime。

## 17. 暂缓能力

以下能力不进入当前 class 统一模型：

- `new` / `delete`。
- class 反射 API。
- native 资源的主动提前释放语法。
- native 资源 move 语义。

这些能力后续如果要做，必须单独设计，不能作为 DEMO5 兼容项自动进入。

以下能力已经转入 `class_object协议设计.md` 作为 class/OOP 下一批设计，不再视为本章暂缓项：

- `object` 标准库基类。
- 动态字段。
- 缺失字段读写/call 协议。
- 运算符协议。
- 属性 `get` / `let`。
- 索引协议与多参数索引。
- `virtual` 动态派发。
