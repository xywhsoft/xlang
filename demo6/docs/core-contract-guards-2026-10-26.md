# 核心契约守卫与产品析构依赖：2026-10-26

本批完成旧 Cgen 清退后的核心静态守卫迁移，并修复一个真实的生成依赖缺口。
不增加公开 API，不修改 XRT、时间 ABI 或算法，不代表五组长期任务已封板。

## 守卫按当前职责检查

旧断言仍要求已删除的 template、codec、网络、容器及同步生成实现，或要求
过时的诊断文本。逐项对照现行声明、XLIR 合同、驻留实现与生成消费点，
把检查放回所属层；没有把 runtime 算法拼入 Cgen 源码来满足旧断言。

- 声明侧保留精确参数／结果、借用、效果与拥有策略检查。
- 驻留侧检查容器分派、同步身份及 checked 恢复；Cgen 侧检查声明消费和
  机械调用，禁止旧的私有句柄、镜像布局及算法重新出现。
- Cgen 源码扫描沿实际 `src/cgen/xl6_ir_cgen*.c` 包含递归发现，去重且防环，
  覆盖二级 queue／tree 片段，不能通过将 AST 指针藏进嵌套片段逃过检查。
- 新守卫单元执行实际守卫 AST，并在内存或读入边界移除合同证据、注入
  禁止实现及循环包含；不修改生产文件，不把文本检查当成编译验收。

## 真实缺陷及修复

原始 `stdlib_channel_receive_ir.xl` 的导出接收结果包含可空 string；生成器
会输出该产品类型的析构器，但没有选择它调用的 `xlir_string_drop` 支持。
GCC 与 TCC 均报告缺失声明。这不是 Channel 接口错误，也不应以函数名
特判或无条件引入全部 string runtime 修复。

新增通用物理析构依赖分析：使用与实际产品析构输出相同的可达性谓词，
递归检查成员的闭合 C ABI，精确选择 string、C-owned、bytes、xvalue、
Error、Future、Generator、Closure、Iterator 或原生值析构支持。无效、
循环和未闭合描述拒绝；未使用的签名不因此引入实现。

私有单元覆盖十类拥有值、嵌套产品、最小依赖位及非法描述。它包含实际
生产 Cgen 实现，链接时不重复加入该对象；不伪造原生对象或拥有图，也不
宣称单元测试就是完整编译器／发布产物证明。
