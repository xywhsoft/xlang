# 动态调用的二进制默认值

动态方法、绑定方法与显式 `xcall` 支持声明中的 bytes 字面量默认值，
包括空 bytes、可空 bytes、内嵌 NUL、任意高字节和 UTF-8 数据。
ProcessCommand／ProcessPipeline 的 `run()` 默认空输入因此可从
动态值调用，不再因缺少默认值合同而被标记为不支持。

## 声明与拥有合同

XLIR 保存独立的 bytes 默认值类别。常量从前端已解码的字节和显式
长度生成规范 C 字面量，验证器同时核对类别和完整内容。合法但不同
内容的常量也不能替代声明的默认值。高字节采用三位八进制转义，
不把任意二进制数据直接写为生成 C 的非法 UTF-8。

动态方法按已验证默认值构造语言 bytes。绑定 callable 的借入参数
还有一个独立的默认值临时 owner；可空与非可空参数均在正常和失败
路径释放。若参数合同要求拥有值，则另取得该参数的引用，真正进入
目标调用后才转移，不能把默认临时 owner 当作转移后的参数再释放。
清理先清空临时槽，沿用首错事务，不发布部分结果。

Cgen 只渲染封闭默认值类别、构造调用和清理，不解析源码的转义、
前缀或文字，也不增加进程库专用算法。未传参数与显式传 null 不同；
显式参数覆盖默认值，非 bytes 参数仍按声明域拒绝。

## 验收范围

专项实际执行动态方法、绑定方法、具名函数 `xcall`、可空／空 bytes、
具名实参、错误类型及受控 ProcessCommand／Pipeline 子进程。旧综合
Native／Array／Dict／Stack 用例纳入严格 C、JIT、checked module 和
生产 AOT；历史 `.pending` 文件名仅为保留旧证据，其注释已更新。
有符号默认值、nullable callable 和 float32 投影同时回归。
动态方法与 `xcall` 的写入参数也实际修改默认 bytes，连续调用仍取得
独立初值，不污染声明默认内容。

Windows、Linux 普通和 Linux 指定插桩通道各 85 项通过。完整驻留
目录双端仍为 304 个组件／1507 个导出，92416 对依赖闭包和 23 个
负控通过；本批没有新增驻留导出或公开标准库 API。

24 个默认值内容／类别破坏反例在 C 和头文件输出前拒绝。字节
常量的 NUL／0x80／0xff、空输入和大小溢出边界也有独立检查。
正向语言用例在 O0/O2 各完成 66 个同步分配前缀，包含首次未触发点，
并核对模块退役后的内存账本。故意捕获 TypeError 的反例独立运行，
不套用“任何分配失败命中都必须令程序失败”的正向前缀断言。

删除默认 owner 清理的实际生成代码负控必须失败。纯 bytes 默认值
使用同一部署计划构建、运行未剥离裁剪产物，要求真实符号表存在，
且不引入 Process／Regex 提供方。Linux 插桩范围为生成 C 和测试
宿主，链接的其他编译器／XRT 提供方及额外裁剪产物不在该范围内。

## 后续接入与总验收

本批不等同于全部动态／Native 编解码完成。当前声明合同检查仍
发现 Regex 回调参数、File.map／lock 的非字面量默认值及异步方法
动态返回等类别未接通；原始 point 互操作也不能自动视为安全动态值。
完整 class 目录输入的 Lowering 诊断仍需收口，不能用所选类用例的
成功冒充全部目录通过。

工作线程／对象图故障、模块组合、真实卸载和 CLI／DLL／VFS 发布
总门继续。未新增公开 API，不改变 CRT 0、XRT 19 组未决策范围；
WaitQueue 保持 MPMC 与拥有接收合同，对象池最后。
