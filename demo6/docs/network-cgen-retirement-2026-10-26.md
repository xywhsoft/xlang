# 网络旧 Cgen 清退：源码批次

本批删除默认标准库已经不再使用的网络生成后端；现代 TCP／UDP／Resolver／
NetBuffer／Framer／TLS 的驻留运行时、显式服务对象及拥有图没有被替换。
没有增加兼容旧入口的兜底，也没有升级两边各自的时间 ABI。

## 实现边界

- 删除六个生产文件：`xl6_cgen_net.h`、`xl6_cgen_net_transport.c`、
  `xl6_cgen_net_datagram.c`、`xl6_ir_cgen_emit_net.c`、
  `xl6_ir_cgen_emit_net_datagram.c`、`xl6_ir_net_datagram_bridge.c`。
- 删除 TCP 名称前缀推断、13 个旧桥接种类、两个旧操作编号、网络专用 needs
  标志及孤立的旧 TLS native group。现代网络仍由精确声明、ABI 合同和组件
  登记选择实现，Cgen 不重新构造网络语义。
- 删除模块隐式 Engine／Resolver 单例及专用 `networkServiceAbi` 字段。
  通用 execution／deadline／executor／TaskPool 拥有图与 checked 退役保留。
- Native Future 映射仍服务于文件异步；只清退它的旧网络消费者。底层
  `xl6_network_service` 原生设施与生命周期测试保留，没有因生成器清退而
  删除有效的底座覆盖。
- 删除未被引用的旧 NetFrame／LineFramer／LengthFramer 源声明，以及仅能
  观察旧生成器私有变量的专用测试和工具。入口库存改指向显式服务拥有图
  验收；通用 callback 的代码租约、排队、取消和资源平衡测试继续存在。

生产侧净减少约 1,500 行；这不是二进制体积的测量。

## 批量发现和修复

首轮完整记录保留，不把失败报告改写成成功：

1. 产品缺陷：Framer 总会声明 `appendRef(NetBytes)`，但独立使用 Framer
   未必展开 NetBytes，导致语义检查出现未知类型。现在先闭合声明类型依赖，
   未使用实现仍按普通可达性裁剪。
2. 合同测试不能要求每种对象都使用 V4；无异步服务的对象正确使用通用 V2。
   现在独立重算要求，再检查对应导出和所有错误 ABI 的拒绝。
3. 原生服务测试遇到冻结锁竞争时应重试准入；真正访问活跃回调根后，仍必须
   拒绝不静止的拥有图，不把准入竞争当成已访问根。
4. 普通 C 前缀回归的同名 sidecar 被自动发现后又显式加入一次。提供方改为
   不同文件名并仅显式加入；不修改编译器来接受重复定义。

fast-path 与文件发送 fixture 已迁移，保留精确字节、NUL、UTF-8、向量、UDP
批量、拥有结果、文件范围及独立游标覆盖。两份 BAT 只更新相关断言，其他
既有工作区更新不属于本批。

## 验收

Linux 136、Windows 134，共 270 个阶段全部通过，独立收据读取器已复核。
另外 4 个实际静态守卫块正常通过，25 个内存／路径边界变异全部拒绝；
Cgen 隔离守卫接受 8 种合法原生形态，拒绝 9 种前端／旧后端形态。
全局入口复用本批编译器后，额外通过 O0／O2 编译的运行时操作／效果合同
目录 4 个阶段。该目录工具的 Windows 长对象路径改用 GCC 响应文件，并保留
完整原始命令、实际命令和消费的响应文件字节。

| 层次 | Windows | Linux |
| --- | ---: | ---: |
| 完整新源码编译器翻译单元，O2 | 1,272 | 1,271 |
| Cgen 全单元、IR 变异、底层服务／callback、12 个语言 fixture | 109 阶段 | 105 阶段 |
| 显式混合服务拥有图、宿主、取消／退役、独立 AOT | 25 阶段 | 31 阶段 |

语言路径覆盖 JIT、显式模块、独立 AOT、GCC O0／O2 严格 C；同一次正常五组
联合流使用固定离线材料与自建 loopback。数值解析不使用公网 DNS。
Framer 另检查没有拉入网络 Engine、TCP、UDP、TLS 实现，普通 C 前缀入口
不得自动变成网络桥接。文件异步映射的正例、网络无旧映射的反例均保留。

主要证据在 `F:/xlang-validation/five-groups-20261025/p7-network-retirement/`：
两份源码归档、两轮失败／成功报告、完整对象构建收据、各阶段日志、
`verified-windows.json`／`verified-linux.json` 和 Linux 证据镜像。
Linux 镜像含 5,754 个文件，逐文件字节核验后另存于 Windows 卷，避免将
WSL 临时不可达当成证据丢失。守卫修复只覆盖与本次清退直接相关的断言；
相关原生服务静止检查、BUSY 拒绝卸载及通用退役要求没有删除。
未指定依赖目录的全局守卫尝试另行重建编译器，已按 PID、创建时间和命令行
核对后停止该重复构建，保留中断记录；随后显式复用本批完整编译器收据。
首次启动构建过早与重复 PATH 导致的控制器错误也保留，没有伪装成产品失败。

## 未完成范围

这是完整源码编译器批次，不是本轮新发布 CLI／DLL／SO／VFS 的封板证明。
TCC 依赖来自前批独立普通构建的真实 runtime；没有以源码对象覆盖发布产品。
下一步仍需用本批清理后的完整源码生成新发布候选，核对剩余旧 fixture／
静态守卫并闭合逐项五组验收矩阵。全局入口目前停在已删除的
`xl6_ir_cgen_emit_template.c` 的旧读取，尚未全部通过；参数化
工具库存另有三个其他批次新增的 C-owned worker 尚未登记审查，不计为本批
网络功能失败，也不擅自加入库存。

长期目标仍 active。未决策 CRT 0／XRT 11；内存池最后。验证不包含公网、
扫描、攻击模拟或网络安全性质专项。删除的跟踪文件可从 Git 历史恢复。
