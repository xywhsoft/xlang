# TaskGroup 桥接句柄的真实拥有与重入安全

TaskGroup 语言桥接不再借用父取消观察者的 Data，也不在释放包装器锁
之后使用无生命周期保护的原生裸指针。公共句柄、父观察者和每个在途
操作分别持有真实引用；包装器的原生 Group 槽保留到物理末次释放。

取消、等待、Unwatch 和原生销毁均在包装器锁与短 mutation 之外执行。
父取消回调可以重入普通方法，甚至销毁公共句柄；当前操作的独立引用
仍保护原生 Group。正在等待的操作同样保留实际引用，不被根折扣忽略。
父绑定先预留状态，拒绝的第二个已取消父级仍不能产生取消副作用。

## 循环退役协议

桥接提供明确的物理拥有视图和 owned 父观察者策略。Count 拒绝正在
执行方法、绑定或关闭中的节点，不把它们当作叶子。Trace 分别报告
原生 Group 和 ParentWatch 的真实强槽，观察者则拥有自己的 Data 引用。

Clear 仅标记退役并保留槽。完成阶段通过 `xrtCancelUnwatchChecked`
消费实际注册权，再归还原生创建者权；所有节点的计划引用仍保留到
全部完成。XRT 与消费头仅同步取消模块增量，毫秒到微秒适配保持不变。

XRT 新的 checked Unwatch 和旧 void 入口共用同一实现，支持 NULL、
回调自身注销和并发尾部等待。checked 返回值与诊断分配无关；它只
确认注册权消费，不替代 Watch 的物理完成状态。

## 验证与后续接入

`check_task_group_bridge_ownership.py` 批量检查完整源码对象、严格 C、
GCC 和 TCC，以及可选的 Linux 全专项 ASan／UBSan。物理图测试包含
160 个真实循环、80 个中止恢复、80 个重入回调和20个并发等待销毁。
节点、边和真实外部根先由独立检查器核对，完成路径零分配并平衡账本。
既有方法、故障前缀、JIT、模块和移动 AOT 仍由原 TaskGroup 门禁验证。

本批不添加语言 API，也不自动启用 TaskGroup 的全局循环准入。
FutureCombine、continuation、生产者准备职责和目录协议必须一并完成
协调后，才能将新的物理桥接策略接入语言全局收集器。53 模块与正式
产品发布验收仍未结项，对象池继续最后处理。
