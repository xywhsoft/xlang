# TaskGroup 和 Future 的终结后退役

原生 TaskGroup 和 Future 已具备可执行的循环退役协议。组、活动项、
等待注册、取消观察者和端点均按真实强槽清理，全部语义终结之前
不会提前关闭 Future、取消任务或 Unwatch。语言桥接句柄和整个
拥有目录的协议切换仍需接通，当前不自动启用新准入。

## 全局 Clear 和完成职责

Future V5 在 Clear 中标记退役关闭，但保留所有物理槽和等待注册，
不派发完成回调，也不改写一个单独存活的取消令牌。真实等待注册
拥有者解绑之前，完成 Step 返回无拥有边副作用的 BUSY；解绑后
才归还 payload、producer、Owner、Error 和 Cancel 等引用。

TaskGroup 适配器分别识别组和真实活动项。组归还活动链表引用并
消费自己的取消注册权；活动项解绑自己的 Future 完成注册，分别
归还注册、源 Future、子组和所属组的引用。已 Clear 组的公开
Destroy 只归还调用方真正持有的组引用，不重复执行关闭和取消。

完成阶段串行运行在冻结和 mutation 之外，允许不同节点的职责
顺序交错。每个物理节点的实际计划引用保留到全部 Step 完成；
一个节点 READY 不允许提前释放它的计划引用。派发尾部仍在运行时，
Watch 可继续 BUSY。READY 幂等，FAILED 不依赖诊断对象能否分配。

单独被外部持有的完成 Future 是真实外部根，不随组 Clear。
组的完成职责仍正常 resolve 它，而不是丢弃或改为 CLOSED。
Clear 前中止时，Restore 保留原有注册、待决端点和取消行为。

## 准入与验证

Future V5、TaskGroup 适配器、Cancel Watch V2 和 Token V3 必须
共同使用；每个传递节点仍须独立准入。未知身份和 legacy 观察者
不被当作叶子，拒绝不修改完成输出。旧 Future V1 至 V4 及取消
适配器的身份和准备协议保持不变，不能在同一物理节点混用协议。

原生测试覆盖 64 种真实外部根、嵌套拓扑和清理顺序组合，4 种
中止恢复，以及 2 个真实派发尾部并发场景。计划引用建立前使用
独立物理图检查器复核节点、边和外部根。收集只针对无外部根的
节点，不以取消请求、根折扣或合成引用代替生命周期。

`check_task_group_retirement.py` 对两份实际消费单头执行 O0 和 O2
检查，并可核对完整源码对象后执行同一原生循环测试。规范源码和
消费头哈希记录在 `lib/xrt/backports/task_group_retirement.json`。
同步仅包含拥有协议增量，嵌入式相对超时仍为微秒，旧协议与无关
模块不整体替换。没有新增语言 API 或 Cgen 特例。

## 语言层剩余接入

父取消桥接句柄仍须具备真实引用和 owned 策略；拥有目录必须对
相同物理节点一致选择新完成描述符，不能各域返回冲突身份。
这些接通前，原生循环测试通过不等于语言 TaskGroup 的全局循环
退役或正式发布验收通过。
