# 标准库签名与产品执行用例

标准库公开面的源码绑定，现在与 Windows、Linux 的实际产品执行结果关联。
每项签名都必须找到同一份源码，在两端 JIT、模块和迁移后的独立 AOT 中通过。
这关闭了五项执行清单缺口，不改变标准库 API 或生产实现。

## 补齐的执行用例

`array.sort`、`array.sortBy`、`array.binarySearch` 原来只有 CRT 算法夹具作为
绑定依据，该夹具没有进入三组产品执行人口。新增可移植 Array 用例覆盖重复值、
首次命中、空输入、UTF-8 和内嵌 NUL 排序、键提取次数，以及键提取失败不改变原值。

`process.runFile` 和字符串重载 `process.start` 原来只有依赖 cmd、findstr、
more 的 Windows 用例作为依据。新增用例使用验证器编译的受控子程序，检查
非零退出码、交互式 stdin/stdout/stderr、精确二进制内容和 NUL 输入拒绝，
在 Windows 与 Linux 运行同一份源码。

## 签名核对合同

真实 Linux 编译器 SO 提供 142 项原生容器签名、228 项静态签名和 329 项
类可调用成员，共 699 项目录记录。普通调用新增 IR 来源、源码位置和所在函数
可达性，与原生 intrinsic 使用一致的核对口径；旧观察器与新观察器的调用结果
必须相同。

反例同时包含字符串中的 API 名称、未调用函数中的真实调用，以及顶层执行调用。
仅声明、同名用户成员和未调用函数不能代替可达调用。完整绑定门要求上述三类
签名都有可达函数中的源码调用，但可达函数不等于其所有运行分支都执行。

产品关联门进一步要求，同一份夹具源码的 SHA-256 出现在四份完整执行报告中，
且对应程序确实通过两端 JIT／模块和独立 AOT。需专用宿主、平台条件、负例检查、
只编译未运行以及只成功一个通道的项目，不计作这一项的执行佐证。

该关联不是运行时分支插桩，也不证明夹具中每一条件分支均进入。53 模块的最终
完成审计、特定平台条件和调度器全线程同时故障仍单独保留；不据此宣称全仓可发布。

## 证据检查与复用

关联门只读原报告，不改写 Windows 或 Linux 路径；Windows 驱动器路径在 WSL
映射后逐项复算。检查范围包括报告输入、子报告、对象、日志、原生产物和独立
AOT 程序。四份报告必须属于相同执行人口，同平台 JIT 与 AOT 必须使用相同产品，
Linux 产品还必须与真实 SO 的签名核对一致。

生产输入和普通构建产品未变，复用此前冻结的 CLI／DLL／SO。完整执行人口重新
运行；已完成子门只有在当前脚本、构建、产品及全部证据复算相符时才能复用。
新版 Linux 签名门因观察程序和合同变化重新执行，不复用旧绑定统计。

运行关联门使用 `tools/check_stdlib_product_witnesses.py`，参数为
`--census-report`、`--windows-products`、`--windows-aot`、`--linux-products`、
`--linux-aot` 和新 JSON 路径 `--out`。其 Linux 单元测试
`tools/test_stdlib_product_witnesses.py` 固定 16 个正反例，防止把过期、不同源码、
不同产品或未执行状态计作成功。

完整人口的要求只施加于四份产品执行报告和签名目录。拥有图等已批准专项
子门仍按各自范围复算，不因它们使用定向人口而误拒绝整个产品报告；子门也
不能反过来代替完整人口。

本批严格 C 专项使用实际 AOT 模式保存的 `module.c` 和 `xl6_xrt_impl.c`，
两端分别按 O0／O2 编译。首次脚本误把仅保存 module 的模式当作完整 AOT 输出，
失败记录保留；改用真实 AOT 输出，不补造或跳过原生实现文件。

## 决策范围

不可空并发队列的局部、全局和字段声明仍必须显式初始化；可空队列支持延迟创建。
本批未修改 XRT、生产编译器、运行时或未评估扩展库。CRT 未决策 0、XRT 未决策
19 组与对象池最后的顺序不变。

## 实际执行结果

两端完整产品清单各 326 项，适用正例各 317 项通过；独立 AOT 清单各 326 项，
适用正例各 316 项通过。JIT／模块清单保留七项专用宿主、一项预期拒绝和一项
平台条件；AOT 保留八项专用宿主及相同类型的拒绝、平台条件。

产品必需子门分别为 Windows 17、Linux 19 项，全部通过。其中 16／17 项
复核证据后复用；完整语言执行人口、头文件门和新版 Linux 签名门重新运行。
新增两个程序的真实生成 C 在两端各十个保存／严格编译阶段通过。

产品和 AOT 报告位于 `D:/xlang-validation/stdlib53-b337r2-products-win`、
`stdlib53-b337r2-aot-win`，以及 `/var/tmp/xlang-stdlib53-b337r2-products-linux`、
`xlang-stdlib53-b337r2-aot-linux`。真实 SO 签名报告为 Linux 产品目录下的
`gate-native-public/results.json`；严格 C 专项为两端对应的 `b337r2-strict-*`。

最终关联报告 `/var/tmp/xlang-stdlib53-b337r2-witnesses.json` 复核 31,779 个
唯一文件；699 项签名均有同源码的四通道执行用例佐证，关联缺口为零，
`Complete` 和 `InputsUnchanged` 均为 true。16 个正反例控制通过。
