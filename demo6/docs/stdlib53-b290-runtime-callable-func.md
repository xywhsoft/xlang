# 动态调用的函数参数合同

普通 `xcall` 的函数形参采用与函数返回和动态方法相同的闭包装箱与
反向适配底座，固定签名支持嵌套函数、nullable 函数和运行时默认函数值。
typed 调用仍走原生闭包签名，不为直接调用引入动态装箱。

## 类型与调用

动态实参的 typed 函数值必须通过显式 `xcall` 进入 xvalue。
参数投影先确认 callable 及声明的完整函数类型身份，再构造反向
闭包；签名不符、普通数值和非可空参数的 null 在目标进入前拒绝。
参数名不参与猜测转换，默认值仍由统一 argument-default IR 程序求值。

nullable 函数以已有空指针作为 null，不改变非空闭包的调用签名。
其桥接计划明确分离 nullable carrier 与底层函数类型；null 直接
往返 xvalue null，非空值使用底层签名的 entry 和类型身份。

## 所有权与依赖

函数参数解码返回适配器拥有的闭包。目标借入时，适配器在调用后
释放该 owner；目标消费时按既有提交协议移交。失败路径释放已投影
的闭包及默认值，保留首次失败；闭包与盒装函数的代码租约保持
创建者退役后的调用和析构地址有效。

函数参数需要的适配方向与返回相反：输入解码需要子函数的反向
入口，输入编码需要正向入口；返回沿用父适配方向。Cgen 从已验证
IR 桥接参数／结果计划建立这些物理依赖，不重新恢复源类型意图。
效果、presence、payload 类型、编码、解码和销毁均由 IR 独立审核。

## 验收范围

`tools/check_stdlib_runtime_callable_func.py` 检查 typed／nullable 参数、
nullable 返回、默认函数值、前序捕获、嵌套高阶调用、显式签名拒绝、
目标未进入、原始异常和闭包清理。已有默认程序、动态方法、整数
常量、File map／lock、回调、float32 和 bytes 默认值同时回归。

门禁包括确定性 C、严格 O0／O2、JIT、checked module、生产 AOT、
实际裁剪产物、IR 破坏反例和完整同步分配前缀。故意遗漏函数参数
owner 清理必须被账本检出。Linux sanitizer 的范围为生成 C 与
测试宿主，不代表所有提供方或裁剪产物插桩。

Windows、Linux 普通和 Linux 指定插桩通道各 192 项通过。338 个
IR 编解码／presence／类型／销毁／默认程序破坏反例均在输出前
拒绝。O0／O2 各完成默认函数值 7 个、函数参数 105 个、错误用例
31 个同步分配前缀，首次未触发点为 6／104／30；10 个已有原异常的
诊断恢复点逐个经过堆栈审计。遗漏参数闭包释放的坏实现被三通道
账本检出。双端各 310 个三组夹具通过严格编译；驻留目录保持
304 组件、1507 导出、92416 对依赖闭包和 23 个拒绝负控。

变长函数反向适配的实参展开、nullable 动态方法回调、异步动态返回、
其余动态／Native 组合、线程及对象图故障、模块
组合／真实卸载、时区与完整 CLI／DLL／VFS／RC0 发布验收继续。
