# 独立程序入口与对象图退役

原生 Context／Buffer 的后续修复与剩余拥有审计见
[原生 Context 和 Buffer 的驻留拥有合同](stdlib53-b304-xlang-context-policy.md)。
以下失败记录保留本阶段发现时的范围，不代表后续仍未修复。

独立可执行程序现在由编译器提供明确的部署合同，在模块初始化前
创建并绑定拥有记录，退出时使用共同原生退役驱动。Cgen 只生成
入口接线，不实现对象图算法，也不回查 AST 或扫描生成的 C。
源码专项中，原有 Stack、Tree、Queue 循环图分别执行 1、5、6 次
析构，原有字段与模块环境断言保持不变。

## 编译计划与裁剪

可执行计划区分直接入口和对象图入口。选择来自已验证 IR 的实际
组件、全局存储、导出和读取边界。纯标量程序保留直接入口，不引入
静态模块记录或策略目录；需要对象图生命周期的程序才选择相关
组件，并从精确能力登记派生 getter 列表。原生模块要求完整保留。

可执行 Cgen 要求部署合同。缺失或尺寸错误的合同、非法 C 标识符、
重复能力、损坏的能力数组以及遗漏所需对象图生命周期的直接入口，
均在输出任何 C 之前拒绝。宿主接管的 JIT、共享库及外部 C main
仍由对应宿主负责绑定和退役，不擅自生成第二个进程入口。

类对象发现只在实际选择类终结组件时接入，不让静态模块底座
无条件依赖类、Future、网络、进程或全部策略。

## 只读观察与退役

读取准入是独立的能力，不由“可找到退役适配器”推导。动态字段
只接受精确的原生身份和句柄策略；未知引用不会触发其 Count 或
Trace。JIT 与独立程序共用同一动态字段读取判断。

独立模块使用无分配的准入协调，读取和退役互斥。只读作用域只能
由创建线程结束，不能复制作用域、跨线程借用或嵌套执行退役。
语义析构回调可在本线程同步观察仍完整的字段，结束后恢复原退役
准入。外部执行仍阻止不安全的读取。真实 lease、计划 pin 与入口
拥有计数不变，不虚构根或减去实际引用。

独立控制记录的存储寿命由入口保证，即便没有类或闭包 lease，
共同计划也先取得一个真实的根 pin，随后将这个实际 Hold 作为
内部拥有槽计入每次快照，并在成功或失败时平衡 Drop。首次快照
不再依赖“恰好存在语言对象 lease”。未知节点仍须先通过精确
准入，不对零引用的失效 Value 放宽检查。

退出驱动推进已有可重试协议。临时忙状态可以等待，外部拥有根、
准备失败及资源错误则保留可检查的记录，不返回假成功。语义析构
失败后恢复旧计划并重新发现，已经执行的析构不会重入；首个失败
持续保留，包括没有诊断对象的失败。记录只有在物理退役完成后
销毁，策略目录活到所有相关计划结束。

## 源码专项验收

Windows 391、Linux 390 个翻译单元的完整源码构建后，两端各通过
50 阶段入口专项。十一项独立程序包括无环对照、原有三类循环图、
纯标量、三类恢复与克隆，以及主函数异常、返回码 23 和析构异常。
检查包含严格 C、实际运行、保留 finally 与字段断言、一次性析构，
以及搬离编译目录后不依赖产品 DLL 或 SO；Linux 不携带 RPATH。
O0、O2 的部署合同反例均在输出前拒绝。

共同原生底座每端 68 阶段通过，覆盖 null、布尔、内嵌 NUL 文本
和无 lease 容器的四类回归，以及六个实际错误实现拒绝控制。
Linux 同组全部参与源文件使用 ASan、UBSan。裁剪底座每端
60 阶段通过；O0、O2 各扫描 51 个完整退役分配前缀，首个未触发
点为 50。目录与源码 JIT 每端 110 阶段通过，保留原有完整对象图
宿主和错误实现拒绝控制。精确组件审计每端核对 352 个组件、
1585 个导出和 23 个拒绝控制。

上述入口专项使用物理私有源码 SDK。正式产品内嵌 VFS、三组完整
产品清单和发布验收单独执行，不由源码专项代替。

首轮正式 VFS 暴露策略源文件引用仓库 `release/include` 路径，现已
统一使用私有编译环境实际提供的 `include/xruntime_decl.h`，并增加
覆盖全部 41 份策略源的路径守门。随后数值产品回归发现无 lease
控制记录的首次快照失败，促成上述真实根 pin 接入；原失败记录
与修复后结果分开保留。

两端均重新执行普通构建，重建 TCC、XRT、CLI、运行库、编译库及
两份 VFS 镜像。原有四项独立对象图验收门全部通过，实际析构为
1、1、5、6 次；十项安全数值产品回归各 61 阶段通过，包含真实
check、run、module、独立 AOT 及搬离编译目录后的运行。

## 仍需完成

Windows 终端尺寸交付的已复现失败仍然阻塞发布，本批不修改 XRT。
批量产品验收还发现 `stdlib_nested_sdk` 与
`stdlib_string_bridge_boundaries` 的主逻辑输出 PASS，但独立程序
退役返回 StateError。其 `xlang.Context` 的原生 payload 仍使用生成
侧 Drop 包装，缺少共同退役要求的完整准入合同；必须继续迁移，
不能将未知原生拥有关系当成叶节点放行。新增入口不代表嵌套 SDK
或整个发布验收已经通过。
全局 `exit(code)` 已获设计批准，但当前语义检查仍报告未声明；
普通 `return 23` 的退出码及清理通过不等于全局 exit 已完成。
CRT 未决策仍为零，以上属于已决策待实现项。

对象池继续放在最后，XRT 其余十九组未决策不因本批实现而改变。
