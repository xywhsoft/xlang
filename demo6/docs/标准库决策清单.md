# xlang 标准库决策清单

更新日期：2026-10-05

本文是 xlang 标准库重设计的状态账本和后续逐项评估入口。CRT、XRT、xruntime、
xlang 编译器 intrinsic 与宿主桥接的任何公开能力变更，都应先更新本清单，再进入设计和实现。

2026-10-03 signal 交付决定：用户选择显式注册线程事件泵。原生 dispatcher
只记录有界事件；on/once、channel 与 TaskGroup 路由均在注册线程调用
dispatch/dispatchFor 后执行。基础订阅与回调门面独立注入，保留精确
事件快照、队列满重试及同步退役，不引入后台自动脚本执行。
该决定属于已批准的 53 模块任务，不变更下方 19 个未决策分组。

B20b 实施验收（2026-10-03）：基础订阅/独立事件快照、on/once 两种
handler、显式泵、channel 满队列重试和 TaskGroup 取消入口已接通。
Windows 300 项、Linux 362 项及 82 resident/6724 依赖对/611 导出/5
实际闭包专项通过；193 个逻辑失败点和 4 个首次未触发点账本平衡。
只允许无继承且无对象图字段的平坦 class 消息；复杂 channel 图与完整
TaskGroup 公开面未验收。旧 print/println 与 channel 的原生错误分类/
cause 保留问题列入总验收，不以本批通过冒充已修复；详见三组长期任务。
signal 跨组总验收、process、typed 容器仍继续；CRT 无未决策新增，
19 个 XRT 未决策分组保持不变，对象池最后。

B21 实施验收（2026-10-03）：owned Command/Options、直接 argv/显式 shell、
精确 bytes 输入/输出、独立 Result/Status、取消/期限及捕获限制已接通。
Windows 278、Linux 303 项专项和 86 resident/7396 依赖对/652 导出/5
独立装配通过；XRT argv/OOM 错误保留与同步 waiter 退役缺陷同时修复。
旧 process 专用 Cgen 算法移除，41 桥接由声明/XLIR 合同选择；详细冻结
证据与未验收边界见三组任务 B21。live Process、pipeline、Future、文件
重定向、PTY、typed 容器与跨组总验收仍继续，不关闭 DEV-XRT-53；CRT
和 19 个 XRT 未决策分组没有扩张，对象池仍最后。

B22b 原生安全收口（2026-10-03）：Process read/write 与 close 的 OS
句柄退役窗口已动态复现并修复。非零读写在槽位锁下复制不可继承的操作
句柄，锁外执行 I/O 并在所有返回路径释放；close 不取消已开始的阻塞
调用。三流关闭/复用、复制失败、首错保留、释放错误、短读写与 EOF
专项通过，XRT 原库提交 9bbc3135，xlang 仅精确同步两份固定快照。
Windows 321、Linux 365 项批量回归与独立装配专项通过；不新增 Cgen
算法或公开 API。live Process/streams/wait 等仍待开发，详见三组任务
B22b；CRT 无未决策，19 个未批准 XRT 分组不变，对象池最后。

B23 接入验收（2026-10-03）：live Process、PID/state、独立 nullable
wait/status、唯一拥有的 Reader/Writer 已接通，流可离开父 Process 作用域。
14 个声明桥接、两个按需组件，没有增加 Process Cgen 算法。Windows
360、Linux 432 项专项及 90 resident/8100 依赖对/668 导出/8 个实际
闭包通过；原生流构造 OOM 3/3 失败点与退役账本通过，生成 live 的完整
语言 OOM 前缀尚未验收。析构暂沿用 XRT，不隐式杀进程；默认终止策略
仍待用户确认。nullable getter 安全访问缺口在 B24 以通用 semantic/IR
合同修复，原 pending 夹具已提升为语言、合同和跨平台验收用例，不
通过标准库绕行。pipeline、Future、重定向、PTY、typed 容器与总验收
仍继续；CRT 和 19 组未决策不变。

B24（2026-10-03）：可空 getter 增加显式 receiver gate，接收者仅求值
一次，空值不调用 getter；返回类型提升且 nullable/var 不嵌套。覆盖协议、
泛型和继承，补齐 bytes 的既定空值哨兵与空合并路径；仅物理空值 ABI
校验在 Cgen 接受 bytes，不新增库专用生成逻辑。正式专项验收结果见
三组长期任务 B24：Windows 230 / Linux 271，7 个实际裁剪闭包
ASan/UBSan/leaks，32 gated CallSite / 156 合同破坏拒绝，别名 OOM
144+1 账本平衡。既有安全索引空值仍求值 key 的问题保留精确 pending
用例，下一批优先处理；53 模块任务仍进行中，未决策和对象池顺序不变。

当前 XRT/xruntime 已公开函数快照、保留 CRT 能力的去重候选集和补充/删除差分，
见《标准库CRT_XRT功能差分清单.md》。该文是评审证据，不会自动关闭本文的未决策项。

CRT 当前公开面和逐项候选见《标准库CRT功能决策清单.md》。XRT 逐模块
评估已覆盖 X05 的 math、非加密 hash32/hash64、hash_keyed 与随机族；
X08 的四个结构化数据格式本轮也已确定语言公开面并实施；其余 XRT 分类仍按下表逐项决策。

2026-09-23 实施决定：用户选择将上一轮列出的 CRT 候选函数纳入标准库，
包括 `math.divRem`、`math.minNumber/maxNumber` 和 `console.readChar` 等
可选项。普通安全入口目标为默认标准库，`cString.length` 仅属显式 C
互操层；会修改线程舍入模式或浮点异常标志的能力放在**显式导入的高级
`floatEnv` 模块**。`env.get(name)` 在变量不存在时返回可空字符串，不能
把缺失和空字符串混淆。当时相关签名及错误/所有权合同尚未拍板；
后续 CRT 决定见下段。不以“已列名”冒充“已开发”。

2026-09-28 CRT 合同决定：用户采纳 C04、C06、C07、C08-FP、C09-CONSOLE、
C13-ENV 的本轮建议；C13-PROCESS 只纳入一个全局 `exit(code)` 能力，其余
`abort/system/atexit/_Exit/quick_exit` 等均不进入 xlang CRT 标准库。
用户明确要求 `exit` 先完成沿途语言 `finally`、作用域析构、模块终结及
宿主清理，最后才交付退出码；因此禁止把公开 `exit` 直接映射为 C
`exit()`。这些决定确立设计合同，不代表代码已经实现或跨平台验收完成。
该轮 CRT 决策未处理 XRT/xruntime 分类和实现。

2026-09-28 XRT math 决定：既有 math 入口继续保留，补入
`math.isClose(a, b, absTolerance, relTolerance)` 和
`math.intNear(a, b, tolerance)`，分别直接映射 `xrtMathNear` 与
`xrtMathIntNear`。`isClose` 的负值或 NaN 容差抛 `ValueError`，因此不标记
`@no_raise`；`intNear` 是无溢出的纯非阻塞调用。X05 的随机与散列部分
仍未决策。

2026-09-28 X05 接入核查（非设计决策）：现有 `hash.u32/u32WithSeed/u64/u64WithSeed`
仅接受 `string`，运行时使用零结尾长度；`string` 内嵌 NUL 会被截断，`bytes` 和
`Buffer` 尚无公开重载。直接叠加指针重载会与 Cgen 生成的 XRT 原型冲突，
需要先统一“借用数据＋精确长度”的外部调用 ABI。`random.u32/u64` 已实测可运行；
`random.range/seed/string`、`Random.u32`、`crypto.randomBytes/randomHex` 虽有
标准库声明，但运行时出现未解析的 `xl6_xrt_*` 桥接符号，不能算已开发。
`hash_keyed`、安全随机文本尚未进入默认标准库。X05 仍保持未决策；
 本段只记录事实，不代替后续公开 API 选择。

2026-09-29 X05 hash32/hash64 补缺决定与验收：四个非加密哈希入口保留，
`string` 与 `bytes` 使用同名重载；可变 `Buffer` 使用 `u32Buffer`、
`u32BufferWithSeed`、`u64Buffer`、`u64BufferWithSeed`，避免仅用字符串哈希
时无谓注入 `Buffer` 类。所有入口的末尾可选 `size = -1`：省略处理完整
实际字节长度，非负值截断到实际长度，低于 `-1` 抛 `RangeError`。内嵌 NUL
完整计入，`bytes` 借用受管数据，不逐字节复制；XRT 调用通过已验证的
pure/no-raise/nonblocking（可变 `Buffer` 不标 pure）桥接合同生成，不再
为每次有效哈希调用建立外部错误作用域。XRT 固定向量、UTF-8/NUL、三种
输入等价、size 边界、4096 字节、语言运行/独立 build 和生成 C 严格 GCC
检查通过。普通 seed 不是密钥。此决定不涵盖 hash_keyed 或随机族；
这些仍属 X05 未决策。

2026-09-29 X05 hash_keyed 决定与实施：默认标准库提供明确命名的
`siphash.hash64(string|bytes, key: bytes, size=-1)`、
`siphash.hash64Buffer(Buffer, key: bytes, size=-1)` 和
`siphash.hasher(key) -> SipHasher64`。严格 16 字节密钥，无默认密钥或伪随机
回退；`size` 只按实际字节截断，保留内嵌 NUL；非终结流式快照支持
`update(string|bytes)`、`updateBuffer(Buffer)`、`digest/reset/clone/inputBytes`。
用户程序仅在使用时选择 `XRT_MODULE_HASH_KEYED`；扩展包改为单独的
`siphash128`，只编译域分离的 128 位算法，不重复编译 XRT 64 位实现。
Windows JIT/AOT、生成 C 严格语法、64/128 位固定向量与模块裁剪已专项
通过；跨平台和故障注入尚未验收。旧组合扩展包及旧文件哈希 API 退出现役，
不以未发布版本的兼容性阻止边界收敛。X05 剩余仅随机族。

2026-09-29 X05 后续 7 模块接入评估（接入前快照；现已由后续决定取代）：

| XRT 模块 | 当前 xlang 接入 | 待补能力与边界 |
|---|---|---|
| `hash_keyed` | 默认标准库无入口；独立 `siphash` 扩展库不计为默认标准库接入 | 决定是否提供 SipHash-2-4 一次性及分块状态；完整 128 位密钥、精确字节长度、固定向量与普通 seed 的安全边界 |

2026-09-29 X05 随机族决定与实施：`Random(seed, seq=1)` 是显式、可复现的
线程归属状态，`random.*` 是当前线程默认伪随机状态。两者公开
`u32/u64/below/range/rangeClosed/real/bytes/string/shuffle`，其中
`range` 为半开区间、`rangeClosed` 为闭区间，`below` 使用无偏采样；
`fillBytes(Buffer)` 与 `shuffleBuffer(Buffer)` 只在用到 Buffer 时注入。
`crypto.randomBytes(count) -> bytes`、`crypto.fillRandomBytes(Buffer)`、
`crypto.randomHex(byteCount)` 和 `crypto.randomString(...)` 仅使用系统
安全随机源，失败绝不回退到伪随机源。文本默认 URL-safe 字母表，
自定义字母表限无重复的可见 ASCII；`alphabetSize=-1` 使用实际字节长度，
非负值按实际字节长度截断，因此可显式选取含 NUL 字符串的有效前缀，
但 NUL 本身不会作为随机文本字符。负长度报错；随机字节返回独立
`bytes` 值，Buffer 入口就地填充。按实际使用的适配器选择 XRT 模块，
最小默认、显式、安全随机生成 C 均未注入彼此无关的适配器。
Windows JIT/AOT、严格生成 C 和专用边界夹具已通过；跨平台与 OS
安全随机源故障注入仍未在本轮验收。`bytes` 不提供锁页或销毁擦除保证。

2026-09-28 string/bytes 长度合同决定：对按字节处理的公开入口提供可选的
`size`（多输入时使用 `dataSize`、`keySize` 等明确名称）。省略时处理输入的
完整**实际字节长度**；显式传入时只处理前 `min(size, 实际字节长度)` 个
字节，`0` 表示空输入，负数不得被转换为无符号长度。此合同覆盖内嵌 NUL，
不得用 `strlen` 或 `xrtStrView` 推测 xlang `string` 的实际长度，也不得把
用户传入的长度直接用于无界指针读取。该决定允许破坏旧 API，不以兼容性
为实现约束。当时 `string` 的 C ABI 仍为 `char*`，无法传递精确长度；
2026-09-29 已将语言/XLIR/Cgen 的值表示迁至 `Data+Size`，但外部 C 调用
边界仍须逐项标注“精确字节视图”或“拒绝内嵌 NUL 的 CString”，并通过
运行测试后才可将相应标准库入口记为已开发。Unicode 字符操作与按字节
操作的范围边界另行核查。

2026-09-28 首轮存量审计：src/stdlib/xl6_stdlib_data.c 曾有 41 处
__xl_std_crt_strlen，分布于摘要流文本 update、文件文本写入、进程输入、
codec、hash 和加密/签名/KDF 等入口。2026-09-29 双字段 string 迁移已将
这些隐式 C 长度调用清退；语言值以 Data+Size 保留内嵌 NUL，
test/cases/cgen_string_embedded_nul.xl 已通过基础长度、复制、拼接、
Base64、Hex、Percent、动态对象字面量键与闭包捕获的内嵌 NUL 往返和严格
C 生成检查；双向 callable、动态绑定方法、类 JSON/XLON 缺失字段默认值、
TCP 同步/异步收发及 UDP 原始字节收发也有专项回归。其余 XRT/CRT 桥接与公开 C ABI 仍需
继续逐项验证，不能以这一基础回归代替全量验收。
Buffer 已携带精确长度，首批为 append(Buffer, size)、
insert(index, Buffer, size) 补充可选上限并验证；部分 crypto bytes
入口虽有标准库声明，但 xl6_xrt_* 桥接符号缺失，须先修复链接链路再
进行公开 API 扩张。原始 point + c_size 属显式不安全互操，无法从指针
推知分配边界，不适用自动截断合同。

2026-09-29 语言参数边界：所有公开函数、函数类型、`extern` 参数声明和调用
不再接受 `byval/byref/out`；替换值通过返回值或多返回值交付。CRT 的
`frexp/modf/remQuo` 输出指针由标准库私有 ABI 合同注入，公开包装层继续提供
值返回 API；其他 C 输出指针需通过显式 C 包装层接入。本轮没有据此决定
新的 XRT 模块公开面，下面的未决策分类不变。

2026-09-29 已决策遗留实施批次：C06 严格数字 `parse/tryParse` 完成并验收；
C13 环境变量四个入口完成 Windows 功能与所有权专项，跨线程及非 Windows
验收继续保留在待开发。未处理 XRT/X01–X29 的公开范围决策。

2026-09-30 X02 排期决定：将 xlang 托管的对象池/内存池（包括固定尺寸池、
通用池以及“销毁池即清理其所拥有对象”的生命周期能力）放在本轮 XRT
标准库逐组评估与实施的最后处理。该决定仅改变优先级；对象逃逸、析构、
分配器 ABI 与公开 API 仍未定案，X02 继续列在“未决策”。

2026-09-30 X08 结构化数据决定与实施：XRT 的 XSON/XSONL 命名统一迁为
XLON/XLONL；线格式保持不变。`json/jsonl/xlon/xlonl` 公开基础与高级配置
的解析、验证、序列化、文件读写和回调写出。单值格式另有访问事件；JSON
公开引用/转义，XLON 公开自定义标签解码和手工标签写出。原生配置结构体、
错误位置 helper、自动自定义编码回调和回调型增量写入器保留在 XRT C 层，
不把 C 指针及跨调用回调生命周期直接暴露给 xlang；语言层由配置字典、
事件位置、`writeTag` 与一次性 `writeTo` 提供对应的安全公开面。详情和
实际边界以《结构化数据标准库.md》为准。

2026-09-30 X23 标识符决定与实施：XID 使用不可直接构造的 `Xid` 名义值，
以 24 字节受管数据承载而不暴露可变字节视图。默认标准库保留生成文本的
`id.xid()`，新增 `id.make/makeMany/parse/tryParse/fromBytes`；值方法提供
`toString/toBytes/timestampMicros/compare/isZero` 和按内容比较。规范文本为
32 字符，解析按实际字节长度执行，错误带位置；只有格式错误被 `tryParse`
转换为 `null`。生成与编解码只使用 XRT XID 实现，安全随机源失败不回退。
名义类型的非对象表示在 XLIR 身份集合中有显式 TypeId，动态 `is/as` 不靠
Cgen 追溯类源声明。X23 已从未决策移出。

2026-09-30 X12 文件操作与模块合并边界决定：xlang 保留 `io` 与 `file`
两套文件操作。`io` 提供基础的字节流与文件打开、读取、写入等操作，

## 状态规则

- **未决策**：尚未决定是否进入 xlang，或父分类已决定进入、但具体 API 范围仍未确定。
- **已决策**：边界已经确定且不需要新增开发，例如弃用、委托给 XRT、保持为内部能力。
- **待开发**：已经决定进入 xlang，但尚未完成设计、实现和验收。按表中顺序推进。
- **已开发**：已经实现，并且本轮标准库重设计明确确认保留；仅仅“旧代码当前存在”不自动算已开发。

“弃用”只表示**不进入 xlang 默认标准库或不再从 CRT 直接公开**，不表示删除目标平台 CRT，
也不禁止高级用户通过显式 C FFI 使用相应能力。

父分类与子决策可以处于不同状态。例如浮点环境的公开边界已经决定，
但非 Windows 和跨线程验收仍属于“待开发/待验收”。

## 每轮对话规则

1. 每次标准库讨论都以本文为唯一状态来源。
2. 每轮回复必须附带当前阶段的“未决策”列表；已关闭项目不再出现在该列表中。CRT 当前没有未决策项，XRT 按模块逐项评估。
3. 用户作出决定后，当轮同步更新本文，并记录目标层级：语言内核、默认标准库、可选扩展、显式 FFI 或内部实现。
4. 从“待开发”移入“已开发”必须同时满足：设计明确、实现完成、测试通过、公开文档同步。
5. XRT 当前已有实现不等于 xlang 已经决定采用其语言外观；XRT 项仍须逐项评估。

### C14 信号覆盖核查

XRT 已覆盖标准信号能力，并提供跨平台稳定代码、平台支持查询、名称、重复/单次订阅、
owned 回调数据、引用计数监听句柄、注销、忽略、恢复、raise、累计计数、清零、健康检查和安全停机。
回调在 XRT 调度线程运行，而不是在原生 signal handler 上下文执行。覆盖范围足以关闭 CRT signal 直连方案；
未来只需在 X13 阶段决定 xlang 的高级语言外观。
