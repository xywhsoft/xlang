# 核心驻留依赖合同修正

本批修复两类实际依赖遗漏与一个声明头问题：

- 22 个 X.509 记录、配置和 CRL 组件使用原生句柄策略及错误作用域，却没有声明 `NATIVE_HANDLE` 依赖。逐组件补齐，复用其既有 `FOREIGN_ERROR` 传递依赖，不把整个 X.509 族强行挂到共同底座。
- 网络向量输入调用 `xl6ErrorScopeCaptureFailure`，补齐该组件直接的 `FOREIGN_ERROR` 依赖。
- `xl6_task.h` 在首次使用 `struct xrtownershippreparationv1` 后才声明它。将前置声明移到首次使用之前，修复独立包含此头文件时的严格 C 编译失败；布局和函数 ABI 不变。

同时修复驻留目录验收工具自身的边界：展开分文件组件 ID；检查声明头的实际包含关系；使用响应文件传递长编译命令；以真实 C 预处理和 `xl6ArtifactRuntimeSymbolOwner` 查询完整注册表，而不是猜测宏展开后的名称。Cgen 入口必须有正确且唯一的实现；私有 C 符号仍检查唯一物理属主和所有跨组件引用。不同角色引用同一 Getter 时，必须拥有相同组件属主，冲突仍拒绝。

Windows 证据：

- 完整重编译 1,295 个源编译单元，全部禁用对象缓存。
- 正常构建重新生成 CLI、两个 DLL 以及运行时、编译器两套内嵌 VFS。
- 另外独立编译 1,251 个驻留组件的严格 O0 对象。修正测试解析器后，对同一批源码和对象校验哈希并重新审计，未复用旧的通过结论。
- 目录审计通过 1,565,001 个组件依赖组合；确认 5,016 个 Cgen 入口、400 个私有 C 符号和实际宿主能力；28 项负例全部拒绝。

独立证据汇总：`E:/xlang-validation/five-groups-20261027/p7-shipping/closure-recovery-proof-r46/results.json`。实际目录报告为同级 `catalog-recheck-r44/audit.json`。

本批不修改 XRT 时间 ABI、不增加 Cgen 包装代码。它证明上述核心依赖修正及 Windows 专项；Linux、完整 74 项门禁、所有联合场景仍需最终验收。原先一次聚合依赖内存快照不一致的原因尚未证实，也未因后续重复通过而宣称解决。
