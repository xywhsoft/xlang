## 目标

本计划把 `release/extlibs` 中的目录分成可验证的生态状态，而不是把“存在
目录”误写成“已经发布”。每一个第一期扩展库都必须同时具备：

- 可构建的 xlang 包清单和真实的底层实现；
- 明确、简短并适合 xlang 的公开 API；
- 正常路径、错误路径、资源释放和取消/回调边界测试；
- 可运行的 xlang 范例；可稳定独立编译时再提供对应 C 范例；
- 由元数据生成的官网详情页。

`tools/audit_extlib_ecosystem.ps1` 从包目录、包清单、测试和示例生成机器可读的
`test/extlib_ecosystem.json` 和审计报告。当前 schema 为 `xlang-extlib-ecosystem-2`；
登记、源码清点、历史候选队列与测试结果分离，自动标签不能作为发布证明。
实际验收必须附带当前源文件/构建哈希、测试时间、命令、输出、退出状态与未验证范围。

## 状态定义

以下是自动清点状态，不是发布等级。正式准入必须另附具体版本、平台、API 范围与验收证据。

| 状态 | 含义 | 官网展示 |
| --- | --- | --- |
| `registered` | 登记了 featured、phase1 或 platform 套件，不代表已经运行或通过 | 显示登记与最近实际结果，不标已发布 |
| `source-review` | 存在清单声明的源码，完整范围尚需人工审查 | 不凭文件数量推断占位或完整实现 |
| `existing-hardening` | 已有真实后端，继续压实；已登记库也保留新增预算豁免 | 明确后端与未验证边界 |
| `budget-review` | 历史大型后端候选；未完成当前新增代码成本评估 | 不直接判定超过 10000 行或永久暂缓 |
| `environment-review` | 历史环境敏感候选；需明确设备、服务或凭据条件 | 不把缺少测试环境解释为没有实现 |
| `needs-abi-review` | 文本扫描发现本地 XRT 声明或旧 ABI 标记 | 仅为审查提示，须确认活跃调用及真实编译结果 |
| `invalid-package` | 清单不可解析、格式或名称错误、声明源码缺失等 | 明确具体问题，不展示可用标记 |
| `blocked-dependency` | 依赖不存在、清单无效或依赖上述阻塞包 | 明确依赖关系；不会据文本提示传播假阻塞 |
| `internal` | 仅供其他包使用的私有依赖 | 不生成公共详情页 |

`placeholder`、`deferred-large` 与 `deferred-platform` 只作为人工处置结论，
须列明实际缺失能力、预算或外部环境依据。一个 C 文件、正常失败返回、待办注释、
测试文件存在和登记名单都不能独立证明这些结论。

## 第一期开源生态准入规则

1. 不以目录数量作为生态规模，不以 `extern` 声明数量作为功能完整度。
2. 新实现优先下沉到 XRT；扩展库只承担 XRT/C 库到 xlang 的薄包装、对象
   生命周期、错误映射和易用 API。
3. 只有占位库在补齐真实能力时预计需要新增超过 10000 行的自研算法、协议栈或
   大型依赖移植，才记录为 `deferred-large`。已有实质实现的库不受总代码量限制，
   必须进入 `existing-hardening`，按真实后端完成迁移、测试、范例和边界压实。
4. 网络服务、数据库、GPU、模型推理、GUI、硬件和云服务库必须有可重复的
   本地或容器测试环境；没有环境时不宣称生产可用。
5. `native` 类必须有明确的 create/destroy、所有权和失败约定；错误必须进入
   当前 XRT error 模型，禁止复用废弃的局部错误/缓冲区 ABI。
6. C 范例只在库本身拥有稳定 C 表面时提供。依赖 xlang 运行时内部私有模块的
   包，不伪造独立 C 可用性。

## 本轮批次

### A. 已有 RC 基线

`aho_corasick`、`argon2`、`blake2`、`blake3`、`bloom`、`brotli`、`bson`、
`bz2`、`crc32`、`lz4`、`lzma`、`md5`、`miniz`、`murmur3`、`sha3`、
`siphash`、`snappy`、`xxhash`、`zstd`。

这些是历史重点名单，不凭名单维持当前 `featured-rc` 结论。默认后端或运行库改变后，
必须在相应构建上复验；仍以破坏性测试、性能回归和 API 一致性改进为主，不以兼容旧接口扩张。

### B. 首期优先补强候选

- 数据与配置：`cbor`、`csv`、`ini`、`toml`、`plist`、`yaml`、`xml.sax`、
  `xml.etree`、`xml.dom`、`zip`、`tar`、`gzip`、`md4c`、`netrc`。
- 算法与本地工具：`chardet`、`consistent_hash`、`crontab`、`diff`、`dotenv`、
  `fuzzy`、`geohash`、`hyperloglog`、`lru`、`progress`、`tabulate`、`trie`。
- 具备明确平台条件的小型能力：`clipboard`、`com`、`daemon`、`sysinfo`、
  `watch`、`singleinstance`、`sharedmem`、`serial`、`process` 类近邻能力。

候选不等于已发布。每个库需通过本计划的门禁后才能变成 `phase1`。

重新执行整个 144 项 catalog 或做远端发布；旧 catalog 的 1948 个输入复核仍匹配。

本轮新增 CSS/DNS 独立诊断：正常输入通过，非法谓词输入抛 IOError/ValueError，
与现有 false/0 预期不一致，捕获后正常调用恢复。统一原生错误合同进入接入收口队列；
不能通过直接标 `@no_raise` 掩盖仍会建立的错误。HCL/FIX/PKCS 的类似外显失败
另行定位，不能将七个运行时异常一概归因到同一个问题。

另追踪 native-backed class 的宿主观察：直接 point 写入 handle 后的表示一致性，
以及原生工厂构造时普通语言字段默认初始化。Aho 改用已有接管构造、把 Scanner 状态
放入 C 对象后主路径通过，不等于这些生成器边界已经全面修复。后续使用独立小用例
审查当前源码及生成 C，不替换共享宿主来掩盖库侧问题。

另记录宿主侧待复核观察：范例中把带字符串实参的查询直接嵌入 f-string
（`f"{db.query('select id from people').length}"`）时，当前宿主报插值表达式解析错误。
范例已改为先取得行数再格式化；这不是语言问题已修复的证明，也不应通过放宽库的
测试来掩盖。后续须独立确认表达式边界与当前编译器源码状态。

### C. 既有实现压实与暂缓评估

`onnxruntime`、`dinov3`、`rapidocr`、`xfeat`、`opencv`、`xbot`、`sqlite`、
`md4c` 与图像基础库已有可审计实现，不因总代码量大而暂缓。它们先进入
`existing-hardening`：确认后端真实可调用、资源生命周期、错误映射、可重复测试、
C/xlang 范例和平台依赖，再决定是否纳入第一期。

下列类别通常不能以轻量自研代码达到第一期质量：

- 尚无真实后端的大型推理/视觉/音频栈：`llama`、`libtorch`、`tensorrt`、
  `openvino`、`whisper`、`stablediffusion` 等。
- 大型数据库和消息系统：`mysql`、`postgresql`、`mongodb`、
  `rabbitmq`、`clickhouse`、`tdengine` 等。
- 大型协议/基础设施：`grpc`、`quic`、`webrtc`、`kubernetes`、`docker` 等。

这些是评估类别，不是逐项已完成的延期决定；以实际 backend、缺失能力和新增成本为准。
`xssh` 已有实现，不能再按旧 `ssh` 占位判断；`terraform_state` 已在集中测试清单中。

### D. 当前集成收口队列

以下属于已有实现的接入与质量问题，不按占位库新增预算整体暂缓：

- 包原型：检查 bool/整数、`point`/`const void*`、无返回析构、typed 容器与
  C 真实参数的精确对应。不得屏蔽原型检查或强制转换不兼容的容器指针。
- XRT 模块与声明 SDK：让包声明的 `xrtModules`、编译宏和头文件依赖检查保持
  一致；不能通过恢复整库默认编译或吞掉 `#error` 让包假通过。
- XLIR 与错误桥：处理正常返回、异步终止块、辅助符号、原生错误与语言异常合同。
- `_xge_native`：当前桥已经使用 `xrtValueInvoke`，不能继续套用“仍大量使用 xvo”
  的旧判断。当前导入测试暴露的是生成原型与 C 声明冲突；导入通过之后仍需真实
  渲染、交互和回调生命周期验收。
- 简化库自身边界：本次独立 C 探针确认 MySQL 状态字符串越界、FAISS 小数输入
  不前进。这些是真实实现问题，不能被公共编译链失败掩盖。
