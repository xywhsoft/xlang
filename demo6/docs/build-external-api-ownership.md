# 构建能力矩阵：显式扩展产品归属

普通 Windows／Linux 构建在 XRT 快照校验阶段被既有 XACME 驻留适配器阻断：
它调用的是独立扩展产品的 `xrtAcme*`，不是核心 XRT／xruntime 的公共 API。
此前矩阵把这些实际调用归入未知核心符号；本批不修改扩展功能或网络行为。

`gen_xrt_xlang_matrix.py` 的显式产品登记现在区分：

- 核心及 xruntime：仍来自固定快照、精确符号表及既有语义能力合同。
- 扩展产品：从登记的单头公共声明区读取精确名字，检查提供方文件存在，
  并限定允许引用的适配器文件；不按 `xrtAcme` 等前缀放行。
- 未知引用：仍进入原来的严格延期／未知检查。拼错的新名字、不同使用方、
  核心符号归属冲突或缺失声明／提供方均拒绝。

外部 API 的声明与引用单列于 `externalProductReferences`，不增加核心公共
API／TCC 符号或延期数量。原始公共头中同一来源、完全相同的 C 重复声明
可以合并；不同原型／来源仍拒绝，核心头原有的重复声明检查保持严格。

静态检查只证明上述声明和引用归属，不证明提供方实现质量、链接正确性、
功能完整或安全性；实际链接和产品运行继续由正常构建与验收负责。

`check_xrt_external_api_matrix.py` 在 Windows／Linux 各通过 14 项纯静态
检查，涵盖操作表地址、未知名字、错误使用方、冲突原型／来源、缺失输入和
核心数量隔离。真实报告单列 42 项扩展引用，核心仍为 3434 API，xruntime
产品仍为 3899 API，延期为 0。测试不调用任何扩展 API，不发起网络连接。

这是五组联合封板所需的构建前置，不是 XACME 新功能、功能验收或新增标准库
决策。首轮普通构建的真实拒绝和静态测试记录保存在
`F:/xlang-validation/five-groups-20261026/p7-crypto-migration/`。
