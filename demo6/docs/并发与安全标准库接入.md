# 并发与安全标准库接入

本批按已批准方案更新并发、密码学与 ASN.1、X.509、TLS。实现复用 XRT，
安全适配驻留于 runtime；XLIR 验证参数、结果、效果和拥有权，Cgen 只负责声明、调用和清理。
本轮首批实现摘要、HMAC、KDF、AEAD 以及 DER/PEM；四组整体尚未完成。

2026-10-18 后续已纳入《五组标准库接入长期任务.md》：按共同合同、并发、
网络、非对称密钥、X.509、TLS 顺序推进。后续测试遵守用户限制，只做离线
及受控本机常规验收；网络安全专项由用户在 XRT 层执行，历史首批证据不变。

## 摘要和密钥派生

`crypto` 提供 SHA224、SHA256、SHA384、SHA512、SHA512_256；
`cryptoLegacy` 提供 MD5、SHA1，仅用于已有格式和非安全兼容场景。
每种摘要均有 string/bytes 重载、显式 `*Buffer`、返回 string 的 `*Hex`/`*BufferHex`。
默认返回 bytes，十六进制统一小写。消息的 `size=-1` 使用完整字节，非负值截断到实际长度，
小于 -1 报错；UTF-8 和内嵌 NUL 不作 C 字符串处理。

`*Stream()` 或相应类提供 `update`、`updateBuffer`、`final`、`hex`、`clone`、`reset`。
final/hex 读取快照而不封闭状态；clone 的后续更新独立。可变流绑定创建线程，
跨线程访问报状态错误，不能假定可跨 await 使用。析构擦除状态及 HMAC 初始状态。

HMAC-SHA256/384/512 与上述消息接口一致，但 key 必须为完整 bytes。
`pbkdf2Sha256/384/512(password, salt, iterations, length)` 使用 bytes 密码和盐；
iterations 必须处于 1..UINT32_MAX，输出限制为 16 MiB。
这是 PBKDF2 原语，不是自动选择成本参数的密码存储方案。

`hkdfSha256/384/512(ikm, salt, info, length)` 使用完整 bytes 材料；
`*Extract(ikm, salt)` 和 `*Expand(prk, info, length)` 单独公开。
Expand 要求 PRK 长度等于该摘要长度，输出最多 255 个摘要块。
可分配或报错的入口不能声明 no_raise；PBKDF2 不标记 nonblocking。

## AEAD

`AesGcm(bytes key)` 接受 16/24/32 字节密钥；`ChaCha20Poly1305(bytes key)` 接受 32 字节。
密钥对象不公开私有数据字段，析构擦除密钥/展开状态。两者提供：

```text
seal(string|bytes data, bytes nonce, bytes aad = b"", int size = -1, int aadSize = -1) -> bytes
open(bytes data, bytes nonce, bytes aad = b"", int size = -1, int aadSize = -1) -> bytes
```

输出为 cipher || tag。nonce 固定 12 字节，tag 固定 16 字节，不能用消息 size 截断密钥或 nonce。
同一密钥下 nonce 必须唯一，接口不会自动为使用者管理 nonce。
open 必须认证成功才交付拥有式明文；失败擦除并释放暂存输出，不以空字符串掩盖错误。
旧的十六进制字符串 AEAD 函数退出默认公开面，不保留两套兼容接口。
`crypto.timingSafeEqual(bytes, bytes)` 在长度相等时使用 XRT 恒定时间比较；长度视为公开信息。

## DER 和 PEM

`asn1.parse(bytes data, size = -1, byteLimit = 16777216)` 要求完整、规范且仅一个 DER 值，
返回 `DerValue`。它拥有独立原始数据，提供标签、原始/内容字节、布尔/整数/无符号字节、
BIT STRING、OCTET STRING、OID 文本及独立子 Reader。原生验证深度上限为 64。

`DerReader` 有独立拥有数据、done、remaining、read、peek；既支持连续 TLV，也支持构造值子游标。
读取失败和分配失败均不推进游标。正常结束由 done 查询区分，结束后 read 报范围错误。
`DerBuilder` 提供布尔、有符号/无符号整数、NULL、OID、位串、原始 TLV 和完整标签构建，
另有 octets/sequence/set 便利方法。任意构造内容仍须通过规范验证，包括 SET 排序。
finish 返回独立 bytes，reset 清除已写入数据；默认输出预算为 16 MiB。

`pem.encode(label, bytes data, size = -1)`、`pem.parse(text, label = "", size = -1, byteLimit = 16777216)`、
`pem.decode` 和 `PemReader` 支持单块、指定标签及多个块。PemBlock 拥有 raw/label，decode 返回 bytes。
label 拒绝内嵌 NUL；解析保留有界长度，不依赖 strlen。Reader/Builder 绑定创建线程。

## 首批验收

2026-10-18 的最终全新优化候选通过 Windows 84、Linux 93 个阶段，输入和输出日志哈希均保持一致。
217 个接口的 ABI 声明、闭合合同、符号登记以及两端双产品的真实导出逐项一致。
语言用例覆盖 JIT、模块重定位、无 xl 依赖的独立 AOT，以及严格 GCC O0/O2。

原生故障宿主在每个产品上尝试 384 个 crypto 和 352 个 DER/PEM 分配故障前缀，
核对分配账本、无部分结果与读取失败不推进游标。Linux 另有 3225 次实际降低后 IR 的
合同变异拒绝，错误合同在输出 C 或头文件之前被阻止。SHA256 独立用例不引入其他密码算法或 TLS。
私有句柄访问拒绝、可变状态异线程拒绝、不可变 AEAD 密钥跨线程使用和 OID 的精确输出预算均已验证。

验收入口为 `tools/check_stdlib_crypto_asn1.py --root <fresh-demo6> --out <fresh-directory>`。
候选保存在独立验证目录，没有覆盖仓库 release 二进制；以上不代表四组整体完成、完整密码学安全审计或全仓 RC0。

### 独立的语言边界

验收中观察到 `bytes` 索引的 u8 与 int 字面量直接进行混合位运算时，
`data[0] ^ 1` 会被 IR 的物理值转换检查拒绝。本批篡改向量使用显式的
`uint8(int(data[0]) ^ 1)`，不放宽或绕过 IR 验证；混合窄整数位运算及其诊断
需在语言层单独修复，不能由密码学适配器补丁掩盖。

后续五组长期任务的 P0 首批已修复可表示整数常量的路径，包括
`data[0] ^ 1`；越界常量与一般变量的隐式缩窄仍不允许。
Windows 28、Linux 30 阶段离线复测通过，详见长期任务记录。

## TaskGroup 配置与拥有式观察（2026-10-19）

公开类不再提供 `point` 构造、`childNative`、公开句柄或窄 `c_int` 计数。
`TaskGroup(limit = 0, cancelOn = 0)`／`task.group(limit = 0, cancelOn = 0)`
复用同一个原生实现；另有 `TaskGroup(CancellationToken, limit = 0, cancelOn = 0)`。
`child(limit = 0, cancelOn = 0)` 直接返回受管理子组，不经拥有式裸指针临时值。
limit 必须非负，0 表示不限额；策略是可组合的整型常量
`taskGroupCancelOn.none/failed/cancelled/closed/stopped`（0/1/2/4/7），未知位拒绝。
策略决定成员以相应非成功终态结束时，是否向其余成员请求取消；closed 指
成员 Future 的生产端关闭，不是调用组的 close()。close() 本身只关闭后续接入。
满额或已关闭的 `add` 返回 false，资源错误走 checked 错误；不能把
“启动后再 add”当作原子启动。原生 `xl6TaskGroupStartV1` 已复用 XRT 的
先预留、后调用同步 starter 合同；语言 typed starter 接入仍未完成。

`snapshot()` 返回独立、不可变的 `TaskGroupSnapshot`，只拥有 POD 数据，
不隐藏持有组、Future、错误或取消令牌。计数是 uint64：active、added、
completed、succeeded、failed、cancelled、closed、rejected；另有 accepting、
cancelling、hasFirst、firstIndex、firstState。firstIndex 只有 hasFirst 时有效；
firstState 对应 `taskGroupState.pending/resolved/failed/cancelled/closed`。
firstIndex 是最先观察到的非成功终态的入组序号，不是最小失败序号。
`count`、`reapCompleted()` 也使用 uint64，不再经过 INT_MAX 饱和。
快照和 `cancellationToken()` 返回的独立引用均可在原组释放后使用。
`throwIfFailed()` 以原始拥有式错误传播首个失败；只有取消／关闭时不抛出
失败异常，这两种终态仍由快照单独区分。

join／wait 的 true 只表示所有成员结束，不代表所有成员成功；失败情况读取
快照或调用 throwIfFailed。超时参数统一非负毫秒，负值／乘法溢出报错；
joinUntil／waitUntil 接受 uint64 单调微秒期限，不再使用旧的有符号毫秒 ABI。
joinCancel、joinTimeoutCancel、joinUntilCancel 只中断调用者等待，不取消组或
其他等待者。等待会关闭组的后续接入，这与 XRT 原生合同一致。

joinAsync 保留独立消费者的原生 inline 观察者。它不执行生成的语言代码，
没有语言捕获，也不为每次等待创建系统线程或协程栈；不能仅凭 V1/V4 名称
误判其为旧的每等待线程模型。取消是协作请求，不冒称已完成物理清理；
共享完成源和其他消费者不会被一次 join 的取消破坏。Close 仍可能同步通知
已有原生观察者，因此不误标 nonblocking。所有适配留在驻留 runtime，
XLIR 验证精确合同，Cgen 未新增库实现。

本批普通候选以源 TCC/XRT 与双 VFS 全新构建；Windows 916、Linux 909 阶段
通过，输入和日志封条保持一致。两个产品镜像各自完成完整语言分配前缀：
Windows 414／414，Linux 407／407，包含 checked 退役后的受控恢复与账本
平衡。实际 Linux 编译器的 123 项错误合同拒绝、四个裁剪计划，以及两端
JIT、module、严格 O0/O2 和可搬移独立 AOT 均通过。
入口为 `tools/check_stdlib_five_groups.py --stage task-group`；这不代表全部
TaskGroup 公开能力、P1、五组整体或全仓 RC0 已完成。
