# TaskGroup 语言拥有域与清理合同

TaskGroup 的语言句柄现在公开实际桥接节点，而不是被视为没有拥有边的原生叶子。
声明式注册表指定常驻句柄策略，独立拥有域负责准入桥接、原生组及其真实
Future、Promise、取消令牌和观察者。Cgen 继续使用通用句柄生成路径。

## 清理顺序

语言桥接的准备阶段沿用语言对象原有的销毁语义：关闭接纳；仍有活动项时
请求协作取消，并等待实际生产者确认完成。活动项归零后注销父取消观察者。
这与原生组 V2 的仅关闭并等待合同不同；语言拥有者可以请求取消，原生组
描述符本身没有新增取消授权。

准备、对象终结、全图 Clear 和物理 Finish 分离。准备不消耗原生创建者权利；
Clear 保留所有拥有槽位，Finish 才归还实际权利。所有物理完成职责就绪前，
计划保留每一个真实 pin。生成的 catch/finally 仍由正常执行路径负责。

准备开始后拒绝重新绑定父任务，避免清理过程中引入新的取消关联。旧 V1
描述符仍拒绝 Closing 桥接；新 V2 使用不同身份，允许计划继续观察稳定的
关闭外壳及已正常退役但仍被计划持有的原生项。

## 验收用例

原生目录测试覆盖 128 个真实语言句柄图，包括重复任务、嵌套组、父取消
关联、外部 Done 引用，以及准备前中止恢复。测试分别只加载 TaskGroup 域，
以及同时加载共享 Future 域，确认基础描述符身份一致。外部 Promise 是真正
的生产者根，必须由宿主正常确认取消；收集器不能伪造终态或折算外部引用。
未知句柄策略在调用它的 Trace 前拒绝；完成阶段禁止新分配并核对完整账目。

独立语言测试通过公开编译和模块 API 加载真实 xlang 程序。异步函数先等待
宿主启动，再等待包含自身的 TaskGroup。外部结果 Future 存在时，模块保持
存活且不能提前取消；释放后，生成的 catch 和 finally 各执行一次，类终结时
模块全局值仍可读。测试检查代码映像退役及完整分配账目，共覆盖 18 次真实
模块生命周期，包括显式激活、一次性执行及仅使用 task.spawn 的模块。
外部结果引用保持、宿主错误保留、清理重入和无诊断终结失败分别检查。
原生图测试不能替代这项语言端到端测试。

独立程序先建立 join Future，再发布真实启动屏障，构造组包含自身输出的
等待循环；不能把进入函数的通知误当成等待已建立。生成代码通过
严格 C 检查，并在搬移后的独立 EXE 中检查 catch/finally 和类终结。
独立程序不加载 xlang 运行库，不依赖工作区路径。

## 暂态准入与服务退役

含执行器、任务池或网络服务的模块统一使用可重试的 V4 退役合同。XLIR
根据实际服务所有权确定合同，构建、刷新和验证使用同一规则。Cgen 不从
名字猜测服务，也不把任务池的 BUSY 折成 bool 失败；所有已接纳工作和正常
清理结束后，才允许全局值终结及代码映像退役。

生命周期准入分为 ADMITTED、BUSY 和 REFUSED。常驻的
`xrtownershipquiescencev1` 只识别精确 Ops 身份的原生暂态；查询在全图冻结
期间只读执行，不调用 Count、Trace、用户代码或分配。执行器状态切换、
队列回调尾部、语言任务池和原生任务池执行／析构尾部均使用这项独立能力。
BUSY 不授予回收权限，不降低物理计数。未知节点、冲突能力和稳定的 opaque
数据仍按原有严格规则拒绝。

静态模块在每次计划探测时重新检查实际活跃代码栈，不能依赖前一轮冻结的
观察。终结器交接给独立工作线程的 64 次带屏障回归，固定检查这一竞态：
旧路径会把 Count 拒绝记成永久失败；新路径返回 BUSY，保留真实 lease 和
全部计划 pin，待线程正常退出后完成一次性终结及完整物理释放。

执行器专项另覆盖 64 个真实工作线程及 64 个原生任务池的执行／析构尾部
屏障，检查暂态恢复、未知 Count／Trace 拒绝、零分配探测和完整内存账目。
Linux 插桩通道覆盖完整 XRT/xruntime 实现及指定驻留提供方，不借用未插桩
的运行库实现这些职责。

## 宿主与独立程序退出

宿主 SDK 的 `xlRuntimeDrainRetiringChecked(milliseconds)` 仅处理已进入退役
队列的模块，分别报告 ready 和 ok。0 执行一轮，正数在轮次之间检查期限，
-1 等待真实工作及外部引用结束。调用者应先停止新上下文接纳并释放不再需要
的外部根；该接口不强制释放引用，不中断用户终结器，也不把错误当成忙碌。
无诊断的语义失败仍保留失败状态，已有宿主诊断保持优先。

一次性 run、module、源码 CLI 及独立入口均接入明确的退出清理边界。独立
入口使用可重试静态模块合同，在结束前等待正常 finally 和物理收尾，而不是
靠一次非阻塞探测或固定延时判断完成。独立程序在搬移目录后重复执行 64 次，
逐次要求成功退出且恰好输出一次清理标记，并检查不依赖 xl.dll、xlc.dll 或
libxl。任一失败都会使整项验收失败，不再收录为可忽略的已知阻塞。

本批次证据位于 `D:/xlang-validation/stdlib53-b322-dev`。完整构建使用独立
选定源码树，Windows 460 个、Linux 459 个翻译单元；只复用真实 TCC 核心。
运行检查由 `tools/check_task_group_catalog.py` 完成，既有 TaskGroup、Future
组合、桥接物理退役、原生准备及声明目录检查继续作为回归门槛。XRT 的
任务池查询已独立提交；消费侧只回移该合同，并保存源文件和生成头摘要，
不顺带同步其他 XRT 工作区改动。

这批合同不代表全部 53 模块或发布 DLL 已完成验收。异步多返回值仍保持现有
限制；未批准的功能不扩展，对象池保持最后处理。

外部父取消、纯原生通知与模块退出并行的交错，仍需独立检查桥接的 Busy／
BindingParent 及原生节点的暂态准入边界。现有专项不能替代这部分并发覆盖，
也不能替代全部 53 模块、发布 DLL、VFS 和 RC0 的最终验收。
