# 按光标查询的编译器补全接口

本增量为 IDE 语义补全提供独立查询接口。查询读取当前输入和覆盖层中的实际词法作用域、符号与接收对象类型，不复用上一次成功检查的索引，也不把静态命令目录当作语义候选。

## 接口与输入

```c
int xlcComplete(XLC_Context* ctx, const char* queryPath,
                size_t byteOffset, const char* outputPath);
```

```text
xl check entry.xl --json --completion-at source.xl byteOffset
xl check entry.xl --json --completion-at source.xl byteOffset --source-overlay source.xl snapshot.utf8
```

`queryPath` 必须是此次入口或其真实加载的 xlang 依赖。路径按上下文工作目录解析；Windows 使用 Unicode 路径比较。偏移为去掉可选 UTF-8 BOM 后的字节偏移，必须落在 Unicode 标量边界。已有内存入口和覆盖层 API 可直接用于查询，不保存或改写源文件。

支持标识符内部和末尾的查询，以及成员点号或安全成员点号后紧邻的查询。标识符内部查询使用光标前缀过滤，并返回整个标识符的替换范围。空成员名返回零宽度范围。字符串、注释、标量内部、声明名或未恢复的其他语法位置不会返回伪候选。

## 查询与检查的区别

解析器只在这一次查询的 token 流中替换目标标识符，或在点号后插入一个零宽度标识符。它保留原始文本、输入哈希和所有原始源码范围。查询 AST 带有专用源信息；普通解析不设置这个标记。语义检查到达目标表达式时捕获真实作用域，随后让查询表达式停止检查。查询编译单元禁止进入 IR 降级或生成产物。

查询返回 `phase: "completion"`，包含独立的 `completion` 对象；`ok` 表示该次查询是否取得候选事实。`completion.scope` 固定为 `cursor-query`，`checkedCompilation` 固定为 `false`。即使查询成功，原输入也可能包含尚未完成的标识符或点号。因此不能将它当作普通 `check` 成功、成功语义索引或项目可以构建的证明。原 `xlcCheck`、`xlcCheckWithSources`、`xlcCheckWithIndex` 的合同保持不变。

正常检查的诊断不会混入查询响应。无法建立前置语义条件、解析失败、重复解析目标源、接收对象无法求类型或容量超限时，查询返回失败、空候选及查询原因。

## 候选事实

名称候选来自光标处仍然存活的编译器作用域，使用实际查找顺序排除被遮蔽的名称，并应用确定赋值与函数捕获边界规则。变量类型取实际流分析结果；函数候选保留真实重载的符号身份和各自签名；注册类型来自实际类型注册表。编译器认可的默认初始化变量可用于补全。

成员候选读取真实接收对象类型，按实际 class 继承、最近成员、private/protected、静态/实例和泛型替换规则过滤字段及方法。候选包含名称、类别、实际符号 ID、规范类型，以及存在真实来源时的声明选择范围。内建或隐式实体没有源码选择位置时返回空范围。

响应同时携带本次加载文件的 `sourceReport`、解析候选的 `resolutionReport`。来源使用原始输入哈希；序列化前后重新校验磁盘输入。IDE 消费者仍需按文档版本、请求身份、光标、编译器身份及这批来源/解析条件验证结果，不能仅依靠候选名称判断是否过期。

容量限定为最多 4096 个候选、4 MiB 已保留文本、单项名称 512 字节、单项规范类型 8192 字节，类型格式化另有深度和访问限制。超限整批拒绝，不宣称截断结果完整。

## 当前边界与接入顺序

本接口首批支持词法名称和 class 字段/方法；导入命名空间需要导入解析器提供公开别名映射，动态容器、协议、枚举、union 和特殊成员仍需扩展。编译器内部扁平化导入名称不会作为可插入的源码候选泄露。此接口不提供 C 项目语义查询，也不承诺完整项目、多 C 输入或原生 ABI 文件依赖索引。

IDE 的 C/xlang 双语法与现有静态命令补全继续可用。此增量不宣告 LSP `completionProvider`；后续接入独立补全进程、版本/来源校验、标准 UTF-16 textEdit、原生候选窗格和取消/过期回归后，再开放真实语义补全能力。
