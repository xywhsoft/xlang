# 文件系统标准库实施记录

更新：2026-10-01。范围为 22 个原生文件系统模块与 4 个 VFS 模块。
本轮开始实施，不代表 26 个模块的语言公开面已全部完成。

## 架构合同

- `path` 处理路径文本及平台路径转换；不隐含打开文件。
- `io` 保留基础字节 IO；`file` 保留 XRT 的高级文件、编码识别与文本转换。
- VFS 是显式 `Vfs` 对象及 `vfs` 工厂命名空间；不替换进程全局文件系统，
  不拦截既有 `file`、`dir`、`io` 的路径。
- 原生和虚拟文件共用 XRT `xfile` backend。虚拟 provider 不能伪造平台句柄；
  lock、map、异步绑定按 capability 拒绝不支持的 backend。
- native-backed class 使用语言自动生命周期。资源句柄的物理投影、错误边界及
  destructor 身份在 XLIR 中封闭验证，Cgen 只消费这些结果，不追溯 AST 或猜测句柄类型。
- 数据 `string`/`bytes` 使用实际字节长度；可选输入 `size=-1` 表示全部，
  非负值超过输入长度时截断，小于 -1 报错。路径不接受内嵌 NUL，不能静默截断。

## 本轮完成的基础批次

XRT 主线整合已有 VFS 实现：`vfs`、`vfs_memory`、`vfs_disk`、`vfs_pack`，
以及文件 backend、root-relative 目录读取和资源包解码依赖。
保留主线已经修好的原生预分配顺序，避免 OS 成功截断文件后才发生 wrapper OOM。
普通路径、FileRoot 与 DiskFS 的写打开均有分配失败回归。

xlang 第一批公开面：

| 类型/入口 | 已实现能力 |
|---|---|
| `vfs.create() -> Vfs` | 独立挂载表、受管理生命周期 |
| `vfs.memory() -> MemoryFS` | `put(path, string/bytes, size=-1)` 精确复制；`seal()` 冻结 |
| `vfs.disk(root, access=1) -> DiskFS` | 受限根目录；access 1=读、2=写、3=读写 |
| `vfs.pack(source, offset=0, length=-1, format=0, cacheBytes=67108864, maxEntryBytes=1073741824, maxDecodedBytes=8589934592) -> PackFS` | 原生文件来源、切片、格式选择、解码/缓存预算；`format` 查询 |
| `Vfs.mount(prefix, MemoryFS/DiskFS/PackFS, priority=0, caseMode=0) -> VfsMount` | 高优先级覆盖；仅 MISS 回退，权限、CRC 等 ERROR 不回退；caseMode 0=敏感、1=ASCII 不敏感 |
| `VfsMount.id / unmount()` | 挂载标识及幂等卸载；控制句柄析构只释放句柄，不隐式卸载 |
| `Vfs.readBytes(path, maxBytes=67108864) -> bytes` | 有界完整读取、保留 NUL；超出限额报错，不返回半份数据 |

挂载保留 provider；销毁创建方变量或控制句柄不会使挂载内容悬空。
XRT 决定原生文件源的接管时机：PackFS 创建成功后接管，失败时适配器关闭文件并保留原错误。
当前数字选项有严格范围检查；最终枚举/配置对象公开面与完整 File/IO 接入属于后续批次。
资源包 CRC 用于损坏检测，不是密码学完整性认证。

```xlang
auto fs = vfs.create()
auto memory = vfs.memory()
memory.put("data.bin", b"a\0b")
memory.seal()
auto mount = fs.mount("/app", memory)
bytes data = fs.readBytes("/app/data.bin")
assert data.length == 3
mount.unmount()
```

## 26 模块验收状态

### 统一 File 与元数据批次

已新增 45 个封闭文件系统操作描述，参数/结果 ABI、资源 destructor 身份与原生依赖
来自同一份 `xl6_ir_fs_operations.inc`。只生成可达操作的适配器；三个 64 位操作掩码
有编译期容量检查。旧的 `File` 标准库类声明已删除，不再同时维护两种 File 表示。

- `file.open(path, flags=1, mode=438, share=7)` 和
  `Vfs.open(path, flags=1, mode=438, share=7)` 均返回同一种受管理 `File`。
  flags 使用 XRT 的 read=1、write=2、create=4、truncate=8 等位；默认只读。
  原生控制块在打开/截断之前分配。语言受管理对象的接管仍可能在打开成功后分配失败；
  此时会关闭文件，但不会撤销已创建文件或已完成的截断。需要替换事务时使用原子写入，
  不能将 `open(..., truncate)` 的失败理解为文件内容不变。
- `File` 提供 `read/readBytes/readExact/readAt/readAtExact`、
  `write/writeAll/writeAt/writeAtAll`、精确长度 `writeText`、`readText`、
  `seek/pos/size/flags/resize/flush/close/closed/eof/setEOF`。
  字节读取返回 `bytes`，不再隐式返回 Buffer；偏移读取不改变游标。
  `pos/size/seek` 返回 uint64，写入次数返回 int。
- `readText(count=-1, encoding=0, policy=0)` 保留 NUL 和真实结果长度；encoding
  使用 XRT Unicode 编码编号 0=检测、1=UTF-8、2/3=UTF-16 LE/BE、4/5=UTF-32 LE/BE，
  policy 0=严格、1=替换；检测读取移除匹配 BOM，冲突 BOM 报错。
  缺省 count 从当前游标读到末尾，设 64 MiB 硬上限，正数 count 为单次请求。
  此编号不等同于旧全局 `encoding` 的代码页编号；全局 file 文本面仍待统一迁移。
- `native()` 只查询真正的 OS 句柄整数；虚拟文件返回 XRT 的不支持错误。
  `nativeHandle()` 是供已有 C/网络调用桥接使用的借用 xfile 指针，不是 OS 句柄；
  不得保存到 File 生命周期之外，也不得由外部调用者关闭。
- `file.stat(path, follow=true)`、`File.stat()`、`Vfs.stat(path, follow=true)`
  返回拥有快照的 `FileStat`：type/available/mode/attributes/size/device/identity/linkCount，
  accessed/modified/created/changed（Epoch 微秒）及 path/name/nameBytes/validUtf8。
  必须用 available 判断元数据字段是否由平台提供，不把零值当成有效值证明。
- `dir.open(path, flags=0)` 和 `Vfs.openDir(path, flags=0)` 返回同一种
  `DirectoryIterator`：advance/current/path/close 与 for 迭代。
  flags 1=查询元数据、2=跟随链接、4=包括点目录。
  current 返回独立 FileStat 快照，名称不会随下一次迭代失效；非法 UTF-8 名称可用
  nameBytes 检查，name 字符串访问明确报错。
- 文件和目录显式关闭均幂等；关闭后的读写/查询报错。XRT 短读和严格 EOF 错误保留。
  PackFS 的旧 `statCounter(field)` 已由下文的一次采样 `PackStats` 替代。

### 能力、流与资源批次

新增 28 个封闭操作，共 73 个。`File.capabilities` 是模式过滤后的能力位，不以原生句柄
推断读写权限。`reader()` / `writer()` 创建 IoReader / IoWriter，并保留文件控制块；
来源 File 离开作用域后仍有效。File 显式 close 在流、映射或锁活跃时拒绝关闭。

- `File.map(offset=0, size=0, flags=1)` 返回 MappedFile；size=0 表示映射到末尾。
  `bytes(offset=0, size=-1)` 返回独立快照；`write(offset, bytes, size=-1)` 有界写入；
  `flush/close/size` 不公开悬空映射指针。虚拟 backend 不支持时明确报错。
- `File.lock(mode=2, offset=0, size=0, wait=false)` 返回 FileLock；一个 File 只允许一个
  活跃租约。显式 close 解锁失败时保留租约可重试，析构保留原错误并尽力释放。
  Windows 锁按句柄；POSIX XRT 仍为进程级 fcntl 锁，同 inode 的其他描述符关闭可能
  解除锁。不能将此接口理解为跨描述符独立锁，也不保证同进程线程之间互斥。
- `file.root(path)` 返回 FileRoot；公开根内 open/openDir/openRoot/stat/createDir/remove/
  readLink/createLink/createHardLink/createFifo/setMode。子根及打开资源独立持有原生锚点，
  不借用诊断路径实现安全检查。关闭父根不使子根或已打开资源悬空。
- 原子引用计数仅解决内部资源寿命，不保证 File 的游标、读写或显式关闭跨线程安全；
  并发操作及关闭由使用者同步。Root 关闭同样不能与根操作并发。
- Windows `FileRoot.setMode` 现与普通 `file.setMode` 一致：POSIX 权限模式明确不支持，
  不再只查询目标存在后返回假成功。XRT modular/single 与语言平台夹具检查此边界。

### 路径、完整文件与文本批次

新增 64 个封闭操作，共 137 个；生成器按路径与整文件分文件维护，仍只按 XLIR
已验证的操作选择。`path` 与新的全局 file 入口不再触发旧 `XL6_FILE_RUNTIME` 大块输出。

| 公开面 | 合同 |
|---|---|
| path.parse(path, style=0) -> PathParts | 拥有输入快照；root/parent/name/stem/ext/rootKind/flags |
| path.components(path, style=0) -> PathIterator | 组件迭代；advance/text/kind，for 返回 PathComponent? 快照（使用前收窄非 null） |
| path.build(array parts, style=0) | 每项必须为字符串，一次调用 XRT Build；不反复追加复制；拒绝 NUL |
| path.clean/normalize、relative、isLocal | style 0=本机、1=POSIX、2=Windows；仅词法运算，不是符号链接沙箱 |
| path.name/nameExt、stem、parent/dir、ext、join、withName/withExt | name 含扩展名，stem 不含；nameExt/dir 是别名；join 支持变参 |
| path.isAbs/isRoot/isRooted、isSafeEntry、sep/listSep | 安全条目检查不替代 FileRoot；无效候选返回 false，NUL 参数报错 |
| path.cwd/setCwd/abs/real/rel/home/temp/executable/appDir | real 必须存在且解析物理链接；setCwd 改变进程全局状态，调用者同步 |
| file.readBytes(path, maxBytes=67108864) -> bytes | 完整有界读取，超限报错，无隐式 Buffer；空文件返回空 bytes |
| file.writeBytes/appendBytes/writeBytesAtomic(path, bytes, size=-1) | 精确字节前缀；原子替换走同目录临时文件，普通写入不是事务 |
| file.readText(path, encoding=0, policy=0, maxBytes=67108864) | 精确 UTF-8 结果长度，NUL 保留，源字节上限；检测 BOM/编码与转换由 XRT 负责 |
| file.writeText/writeTextAtomic(path, text, encoding=1, policy=0, bom=false, size=-1) | UTF-8 前缀输入，目标编码 1..5；严格模式切断 UTF-8 序列时报错 |
| file.appendText(path, text, encoding=1, policy=0, size=-1) | 转码后追加，不插入 BOM，不推断或改变已有文件编码 |
| file.size/setSize、attr/setAttr/setMode、exists/delete/touch/copy/move/rename/replace | size 为 uint64；失败通过 XRT 错误传播，不以 false 静默吞掉 OS 错误 |
| file.readLink/createLink/createHardLink/deleteLink/createFifo | 链接不冒充复制；不支持的平台或权限不足明确报错 |
| dir.create/createAll(path, mode=511)、exists/empty/remove、copy/move | remove 只删除空目录；递归 create 的失败可能留下已创建前缀 |
| dir.temp(directory="", prefix="xl-", suffix="") -> string | 排他创建临时目录，空 directory 使用系统临时目录；返回路径由调用者管理，释放字符串不会隐式递归删除目录 |

本批是有意破坏兼容性的更新：file 字节入口从 Buffer 改为 bytes；文本编码编号统一
为 XRT 0=检测、1=UTF-8、2/3=UTF-16 LE/BE、4/5=UTF-32 LE/BE（写入不接受 0）；
policy 0=严格、1=替换。旧代码页参数不沿用。path.name 统一为包含扩展名的末级名称，
旧用途应改用 path.stem。FileStat.available 仍是判断元数据字段有效性的依据。

## 同步目录树、统计和临时文件批次

新增 16 个封闭操作，共 153 个。新增公开面：

- `file.temp(directory="", prefix="xl-", suffix=".tmp") -> File`：0600 排他创建；
  `tempPath` 返回拥有路径副本，`keep()` 将路径清理责任转交给调用者。
  默认随最后一个 File/IO/map/lock 持有者释放而清理；活跃租约仍禁止显式 close。
  文件默认仍是具名文件，调用者须避免名称被外部并发替换或移动。
- 显式 close 先删除打开的临时对象再关闭；删除失败保持 File 打开以便重试。
  析构清理是 best-effort，OS 权限/共享冲突仍可能留下文件，不能承诺无条件删除。
  XRT `xrtFileDeleteOpen` 的成功路径不申请内存；语言包装分配失败时不会因
  Windows 路径转换再次 OOM 而遗留临时文件。普通文件不自动删除。
- `dir.roots() -> array<string>`；`dir.list/files/dirs(path, recursive=false,
  maxEntries=1048576)` 返回独立路径数组，超限报错而非静默截断。顺序由文件系统决定。
- `dir.stats(path, recursive=true) -> WalkStats`、`file.walkStats(path, flags=0,
  maxDepth=-1)`；统计包含 items/files/directories/links/others/bytes/stopped，
  根对象计入 items，目录只在进入时计一次；默认不跟随链接。
- `file.copyTree(source,target,flags=0) -> TreeStats` 和
  `file.removeTree(path,keepRoot=false) -> TreeStats` 使用 XRT 策略，不复制遍历算法。
  copy flags：1 merge、2 replace、4 follow links、8 skip links、16 one filesystem、
  32 skip special、64 metadata；4 与 8 冲突。默认目标必须不存在、保留链接、拒绝特殊文件。
  copy/remove/move 不是事务，失败可留下部分进度；返回语言对象分配失败也不会回滚树修改。
- `dir.delete/clean/ensureEmpty/count/size` 已迁移；count/size 为 uint64，
  count 不包括根。删除缺失目录会报错，旧夹具清理改为先检查存在。
- `file.setTimes(path,accessed=null,modified=null,follow=true)` 使用 Unix Epoch 微秒；
  null 保留对应字段，两项均 null 报错；`FileStat.available` 决定读取时间是否有效。

受管理 walk 回调、目录过滤/条目入口在下一个批次实现；异步仍未完成。

### 完整 Pack 配置与来源

- `vfs.packOptions(format=0, maxEntries=100000, maxIndexBytes=67108864,
  maxEntryBytes=1073741824, maxDecodedBytes=8589934592, cacheBytes=67108864)`
  返回只读 `PackOptions`，完整对应 XRT 六个公开配置字段。解析上限必须非零，
  maxEntries 不超过 uint32；CacheBytes=0 禁用缓存保留。其他预算使用 uint64。
- `vfs.pack(path, options, offset:uint64=0, length:int=-1)` 使用完整配置；
  旧简洁参数入口仍可使用。offset/length 必须处于来源范围内，不做溢出加法。
- `vfs.takePack(source:File, options, offset:uint64=0, length:int=-1)` 明确转移所有权。
  要求 readAt/stat capability、无活动 reader/writer/map/lock，临时 File 必须先 keep。
  XRT 解析失败不接管来源，File 保持打开；解析成功立即清空原 File，所有别名观察到
  closed。后续语言 wrapper 分配失败时销毁已接管的 pack，并不恢复原 File。
  该入口不能与同一 File 的其他操作并发；引用计数不是并发操作锁。
- 原生与 MemoryFS 来源均可接入，不要求平台句柄；提供者最后一个引用释放才关闭来源。
- `PackFS.stats() -> PackStats` 一次采样 hits/misses/loads/failures/residentBytes/evictions，
  只读快照不会随后续读取变化；不再用每个字段分别采样的 statCounter。
- XRTPACK v1 与 XSVPACK v1 均保留 stored/LZMA1 逐条 codec、CRC、格式硬选择及预算合同。
  解码失败不回退到 overlay 的低优先级 provider；CRC 不是安全认证。
- 目录路径列表不跟随根符号链接，类型不匹配时报错。string 路径列表遇到无效 UTF-8
  名称报 ValueError，不制造非法 string；DirectoryIterator 的 FileStat.nameBytes 保留原始名称。

“已有”只说明本轮之前存在部分入口，不等于已按新合同迁移或通过完整验收。

### 受管理遍历与条目批次

封闭操作总数为 163。Windows/POSIX 专项验收见下文：

- `file.walk(path, visitor, flags=0, maxDepth=-1) -> WalkStats`，以及带
  `onError` 第三个参数的重载。visitor 为 `func(WalkEntry) as int`，onError
  为 `func(WalkError) as int`；进入/离开事件、链接、环与跨文件系统标志保留。
  动作使用 `file.walkContinue/walkSkip/walkStop/walkError`；错误处理使用
  `walkAbort/walkSkipError/walkStopError`。非法动作报错，默认错误策略为中止。
- 回调接收拥有的只读快照，允许保存到数组或闭包；没有借用原生遍历缓冲的悬空视图。
  回调抛出的语言错误保留身份与消息，嵌套遍历和捕获内层异常不污染外层错误边界。
  XRT 不允许恢复的分配/程序错误不能被 onError 静默跳过。
- WalkEntry 保留 path/parent/name、对应 bytes、event/flags/depth/validUtf8、完整
  FileStat 元数据。非法 UTF-8 名称仍可通过 bytes 无损读取，字符串 getter 报 ValueError。
  WalkError 保留 path/pathBytes/kind/code/systemCode/domain/operation/message。
- `dir.glob(path,pattern="*",recursive=false,maxEntries=1048576) -> array<string>`；
  `dir.entries(path,recursive=false,maxEntries=1048576)` 和
  `dir.matchEntries(path,pattern="*",recursive=false,maxEntries=1048576)` 返回
  `array<WalkEntry>`。`dir.walk(path,pattern="",maxEntries=1048576)` 包含递归进入/离开
  事件，但不包含根事件。各列表超限报错，不隐含截断；根必须是非链接目录。
  空 pattern 表示不筛选，以便 bytes 元数据处理任意 POSIX 文件名；非空 pattern
  使用严格 UTF-8 glob，内嵌 NUL 不丢失，也不解释为 C 字符串终止符。
- `file.info(path,follow=true)` 统一返回一次采样的 FileStat；删除旧 FileInfo 及其
  多次查询/伪默认值实现。查询缺失文件报错，判断存在使用 file.exists。
- 补齐 `bytes(dynamicValue)` / `dynamicValue as bytes` 的封闭检查转换：仅接受
  XVALUE_BYTES，返回独立值 owner，保留内嵌 NUL；其他动态类型通过 TypeError 路径失败。
  Cgen 消费 Cast ABI，不从转换函数名称猜测语义。

公开范例：`release/examples/stdlib_fs_walk.xl`。

## 批量验证证据

当前实测平台为 Windows x64 GCC/TinyCC 与 WSL Ubuntu x86_64 GCC 原生 POSIX。
Linux TinyCC JIT、其他发行版及正式发布全回归仍需后续验收。

- XRT 隔离源码导出：7 个基础 suite，14 个 modular/single 测试程序通过，含写打开 OOM；
  8 个 provider OOM/并发 suite，16 个 modular/single 测试程序通过，均使用 `-Werror`。
- XRT 公开结构 ABI 检查 3 项通过；原生 file/map/lock/root 与 root 目录 OOM 回归通过。
- `tools/check_stdlib_vfs.ps1`：8 个正向夹具，逐一通过严格生成 C、JIT、独立 AOT、
  确定性输出及依赖裁剪；3 个错误资源 ABI 夹具在输出 C 前被拒绝；公开范例 JIT/AOT 通过。
- 统一 File 批次扩展为 10 个正向、5 个错误 ABI 夹具；新增用例覆盖原生/内存/DiskFS
  打开、NUL 文本/字节、短读/偏移游标、只读拒绝、元数据快照、目录 for 与关闭边界。
  45 个操作描述通过 Windows GCC `-Werror` 生成 C、TinyCC JIT、独立 AOT 和重复输出一致性。
  旧 Buffer/File 与网络 sendFileHandle 用例 JIT 回归通过；路径/File 旧夹具语法检查通过。
- 覆盖精确 NUL 字节、UTF-8 路径、长度截断、大小写、overlay/MISS/ERROR、
  读取预算、路径 NUL/穿越拒绝、包 CRC/切片/解码预算和 provider 生命周期。
- 资源批次扩展为 13 个正向及 5 个 ABI 负例；新增流/映射越作用域、活跃资源关闭拒绝、
  映射越界/快照独立、重复锁租约、虚拟 map/lock 拒绝、子根独立、硬链接和越界路径。

  Buffer 自身的旧 text() 限制不在本批擅自修改。

  runtime 源码独立链接，逐一通过原生 Linux GCC `-Werror` 编译与执行，含 NUL/编码、
  POSIX 路径、FileRoot、映射/锁/持有资源、两类分配失败扫描。此门不依赖 Windows DLL。

- 同步树/统计/临时文件批次：22 个正向、5 个 ABI 负例通过 Windows 严格 C/JIT/AOT、
  确定性及裁剪门；同批 22 个生成 C 在 POSIX GCC 下编译执行通过。新增 5 类各 48 个
  分配点故障注入，覆盖临时文件工厂回滚、系统根、路径列表和统计。公开临时 File/IO
