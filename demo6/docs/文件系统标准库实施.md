# 文件系统标准库实施记录

更新：2026-10-01。范围为 22 个原生文件系统模块与 4 个 VFS 模块。
本轮开始实施，不代表 26 个模块的语言公开面已全部完成。

## 架构合同

- `path` 处理路径文本及平台路径转换；不隐含打开文件。
- `io` 保留基础字节 IO；`file` 保留 XRT 的高级文件、编码识别与文本转换。
- VFS 是显式 `Vfs` 对象及 `vfs` 工厂命名空间；不替换进程全局文件系统，
  不拦截既有 `file`、`dir`、`io` 的路径。
- 原生和虚拟文件共用 XRT `xfile` backend。虚拟 provider 不能伪造平台句柄；
  lock、map、异步绑定按 capability 拒绝不支持的 backend。
- native-backed class 使用语言自动生命周期。资源句柄的物理投影、错误边界及
  destructor 身份在 XLIR 中封闭验证，Cgen 只消费这些结果，不追溯 AST 或猜测句柄类型。
- 数据 `string`/`bytes` 使用实际字节长度；可选输入 `size=-1` 表示全部，
  非负值超过输入长度时截断，小于 -1 报错。路径不接受内嵌 NUL，不能静默截断。

## 本轮完成的基础批次

XRT 主线整合已有 VFS 实现：`vfs`、`vfs_memory`、`vfs_disk`、`vfs_pack`，
以及文件 backend、root-relative 目录读取和资源包解码依赖。
保留主线已经修好的原生预分配顺序，避免 OS 成功截断文件后才发生 wrapper OOM。
普通路径、FileRoot 与 DiskFS 的写打开均有分配失败回归。

xlang 第一批公开面：

| 类型/入口 | 已实现能力 |
|---|---|
| `vfs.create() -> Vfs` | 独立挂载表、受管理生命周期 |
| `vfs.memory() -> MemoryFS` | `put(path, string/bytes, size=-1)` 精确复制；`seal()` 冻结 |
| `vfs.disk(root, access=1) -> DiskFS` | 受限根目录；access 1=读、2=写、3=读写 |
| `vfs.pack(source, offset=0, length=-1, format=0, cacheBytes=67108864, maxEntryBytes=1073741824, maxDecodedBytes=8589934592) -> PackFS` | 原生文件来源、切片、格式选择、解码/缓存预算；`format` 查询 |
| `Vfs.mount(prefix, MemoryFS/DiskFS/PackFS, priority=0, caseMode=0) -> VfsMount` | 高优先级覆盖；仅 MISS 回退，权限、CRC 等 ERROR 不回退；caseMode 0=敏感、1=ASCII 不敏感 |
| `VfsMount.id / unmount()` | 挂载标识及幂等卸载；控制句柄析构只释放句柄，不隐式卸载 |
| `Vfs.readBytes(path, maxBytes=67108864) -> bytes` | 有界完整读取、保留 NUL；超出限额报错，不返回半份数据 |

挂载保留 provider；销毁创建方变量或控制句柄不会使挂载内容悬空。
XRT 决定原生文件源的接管时机：PackFS 创建成功后接管，失败时适配器关闭文件并保留原错误。
当前数字选项有严格范围检查；最终枚举/配置对象公开面与完整 File/IO 接入属于后续批次。
资源包 CRC 用于损坏检测，不是密码学完整性认证。

```xlang
auto fs = vfs.create()
auto memory = vfs.memory()
memory.put("data.bin", b"a\0b")
memory.seal()
auto mount = fs.mount("/app", memory)
bytes data = fs.readBytes("/app/data.bin")
assert data.length == 3
mount.unmount()
```

## 26 模块验收状态

### 统一 File 与元数据批次

已新增 45 个封闭文件系统操作描述，参数/结果 ABI、资源 destructor 身份与原生依赖
来自同一份 `xl6_ir_fs_operations.inc`。只生成可达操作的适配器；三个 64 位操作掩码
有编译期容量检查。旧的 `File` 标准库类声明已删除，不再同时维护两种 File 表示。

- `file.open(path, flags=1, mode=438, share=7)` 和
  `Vfs.open(path, flags=1, mode=438, share=7)` 均返回同一种受管理 `File`。
  flags 使用 XRT 的 read=1、write=2、create=4、truncate=8 等位；默认只读。
  原生控制块在打开/截断之前分配。语言受管理对象的接管仍可能在打开成功后分配失败；
  此时会关闭文件，但不会撤销已创建文件或已完成的截断。需要替换事务时使用原子写入，
  不能将 `open(..., truncate)` 的失败理解为文件内容不变。
- `File` 提供 `read/readBytes/readExact/readAt/readAtExact`、
  `write/writeAll/writeAt/writeAtAll`、精确长度 `writeText`、`readText`、
  `seek/pos/size/flags/resize/flush/close/closed/eof/setEOF`。
  字节读取返回 `bytes`，不再隐式返回 Buffer；偏移读取不改变游标。
  `pos/size/seek` 返回 uint64，写入次数返回 int。
- `readText(count=-1, encoding=0, policy=0)` 保留 NUL 和真实结果长度；encoding
  使用 XRT Unicode 编码编号 0=检测、1=UTF-8、2/3=UTF-16 LE/BE、4/5=UTF-32 LE/BE，
  policy 0=严格、1=替换；检测读取移除匹配 BOM，冲突 BOM 报错。
  缺省 count 从当前游标读到末尾，设 64 MiB 硬上限，正数 count 为单次请求。
  此编号不等同于旧全局 `encoding` 的代码页编号；全局 file 文本面仍待统一迁移。
- `native()` 只查询真正的 OS 句柄整数；虚拟文件返回 XRT 的不支持错误。
  `nativeHandle()` 是供已有 C/网络调用桥接使用的借用 xfile 指针，不是 OS 句柄；
  不得保存到 File 生命周期之外，也不得由外部调用者关闭。
- `file.stat(path, follow=true)`、`File.stat()`、`Vfs.stat(path, follow=true)`
  返回拥有快照的 `FileStat`：type/available/mode/attributes/size/device/identity/linkCount，
  accessed/modified/created/changed（Epoch 微秒）及 path/name/nameBytes/validUtf8。
  必须用 available 判断元数据字段是否由平台提供，不把零值当成有效值证明。
- `dir.open(path, flags=0)` 和 `Vfs.openDir(path, flags=0)` 返回同一种
  `DirectoryIterator`：advance/current/path/close 与 for 迭代。
  flags 1=查询元数据、2=跟随链接、4=包括点目录。
  current 返回独立 FileStat 快照，名称不会随下一次迭代失效；非法 UTF-8 名称可用
  nameBytes 检查，name 字符串访问明确报错。
- 文件和目录显式关闭均幂等；关闭后的读写/查询报错。XRT 短读和严格 EOF 错误保留。
  PackFS 已有 `statCounter(field)` 查询，0..5 分别为 hits/misses/loads/failures/residentBytes/evictions；
  这是独立取样计数，完整配置/统一 File 来源/统计快照还未封板。

### 能力、流与资源批次

新增 28 个封闭操作，共 73 个。`File.capabilities` 是模式过滤后的能力位，不以原生句柄
推断读写权限。`reader()` / `writer()` 创建 IoReader / IoWriter，并保留文件控制块；
来源 File 离开作用域后仍有效。File 显式 close 在流、映射或锁活跃时拒绝关闭。

- `File.map(offset=0, size=0, flags=1)` 返回 MappedFile；size=0 表示映射到末尾。
  `bytes(offset=0, size=-1)` 返回独立快照；`write(offset, bytes, size=-1)` 有界写入；
  `flush/close/size` 不公开悬空映射指针。虚拟 backend 不支持时明确报错。
- `File.lock(mode=2, offset=0, size=0, wait=false)` 返回 FileLock；一个 File 只允许一个
  活跃租约。显式 close 解锁失败时保留租约可重试，析构保留原错误并尽力释放。
  Windows 锁按句柄；POSIX XRT 仍为进程级 fcntl 锁，同 inode 的其他描述符关闭可能
  解除锁。不能将此接口理解为跨描述符独立锁，也不保证同进程线程之间互斥。
- `file.root(path)` 返回 FileRoot；公开根内 open/openDir/openRoot/stat/createDir/remove/
  readLink/createLink/createHardLink/createFifo/setMode。子根及打开资源独立持有原生锚点，
  不借用诊断路径实现安全检查。关闭父根不使子根或已打开资源悬空。
- 原子引用计数仅解决内部资源寿命，不保证 File 的游标、读写或显式关闭跨线程安全；
  并发操作及关闭由使用者同步。Root 关闭同样不能与根操作并发。

路径、临时对象、树、异步及完整 Pack 配置仍未全部完成。

## 批量验证证据

当前实测平台仅 Windows x64，GCC/TinyCC。Linux、POSIX 路径和正式发布全回归仍需后续验收。

- XRT 隔离源码导出：7 个基础 suite，14 个 modular/single 测试程序通过，含写打开 OOM；
  8 个 provider OOM/并发 suite，16 个 modular/single 测试程序通过，均使用 `-Werror`。
- XRT 公开结构 ABI 检查 3 项通过；原生 file/map/lock/root 与 root 目录 OOM 回归通过。
- `tools/check_stdlib_vfs.ps1`：8 个正向夹具，逐一通过严格生成 C、JIT、独立 AOT、
  确定性输出及依赖裁剪；3 个错误资源 ABI 夹具在输出 C 前被拒绝；公开范例 JIT/AOT 通过。
- 统一 File 批次扩展为 10 个正向、5 个错误 ABI 夹具；新增用例覆盖原生/内存/DiskFS
  打开、NUL 文本/字节、短读/偏移游标、只读拒绝、元数据快照、目录 for 与关闭边界。
  45 个操作描述通过 Windows GCC `-Werror` 生成 C、TinyCC JIT、独立 AOT 和重复输出一致性。
  旧 Buffer/File 与网络 sendFileHandle 用例 JIT 回归通过；路径/File 旧夹具语法检查通过。
- 覆盖精确 NUL 字节、UTF-8 路径、长度截断、大小写、overlay/MISS/ERROR、
  读取预算、路径 NUL/穿越拒绝、包 CRC/切片/解码预算和 provider 生命周期。
- 资源批次扩展为 13 个正向及 5 个 ABI 负例；新增流/映射越作用域、活跃资源关闭拒绝、
  映射越界/快照独立、重复锁租约、虚拟 map/lock 拒绝、子根独立、硬链接和越界路径。
  分配失败夹具在 8 类资源操作的各 48 个分配点注入故障，检查异常与注入一致，
  并用最终 File.close 验证没有遗留内部引用。测试平台仍仅 Windows。
- 双字段 string、char/bytes 的语言基础另做前置验证；新 VFS 不引入第二套字符串 ABI。
- 新工厂均有文档、测试和公开范例；历史全量标准库 coverage 门仍报告其他 API 的
  文档/范例缺口，不能据此宣称全量 RC0 通过。本轮没有放宽该门或用 deferred 掩盖缺口。

测试入口：在 demo6 根目录运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_stdlib_vfs.ps1`。
夹具与生成产物位于 `test/cases/stdlib_vfs_*.xl` 和忽略目录 `build/test`。
前置源码与本批 VFS 源码分别从 index 导出、独立构建并运行专项门，不依赖其他未提交扩展库。
