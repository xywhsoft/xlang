# xlang DEMO6 类型与隐性类设计

本文档记录 DEMO6 中类型、隐性类、类型标识符和 `type` 类型的设计口径。

## 1. 总原则

xlang 的类型属于隐性类。

也就是说：

- 每一种类型背后都有一个同名隐性类。
- 字面量可以作为该类型隐性类的实例调用方法。
- 变量可以作为该类型隐性类的实例调用方法。
- 隐性类方法调用必须能稳定 lowering 到静态函数或标准库函数。
- 隐性类不是动态对象，不默认带动态字典、反射、元方法或额外对象开销。

## 2. 基础类型的隐性类

示例：

```xlang
auto text = 123.toString()
```

含义：

- `123` 是 `int` 字面量。
- `int` 背后存在同名隐性类 `int`。
- `int` 隐性类有方法 `toString`。
- `123.toString()` 调用的是 `int.toString` 对应实现。

这类调用应 lowering 为静态函数或标准库函数调用。

示意：

```c
xl_int_toString(123)
```

## 3. 容器类型的隐性类

数组示例：

```xlang
auto a = [1, 2, 3]
a.append(4, 5, 6)
a.clear()
```

字符串示例：

```xlang
auto a = "1,2"
auto b = a.split(",")
```

规则：

- `array`、`list`、`set`、`dict`、`string` 等类型都可以有隐性类方法。
- 容器方法调用不等于动态对象分发。
- 容器方法应优先 lowering 到 XRT 或 xlang runtime 中的确定函数。

第一阶段范围：

- 本文先固定“类型背后存在隐性类、隐性类方法必须静态 lowering”的方向。
- 第一阶段不实现通用隐性类方法声明系统。
- 第一阶段不内置 `toString`、`split`、`append`、`clear` 等方法集合。
- 已经确定且实现的能力是：`type(expr)`、类型字面量比较、类型转换函数、class/custom 方法、以及容器/function `arg.length` 这类明确内置成员。
- 后续添加隐性类方法时，必须先明确声明位置、重载关系和 XRT 映射函数，不能走动态查找或装箱回退。

## 4. 类型标识符的三种角色

类型标识符同时承担三种角色。

### 4.1 声明变量

```xlang
int a = 0
string name = "xlang"
```

在声明位置，`int`、`string` 等类型标识符表示变量类型。

### 4.2 构造函数/类型转换函数

```xlang
int a = int("3.14")
float b = float("1.25")
string c = string(123)
```

在调用位置，类型标识符可以作为构造函数或类型转换函数。

规则：

- `Type(expr)` 表示类型构造或类型转换。
- 转换是否允许、如何失败、是否截断等规则由具体类型定义。
- 构造/转换调用必须是显式的，不做隐藏兼容回退。

### 4.3 type 类型的字面量

```xlang
auto a = 0
type b = type(a)

if b == int then
    print("b is int")
end
```

在表达式位置，当类型标识符参与 `type` 比较或作为类型值使用时，它表示 `type` 类型的字面量。

规则：

- `int` 可以作为类型字面量。
- `string` 可以作为类型字面量。
- `array`、`list`、`set`、`dict` 等也可以作为类型字面量。
- 自定义 `class` 和 `custom` 类型也应有对应类型字面量。

## 5. type 类型

`type` 是一种真实存在的特殊类型。

核心定位：

- `type` 用于表示“类型的类型”。
- `type` 本质上是枚举值。
- `type` 底层可以用整数表示。
- `type` 的表达方式和 `int` 不同。
- `type` 可以直接比较。

示例：

```xlang
auto a = 0
type b = type(a)
print(b)
```

输出方向：

```text
int
```

比较：

```xlang
if b == int then
    print("b is int")
end
```

规则：

- `type(expr)` 返回表达式运行时或静态可知的类型值。
- 普通静态类型表达式直接返回编译期确定的稳定 type id。
- `var` 表达式返回 XRT 动态值中的实际基础类型 id。
- `var` 表达式中的容器只返回 `array`、`list`、`set`、`dict` 这类基础容器类型，不携带元素泛型信息。
- `null` 同时是值字面量和内置类型名；在 `type` 相等性比较上下文中，`null` 右值按 null 类型字面量处理。
- `type` 值可以和类型字面量比较。
- `type` 值打印时输出类型名。
- `type` 虽然底层可以用整数表示，但不能和普通 `int` 混用。

## 6. 解析规则

同一个类型标识符在不同上下文中含义不同。

```xlang
int a = 0
int b = int("3.14")
if type(a) == int then
    print("int")
end
```

解析规则：

- 声明位置：`int a` 中的 `int` 是类型声明。
- 调用位置：`int("3.14")` 中的 `int` 是构造/转换函数。
- 类型值位置：`type(a) == int` 中的 `int` 是 `type` 字面量。

编译器需要根据语法上下文解析类型标识符角色，不能依靠运行时猜测。

## 7. 与动态对象能力的边界

隐性类不是动态对象。

因此：

- `123.toString()` 不需要把 `123` 装箱成动态对象。
- `"1,2".split(",")` 不需要进入动态成员查找。
- `[1, 2, 3].append(4)` 不需要绑定动态字段字典。
- 隐性类方法不存在时，应在编译期报错。

动态字段、元方法、缺失字段处理等能力暂不进入当前 DEMO6 class/custom 方案。

## 8. C 混编提醒

隐性类方法应尽量映射到普通 C 函数。

示例：

```xlang
auto text = 123.toString()
```

生成方向：

```c
xl_int_toString(123);
```

这符合 DEMO6 第一绝对原则：

- 无动态查找。
- 无隐藏装箱。
- 无额外对象模型成本。
- 可稳定生成 C 符号。

## 9. `type`、泛型与透明别名

第一阶段 `typedef` 是透明别名，`type` 值比较也遵守透明别名口径。

示例：

```xlang
typedef MyInt = int

MyInt value = 1

if type(value) == MyInt then
    print("int")
end
```

规则：

- `type(value) == MyInt` 与 `type(value) == int` 语义一致。
- 泛型实例中的透明别名先解析为目标类型，再参与实例缓存和 ABI 符号生成。
- `Box<MyInt>` 与 `Box<int>` 的 `type` 值应表示同一个具体实例类型。
- `type` 是真实存在的特殊类型，但普通 `typedef` 不创建新的运行时类型身份。
- 如果后续需要不透明别名或 newtype，必须单独设计，不能复用普通 `typedef`。

当前边界与后续设计议题：

- 内置类型的隐性类方法默认来自 XRT/标准库注册层，不在用户源码中另建一套重复声明系统。
- 普通自由函数不会自动变成隐性类方法，避免污染类型方法空间；如果后续需要扩展方法，必须单独设计显式绑定语法。
- 类型字面量的数值编号不作为公开 ABI 承诺；跨模块、跨 C 边界应使用 canonical type descriptor、XAPI type 字符串和 signature id。
- 基础类型可以有内部稳定 id，但文档和用户代码不得依赖具体整数值。
