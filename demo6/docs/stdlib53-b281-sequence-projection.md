# Array 与 Stack 的动态类型投影

动态 `var` 可以通过 `as array<T>`、`as Stack<T>` 恢复原生容器类型。
成功结果与源容器共享同一个受管理对象，修改元素或弹出 Stack 会影响
源对象；转换不复制元素，不修改源对象的类型身份或接纳策略。

## 类型与错误合同

严格转换必须同时匹配真实原生 owner、ARRAY／STACK 角色、容器身份、
元素身份、物理布局和完整的不可变接纳策略。只有 TypeId 相同不足以
通过检查；普通 wire Array 和伪造句柄也不能冒充原生容器。

`as array<T>?`、`as Stack<T>?` 在类型不匹配时返回语言 null。
严格转换不匹配时抛 `TypeError`。原生失败与“不匹配”不同：工厂、
元数据保活或清理失败仍沿 checked 异常边传播，诊断对象分配失败
也不能把失败变成成功。输出只在整个事务成功后发布。

元数据记录独立拥有策略，不保留源工厂对象、元素存储或生成代码。
验证允许 genuine owner 已处于操作 BUSY 状态，因为匹配只读取其
不可变元数据，不借出槽位。每次匹配不分配内存；当前语言转换会先
调用既有目标工厂创建私有见证对象，捕获完整策略后释放它，因此
整个 `as` 操作仍可能分配内存，不能宣称转换全程零分配。

## 统一 IR 与生成 C

XLIR 保存精确目标类型、元素域、见证工厂、借入源、消费见证、拥有
结果和独立 STATUS_OUTPUT。工厂创建和投影各有明确失败边，临时源
在成功与异常路径都清理。nullable 转换也保持 may-raise 合同。

Cgen 只消费这些合同并调用独立驻留入口；不生成类型匹配算法，
不根据名称猜测布局，也不通过 retag 或重新绑定策略强行接纳对象。
调用前初始化空输出，调用后清空被消费的见证。未使用动态投影的
程序不引入 `SEQUENCE_PROJECTION_SCHEMA` 组件。

## 验收与后续范围

专项覆盖基础值、char、bytes、float32、nullable 窄整数、类对象、
callable 和嵌套 Array／Stack；包括内嵌 NUL、引用共享、临时源寿命、
完整策略错配、BUSY、伪造身份、清理失败和无诊断失败。
240 个 IR 破坏反例在 C／头文件输出前拒绝，包含错误分支 operand
索引越界。严格 C O0/O2、JIT、
checked module、独立 AOT、完整同步 OOM 前缀及实际符号裁剪由专项
门验证；源码构建和消费快照必须逐项一致。

Linux 插桩范围是生成 C、测试宿主和本批 schema helper，其他链接的
编译器／XRT 提供方不在该插桩范围内。该专项不关闭 List／Set／Dict／
Tree 等其他容器转换、`as float32`、其他动态／Native 编解码组合、
工作线程与对象图故障、模块组合、真实卸载和 CLI／DLL／VFS 发布总门。

显式嵌套 `array<Stack<int>>[...]` 字面量目前仍被语义层拒绝，
可使用有明确目标类型的普通字面量；索引产生的临时 Stack 接收者
仍受现有具名接收者约束。专项用例不表示这两条语言限制已解除。
WaitQueue 保持 MPMC 与 `(status, T?)`，对象池最后；CRT 无未决策，
XRT 19 组未决策范围不变。
