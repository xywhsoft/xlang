# 扩展库现状复核：2026-09-27 23:11 固定构建

## 总体判断

扩展库的真实实现已经明显超过早期的占位状态，但源码能力、xlang 接入、边界测试和
官网交付仍未同步。当前应优先把已有能力接通并验收，不能把包数量、测试文件数量或
历史通过记录直接当作发布成熟度。

本轮只清点、阅读、复测并保存审计材料；没有修改扩展库或编译器实现，没有同步 XRT，
没有替换正式发布程序，也没有更新官网。工作区已经进行中的 CSV 修改照实纳入受测输入。

## 核查范围

- 重新解析全部 225 个活动包清单，检查直接声明源码、include 目录、依赖和包内测试路径。
- 核对集中测试登记、同名范例、README、包内维护型官网正文与本地官网。
- 抽查基础库、网络、AI、GUI、Agent 和工具库的活动声明及关键实现。
- 固定当前发布 CLI/DLL/include，复跑 56 个 Windows JIT 入口，涉及 55 个公共包。
- 重新编译运行 CSV 的 5 个独立 C 测试程序；为 graph 增加独立 C 诊断探针并在 WSL 执行。

**没有逐行审计全部 225 个包，也没有执行全部平台、全部 API 或完整产品场景。**
未选择不等于失败，入口通过不等于整包发布准入。

QoS 交付引擎。xregex 的既有专项详见 [交付收口](扩展库xregex交付收口_2026-09-27.md)。

## 需要联动修复的底层问题

### graph：已经复现，不只是性能建议

独立 C 探针直接编译当前活动 `graph_native.c`，在 WSL Ubuntu 上启用 ASan/UBSan：

| 场景 | 实际结果 |
| --- | --- |
| 520 个节点组成一个环 | 成功，得到 1 个包含 520 节点的分量 |
| 521 个节点组成一个环 | UBSan 报 `index 520 out of bounds for type 'int [520]'`，退出 1 |
| 已读入合法节点后遇到非法边 | XRT 分配快照显示遗留 2 次分配、6 字节，探针退出 2 |

原因分别见 [SCC 静态桶声明](../release/extlibs/graph/graph_native.c:492)、
[越界写入](../release/extlibs/graph/graph_native.c:555) 和
[装载失败直接返回](../release/extlibs/graph/graph_native.c:592)。

建议统一整改图存储和失败清理：分量采用节点连续缓冲与偏移/长度，内存按 O(V) 组织，
移除共享静态可变桶；装载失败统一释放已创建节点、保留真正错误。
不要仅把 520 扩成 4096，这会继续保留大内存、共享状态和清理缺口。
邻接访问还应避免反复扫描全边；补大分量、多个分量、非法边、OOM、并发和重入测试。

### 其他源码审查发现

以下判断来自当前源码，不冒充本轮已经通过端到端复现的独立用例：

- **压缩 Unicode 长度：** LZ4/LZMA/miniz/Snappy 的一次性和流式字符串入口把
  `string.len(text)` 传给 C 的字节数参数，会截短非 ASCII 内容。入口目前先被 ABI 阻断；
  修原型时应一起补 byteLen、Buffer、中文、NUL 和分块往返测试。
- **Memcached 传输：** set 用文本长度组装协议，get/set/del 各只 recv 一次，缺少完整
  帧累积；空值与未命中均返回空串。当前报文辅助测试通过不代表完整客户端可用。
- **Agent 工作区与资源策略：** Resolve 只比较文本前缀，没有路径分量边界；writable
  未被消费。fs_read 先全读再按字符截断，不是字节读取限额；超时、行范围、递归等配置
  没有完整进入行为。Trace 直接拼 JSON。需统一行为与公开参数，不能宣称强隔离。
- **返回字符串所有权：** color、semver、units 等仍有共享静态环形缓冲；需验证下一次
  调用、重入、跨线程与语言复制时机，不能用更多固定缓冲替代清晰所有权。

对应源码包括 [压缩长度](../release/extlibs/lz4/src/lz4.xl:71)、
[Memcached 客户端](../release/extlibs/memcached/src/memcached.xl:78)、
[Agent 路径](../release/extlibs/xbot.agent/src/agent.xl:131)、
[Agent 读取](../release/extlibs/xbot.agent/src/agent.xl:356)。

## 收口优先级

1. **先消除确定的阻断与内存问题。** graph 两个已复现缺陷、17 个 ABI 冲突、3 个缺符号
   优先；用实际生成声明与真实 C 头/定义一起编译作门禁，不关闭检查或加入旧接口回退。
2. **完成 CSV 整包交付，再恢复 6 个历史重点包。** BSON、LZ4、LZMA、miniz、Snappy、Zstd；
   压缩包一起检查 Unicode、流式上限、回调取消、OOM 和失败不损坏目标文件。
3. **将 17 个专项候选放入同一构建的发布批次。** C/XL、JIT/AOT、DLL、Linux 和范例输出
   分开记录；不能把不同构建、不同时段的通过项拼为总通过率。
4. **推进高价值已有后端。** HTTP/邮件/SSH/Agent 先打通，再用本地可重复端点和限额测试验收；
   AI/GUI 使用成功推理与真实交互场景，不按占位处理。
5. **统一测试发现和官网交付。** 34 个缺页公共包、31 个遗留 generated 页按当前包集合核对；
   页面标明真实能力、依赖、平台和最后受测版本，辅助型包不要冒称完整产品。

当前没有依据给全生态报可靠的完成百分比。更有用的计量是：每个首期候选在指定构建与
平台上，其 API、错误、所有权、资源限制、双语范例、文档还有哪些具体验收项未完成。
