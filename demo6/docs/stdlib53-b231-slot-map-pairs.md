# SlotMap 同次配对快照的原生合同

SlotMap 新增同次键值捕获底座，供后续统一 IR 的成对 foreach 接线。
键和值在一个源操作 pin、一次 XRT 槽位遍历中逐行复制，两个拥有
结果仅在全部复制和清理成功后共同发布。此批不是公开 foreach
完成声明，也不把两次独立 `keys()`／`values()` 当作配对快照。

## 捕获与拥有关系

`xl6SlotMapSnapshotPairTakeV1` 消耗空的键 schema witness，但不填充
或修改 witness；其别名在成功和失败后都看不到半成品。值 schema
来自原表捕获的精确布局与独立拥有准入元数据。输出是私有、已清零
的双拥有数组结果；非空输出、错配布局和非法转换器被 checked 拒绝，
失败不改写原输出。

一个遍历位置同时生产真实实例与代际键、对应的拥有值。没有第二次
槽表扫描、wire 容器转接或 Cgen 生成的复制算法。空表返回两个合法
空数组，顺序沿用供应方槽位顺序，不承诺插入顺序。源表修改、clear
或销毁不改变捕获的结构；对象／容器值仍是共享引用，不宣称深克隆。
键持有独立实例记录，不保活原表或元素。

部分行复制失败、无诊断失败、静默短迭代和重入错误都会释放两个
未发布结果，原表保持可用。既有独立键、值快照复用同一遍历实现，
没有另造配对用的分配器或槽表。完整性检查不把提前结束伪装成成功。

## 按需组件与构建输入

`SLOT_MAP_PAIRS` 是独立的常驻生产者，构造键 witness 后调用共享
捕获底座。普通值快照不选择该生产者、键装箱、键哈希或键数组工厂。
共享底座仍属于 SlotMap 原生组件，不声称其每个 C 函数都已按需裁剪。

源码清单同时修复此前遗漏的 SlotMap／原生值提供方：Windows 已跟踪
DLL 构建漏列的 8 个文件、Linux 的 15 个历史运行时漏项与本次配对
生产者均已列入，并对照实际源码驱动清单核对完整集合。工作区现有
发布脚本重写与无关改动保留；普通发布
脚本输入修复不等于 shipping 动态库与内嵌 VFS 已通过验收。

## 双端验证

Windows／Linux 源码驱动分别构建 308／307 个翻译单元。
配对原生专项每端 67 个阶段、O0／O2 合计 34 个完整分配失败前缀
通过，包含实际失败后的同操作重试。标量、精确 NUL／UTF-8 文本、
引用、Future 和拥有型原生记录五种传输域保持拥有值平衡。

真实供应方包装验证一次 IterBegin、每行两次 typed push，以及键与
值位置对应。3 个实际编译的坏实现分别漏复制值、丢失代际和接受
短迭代，均在相应断言被拒绝。空表、源表退役后读取、schema 别名、
错误／非空输出、无诊断部分复制、pending error 与重入也通过。
Linux ASan／UBSan 覆盖选定的完整原生闭包，不覆盖整个编译器。

既有独立快照专项每端 75 个阶段、32 个完整分配失败前缀和 3 个
坏实现拒绝保持通过。公开 SlotMap／独立快照的严格 C、JIT、实际
AOT、故障／生命周期与按需独立产物回归通过。常驻目录在每端核对
269 个组件、1416 个精确导出和 13 个坏目录拒绝。

证据保存在 `E:/xlang-validation/stdlib53-b231-*` 与
`/var/tmp/xlang-stdlib53-b231-*`；提交前核对实际测试与构建输入、
私有 SDK、对象、产物及日志和最终选择性消费者源码。
