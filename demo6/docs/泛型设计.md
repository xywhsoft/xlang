# xlang DEMO6 泛型设计

本文档记录 DEMO6 已确认的泛型语法口径。

## 1. 总原则

泛型设计必须服从 DEMO6 第一绝对原则：xlang 能够和 C 完美混编。

因此：

- 泛型声明和泛型实例化必须能稳定生成 C 符号。
- 泛型函数默认不直接导出为 C ABI。
- 需要导出给 C 的泛型能力，必须由 xlang 侧显式导出具体实例 wrapper。
- 不为兼容旧写法增加多套泛型调用语法。

## 2. 类型位置使用 `<...>`

类型位置继续使用 `<...>` 表示类型参数。

示例：

```xlang
array<int>
list<string>
set<int>
dict<string>
Box<int>
```

说明：

- 类型上下文中，`<...>` 不会和小于号、大于号表达式产生严重歧义。
- 这和当前内置容器类型 `array<T>`、`list<T>`、`set<T>`、`dict<T>` 的设计一致。

## 3. 声明位置使用 `<...>`

泛型函数、泛型类等声明位置使用 `<...>` 声明类型参数。

示例：

```xlang
func max<T>(T a, T b) as T
    if a > b then
        return a
    end
    return b
end

class Box<T>
    T value
end
```

说明：

- 声明位置有明确的语法入口，例如 `func`、`class`。
- 因此 `max<T>`、`Box<T>` 在声明中不会被解析成表达式比较。

## 4. 表达式显式实例化使用 `::<...>`

在表达式中，如果需要显式指定泛型实参，统一使用 Rust 风格的 `::<...>`。

示例：

```xlang
var a = max::<int>(1, 2)
var b = parse::<float>("1.25")
```

泛型 class 构造表达式的显式类型实参也使用同一规则：

```xlang
var box = Box::<int>()
```

说明：

- 表达式位置不采用 `max<int>(1, 2)`。
- `::<...>` 可以清楚告诉 parser：这里是泛型实参，不是比较表达式。
- lexer 需要优先识别 `::`，再识别单独的 `:`。

## 5. 不采用 `[]` 泛型语法

DEMO6 不采用 Go/Python 风格的 `List[T]` 作为泛型语法。

原因：

- xlang 已经使用 `[]` 表示数组字面量。
- xlang 已经使用 `[]` 表示列表字面量。
- xlang 后续大概率还需要 `[]` 表示下标访问。
- `array[T]` 容易同时像类型、带类型名前缀的容器字面量、下标访问。

因此，使用 `[]` 做泛型会让 xlang 的表达式、类型、容器字面量之间产生额外歧义。

## 5.1 嵌套泛型中的 `>>`

lexer 仍按最长匹配把源码中的 `>>` 识别为右移 token。

parser 前置 token 流处理在确认某一段属于类型上下文或 `::<...>` 显式泛型实参时，把嵌套泛型末尾的 `>>` 拆成两个 `>`。

示例：

```xlang
array<dict<int>>
identity::<array<dict<int>>>(values)
```

规则：

- 类型上下文中的 `array<dict<int>>` 解析为 `array<dict<int>>`，不是右移表达式。
- 表达式上下文只有 `::<...>` 内部会按类型实参拆分 `>>`。
- 普通表达式里的 `a >> b` 仍然是右移运算。
- 不引入为了兼容旧写法的 `max<int>(value)` 泛型调用。

## 6. C 混编规则

泛型声明本身没有直接 C ABI。

错误方向：

```xlang
export "max" func max<T>(T a, T b) as T
    ...
end
```

推荐方向：

```xlang
func max<T>(T a, T b) as T
    if a > b then
        return a
    end
    return b
end

export "xlang_max_i64" func max_i64(int64 a, int64 b) as int64
    return max::<int64>(a, b)
end
```

说明：

- `export` 面向 C 时必须得到确定的参数类型、返回类型和符号名。
- 泛型实例的内部符号名必须由编译器稳定生成。
- 对 C 暴露的符号名必须由 `export "c_symbol"` 显式指定。
- 泛型实例的 signature id 与 internal ABI symbol 规则见 `ABI设计.md`。

## 7. 泛型函数推断

DEMO6 第一阶段支持泛型函数类型推断。

示例：

```xlang
func first<T>(array<T> values) as T
    return values[0]
end

auto a = first([1, 2, 3])
auto b = first::<string>(["a", "b"])
```

规则：

- 泛型推断只从调用实参推断类型参数。
- 第一阶段不从返回值接收位置反向推断类型参数。
- 第一阶段不做部分显式类型实参；要么完全省略，要么写完整 `::<...>`。
- 所有类型参数都必须能推断出来，或由 `::<...>` 显式给出。
- 多个实参推断出同一个类型参数时，必须得到同一个规范化类型。
- 若实参类型需要隐式转换，先按重载规则选候选，再在候选内做可赋值检查。
- 推断失败必须产生编译期诊断，不能退回裸 `var` 调用。

推断范围：

- 支持直接参数：`T value`。
- 支持容器参数：`array<T>`、`list<T>`、`set<T>`、`dict<T>`。
- 支持嵌套容器参数：`array<dict<T>>`。
- 支持函数参数：`func(T) as T`。
- 暂不从 `***` 字典可变参数推断类型参数。

## 8. 泛型约束

DEMO6 采用显式泛型约束，但不引入 `where` 子句。

统一语法：

```xlang
func max<T is comparable>(T a, T b) as T
end

func cloneAll<T is cloneable>(array<T> items) as array<T>
end

func draw<T is Entity>(T obj)
end

func save<T is Entity and json and cloneable>(T obj)
end
```

设计原则：

- 约束写在类型参数列表内，避免函数签名尾部继续变长。
- `is` 在泛型参数列表中表示“类型参数必须满足某个能力或基类约束”。
- 不使用 `where`，也不使用 `T extends Base` 作为泛型约束语法。
- 多个约束使用 `and` 连接，含义是同时满足。
- 约束名可以来自内置能力、协议能力、class 名称或未来的 interface/protocol 名称。
- `T is Entity` 表示 `T` 必须是 `Entity` 或其子类。
- `T is comparable` 表示 `T` 必须提供比较能力，例如内置比较或对应协议。
- `T is json` 表示 `T` 必须具备 json 持久化能力，例如 `derive json` 或等价协议。
- `T is cloneable` 表示 `T` 必须能被 `clone()` 深拷贝。

约束检查：

- 泛型声明解析阶段保存约束表达式。
- 泛型实例化时，对实际类型检查约束是否满足。
- 函数体或方法体仍需要在实例化时检查具体运算、调用、字段访问是否合法。
- 诊断信息必须同时指出泛型声明位置、约束位置和实例化调用位置。
- 约束只收紧合法实例集合，不改变运行时 `is` / `as` 表达式的语义。

解析规则：

- `<T is comparable>` 只在泛型参数声明位置合法。
- 表达式位置仍使用运行时类型判断语义，例如 `value is int`。
- `as` 继续作为函数返回类型标记和运行时转换运算符，不参与泛型约束语法。
- 约束解析必须基于语法上下文，不允许通过兼容分支猜测旧写法。

## 9. 泛型 class

DEMO6 第一阶段允许泛型 class。

示例：

```xlang
class Box<T>
    T value

    create(T value)
        self.value = value
    end

    func get() as T
        return self.value
    end
end

Box<int> a = Box::<int>(123)
auto b = Box::<string>("x")
```

规则：

- `class Box<T>` 是开放泛型类型声明。
- `Box<int>` 是具体实例类型。
- 每个具体实例拥有独立的类型描述符、布局描述、方法实例和 ABI 名称。
- 泛型 class 的字段布局在实例化后确定。
- 泛型 class 的方法在实例化后按具体类型检查。
- `type(Box<int>)` 得到具体实例类型的 `type` 值。
- 开放类型 `Box<T>` 不作为运行时可构造类型。
- 第一阶段不设计泛型 custom。
- 第一阶段不设计泛型 class 的虚分发或动态反射。

继承限制：

- 第一阶段允许非泛型 class 继承非泛型 class。
- 泛型 class 继承、泛型父类实例化继承暂缓。
- 这样可以避免 class layout、构造顺序、ABI 名称和实例缓存在第一阶段过早复杂化。

## 10. 实例缓存与 ABI

泛型采用按需实例化。

规则：

- 相同模块内，同一个泛型声明加同一组类型实参，只生成一个实例。
- 不同模块中的实例是否合并，后续由模块 ABI 设计决定。
- 实例 key 使用规范化类型名，而不是源码文本。
- `array < int >` 与 `array<int>` 是同一个类型实参。
- `typedef MyInt = int` 作为透明别名时，`MyInt` 与 `int` 生成同一个实例。
- 实例 ABI symbol 必须包含泛型声明 id 和规范化类型实参 id。

## 10.1 泛型与 `typedef` / `type`

第一阶段的 `typedef` 是透明别名。

示例：

```xlang
typedef MyInt = int

auto a = identity::<MyInt>(1)
auto b = identity::<int>(2)
```

规则：

- 泛型函数实例缓存使用别名解析后的规范化类型。
- 泛型 class 实例缓存使用别名解析后的规范化类型。
- `identity::<MyInt>` 与 `identity::<int>` 必须生成同一个泛型函数实例。
- `Box<MyInt>` 与 `Box<int>` 必须生成同一个泛型 class 实例。
- 内部 ABI symbol 不编码透明别名名本身，而编码别名目标类型。
- `type` 值比较同样按透明别名口径处理，`type(value) == MyInt` 与 `type(value) == int` 语义一致。
- 如果后续需要不透明别名，必须单独设计，不能改变普通 `typedef` 的透明语义。

## 11. extern / export 限制

第一阶段规则：

- `extern` 函数不能声明泛型参数。
- `export` 函数不能声明泛型参数。
- 如需对 C 暴露泛型逻辑，必须手写固定签名 wrapper，并在 wrapper 内调用具体泛型实例。
- 诊断必须在语义检查阶段给出，不能等到 C 生成阶段失败。
