# 取消选项和基础资源的驻留清理

ProcessRunOptions、Random 和 File 已采用驻留拥有策略。取消选项
追踪其真实取消令牌，Random 和 File 的资源析构不再由生成模块
定义。原先 31 项可达拥有入口中已有 25 项具备精确策略，另六项
仍需完成任务组或回调来源审计。完整三组标准库目标保持不变。

## 取消令牌的真实拥有关系

ProcessRunOptions 包含一个 xcancel 强引用。令牌可以被运行操作
共享，不能把 options 当作只有一个节点的叶资源。新 Trace 发出
实际取消令牌拥有边，未注册观察者时快照包含 Handle 和令牌
两个节点，不增加虚构边或调整真实引用计数。

对应拥有域使用 XRT Cancel V2 与 CancelWatch V1 合同，按已封存
的观察者策略集合查询。未知或旧式借用观察者仍被拒绝；没有
通过请求取消、跳过回调或提前注销来伪造可退役状态。准备阶段
和最终释放仍消费真实的取消令牌生命周期。

原生回归另外保留一个令牌引用，再销毁 options，确认保留引用
仍可正常请求和观察取消。旧式观察者的拒绝测试不会执行该观察者。

## Random 和 File 的原生资源

Random 状态只含内联 xrng 与创建线程 ID，没有语言对象边。
创建、默认序列创建及安全清零销毁迁至驻留单元；其余已批准
随机操作保留原合同。生成适配器与驻留实现使用相同的物理
状态声明，不再分别定义资源布局。

File 的原生投影含文件、引用计数、同步状态和临时路径。驻留
析构复用同一个 file drop，保留既有 no-raise 合同；显式 close
仍检查资源租用并传递错误。回归额外保留一个真实文件引用，
销毁语言 Handle 后继续读取文件大小，最后释放保留引用并核对
分配数量和字节平衡。

这些策略不认证任意 IO 或 VFS 回调。File 的 reader 适配器和
VFS 入口仍有独立的待审拥有入口，不能因 File 析构驻留而一并
宣称完成。

## 统一声明和按需部署

专门的桥接族与 direct bridge 读取同一份精确资源策略声明。
按完整 C 链接名匹配，包括解析阶段的引号形式；不新增 Cgen
名字猜测、前缀识别或资源特例。XLIR 的目标和字段继续独立
校验策略，错误合同在任何 C 输出之前被拒绝。

新增两个资源生产单元和三个拥有域，现有 ProcessOptions 单元
增加真实拥有边。驻留目录为 377 个组件、1639 个精确导出、
63 个拥有域和 33 项 Handle 策略。标量程序继续裁剪这些生产
单元；新资源不会作为全局常驻运行代码加入每个程序。

## 验收范围

原生专项覆盖累计 26 个真实资源工厂，逐项检查拥有节点、
52 个 Ops 或 Trace 伪造拒绝、分配失败闭合前缀及分配平衡。
原有正则并发关闭测试继续保留。Linux 对 43 个真实生产单元
使用 ASan 和 UBSan，包括 XRT 与 xruntime 核心；它不代表
其他编译器单元全部插桩。完整核心的 O2 插桩编译有独立的
600 秒限额，普通单元仍为 180 秒；超时失败记录不被覆盖。

XLIR 专项核对 25 个析构目标、25 个字段策略和 100 次输出前
拒绝。独立 AOT 专项包含 11 份用例；三份循环对象在析构中
读取原生子资源，每份搬离执行四次且最终标记恰好出现一次。
完整产品、数值转换和快照门禁仍分别报告，不以局部专项替代。

## 剩余工作

仍未准入的六项是 SignalTaskGroup、IO reader、IO writer、
VFS、内存 VFS 和挂载对象。任务组内部 Future、取消观察者、
活动项及父子引用需要完整协议；IO 和 VFS 的回调地址及其
上下文生命周期需要真正的驻留实现与认证，不能声明为空 Trace。

Windows 终端 resize 的历史间歇失败尚无根因修复，某次复测
通过不能关闭该项。全局 exit 的完整语言栈和模块清理、函数级
覆盖及发布总门继续。CRT 无未决策，XRT 十九组未决策与对象池
最后的顺序不变。本批不修改 canonical XRT 或无关扩展库。
