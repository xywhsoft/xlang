# Channel 常驻拥有值底座

Channel 的原生底座复用 XRT 的缓冲、会合、等待和关闭机制，类型准入、
拥有值与生命周期由常驻组件管理。公开接收接口已经决定采用
`(status, T?)`；本批次完成原生合同与专项验收，语言声明、统一 IR
接线和旧 Cgen 实现清退仍待完成，WaitQueue 不计为已完成。

## 返回值与拥有权

原生操作用独立 `bool` 表达真正失败，不依赖是否分配出错误对象。
正常状态包括成功、空、满、关闭和超时。成功接收 nullable null
仍是成功，不能与未收到消息混淆。公开语言层后续投影此合同，
复制和资源故障走异常边，不成为第六种正常状态。

发送复制精确字符串或保留引用，接收直接移出已拥有的槽位，
不会在取出消息之后再分配、复制或创建默认值。原生接收槽必须
大小、对齐正确，拥有值为空且不与状态或内部 owner 存储重叠。
任何路径上输出槽仍由调用者负责，包括已经移出值后的清理错误。

构造消费已准入的 Array 或 Stack schema，仅保留独立拥有的常驻
元数据，不保存源模块回调或 schema 的元素存储。逻辑身份、
物理 ABI、完整准入政策与真正的 provider ops 共同决定类型匹配。
V1 支持平凡值、精确 string 和 retained xvalue 引用；Future 与
拥有型原生记录是 checked 拒绝，不宣称这些值域已经接通。

容量精确传给 XRT，零容量使用会合机制。超时采用毫秒，负值拒绝，
正值换算微秒饱和；非超时操作不接受非零超时参数。

## 生命周期与图回收

每次原生操作保留 owner 并登记活动状态。阻塞时不持有拥有图的
修改门；图观察拒绝正在活动的 owner，不在冻结门内等待。
关闭可以与等待并发，唤醒等待者并保留已有消息供排空。
应用必须显式关闭以结束无限期等待，操作 pin 不能替代取消协议。

消息拥有边由常驻 intrusive 列表登记，短临界区只更新链指针。
复制、析构、XRT 等待和任意值回调均不在该锁内执行。
这份列表只记录已有消息的拥有权，不另建队列算法，也不窥探
XRT 的不透明 ring 或用 Count 猜测引用边。

静止 owner 参与既有 hold、claim、clear、finish 退役协议。
所有消息析构和 channel 同步资源清理都会尝试执行，保留首个错误，
无诊断的失败仍可检查。失败的已消费物理清理可以由退役记录再次
确认，不重复析构。XRT 的 Unit 会尝试并清空同步资源状态；本批次
不扩展它的 OS 原语销毁失败恢复能力。

## 构建与裁剪

`TYPED_CHANNEL` 独立于宿主 scheduler 使用的 `CHANNEL` bridge。
组件声明指定 Sequence、错误作用域与 XRT channel、spin 模块。
独立专项的九个常驻源文件由实际组件闭包计算，其中包含测试所需
的 primitive、reference 和 Future 拒绝输入工厂，不代表公开语言产物。
它不包含旧宿主 channel bridge、typed queue、OrderedMap 或 regex。

Windows DLL 构建入口单独编译 provider，并将对象加入两个 DLL 的
链接输入；Linux 与公开源码构建清单显式包含该源文件。
本地未提交的响应模板、构建 helper 与无关工作区修改保持原样。

## 验收范围

`check_stdlib_channel_native.py` 使用新源码构建，严格 C O0 和 O2，
并执行真实按需闭包。每端 97 个阶段，八组完整分配失败前缀共
44 次运行；四个执行通道各验证 1000 轮生命周期。

测试包含精确 UTF-8 与内嵌 NUL、nullable presence、非空输出拒绝、
完整 schema 与伪造 provider 拒绝、自引用图回收、首错与全部析构、
无诊断复制／传输／资源失败、操作 pin、缓冲多生产者多消费者、
零容量会合，以及真实阻塞发送和接收的关闭唤醒。
四个已编译错误实现必须在实际执行中被拒绝。

Linux 的独立闭包和测试宿主接受 ASan 与 UBSan；不是全编译器、
全运行时或线程竞态检测。双端常驻目录验证 264 个组件、1406 个
准确导出与 13 个坏目录控制。发布 DLL／VFS、公开 JIT／AOT 接口
与全部 53 模块总验收继续，不作本批次完成声明。
