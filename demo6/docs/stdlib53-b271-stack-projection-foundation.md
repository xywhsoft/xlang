# Stack 动态值投影底座

2026-10-14。Stack 的原生擦除边界已补齐：擦除返回同一个 Stack 的独立
拥有引用，不复制内容；读写复用 XRT typed storage、既有类型接纳规则和
驻留转换器。Array 的擦除入口仍只接受 Array，不因底层存储相同而接受
Stack。语言端的 Stack 动态分派仍待接入统一 IR，综合 pending 用例保持
未通过状态。

## 角色与拥有合同

共享 Sequence 增加带精确角色的绑定和探测入口。探测先认证驻留 handle
操作表，再读取角色；不解引用外部句柄的任意数据指针。Array 和 Stack
各自验证角色、身份和 BUSY 状态。错误角色判定不分配内存、不覆盖现有
诊断，失败输出不留下陈旧 pin 或布局信息。Array 图恢复入口没有放宽。

Stack 的投影在显式擦除时绑定，不改变纯 typed 构造。转换器不能携带
借用的 Context，也不能在绑定后更换。克隆同时保留角色、精确接纳规则
和投影策略。引用槽复用现有保留引用的转换器，不改为动态对象图复制。

Push 在接纳和转换成功后追加。Peek 返回独立拥有值；Pop 先完成装箱、
身份绑定和接纳，再移除原槽。明确失败但无法分配诊断对象时，也不能
提前 pop。移除开始后的析构失败遵循原有已提交修改合同，不承诺撤销
已执行的析构。操作 pin 保住转换期间的存储，包括回调释放最后语言
引用的情况。

## 原生验收

Windows 严格 C11 O0/O2，Linux 相同配置加所选实现的 ASan/UBSan。
每端 Stack 专项包含 41 个执行或构建阶段，以及三份实际错误实现的
运行期拒绝。覆盖精确 NUL／UTF-8、窄整数范围、引用身份和 null 数据、
别名、克隆、错误角色、伪造外部句柄、BUSY／跨线程拒绝、不可重绑策略、
首个无诊断失败及回调中的最后引用退役。

Peek、Pop、Push、Clone 的 O0/O2 共八条分配故障前缀全部闭合，每端
32 次预算尝试，24 次触发故障；每次检查原内容及完整内存账本。三个
错误实现分别删除失败后禁止 pop 的判断、允许 Array／Stack 相互冒充、
使 Stack 克隆丢失投影，均由对应状态断言拒绝，不以编译失败充数。

既有 Sequence 身份回归每端 44 项通过，涵盖 30 组循环、80 个并发线程、
标量／文本／引用／Future、错误和对象图内存平衡。该回归的源码闭包补上
已经被字符串实现使用的错误作用域提供方；没有更改这些功能的实现。

专项证据分别为 `E:/xlang-validation/stdlib53-b271-native-win-final3/results.json`
和 `/var/tmp/xlang-stdlib53-b271-native-linux-final3/results.json`。身份回归为
`stdlib53-b271-identity-win-final2` 和 `xlang-stdlib53-b271-identity-linux-final2`。
所有结论限于各报告冻结的所选原生源码，均要求 Complete 与 InputsUnchanged。

## 下一步

统一 IR 仍须在 Stack 到动态值的转换处选择显式投影操作，登记物理
布局、拥有权和错误边；Cgen 只输出已验证的调用，并按需选择转换器与
提供方。纯 typed Stack 不应因这一接入而强制包含动态装箱代码。

随后补齐已批准 Stack 方法的动态分派，执行原综合 pending、语言
C／JIT／module／AOT、裁剪及故障验收。本批不是语言动态调用完成、
新发布动态库或 53 模块总门通过的证明。WaitQueue 继续采用已批准的
MPMC 和 `(status, T?)` 拥有接收接口；19 个未决策分组与对象池最后不变。
