# 原生资源的精确拥有边与销毁

DateTime、文本迭代器、Pattern、正则、同步进程结果和信号队列等
22 个已有原生析构入口，已采用驻留 Handle 策略。策略按实际
Ops 和 Trace 双重身份准入；不把未知 point 或任意 Handle 当作叶子。
此前 31 项待审入口还剩 9 项，不代表三组标准库整体封板。

## 原生布局与拥有边

DateTime、UTF8 验证器、文本迭代器、Pattern 程序与匹配快照、
PatternOptions、进程管线配置与结果、单次进程结果、Regex 程序与
RegexSet、信号订阅队列与事件，只拥有各自原生数据或操作系统
资源，不持有语言对象。信号队列的原生监听器只记录事件；注销
等待原生回调离开，队列释放不执行语言回调。

另有八项资源确实持有 xvalue，不能声明为空 Trace：PatternBuilder
持有身份值，PatternEdit 和 PatternKey 持有身份值及发布标记；
RegexMatch、RegexIterator、RegexSplitIterator、RegexSplitPart 与
RegexReplacer 持有输入值。实际快照分别验证二个或三个拥有节点，
私有 Pattern 发布标记也有独立驻留策略。

用户标签仍保存在语言层普通字段。原生 builder、key 和 edit
持有的是内部身份与发布状态，不是用户标签。正则替换回调仅在
同步调用栈借用，不成为 RegexReplacer 的拥有边。

## 关闭与销毁顺序

正则迭代器和 split 迭代器关闭时，先在短 ownership mutation 中
摘除输入、程序及匹配状态，再结束 mutation，释放程序和输入值。
mutation 不跨越任意语言析构或替换回调。并发测试在真实冻结中
阻止创建线程关闭，确认快照仍含两个节点；解冻后关闭完成，
再取快照只含 Handle 自身。

Handle 接管在创建或绑定失败时消费独立原生槽位，执行一次真实
清理并保留第一次错误。Drop 的错误作用域与现有原生析构边界
一致。读取准入与生命周期准入仍是独立能力，本批没有通过
Resolve 成功来泛化授权读取。

## 声明与部署

统一声明表包含 22 个语言析构入口和一个内部发布标记，关联
17 个实际原生生产单元。XLIR 的析构目标和原生字段消费同一
策略合同；错误策略和擦除策略在生成任何 C 字节前被拒绝。
没有新增 Cgen 资源特例，也不保存生成模块的回调地址。

驻留目录目前有 372 个组件、1629 个精确导出、60 个拥有域，
其中 Handle 策略 30 项。标量程序继续裁剪掉这些资源生产单元。
原生 SDK 的策略原型是完整物理声明，不依赖未打包的相邻 inc。

## 验证结果

两端均完成真实源码构建与 CLI 和共享库产品构建。原生专项按
O0 和 O2 检查 23 个真实资源工厂、46 个伪造拒绝对照、逐资源
分配失败闭合前缀及分配数量和字节平衡。Linux 对 37 个实际
生产单元加 ASan 和 UBSan，包括完整 XRT 和 xruntime 核心；
这不等于全部编译器生产单元均已插桩。

两端各验证 22 个 XLIR 析构目标、22 个字段策略和 88 次输出前
拒绝；各构建并搬离执行 10 份真实 AOT 用例。两份新增循环对象
在析构中读取原生子资源，每份重复四次且最终标记恰好出现一次。
另八份保留原始语言断言。清理续体的两份原始搬离 AOT 程序
每端各重复 100 次，全部正常退出。

完整产品清单每端 311 项。Linux 为 303 项执行通过、一项预期
拒绝、六项宿主要求和一项平台要求，八个附加门均通过。
Windows 为 302 项执行通过、一项执行失败、一项预期拒绝、
六项宿主要求和一项平台要求，七个附加门均通过。失败仍是
终端 resize 未观察到新尺寸，不以另轮偶然通过替代修复。

## 剩余目标

以下九项继续拒绝未经审计的原生清理：ProcessRunOptions、
SignalTaskGroup、旧 fs file、IO reader 和 writer、Random 状态、
VFS、内存 VFS 和挂载对象。前两项需要实际取消或任务拥有协议；
后七项需要把生成辅助实现收口到经过布局及回调来源审计的
驻留生产单元。不能为任意自定义 IO 或 VFS 回调提供叶子证书。

Windows 终端竞态、全局 exit 的完整清理、函数级覆盖与全部发布
验收继续。CRT 未决策为零，XRT 其余十九组未决策保持不变，
对象池仍最后处理；本批不修改 canonical XRT 或无关扩展库。
