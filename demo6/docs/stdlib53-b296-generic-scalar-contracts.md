# 泛型 C 数值构造与原生字段合同

泛型定义中的类型参数不是动态 var，也没有可执行的物理 ABI。
C 数值构造在模板阶段保留明确的待实例化合同；具体实例化后必须
重新验证完整源类型、目标类型、操作数、返回和错误 ABI。字符串、
未解包 nullable 等不支持的具体输入不能继承模板的许可。

## 统一 IR

语义检查不再过早拒绝未知类型参数的数值构造。Typed IR 的 C 数值
构造只允许真正泛型函数中的类型参数进入 generic-dependent 状态；
普通具体调用必须是 verified，Cgen 和可执行 runtime op 不接受待定
合同。实例化继续复用统一合同验证器，不按名字重新分类。

原生标量字段、float32、char 的默认初始化与值声明共用同一零值
域，构造和验证不再维护不一致的类型清单。原生字段的精确读写保留
实际 C ABI；默认值复用已存在的拥有装箱边界，与后续字段写入一致。
本批整理了这些路径所必需、已有但未提交的字段修改，其余工作区
修改不纳入提交。

## 验收

冻结源码专项包含泛型 int／var／C 标量／float32／char 输入、模板
实例化后的反射拒绝、20 个 C 数值字段的默认零值、精确字段读写，
以及 float32／char 字段。泛型字符串和 nullable 输入必须在输出 C
前拒绝；泛型待定与具体许可的错误互换同样由 IR 负控检查。

Windows、Linux 普通与 Linux 指定插桩专项各 418 个阶段，3044 个
坏 IR 反例输出前拒绝。泛型／字段用例 O0／O2 各完成 4／235 个
同步分配前缀，首次未命中点为 3／234；既有四个用例仍分别为
36、27、16、23 个前缀，失败和退役后账本平衡。插桩只覆盖生成 C
及测试宿主，不代表全部原生提供方。

本批还把三组 310 个既有夹具从仅编译扩大到双平台 JIT＋模块运行。
专用宿主、平台与 CLI 产品条件保持显式未验收，不能当作通过；
各平台最新完整执行记录为 604 个阶段，301 个用例双通道实际执行、
1 个预期语义拒绝及 8 个未执行要求。驻留目录仍为 308 个组件、
1515 个精确导出、94864 对闭包与 23 个拒绝负控，没有新增提供方。
各公开函数的分支覆盖、全量原生插桩与发布验收不由这份库存替代。
证据位于 `E:/xlang-validation/stdlib53-b296-*` 及 Linux 对应目录。

## 剩余工作

补充探测已确认，普通语言 int／uint64／float／float32 的动态构造
尚未一致拒绝反射令牌；它们的历史生成式解析也需核对精确字符串
长度，不能在 Cgen 继续堆分支。复现保存在本批 probes 目录，后续
迁到共用原生数值转换及完整 IR 合同。

安全构造的范围优化、其他动态／Native 组合、专用宿主、Windows
DST、模块组合／卸载、线程／对象图故障及 CLI／DLL／VFS／RC0 发布
总验收继续。CRT 0、XRT 19 组未决策、WaitQueue MPMC 与对象池最后
的范围和顺序不变。

修复后的早期 Windows 整批执行在 terminal_session 的 module 阶段
出现一次断言失败，run 阶段通过；额外 48 次带输出探测均通过，
尚未证明根因或修复。原断言新增失败标记与原始字节输出，条件
没有放宽；失败证据保留于 execute-win2，不能由后续绿色结果覆盖。
终端可靠性仍属于未完成的发布验收要求。
