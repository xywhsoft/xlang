承接 [字符串拥有权修复](扩展库字符串拥有权收口_2026-09-05.md)；逐项复测记录在
[extlib_string_bridges_2026-09-05.results.json](extlib_string_bridges_2026-09-05.results.json)。

## 实现

补齐当前标准库已有功能在默认 XLIR 后端中的七种桥接，不增加新语法或兼容入口：

| 语言接口 | 边界规则 | 实现基础 |
| --- | --- | --- |
| `string.byteLen` | 借用字符串，返回 C size | `xrtStrView` |
| `string.byteAt` | int64 字节索引；负索引；越界为 -1 | XRT 字符串视图 |
| `string.slice` | 起点与字符数量；不是结束索引 | `xrtUtf8Substr` |
| `string.replace` | 原始拥有缓冲交给 TAKE_CSTR | `xrtStrReplace` |
| `string.startsWith` | 默认区分大小写，显式 ignoreCase | `xrtStrStarts` / `xrtStrCaseStarts` |
| `string.endsWith` | 默认区分大小写，显式 ignoreCase | `xrtStrEnds` / `xrtStrCaseEnds` |
| `string.split` | 拥有型 var 数组，片段不借用输入 | `xrtStrSplit` / xvalue |

- `xl6_ir.c` 的小型合同表统一描述 C 名、桥接种类、返回类型和参数类型。
- lowering 与验证器共用合同校验；参数的物理表示、借用方式、返回拥有权不能漂移。
- `xl6_ir_cgen_emit_string_bridges.c` 是独立责任分片；后端只消费需求标记，不猜 C 名字。
- 按实际用到的函数生成适配代码，单独 byteLen 不拉入 split/replace/slice。
- 不重写 XRT 字符串算法，不调用或链接旧后端，不同步开发中的 XRT。

## 顺带收口的边界

1. 原 splitLines 重新声明了一个 XRT 字符串列表影子结构。本批改用公开 `xstrlist`，
   split 和 splitLines 共用列表接管与清理逻辑。
2. `xrtValueArrayAppendNew` 在成功、失败时都会消费传入值。原 splitLines 的失败路径
   再次释放 item，存在双重释放风险；本批移除了第二次释放。
3. 已导入 XRT 正式声明时，动态迭代器不再重复定义 `xvaluekey`，持久化辅助声明也不再
   将 `xrtValueIterAdvance` 的枚举返回类型重新声明成 int。

这些是受本批组合场景触发的修复，不表示所有 XRT 声明重复问题已经清空。

## 门禁与范例

新增 `tools/check_xlir_string_bridges.ps1`，接入语言前端套件：

- 检查七种桥接及 splitLines 的 lowered JSON 合同，保证没有额外字符串复制标记。
- 错误 C 返回类型、错误索引宽度必须在 lowering 边界被拒绝。
- `xlir_function_lower.c` 逐项篡改桥接的参数数量、借用方式、返回类型和种类。
- 字符/字节单位、负索引、int64 极值、越界、空前后缀、空分隔符、空片段。
- 临时输入的生命周期、具名函数值调用，以及 200 次重复分配与释放。
- 对 split 和 splitLines 分别扫描 128 个分配失败位置，验证失败与成功路径，检查
  XRT 的 DoubleFreeCount 和 InvalidFreeCount 均为零；本机实测 50 次失败清理、206 次完整成功。
- 严格 GCC `-Werror`、`xl run` 内存运行、`xl build` 后执行全部通过。
- 测试使用独立运行库对象，不读取其他测试正在重建的共享 `xrt_cgen.o`。

双语言范例：

- `release/examples/stdlib_string_boundaries.xl`
- `release/examples/stdlib_string_boundaries_c.c`

两者均可直接 `xl run`，十三行输出逐行一致。C 版本只调用 CRT/XRT。

其他验证通过：正常 DLL 构建、运行/编译两份 VFS 快照检查、XLIR 合同检查、函数 lowering
单测，以及 foreign string、foreign function value、named function adapter、managed native
receiver、protocol witness adapter、string conversion 六项邻近门禁；动态容器转换的
完整样例也通过严格 C 编译与运行。

## 扩展库复测

Windows x64，默认 XLIR，沿用前批同一组 125 个用例。每例独立进程，30 秒超时，
测试前后编译器哈希一致。完整输出和构建哈希保存在 JSON 中。

| 范围 | 通过 | 失败 |
| --- | ---: | ---: |
| 重点/第一阶段聚焦用例 | 88 | 18 |
| HTTP/WS 包内用例 | 4 | 15 |
| 合计 | 92 | 33 |

相较前批恢复 14 个，回退 0，超时 0。恢复项：

`xssh`、`xregex`、`argon2`、`bloom`、`rapidocr`、`fix`、`jwt`、`cbor`、`xbot`、`msgpack`，
以及 HTTP body、body decode、multipart、MIME 四个包内用例。

这是测试范围内的恢复，不代表整个包通过生产级验收。尤其 RapidOCR 和 xbot 的聚焦测试
并不覆盖完整真实业务后端。

剩余 33 项按当前外显结果分组：

- 7 项缺失辅助符号：os args、time fromUnix、dir list、extlib error clear。
- 4 项生成 C 错误：xmail、dotenv、两个 WS 回环。
- 5 项 async/native 返回或挂起 ABI 拒绝。
- 17 项运行时、错误传播或断言退出；部分原先被缺失字符串符号遮住，本批接通后才能执行到。

下一批优先统一 extlib error bridge 及外部调用错误传播，并定位退出码 3 的 native 容器/查询
访问。async、serial、协议分包、真实模型、C 范例覆盖与官网详情页仍在完整长期目标内。
