# 独立模块拥有记录与可重试退役底座

独立模块现在具有可复用的原生拥有记录和 checked 退役驱动。
它复用现有 OwnershipPlan，不在 Cgen 中实现第二套对象图收集。
当前完成的是驻留底座：生成入口尚未创建和绑定此记录，原有
Stack、Tree、Queue 独立 AOT 退役失败仍是发布阻塞项。

## 生命周期合同

Create 建立一个真实入口引用。初始化前取得并绑定借出的
CodeOwner；类、闭包及其他接受者通过原有 CodeLease 接口取得
真实拥有权。Retire 关闭新准入并且仅消费一次入口引用，不折减
其他引用。快照 pin 和实际 lease 分开计数，活动执行范围和外部
强根会阻止提交。

合同携带模块全局 trace、准备、完成回调及精确策略 resolver。
拥有记录只识别自身；其他节点交给明确的策略授权，在 Count／
Trace 前拒绝未知类型。真实类注册表发现已脱离全局变量的循环
岛，不用猜测引用数或只扫描当前根。

驱动分步执行准备、语义析构、提交、完成和销毁。准备工作持久
登记在 OwnershipPlan 中；BUSY 保留进度并返回，不无限自旋。
清理失败可重试，Destroy 在物理退役前拒绝释放记录并保持指针
不变。所有权状态变化进入 Mutation，快照在 Freeze 下读取；
语言回调不在记录锁或 Freeze 内执行。

结果分别报告 ready 和 ok：物理清理最终完成不消除先前错误。
第一条失败事件包括没有诊断对象的失败，后续错误不能替换它；
已有调用者诊断也受 checked 错误范围保护。调用者必须保留
checked 结果，按原有宿主规则排除并发 Retire／Destroy，并在
最终 Destroy 前停止和回收所有使用借出 owner 的尝试。

## 原生验证

原生宿主使用实际 ClassRuntime、typed Stack、CodeLease 和 XRT
图协议构造类与 Stack 自环。析构检查完整字段、容器内容和模块
环境仍有效，并验证只执行一次。覆盖外部强根、完成阶段 BUSY、
无诊断失败、首错保持、重入、脱离全局根的循环岛、过早 Destroy、
析构新建节点和析构取得真实 lease 后的再次静默。

OOM 注入覆盖完整多轮退役事务，直到首次未触发分配点；每次
恢复后核对实时分配数量、字节、分配释放账本及非法释放计数。
五个实际错误实现控制分别破坏 lease 计数、析构执行、关闭后
准入、无诊断失败记录和全局释放顺序，验证门必须拒绝它们。

Windows／Linux 普通通道和 Linux ASan／UBSan 通道各通过 48
阶段。两种优化级别 O0／O2 各跑 17 种场景和 49 次完整分配
前缀，首个未触发点为 48。插桩覆盖全部九个参与源文件，包含
实际选用的 XRT／xruntime 实现，而不只是测试宿主。

## 接入边界

新增五个精确导出属于独立的 STATIC_MODULE 组件，声明依赖为
CodeLease、CodeFinalizer、OwnershipPlan 和 ForeignError。
组件不自动加入纯标量程序，不能为了接入图退役拉入网络、进程
或正则实现。

两端完整源码构建分别为 Windows 349 和 Linux 348 个翻译单元。
精确组件审计各检查 310 个实际独立编译的提供方、1523 个导出、
96100 对依赖组合和 23 个拒绝控制，全部通过。

裁剪验证由生产组件闭包生成实际 XRT 实现及七个驻留源文件，
测试仅额外启用 MEMORY_DEBUG 账本。双端各 42 阶段通过：
O0／O2 独立二进制搬到新目录后运行完整 17 场景及 OOM 前缀，
没有 xl／xlc 动态库依赖，Linux 没有 RPATH／RUNPATH。
这里的独立二进制执行的是原生合同宿主，不是语言生成的 main。

后续仍需由已降级 IR 和组件选择产生精确策略元数据，初始化前
绑定真实 owner，并将独立 main 的退出接到共同驱动。读边界、
跨模块图和所有获准类型的策略授权也必须完整处理。原生宿主
手工提供合同只能证明底座，不替代这些生产接线；完整产品 AOT
验收继续以原有三个循环图的真实析构结果为准。
