# 文本标准库接入

本页记录 B1—B9 文本与数字/编码合同；53 模块剩余工作见《三组标准库接入长期任务.md》。

## 首批 string API

以下函数返回独立拥有的 string，保留内嵌 NUL；成功的空串也拥有有效空值。
输入在调用期只读，返回值之后的修改不影响原始输入或另一次调用的结果。

| API（前置参数） | 追加可选参数 |
|---|---|
| lower(text)、upper(text)、reverse(text) | size = -1 |
| trim(text, chars = "")、ltrim、rtrim | size = -1, charsSize = -1 |
| filter(text, chars) | size = -1, charsSize = -1 |
| replace(text, oldText, newText) | size = -1, oldSize = -1, newSize = -1 |
| slice(text, start, count = -1)、mid | size = -1 |
| left(text, count)、right(text, count)、repeat(text, count) | size = -1 |
| removeAt(text, start, count) | size = -1 |
| insert(text, start, part) | size = -1, partSize = -1 |

`size` 是 UTF-8 **字节上限**：`-1` 使用实际长度；非负数与实际长度取较小值；
小于 `-1` 抛 RangeError。上限切断 UTF-8 scalar 时抛 ValueError（XRT Unicode
错误包含偏移），不静默产出坏字符串。多输入分别设上限，先选片段再执行运算。

`start/count` 是 Unicode scalar 索引/数量；负索引从末端计算，越界范围按 XRT
切片合同夹紧。slice/mid/removeAt 的 `count=-1` 表示余下全部，小于 -1 拒绝；
left/right/repeat 的 count 必须非负，right(text,0) 和 repeat(text,0) 返回空串。
输出长度溢出报 RangeError；分配失败报 MemoryError，不退化为空串。

lower/upper 仅变换 ASCII 字母，不宣称 Unicode case folding。
trim 的空字符集合表示 ASCII 空白 `space/tab/CR/LF/VT/FF`；传入集合按 scalar
匹配，包含 NUL 合法。filter 删除指定集合。replace 是区分大小写、非重叠的
字节子串替换，空 oldText 返回独立原值；三个输入均须是有效 UTF-8。

## B2：查询、字符、字节、填充及匹配

本批迁移 25 个旧公开入口，新增 `string.glob`、`string.distance`，均为
声明直接调用。所有 size 参数为可选字节上限，`-1`/夹紧/非法负值合同同 B1。

| API（前置参数） | 追加可选参数 | 结果/语义 |
|---|---|---|
| len(text) | size = -1 | int；Unicode scalar 数 |
| byteLen(text) | size = -1 | int；原始字节数 |
| compare(left, right, ignoreCase = false)、equals | leftSize = -1, rightSize = -1 | int 的符号 / bool；仅 ASCII ignoreCase |
| contains(text, part, ignoreCase = false)、indexOf、lastIndexOf、count | size = -1, partSize = -1 | bool / scalar 索引 / 非重叠数量 |
| startsWith(text, prefix, ignoreCase = false) | size = -1, prefixSize = -1 | bool |
| endsWith(text, suffix, ignoreCase = false) | size = -1, suffixSize = -1 | bool |
| hasAny(text, chars) | size = -1, charsSize = -1 | scalar 集合相交 |
| isEmpty(text)、isBlank(text)、isUtf8(text) | size = -1 | bool；Blank 仅 ASCII 空白 |
| charAt(text, index) | size = -1 | char；不是 string 或普通整数 |
| byteAt(text, index) | size = -1 | uint8；取原始 UTF-8 字节 |
| chars(text) | size = -1 | array<char>；独立数组，元素为实际 CHAR 值 |
| bytes(text) | size = -1 | bytes；独立连续字节值，不是整数数组 |
| remove(text, part, ignoreCase = false) | size = -1, partSize = -1 | string；删除非重叠子串 |
| padLeft(text, width, pad = " ")、padRight、padCenter | size = -1, padSize = -1 | string；width 为 scalar 数，保留精确 NUL 字节长度 |
| like(text, pattern, ignoreCase = false) | size = -1, patternSize = -1 | bool；glob 的便利入口 |
| glob(text, pattern, flags = 0) | size = -1, patternSize = -1 | bool；flags 0，或 1=ASCII 忽略大小写 |
| distance(left, right, limit = -1) | leftSize = -1, rightSize = -1 | int；scalar Levenshtein 距离，超过限额返回 -1 |
| sim(left, right) | leftSize = -1, rightSize = -1 | float；归一化相似度 |
| approx(left, right, tolerance = 0.95) | leftSize = -1, rightSize = -1 | bool；sim >= tolerance |

索引查询未命中返回 -1；空子串 count 为 0。charAt/byteAt 的负索引从末端
计算，超出范围抛 RangeError（不返回空串或 0 伪装成功）。charAt/chars 与
文本算法要求选中片段为有效 UTF-8；byteLen/byteAt/bytes 是原始字节操作，
允许上限落在多字节 scalar 内部。isUtf8 在片段非法时返回 false；非法 size
仍报 RangeError。NUL 是合法 Unicode scalar，也可作为模式和集合成员。

填充不会截短原文；空 pad 使用空格，每侧从模式起点独立循环。Center
将不足宽度的一半（向下取整）放在左边，余数放在右边；width 为字符数量，
不是终端显示列数。距离 limit 必须为 -1 或非负，容差必须在 [0,1]（NaN
也拒绝）。限额超出与 OOM 是不同状态：前者无错误地返回 -1，后者抛
MemoryError。glob 未匹配无错误返回 false，非法模式抛 ValueError；未知 flags
抛 RangeError。

字符数组使用目前语言集合的 xvalue carrier，元素精确为 XVALUE_CHAR；
尚未把全体语言集合迁移为 xruntime typed 原生存储。B2 补齐了已有集合的
char 装箱准入、普通/安全索引、dict 动态键及遍历投影，复用封闭 scalar
projection，Cgen 仅机械选择 xrtValueGetChar。XRT Set 准入遗漏也已修正，
字符与数值相等时复用既有规范哈希，不另造一套集合算法。

## B3：独立拆分值与类型安全连接

| API | 可选参数 | 结果 |
|---|---|---|
| split(text, separator) | size=-1, sepSize=-1 | array<string> |
| splitLines(text) | size=-1 | array<string> |
| fields(text) | size=-1 | array<string> |
| join(array<string> values, separator="") | sepSize=-1, itemSize=-1 | string |

size 是各输入的字节上限，沿用 -1/夹紧/非法负值拒绝及选中片段严格 UTF-8
合同。join 的 itemSize 对每个元素单独应用，不是数组长度限制。所有输入和
分隔符中的 NUL 都作为实际字符保留；join 不隐式转换动态值、整数或 nullable
元素，语言签名必须为 array<string>，原生入口仍精确检查每个 STRING tag。

split 保留连续和尾部空项；空输入得到一个空项，空分隔符得到整个输入一个
项。splitLines 识别 LF/CRLF/CR，去除终止符；空输入得到零项，最终终止符
不额外制造一行空项，但中间空行保留。fields 跳过连续 ASCII 空白，不产生
空项，不宣称 Unicode whitespace 分类。零元素 join 返回独立拥有的空串。

每个拆分项都是独立 string 值，不借入源内容；源变量替换、结果数组覆盖项
和释放都不影响已经保存的其他值。算法调用 XRT 零分配片段迭代器，适配器
只负责创建拥有式 STRING 元素和失败清理，不经过一次性列表的重复数据复制。
join 借入元素并建立临时视图表，调用唯一 xrtStrJoinSized 实现；该实现直接
交付已算出的 Data/Size，不重扫结果、不以 strlen 或分配槽大小推测长度。

XLIR 的直接桥接合同现在明确数组的元素 ABI 与元素拥有形态，同时验证
array<string> 借入和拥有式返回；不因物理 xvalue* 相同而接受 array<int>
或 array<char>。TEXT_SPLIT/TEXT_JOIN 为独立按需组件，连接不引入拆分模块。

本批 Windows 589 项冻结输入检查通过；12 个严格 C/JIT/AOT/确定性样例，
11 个 ABI/默认参数负例及旧标准库回归均通过。短/大字段分配失败前缀扫描
覆盖 10/10/10/2 与 71/71/71/2 个点，另验证各模式的最终无故障路径；
部分结果与逻辑分配账本保持平衡。47 组件/2209 对依赖/331 导出身份和
12 个独立实际原生闭包通过，仅连接/仅拆分的互斥组件选择纳入回归门。

惰性拆分仍在同一长期任务中，后续以管理输入寿命
且返回独立项的迭代接口实现；不能把本批 eager 数组入口写成 string_split
已完整验收。

## 实现边界

标准库保存 extern 声明，XLIR 检查完整参数、managed string 借入/拥有结果、
保守 effect 与 XRT 错误观察 ABI。原生适配器 `xl6_text_value.c` 使用 XRT 字符串/
Unicode 算法，返回 `xstrview {Data, Size}`；Cgen 只发头、声明、调用和语言清理。
不使用 take-cstr、strlen 或分配槽位推测结果长度。XRT 的 `xrtStrReplaceSized`
从唯一替换实现交付它已算出的字节长度，原有 xrtStrReplace 复用该实现。

独立产物按使用选择 TEXT_VALUE、TEXT_QUERY、TEXT_BINARY、TEXT_CHARS、
TEXT_GLOB、TEXT_DISTANCE。结果编辑、查询、二进制值、字符数组、glob 与
距离组件分别声明实际 XRT 原生根，不把 glob/距离/值容器合并进普通查询
组件。语言核心原有的错误/清理/类型等根仍保留；不宣称组件内逐函数链接裁剪。

XRT 新增三个 Pad*Sized，与旧 Pad* 共用唯一布局和写出实现，在已知结果
长度处交付 Size；别名输出槽被拒绝且不改输入，普通失败清零。标准库的
byteAt 虽语义为 uint8，物理 ABI 仍是语言的 int64 carrier；XLIR 同时检查
语义宽度和 C ABI，char 使用独立 uint32 scalar ABI，chars 检查完整元素类型。

## B4：惰性字符串片段

| API | 合同 |
|---|---|
| string.splitIter(text, separator, size = -1, separatorSize = -1) | 分隔规则与 split 相同；保留空片段，包括末尾空片段 |
| string.linesIter(text, size = -1) | 与 splitLines 相同；CR/LF/CRLF；末尾换行不产生额外空行 |
| string.fieldsIter(text, size = -1) | 与 fields 相同；ASCII 六种空白；不产生空字段 |
| StringIterator.next() as string? | 独立拥有的字符串；空串不是 null；结束/关闭返回 null |
| StringIterator.close() | 幂等释放输入；已有返回项仍有效 |
| StringIterator.closed() as bool | 已显式关闭或 next 已观察到 EOF |

三个工厂在创建时验证严格 UTF-8 与 byte cap 并复制选定输入一次；split
同时复制分隔符。源变量替换/销毁后迭代仍有效，不向用户暴露字符串借用。
每次 next 只复制当前项，避免提前分配整个数组。算法复用 XRT 的
xstrsplit/xstrlines/xstrfields，内嵌 NUL 不截断。next 的结果分配失败抛
MemoryError 且不推进游标；恢复后重试返回原项。EOF 自动释放输入。

StringIterator 是受管有状态对象；赋值别名共享一个游标，不按 string 的
值语义复制迭代状态。它提供 __iter__/__next__，可用于 for。break/异常
释放循环引用；若仍有外部别名，资源保持有效，需 close 或等最后引用释放，
不会在 break 时强制关闭其他别名。普通作用域退役与模块终结释放最后引用。
高级直接构造 StringIterator(text, separator, mode, size, separatorSize)
接受 mode 0/1/2（split/lines/fields），其他值抛 RangeError；优先用三个工厂。

游标按创建线程使用；跨线程 next/close/closed 抛 RuntimeError（XERR_STATE），
沿用当前语言错误映射，不新增异常种类，不触碰游标。
最后引用的销毁允许发生在其他线程，销毁不分配、不抛错、保留已有错误。
原生 handle 仅由受管包装持有；C 宿主若直接使用私有 ABI，必须保证调用期间
其生命周期，不得同时销毁 handle。没有可逃逸的片段视图或 raw handle 方法。

XLIR 的共享 value/resource 描述表显式编码 factory take、receiver borrow、
唯一字段/析构身份、nullable string 和 no-raise destroy。语义层允许原生
资源方法的 nullable string 结果；不是放宽 C char* 到语言 string 的隐式转换。
Cgen 无新增拆分函数体；仅有三种工厂和迭代协议的语言胶合。
TEXT_ITERATOR 是独立按需组件，仅惰性拆分不会选入 eager TEXT_SPLIT/TEXT_JOIN。

最终 Windows B1—B4 门为 648 项冻结输入检查，14 个正向样例、15 个负例
和既有回归全部通过。B4 的 native 三模式实际分配失败点为 5/4/4，受管
完整/最小样例为 11/7，且各自运行最终无故障路径，跟踪清理账本平衡。
allocator 重入用隔离进程关闭 debug quarantine 后验证实际 backing free
不重复释放；不将其写成带调试账本的 OOM 探针。
独立产物检查 48 组件、2304 对依赖、336 导出、14 个实际原生闭包通过。
证据见 build/test/stdlib53-b4-win-final 与 stdlib53-b4-artifact-final；正式
Windows DLL/发布 CLI 验证通过。Linux 最终完整语言宿主仍待验收。

## B5：单值数字格式

int.format(int/uint64)、float.format(float)、string.format(int/uint64/float)
统一接受 (value, format = "", size = -1)，声明直接绑定三个 resident
符号，再复用 XRT 的 Int/UInt/NumFormatSized。size 是格式文本的字节
前缀上限，不是数字结果宽度；结果宽度仍写在格式语法中。全输入包含
NUL 或非 ASCII 格式语法时报 ValueError；显式截到有效格式前缀可以成功。
超长 size 截断到实际长度，size < -1 抛 RangeError。结果有独立所有权，
不会走临时区、take-cstr 或 strlen。

c 格式支持 U+0000 的 1 字节结果及带宽度填充，UTF-8 Unicode 标量
保留原格式规则；非法标量仍产生空文本。其他整数支持完整 int64/uint64、
二/八/十/十六进制、符号/前缀/宽度/分组。浮点由同一 XRT 层提供最短
往返、精确舍入、负零、NaN/Inf、指数/有效数字/固定小数/百分比，精度
上限 1000。未知语法不静默忽略；宽度/分配错误按结构化错误传播。

Buffer.appendFormat 的三个重载遵循同一合同。先取得独立原生格式
结果再追加；格式错误与内存不足保持 Buffer 有效内容不变，并安全
支持借入的格式位于 Buffer 自身。只有使用该方法才引入其专用组件。
当前多一次原生临时分配，以保留失败原子性；不把优化变成 Cgen 特例。

六个既有格式入口的语言函数体与私有 raw-pointer 注册已删除；旧 IR
枚举/特例、Cgen helper/needs 一并删除。共享 IR 合同固定标量宽度、
字符串拥有/借入和 Buffer 析构身份。原生方法默认参数只在调用点展开，
不会降低固定 C ABI 的完整性；类型与可选参数顺序由语义层检查。

Windows B1—B5 为 707 项冻结输入检查、16 正向和 21 负例。
数字 native 三个模式各 1 实际 OOM 点，Buffer 各 2 点，完整/最小受管
数字样例 14/2 点，全部含最终无故障路径与清理账本。50 组件、2500 对
依赖、342 导出、16 实际原生闭包与正式 DLL/发布 CLI 通过。
证据见 build/test/stdlib53-b5-win-final2 和 stdlib53-b5-artifact-final。
本节不将数字解析/基础写出、printf 格式接口或 Linux 宿主验收写成完成。

## B6：数字解析与基础写出

| API | 合同 |
|---|---|
| int/int8/int16/int32/int64/uint8/uint16/uint32/uint64.parse(text, base=10, flags=0, size=-1) | 严格完整解析选定字节；窄类型校验范围后返回 |
| 上述类型.tryParse(同参数) | 返回 (bool, 对应类型)；只捕获 ValueError/RangeError，资源失败继续抛出 |
| float.parse/tryParse(text, flags=8, size=-1) | 正确舍入的 double；默认允许 NaN/Inf，flags=0 为严格十进制 |
| int.toString(int/uint64, base=10, flags=0) | 精确拥有字符串，完整 64 位值；写出支持 2～36 进制 |
| float.toString(value, flags=0) | 最短往返文本，保留负零；默认保留整数型 double 的 .0 |
| Buffer.appendNumber(int/uint64, base=10, flags=0) / appendNumber(float, flags=0) | 成功后提交追加；无临时堆字符串，容量不足时才扩容 |

NumberParseFlags：none=0、allowWhitespace=1、allowPrefix=2、allowSeparator=4、
allowSpecial=8；IntegerTextFlags：none=0、upper=1、prefix=2、plus=4；
FloatTextFlags：none=0、compact=1。枚举使用时才注入；参数是 int，显式
int(枚举值) 可组合选项。整数不接受 allowSpecial，浮点不接受 allowPrefix；
未知位、负值、超出 uint32 的 base/flags 都拒绝，不截断高位。
解析 base=0 默认十进制，仅允许前缀时自动识别 0b/0o/0x；写出 base=0 拒绝。

size 是输入字节上限，不是字符数量：省略取完整实际长度，非负截到实际
长度，低于 -1 抛 RangeError。NUL 不截断；完整输入含 NUL 不能作为数字，
但显式选取有效数字前缀可成功。数字语法为 ASCII，不做 locale 或隐式
Unicode 数字转换。XRT 的语法错误映射为 ValueError，并保留域/代码/
系统代码/操作/诊断/数据/原因链/源码位置；范围和内存错误原样传播。
映射诊断分配失败时保留 MemoryError，不伪造成 tryParse 的 false。

调用直接绑定封闭 resident 符号，Cgen 不复制数字算法；旧输出指针注册、
IR 分支、生成函数体与依赖 needs 删除。基础写出通过 XRT bounded writer
在固定栈缓冲区完成后交付拥有结果或追加 Buffer，避免查询/重复解析。
int 与显式 int64 的语言声明不同，分别绑定小型原生入口，共用解析实现。

## B7：Unicode 标量、流式校验与 HTML

| API | 合同 |
|---|---|
| unicode.isScalar(code: int) | 0..0x10FFFF，排除代理项；负值及超宽值返回 false，不截断 |
| unicode.toString(value: char) | 一个标量的独立 UTF-8 string；U+0000 返回长度 1，不是空串 |
| unicode.byteOffset(text, index, size=-1) | 非负标量索引到字节偏移；允许末端索引，超界抛 RangeError |
| unicode.scalarIndex(text, offset, size=-1) | 非负字节边界到标量索引；字符内部偏移抛 RangeError |
| unicode.validate(string/bytes, size=-1) | (bool, int)：合法为 (true,-1)，非法为 (false, 首个非法序列的字节偏移)；不分配诊断 |
| unicode.validator() / Utf8Validator() | 创建受管的流式 UTF-8 校验器；不保留输入或公开裸 handle |
| html.escapeText(text, size=-1) | 转义 &、<、>；严格 UTF-8，结果保留 NUL |
| html.escapeAttribute(text, size=-1) | 同上并转义单双引号，只用于已加引号的 HTML 属性值 |

size 统一为实际输入的 byte cap：-1 全长、非负夹紧、低于 -1 抛 RangeError。
Unicode 索引转换验证**完整选定范围**，不会因所求索引在非法尾部之前而
接受坏文本；截断到字符中间属于非法 UTF-8。validate 对这种数据返回 false，
索引操作抛 ValueError，HTML 保留 XRT 的 xrt.html 结构化诊断。
string.charAt/chars/slice 等仍提供已有的标量读取/切片，不复制相同算法。
UTF-8/16/32 转码和替换策略属于下一批 encoding 接口，不能据本批宣称完成。

Utf8Validator.feed(bytes, final=false, size=-1) 返回 int 状态：
unicode.complete=0、more=1、invalid=2；more 表示分块尾部有最多三个
待补齐字节，不能当作成功结束。final=true 检查未完成前缀，并封闭本次流；
再次 feed 抛 RuntimeError（XERR_STATE），reset() 才能重新开始。
非法数据为普通 invalid，错误偏移为整个流的绝对字节位置；一旦非法，
状态保持失败，不消费后续块，直到 reset。属性 errorOffset=-1 表示无错，
total 是 XRT 已接收块的完整总字节数（非法块也计入），finished 表示已 final。
参数错误或总长度超出 int64 不提交块；total 不包含被 size 排除的字节。

校验器按创建线程使用；feed/reset/属性跨线程抛 RuntimeError，最终引用的
退役可以跨线程完成且不替换已有错误。赋值共享游标状态；输入 bytes 只是
本次同步调用的借入，保存的 UTF-8 前缀由 XRT 拷入状态，原值替换/释放安全。
feed/reset/合法查询不分配内存；只有构造、拥有字符串及需要诊断的失败可能分配。
最后引用由普通受管对象生命周期释放，不引入语言层 byref 或 borrow 语法。

三个 resident 组件分别为 Unicode 值、Unicode 校验器、HTML，各有独立原生根。
声明与 XLIR 显式保存 char/bytes/int 宽度、借入/拥有、factory/destructor 和
线程错误观察；Cgen 不生成 UTF-8/HTML 算法。HTML 不是 sanitizer，不保证 URL、
CSS、JS 或无引号属性安全，不对已有 entity 做解码或信任处理。

## B8：五种 Unicode 编码与替换解码

`encoding` 统一使用 XRT 编码 ID：unknown=0、utf8=1、utf16LE=2、
utf16BE=3、utf32LE=4、utf32BE=5，不把 Windows code page、OEM、binary
或 autoDetect 伪装为 Unicode 编码。旧 point/Buffer/code-page 编码外观退役，
不保留兼容层；编码猜测三字段结果待下一批完成，不视为已接入。

| 入口 | 参数与结果 |
|---|---|
| encoding.encode | (string text, int encoding=1, bool bom=false, int policy=0, int size=-1) → bytes |
| encoding.decode | (bytes data, int encoding=1, int policy=0, int bom=1, int size=-1) → string |
| encoding.transcode | (bytes data, int source, int target, int policy=0, int bom=1, int size=-1) → bytes |
| encoding.bom / bomSize | (bytes data, int size=-1) → int；无 BOM 分别返回 unknown / 0 |
| encoding.bomBytes | (int encoding) → bytes；仅接受五种真实编码 |
| encoding.unitSize / name | (int encoding) → int / string；unknown 为 0 / "unknown" |
| encoding.isUtf8 | (string / bytes data, int size=-1) → bool；非法数据是 false |
| unicode.decode | (bytes data, int policy=0, int size=-1) → string；固定 UTF-8，初始 U+FEFF 是数据 |
| unicode.repair | (string text, int size=-1) → string；固定 UTF-8 replacement，保留 U+FEFF |

encodeUtf8/Utf16LE/Utf16BE/Utf32LE/Utf32BE(text,bom=false,policy=0,size=-1)
及 decode 同名五种入口(data,policy=0,bom=1,size=-1) 只是普通语言固定编码
委托，不复制算法。旧 toBytes/fromBytes/convertBytes/charSize/isUtf8Bytes
和裸码元 swap 外观删除；用 transcode 明确源/目标编码完成验证过的换端。

policy：strict=0 非法 UTF-8/代理项/超范围标量/不完整码元抛 ValueError；
replaceInvalid=1 使用 XRT maximal-subpart U+FFFD 替换，不重写解码。
size 按实际字节选前缀，缺省 -1、过大夹紧、低于 -1 抛 RangeError。
切断字符/宽码元按 policy 严格失败或替换，不悄悄忽略尾部。
有效空输入返回独立空值，全部输入/输出保留内嵌 NUL，不推断 strlen/堆尺寸。

decode BOM：keepBom=0 当作原始数据（包括 U+FEFF），stripBom=1
只删除一个匹配源编码的初始 BOM，requireBom=2 必须匹配并删除，rejectBom=3
拒绝任何已识别 BOM。strip/require 下的冲突 BOM 报参数错误；keep 不解释 BOM。
显式 UTF-16LE 的 FF FE 00 00 为 BOM + NUL，不被通用 UTF-32 优先猜测覆盖。
transcode 的 bom 使用上述低两位，另加 writeBom=4 写目标 BOM；默认 1。
encode 的 bool bom 独立控制输出，不能把标记加到编码 ID。
非法编码/policy/BOM mode 原生 XERR_ARGUMENT，按既有语言映射抛 ValueError，
不为本库新增 ArgumentError 异常；isUtf8 参数/长度错误仍抛对应错误。

两个独立 resident：ENCODING（转换/BOM/repair，charset + value 根）、
ENCODING_META（码元宽度/拥有名称，仅 charset 根）。XLIR 闭合合同保存
物理宽度、借入/拥有、效果与线程错误观察，不做乐观 pure/no-raise 许诺。
生成 C 直接调用已登记符号，Cgen 不含编解码、BOM 或名称算法。
XRT 两遍转码交付一次数据分配，bytes 接管数据另建值载体；decode/repair
直接拥有输出，不生成临时 UTF-32 数组/Buffer，不额外重扫长度。

## B9：编码猜测与闭合三字段值 ABI

`encoding.detect(string|bytes data, int size=-1)` 返回三个普通 `int` 值：
`(encoding, bomSize, confidence)`。编码采用同一组 0—5 ID，BOM 长度按
字节计数（无 BOM 为 0），confidence 为 XRT 的 0—100 启发式置信度。
旧 detectBytes 与两条未解析私有桥退役，string/bytes 使用同名重载。

- 按实际字节选取前缀，-1 完整、过大夹紧、低于 -1 抛 RangeError；
  不经 strlen、拷贝、保留值或临时 Buffer。正常调用不分配内存。
- 两种输入均猜测其原始字节，不因为语言类型是 string 而强制猜 UTF-8。
  空输入为 `(unknown,0,0)`；没有可识别编码也返回 unknown，不伪造 UTF-8。
- BOM 100 分只说明初始标记，**不验证正文**：UTF-8 BOM 后跟 0xFF 仍
  猜 UTF-8/3/100。需要验证正文时调用 decode(strict) 或 unicode.validate。
  无 BOM 的 UTF-8/宽编码猜测可能有歧义；置信度不是正确性保证。
- 原生根仅 CHARSET_DETECT + VALUE；单独猜测不选择编码转换、元信息、
  Unicode/HTML/文本/数字 resident 或 Buffer 根，最终闭包以实际产物核对。

Typed XLIR 增加通用闭合 `I64X3_V1` 原生 product profile：三个按声明顺序
排列的 signed 64-bit 值，无指针、引用、拥有或隐含生命周期。原生 C 与
生成 C 共享有 guard 的 `XL6_ProductI64x3V1 {e0,e1,e2}` 定义；普通语言
三整数多返回值使用相同 carrier，非闭合产品仍保留原有结构与边界。
extern 在语义层仅允许三项语言 int/int64（含解析后的类型别名），XLIR
独立检查每项宽度、符号、所有权、null ABI、字段数量及稳定 C 名称。
不是任意外国 C struct 的自动映射，不依据宿主 sizeof 或库符号猜布局。

标准库只保存声明及 size 默认值，Cgen 依据已验证 product 信息生成
一次原生调用与三个字段读取，不增加探测算法、分配或库名特判。
保守效果、may-block 及 XRT 线程错误观察仍保留：合法路径零分配不代表
非法参数的诊断路径 no-raise，也不代表能无证据声明 pure/nonblocking。
