# 原生指针集合合同

`point` 与 `point<T>` 可以作为 Array、Stack、List、Dict 的元素。类型标签约束赋值及集合视图；指针相等性比较使用实际地址，不改变两个操作数的类型身份。

## 存储与生命周期

- XLIR 使用 `RAW_POINTER` 原生槽位、`TRIVIAL_COPY` 传递方式和现有 `C_SCALAR_V1` Sequence 配方。
- 驻留实现使用 XRT 的 `xrtTypePointer()`，槽位直接保存一个 `void*`。复制、移除、扩容和释放集合均不取得或释放被指向对象的所有权，也不延长地址有效期。
- Array、Stack 和各集合的值域保留完整的 owner、element、base TypeId；把 `array<point<A>>` 视为 `array<point<B>>` 会被拒绝。
- 已绑定的动态指针必须匹配值域身份。原生互操作产生的未绑定指针仍沿用已有的显式指针协议。
- 原生空值使用 `NULL` 槽位；动态指针使用 `XVALUE_POINTER(NULL)`。动态 `null` 标签不直接作为原生指针的装箱形式。

## IR 与生成代码

迭代采用 `RAW_POINTER_COPY`，循环变量使用平凡值替换。游标和集合继续使用已有的拥有权及快照协议。

`point(firstBox) == first`、反向比较以及不同静态标签之间的地址相等性可直接生成 C 比较。此规则只补齐 `==`／`!=`；跨标签赋值仍由语义检查拒绝。

Array 的平凡值 `pop`／`take` 统一使用已有 `STATUS_OUTPUT` 合同：成功与否由返回的布尔状态决定，空指针和数值零均可作为成功结果。Cgen 读取 IR 配方、选择描述符并使用该状态，不生成指针适配函数体。

## 验证

- `cgen_typed_point.xl`：原先缺少完整 Sequence 配方的样例。
- `xlir_point_sequence.xl`：Array／Stack／List／Dict、默认空值、移除、迭代、动态视图及地址比较。
- `xlir_point_sequence_host.c`：三个实际不同的静态 C 地址，检查生成代码在非空输入下的行为。
- `xlir_point_sequence_contract.c`：4 个完整配方、3 个平凡迭代目标、10 个显式指针投影、7 处跨 TypeId 的地址比较；46 个破坏性 IR 变异均须在写入 C／头文件前被拒绝。
- `xlir_point_sequence_native.c`：原生描述符、空指针载体、错误标签及身份拒绝、真实地址与内存平衡。

Windows 与 Linux 均通过实际 JIT、实际 AOT、O0／O2 生成代码及原生宿主测试。原生分配失败前缀每个编译级别覆盖 11 个实际失败点，第 11 点首次无注入命中；四条平台／编译级别路径共覆盖 44 个实际失败点，均内存平衡。这些结果属于本合同的验收，整个标准库发布验收另行完成。
