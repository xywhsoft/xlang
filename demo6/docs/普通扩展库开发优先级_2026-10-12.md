# DEMO6 普通扩展库开发优先级（2026-10-12）

## 范围与口径

本表以[扩展库成熟度清单](扩展库成熟度清单_2026-10-12.md)的 208 个公共包快照为起点。之后 `acme` 占位包已移到 `dev/deferred`，当前活动公共包为 207 个；历史 A/B/C 数量保留为快照基数，不代表仍全部发布。`xbot` 交由独立线程维护，不进入本任务：

| 类别 | 包数 | 本轮处理 |
| --- | ---: | --- |
| A：功能冻结候选 | 9 | 只做缺陷、安全和回归维护，不进入扩功能队列；仍需发布门禁 |
| B：已有实际能力，仍需完善 | 121（历史快照） | 排除 19 个专门上下文维护的包、1 个合并候选，并将占位 `yaml` 重新归类，余下 **100 个**进入下表 |
| C：同名核心能力尚未实现 | 78（当前活动重新归类后 78） | **暂停开发，不排优先级**；`acme` 已移出，`yaml` 归入此类，`xbot` 交独立线程，其余以后逐个决定真实后端、窄化或移出 |

“已有实际能力”不等于“生产可用”。这是一份开发排序，不是发布认证；先前的 19 个 featured 用例仅抽样，未对 100 包重新完成逐 API、全平台验收。`yaml` 占位实现的越界和功能缺口见 `demo6/dev/extlib_deferred/yaml.md`，正式发布前不能按完整 YAML 包交付。功能重合的判断与删除前提见[扩展库与 X 体系重合审计](扩展库与X体系重合审计_2026-10-12.md)。

### 从普通队列移出：19 包

- XRT `extlibs/` 专门维护的对应包：`jwt`（对应 `xjwt`）、`oauth2`（对应 `xoauth2`）、`xhttp`、`xhttp.body`、`xhttp.body_async`、`xhttp.body_codec`、`xhttp.body_decode`、`xhttp.body_file`、`xhttp.body_stream`、`xhttp.client`、`xhttp.form_data`、`xhttp.multipart`、`xhttp.protocol`、`xmail`、`xssh`、`xws`。XRT 产品范围以 `D:\GIT\xrt\extlibs\README.md` 和相应产品目录为准。
- XUI/XGE 专门维护：`xui`、`xge`、`xge_shape_ex`。`_xge_native` 本来就是内部依赖，不计入 121 个公共 B 包。

上述 19 包移出仅表示不在本轮普通扩展库维护清单；**不是**删除、弃用或判定已成熟。另将 `xbot.agent` 从普通扩功能队列移到与 XRT `xwork` 的合并/退出审计：已核对双方工具执行、工作区与策略职责交叉，但当前还没有等价的 XLang `xwork` 入口，不能直接删掉仍公开的能力。`ui.auto`、`uia` 属于独立的桌面自动化包，仍在普通队列。

## 开发顺序

| 优先级 | 包数 | 判断依据与交付目标 |
| --- | ---: | --- |
| P0：解除现有阻断 | 13 | 当前正式构建已有明确失败；优先修共同的 XLIR/`bytes`/ABI 边界，再分别验收，避免逐包打补丁 |
| P1：高复用通用能力 | 30 | 解析、配置、数据交换、CLI、归档、基础服务，能直接支撑大量应用和其他包 |
| P2：已有真实后端的专业能力 | 24 | AI、系统、图像、桌面或云平台；用固定模型、真实设备/服务或隔离测试环境验收 |
| P3：窄场景与需求驱动 | 33 | 保持现有可用范围，先补合同和测试；有具体应用需求再扩 API |

优先级是**投入顺序**，不是质量等级。安全或崩溃缺陷一旦确认，跨组提升为即时修复；不能因 P3 而放任已发布能力错误。

### P0：解除现有阻断（13）

`argon2`, `blake2`, `blake3`, `brotli`, `bz2`, `ini`, `lz4`, `lzma`, `miniz`, `snappy`, `sqlite`, `xxhash`, `zstd`。

建议依次推进：

1. 在固定的 `xl.exe` 构建上保留最小失败用例，先收口 `bytes` 实参与 typed XLIR 物理/ABI 路径。若根因在编译器，只修共享层并复跑整组，不在算法库各自加转换兼容层。
2. 单独修复 `sqlite` 的 XLIR runtime operation ABI、`ini` 的 `xini_parse` 声明/原型冲突。
3. 每个包至少验证真实输入输出、坏数据、资源释放、C/XL 对照和对外格式互操作；不能把“主用例恢复通过”当作完整验收。

### P1：高复用通用能力（30）

`bson`, `cbor`, `cli`, `color`, `css`, `cString`, `csv`, `dotenv`, `fix`, `gettext`, `graph`, `gzip`, `hcl`, `json.patch`, `json5`, `md4c`, `msgpack`, `netrc`, `redis`, `semver`, `shellwords`, `statistics`, `sysinfo`, `tar`, `toml`, `watch`, `xml.dom`, `xml.etree`, `xml.sax`, `zip`。

先做 `cli` / `dotenv` / `csv` / `toml` / `zip` / `tar` 这类日常入口，再推进结构化格式、文本处理和系统辅助。`redis` 必须用真实服务验证分包、断线、重连与错误恢复；`csv`、`color`、`graph` 已有边界记录，先复验和修复，再扩大功能。对 `json5` 等窄实现应明确承诺范围，不因包名暗示完整标准。

### P2：已有真实后端的专业能力（24）

`clipboard`, `com`, `daemon`, `dinov3`, `linalg`, `onnxruntime`, `op`, `opencv`, `pkcs`, `procps`, `rapidocr`, `serial`, `sharedmem`, `singleinstance`, `stb_image`, `stb_image_resize2`, `stb_image_write`, `stb_truetype`, `ui.auto`, `uia`, `volc.core`, `volc.phone`, `volc.sts`, `xfeat`。

分场景推进：普通包按公开能力验证成功/失败路径、资源所有权和必要的平台边界；云服务包使用可重放的 mock/沙箱，并将需凭据的真实服务测试分开。`op`、`opencv`、`onnxruntime` 等依赖独立插件或外部桥接的包，本任务只验收 XLang/C 公开调用链：装载、ABI、一次有代表性的真实成功调用、失败调用和结果所有权；插件内部的算法、设备/驱动矩阵及长时压力由其维护者负责，不在本任务重复测试。`op`、`ui.auto`、`uia` 不因邻近 XUI/XGE 而自动移出本表。

### P3：窄场景与需求驱动（33）

`ansi`, `barcode`, `consistent_hash`, `crontab`, `cuckoo`, `diff`, `epub`, `floatEnv`, `fuzzy`, `geohash`, `hyperloglog`, `ical`, `imagehash`, `langdetect`, `lru`, `money`, `pinyin`, `plist`, `progress`, `qr`, `roaring`, `rss`, `rtree`, `sitemap`, `skiplist`, `slugify`, `srt`, `tabulate`, `terraform_state`, `totp`, `trie`, `units`, `vcard`。

这组先补清晰 API 合同、负例、C/XL 对照及可复跑范例，不主动把每个名称扩写成大型框架。出现明确项目需求时，再按实际阻断和复用价值上调优先级。

## 统一验收门槛

每个包进入“本轮已完善”前，应至少有：固定版本的可复跑正/负例；失败诊断和资源所有权合同；C 与 XLang 等价用法；导入、构建、运行主路径；声明平台的回归结果。调用外部模型、服务或设备的包须明确依赖获取方式，并完成与该包验收边界相符的真实调用测试；不要求替独立插件验证其内部实现。跨包共享的编译器/XRT 故障记作一个根因，修后回归所有受影响包；不把包侧绕过记为问题关闭。

本表不安排核心尚未实现的包的新核心实现，也不调度 XRT 扩展库与 XUI/XGE 的专门维护工作。`xbot.agent` 仍在发布目录，已知路径解析与读取限额风险需要立即修复或停止公开交付；移出扩功能队列不意味着可以忽略安全问题。与[成熟度清单](扩展库成熟度清单_2026-10-12.md)的 121 个 B 包逐名对照，排除上述 20 个，再重新归类 `yaml` 后，本表 P0–P3 **共 100 个，且每个仅出现一次**。
