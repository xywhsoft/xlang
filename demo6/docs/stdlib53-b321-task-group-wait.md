# TaskGroup 的等待依赖与清理准备

TaskGroup 现在提供真实等待描述和正常关闭准备。关闭后的组等待全部
活动项进入终态；输入来自实际链表，重复项保持独立，不建立新的拥有边。
准备先关闭接纳，正常执行已接纳工作的完成通知，活动项归零后才注销
组观察者。它本身不取消任务，也不伪造 Done 结果。

正常完成的活动项可能仍由收集计划持有。新的原生 V2 协议允许这种
稳定节点继续报告真实引用和槽位，避免计划刷新时丢失节点；旧 V1
仍只准入活动项。新旧描述符身份不同，不能在同一计划内替换。

语言等待求解器将关闭组视为 ALL-terminal 生产者，读取实际输入时只
增长私有分析空间，不复制输入数组、不增加资源引用。开放组、不同
claim、在途操作或尚有未声明活动项都不能提供认证等待事实。未知或
可完成的 ANY 分支仍可进展；仅指向循环的上游组不获得中断授权。
依赖通过原生模块清单声明，链接目录由实际预处理定义重新生成，
Cgen 不增加名称猜测或回溯补丁。

原生测试使用 32 组真实嵌套、重复、ALL、ANY、开放分支和上游图，
覆盖正常完成、中止恢复、完成态节点、输出拒绝及零分配物理退役。
消费侧同一夹具通过生产求解器检查 96 个实际 provider/claim 判断；
独立图算法 oracle 对 66064 个图、197648 个根判断进行交叉验证。
这些测试不使用模拟生产者。

独立 TCC 用例从已验证的生产目录取等待求解器的完整声明闭包，并
检查该闭包不要求宿主 ABI；它不编译无关的宿主域或提供虚假宿主。
持久化保留键数组改用显式赋值，避免外部 TCC 的复合初始化错误，
保留键、声明键和空键的计长比较规则保持不变并接受回归检查。
等待探针先保存借用引用和预期值再传参，避免外部 TCC 对嵌套结构体
返回参数的错误生码；输入、循环判断和引用计数规则不变。

这一步不自动打开 TaskGroup 的语言全局循环准入。桥接句柄的准备、
语言域目录、Future 与取消观察者的准备和物理完成协议仍须协调，
并通过真实语言回调及 catch/finally 的端到端验收。53 模块发布验收
继续进行，对象池仍在最后。
