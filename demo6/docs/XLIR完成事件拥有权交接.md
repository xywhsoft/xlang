# XLIR 完成事件拥有权交接

2026-09-20，v222 候选。v221 的 Socket 引用保护解决包装对象寿命，
这一轮为载荷处理增加明确的操作拥有权终结点；完整 Transport 和服务图
仍未验收，生产 Cgen 的 live-service 拒绝边界不变。

## 实际交接合同

`xrtNetCompletionTakeV1` 只接受当前 Worker 正在执行的那个原始事件槽，
原子地把 lease 和独立 Accepted 拥有权移给初始化过的调用方存储。
它不分配内存、不增加引用、不执行释放回调。原槽随即清空拥有字段，
Engine 回调尾部不会再次释放已经转出的引用。

处理函数先取得自己后续仍要使用的 Context、Socket、代码等真实引用，
再释放取出的事件。操作 lease 终结之后，处理函数才可以消费或移动
原来由操作保护的缓冲区。释放可能直接销毁 User 和 Completion 描述符，
Engine 因此不能在回调返回后再读取它们。

允许新宿主继续保留整个事件，并按实际引用投影其拥有图；这不把事件
虚构成外部根，也不减去仍然存在的 RC。Accepted 仍由调用方独立接管
或关闭，EventRelease 不消费它。

回调外调用、别的 Worker、复制的事件描述符、重复 Take、目标已有
拥有权、目标落在 Worker 固定事件数组，以及旧借用事件都必须拒绝，
失败不修改任何一侧。现有 Completion 仍是两个指针，不增加 Stream、
Listener 或 UDP 的固定字段；Worker 增加一个非拥有的当前事件指针。

## 验证与后续

原生测试覆盖真实 Post、IOCP／io_uring 接收、取消、Accept、退休、
回调内提前释放、跨回调保留、未取走时自动释放，以及独立缓冲载荷的
实际释放顺序和精确内存平衡。XLIR Engine-Port 测试将部分共享事件
通过 Take 处理，再由未修改的生产规划器验证回收、外部引用及复活。
结果以 v222 的实际测试产物为准，本说明不等于验收已经通过。

跨回调保留事件还覆盖 Engine 创建者先退休的情况：Frame 持有的真实
Engine 引用继续保护 Engine 和 Worker 存储，直到保留事件释放。
Stop 后 Port 已实际退休，对象图不再包含它；创建者退休后则只减少
对应的真实外部引用。这两步分别检查，不能靠修改 Count 掩盖差异。

TCP／UDP／TLS 还没有整体迁移到拥有型提交。后续必须同时处理操作
引用、缓冲预留、回调／内部命令／Timer／continuation 的精确策略，以及
现有小对象缓存和无分配/OOM 合同；不能仅替换 API 名称就解除图准入。
完整服务、语言／FFI、混合生命周期、DLL 卸载和最终发布仍待完成。
