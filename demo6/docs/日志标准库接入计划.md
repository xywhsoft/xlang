# 日志标准库接入计划

状态：设计已批准；第一批基础与控制台已实现。不是 12 个模块全部完成，也不是全平台发布验收完成。

## 统一体系

12 个 XRT 实现模块在语言层统一为 `log`，不要求用户分别导入实现细分模块。
算法和实际输出由 XRT 执行，语言外观负责类型和组合；必要的 ABI 适配器独立编译，
XLIR 固定参数、效果、错误和所有权合同，Cgen 只输出已验证的调用及声明头。
不向生成 C 中注入日志函数实现，也不重复实现 XRT 日志算法。

默认不创建 Logger、Sink、文件或线程。`log.default()` 返回 `Logger?`，未配置默认 Logger
时全局写入返回 `LogResult.skipped`，`log.flush()` 无操作。`fatal` 只表示级别，不退出程序。
`enabled` 是 Logger 阈值的快速预检查，不保证存在接受该记录的 Sink。

`Logger`、`LogSink` 受语言生命周期管理；attach 和默认 Logger 持有独立原生引用，
从默认配置取得 Logger 会获得自己的引用。统计为独立只读快照，五项计数是 `uint64`。
全局写入/flush 直接在原生适配器中短暂持有默认引用，不为每条记录分配语言包装对象；
无默认 Logger 时仍验证级别与 size，不因 skipped 而忽略非法输入。
原生句柄构造/访问用于内部接入和显式 C 互操作，不是安全的任意指针入口。

| logger_format_json_buffer | 未接入 | JSON 写入 Buffer、失败原子性/错误语义 |

后续顺序：结构化记录及 formatter → Writer/原生文件/轮转 → 检查型 printf → async/ring →
全模块批量验收与旧范例迁移。后续工厂分别登记独立适配器与依赖闭包，不把文件/线程实现
塞进当前核心组件。文件目标不得直接把 VFS 路径假装成原生路径；必要时扩展 XRT writer 接口。
工作线程不直接执行任意 xlang 回调。异步 `written` 表示入队成功，不等于已经落盘。

## 本批语言公开面

- `LogLevel`：trace/debug/info/warn/error/fatal/off。
- `LogResult`：written/skipped/dropped；实际操作失败走语言异常，不把错误伪装为 dropped。
- `log.create(name = "xlang", level = LogLevel.info)`、`default/setDefault/levelName`。
- `log.write(level, message, size = -1)` 和六个级别快捷函数、`log.flush()`。
- `Logger`：name、getLevel/setLevel/enabled、addSink/removeSink/clearSinks/sinkCount、write/六级快捷函数、flush/stats。
- `LogSink`：name、getLevel/setLevel、flush/stats。
- `LogStats`：submitted/written/skipped/dropped/failed，只读快照。
- `log.consoleSink(LogConsoleOptions? = null)`。

`LogConsoleOptions` 提供 level、target（stdout/stderr/split）、color（automatic/never/always）、
errorLevel、flushEachRecord，以及 `text: LogTextOptions`。
文本配置提供 style（full/simple/message）、flags、utcOffsetSeconds；flags=-1 使用预设，
其他值是 `log.textTime`、`log.textLevel`、`log.textLogger`、`log.textSource`、`log.textThread`、
`log.textFields`、`log.textNewline`、`log.textRawMessage`
的位组合。UTC 偏移单位为秒，范围 -86399…86399。选项在工厂调用时复制，之后修改选项
不会改变已创建的 Sink。未知标志或非法配置拒绝，不默默降级。

消息和名称使用完整 `string` 字节长度，保留内嵌 NUL。`size=-1` 使用实际长度，非负值
按 `min(size, 实际字节长度)` 截断，其他负值报 RangeError。截断单位是字节，不隐式
改成字符数；文本格式化默认转义 NUL、换行等控制字节，原始输出须显式选择 rawMessage。
输入借入而不复制；返回名称复制为独立字符串。所有可能分配或执行 IO 的入口保守标记
may-raise，不宣称 pure/nonblocking；析构入口 no-raise。

```xlang
auto logger = log.create("app", LogLevel.debug)
auto options = LogConsoleOptions()
options.text.style = LogTextStyle.message
auto sink = log.consoleSink(options)
logger.addSink(sink)
logger.info("a\0b")
logger.flush()
log.setDefault(logger)
log.warn("ready")
log.setDefault(null)
```

旧的 `log.addFile/addRollingFile`、int 级别常量和 `Logger.custom/end` 伪接口不延续。
旧 `stdlib_log.xl`、`stdlib_log_object.xl`、发布日志对照范例仍保留作为后续能力迁移的参考；
包含这些旧接口的全量 suite 还不能作为本批通过声明，必须在相应功能完成时迁移。

## 验收

```powershell
cmd /d /c build_dll.bat
./tools/check_stdlib_logging.ps1
```

验收门冻结源码和工具链摘要，在一次批次中执行：原生捕获 Sink 的长度/NUL/结果/引用测试；
XLIR ABI 借入/效果/错误合同破坏测试；三组语言用例的严格 C/JIT/AOT、确定性及精确输出；两种错误
ABI 的编译前拒绝；基础 IO、文件命名与 CRT 数学回归。输出到独立 evidence 目录，
不覆盖前轮证据。生成 C 不含日志适配器函数体，核心用例不含 console 调用。

独立产物专项还验证了 27 个 resident 组件的 729 对依赖闭包、全部实际导出符号归属，
三组用例的原生目标文件无缺失符号，以及实际 AOT 原生实现与计划相同。
核心及仅全局写入用例的原生目标文件不含 logger console/file/async/ring 实现；
这不表示去除了语言错误输出可能依赖的基础 console 模块。

当前是 Windows 第一批验收。OOM 全路径、语言层失败 Sink、结构化/文件/异步/ring 全家族、
POSIX xlang 宿主、退出清理及全仓 RC0 仍须继续验证，不能据此称整套日志生产级封板。
