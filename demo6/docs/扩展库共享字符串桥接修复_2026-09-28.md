## 根因与修复

`string.join` 已有标准库声明，但 XLIR 未登记它的私有运行时桥，生成程序因
`xl6_xrt_string_join` 未解析而失败。修复统一登记精确参数、结果、拥有权和错误 ABI，
后端只消费已验证的 bridge kind，并按使用情况发射实现，不加入名称猜测或兼容分支。

- 输入是借用的动态数组；字符串元素借用 XRT 的完整视图，其他元素复用现有
  `string(var)` 转换，再交给 `xrtStrJoin`。不重复实现格式化和拼接算法。
- 输出是独立拥有的缓冲；空数组、空分隔符、空元素、UTF-8、混合值和临时数组有测试。
- 任何中间分配或转换失败均清理已持有的缓冲，不返回部分结果，不修改输入。
- 仅用 byteLen 的生成程序不会因此带入 join 或值格式化实现。

分配失败注入还发现一类共同问题：部分会分配的字符串桥被标为不会抛错，导致 XRT
已经报告失败，语言调用却未进入异常分支。现在 `repeat/slice/replace/split/join/
splitLines/takeCstr` 的错误能力集中登记为 `may-raise`，使用既有 `xrt-thread-error`
物理错误 ABI 与 IR 错误边，不新增第二套错误通道。查询桥仍为 `no-raise`。
splitLines、takeCstr 不再各有重复的识别和签名核验分支。

## 前一批失败边界

1. `stdlib_string.xl` 暴露另一个未接入的桥：`xl6_xrt_string_bytes`。
2. 语言字符串的复制、传参和部分 C 视图使用终止符推导长度，含 NUL 时截短；
   `string.byteLen` 探针仍失败。原生 join 能处理 xvalue 的完整字节视图不等于语言边界修复。
3. 上一问题继续导致 graph 的两个含 NUL 名称被混同。
4. CSV 的 class 字段数组迭代探针仍被 canonical iterator ABI 核验拒绝。

这四项均保留真实失败输出，没有修改预期或通过包内绕过宣称修复。NUL 必须统一处理
受管理字符串长度、复制、实参/返回、装箱和 C 文本投影；不采用只补 byteLen 或全局
指针长度表的局部方案。迭代问题须按字段借用、循环持有和清理的同类边界修复。

定向通过集为先前 17 个专项库入口，加 CSV、graph、chardet 三个用例；不能据此
给这些包的全部功能、所有平台或所有集成方式下结论。
