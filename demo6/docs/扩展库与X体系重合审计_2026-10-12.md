# DEMO6 扩展库与 X 体系重合审计（2026-10-12）

## 判定原则

X 体系包括 XRT 核心、`D:\GIT\xrt\extlibs`、XGE/XUI 和 xserver。**功能重合可以合并或删除包**，但“使用了同一个 C 算法”不等于“已提供相同的 XLang 用户能力”。实际移除公开包前，需要确认替代 API 在目标语言中可调用、成功与错误路径等价、现有依赖和范例已迁移，并且当前包没有未保存的工作区改动。既有包即使要退出，也不做兼容别名或长期双轨维护。

xserver 当前是基于 XRT 的配置驱动部署工具，不替代通用数据库、文档解析、文件格式或图形库。某个库被 xs 可选编入，也不等于一般 XLang 程序不再需要它。XUI/XGE 是 UI/游戏体系；`imgui` 等独立工具箱可以提供互补能力，不能按“都做界面”删除。

## 已移出普通维护队列

上轮已将 16 个与 XRT 扩展产品对应的 B 包，以及 `xui`、`xge`、`xge_shape_ex` 共 19 包，交由专门上下文维护；详见[普通扩展库开发优先级](普通扩展库开发优先级_2026-10-12.md)。这不改变当前发布目录，也不是对这 19 包的成熟度认证。

本轮另将 `xbot.agent` 移出普通扩功能队列，列为 **XRT `xwork` 合并/退出候选**。其现有 `AgentPolicy`、`AgentWorkspace`、`AgentToolkit`、工具调用和日志与 `xwork` 的策略、工作区、工具执行和 Agent 循环职责交叉；但 `xwork` 目前尚无同等的公开 XLang 包。先确定 XLang 绑定与迁移路径，再退出旧包。旧包仍公开且已记录路径解析、读取限额风险，过渡期必须修复安全问题或停止交付，不能仅从排期中消失。

## 候选与阻断

| 包 | 已存在的 X 体系能力 | 当前结论 |
| --- | --- | --- |
| `acme`（原 C 类） | XRT `xacme` 有真正的 ACME 证书申请与管理；原 XL 包只提供 JSON/挑战文本等 helper | **已移出**发布目录，归档到 `dev/deferred/extlib_catalog`；不再独立实现第二套 ACME 客户端 |
| `xbot`（C 类） | XRT `xwork` 承担 Agent 工具循环与策略；当前 XL 包仅有 `OpResult`、尺寸/像素等基础类型 | 属于独立维护的 x 生态；**保留原样，不在本任务清理或开发** |
| `xbot.agent`（B 类） | XRT `xwork` 已有 Agent/工具运行时 | 暂停扩功能并准备合并；缺少等价 XLang 入口，不能直接物理删除；安全风险立即处理 |
| `xregex`（A 类） | 内置 `regex` 已有编译、捕获、替换、分割、模式集等主功能 | 评估细项差异后可合并，但 `_xge_native` 明确依赖 `xregex`，必须由 XGE 专门上下文先迁移依赖 |
| `chardet`（A 类） | 内置 `encoding.detect` 与 XRT 编码探测复用同一底层 | `confidence`、`bomSize`、`isUtf8`、`isAscii` 等额外 XL 接口尚须逐项比较/迁移；不能只留 `detect` 就删除 |
| `md5`（A 类） | XRT `xrtMd5` 已提供一次性与流式 C API | 若要减少独立包，应先提供受限的 `crypto.md5` XLang 入口并迁移调用方；仅标兼容用途，不推荐新密码方案 |
| `gzip`（P1） | XRT 已有 gzip/DEFLATE 编解码 | 当前 XL 包还有文件操作、上限控制和进度回调；不是可直接删除的纯重复包。若统一接口，再移交这些能力 |

以上为**退役或合并候选**，不等于本轮已删除。`chardet`、`md5`、`gzip` 等目录有工作区修改和新增文件；直接删除会丢失未提交工作。`xregex` 还有 XGE 依赖和新增文档。物理清理必须和替代接口、依赖迁移、登记更新及回归同批完成。

## 明确保留的互补能力

- `imgui` 与 XUI/XGE 都涉及界面，但用途和集成方式不同；即使其当前核心实现不足，也按原 C 类规则暂缓，而不是因重合删除。
- `op`、`ui.auto`、`uia` 是桌面自动化/窗口操作，不是 XUI 的同义包；`clipboard` 的脚本级系统剪贴板也不因 GUI 框架存在而自动消失。
- `ansi` 生成可组合的终端转义字符串，并提供去除转义/显示宽度；内置 `console` 主要操作终端会话，尚非完整替代。
- `sqlite`、`md4c` 可被 xs 可选编入，但 xs 是部署宿主，不替代它们面向任意 XLang 程序的通用包。`redis`、`rss`、`sitemap` 同理，不因 xs 能运行网络服务而删除。
- `murmur3` 与 XRT 默认 `xrtHash32`/`xrtHash64` 算法不同；`siphash128` 与内置 SipHash-64 输出不同。相近名称不能作为合并依据。

本轮只调整开发队列和退出判定，不对脏工作区里的现有包目录执行破坏性删除。待对应 XLang 接口、依赖和测试替换完成，再逐个从发布目录退役；新增功能仍按[101 包优先级表](普通扩展库开发优先级_2026-10-12.md)推进。
