# 泛型依赖闭包与二进制默认初始化

完整标准库类目录中的声明也会产生动态方法登记。登记所生成的具体
泛型方法，其内部普通调用、类协议、循环协议和资源元素模式必须在
注册物理调用目标之前全部闭合。只对源程序显式调用做实例化，或执行
固定次数的补充遍历，都不能满足这个要求。

## 统一实例化边界

Lowering 对上述依赖来源执行有界固定点计算。节点、类型、具体实例
和类布局不再增长时，才进入最终类型合同刷新和物理目标登记。
实例建造入口共用 1024 个具体实例的模块预算；已缓存实例在预算
达到上限后仍可复用，新增实例明确拒绝，不把预算在不同来源间重置。

源类型接入、类型替换和方法实例化共用泛型元素模式登记。Stack、
消息容器、List 和 OrderedMap 的配套 Array 模式由同一规则产生，
不会因类型出现得晚而遗漏，也不会在 Cgen 临时推导。

## 空 bytes 的语言合同

没有显式初始化表达式的非可空 bytes 字段和变量取得拥有的空 bytes，
不是 null。可空 bytes 的默认值仍为 null。XLIR 为两者保存不同合同，
验证器核对具体类型和失败效果；Lowering 使用既有计长字节构造与
拥有值边界，创建失败沿声明或构造位置的 checked 路由清理。

## 验收边界

完整类目录和仅声明 FixedStack 的输入只做编译验收，不执行尚未
初始化的对象。运行回归通过动态登记访问泛型方法、嵌套 FixedStack、
整数、计长字符串和任意 bytes；另保留完整 FixedStack、泛型动态方法、
协议分派、泛型 callable 和二进制默认参数回归。

Windows、Linux 普通与 Linux 指定插桩通道各 83 项通过。501 个
动态方法目标／bytes 默认合同破坏反例在 C 与头文件输出前拒绝；
O0／O2 各 95 个同步分配前缀包含首次未触发点，退役后内存账本平衡。
泛型样例的实际未剥离裁剪产物运行通过，不引入 Process／Regex。

双端各 310 个三组标准库夹具的 Cgen 与严格 C 语法检查全部通过。
实际调用绑定普查各 311 个候选输入、224 项注册、228 种签名，静态
与所列托管类方法均无漏项；这是绑定覆盖，不等同于所有方法动态
调用可用或全部运行分支已执行。驻留目录仍为 304 个组件、1507 个
导出，92416 对依赖闭包和 23 个负控通过。

专项工具为 `tools/check_stdlib_generic_graph.py`。完整源编译器的生产
链接与私有实例预算白盒测试分别记录；白盒程序不替换生产提供方。
Linux 的指定插桩仅覆盖生成 C 与测试宿主，不能当作全部原生提供方
插桩。回调动态参数、非字面量默认参数、异步动态返回、工作线程和
对象图故障、组合模块、真实卸载以及 CLI／DLL／VFS 发布总门继续。

本批不新增标准库公开 API；CRT 0、XRT 19 组未决策范围、WaitQueue
MPMC 拥有接收合同及对象池最后的顺序保持不变。
