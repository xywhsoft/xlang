# 执行资源生命周期接入合同

本批实现 `xl6_execution_resource` 常驻底座，供后续公开 Executor／TaskPool
接入使用。**不代表语言类、模块资源槽或普通 DLL／JIT／AOT 已经接完。**
原生执行算法、队列、工作线程和作业统计仍复用固定快照中的 XRT，没有添加
第二套调度器，也没有改动独立 XRT 仓库或发布二进制。

## 真实拥有者与最后引用

`ExecutionSource` 是显式拥有的资源源，不是默认 async 执行器。每个源只有一个
原生控制线程，负责关闭后实例的排空和物理回收；不是每个作业创建辅助线程。
正常回调仍在 XRT Executor／TaskPool 工作线程上运行。空闲时等待原生事件，
只有最后用户引用已释放、尚有工作／调用尾部时才作有限期限重试。

源的注册表实际持有每个 Resource 引用；Resource 实际持有源的反向引用，并
持有相应 native creator。三者都是物理拥有槽，可在图中逐一核对，不是虚构的
RC 边。以下引用区分开来：

- 用户拥有者：Retain／Release。最后一个用户引用释放时请求退休。
- 调用 entry：从 Enter 到同线程 Leave，保留实际 Resource，期间 native
  指针只可借用，不可复制 scope 或将指针保存到 Leave 以后。
- 检查 pin：图 Hold／Drop。保持分配存活，但不冒充用户拥有者、不推迟自动关闭。

最后用户引用可以在该 Executor／TaskPool 自己的捕获析构中释放。控制源继续
持有 creator，直到原生 body、捕获释放、结果登记和调用尾部全部完成，再在
独立控制线程回收。因此不会在本机工作线程 self-join，也不会释放仍执行的实例。
持有检查 pin 的 Resource 可以在源物理销毁后继续存活，最后 Drop 才回收分配。

## 关闭、等待与失败

Source.Close 只关闭新资源创建，不替用户关闭／取消尚有用户拥有者的实例。
原生创建和最终注册之间再次检查源准入；关闭竞态拒绝注册时，在元数据锁外撤销
完整的私有创建。Resource.Close 停止其作业准入，但保留原生实例以供已有用户
读统计、等待和错误报告。普通后台回收只处理 owners == 0 的记录。

Executor 回调保留首错与失败计数：首错按完整作业结束后的登记顺序，NULL 诊断
也能代表真实失败，不能用 error 指针是否非空判断成功。Wait 的 READY 是物理
完成，checked bool 独立报告语义失败；Timeout 不报告尚未完成的工作为成功。
原始错误不会重新包装成 StateError。资源最后引用释放后的普通后台回收还会把
账本失败交给源的 checked 清理结果，避免因再也没有调用者而默默遗失错误。

原生物理清理失败时，保留原生 creator、注册记录与首错，停止该记录自动重试。
宿主可显式 Source.Retry 恢复重试；成功回收不会清掉历史失败。Source.Check
和 Source.Destroy 都能报告它。Destroy 的 `{ready, ok}` 两字段独立：ready=true
时消费并置空源的 creator，即使 ok=false 仍必须接收原始错误。BUSY 时保留原槽。
直接的 Resource.Retry 需要有效用户拥有者；无用户的挂起记录使用 Source.Retry。

TaskPool 的原生控制仍使用独立 `XL6_TaskPoolControlV1`；本批没有把 raw native
Task 的 Data 假装成已验证语言捕获，也没有修改 ThreadLocal 为每作业清空。

## 图准入与两阶段退休

Source、Executor Resource、TaskPool Resource 分别有驻留 domain。家族能力是
具体类型的永久常驻表，不是生成 C 的任意 drop／trace 描述。解析先按已注册表
的**指针身份**确认，再允许 Count／Trace；内容相同的副本也拒绝，BUSY 不读取。
Resource 的源、native、错误账本各自作为真实边上报，native 队列与作业沿原协议
独立解析，不把可运行的 native 子图当叶子。

Prepare 只关闭准入和等待已有活动，不取消作业来制造 READY。Source 的控制
线程暂停而非退出；Restore 可以恢复同一控制线程的回收能力，源准入不重新开放。
所有节点完成 Prepare、全部 Clear 后才进入 Finish。Source.Finish 唤醒并回收
纯机械控制线程；Resource.Finish 消费其 native creator，native 子节点独立 Finish。
检查 pin 保持所有节点分配，允许不同 Clear／Finish／Drop 顺序。

TaskPool 新增 `xl6TaskPoolReleaseClearedOwnerV1` 只用于 whole-graph Finish：
要求 wrapper 已 Claim／Clear、有真实 pin、没有调用或活动，消费原始 creator；
不要求独立 native 子节点已经 Finish。wrapper 本身的 Finish 仍负责 native
creator，不能用此入口代替普通 Quiesce／Destroy。普通未 Clear 调用 checked 拒绝。

图测试使用无在途作业的实际实例；带 callback／capture 的完整模块 owning graph、
失败账本在模块 finalization 中的汇报策略仍需公开类／模块接入时联合验收，不能
用本批的空闲图认证代替。

## 按需部署与验收

核心源不引用任何 native 家族算法。Executor 和 TaskPool 是两个独立 provider：
仅使用 Executor 不链接 TaskPool；仅使用 TaskPool 不链接 detached producer、
Closure、语言 Task frame 或默认 async。API 符号拥有者、部署依赖、拥有域、
Linux、DLL 响应清单和源码构建助手同步登记。

维护入口：`tools/check_stdlib_execution_resource.py --out <新目录> --compiler <cc>`。
可重复 compiler，Linux 可加 `--sanitize`。测试严格使用实际部署计划输出的
native selector 与 provider，未用 release DLL、ALL kernel 或替身算法补缺。

每次原生夹具包含：32 次工作线程最后引用释放（其中 16 次失败，含 NULL 首错）、
16 次持有调用的退休、16 次仍拥有实例的关闭／等待、16 次真实创建关闭竞态、
8 次原生清理拒绝及显式重试、64 个精确图（含 32 个空源）的恢复／任意完成顺序、120 个调用线程
分配预算前缀，以及相同内容能力副本的拒绝。每轮检查实际分配／释放账本。
这不是全部 OS 原语失败、所有工作线程分配前缀或任意并发交错的证明。

五个实际错误实现必须编译后被断言拒绝：丢失无诊断失败、错误接纳家族表副本、
Restore 后控制线程无法恢复、TaskPool 强制依赖子节点先完成、已退出空源永远
无法完成图准备。源码／编译器／日志
和产物都有封印。双系统 GCC／TCC O0／O2、整体 ASan／UBSan 与泄漏检查的实测
结果见外部证据报告；未运行网络通信、扫描或安全性质专项测试。
