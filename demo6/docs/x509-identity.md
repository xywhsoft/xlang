# X.509 名称匹配

名称匹配与签名、有效期、用途、路径及信任判断是不同操作。下面的 API
不会查询 DNS、建立网络连接、装载系统根或自动授信；TLS 必须另做完整验证。

## 公开面

| API | 结果 |
|---|---|
| `x509.matchesDns(pattern, host, patternSize=-1, hostSize=-1)` | 比较 DNS 模式和引用名称，返回 bool |
| `certificate.matchesHost(host, size=-1)` | 在 SAN 的 DNS-ID／IP-ID 中匹配，返回 bool；不分配命中名称 |
| `certificate.matchHost(host, size=-1)` | 返回 `X509GeneralName?`；匹配时为独立拥有副本，不匹配为 null |

匹配 false／null 是普通结果。非法名称、非法前缀长度及分配失败是 checked
错误，不与“不匹配”混淆。三个入口均为 pure＋nonblocking，但不是 no-raise。

`size` 遵循既有字节前缀规则：-1 为完整逻辑长度，非负值取不超过实际长度的
前缀，其他负值为 RangeError。它不是输入合法性的“最大长度”限制；身份
验证通常使用缺省的完整名称，只有调用者明确需要前缀时才传递该参数。
两个输入的 DNS 比较分别使用 patternSize／hostSize。

缺省路径从不使用 strlen。逻辑内容中的 NUL 不会作为 C 终止符静默丢失。
例如完整的 `"::1\0"` 不是合法引用主机；显式选择三个字节才是 `"::1"`。
数字地址只解析文本，不进行解析服务或 socket 操作。名称语法、DNS 模式、
数字地址和 SAN 规则复用 XRT；ASCII A-label 等原生输入要求保持，不擅自
转换 IDNA、不退回 Common Name、不以失败再试其他算法猜测成功。

## 拥有权与生成代码

Certificate 保持不可变，三个参数视图只借用到调用结束。布尔路径直接传
原生 pName=NULL，不创建临时 GeneralName、Buffer、证书副本或动态输入容器。
详细路径只复制命中 GeneralName 的 TLV，并沿用既有类型、叶拥有策略和目录。
释放原证书后，命中对象仍可读取；没有新增平行的 HostMatchResult 类。

适配全部驻留 runtime，IR 精确描述参数、效果、可空结果及拥有者。Cgen 仍只
生成调用、结果接管和清理，不生成名称算法或按函数名修补处理。字符串模式
比较、证书布尔匹配、拥有结果为独立组件；纯 DNS 比较不需要语言证书／名称
拥有对象，布尔证书匹配不引入命中对象组件。原生 identity 模块使用 net 的
地址文本解析支撑，不因此选择 DNS／socket／engine／TLS 后端。

## 原生前置与维护

XRT `af2f24f12` 在 IP 视图转 C 字符串前拒绝 NUL，保留完整长度语义。
两端普通模块化／单头 GCC、TCC 及 Linux ASan／UBSan 共 42 阶段通过。
旧代码按 C 的 sizeof 把终止符计入视图时，准确复现预期的 ABI 断言失败；
没有运行原生安全专项或畸形证书测试。

定点回补见 [x509_identity_span.json](../lib/xrt/backports/x509_identity_span.json)。
只有 X.509 公开注释和 identity 源变更，函数签名、结构体布局、两边时间合同
及所有未选中代码段保持不变。

新增命名空间入口后必须运行 `tools/generate_stdlib_index.ps1`；它更新函数
计数和静态查询索引，Python 同名用途的生成器校验计数并产生相同索引。
本轮完整构建曾由计数静态检查拦下，现已生成 1028 入口；首轮失败记录保留。
原生和驻留检查不代替公开语言、JIT／AOT、精确合同及裁剪的最终验收。
