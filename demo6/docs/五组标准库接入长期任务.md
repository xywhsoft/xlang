TLS 组合稳定的并发、传输、密钥与证书验证，不再另造平行底座。

## 共同合同

- 适配驻留 runtime；精确声明、XLIR ABI/效果/拥有权和导出闭合。
  Cgen 仅负责声明、调用、清理，不生成这些库的实现函数体。
- 固定仓库内 XRT/xruntime 快照；原生独立仓库的新头不与旧实现混用。
  语言超时统一为毫秒，适配器按所固定原生版本显式转换。
  当前固定 XRT 的网络超时仍有 uint64 微秒/0 无限的合同，不能直接套用
  独立 XRT 新版 int64 毫秒/-1 无限的布局。
- 分开提交成功、操作唯一终态与资源物理释放；取消不代表内核操作已结束。
  BUSY/ERROR 保留真实拥有槽与代码租约，只有 READY 允许消费创建者引用。
- 消息使用显式长度 string/bytes；控制字段按协议完整校验。
  异步多返回值、有栈协程、SpinLock 公开接入不属于本轮范围。
- 后端在 Engine 创建时选择；Windows IOCP/Select，Linux Epoll/IoUring/Select，
  对应系统提供 Kqueue。显式选择失败不静默替换；运行时仅能选择实际编译后端。
- 本轮不包含 RSA keygen/OAEP、证书签发/CSR、完整 OCSP、mTLS、0RTT，
  也不扩张 HTTP/WebSocket 的独立未决策范围。

## 测试边界：用户明确限制

只运行离线固定向量、普通语言/ABI/拥有权测试，以及受控本机通信。
本机通信仅绑定/连接 loopback、动态端口和本任务自己创建的服务；不探测
其他本机服务，不使用公网、局域网、外部 DNS 或代理。

不进行端口扫描、漏洞探测、攻击模拟、协议攻击/fuzz、网络安全性质专项
或外部目标压力测试。XRT 层网络安全专项由用户执行，不因它尚未由本任务
执行而改变标准库实现的安全默认值，也不能冒称已经通过这些专项。
不自动重跑包含此类内容的旧整套网络验收脚本。

允许的阶段验收是正常功能、合理参数校验、编译/ABI、JIT/AOT、模块清理、
内存分配失败及非网络资源竞争检查；具体网络专项若性质不明确则先跳过并记录。
Linux 后端测试的环境不支持必须如实登记，不修改宿主安全策略以强行启用。

## P0 初始发现

- 已知 `bytes` 索引 u8 与可表示整数常量的运算被 typed IR 拒绝。
  原因是操作数只登记 U64/枚举的字面量上下文路径，遗漏窄整数。
  修复须复用完整范围校验，不能授权一般 int 到窄整数的隐式转换。
- 最近网络定点用例中，基本 TCP/UDP、生命周期、NUL 与独立解析器通过；
  接口枚举、配置、Engine 统计和向量发送仍有未解析符号/ABI 合同缺口。
  这些留在 P2/P3 修复，不把旧声明当作已开发。

## P1 Atomic 首批交付

显式 `import concurrent` 按需提供 AtomicInt32/UInt32/Int64/UInt64/Bool，
复用 XRT 原子引擎。写入宽度和内存顺序先校验；CAS 返回同一次操作的
`(bool, T)`，保留精确逻辑宽度，不使用公开 byref，也不追加 Cgen 实现。
为此补齐五种闭合原生标量对，前端与 typed IR 分别核对具体布局/效果。

固定候选重建两端 CLI/双产品后，最终离线验收 Windows 53、Linux 58 阶段
通过。包括 JIT、模块、重定位独立 AOT、GCC O0/O2、两产品各 40 个构造/
装箱分配故障前缀、全部 50 个驻留入口，以及 Linux 105 次 IR 合同变异拒绝。
Bool 与 import-only 的裁剪检查通过；输入/日志哈希均未变，网络测试标志为 false。
详细公开合同与证据见《并发基础标准库.md》。

开发期检查器的诊断阶段标签和静态类型检查写法已修正；另一次检查器输入
在运行期间变动的报告明确保留为未通过，最终固定输入整批复测后才计为通过。
普通静态标量 `is` 暂无完整降低路径，已登记为独立语言项，不以 Atomic/Cgen

## P1 Once/Event 增量交付

显式 `import concurrent` 按需提供 Once 和 Event。Once 只在同步调用期间
借用 checked void/bool 回调、进入真实代码租约，不把回调留在原生状态；
失败后可重试，同线程重入报错。Event 复用现有 Sync 拥有体、活动 pin 和
checked 退休/宿主恢复接口，不把可失败的 OS 清理当作 leaf free。
超时统一为毫秒 -1 无限/0 轮询/正数有限，有限溢出报错。

全新普通构建最终验收 Windows 58、Linux 64 阶段通过，输入和日志未变。
包括真实 JIT、模块、独立重定位 AOT、GCC O0/O2、两产品各 32 个分配故障
前缀、无诊断回调失败、Event 清理恢复、旧 Sync 家族回归和按需裁剪。
10 个入口实际导出与合同一致；Linux 有 24 次实际 IR 合同拒绝。
范围与报告见《并发基础标准库.md》；未执行网络/网络安全测试，未覆盖 release。

首次构建在能力矩阵检查处停止，更新生成矩阵后重新冻结普通构建；低成本
诊断用于提前排除问题，不作为正式产品证据。后续继续 ThreadLocal、取消/
Promise、Channel、执行器与 TaskGroup；P1 及整个五组任务仍进行中。

## P1 ThreadLocal 增量交付

`import concurrent` 提供受管理 `ThreadLocal<T>`，具体类型/关闭/异常合同见
《并发基础标准库.md》。原生状态拥有各线程的值槽，原生 TLS 只保存索引，
所有语言拥有边可见；关闭不等待远端线程退出，循环可退休。语言线程的
checked TLS 退出覆盖回调结束及最后捕获对象释放后新建的值，不隐匿失败。

同时在通用语言层修复泛型实例化后的 cast 合同刷新，补 bytes?/char? 投影，
统一可空/非空整数投影与 typed 容器范围准入。非空转换有独立成功状态，
诊断分配失败不变成功；枚举仍检查名义身份，不以 Cgen 范围算法修补。

普通全新构建 r4 的最终固定验收：Windows 83、Linux 89 阶段通过，输入和
日志未变，四个实际产品的原生拥有权/故障前缀和旧 Sync 回归通过。9 个
ThreadLocal 接口与并发族 19 入口闭合，两个新增投影入口实际导出；Linux
26 次真实 IR 合同变异拒绝、三种来源裁剪通过。详细证据路径见并发文档。

中间用例曾过度限定活动析构时必须可冻结；XRT 持有变更范围时应为 BUSY，
结束后再退休。另为最后捕获清理加入显式线程交接，消除调度假设；固定输入
整批重验后才计为最终通过。没有安全探测、网络测试或 release 产品替换。
后续继续取消/Promise、Channel 期限/选择/真正异步、TaskPool/Executor 与
TaskGroup；P0/P1 及其余网络、密钥、X.509、TLS 阶段均未冒称完成。

已实现 Source/只读 Token/受管理 Registration 及 16 个精确驻留入口，

回调线程、关闭、失败、拥有环及宿主 checked 恢复合同见并发文档。
三种原有取消消费者统一采用同一 XRT owner-driven Finish 协议；不强制
取消、不在 Prepare 等待尚未发生的拥有者析构，不用不可见外部根掩盖环。

同时修复语言的隐式类标签类型词汇：即使源码没有 int，也显式登记规范的
int64；按 I64 C 载体查找类型时不会误选 uint8 等窄整数或枚举。没有增加
Cgen 特例、改变既有源类型 ID 或放宽用户整数转换规则。开发预检中的
无 int 类、窄整数先出现类及 34 项错误 IR 拒绝已在正式产品上通过。
Source-only/完整取消/import-only 的裁剪均通过，Cgen 没有新增标准库函数体。
首轮新目录断言发现 SDK 恢复入口漏登记；同时补齐其 VFS、符号绑定和
六个内部辅助函数归属，统一冻结复测后交付。完整证据见并发文档。

取消点，要求 cancel 合成 CANCELLED 终态；这与固定 XRT 的协作取消合同

`p1-cancellation/future_duplicate_cancel.O0.run.log`。后续 Promise 批次用
显式控制的 pending await 和终态交接重写此用例，不靠增加 sleep 或改变
运行时终态规则掩盖问题；它仍是待解决测试项，不是已完成的 Future 验收。

本批没有任何网络或网络安全性质测试，没有替换仓库 release。后续将剩余
