# 本批五项能力实现口径

本文记录本轮已经进入 DEMO6 实现与测试的五项能力。它们属于当前发布候选口径，不再视为下一轮暂缓项。

## 1. 泛型约束系统

泛型参数可以在声明处使用 `is` 约束：

```xlang
func maxValue<T is comparable>(T a, T b) as T
end

class Box<T is cloneable>
end
```

多个约束使用 `and`：

```xlang
func save<T is json and cloneable>(T value) as T
end
```

当前规则：

- 当前内置能力约束固定为 `comparable`、`cloneable`、`json`、`xson`。
- 其他名称只在它解析为已声明 class 时作为继承约束；不存在隐式 `hashable` 兼容名。
- class 继承约束使用同一写法，例如 `T is Entity`。
- 泛型函数和泛型 class 在实例化时执行约束检查。
- 不满足约束时报语义错误，不生成 C 代码。

当前边界：

- 不实现 trait/protocol bound 的方法集合推导。
- 不实现 `where` 写法。
- 约束只用于静态语义检查，不改变运行时类型模型。

## 2. 字段级持久化注解

字段可以使用 `@json(...)`、`@xson(...)`、`@persist(...)` 控制 `derive value/json/xson` 的持久化行为。

```xlang
class Profile
    derive value

    string name @json("user_name") @xson("userName") = ""
    private string token @persist(name="token_value", include) = ""
    string password @persist(skip) = ""
    string note @json(omit=empty) @xson(omit=null) = ""
end
```

规则：

- `@json("name")` 只修改 JSON 字段名。
- `@xson("name")` 只修改 XSON 字段名。
- `@persist(name="name")` 同时作为 JSON/XSON 的默认持久化字段名。
- `skip` 表示不参与对应格式的序列化和反序列化。
- `include` 允许 private 字段参与自动持久化。
- `omit=empty` 表示空字符串、空容器等空值不输出。
- `omit=null` 表示 null 值不输出。
- 格式专属注解优先于 `@persist(...)` 的通用设置。

当前边界：

- 注解只允许写在 class 字段上。
- static 字段不参与实例持久化。
- 未知注解名、冲突字段名和非法参数会报语义错误。

## 3. 泛型 class 迭代协议

泛型 class 可以实现 `__iter__` / `__next__` 并参与 `for in`。

```xlang
class PairBox<T>
    T first
    T second

    func __iter__() as PairIter<T>
        return PairIter::<T>(self.first, self.second)
    end
end

class PairIter<T>
    func __next__() as (bool, T)
    end
end
```

规则：

- `__iter__() as IteratorClass<T>` 返回迭代器实例。
- 迭代器必须提供 `__next__() as (bool, T)`。
- `for value in obj` 的 `value` 类型来自 `__next__` 第二个返回值。
- `for index, value in obj` 的 `index` 固定为 `int`，`value` 类型同上。
- 代码生成会实例化泛型迭代器 class，不允许泄漏未替换的泛型形参。
- 当前泛型 class 构造表达式仍要求先落到显式 typed storage，例如 `PairIter<T> iter = PairIter::<T>(...)` 后再返回。

## 4. native-backed class

`custom` 的 C opaque handle 能力已经融合进 class 基座。推荐新代码使用 native-backed class，而不是把 `custom` 作为独立抽象方向继续扩展。

```xlang
class NativeCounter
    native point handle

    extern "counter_open" create(int seed)
    extern "counter_close" destroy()
    extern "counter_add" func add(int value) as int

    func addTwice(int value) as int
        self.add(value)
        return self.add(value)
    end
end
```

规则：

- `native point handle` 声明底层 C 句柄字段。
- `extern "symbol" create(...)` 调用 C 构造函数并写入 handle。
- `extern "symbol" destroy()` 调用 C 析构函数并传入 handle。
- `extern "symbol" func ...` 调用 C 成员函数，第一个参数由生成器自动传入 handle。
- native-backed class 仍可拥有普通 xlang 字段和普通 xlang 方法。

当前边界：

- native extern 成员必须存在 native handle。
- native handle 生命周期由声明的 create/destroy 显式决定。
- 没有 destroy 时 xlang 不额外释放 C 资源。

## 5. class 成员 C ABI 导出

class 成员函数可以显式导出为 C ABI wrapper：

```xlang
class Point
    int x
    int y

    export "xl_point_move" func move(int dx, int dy) as int
        self.x = self.x + dx
        self.y = self.y + dy
        return self.x + self.y
    end

    export "xl_point_pair" func pair() as (int, int)
        return self.x, self.y
    end
end
```

生成给 C 的头文件形态：

```c
int64_t xl_point_move(XL_Class_Point* self, int64_t dx, int64_t dy);
void xl_point_pair(XL_Class_Point* self, int64_t* out0, int64_t* out1);
```

规则：

- 导出的成员仍是普通 class 方法，可被 xlang 代码通过 `obj.method(...)` 调用。
- C ABI wrapper 第一个参数固定为 class 实例指针。
- 多返回值导出为 `out0`、`out1` 等输出指针参数。
- ABI 元数据 使用 `kind: "class_method"` 并记录 `owner`。
- ABI dump 使用 `export_class_method` 描述成员导出。
- 导出符号在整个模块中必须唯一。

当前边界：

- 当前阶段不支持 static 成员导出为 class method C ABI。
- 当前阶段不支持泛型 class 的成员直接导出 C ABI；需要先实例化或另行设计专用 wrapper。
- `create` / `destroy` 生命周期方法不使用成员导出语法导出。
