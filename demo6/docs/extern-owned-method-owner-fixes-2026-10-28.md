# C 字符串链路：方法约束、owner 回调与嵌套泛型

本轮处理 `review-boundaries-93/report.json` 的 F1–F4，基于主线
`9625fa6a6` 在隔离工作树实现。修复覆盖固定签名的方法引用与其调用边界。
普通 string/bytes、cstring/cbytes 的运行时表示和分配器合同沿用现有实现。

约束检查在语义阶段完成，Lowered XLIR 还会核对选中的原始声明及其具体化链。
显式 `as func(...)` 不会跳过约束。约束不成立的候选不会制造假歧义；真正同级的
重载歧义继续拒绝。异步方法比较 `future<T>` 的逻辑结果层。

private/protected 方法沿用词法访问规则，支持返回逃逸的闭包和默认实参。
它们不会被加入公开动态方法表；IR 同时校验选择证据、访问范围与接收者。
泛型类的词法访问范围按同一声明家族判断，具体接收者类型另行验证。

固定签名可以直接保留 C owner 结果，例如：

```xl
typedef Reader=func() as cstring
Reader callback=instance.Text
string text=callback()       // 直接接收 owner 结果，保持 C 生产者指针
print(text)                 // 原有只读使用路径
```

同样支持 cbytes、可空 owner 结果、类型别名、泛型方法、虚分派及结果积类型。
若目标函数签名要求普通 `string`/`bytes` 返回 ABI，既有结果转换在同一个 typed
调用体内完成：需要转换的叶子复制一次，未转换的 owner 字段直接移动。
积类型在任何可能失败的分配之前先保护所有拥有字段，确保部分转换失败时正确释放。

`Box<K>.Echo<T>` 的具体化键为 `[K,T]`。方法类型参数按声明顺序记录，不能因为
`Reverse<U,V>(V first,U second)` 的参数出现顺序而变为 `[K,V,U]`。
接收者从键的类参数前缀恢复；实例化、直接调用、方法引用和 verifier 使用同一规则。
直接作为参数的方法引用先继承调用目标的具体函数签名，再完成绑定。

需要同时推断两侧泛型的方法组仍须提供足够的具体类型证据，例如声明精确签名的
函数变量，或对全局泛型调用提供显式类型实参。此轮没有扩展 `obj.Method::<T>`
的方法显式类型实参语法。

## 成本与安全边界

这批选择、访问、替换与排序工作均在编译期执行。实例方法仍使用原有的单接收者
闭包和 bool/typed-out 调用入口；返回转换复用该调用体。没有新增字符串来源标签、
读取分支、动态结果装箱、额外接收者捕获或一层新的回调转发。
绑定时仍保留既有的闭包构造和接收者引用管理成本。

指针与分配测试分别验证两条路径：兼容 XRT 的 `@owned string` 保留生产者指针，
调用只计一次生产者分配；任意释放器的 cstring/cbytes 保留原指针并使用既有的一个
owner 记录。精确 owner 签名不会额外复制；普通返回 ABI 的转换会复制，测试明确区分。
这些检查证明相应路径的复制/分配合同，不构成全部扩展库与手写 C 等性能的基准结论。

`@owned string` 的前提是实际兼容 xrtMalloc/xrtFree 的分配。相同 CRT 或编译器
不能替代这项合同。`Future<string>` 的共享结果读取仍按原有规则复制；此轮不改变
Future 的所有权、共享或写入规则。
