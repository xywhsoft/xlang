## 范围

先以《普通扩展库开发优先级_2026-10-12.md》的 P0-P3 共 100 包为改造范围，
再对整个发布目录交叉清点。当前有 214 个 `xlang.package.json` 包清单；
改造前全目录的显式 `takeCstr` 涉及 61 包，`gettext` 改造后为 60 包；
除下列普通包外还有
`aho_corasick`, `bloom`, `dns`, `xhttp`, `xhttp.client`, `xhttp.protocol`,
`xregex`。其中 `dns` 仍属核心占位，其他六包已有实际能力，但交由
专门上下文维护，本文只记录风险，不越界修改。
改造前全目录 XL 文件另有 698 处 `extern ... as string`，包含测试与
占位包，不能将其计作
“已完成扩展库”的所有权审计结论。这是静态入口清点和首个真实编译验证，
不是逐 API 发布验收。

| 路径 | 当前发现 | 处理原则 |
| --- | ---: | --- |
| `__xl_runtime.takeCstr` | 初始 54 包；`gettext` 改造后 53 包 | 原生结果由调用方拥有，现接管后构造普通 `string`；是零拷贝返回的主要候选。逐包确认分配器和释放器。 |
| `extern ... as string` | 初始 147 处，涉及 63 包 | 混有静态常量、借用错误消息、`xrtTemp` 和插件返回值；不能按声明机械接管。须从 C 定义及生命周期合同逐个核实。 |
| 生产代码中的 `.text()` | 15 处，其中 3 处是 UI 文本方法而非 Buffer 转换 | 压缩、归档、串口、共享内存等结果本质上是任意字节；嵌入 NUL 和长度语义不能因性能优化丢失。 |

## 已验证的编译器边界

源码版编译器已支持普通同步函数以 `cstring.take(pointer, releaser)`
接管 C 分配，调用方静态读取可共享 owner，避免复制正文。
但当前 `xl6_sem_c_owned.c` 明确禁止 `export func ... as cstring`。
用 `md4c.html` 的实际包导出试编译，得到：

```text
[sem] C result markers require a synchronous language function with an explicit take adapter
```

因此只把包的公开 `as string` 改为 `as cstring` 会直接破坏导入；
保留 `as string` 则仍需在公开返回边界实体化普通字符串。
该实验性包修改已经撤销，未留下不兼容 API。
当前发布目录的 `xl.exe` 也早于源码版 `cstring`，不能作为新语法门禁。

`md4c` 的三个 HTML 结果是 `xrtBufferTake` 产生的独立 XRT 分配，
可由 `xrtFree` 释放；`version` 和 `last_error` 则是借用字符串，
不能接管。`argon2` 的一部分结果来自 `xrtTemp`，同样不能交给
`cstring.take` 释放。这个差异说明改造必须按 C 端所有权，而非按
XLang 的返回类型做全局替换。

## 后续实施条件

1. 先明确导出 ABI：保留对 C 可用的普通 `string` 导出函数，编译器可为
   同模块静态调用生成私有拥有型结果路径；或者正式定义可从 C 安全使用、
   可释放的拥有型导出 ABI。不能仅删除语义检查。
2. 用 `md4c` 验证 import、XAPI、JIT、AOT、C 调用以及成功/失败/异常
   释放，再迁移其余确认由 XRT 分配的 `takeCstr` 入口。
3. 对 147 个 `extern ... as string` 从 C 端分类：静态/借用/临时保持复制；
   独立拥有结果才接管。插件 DLL 未提供稳定释放器时不可猜测。
4. Buffer 转文本先确认 UTF-8、NUL 和长度合同；压缩、归档等二进制
   主 API 继续返回 Buffer。仅文本专用接口在证明等价后考虑所有权转移。

在导出边界未打通前，包侧已有的 `xrtBufferTake` 是有效的 C 内部优化，
但不能宣称 XLang 公开返回已经零拷贝。不要为了消除一次复制而引入
可悬空指针、双重释放或改变 `string` 公开语义。

`gettext` 是无需修改编译器的例外：译文本来已保存在 XRT 目录里。
新增的 C 借用入口直接返回该地址或调用方原文；XLang 的 `extern as string`
只在同步调用点复制一次。原有 C 拥有型入口继续单独分配并由调用方释放。
