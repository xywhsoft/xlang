## 已验证的编译器边界

源码版编译器已支持普通同步函数以 `cstring.take(pointer, releaser)`
接管 C 分配，调用方静态读取可共享 owner，避免复制正文。
但当前 `xl6_sem_c_owned.c` 明确禁止 `export func ... as cstring`。
用 `md4c.html` 的实际包导出试编译，得到：

```text
[sem] C result markers require a synchronous language function with an explicit take adapter
```

因此只把包的公开 `as string` 改为 `as cstring` 会直接破坏导入；
这只约束 `cstring` marker 的公开签名，不等于 `takeCstr` 会复制。
对 XRT 分配的 NUL 结尾文本，当前 `takeCstr` 生成 `{pointer, strlen(pointer)}`，
普通 `string` 返回可直接转移该分配，失败清理也调用 `xrtFree`。
该实验性包修改已经撤销，未留下不兼容 API。
当前发布目录的 `xl.exe` 也早于源码版 `cstring`，不能作为新语法门禁。

`md4c` 的三个 HTML 结果是 `xrtBufferTake` 产生的独立 XRT 分配，
可由 `xrtFree` 释放；`version` 和 `last_error` 则是借用字符串，
不能接管。`argon2` 的一部分结果来自 `xrtTemp`，同样不能交给
`cstring.take` 释放。这个差异说明改造必须按 C 端所有权，而非按
XLang 的返回类型做全局替换。

## 后续实施条件

1. 先明确导出 ABI：保留对 C 可用的普通 `string` 导出函数，编译器可为
   同模块静态调用生成私有拥有型结果路径；或者正式定义可从 C 安全使用、
   可释放的拥有型导出 ABI。不能仅删除语义检查。
2. 对已有 `takeCstr` 入口只核实原生所有权、XRT 分配器、NUL 合同和失败释放；
   不为了新语法重写已零拷贝的入口。`md4c` 的源码版独立 EXE 已能运行，
   但全包发布验收仍按包级门禁进行。
3. 对初始 147 个 `extern ... as string` 从 C 端分类：静态/借用/临时保持复制；
   独立拥有结果才接管。插件 DLL 未提供稳定释放器时不可猜测。
4. Buffer 转文本先确认 UTF-8、NUL 和长度合同；压缩、归档等二进制
   主 API 继续返回 Buffer。仅文本专用接口在证明等价后考虑所有权转移。

`takeCstr` 的公开 `string` 返回当前确实可以直接接管 XRT 分配；
`cstring.take` 负责不同 releaser 的拥有型结果与跨静态调用共享 owner，
二者不能混为一谈。不要为了消除一次复制而引入
可悬空指针、双重释放或改变 `string` 公开语义。

## 已落地：BLAKE3 可变长文本结果

原 C 接口的 hex 字符串借用 XRT 临时区，面向 C 的生命周期合同保持不变。
XLang 的一次性普通/keyed/KDF、文件和流式摘要改走新增 `_owned` 原生入口：
摘要仍在临时区计算，但 hex 直接写入一份 XRT 堆分配，`takeCstr` 接管，
不再为 `extern as string` 复制整个可变长 XOF 文本。失败返回 NULL，
原生边界和 XLang 包装保留原来的错误类别。

当前源码版驱动的向量 JIT、独立 EXE、GCC 原生边界和分配故障注入均通过；
保留的生成 C 显示新结果只经过 `xl6_xrt_take_cstr`，`from_cstr` 仅用于
版本号和错误消息等借用文本。完整 `check_extlib_blake3.ps1` 在测试前被
既有 `third_party/blake3_impl.h` 与 vendor 清单 SHA256 不符挡住，
本轮未改动或重锁该第三方文件，因此不宣称整包门禁通过。
发布目录现有 `xl.exe` 还不认识包中此前已有的 `cbytes` 声明，
故此轮 XLang 验证使用当前源码驱动，不能把旧二进制的拒绝误记为本轮回归。

## 已核对但不机械改写

- `sqlite`：列文本、列名和错误消息从 SQLite 的借用内存复制一次到
  XRT 所有权，再由 `takeCstr` 直接接管。改为 `extern as string` 借用
  仍须为稳定返回复制一次；原 C 借用接口还承诺 XRT 临时区生命周期。
- `com`：原生 `IDispatch` 文本直接转换进对象自有 XRT 缓冲，原
  `extern as string` 随后又复制整个 UTF-8 结果。现新增 C 拥有型
  `x_com_get_text_owned`，XLang 直接 `takeCstr`；原 C 借用入口不变。
  长文本 6006 字节、空文本、NUL 拒绝、重复读取和 C/XLang 双语
  `-SkipAot` 门禁通过；当前源码版真实服务器脚本运行退出 3，未计作
  AOT 发布验收。
- `uia`：BSTR 转换后的元素文本与可增长 JSON 缓冲原本由桥接层持有，
  XLang 的 `extern as string` 又复制一次；现在新增对应的 `_owned`
  C 返回入口，从缓存直接移交 XRT 分配给 `takeCstr`。原 C 借用入口
  保持不变；空事件结果仅分配一个短字符串，静态版本号、错误文本和
  固定短矩形 JSON 不改。C 严格构建、XLang 包内测试、C/XLang 范例和
  核心 AOT 的 `check.ps1 -StrictC` 通过，覆盖 70,002 字节 JSON
  原指针移交、缓存重用、长文本与失败路径。
- `sha3`：SHAKE 可变长 XOF 和流式摘要的 hex 原本借用 XRT 临时区，
  随后在 `extern as string` 边界复制。现为一次性 SHA3/SHAKE、流式
  digestHex 提供独立 `_owned` 输出，摘要和 hex 落在同一块不重叠
  XRT 分配，语言侧直接接管；原 C 借用入口不变。64 KiB XOF、零长度、
  流式重复、错误边界和 Windows `-SkipAot` 包门禁通过。完整 AOT
  仍因既有 `xl6NativeHandleTraceLeaf` 链接阻断，未签收。
- `md4c`、`ini`、`json5`、`shellwords` 等已有 `takeCstr` 路径：
  生成 C 已是接管原指针，不应为了追求新 marker 引入另一层拷贝。
- `blake2` 和 `argon2`：当前临时区结果会在 `extern as string` 边界
  再复制，但输出有固定小上限（BLAKE2 hex 最多 128 字符，Argon2 原始
  hex 最多 512 字符），需权衡新增多组 C ABI 与故障清理代码的成本；
  暂不把它们误报为与 BLAKE3 可变长 XOF 同级的热点。
- `volc.core`：离线签名结果已由 `x_volc_core_take_result` 直接移交；
  五个在线 `request*` 返回目前还声明 `extern as string`，会复制可能
  较大的响应体。虽然 C 端已有可取走的线程结果槽，XLang 包导入仍被
  `xhttp` 依赖链阻断：当前 `release/xl.exe check
  dev/extlib_blockers/volc_core_import_chain.xl` 首先在 `xhttp.body` 和
  `xhttp.client` 报未知 `cstring` 类型；旧记录中的 `xhttp.multipart`
  `appendBytes` 故障不是当前首个报错。无法按任务约束完成包侧实跑验收；本轮
  只登记候选，不在阻断状态下修改公开返回 ABI。HTTP 响应还需要明确
  含 NUL 字节的语义，不能默认为所有响应都是 C 字符串。
- `bz2`、`brotli`、`gzip`、`lz4`、`lzma`、`miniz`、`snappy`、`zstd`
  的解压文本入口，以及 `zip`、`tar` 的 `readText`：来源可能包含内嵌
  NUL，现有 `Buffer.text()` 按精确长度构造语言字符串。不能直接换为
  以 NUL 终止的 `takeCstr`；先建立带长度、可移交所有权的文本边界，
  再考虑消除 Buffer 到 string 的复制。

`gettext` 是无需修改编译器的例外：译文本来已保存在 XRT 目录里。
新增的 C 借用入口直接返回该地址或调用方原文；XLang 的 `extern as string`
只在同步调用点复制一次。原有 C 拥有型入口继续单独分配并由调用方释放。
