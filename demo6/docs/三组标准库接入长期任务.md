# 三组标准库接入长期任务

立项：2026-10-02。状态：进行中；53 是原生模块数，不是 53 个新命名空间。

用户已批准此前评估方案并要求补全及测试。复用 XRT 算法和 xruntime typed
对象生命周期；不把原生内部实现逐个包装为公开类，不在 Cgen 添加库函数体。
每批冻结输入、集中检测、集中修复，再统一验收并提交。专项通过不代表全仓 RC0。

## 批次与验收

1. 文本根基：清理 raw pointer → strlen 的拥有结果；char/bytes、size、UTF-8、数字与编码。
2. Pattern/Regex：编译对象、独立捕获、查找/替换/拆分/集合与资源预算。
3. 系统：绝对/本地/单调时间，文本与 DST；保留 env，封闭 signal 交付线程。
4. 进程：direct/shell、owned streams、完整结果、期限/取消、pipeline、Future、PTY。
5. 容器：typed 基础集合增补、Buffer codecs、Queue/Stack/OrderedMap/SlotMap。
6. 总验收：跨平台严格 C、JIT/AOT、错误/寿命/实际 OOM、生成代码声明化及按需闭包。

每项完成标准：公开文档 + 声明/ABI/效果/所有权 + 运行/负例/裁剪测试。
原生 C 子模块只作为内部依赖的项目，以公共功能覆盖及正确裁剪为验收标准。
CRT 全局 exit、通用非字符串 dict 键、对象池与未批准扩展不计入此次完成范围。

### B18a：时间核心的声明化标量接入

本批是 time 的第一段，不是 time/time_local/time_text 完成。补充和迁移：

- `time.fromDate(year, month, day)`、`time.fromTime(hour, minute, second,
  microsecond=0)`、`time.fromDateTime(year, month, day, hour=0, minute=0,
  second=0, microsecond=0, offset=0)`。所有整数先检查再转 C int，月份
  4294967297 等不再绕回合法值。offset 为 UTC 以东秒数，不是当地时区。

  溢出，`time.toUnix()` / `time.toUnixMs()` 对负数向负无穷取整。

## B22b：进程管道关闭 / I/O 安全持有（2026-10-03）

不是仅凭静态审计判定：固定屏障暂停在原生 ReadFile/WriteFile/read/send
边界，另线程调用真实 xrtProcessClose。旧 Windows 读写报失效句柄；
旧 Linux 精确复用原 fd 后，stdout/stderr 读到无关管道的 F，stdin
写入无关 socket。before2 双端证据保留且明确失败，不计通过。

Windows/POSIX 原生 read/write 改为在 Process 槽位锁下取得不可继承的
私有 OS 副本，在锁外执行阻塞 I/O，所有返回路径释放。没有增加
公开 native API、xlang 函数、语言引用或 Cgen 库算法，也没有 XRT
payload 分配。原生读写失败先保存 OS 错误，释放不能覆盖首错；IO
成功/EOF 后释放失败报告 CLOSE，数据可能已经读写，不能盲目重试。
Windows 复制失败不信任 output 参数，EOF 不信任失败后的 byte count；
POSIX 保留 EINTR 重试与 terminal EIO→EOF，不重试 close(EINTR)。

关闭合同明确：Close 退役槽位并拒绝后续非零操作，不取消、等待或关闭
已经取得私有副本的阻塞调用；stdin 副本退役之前子进程可能未见 EOF。
单流单读者 / 单写者及调用者保持有效 Process ref 的约束不变。
借用 StreamNative 数值仍不能充当并发安全持有权，不用于语言流适配。
每次非零 IO 增加 duplicate/close OS 成本，不宣称零开销；不持有全局
Process 锁跨阻塞 IO，避免 stdout 排空与 stdin 写入互相阻塞。

### B26：typed Process Future 与通用协作取消（2026-10-03）

`Process.waitAsync()` 返回 `future<ProcessExitStatus>`；非零退出、重复等待、
独立结果、receiver 提前释放及同进程多等待者均有正式夹具。私有

factory 非阻塞但可失败；XLIR 检查 Future carrier、元素、空值/所有权、

公共合同见《进程标准库异步等待.md》。

首轮正确取消夹具复现 15 秒超时：cancel 后等待仍依赖共享进程终态。
修复落在通用 Future/continuation 层，而非为标准库绕过取消或改变断言：

- XRT 新增 ProducerBindTakeV2 的显式 cooperative capability，仍是同一
  真实 producer 节点，不新增 Watch/隐藏引用/图边。持真实引用后在本次
  Future 锁/mutation 外交付首个成功显式 cancel；原 V1 policy 与图准入
  不变，Retain 拒绝不请求 token，重复请求不重复交付。
- frame producer 保存 durable 请求，在活动前驱/私有后继交接期间也
