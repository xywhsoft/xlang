# XLIR 原生发送与 Accept 拥有链

本批补齐 TCP 发送任务和 Accept 两阶段跨 Worker 任务的物理引用；不把
局部任务 Trace 成功解释为整个原生对象拥有图完整，也不切换默认 Cgen。

## 发送链

Copy、Take、Ref、Refs、File 共用一种拥有节点身份。资源引用与调度器引用
分别计数；任务内部完成或丢弃资源后，节点与 Stream 仍由调度器保护，直到
Drop。拒绝提交只在本地回滚，不接管调用者的 Take/Ref 数据；接管成功但
未运行的任务仍须丢弃资源、归还队列预算并完成唯一一次 Drop。

未知外部释放回调保持不透明，Trace 在报告任何边之前拒绝接纳。缓冲视图、
Refs 元素及完整 payload 图仍须后续补齐，不能用任务计数代替这些边。

## Accept 链

分发与返回任务共用真实引用计数和规范 Ops。返回 Listener Worker 前独立
持有一次引用，因此返回任务可以先于分发回调结束，不会提前回收上下文。
上下文最后释放 Listener 引用，覆盖 Listener 创建者已经销毁的顺序。

运行中阶段和未适配的 Error 拒绝图接纳；稳定阶段报告 Listener 与仍由任务
拥有的 Stream 创建者引用。接受、拒绝、跳过分发、跳过返回和队列拒绝分别
验证引用转移，不依赖 Cgen 回溯语义或特判补丁。

## 证据与未完成项

原生持久测试为 tests/network/test_net_transport_jobs.c，由单头测试包装器
引入。它检查实际私有队列与返回槽，刻意控制跨线程顺序，注入真实分配失败，
并要求精确内存配平。它不是模块化链接证明，也不证明自然关闭路径必然跳过
任务；模块化公共行为由现有 TCP/File/Listener 测试独立覆盖。

验证按冻结源码上的专项矩阵、内存检查、一次扩大回归和七组 XLIR planner
进行。build/tmp 下每次尝试单独保存，不覆盖失败，也不把原生专项通过算作
语言集成通过。受保护的发布文件、生产头、所有权 planner 和完整图拒绝条件
保持不变。

扩大验证期间发现旧 Engine/Port planner 测试存在两次快照间的观察空隙：先前
检查成功不保证 Worker 在创建计划时仍停驻。诊断在同一次创建快照中观察到
Engine 运行中、Worker 未停驻而 Count 拒绝，且没有发布计划。测试只对解析器
在该快照中记录的规范 Engine Count 拒绝进行有界重试；未知适配器、错误策略
和其他图错误仍直接失败。该修复不修改生产 planner 或运行时代码；原始失败、
诊断以及修复后的单项复测分别保存。

完整 UDP/Dial/Future/TLS/payload 拥有图、回调收集适配、混合生命周期、DLL
卸载、语言/FFI 集成与默认后端评估仍未完成。
