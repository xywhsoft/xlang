# 扩展库现状复核：当前交付能力与剩余风险

## 结论

扩展库已经有较宽的真实实现基础，但实现、语言接入、测试和对外交付并未同步完成。
现在的主要矛盾不是包数量不够，而是已有实现尚未形成稳定、可重复验收的发布集合。

- 活动包仍为 **225 个，其中公共包 218 个**。相对 9 月 5 日，包集合未增加；近期进展主要在包内部。
- 有范围明确的专项记录、且本轮所选入口通过的基础库为 **17 个**。这不等于 17 个库的所有 API、平台和性能都已达到生产级。
- 本轮 **56 个 Windows JIT 用例：31 通过、25 失败、0 超时**，涉及 55 个公共包。
- 其中原来的同范围 50 项仍为 31 通过、19 失败；另外补测的 6 个历史重点库入口全部失败。不能把扩大范围后的数量当作 6 项新回归。
- 不能继续使用“116 个库已压实”的说法。116 是集中测试登记数，不是当前通过数或发布准入数。

本轮只进行复核、测试和报告整理，没有修改扩展库/编译器实现，没有升级 XRT，
没有替换正式发布程序，也没有发布官网。CSV 工作区中尚未完成的修改被如实计入现状。

## 近期进展与能力分层

### 有专项证据的 17 个基础库

`aho_corasick`、`argon2`、`bloom`、`blake2`、`blake3`、`sqlite`、`xxhash`、
`crc32`、`md5`、`murmur3`、`sha3`、`siphash`、`mqtt`、`gzip`、`brotli`、`bz2`、`xregex`。

近期工作已经从基础调用，推进到物理 ABI、所有权、错误传播、进度回调、取消、
分配失败、流式处理、文件事务、C/XL 同输出范例及维护型官网正文。
各包既有专项的平台和边界范围不同，本轮没有重新执行这些库的全部专项。

其中 xregex 最近的专项记录包括 Windows 37 项检查、49 个实际生成原型、
Windows/Linux 各 169 个分配失败点，以及 Linux 独立 C sanitizer、双语输出和页面范例。
本轮另外复跑其综合和生命周期两个 JIT 用例，均通过。详见
[xregex 交付收口](扩展库xregex交付收口_2026-09-27.md)。

MQTT 的已验证范围是 3.1.1 QoS 0/1 报文、TCP 逐帧传输和一次性握手，
不是带自动心跳、重连、持久会话和 QoS 交付保证的完整客户端或 broker。
“已压实”必须同时带上这类范围说明。

## 本轮实际失败

55 个受测公共包中，30 个在所测范围通过、25 个失败，另外 163 个公共包本轮未选择。
xregex 有两个入口，所以包数与用例数不同。未选择不等于失败，通过不等于发布准入。

| 类别 | 包 | 当前观察 |
| --- | --- | --- |
| 原生声明不一致，18 包 | csv、onnxruntime、rapidocr、xssh、xhttp.client、barcode、color、graph、json.patch、semver、sitemap、slugify、units、lz4、lzma、miniz、snappy、zstd | 真实 C 定义与生成原型冲突；client 的具体冲突来自 xhttp.protocol 析构返回值 |
| 缺失运行时符号，3 包 | cli、xmail、bson | 分别缺 `xl6_xrt_os_args`、`xl6ExtlibTlsLeaseRelease`、`xl6_xrt_time_from_unix` |
| 错误/类型合同，3 包 | xhttp、srt、statistics | URL 用例错误类型不匹配；后两者抛 TypeError，不能不经定位就归为同一根因 |
| 编译器控制流，1 包 | xhttp.body_file | XLIR 非空返回函数仍有可达的未终结块 b439 |

原来的 50 个入口通过/失败状态没有变化，但 CSV 的失败阶段已经变化：从先前的错误分类
不一致，变成当前 C/XL 声明未同步导致无法编译。因此同一个失败数量不代表内部问题未变。

### CSV 是明确的进行中状态

当前 C 层 `xcsv_reader_count` 返回 `int64`，`xcsv_reader_field` 的索引也是 `int64`；
语言层仍把返回值和参数声明为 `c_int`，见
[csv_native.c](../release/extlibs/csv/csv_native.c:210) 与 [csv.xl](../release/extlibs/csv/src/csv.xl:30)。

本轮用 GCC `-O2 -Wall -Wextra -Werror` 重新编译并执行了 6 组 C 回归：
行数上限后的正常 EOF、单空字段往返、输入/结果生命周期、格式错误分类、关闭一次、嵌入 NUL。
均通过。它们不能替代语言绑定、OOM、短读短写、文件事务、C/XL 范例和文档的完整验收。
CSV 应标为“C 层部分修复，整包收口未完成”，不宜对外承诺当前可用。

### 当前构建的交付卫生

56 个受测入口的 stderr 都出现 `probe new AST function ...` 调试输出。
本轮没有在当前 `src` 文本中定位同样的完整字符串，不能直接归责某段现行源码；
应核对发布构建来源并去除非预期诊断。退出码通过也不代表 stderr 干净。

## 不能只修编译错误的边界

以下是本轮重新核对源码所得，不冒充已经运行的破坏性测试：

1. **压缩字符串字节数错误。** LZ4、LZMA、miniz、Snappy 的一次性/流式字符串入口
   使用 `string.len(text)` 传给 C 字节长度参数。当前 `string.len` 是 codepoint 数，
   非 ASCII 输入会截短。见 [lz4.xl](../release/extlibs/lz4/src/lz4.xl:71)、
   [lzma.xl](../release/extlibs/lzma/src/lzma.xl:71)、
   [miniz.xl](../release/extlibs/miniz/src/miniz.xl:71)、
   [snappy.xl](../release/extlibs/snappy/src/snappy.xl:57)。这些入口目前先被 ABI 阻断；
   后续必须同时补中文、组合字符、Buffer、NUL 和分块往返，而非仅修改函数原型。
2. **Memcached 不完整的传输合同。** [set/get](../release/extlibs/memcached/src/memcached.xl:78)
   用文本长度填协议字节数，每次只 recv 一次；分段、合并、长响应未处理，未命中与空值都返回空串。
   当前通过的是报文辅助测试，不能代表完整网络客户端可用。
3. **Agent 工作区判断不构成严格边界。** [Resolve](../release/extlibs/xbot.agent/src/agent.xl:131)
   只比较文本前缀，没有路径分量边界；相邻目录名可满足前缀条件。`writable` 参数未消费。
   还需明确路径别名/符号链接规则，不能把此函数当作沙箱保证。
4. **Agent 资源策略没有完整执行。** [fs_read](../release/extlibs/xbot.agent/src/agent.xl:356)
   先全量读取再按字符截断，不是真正的字节限额；start_line/end_line/recursive 和超时字段
   没有全部进入行为，Trace 直接拼接 JSON。配置字段存在不等于策略已生效。
5. **共享字符串缓冲。** color、semver、units、Memcached 使用静态可变返回缓冲；
   下一次调用、重入和多线程需分别验证。应统一所有权，不通过复制更多固定缓冲掩盖问题。
6. **图算法的内存和复杂度。** [XGraph](../release/extlibs/graph/graph_native.c:43)
   包含固定 4096 节点/32768 边数组，多处在栈上分配；x64 约 544 KiB，部分遍历反复扫描全边。
   应使用按需堆存储与邻接结构，并补规模、OOM 和算法正确性测试。

## 建议的收口顺序

1. **统一 ABI 和宿主符号合同。** 先打通上述 18 个原型问题及 3 个缺符号；以真实生成声明
   与公共 C 头/实现共同编译作门禁。准确处理 c_int、bool、固定宽度整数、size_t、const、
   析构返回和所有权，不关闭类型检查，不加旧接口回退。Windows LLP64 和 Linux LP64 都检查。
2. **关闭进行中的 CSV 整包修改，补齐六个历史重点包。** 复用 gzip/Brotli/BZ2 的测试经验，
   覆盖 Unicode、空输入、分块、资源上限、回调取消、文件不被失败操作截断及分配失败。
3. **把 17 个有专项证据的库形成统一发布批次。** 固定同一组 CLI/DLL/XRT/SDK 输入，
   执行 C/XL、JIT/AOT、平台和范例测试；不能把不同构建、不同时段的通过项拼成总通过率。
4. **优先接通高价值已有能力。** CSV/CLI/常用工具、HTTP、邮件、SSH、Agent 文件工具优先；
   网络必须有本地可重复端点、分段、断连、超时、取消和生命周期用例。
5. **对已有 AI/GUI 后端做真实功能验收。** 固定小模型、固定图像/输出、真实事件及反复创建销毁；
   已实现能力不计入占位库新增 10000 行预算，不能因总代码多直接暂缓。
6. **官网跟随验收同步。** 34 个缺页公共包、31 个遗留 generated 页逐项处理；说明当前 API、
   依赖、范围和最后受测版本。只有辅助函数的库必须明确标注，不使用产品全名暗示完整后端。

尚未逐项完成源码成本估算的包继续保持“待审查”。只有真正的占位库，在明确缺失能力、
估计新增代码超过 10000 行之后，才进入暂缓候选。现在没有可靠依据给全生态报一个完成百分比。
