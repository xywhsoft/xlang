# DEMO6 文档状态矩阵

本文用于给 `demo6/docs` 下每份文档标明当前身份、使用方式和维护触发条件。它不新增语言功能，只作为文档体系的状态总表。

## 使用原则

- 当前权威设计文档可以作为 DEMO6 语言、ABI、标准库、扩展库和运行时设计来源。
- 当前工程与质量文档用于判断守门、测试、工作区和文档维护口径。
- 历史任务单只保留决策来源和阶段快照；如果与当前权威设计、当前代码或 cgenrule 冲突，以当前口径为准。
- 明确写为“暂缓能力”“后续设计议题”“非阻断增强”的内容，不视为当前实现缺口。

## 冲突处理顺序

当文档、代码和规则表出现口径不一致时，按以下顺序处理：

1. 当前代码、主回归测试、RC0 守门脚本和 `demo6/cgenrule` 中的已核验生成规则。
2. 本目录中标记为“当前权威设计”的文档。
3. 本目录中标记为“当前工程与质量口径”的文档。
4. 历史任务单和阶段性开发记录。
5. `demo3`、`demo4`、`demo5`、`dev` 等历史目录中的材料。

历史目录只能作为迁移参考，不能自动成为 DEMO6 设计来源。

## 代码生成规则文档

代码生成规则不在 `demo6/docs` 内维护，统一进入 `demo6/cgenrule`：

- `../cgenrule/README.md` 是 cgenrule 总入口。
- `../cgenrule/01_入口与声明规则.md` 到 `../cgenrule/33_P2_DLL_API动态执行细则.md` 是规则细则。
- `../cgenrule/35_主干P0规则验证矩阵.md` 到 `../cgenrule/42_P2_CLI_DLL验证矩阵.md` 是验证矩阵。
- `../cgenrule/43_文档整理收口.md` 和 `../cgenrule/44_文档整理验收报告.md` 是 cgenrule 文档收口状态。

修改代码生成行为时，不能只改 `demo6/docs`，必须同步修改对应 `CGEN-*` 规则和验证矩阵。
