# SlotMap 原生拥有权与实例键

SlotMap 原生底座复用 XRT 的槽表、空闲链和代际算法，接通精确 typed
元素、拥有型读取、受管理实例键及分阶段退役。原生公开查询将正常缺失
与 checked 失败分开，生成代码不承担槽表算法。双端原生专项已通过。
语言 `SlotMap<T>` 声明、键值投影和统一 IR 接线仍待完成，slot_map
模块不因此标为全部接入。

## 实例键与值语义

私有 `XL6_SlotMapKeyV1` 保存独立实例记录和 XRT 代际槽标识。复制和
移动由固定驻留 `xrttype` 声明；复制仅增加记录引用，不分配内容，不
借入容器。记录没有容器、元素或生成模块的拥有边，键保留期间容器仍能
释放。记录不能复用，因此旧键不会因容器地址重用而命中新实例。

删除、clear 和槽位复用沿用 XRT 代际规则；耗尽代际的槽隔离，不循环
回旧代际。零键、旧键和其他实例的键查询为正常缺失，不把普通缺失变成
异常。键不是可持久化的进程独立 ID，也不公开实例地址或裸 `xslot`。

## 完整值域与原生生命周期

构造消费空 Array 值域见证，捕获完整逻辑准入和物理布局，并取得独立
驻留元数据引用。槽表存储非空拥有型分配；非空的是存储地址，不是语言
元素的存在性，可空元素仍由自己的物理描述符表达。

标量复制、精确 NUL 文本、引用与 Future 复用既有 typed 描述符。
读取返回独立结果；插入和替换先验证准入、准备副本，再发布。
失败复制即使已取得部分资源也撤回结果，保留首错；正常成功与没有诊断
对象的失败均有 checked 布尔状态。已有标量槽读取与键复制零分配。

XRT slot_map 以指针保存元素，因此本层每个元素有一个独立存储分配；
它不是连续元素布局，也不在本轮擅自增加对象池。每个实例额外有一个
很小的身份记录，键复制不会复制元素或保留整个容器。

拥有图逐一枚举重复和自引用边，Future 访问其真实控制块，并要求独立
授权驻留 TraceSlot。退役先在冻结下分离存储，再在冻结外清理；边界
进入失败可重试。clear、remove、替换在旧元素清理前提交，清理错误
可能意味着修改已经发生，调用方不能把失败一律当作未提交而重复操作。

## 验收范围与下一步

严格 O0／O2 原生专项覆盖实例隔离、代际复用与耗尽、精确值域、NUL
文本、独立结果、部分复制失败、首错、重入清理及完整分配失败前缀。
实际编译的错误实现覆盖省略实例认证、接纳旧键、省略读取复制及泄漏
失败输出。代际耗尽使用实际供应记录白盒 seam，不声称进行了数十亿次
循环。所选 Linux 原生闭包另执行 ASan／UBSan。

Windows／Linux 各通过 56 个原生阶段、14 组完整故障前缀（32 次运行）
及 4 个实际编译的错误实现拒绝。Linux O0／O2 原生闭包通过 ASan／UBSan；
这不表示完整编译器或供应库均接受了 sanitizer 验收。

完整目录确认 257 个组件、1368 个实际导出、66049 个依赖对和 13 个
损坏目录拒绝，覆盖增加第五个组件位图字后的边界。相邻 Dict 真实产品
回归双端各 225 阶段、480 项损坏 IR 合同拒绝及 666 次完整故障前缀
运行通过；三个产品计划均未选择 SlotMap 源文件或 XRT slot_map 模块。
Windows／Linux 重新构建源码驱动，分别编译 296／295 个源对象。

`E:/xlang-validation/stdlib53-b205-verify-win-dev2` 和
`/var/tmp/xlang-stdlib53-b205-verify-linux-dev2`。生产代码和最新测试
均从所选 index 冻结；文档收尾后另核对编译输入、实际产物和最终所选
源码，不把工作区探针视为最终源码证书。不改动 XRT 供应库，也不提升
发布 DLL／SO、TCC 或 VFS 产物。本专项不表示语言 SlotMap 或三组总门完成。
