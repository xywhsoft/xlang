# 编译阶段失败的定位与产物保护

本批只增强公共编译 API 的失败诊断，并验收已有产物保护合同。
不改变语言语义、IR 验证规则、Cgen 生成策略或运行时 ABI。

## 行为

底层已有源诊断时，继续报告原文件、行列和诊断内容；不使用通用标签替换它。
底层返回失败却没有诊断时，公共 API 现在报告源路径及实际失败阶段：

- `ir-lower`：typed IR 降低失败。
- `ir-verify`：降低后的 IR 不满足验证合同。
- `cgen-verify`：IR 不能进入 C 生成。
- `cgen-emit`：C 生成失败。

文件输出与内存输出／模块生成使用相同分类。缓冲创建、写入和复制失败仍保持
独立错误，不混成语义失败。失败不会自动重试，也不绕过验证器。

已有输出层先在内存生成，再由 XRT 原子写入；本批不重新实现该机制。
验证覆盖生成器已经写入部分 C 后返回失败的情况，旧目标文件仍应逐字节保留。
重新载入合法源码后，同一上下文必须恢复正常生成并清除上次错误。

## 验收

离线检查器为 `tools/check_compiler_stage_diagnostics.py`，使用完整源码构建清单
中的实际编译器对象，只有测试程序通过链接器 `--wrap` 对四个依赖返回受控失败。
产品源码没有故障开关、替代实现或自动重试。

每个平台、每个测试程序优化级别 O0／O2，执行 10 项公共 API 检查：四个无诊断
阶段和一个已有精确诊断场景，各走文件／模块两个入口。检查失败标签、原始诊断、
旧文件内容及上下文恢复。编译器本身使用源码驱动的 O0 对象；不据此声称完整编译器
已通过 O2 构建验收。

证据根目录：`F:/xlang-validation/five-groups-20261020/p0-stage-diagnostics/`。

| 范围 | Windows | Linux |
|---|---|---|
| 实际源码构建 | source-win-r1，652 单元 | source-linux-r1，651 单元 |
| 阶段／恢复检查 | check-win-r2，O0／O2 各 10 项 | check-linux-r1，O0／O2 各 10 项 |
| Socket／标量组合／旧 Atomic 回归 | language-win-r1，65 阶段 | language-linux-r1，65 阶段 |

回归每端包含 5 个精确拒绝、6 个独立 AOT 及导入检查、JIT／模块运行和严格 C
O0／O2 编译。IR 合同测试每个优化级别检查 174 个损坏合同拒绝、25 个直接调用
目标及 7 个名义状态／计数组合。证据必须在提交前重新核对输入、日志、产物与
源码清单摘要；前期测试工具缺少静态嵌入编译宏的链接失败只作诊断记录。

阶段检查完全离线；Socket 回归仅使用自己的 IPv4 回环端点和动态端口，
不涉及外部网络或网络安全专项。本批不构建或认证 shipping DLL／SO／VFS。

## 仍开放的历史观察

上一批 `p2-socket/language-win-r2/stdlib_net_socket_udp.module.log` 曾出现一次
`public source relocate failed: xlang compile failed`。当时没有底层诊断，不能据此
判定是 Socket、内存不足、系统或防护软件导致。

后续独立进程与完整回归没有复现，不等于找到根因。本批验证的是再次发生时可定位
失败阶段，以及失败／恢复合同；**没有证明历史偶发问题已修复**。该观察继续保留在
P0／P7，不能作为完整核心封板或发布完成的证明。其它长期任务范围不变。
