本文记录 DEMO6 当前文档体系的整理结果。它不新增语言功能，只用于避免后续开发混用历史口径。

## 收口范围

本轮整理覆盖以下文档：

- `demo6/docs`：语言设计、工程基线、扩展库、标准库、DLL、质量压实等设计与任务文档。
- `demo6/cgenrule`：代码生成规则对照表、规则验证矩阵和 cgen 文档守门脚本。
- `demo6/examples/README.md` 与 `demo6/examples/*/README.md`：范例入口文档，作为可用功能展示和回归入口说明，不作为语言设计来源。
- `demo6/packages/README.md`：package/import/XAPI 测试资产入口文档，不作为语言设计来源。
- `demo6/test/README.md`：测试目录入口、用例前缀索引和测试资产守门说明，不作为语言设计来源。
- `demo6/README.md`、`demo6/src/README.md`、`demo6/tools/README.md`、`demo6/include/README.md`、`demo6/lib/README.md`、`demo6/release/README.md`：工程目录入口文档，只描述目录职责、构建入口和维护边界，不作为语言设计来源。

## 仍允许存在的非阻断项

以下内容不是文档缺失：

- 明确标为“暂缓能力”“后续设计议题”的功能。

## 维护要求

- 新增或修改语言规则时，先更新 `demo6/docs` 中对应设计文件。
- 新增或修改代码生成行为时，同步更新 `demo6/cgenrule` 中对应 `CGEN-*` 规则和验证矩阵。
- 新增测试或范例后，如它证明某条规则，应同步补入对应验证矩阵。
- 新增设计文档后，必须把文件加入 `demo6/docs/README.md`。
- 新增、删除、重命名文档或改变文档身份后，必须同步维护 `demo6/docs/文档状态矩阵.md`。
- 新增 `README.md` 入口文档后，必须同步登记到文档索引口径；构建产物临时目录和第三方依赖副本不作为 DEMO6 文档入口。
- 新增或修改范例 README 后，必须保持其命令行示例不硬编码旧工具链路径；工具链默认值只允许集中在 `tools\xl6_toolchain_env.bat`。
- 不再使用裸待办标记作为设计状态；未完成内容应写成“当前边界”“后续设计议题”或“暂缓能力”。
