# 静态成员补全与函数值预绑定

常规 Windows API/IDE 验收发现，`auto result = Box.` 的查询占位表达式
会先进入唯一命名函数值绑定，产生“重载或泛型函数值需要显式签名”的错误。
随后真正的补全捕获看到了这个错误，拒绝列出静态字段和方法。
普通完整的 `Box.total` 程序不受此问题影响。

现在预绑定使用与补全捕获相同的精确节点判断：必须存在当前查询、解析器的
查询源标记、内部占位名称以及完全一致的起止字节范围。只有该占位节点
交给原有补全处理。普通函数值规则、用户同名标识符以及先前的真实错误
继续按原规则检查，没有清除诊断或按类名增加特例。

永久补全套件新增静态成员前缀、实参中的静态成员、查询之前同名用户函数
的真实歧义三项检查。Windows 源码候选 CLI 的完整套件通过 45 项；
其中既有的 DLL 内存查询检查仍使用原常规 DLL，不能作为修复后的 DLL 证明。
为此另在 Windows 和 Linux 链接完整源码对象及修复后的语义单元，实际调用
公开 `xlcComplete`，并对照 CLI：静态字段/方法、前缀、实参均成功，
前序用户函数歧义仍拒绝。两端各 14 个普通程序生成的 C 与修复前逐字节相同，
原有 private 静态方法值负例也继续拒绝且不写出 C。

本批是明确替换一个语义编译单元的源码诊断，不冒充全新常规 DLL/SO。
独立复核分别重新校验 13,288 和 13,305 个输入、日志及输出哈希。
