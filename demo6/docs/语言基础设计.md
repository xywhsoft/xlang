# xlang DEMO6 语言基础设计

本文档记录 DEMO6 已固定的语言基础设计，包括源码编码、标识符、注释、语句分隔、保留字、字面量、内置类型等。

## 1. 与 C 混编的总约束

本文件中的所有设计都必须服从 DEMO6 第一绝对原则：xlang 能够和 C 完美混编。

需要特别注意：

- xlang 语言大小写敏感，C 符号也大小写敏感。
- xlang 内部符号到 C ABI 符号仍然必须有稳定编码规则，尤其要处理中文标识符和非 C 标识符字符。
- 对外导入/导出 C 符号时，必须使用显式字符串保留 C 原始大小写，例如 `extern "xrtSleep"`、`export "app_add"`。
- 任何自动生成的 C 符号都必须稳定、可重复、无歧义。
- xlang 标识符到 C internal ABI symbol 的编码规则见 `ABI设计.md`。

## 2. 源文件与标识符

源文件固定采用 UTF-8 编码。

标识符按照 C 语言的设计，但 xlang 支持中文标识符，也就是支持 UTF-8 字符作为标识符的一部分。

语言大小写敏感。

关键字（保留字）不能作为标识符。

设计说明：

- `Name`、`name`、`NAME` 在 xlang 中是三个不同的标识符。
- 中文标识符按 UTF-8 内容区分。
- lexer 和符号表必须保留标识符原始大小写。

## 3. 注释

单行注释：

```xlang
// 单行注释
```

多行注释：

```xlang
/*
    多行注释，支持嵌套使用
*/
```

多行注释支持嵌套：

```xlang
/*
    外层注释
    /*
        内层注释
    */
*/
```

实现要求：

- lexer 需要维护块注释深度。
- 未闭合多行注释应报词法错误。

## 4. 空白与语句分隔

空格、tab 等普通空白被忽略。

换行是语句分隔符。

分号 `;` 也可作为语句分隔符，但是不像 C 语言那样强制使用。

严格规则：

- 当 lexer/parser 处在 `()`、`[]`、`{}` 内部时，换行不结束语句。
- 只有分隔符嵌套深度为 0 时，换行才作为语句分隔符。
- 分号主要用于同一行书写多条语句。
- 分号不强制使用。
- 分号在 `()`、`[]`、`{}` 内部不承担普通语句分隔职责，除非后续某个语法显式允许。

示例：

```xlang
var a = 1
var b = 2; var c = 3
var d = add(
    1,
    2
)
```

## 5. 保留字

当前固定的保留字列表：

```text
null true false
func const var auto typedef as
if then else elseif end
for in while do
break continue return
async await yield
try catch finally throw assert
import export extern include define
class custom extends union get let
and or not
```

说明：

- 用户已主动去掉一部分 DEMO5 保留字，留到后续商议。
- 保留字大小写敏感，当前保留字列表中的小写形式是保留字。
- 保留字不能作为标识符。
- 例如 `func` 是保留字，`Func` 不是当前保留字，但不建议用这种方式编写容易混淆的标识符。

### 5.1 内置类型名不是词法保留字

采用类型注册系统后，内置类型名不作为词法保留字处理。

以下名字由类型注册系统预声明：

```text
type
function
array
list
set
dict
```

规则：

- lexer 只把真正的保留字识别为关键字。
- `type`、`function`、`array`、`list`、`set`、`dict` 在词法层仍然是普通标识符。
- 语义阶段在类型位置查类型注册表。
- 表达式位置遇到类型名时，可解析为 `type` 类型的字面量，例如 `type(a) == int`。
- 如果表达式位置同时存在同名变量和值符号，优先解析为值符号；需要避免这种写法造成歧义。
- 用户自定义类型不能和同一作用域中已经存在的类型名重复。

`auto` 是保留字。它只用于声明时的类型推断，不通过类型注册系统作为普通类型名解析。

### 5.2 上下文关键字

以下名字不作为全局保留字：

```text
self
base
create
destroy
```

规则：

- `self` 只在 class/custom 方法、构造、析构体内作为编译器注入的当前实例。
- `base` 只在 class 继承相关上下文中表示父类构造或父类视角访问。
- `create` 只在 class/custom 类型体成员声明位置作为构造入口。
- `destroy` 只在 class/custom 类型体成员声明位置作为析构入口。
- 离开这些上下文后，它们按普通标识符处理。

## 8. 字符串字面量

普通字符串：

```xlang
"hello"
'hello'
```

规则：

- 可以使用 `''` 或 `""` 标识字符串。
- 两者语义没有区别。
- 字符串默认支持转义符。

raw string：

```xlang
r"c:\123.txt"
r'c:\123.txt'
```

规则：

- 可以使用 `r''` 或 `r""` 声明 raw string。
- raw string 不处理普通转义。

模板字符串暂缓：

```xlang
f"hello ${name}"
f'hello ${name}'
```

规则：

- `f''` 或 `f""` 是保留语法方向。
- 第一阶段不实现表达式插值。
- 第一阶段 parser 遇到模板字符串应给出明确诊断：模板字符串暂未实现。
- 第一阶段只实现普通字符串、raw string、多行字符串。

## 9. 时间字面量

time literal 使用 `#...#` 形式。

```xlang

#yyyy-mm-dd hh:mm:ss#
```

示例：

```xlang

#12:30:59#
#2026-06-18 12:30:59#
```

集合字面量：

### 带类型名前缀的容器字面量

数组：

```xlang

```

列表：

```xlang

list[1: "a", 2: "b", 3: "c"]
```

集合：


字典：


- `{key: value}` 形式表示 dict 字面量。
- `{value, value}` 形式表示 set 字面量。

## 12. 内置数据类型

### 基本类型

```text
null
bool
int
int8 uint8
int16 uint16
int32 uint32
int64 uint64
float
float32 float64
string
time
point
function
```

说明：

- `int` 是默认整数类型。
- `float` 是默认浮点类型。
- `point` 表示指针/句柄类 C 互操作类型。
- `function` 表示函数类型。
- 无返回值函数省略返回类型；函数语法详见 `函数设计.md`。

### C ABI 专用基础类型

以下类型用于精确表达 C ABI，不作为日常 xlang 代码的推荐写法：

```text
c_char c_schar c_uchar
c_short c_ushort
c_int c_uint
c_long c_ulong
c_longlong c_ulonglong
c_size c_ssize
c_ptrdiff
c_intptr c_uintptr
c_bool
c_float c_double
c_wchar
```

说明：

- `c_*` 类型只在 `extern`、`export`、custom 绑定、XRT/CRT 函数声明等 ABI 场景下优先使用。
- 需要固定宽度整数时，继续使用 `int8`、`uint32`、`int64` 等 xlang 固定宽度类型。
- `c_long`、`c_ulong`、`c_wchar` 等类型长度跟随目标平台 ABI，不承诺跨平台固定宽度。
- `c_char` 对应 C 原生 `char`，不承诺 signedness；需要明确符号语义时使用 `c_schar` 或 `c_uchar`。

### 容器类型

```text
array
array<T>
list
list<T>
set
set<T>
dict
dict<T>
```

说明：

- `array` 表示数组。
- `list` 表示带 `int64` 稀疏索引的数据结构。
- `set` 表示集合。
- `dict` 表示字典。

### 自定义类型

```text
class   自定义类
custom  轻量自定义类型
```

### 动态与推断

`var` 是动态值类型。

`var` 支持以下原生类型：

```text
null
bool
int
float
string
time
point
array
list
set
dict
```

规则：

- `var` 中的 `int` 只能表示 64 位精度。
- `var` 中的 `float` 只能表示 64 位精度。
- `function` 是独立的一等公民类型，第一阶段不装入 `var`。
- 第一阶段 `class` / `custom` 不默认装入 `var`。
- 如果后续需要 `var` 持有 `function` / `class` / `custom`，必须先设计完整 typeops：copy、move、destroy、trace、type id。

`auto` 是局部声明推断类型。

顶层可执行语句按脚本主块处理，允许使用 `auto`；类型字段、函数参数、函数返回类型、typedef 目标和 function 类型签名中不能使用 `auto`。

`type` 是一种真实存在的特殊类型，用于表示“类型的类型”。

说明：

- `type` 本质上是枚举值。
- `type` 底层可以用整数表示，但语义上不等同于普通 `int`。
- `type(expr)` 返回表达式的类型值。
- `type(varExpr)` 返回 XRT 动态值中的实际基础类型值，例如装箱整数返回 `int`、装箱字符串返回 `string`。
- `var` 中的容器只保留运行时基础类型，`type(varArray)` 返回 `array`，不返回 `array<T>`。
- 类型标识符可以作为 `type` 字面量参与比较，例如 `type(a) == int`。
- 详细规则见 `类型与隐性类设计.md`。

动态对象基类不进入当前 DEMO6 class/custom 方案，暂不作为内置数据类型记录。

## 13. 变量与常量声明

变量声明采用 C 风格类型前置。

基础形式：

```xlang
Type name
Type name = value
var name
var name = value
auto name = value
const Type name = value
```

示例：

```xlang
int count = 0
string name = "xlang"
var value = 123
auto total = count + 1
const int maxCount = 100
```

规则：

- `Type name` 声明静态类型变量。
- `var name` 声明动态值变量。
- `auto name = value` 声明局部推断类型变量。
- `const Type name = value` 声明常量。
- `auto` 必须有初始化表达式。
- `const` 必须有初始化表达式。
- 没有初始化表达式的变量使用类型默认值初始化。
- `auto` 只允许用于函数体、控制流块和顶层脚本主块中的变量声明，不作为函数参数类型、返回类型、字段类型、typedef 目标或 function 类型签名。
- 同一作用域内不允许重复声明同名变量、常量、参数。
- 内层作用域允许遮蔽外层变量，遵循 C 语言的词法作用域习惯。
- 全局变量、全局常量与全局函数重载组不能同名。
- 类型名与值名分属不同语义空间，但不建议写出和内置类型名同名的变量。

默认初始化方向：

```text
null      null
bool      false
int       0
float     0.0
string    ""
time      0 或 XRT 时间零值
point     null pointer
function  null function
array     empty array
list      empty list
set       empty set
dict      empty dict
class     按字段默认值初始化
custom    空句柄
```

说明：

- `var name` 默认初始化为 `null`。
- `custom` 空句柄是否能被方法调用，由 custom 映射约束决定，详见 `类型系统设计.md`。
- 默认初始化必须能稳定 lowering 到 C/XRT 初始化代码。

## 14. C 混编提醒

本文件中已有几个会影响 C 混编的设计点：

- 大小写敏感需要 C ABI 符号编码保留大小写差异。
- 中文标识符需要稳定 C 符号编码。
- `point` 应成为 C 指针/句柄互操作的核心类型。
- `string` 与 C 的 `char*` / `const char*` 映射需要明确所有权。
- `var` 不应默认作为 C ABI export 类型，除非显式设计为 XRT value。
- `class/custom` 不应默认直接跨 C 暴露，第一阶段应优先通过 `point` 句柄暴露。
