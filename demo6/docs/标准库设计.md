# xlang DEMO6 标准库设计

## 总原则

DEMO6 标准库默认进入 xlang 编译环境，用户不需要为基础能力手写 `extern` 或 `import`。

标准库不是另起一套运行库。能够由 XRT 提供的能力，必须优先映射到 XRT；确实属于 CRT 基础设施、没有必要在 XRT 重复实现的能力，可以直接映射到 CRT。典型例子是 `math` 命名空间，它映射到 C 数学函数。

标准库使用短命名空间：

```xlang
math.log(10.0)
string.split("a,b", ",")
time.now()
file.readText("data.txt")
```

不采用 DEMO5 中额外增加一层包命名空间的写法。

## 编译器实现口径

标准库命名空间在语义检查前展开：

1. 编译器识别 `namespace.name` 或未来的 `namespace.sub.name` 成员访问。
2. 如果命中标准库函数表，将其改写为内部函数名。
3. 编译器只为实际用到的标准库函数注入 `extern` 声明。
4. 后续语义检查、类型推断、C 代码生成继续复用现有 C 混编能力。

示例：

```xlang
auto x = math.sqrt(9.0)
```

会在编译器内部等价展开为：

```xlang
extern "sqrt" func __xl_std_math_sqrt(float x) as float
auto x = __xl_std_math_sqrt(9.0)
```

这保证标准库和 C 混编使用同一条 ABI 路径。

## 字符串所有权

DEMO6 当前的静态 `string` 仍按 `const char*` 表达。为了安全接入 XRT 中“返回值需 `xrtFree`”的函数，标准库采用统一桥接策略：

1. 底层 XRT 函数在私有声明中返回 `point`，表示原始 C 指针。
2. 公共标准库函数立即调用 `xl6_xrt_take_cstr`。
3. `xl6_xrt_take_cstr` 将 XRT 堆字符串复制到 `xrtTempMemory` 临时内存区，并释放原始指针。
4. 返回给 xlang 的值是普通 `string`，用户不需要也不能手动释放。

临时字符串的生命周期由 XRT 线程临时内存管理，随运行环境 `xlUnit` / `xrtUnit` 或线程退出释放。后续如果引入真正 owning string 类型，应以这一层为兼容边界继续演进，而不是让每个标准库函数各自处理释放。

## 命名空间规则

标准库命名空间只在成员访问位置生效，例如 `math.sqrt`。

如果写了已存在标准库命名空间但不存在的符号，例如 `math.unknown()`，编译器报错。

标准库支持命名空间常量，例如 `math.pi`。常量在标准库重写阶段直接改写为字面量，不生成运行时函数调用。

## 第一批已实现函数

全局输出函数默认进入环境，不需要命名空间。多个参数按调用顺序输出，参数之间自动插入一个空格；`print` 不追加换行，`println` 追加换行。空参数时 `print()` 不输出内容，`println()` 只输出换行。

`xl6_xrt_print` 的生成代码不使用 C `FILE*`、`stdout`、`fwrite` 或 `fflush`。Windows 下由生成文件自声明最小 WinAPI 原型并通过标准输出句柄写入，不依赖 `windows.h`；POSIX 下通过 `write(1, ...)` 写入。值格式化仍优先使用 XRT 的整数、浮点、时间和 JSON/XSON 转换能力。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `print(...)` | `xl6_xrt_print` | 输出任意数量的 `var` 参数到标准输出 |
| `println(...)` | `xl6_xrt_print` | 输出任意数量的 `var` 参数到标准输出，并在末尾换行 |

字符串迭代规则：

```xlang
for c in "1234你好"
    print(c)
end

for b in string.bytes("A你")
    print(b)
end
```

默认 `for ... in string` 按 UTF-8 字符迭代，循环值类型为 `string`；双目标写法 `for i, c in text` 中 `i` 为 0 基字符索引。需要逐字节处理时使用 `string.bytes(text)`，返回每个字节的整数值。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `random.u32()` | `xrtRand32` | 返回 `uint32` 随机数 |
| `random.u64()` | `xrtRand64` | 返回 `uint64` 随机数 |
| `random.range(min, max)` | `xrtRandRange` | 返回闭区间 `[min, max]` 内的 `int` 随机数 |

`Random` 是标准库提供的 native-backed class，底层保存 XRT `xrtRandObj` 状态，适合游戏、仿真、测试重放等需要可复现随机序列的场景。创建独立随机对象使用普通 class 构造器写法：`Random rng = Random(uint64(seed), uint64(seq))`；标准库不提供命名空间工厂函数，避免不可复制对象经函数返回破坏当前生命周期规则。

| `rng.u64()` | `xrtRand64Obj` | 使用对象状态生成 `uint64` |

`Buffer` 是标准库提供的 native-backed class，底层保存 XRT `xbuffer`，用于二进制缓冲、网络收发、文件读写和后续二进制安全 codec/crypto API。创建方式使用普通 class 构造器：`Buffer buf = Buffer()` 或 `Buffer buf = Buffer(step)`；标准库不提供 `buffer.create()` 工厂函数，避免不可复制原生资源经函数返回破坏生命周期规则。

`encoding` 命名空间映射 XRT 字符集探测与 UTF 编码转换能力。xlang 普通 `string` 固定是 UTF-8 文本，因此 `encoding.toBytes` 在目标编码不是 UTF-8 时返回不可复制的 `Buffer`，`encoding.fromBytes` 从显式 `point + size` 字节视图解码回 UTF-8 `string`。不让 `encoding.fromBytes(Buffer)` 按值接收 `Buffer`，是为了遵守 native-backed class 默认不可复制的生命周期规则。

- `encoding.autoDetect = -2`

- `encoding.oem = 0`
- `encoding.utf8 = 65001`
- `encoding.utf16 = 1200`
- `encoding.utf16BE = 1201`
- `encoding.utf32 = 65005`
- `encoding.utf32BE = 65006`
- `encoding.bom = 1073741824`

| --- | --- | --- |
| `encoding.charSize(charset)` | `xrtGetCharSize` | 返回指定编码 code unit 的字节宽度，UTF-8/OEM 为 1，UTF-16 为 2，UTF-32 为 4 |
| `encoding.name(charset)` | 标准库 wrapper | 返回 `auto`、`binary`、`oem`、`utf-8`、`utf-16`、`utf-16be`、`utf-32`、`utf-32be` 或 `unknown` |

| `encoding.isUtf8Bytes(data, size)` | `xrtIsUTF8` | 检查原始字节视图是否为合法 UTF-8 |

常见写法：

```xlang

```

`template` 命名空间映射 XRT `xte` 模板引擎。模板层只负责把 `xvalue` 数据渲染为文本，不承担业务计算；xlang 的 `var`、`array`、`dict` 会直接落到 XRT `xvalue`，因此可以零额外数据模型进入 `xteMake`。`Template` 是 native-backed class，`template.compile` 返回预编译模板对象，适合 Web 页面、代码生成、Agent prompt 等需要重复渲染的场景；`template.render` / `template.renderFile` 是脚本便捷路径。

模板默认使用 `{}` 定界符，例如 `{$title}`。需要嵌入 JSON/HTML/其他模板片段时，可以通过 `bracket` 改为 `"<>"`、`"{{}}"`、`"(())"` 等偶数字符串，其中前半段为开始定界符，后半段为结束定界符。模板语法由 XRT 统一实现，当前支持文本输出、数字/时间格式化、行内布尔分支、`if/elseif/else`、`for`、`foreach`、`break/continue`、`define`、`script` 和 `include`。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `template.compile(text, bracket = "{}")` | `xteParse` | 编译模板文本，返回 `Template` 对象 |
| `template.render(text, data = null, bracket = "{}")` | `xteParse` + `xteMake` | 一次性编译并渲染模板 |
| `template.renderFile(path, data = null, bracket = "{}")` | `file.readText` + `xteMake` | 通过 XRT UTF-8 文件层读取模板文件并渲染 |
| `Template(text, bracket)` | `xteParse` | 显式构造预编译模板对象 |
| `tpl.render(data = null)` | `xteMake` | 使用 `var` / `array` / `dict` 数据渲染文本 |
| `tpl.nodeCount` / `tpl.exprCount` / `tpl.argCount` / `tpl.stringPoolSize` | `xteTemplateGet*` | 读取预编译模板统计信息，用于诊断和测试 |

常见写法：

```xlang
var page = {"title": "xlang", "items": [{"name": "one"}, {"name": "two"}]}
Template tpl = template.compile("<h1>{$title}</h1>{#foreach:items}<p>{$name}</p>{#end}")
string html = tpl.render(page)
```

`http.server` 命名空间映射 XRT `xweb` 高层 HTTP 服务基座。当前采用“服务句柄 + 路由注册”模型：`create` 返回 `point` 句柄，调用者注册 `get`、`post`、`any`、`getRequest`、`postRequest`、`anyRequest` 或静态目录，再显式 `start`、读取端口、最后 `destroy`。server 默认绑定 `127.0.0.1`，`port = 0` 表示由系统分配空闲端口。

`get`、`post`、`any` 是简化路由 API，handler 固定为 `func(string, string, string, string) as string`，四个参数依次为 `method`、`path`、`query`、`body`，返回值作为 `text/plain; charset=utf-8` 响应正文。`getRequest`、`postRequest`、`anyRequest` 是对象化路由 API，handler 固定为 `func(point, point) as bool`，两个参数分别是借用的 request/response 句柄，函数体内应构造 `HttpRequest` 和 `HttpResponse` 对象访问请求、设置状态码、响应头和响应体。路由 pattern 由 XRT `xweb` 解析，支持静态段、变量段 `{id}` 和尾通配符 `*`，匹配优先级为静态段 > 变量段 > 通配符。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `http.server.create(port = 0)` | `xrtWebConfigInit` + `xrtWebServerCreate` | 创建本机 HTTP server 句柄 |
| `http.server.get(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_GET, ...)` | 注册 GET 路由 |
| `http.server.post(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_POST, ...)` | 注册 POST 路由 |
| `http.server.any(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_ANY, ...)` | 注册任意 HTTP 方法路由 |
| `http.server.getRequest(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_GET, ...)` | 注册对象化 GET 路由，handler 接收 `HttpRequest`/`HttpResponse` 原始句柄 |
| `http.server.postRequest(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_POST, ...)` | 注册对象化 POST 路由 |
| `http.server.anyRequest(server, pattern, handler)` | `xrtWebServerRoute(..., XWEB_METHOD_ANY, ...)` | 注册对象化任意方法路由 |
| `http.server.static(server, mount, root)` | `xrtWebServerStatic` | 挂载静态文件目录，只服务 GET/HEAD |
| `http.server.mimeByPath(path)` | `xrtWebMimeByPath` | 按文件扩展名获取 HTTP Content-Type |
| `http.server.start(server)` | `xrtWebServerStart` | 启动监听，返回是否成功 |
| `http.server.port(server)` | `xrtWebServerPort` | 获取实际监听端口 |
| `http.server.stop(server)` | `xrtWebServerStop` | 停止监听 |
| `http.server.destroy(server)` | `xrtWebServerDestroy` | 释放 server 句柄和已注册 handler 引用 |

对象化路由中的 `HttpRequest` 和 `HttpResponse` 是 native-backed class，底层句柄由 XRT 在一次请求生命周期内管理，xlang 只借用，不负责释放。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `HttpRequest(reqHandle)` | 借用 `xwebrequest*` | 包装当前请求句柄 |

示例：

```xlang
func hello(string method, string path, string query, string body) as string
    if path == "/users/42" then
        return "user-42"
    end
    return "hello"
end

func(string, string, string, string) as string handler = hello
point server = http.server.create(8080)
http.server.get(server, "/users/{id}", handler)
http.server.post(server, "/echo", handler)
http.server.static(server, "/public", "public")
http.server.start(server)
http.server.destroy(server)
```

## 暂缓能力与后续设计议题

以下能力已明确暂缓，不属于当前标准库缺失。后续进入新批次时，应先补齐底层类型或运行时模型，再进入标准库公开 API：

- `codec`：基于 `Buffer` 补充二进制安全的 encode/decode API。
- `crypto`：基于 `Buffer` 补充二进制安全摘要、HMAC、HKDF、AEAD、随机字节和密钥交换接口。
- `process`：后续在记录类型或对象模型稳定后，再提供 stderr、环境变量、工作目录、流式进程句柄和异步等待。
- `xson`：后续如需暴露 XRT flags，应设计为稳定枚举或选项对象，而不是直接泄漏裸整数标志位。

HTTP client 当前暂缓进入标准库，等待底层能力成熟后再纳入。

## C ABI 类型要求

标准库公开 API 应尽量使用 xlang 推荐类型，例如 `int`、`float`、`bool`、`string`、`time`、`point`。

标准库内部桥接 XRT/CRT 函数时，必须使用 `c_*` 类型对齐真实 C 原型。例如：
- `size_t` 使用 `c_size`。
- C `int` / `unsigned int` 使用 `c_int` / `c_uint`。
- C `bool` 使用 `c_bool`。
- `ptrdiff_t` / `intptr_t` / `uintptr_t` 使用对应 `c_ptrdiff` / `c_intptr` / `c_uintptr`。

不要为了方便把平台相关 C 类型猜成 `int32`、`uint64` 等固定宽度类型；这会破坏和 XRT 头文件或用户 C 头文件的 ABI 一致性。
