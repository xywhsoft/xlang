# xlang DEMO6 标准库设计

## 总原则

DEMO6 标准库默认进入 xlang 编译环境，用户不需要为基础能力手写 `extern` 或 `import`。

标准库不是另起一套运行库。能够由 XRT 提供的能力，必须优先映射到 XRT；确实属于 CRT 基础设施、没有必要在 XRT 重复实现的能力，可以直接映射到 CRT。典型例子是 `math` 命名空间，它映射到 C 数学函数。

标准库使用短命名空间：

```xlang
math.log(10.0)
string.split("a,b", ",")
time.now()
file.readText("data.txt")
```

不采用 DEMO5 中额外增加一层包命名空间的写法。

## 编译器实现口径

标准库命名空间在语义检查前展开：

1. 编译器识别 `namespace.name` 或未来的 `namespace.sub.name` 成员访问。
2. 如果命中标准库函数表，将其改写为内部函数名。
3. 编译器只为实际用到的标准库函数注入 `extern` 声明。
4. 后续语义检查、类型推断、C 代码生成继续复用现有 C 混编能力。

示例：

```xlang
auto x = math.sqrt(9.0)
```

会在编译器内部等价展开为：

```xlang
extern "sqrt" func __xl_std_math_sqrt(float x) -> float
auto x = __xl_std_math_sqrt(9.0)
```

这保证标准库和 C 混编使用同一条 ABI 路径。

## 字符串所有权

DEMO6 当前的静态 `string` 仍按 `const char*` 表达。为了安全接入 XRT 中“返回值需 `xrtFree`”的函数，标准库采用统一桥接策略：

1. 底层 XRT 函数在私有声明中返回 `point`，表示原始 C 指针。
2. 公共标准库函数立即调用 `xl6_xrt_take_cstr`。
3. `xl6_xrt_take_cstr` 将 XRT 堆字符串复制到 `xrtTempMemory` 临时内存区，并释放原始指针。
4. 返回给 xlang 的值是普通 `string`，用户不需要也不能手动释放。

临时字符串的生命周期由 XRT 线程临时内存管理，随运行环境 `xlUnit` / `xrtUnit` 或线程退出释放。后续如果引入真正 owning string 类型，应以这一层为兼容边界继续演进，而不是让每个标准库函数各自处理释放。

## 命名空间规则

标准库命名空间只在成员访问位置生效，例如 `math.sqrt`。

如果写了已存在标准库命名空间但不存在的函数，例如 `math.unknown()`，编译器报错。

当前第一版不提供标准库属性值，因此 `math.pi` 暂不实现。常量是否采用 `math.pi` 属性形式，后续单独定稿。

## 第一批已实现函数

全局输出函数默认进入环境，不需要命名空间。多个参数按调用顺序输出，参数之间自动插入一个空格；`print` 不追加换行，`println` 追加换行。空参数时 `print()` 不输出内容，`println()` 只输出换行。

`xl6_xrt_print` 的生成代码不使用 C `FILE*`、`stdout`、`fwrite` 或 `fflush`。Windows 下由生成文件自声明最小 WinAPI 原型并通过标准输出句柄写入，不依赖 `windows.h`；POSIX 下通过 `write(1, ...)` 写入。值格式化仍优先使用 XRT 的整数、浮点、时间和 JSON/XSON 转换能力。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `print(...)` | `xl6_xrt_print` | 输出任意数量的 `var` 参数到标准输出 |
| `println(...)` | `xl6_xrt_print` | 输出任意数量的 `var` 参数到标准输出，并在末尾换行 |

`net` 命名空间映射 XRT 本机网络识别能力。返回值依赖操作系统和当前网络环境，无法获取时返回空字符串，不抛出异常。

| xlang 写法 | 底层能力 | 说明 |

`url` 命名空间映射 XRT URL 解析和规范化能力。第一版保持纯函数设计，不引入 URL 对象；解析失败时返回 `false`、`0` 或空字符串。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `url.valid(text)` | `xrtUrlParseViewN` | 判断 URL 或 target 是否可被 XRT URL 解析器接受 |

| `url.isSecure(text)` | `xrtUrlParseViewN` | 判断 scheme 是否为安全协议，例如 `https`、`wss` |

| `url.query(text)` | `xrtUrlParseViewN` | 获取 query，不含 `?` |
| `url.fragment(text)` | `xrtUrlParseViewN` | 获取 fragment，不含 `#` |

`query` 命名空间映射 XRT form-url-encoded / percent 编码能力。第一版保持纯字符串 API，不解析为 `dict`，避免在容器泛型和字符串所有权完全收口前引入不稳定语义。编码规则采用表单风格：空格编码为 `+`，其他非 unreserved 字节编码为大写 `%HH`，UTF-8 文本按字节编码。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `query.encode(text)` | `xrtPercentEncodeTo` | 对单个字段文本进行 form-url-encoded 百分号编码 |
| `query.decode(text)` | `xrtFormUrlEncodedDecodeTo` | 解码 form-url-encoded 文本，`+` 还原为空格 |
| `query.valid(text)` | `xrtFormUrlEncodedValidateN` | 判断 query 字符串是否符合 XRT key/value 结构和限制校验规则 |
| `query.pair(name, value)` | `xrtFormUrlEncodedAppendFieldTo` | 生成一个 `name=value` 字段，名称和值都会编码 |
| `query.append(query, name, value)` | `xrtFormUrlEncodedAppendFieldTo` | 向已有 query 追加字段，非空时自动插入 `&` |

`regex` 命名空间映射 XRT 正则表达式能力。第一版保持一次性匹配 API：每次调用内部创建 XRT 正则对象、执行匹配、立即销毁，不暴露 compiled regex 句柄，也暂不暴露捕获组。正则语法和匹配能力遵循当前 XRT 正则模块。

非法 pattern 不抛出异常，`isMatch` 返回 `false`，`find` 返回 `-1`。后续如果需要错误详情、捕获组、正则对象复用，应在 custom/handle 类型和错误模型完全收口后再扩展。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `regex.isMatch(text, pattern)` | `xrtRegexCreate` + `xrtRegexIsMatch` | 判断文本是否匹配 pattern |
| `regex.find(text, pattern)` | `xrtRegexCreate` + `xrtRegexFind` | 返回首个匹配的 0 基起始索引，不匹配或 pattern 非法时返回 `-1` |

`process` 命名空间映射 XRT subprocess 能力。第一版只提供同步 shell 命令执行，用于脚本化任务和构建辅助，不暴露进程句柄、流式读写、环境变量、stderr 或结构化退出记录。

`process.exec` 返回 stdout 文本；命令启动失败、超时、无输出或非零退出但没有 stdout 时返回空字符串。`process.success` 返回命令是否成功退出，要求进程正常退出、未超时且退出码为 0。`process.exitCode` 返回命令的退出码；命令启动失败或超时时返回 `-1`。命令解释方式使用 XRT 当前平台 shell 规则。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `process.exec(command, timeoutMs = 0)` | `xrtProcessConfigInit` + `xrtExecCapture` | 执行 shell 命令并返回 stdout 文本，`timeoutMs = 0` 表示不限制 |
| `process.success(command, timeoutMs = 0)` | `xrtProcessConfigInit` + `xrtExecCapture` | 判断 shell 命令是否以退出码 0 成功结束 |
| `process.exitCode(command, timeoutMs = 0)` | `xrtProcessConfigInit` + `xrtExecCapture` | 返回 shell 命令退出码，启动失败或超时返回 `-1` |

`http.server` 命名空间映射 XRT HTTP server 能力。第一版采用最小可用句柄模型：`create` 返回 `point` 句柄，调用者显式 `start`、读取端口、最后 `destroy`。server 默认绑定 `127.0.0.1`，`port = 0` 表示由系统分配空闲端口。

handler 固定为 `function(string, string, string, string) -> string`，四个参数依次为 `method`、`path`、`query`、`body`，返回值作为 `text/plain; charset=utf-8` 响应正文。第一版暂不暴露 request/response 对象、状态码和响应头；这些能力后续应在 request/response 类型定稿后扩展。

| xlang 写法 | 底层能力 | 说明 |
| --- | --- | --- |
| `http.server.create(port, handler)` | `xrtNetEngineCreate` + `xrtHttpdCreate` | 创建本机 HTTP server 句柄，handler 必须是显式 function 值 |
| `http.server.start(server)` | `xrtHttpdStart` | 启动监听，返回是否成功 |
| `http.server.port(server)` | `xrtHttpdBoundPort` | 获取实际监听端口 |
| `http.server.stop(server)` | `xrtHttpdStop` + `xrtNetEngineStop` | 停止监听和网络引擎 |
| `http.server.destroy(server)` | `xrtHttpdDestroy` + `xrtNetEngineDestroy` | 释放 server 句柄和 handler 引用 |

示例：

```xlang
func hello(string method, string path, string query, string body) -> string
    return "hello"
end

function(string, string, string, string) -> string handler = hello
point server = http.server.create(8080, handler)
http.server.start(server)
http.server.destroy(server)
```

## 暂缓能力与后续设计议题

以下能力已明确暂缓，不属于当前标准库缺失。后续进入新批次时，应先补齐底层类型或运行时模型，再进入标准库公开 API：

- `codec`：补充 byte/buffer 类型后，再提供二进制安全的 encode/decode API。
- `crypto`：补充 byte/buffer 类型后，再提供二进制安全摘要、HMAC 和随机字节接口。
- `process`：后续在记录类型或对象模型稳定后，再提供 stderr、环境变量、工作目录、流式进程句柄和异步等待。
- `http.server`：暂缓扩展 request/response 对象、状态码、响应头和路由工具。
- `xson`：后续如需暴露 XRT flags，应设计为稳定枚举或选项对象，而不是直接泄漏裸整数标志位。

HTTP client 当前暂缓进入标准库，等待底层能力成熟后再纳入。

## C ABI 类型要求

标准库公开 API 应尽量使用 xlang 推荐类型，例如 `int`、`float`、`bool`、`string`、`time`、`point`。

标准库内部桥接 XRT/CRT 函数时，必须使用 `c_*` 类型对齐真实 C 原型。例如：
- `size_t` 使用 `c_size`。
- C `int` / `unsigned int` 使用 `c_int` / `c_uint`。
- C `bool` 使用 `c_bool`。
- `ptrdiff_t` / `intptr_t` / `uintptr_t` 使用对应 `c_ptrdiff` / `c_intptr` / `c_uintptr`。

不要为了方便把平台相关 C 类型猜成 `int32`、`uint64` 等固定宽度类型；这会破坏和 XRT 头文件或用户 C 头文件的 ABI 一致性。
