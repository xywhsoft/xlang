# 运行时类型系统基线审计

本文记录 DEMO6 当前运行时类型系统的事实基线，用于后续设计 `is`、运行时类型判断、向下转换和类型收窄。本文不引入新语法，也不把暂缓能力视为当前实现缺口。

## 审计范围

- 类型注册系统：内置类型、C 兼容类型、容器类型、class、native-backed class、union、typedef alias。
- 类型值：`type(expr)`、类型字面量、透明别名、泛型类型值、函数签名类型值。
- 运行时装箱：`var` 保存基础值、函数值、class、native-backed class、union、静态泛型容器。
- XRT 对接：xvalue、type desc、type ops、callable signature、typed container descriptor。
- 生命周期约束：class/native-backed class 的 copy、clone、moveOnly、destroy 对装箱和捕获的影响。

## 当前基线结论

- DEMO6 的类型名由类型注册系统统一管理，基础类型、C ABI 类型、容器类型、并发句柄类型、class、native-backed class、union、typedef alias 都进入同一套查询路径。
- 类型等价是透明别名后的结构等价。`typedef MyInt = int` 后，`Box<MyInt>` 与 `Box<int>` 的类型值相等。
- `type(expr)` 对静态非 `var` 表达式生成编译期类型 id；对 `var` 表达式调用 XRT/xvalue 的运行时类型查询，读取装箱值携带的真实 type desc/type id。
- 函数值不是裸 `func`。带签名的 `func(int) as int` 会生成 callable signature，装入 `var` 后仍保留精确签名类型，`type(boxedFn) == func` 为假。
- class 装入 `var` 时使用 XRT record 盒子；纯 native handle class 装入 `var` 时使用 XRT handle 盒子；union 装入 `var` 时使用对应 union type desc 和 type ops。
- 静态泛型容器使用 XRT typed container。`array<T>`、`list<T>`、`set<T>`、`dict<T>` 的运行时类型不应退化为裸 `array/list/set/dict`。
- object 在 DEMO6 中是标准库声明的普通 class，动态字段通过 `__field__`、`__setField__`、`__item__`、`__setItem__` 协议落到内部字典，不是独立于 class 之外的黑盒运行时类型。
- 当前 `type()` 是精确类型判断，不执行父类折叠，也不表达 subtype 关系。`Base` 与 `Child` 是不同类型值。

## 当前边界

- 普通赋值的类型兼容最终落到精确类型等价；`var` 是受生命周期约束的装箱例外。
- 当前已经实现 `is` 运行时类型判断和 `as` checked downcast；类型收窄、容器 downcast、泛型 class 继承关系推断仍暂缓。
- 当前动态派发用于 virtual 方法调用，不等同于开放任意 `Base value = Child()` 的隐式 upcast 模型。
- `xl6CgenTypeValueUsesBaseType` 当前不折叠到基类，后续如需 subtype 查询，应新增明确的运行时类型关系 API，而不是改变现有 `type()` 精确语义。
- class/native-backed class 如果带有 destroy、moveOnly 或不可复制字段，不能被 `var` 装箱、闭包捕获或容器复制规则绕过。

## 已补基线测试

- `test/cases/cgen_runtime_type_baseline.xl` 集中覆盖当前运行时类型地基：
  - 静态 class 与 `var` 装箱后的 class 精确类型。
  - 父类与子类的类型值不相等，验证 `type()` 不是 subtype 判断。
  - object 派生类的动态字段和索引访问不改变宿主类型。
  - pure native handle class 装箱后保留 class 类型。
  - union 装箱后保留 union 类型。
  - 函数值装箱后保留完整签名，不退化为裸 `func`。
  - `array<Child>` 装箱后保留静态泛型容器 descriptor，不退化为裸 `array`。

## 后续补强要求

- `is` 与 `as` 已先在 xlang 代码生成层闭环；后续应继续下沉为 XRT 层可独立解释的 type relation/type query 能力，保证 C 与 xlang 都能使用。
- subtype 判断必须与 `type()` 的精确类型语义分离，避免破坏已有类型值比较和 ABI 元数据。
- downcast 必须显式处理失败路径，不能依赖未定义行为或裸指针 reinterpret。
- 类型收窄只能发生在语义明确的控制流范围内，不能影响 `var` 的真实运行时 type desc。
- 运行时类型关系应与 ABI 元数据 输出的 class/native-backed class/union 元数据保持一致，扩展库边界需要能复现相同判断。
- 生命周期规则优先级高于类型转换便利性。任何 upcast/downcast/box/unbox 设计都不能绕过 copy、clone、moveOnly、destroy 约束。
