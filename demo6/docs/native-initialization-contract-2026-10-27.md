# 原生资源初始化合同验收（2026-10-27）

本批将既有 IR 约束提前落实到语义检查，并修正验证夹具的 C ABI。没有更改 IR、原生资源默认构造规则或拥有权模型。

## 问题与修复

用户类含有实例级 `native point` 字段时，既有 IR 已要求不可空实例显式初始化。此前语义检查仍接受 `Handle empty`，随后 lowering 才报告缺少经过验证的初始化 ABI。这不是显式全局构造或指针绑定失败。

语义层现在同时检查局部、全局、实例字段和静态字段声明，沿类继承关系检查原生字段，并处理类型别名。没有唯一隐式绑定构造函数的多原生字段类也不能因而获得默认构造。诊断为：

```text
non-null native resource needs explicit initialization or nullable storage
```

显式构造、可空原生资源、普通类、原始指针别名及具有既定默认合同的内置 `mutex` 保持原行为。外部变量声明不受该初始化要求约束。

两个旧清理夹具中需要空状态的变量改为 `Handle?` / `MaybeBox?`。原生指针绑定夹具的提供方改用 `int64_t` 和 `PRId64`；析构函数采用声明要求的 `void` 返回值。这避免 Linux 上 `int64_t` 与 `long long` 是不同 C 类型所造成的重复声明冲突，并修正析构签名。
