# 资源引用投影与 float32 无损转换

Queue、SpscQueue、MpscQueue、MpmcQueue、WaitQueue、Channel、SlotMap、
mutex、cond、rwlock、sem 和 thread 的动态 `as` 转换接入既有统一
原生投影合同。成功保留同一对象身份，不克隆原生资源、不复制消息，
也不改变 SlotMap 的实例与键。`as float32` 使用独立的无损读取合同。

## 资源身份与完整策略

转换目标必须拥有完整的原生准入策略。见证对象是空的
`Array<目标类型>`，只保存独立拥有的不可变元数据；为转换建立见证
不会创建第二个队列、线程或操作系统同步对象。匹配复用各资源的
private owner 检查、逻辑身份、物理布局和完整元素策略。

Channel 和 SlotMap 新增递归引用准入，支持作为数组或队列的元素。
同一 TypeId、相同物理槽位或伪造句柄都不能冒充正确资源。普通赋值
和动态装箱只是保留引用，不因此开放 `copy()`／`clone()` 原生状态。
其他资源 ABI 不自动继承该规则。

严格错配抛 `TypeError`；nullable 错配返回 null。元数据创建、保活、
清理和原生读取的真正失败保持 checked 状态，包括没有诊断对象的
失败。源临时值在成功和异常路径均清理，输出仅在完整事务成功后提交。
已创建见证后的匹配无需分配；创建见证仍可能分配，整个 `as` 不是零分配。

## float32 转换边界

显式 `float32(x)` 正常舍入，有限值超过目标范围抛 `RangeError`，
NaN 与 Infinity 保留。`as float32` 和 typed 读取不采用此宽松规则：
源必须是匹配身份的 float 值，且有限数可以精确表示为 float32。
保存于 `var` 的 `1.1` 因而不能通过该投影，显式 `float32(1.1)` 可以舍入。

nullable 无损错配返回无值；原生 getter 失败仍为失败，不被误判为
无值。结果存在性、数值和成功状态相互独立，零值不能表示失败。
一次 getter 读取后检查数值域，成功才写入输出。

## IR 与部署

类型池在封闭前登记完整元数据见证。XLIR 校验目标、来源、策略、
只读或消费所有权及紧邻的状态分支；Cgen 只发出已验证配方和物理调用。
不在生成 C 中添加类型匹配算法，也不根据源码名称追溯语义。

Queue 和 SlotMap 的构造准备若未创建 schema，直接进入失败路径，
不把 NULL seed 继续传给消费者覆盖第一个 OOM。部署计划识别新增
Channel／SlotMap 布局，由共用符号访问器选择精确提供方与递归依赖。

资源投影、Channel 准入与 SlotMap 准入各自独立为驻留组件。
实际裁剪验收使用同一 IR 的部署计划及裁剪 XRT 实现，构建并运行
未剥离产物，要求真实符号表存在。组件内同文件函数仍可能一起保留，
不能把单函数未使用等同于整个组件应缺席。

## 验收范围

专项覆盖 NUL／Unicode、char／bytes、跨家族错配、相同身份但不同
元素策略、嵌套引用、临时源寿命、无诊断失败、严格 C O0/O2、JIT、
checked module、生产 AOT 与四个实际裁剪产物。374 个 IR 破坏反例
在 C／头文件输出前拒绝，另有丢失成功状态的生成代码负控。

Windows、Linux 普通与 Linux 指定实现插桩通道各 150 项通过；既有
六类容器的 Windows／Linux 回归各 166 项通过。精确导出目录包含
304 个组件、1507 个导出，92416 对依赖闭包和 23 个负控通过。

同步分配失败覆盖资源、float32 与无工作线程的嵌套同步领域用例，
O0/O2 分别穷举到首次未触发点。带 thread 的领域用例实际运行，
但不把当前线程故障账本当成工作线程分配前缀闭合证明。
三类语言用例的前缀数分别为 210、9、102（含首次未触发点）；
六类资源原生前缀分别为 20、20、21、25、17、17，账本均平衡。

Linux 插桩覆盖生成 C、测试宿主、共享投影事务、资源策略适配、
值准入和 SlotMap 实现；其他链接的编译器／XRT 提供方及额外裁剪
产物不在插桩范围。既有六类容器转换另行完整回归。

该专项不关闭其他动态／Native 编解码、线程与对象图故障、模块
组合、真实卸载以及 CLI／DLL／VFS 发布总门。WaitQueue 保持 MPMC
和 `(status, T?)` 拥有接收合同；对象池最后，未决策范围不变。
