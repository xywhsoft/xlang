# TaskGroup 的真实拥有图

TaskGroup 的活动链表、完成注册和取消观察者现在分别持有真实引用。
这补齐原生物理图，不等于语言层已经支持收集任务组循环。组的
Claim、语义终结、Clear、Finish 与桥接句柄策略仍需完整接通。

## 活动项和端点

活动链表拥有每个活动项的一份独立引用。完成注册拥有另一份引用，
Future 的认证策略直接描述真实活动项。完成摘链时只归还链表引用；
回调退出时再归还注册引用。预留启动失败同时回滚链表和尚未交付的
创建引用，不留下活动项或组引用。

活动项持有所属组、可选子组和源 Future。组分别 Trace 完成 Future
和未交付 Promise，即使它们属于同一个物理端点也不能合并强槽。
传播快照中的临时引用保留在实际计数中，前后链接只是借用节点，
不额外伪造拥有边。

## 取消和普通释放

组取消观察者使用 owned 策略，真实持有一份组引用。公开 Destroy
先关闭并请求活动项取消，再移走自己的 Watch 槽，在短 mutation
之外 Unwatch。已经开始的回调和派发尾部退役后才归还 Data 引用。
活动项自己的组引用继续保护尚未结束的任务，不把取消请求当作终态。

所有计数和槽转换参与全图冻结，通知与端点释放在短 mutation
之外执行。预留启动和组回调传播期间拒绝图检查。普通引用释放不
通过调用公开 Destroy 来重复触发关闭或取消语义。

## 验证和接入范围

原生固定图检查覆盖空组五节点七条边、单任务八节点十二条边、
嵌套组十一节点十九条边，以及公开拥有者提前释放后的延迟清理。
使用真实线程屏障验证启动窗口和取消回调的冻结外拒绝；完整分配、
释放、存活字节和非法释放计数必须平衡。

XRT 的模块化和单头测试还覆盖旧接口、OOM、并发、任务池、协程、
TCC 与 Linux ASan 和 UBSan。xlang 的 `check_task_group_physical.py`
分别编译两份实际消费单头；提供 public-directory 时校验完整源码
构建输入，再链接真实对象执行相同图测试。规范源码和消费头哈希
记录在 `lib/xrt/backports/task_group_physical.json`。

同步只应用 task 公共声明和原生组实现的增量，保留嵌入式 Future
及 TaskGroup 的微秒超时契约，不整体刷新上游。没有新增语言 API、
Cgen 特例或自动启用的叶子策略。正式任务组循环退役与全量发布
验收继续以完整生命周期和传递拥有图为准。
