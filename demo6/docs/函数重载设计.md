# xlang DEMO6 函数重载设计

本文档记录 DEMO6 的函数重载设计。

函数重载必须服从 DEMO6 第一绝对原则：xlang 能够和 C 完美混编。

## 1. 总原则

DEMO6 支持函数重载，但必须保持简单、静态、可诊断。

核心原则：

- 重载解析发生在编译期。
- 重载解析不做动态查找。
- 普通调用不使用返回类型选择重载。
- C ABI 不支持重载，导出到 C 必须显式指定唯一 C 符号。
- 找不到唯一最佳候选时，编译期报错。

## 2. 重载组

重载组由“作用域 + receiver + 名称”决定。

普通函数：

```text
fn:<module>.<name>
```

class 方法：

```text
method:<module>.<Type>.<name>
```

native-backed class extern 方法：

```text
method:<module>.<Type>.<name>
```

构造函数：

```text
create:<module>.<Type>
```

示例：

```xlang
func print(int value)
end

func print(string value)
end

class Vec2
    func scale(int value) as Vec2
        ...
    end

    func scale(float value) as Vec2
        ...
    end
end
```

其中：

- `print(int)` 和 `print(string)` 属于同一个普通函数重载组。
- `Vec2.scale(int)` 和 `Vec2.scale(float)` 属于 `Vec2` 的方法重载组。

## 3. 重载签名

重载签名由以下内容决定：

- 重载组。
- 参数类型列表。
- 可变参数种类。
- 泛型参数形态。

普通调用的重载签名不包含返回类型。

原因：

- `auto x = f(1)` 中返回类型可以参与推断，但 `f(1)` 本身必须先能唯一确定。
- `a, b = f(1)` 这类语句如果让返回类型参与重载，会让赋值语义反过来污染调用解析。
- C 语言也不能仅靠返回类型重载，xlang 与 C 混编时应避免这种分裂。

禁止只按返回类型重载：

```xlang
func parse(string text) as int
    ...
end

func parse(string text) as float
    ...
end
```

上例应编译时报错。

## 4. 可选参数与重载

可选参数会产生多个可调用形态。

示例：

```xlang
func add(int a, int b = 1) as int
    return a + b
end
```

它可以接受：

```text
add(int)
add(int,int)
```

为了稳定性，DEMO6 第一阶段采用严格规则：

- 同一重载组中，不允许两个函数产生相同的可调用形态。
- 可选参数产生的省略形态也参与冲突检查。

错误示例：

```xlang
func add(int a) as int
    return a
end

func add(int a, int b = 1) as int
    return a + b
end
```

原因：

- `add(1)` 同时匹配两个声明。
- 即使可以设计“非默认优先”，也会增加隐藏规则。
- DEMO6 第一阶段选择更直接的冲突报错。

## 5. 可变参数与重载

可变参数参与重载解析。

```xlang
func log(string text)
end

func log(string prefix, ...)
end
```

建议第一阶段规则：

- 固定参数候选优先于可变参数候选。
- 可变参数候选只有在没有固定参数唯一匹配时才参与选择。
- `...` 和 `***` 属于不同可变参数种类。
- 同一重载组中不能同时存在参数前缀完全相同、可变参数种类也相同的两个可变参数候选。

示例：

```xlang
log("hello")
```

优先选择：

```xlang
func log(string text)
```

而不是：

```xlang
func log(string prefix, ...)
```

## 6. 候选选择流程

重载解析按以下步骤执行：

1. 找到同一重载组中的候选。
2. 按名称、receiver、泛型显式类型参数过滤。
3. 按参数数量过滤。
4. 对泛型候选执行类型实参推断或显式实例化。
5. 对每个候选计算参数匹配成本。
6. 选择总成本最低的候选。
7. 如果最低成本候选唯一，解析成功。
8. 如果没有候选，报“无匹配重载”。
9. 如果最低成本不唯一，报“重载歧义”。

返回类型不参与第 5 步。

## 7. 匹配成本

DEMO6 第一阶段建议使用越小越优的成本模型。

建议成本：

```text
0    类型完全相同
1    整数字面量适配到目标整数类型
2    浮点字面量适配到目标浮点类型
10   安全数值提升
20   int 到 float 的安全提升
40   泛型实例化后匹配
80   装箱到 var
100  使用一个默认参数
200  可变参数匹配
```

暂不作为隐式匹配：

- `string` 到数字。
- 数字到 `bool`。
- `var` 到具体类型。
- class 子类到父类的按值传递。
- native-backed class 到 `point` 的自动转换。
- `point` 到 native-backed class 的自动转换。

说明：

- `var` 到具体类型必须显式转换，例如 `int(value)`。
- native-backed class 取原始句柄必须后续单独设计显式语法，不通过重载自动猜测。
- class 继承第一阶段只服务布局和成员继承，不默认做按值切片转换。

## 8. 数值重载

示例：

```xlang
func abs(int value) as int
    ...
end

func abs(float value) as float
    ...
end
```

调用：

```xlang
abs(1)
abs(1.0)
```

解析：

- `abs(1)` 选择 `abs(int)`。
- `abs(1.0)` 选择 `abs(float)`。

如果存在多个同成本数值提升，应报歧义。

示例：

```xlang
func f(int32 value)
end

func f(uint32 value)
end

f(1)
```

如果字面量类型无法唯一确定，应要求显式转换：

```xlang
f(int32(1))
```

## 9. var 与重载

`var` 是动态值类型，但重载解析仍然是静态过程。

规则：

- 实参静态类型为 `var` 时，只直接匹配参数类型为 `var` 的候选。
- 不自动把 `var` 拆成运行时具体类型参与重载。
- 如果需要调用具体类型重载，必须显式转换。

示例：

```xlang
func f(int value) as int
    return value
end

func f(var value) as int
    return 0
end

var x = 1
f(x)        // 选择 f(var)
f(int(x))   // 选择 f(int)
```

这条规则能避免运行时值改变导致调用目标改变。

## 10. 泛型与重载

泛型函数可以加入重载组。

```xlang
func pick<T>(T value) as T
    return value
end

func pick(string value) as string
    return value
end
```

规则：

- 显式泛型调用 `pick::<int>(1)` 只考虑类型参数数量匹配的泛型候选。
- 普通调用 `pick(1)` 可以考虑泛型候选。
- 非泛型候选和泛型候选成本相同时，优先选择非泛型候选。
- 泛型推断失败的候选直接移除。
- 泛型实例化后的 internal ABI symbol 由实例化签名决定。

示例：

```xlang
pick("a")
```

优先选择：

```xlang
func pick(string value) as string
```

而不是泛型版本。

## 11. func 类型与重载

重载函数名赋给 func 类型时，可以使用目标 func 类型选择候选。

示例：

```xlang
func convert(int value) as int
    return value + 1
end

func convert(string value) as string
    return value
end

func(int) as int op = convert
```

规则：

- 目标 func 类型提供参数类型和返回类型。
- 赋值时必须找到唯一完全兼容的候选。
- 若函数名有多个重载，而目标类型缺失，则报错。

错误示例：

```xlang
auto op = convert
```

原因：

- `auto` 没有提供函数签名。
- `convert` 是重载组，不是单个函数值。

## 12. 方法重载

方法重载使用 receiver 的静态类型选择重载组。

```xlang
class Buffer
    func write(string text) as int
        ...
    end

    func write(array<uint8> data) as int
        ...
    end
end

Buffer b
b.write("hello")
```

规则：

- receiver 不作为用户参数参与参数数量计算。
- receiver 类型参与重载组选择。
- 第一阶段不做虚分发。
- 子类继承父类方法时，先收集子类方法，再收集父类方法。
- 如果子类声明同名同参数类型方法，视为覆盖父类方法。
- 如果子类声明同名不同参数类型方法，视为加入该方法重载组。

## 13. native-backed class extern 方法重载

native-backed class 的 extern 方法可以重载，但必须对应不同 C 符号。

```xlang
class Image
    native void* handle

    extern "image_resize_i" func resize(int w, int h) as int
    extern "image_resize_f" func resize(float w, float h) as int
end
```

规则：

- xlang 侧重载解析选择 `resize(int,int)` 或 `resize(float,float)`。
- C 侧调用的是对应 `extern` 字符串中的 C 符号。
- 同一 class 内，不能把两个不同 extern 方法签名绑定到同一个 C 符号。

## 14. create 重载

用户层 `create(...)` 和 native-backed class 的 extern `__create__(...)` 使用同一套构造重载规则。

说明：普通 class 可以继续使用 `create(...)` 作为构造声明入口；编译器内部归一到 `__create__` 协议语义。native-backed class 绑定 C 构造函数时，推荐直接声明 extern `__create__`，避免把普通用户方法名和协议方法混淆。

```xlang
class Point
    int x
    int y

    create()
        self.x = 0
        self.y = 0
    end

    create(int x, int y)
        self.x = x
        self.y = y
    end
end
```

调用：

```xlang
Point()
Point(1, 2)
```

规则：

- class 的 `Type(...)` 解析到 `create:<module>.<Type>` 重载组。
- 如果 class 没有声明用户层 `create(...)` 或协议层 `__create__(...)`，`Type()` 使用默认构造，其他参数形式报错。
- 声明了 extern `__create__` 的 native-backed class，其 `Type(...)` 解析到 `create:<module>.<Type>` 重载组。
- 完全没有声明 `__create__` 的 native-backed class，不存在 `create` 重载组；已有 C 指针绑定必须走显式 native 绑定规则。
- 如果 native-backed class 声明了 extern `__create__`，则禁用直接指针绑定，避免构造与绑定语义混淆。
- `__destroy__` 不能重载。
- `__destroy__` 只能有一个无参数声明。

## 15. C ABI 与重载

C ABI 不支持 xlang 重载。

正确示例：

```xlang
func add(int a, int b) as int
    return a + b
end

func add(float a, float b) as float
    return a + b
end

export "add_i64" func add_i64(int a, int b) as int
    return add(a, b)
end

export "add_f64" func add_f64(float a, float b) as float
    return add(a, b)
end
```

规则：

- 重载函数本身可以作为 xlang 模块导出。
- 如果导出到 C，必须写唯一 C 符号。
- `export "same"` 指向多个重载时编译报错。
- C 头文件中只出现 C export symbol，不出现 xlang 重载组。

## 16. 诊断信息

重载相关错误必须给出候选列表。

无匹配：

```text
no overload matches add(string,int)
candidates:
  add(int,int) as int
  add(float,float) as float
```

歧义：

```text
ambiguous overload for f(1)
candidates:
  f(int32) as int32
  f(uint32) as uint32
hint:
  use int32(1) or uint32(1)
```

重复声明：

```text
duplicate overload add(int,int)
previous:
  add(int,int) as int at a.xl:10
current:
  add(int,int) as float at a.xl:20
```

## 17. 暂缓能力

以下能力暂缓：

- 返回类型参与普通调用重载解析。
- 命名参数参与重载解析。
- 调用侧数组展开。
- 调用侧字典展开。
- `var` 按运行时类型分派。
- 多模块重载合并冲突的复杂优先级。

以下能力已经进入下一批 class/OOP 设计，具体口径以 `class_object协议设计.md` 为准：

- 协议调用重载解析。
- 多参数 `__item__` / `__setItem__`。
- 运算符协议重载。
- 属性 `get` / `let` 重载。
- class `virtual` 动态派发。
