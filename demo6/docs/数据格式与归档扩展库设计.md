# 数据格式与归档扩展库设计

本文档是 DEMO6 数据格式、压缩与归档自带扩展库的当前设计口径。实现不兼容旧试验接口，不提供旧名称或旧返回值的回退路径。

## 目标

- 提供 `gzip`、`bz2`、`zip`、`tar`、`csv`、`ini`、`toml`、`plist`、`netrc`、`xml.sax`、`xml.etree`、`xml.dom`。
- C 与 xlang 共用同一套 XRT 格式引擎，xlang 层只承担声明、对象化和异常转换。
- 二进制数据固定使用 `Buffer`，文本固定使用 UTF-8 `string`。
- 文件访问固定经过 XRT 文件对象或 XRT 流接口，不直接使用 CRT 文件路径接口。
- 所有解析器和解压器具备明确的资源限制、安全默认值和损坏输入诊断。
- 扩展库采用源码 package，仅在被 `import` 时参与编译和链接。

本批模块已经进入发布实现，不再只是预留设计：

## 正式依赖

- gzip/Deflate：官方 zlib。固定版本、源代码清单和校验值后纳入发布扩展库。
- ZIP：libzip，Deflate 后端使用同一份 zlib。
- BZIP2：官方 libbzip2。
- TOML：tomlc17；XRT 另行实现编码器。
- XML：Expat；SAX、ElementTree 和 DOM 共用同一个解析核心。
- TAR、CSV、INI、netrc、binary plist：使用 XRT 风格实现，不引入重复的大型依赖。

`miniz` 是独立轻量扩展库，不是 `gzip`、`zip` 或 `tar` 的依赖。正式扩展库不得声明或调用 `xminiz_*` 符号。

## XRT 流基座

新增独立的 reader/writer 抽象，供格式引擎和 C 用户共同使用：

```c
typedef struct xreader_struct* xreader;
typedef struct xwriter_struct* xwriter;
```

reader 提供 `read`、`seek`、`tell`、`size`、`close`；writer 提供 `write`、`seek`、`tell`、`flush`、`close`。`seek` 和 `size` 可以由流声明为不支持。

XRT 必须提供以下适配器：

- `xfile` reader/writer。
- `xbuffer` reader/writer。
- 只读内存块 reader。
- 用户回调 reader/writer。

偏移和长度使用 64 位无符号整数；从外部格式转换时必须检查溢出。流对象具有明确所有权，包装既有 `xfile` 或 `xbuffer` 时可选择借用或接管。

## 公共资源限制

所有模块共享限制对象，至少包含：

- 最大输入字节数。
- 最大输出字节数。
- 最大单项字节数。
- 最大条目或节点数量。
- 最大嵌套深度。
- 最大解压比例。
- 是否允许符号链接、设备文件和外部实体。

便捷函数使用保守默认值；调用者可显式提高限制，但不能通过负数或溢出绕过检查。

## 压缩模块

### gzip

公开一次性 `compress`、`decompress`，增量 `GzipCompressor`、`GzipDecompressor`，以及流式文件便捷函数 `compressFile`、`decompressFile`。C 层通过 `xrtGzipCompressStream`、`xrtGzipDecompressStream` 直接组合任意 `xreader/xwriter`。

实现使用 zlib 的 `deflateInit2`、`inflateInit2` 等流接口，不使用 `gzopen`。必须支持 CRC 校验、截断检测、拼接 member、Buffer 和 XRT 文件流。确定性编码允许显式设置 `mtime=0`。

### bz2

公开与 gzip 对齐的一次性、增量和文件流接口。支持拼接 bzip2 流；随机 seek 不伪装为常数时间，不公开虚假的任意 seek。

## 归档模块

### zip

libzip 只能通过 `zip_source_function`/`zip_open_from_source` 接入 XRT reader/writer，不直接使用路径打开函数。

第一版支持 stored、Deflate、ZIP64、UTF-8 名称、内存归档、读取、创建、追加、替换、删除、重命名、CRC、注释、时间和权限。本批不启用 BZIP2、LZMA、Zstandard 与 AES；未来需要这些能力时只能按依赖接入，不在 ZIP 层重复实现算法。

写文件采用事务语义；失败时保留原归档。解压默认拒绝绝对路径、父目录穿越、Windows 盘符/UNC/设备名、越界符号链接、设备文件和超出资源限制的内容。

### tar

支持 ustar、PAX 和 GNU longname/longlink。压缩层复用 gzip、bz2、lzma 和 zstd，不在 TAR 模块中实现压缩算法。

普通文件和目录默认可提取；符号链接、硬链接与 FIFO 需要显式安全策略。硬链接在归档读取结束后解析，因此允许目标晚于链接出现，并拒绝自引用、循环和未解析目标。FIFO 仅在 POSIX 创建，Windows 明确报告平台不支持。

字符/块设备节点只解析、保留和写出 major/minor 元数据，提取端有意拒绝创建高权限设备节点。权限恢复只在 `preservePermissions=true` 时启用，并始终经过 `fileModeMask`；POSIX 在所有内容提取结束后统一应用，Windows 不伪装 POSIX 权限语义。

## 结构化文本模块

### csv

使用流式状态机实现 `Reader`、`Writer`、`DictReader`、`DictWriter`。支持引号内换行、双引号转义、自定义分隔符、换行风格、BOM、空字段和严格模式。CSV 值保持字符串，不自动推断数字和布尔类型。

### ini

使用 `Config` 对象保存 section、键值、顺序和注释。键名默认大小写敏感，重复 section/key 默认报错。提供显式的 string/int/float/bool getter；插值默认关闭，启用后只使用 `${section.key}`，并检测循环引用。

### toml

`parse/load` 返回嵌套 `var` 容器，`stringify/save` 提供确定性编码。整数、浮点、布尔、字符串和数组使用原生值；offset datetime 映射到 `time`，local date/time/datetime 使用专门值类型以保证无损往返。

### plist

支持 XML plist 与 binary plist。普通值映射为 `var` 容器；Data 映射为 `Buffer`，Date 映射为 `time`，UID 映射为 `PlistUID`。不采用 LGPL 的 libplist 静态实现，避免把额外发布义务传递给扩展库使用者。

### netrc

提供默认路径加载、machine/default/macdef、host 查询和修改。POSIX 下默认检查敏感文件权限；任何日志、诊断和字符串化接口都不得输出密码。

## XML 模块

Expat 作为唯一解析器核心：

- `xml.sax` 直接提供流式事件和回调。
- `xml.etree` 在 SAX 事件上构建轻量元素树。
- `xml.dom` 构建保留完整节点类型、父子关系和顺序的文档树。

默认禁止 DTD、外部实体和网络加载，并限制实体展开、深度、节点数、属性数和文本总量。XML 输入按 XML 声明和 BOM 解码，公开字符串统一转换为 UTF-8。

## 错误模型

xlang 层至少提供 `CompressionError`、`ArchiveError`、`CsvError`、`ConfigError`、`TomlError`、`PlistError` 和 `XmlError`。错误包含模块错误码、消息、输入位置；解析错误尽可能包含行、列和字节偏移。

公开 API 不使用 `lastError()`，不以空字符串、空 Buffer 或 `false` 表示无法区分的失败。可预期查询可返回 `null`，损坏输入、I/O 失败和资源限制必须抛异常。

## 包与裁剪

- `gzip` 依赖 `zlib`。
- `zip` 依赖 `zlib` 和 libzip 自身源码。
- `tar` 按格式依赖相应压缩 package。
- `xml.sax` 依赖私有 XML 核心，`xml.etree` 和 `xml.dom` 继续依赖 SAX/核心。
- 相同 package identity 由 resolver 去重，单个程序不得编译两份 zlib 或 Expat。

第三方源码、许可证、固定配置头和源码清单全部放入 package。用户机器不依赖 CMake、Autotools、系统 zlib 或系统 libzip。

## 验收标准

- 每个模块具有 C 与 xlang 对照测试和范例。
- `xl run` 与 `xl build` 行为一致。
- Windows UTF-8 路径、Linux 路径、Buffer 和大文件流均有覆盖。
- 与 Python 标准库或主流命令行工具进行双向互操作测试。
- 损坏、截断、空输入、超大声明、深层嵌套、路径穿越和压缩炸弹具有负例测试。
- parser/decoder 预留持续模糊测试入口，第三方库保留上游测试向量；进入正式 CI 后持续运行。
- 组合导入验证依赖去重、链接顺序和符号唯一性。
- 未导入相关模块时，生成程序不包含对应格式引擎。
- 所有资源均通过泄漏检查，重复创建/销毁和异常退出不残留句柄。
