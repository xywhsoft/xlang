# DEMO6 扩展库成熟度清单（2026-10-12）

> 本文是全量成熟度分类快照，不是当前开发队列。普通扩展库的最新维护边界、102 包清单与优先级见[普通扩展库开发优先级](普通扩展库开发优先级_2026-10-12.md)：XRT 扩展库及 XUI/XGE 转入专门上下文，C 类核心能力尚未实现的 78 包暂停开发。下文对这些包的历史建议不再作为当前排期依据。

## 口径与证据

活动目录 `release/extlibs` 共 215 包：208 个公共包、7 个内部依赖。本表对 208 个公共包逐一归类；上一轮移出发布目录的 12 个包另列于文末。`test/extlib_ecosystem.json` 的 `registered` / `budget-review` 是清点标签，不是成熟度。本表综合当前公开 API、已接入的直接源码、[2026-09-28 限定复核](扩展库现状再评估_2026-09-28.md)、[xregex 专项](扩展库xregex交付收口_2026-09-27.md)及本次正式 `release/xl.exe` 的重点用例；**没有逐 API、全平台、全套件重新认证**。

这里的“停止扩功能”是工程投入建议：维持现有公开范围，只做缺陷、安全修复与回归。它不等于可以跳过正式发布门禁。严格按“当前构建已在全部声明平台和全部 API 达到 RC”计算，**目前没有任何包获得这样的全域证明**。

## A. 功能冻结候选：9 包

`aho_corasick`, `bloom`, `chardet`, `crc32`, `md5`, `murmur3`, `sha3`, `siphash128`, `xregex`。

这些包已有实质实现、边界或双语专项基础；本次各自主测试在当前 `xl.exe` 退出码均为 0。可停止继续扩 API，把投入改为固定构建的定期回归、XRT 更新后的重验和文档维护。`md5` 仅用于兼容和校验场景，不能作为新密码安全方案推荐。`chardet` 的承诺是有限 Unicode 编码探测，不是任意字符集识别。`xregex` 的共享可变 matcher 并发边界仍须遵守其合同。上述专项不能替代完整 Linux XL、ARM 或长期性能验收。

## B. 已有实际能力，但仍需完善或验收：121 包

下列包至少有可用的限定功能、真实封装或已存在的后端，不宜按“占位库”重写；但公开范围、质量或当前正式构建尚不足以停止投入。名单完整列出：

- A–F：`ansi`, `argon2`, `barcode`, `blake2`, `blake3`, `brotli`, `bson`, `bz2`, `cbor`, `cli`, `clipboard`, `color`, `com`, `consistent_hash`, `crontab`, `css`, `cString`, `csv`, `cuckoo`, `daemon`, `diff`, `dinov3`, `dotenv`, `epub`, `fix`, `floatEnv`, `fuzzy`。
- G–M：`geohash`, `gettext`, `graph`, `gzip`, `hcl`, `hyperloglog`, `ical`, `imagehash`, `ini`, `json.patch`, `json5`, `jwt`, `langdetect`, `linalg`, `lru`, `lz4`, `lzma`, `md4c`, `miniz`, `money`, `msgpack`。
- N–S：`netrc`, `oauth2`, `onnxruntime`, `op`, `opencv`, `pinyin`, `pkcs`, `plist`, `procps`, `progress`, `qr`, `rapidocr`, `redis`, `roaring`, `rss`, `rtree`, `semver`, `serial`, `sharedmem`, `shellwords`, `singleinstance`, `sitemap`, `skiplist`, `slugify`, `snappy`, `sqlite`, `srt`, `statistics`, `stb_image`, `stb_image_resize2`, `stb_image_write`, `stb_truetype`, `sysinfo`。
- T–Z：`tabulate`, `tar`, `terraform_state`, `toml`, `totp`, `trie`, `ui.auto`, `uia`, `units`, `vcard`, `volc.core`, `volc.phone`, `volc.sts`, `watch`, `xbot.agent`, `xfeat`, `xge`, `xge_shape_ex`, `xhttp`, `xhttp.body`, `xhttp.body_async`, `xhttp.body_codec`, `xhttp.body_decode`, `xhttp.body_file`, `xhttp.body_stream`, `xhttp.client`, `xhttp.form_data`, `xhttp.multipart`, `xhttp.protocol`, `xmail`, `xml.dom`, `xml.etree`, `xml.sax`, `xssh`, `xui`, `xws`, `xxhash`, `yaml`, `zip`, `zstd`。

**B1：优先解决发布阻断，不应另加功能。** `sqlite` 当前主用例与范例报 XLIR runtime operation ABI 未解析；`ini` 范例报 `xini_parse` 原型冲突。`blake2`、`blake3`、`brotli`、`lz4`、`lzma`、`miniz`、`snappy`、`xxhash`、`zstd` 的当前主用例在 `bytes` 实参检查失败；`argon2`、`bz2` 在 typed XLIR 物理路径失败。这 11 项集中指向共享编译器/类型边界，不能简单算作 11 个独立算法缺陷。`csv`、`graph`、`color` 主用例当前通过，但已有正式默认参数、含 NUL 文本、OOM 等边界记录；`cli`、`dotenv`、`fix`、`css`、`hcl` 也有历史合同/生成问题，须在新构建上复验。

**B2：真实后端需要成功路径和资源合同。** `xhttp` 家族、`xws`、`xmail`、`xssh` 要完成 TLS/回环、拆包、取消、连接复用与关闭竞争；客户端生成耗时要单独定位。`onnxruntime`、`rapidocr`、`opencv`、`xfeat`、`dinov3` 必须用固定模型/图像验真，不能只测后端缺失。`xui`、`xge`、`op`、`uia`、`ui.auto` 需要真实桌面交互和销毁检查。`xbot.agent` 有路径解析与读取限额风险。`redis` 要验证真实服务的分包、断线和错误恢复。

**B3：功能限定或证据不足，按具体任务补门禁。** 其余 B 包通常已有狭义实用功能，但不少只有单个范例或登记，没有完整 C ABI、并发/内存、跨平台、互操作验证。例如 `linalg` 仅提供小维向量运算，`json5` 是查询型表层；不得按同名大型框架宣传。`lzma`/`miniz`/`snappy` 流格式的独立互操作、`zstd` 标准格式验证也未闭环。B3 进入 A 必须先明确承诺范围并补当前正式构建证据。

## C. 同名核心能力尚未实现：78 包

这些包**不是零行代码**：不少提供名称表、计算辅助、协议帧或请求片段。问题是包名通常暗示数据库、推理、设备、协议客户端等完整能力，而当前公开面不能完成对应核心任务。开发前先决定是补真实后端、改成准确的窄名称，还是移出发布目录；不能靠现有 helper 测试判定产品可用。

- A–G：`acme`, `canbus`, `clickhouse`, `clip`, `coap`, `dataframe`, `dns`, `docker`, `embeddings`, `enet`, `etcd`, `faiss`, `flatbuffers`, `freetype`, `ftp`, `ggml`, `git`, `glad`, `gpio`。
- H–M：`harfbuzz`, `hnswlib`, `html5`, `icu`, `imgui`, `influxdb`, `jieba`, `kubernetes`, `ldap`, `leveldb`, `libsndfile`, `libsvm`, `libusb`, `llama`, `lmdb`, `mdns`, `memcached`, `minio`, `mnn`, `modbus`, `mongodb`, `mqtt`, `mysql`。
- N–R：`nanomsg`, `ncnn`, `neo4j`, `nsq`, `ntp`, `opentelemetry`, `openvino`, `opus`, `passkey`, `pcap`, `pdf`, `pdfium`, `portaudio`, `postgresql`, `pptx`, `prometheus`, `rabbitmq`, `ratatui`, `rocksdb`, `rtmp`。
- S–Z：`sciter`, `sentencepiece`, `snmp`, `socks`, `sox`, `taglib`, `tdengine`, `tokenizers`, `treesitter`, `upnp`, `vault`, `vectordb`, `webview`, `whisper`, `xbot`, `zeromq`。

**优先投资的 C 包：** `mysql` / `postgresql` 二选一先做真实远端 SQL 驱动；`mqtt` 从已存在的帧与握手推进到客户端生命周期；`opentelemetry` / `prometheus` 先选最小可用的指标与导出闭环；`dns` 如标准库已有足够解析能力，则只补缺口或并入标准库。`faiss` 与 `xbot` 已有其他位置的相关基础，应先决定既有能力整合边界，再谈新实现。

**优先降级或移出的 C 包：** GPU/AI 框架、专业数据库、音视频、GUI 工具箱、云管理、设备协议等没有实际后端的同名包。`libusb` 当前甚至使用固定的模拟设备表，不能以真实 USB 枚举对外展示；`acme` 仅构造部分 JSON/挑战文本；`postgresql` 只做连接参数和 wire 片段；`influxdb` 只生成 line protocol；`faiss` 只有距离运算，没有索引。这些事实足以说明发布宣传范围需要收窄，但不抹掉协议片段本身的复用价值。`mysql`、`faiss` 有进行中的本地修改，本表仅按当前公开面分类，不移动或覆盖其工作。

## 本次抽样结果与后续准入

当前正式 `xl.exe`（SHA-256 `616888E9DA0097E5449CB4ABD25FC42F87606D836611B3D739860CE57E2D1E3F`）执行 19 个 featured 主用例：**8 通过、11 失败**。另执行 `chardet`、`xregex`、`graph`、`color`、`csv` 主用例均通过；`sqlite` 主用例失败，`ini` 范例失败。以上是选定入口，不是全部 208 包的测试结果，也不能把失败直接归咎于包源码。

进入 A 的最低要求：明确狭义 API 合同；当前 CLI/DLL 所需路径通过；C/XL 双语范例与 ABI、错误/所有权、异常、边界测试通过；有目标平台和可复跑记录。进入首期公开生态的 C 包，先证明一项真实用户任务可以完成。大量 B/C 包没有足够的新鲜证据，后续应按投资优先级逐个复核，不把本表当作产品认证。

内部依赖 `_bzip2`、`_expat`、`_libzip`、`_tomlc17`、`_xge_native`、`_zlib`、`pkg.math` 不计入 208 个公共包；它们由使用方的门禁验收。上一轮已移出发布目录的 `docx`、`duckdb`、`ffmpeg`、`grpc`、`libtorch`、`nats`、`protobuf`、`quic`、`stablediffusion`、`tensorrt`、`webrtc`、`xlsx` 也不在本表 208 包内；参见 [生态重整决策](扩展库生态重整_2026-10-12.md)。
