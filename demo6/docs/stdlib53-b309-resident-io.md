# IO 的驻留实现和文件流回调

同步 IO 的 51 个适配入口已迁入运行时，包括文件整体读写、
Reader、Writer、行读取、复制以及 File 的 reader 和 writer。
Cgen 不再生成这些函数体或 File 流回调。公开 API 和参数合同
保持不变，本批不把进程流认证为无拥有边的资源。

## 组件和调用边界

实现分为 17 个组件。文件、内存和标准流的构造分别登记，避免
仅使用内存 Reader 的程序引入文件打开或标准输入输出生产者。
读取、写入、位置操作、行读取和复制也使用独立生产单元。
精确导出表连接已验证的 XLIR 调用与运行时组件，不由 Cgen
按函数名猜测实现。连同六个新增拥有域和三个派生文件资源的
析构，组件累计 418 项，目录有 1752 个精确导出、75 个拥有域
和 48 项 Handle 策略。

File 流的读写、定位、统计、刷新和关闭回调位于同一个驻留
生产单元，继续持有 File 的真实原生引用。File 对象先离开作用域
不会使存活流失效；最后一个流关闭后仍按原规则处理临时文件。
行读取继续接管原 Reader 的 stream，构造失败则不接管。

MappedFile、FileLock 和 FileRoot 的析构也迁入驻留单元，避免
文件流用例在业务断言结束后仍被旧析构回调阻止 AOT 退役。
它们只保存原生映射、原生 File 引用或目录句柄及诊断路径，
不保存语言对象。Cgen 与驻留实现共用同一份物理布局声明。

路径按完整 string 长度拒绝内嵌 NUL。数据保留完整 bytes 或
string 字节长度，可选长度仍按已批准规则截断至实际长度。
不增加 strlen，不隐式转换编码，也不改变显式 close 的错误合同。

## 失败和销毁

包装分配失败时先保存首个错误，再关闭已创建流和释放拥有者，
最后恢复原错误。首个失败没有诊断对象时，同样清除清理阶段的
次生错误；不能仅凭错误指针非空来判断失败是否发生。

显式 close 先摘除 stream，再调用底层关闭，因此失败后也不会
重复关闭同一资源。析构继续为 no-raise，保留进入前的错误状态。
Writer 的自有 Buffer 在 stream 关闭后仍可生成独立 bytes 值，
直到 Writer 自身销毁才释放，不把 close 改成对象析构。

## Windows 构建

DLL 对象改用 GCC 响应文件。对象清单从显式编译命令导出并逐项
检查存在性、重复项和路径，不扫描构建目录中的通配对象，也不
借用旧配置的产物。普通 build.bat 同时构建运行时和编译器 DLL；
组件增加不再扩大批处理累加变量或每次链接的命令行长度。

目录专项提供显式并发上限，严格 C 清单采用流式 JSON 和原子
报告替换，降低大批并行验证的内存峰值。内存不足的旧候选保留，
复测不删除用例、不减少原断言，也不把资源压力当作产品通过。

## 内建流的拥有策略

Reader、Writer 和行读取使用独立的驻留拥有策略。私有工厂写入
不可变来源：文件、内存快照、自有 Buffer 和标准流只拥有原生
资源；文件回调也不保存语言值或生成模块地址。

Process 的 stream 工厂显式标注进程来源，行读取接管时传递该
来源。未知和进程来源在追踪阶段拒绝，不能继承内建流的叶子
合同。追踪只检查不可变来源，不读取与 close 并发修改的 stream
状态，也不通过关闭进程或隐藏 Future 边来使检查通过。

## 专项验证

原生专项使用十种真实工厂，逐分配失败直至首次未命中，核对
分配数量、字节、File 引用和接管状态。另检查首个错误对象及
NULL 诊断的保留、显式关闭失败和恰好关闭一次。六个来源拒绝
负例使用真实拥有流，不替换原生生产者或调用隐藏边。

十二份原有语言用例保留原断言，经严格生成 C、JIT 和搬离后的
独立 AOT 执行，包含 IO 分配失败、文件流存活和临时文件清理。
内存 NUL、长度、行结束和按需裁剪检查均不以新夹具替换原断言。
Linux 插桩仅覆盖本专项选定的 22 个真实生产单元，包括完整
XRT 与 xruntime 核心；其他驻留生产者和产品执行不冒称插桩。

20 个 IO 与派生文件资源对象的未解析符号逐一对照组件的传递依赖和
XRT 预处理模块闭包。移除 ReaderData 的 IO_BUFFER 依赖必须
检出 ReadAll 缺口，不能等完整 XRT 的宿主链接掩盖缺失后才
声称裁剪正确。VALUE 和 BUFFER 的直接引用也接受相同检查。

原生资源专项增至 41 类策略和 82 个伪造拒绝。IR 逐一核对
40 个析构入口与对应字段，并在输出前拒绝 160 个破坏合同的
变体。新增独立 AOT 循环对象在析构中读取内存流、保留的 File
流和行数据，检查最终标记恰好出现一次。

信号事件快照的堆计量以调度器同步 shutdown 为边界。Off 只
保证用户回调已经结束，调度器最后持有的 watch 引用仍可能
稍后释放；专项实际等待并释放该拥有者，不延时猜测或扣减账本。

## 继续工作

内建流已声明精确拥有策略，但进程流
持有 ProcessLive，原生进程的共享等待 Future 和续体可能继续
拥有模块引用；这一传递关系必须真实追踪，不能套用叶子策略。
任务组、取消观察者和活动任务同样继续审计。静态入口登记的
缺口与运行时来源的传递拥有图是两类检查，不能用前者的数量
宣称全部原生资源已经收口。

终端 resize 的历史间歇问题、完整 exit 清理、函数级覆盖和
发布总门继续。没有新增公开 API 决策，CRT 无未决项，XRT
十九组未决项和对象池最后的顺序保持不变。
