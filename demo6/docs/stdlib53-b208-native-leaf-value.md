# 不可变原生值在开放 Set 中的内容语义

开放 `set<var>` 的键策略区分可变引用与不可变基础值。SlotMapKey 使用
通用的驻留原生值投影，独立装箱的同一个键按内容去重；普通可变对象、
容器、Future 与外来 native handle 仍按引用身份处理。

## 明确的值能力

原生值投影使用固定的生产者 operations，内容合同包含永久驻留的类型、
名义身份、相等与哈希和空输出判断。合同明确禁止可变内容、语言图拥有边、
生成的回调以及短寿命模块内元数据。仅有相同类型 ID 或自定义 Hash／Equal
回调的外来句柄不取得这一能力；检查生产者后才读取原生载荷。

SlotMapKey 投影复用此通用实现，不再自行管理另一套盒子拥有权和 checked
复制事务。复制读取保留原生实例记录，不分配内容；目标已占用时拒绝。
部分复制以及有／无诊断失败清理输出，保留沿途 checked 失败。

## 裁剪与接入边界

Set 键策略只依赖通用原生值组件，不依赖 SlotMap 键类型、装箱适配器、
准入工厂或槽表算法。SlotMap 原生存储仍不因本修改选择键装箱。
键的真实 native typed 存储与开放 Value 存储使用一致的内容合同，不产生排序能力。

这是语言 API 的前置值合同，不是 SlotMapKey 直接 C ABI、frame 或
SlotMap 公开构造／方法／迭代的完成声明。三个分类的 53 模块总验收继续；
XRT 供应库、发布 DLL／SO 和 TCC 不在本批修改范围内。

## 验证范围

Windows／Linux 源码构建分别重新编译 300／299 个对象。双端键投影
各通过 67 阶段、16 次完整故障前缀及 5 个实际编译损坏实现拒绝；
拥有型值容器各通过 74 阶段、86 次完整故障前缀及 4 个错误实现拒绝。
原生 SlotMap 各 58 阶段、32 次故障前缀通过；可变 Set 身份策略
12 阶段和 4 个错误实现拒绝，以及 Set 存储 102 阶段和 8 个错误实现
拒绝通过。上述 Linux 原生闭包的 O0／O2 ASan／UBSan 均通过。

真实源程序各通过 8 阶段：公开 JIT、确定性 C 生成和严格 O0／O2 C
消费者。真实槽表生成的两个相同键和一个跨实例键，经公开 `var` 参数
进入语言 Set，去重、独立复制和释放平衡正常；string／bytes 内容键与
可变容器身份键同时验证。此消费者链接源码构建的驻留对象，不是裁剪
后的发布产物，也不表示语言 SlotMapKey 直接 ABI 已完成。

真实目录确认 261 个组件、1386 个实际导出及 68121 个依赖对；13 个
损坏目录拒绝和额外的通用 Set 不选择键组件合同通过。相邻 Dict 真实
裁剪产物各 225 阶段、480 项损坏 IR 拒绝和 666 次故障前缀通过。
