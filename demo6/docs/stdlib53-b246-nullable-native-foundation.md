# 可空原生键的拥有值底座

2026-10-13。原生可空 SlotMapKey 的布局、复制、移动、释放和动态值
转换已通过 Windows／Linux 专项。该底座用于后续语言可空原生值接线；
当前尚未登记语言表示、IR 生命周期或 Stack 的 try 接口，不能据此声称
`Stack<SlotMapKey>.tryPop()` 已可用。三组标准库长期任务继续进行。

## 表示与所有权

`XL6_NullableSlotMapKeyV1` 包含独立的 `hasValue` 和拥有的 SlotMapKey。
缺席时载荷为空，但存在的空键仍是存在，不能靠载荷比特推断 presence。
普通原生复制和移动不创建堆装箱；动态 xvalue 边界才使用现有认证的
原生叶值装箱，缺席映射到动态 null。动态往返保留“存在的空键”。

类型描述使用独立 ABI 身份、实际 size／alignment 及 Init／Copy／
Move／Drop／Clone。C 赋值只观察或转移已有拥有权；Copy 才取得独立
拥有权。类型没有被标成 POD，也没有以借入指针代替拥有记录。

## 失败不发布，清理不依赖存在位

复制、包装、投影和解箱均先取得临时拥有值，归一 checked 结果后才
发布。返回 false、部分取得后 false、成功伴随诊断均按失败处理，
清理临时引用。初始化目标的 typed Copy 失败时保留原值，成功后再
退休旧值；公开 acquire 接口要求对齐的空目标，非法目标保持不变。

投影同样使用临时键，不把部分取得的引用写进调用者结果。清理不能
只看 `hasValue`：复制过程中载荷可能已经取得，存在位尚未发布。
精确 self-copy／self-move 保持合法；部分重叠被拒绝。成功复制保留
调用前已有诊断，失败仍通过现有外部错误作用域传播。

## 按需组件与构建

追加一个组件身份和 8 个精确登记的私有入口，不改变已有组件编号。
显式依赖原生键、原生键动态值及外部错误组件，复用 XRT typed 类型。
Windows／Linux 常规构建和完整源码检测驱动均加入同一个供应方。
没有修改 XRT／xruntime 单头、语言标准库登记、IR 或 Cgen。

显式原生单位闭包只选 5 个供应方，不拉入 SlotMap 存储、Stack、Dict
或编译器；独立产物符号也检查这些排除项。实际普通语言程序的原生
计划不选择可空键供应方。这是底座单位闭包和未使用裁剪证明，不是
尚未接通的语言可空键程序的 JIT／AOT 证明。

## 验收证据与边界

Windows 318、Linux 317 个完整源码编译单元通过。底座专项分别通过
108、138 个阶段，每端 O0／O2 共 42 组、76 次完整失败前缀运行。
每个优化等级各执行 1000 次生命周期向量，检查存在／缺席、存在的
空键、初始化目标替换、移动、动态往返、非法输入、继承错误及部分
拥有值清理。复制只 retain 的路径可能不分配，报告如实记录无注入
分配，不把它计为发生过 OOM。

三个实际编译链接的坏供应方均被拒绝：丢弃存在位未发布的部分引用、
未检查诊断就替换拥有记录、未检查诊断就发布投影。Linux ASan／UBSan
覆盖所选供应方、原生实现和测试宿主，不外推为整个编译器插桩。
测试检查内存分配、释放、存活数量和字节平衡，故障后均清理并重试。

源码和报告保存在 `E:/xlang-validation/stdlib53-b246-*`；Linux 原生
报告保存在 `/var/tmp/xlang-stdlib53-b246-*`。本批提交证书逐项核对
所选源码、编译输入、产物和日志，不以 shipping 编译器替代源码构建。
