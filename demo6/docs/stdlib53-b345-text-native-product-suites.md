# 文本原生测试的真实产品验收

十四份既有 C 测试宿主已通过当前 Windows 与 Linux 的运行库、编译库验收。
原断言保持不变，消费对象分别以 O0、O2 编译，每端 56 个组合通过。
本批新增验收门和账本观察器，不修改生产编译器、标准库或 XRT 快照。

## 功能与实际链接

宿主覆盖字符串编辑、查询、char／bytes、eager／lazy 拆分与连接、数字解析和
格式化、Unicode／HTML、五种 Unicode 编码与检测，以及 Regex 和 Pattern。
既有断言继续检查内嵌 NUL、UTF-8 字节边界、精确值类型、拥有返回、独立快照、
事务失败回滚、线程限制、迭代重试和 allocator 回调重入。编码检测保留
30,000 次查询的分配计数检查及拒绝分配时的普通查询。

消费者只链接选定的实际 DLL／SO，不编入驻留运行时、XRT 或编译器实现对象。
检查器在链接前检查消费对象的外部定义，并核对最终导入的运行库身份。
头文件来自同次产品构建，原宿主断言字节与冻结来源逐一比较。

宿主仍使用已有测试辅助函数和独立逻辑类型 ID；数字诊断映射与 Pattern ID
映射的少量私有 inline 参考检查也保留。这些检查不冒充相应 DLL 函数的执行，
语言层规范类型身份由独立的 JIT／模块和 AOT 用例验证。

## 分配故障模型

以下统计均为每个操作系统的四种产品／优化组合之和，三种模型分别计数。

| 模型 | 覆盖 | 触发故障数 |
|---|---|---|
| 原宿主分配器的持续物理失败 | 40 模式，160 条完整前缀 | 1,300 |
| Regex／Pattern 的线程局部一次性逻辑失败 | 33 家族，132 条原生前缀 | 2,160 |
| 字符串编辑的首个物理分配失败 | 19 操作，76 次单点检查 | 76 |

物理前缀在新的消费进程中从第一个实际 allocator 请求开始，保留旧宿主的
持续失败行为；确认首个未触发点及其下一个点均符合正常预期结果。成功的
内部堆缓存请求不一定调用物理 allocator，不能把这组统计称为所有逻辑
分配点。测试选择的四十个操作都必须真实触发故障，零故障不能冒充完整前缀。

Regex／Pattern 保留原宿主内的完整逐点逻辑失败循环及首个未触发确认，
不虚构额外的第二个未触发点。迭代器失败重试、Buffer 事务不变、原始回调
异常和构造／编译／标签快照的清理继续由这些原断言验证。

数字的语法错误、范围错误与非法 Unicode 输入在未触发资源故障时仍可按
预期 checked 拒绝；这里的前缀结束表示预期语义成立，不一概解释为操作成功。
这些 C 接口故障证据不替代语言装箱、未插桩 JIT 或所有工作线程同时 OOM 的验证。

## 堆账本与拒绝控制

消费端透明观察 `xrtMemDebugReset`，调用实际产品函数一次并原样返回结果。
每次清零前检查真实 live 数量与字节、分配／释放差和 invalid free、double
free、use after free 计数，再累计清零前的账本。宿主结束后还须无资源和
未处理错误，累计分配与释放相等。第一次分配就失败时，零分配、零释放是
合法结果，不应被检查器误拒绝；初轮误拒绝日志保留。

原 allocator 重入探针为触发真实 backing free，主动关闭 debug quarantine。
它单独编译为四个实际产品程序，保留回调重入和脱离输入后的状态断言，明确
不接受其空调试账本作为完整堆证明。其余向量和故障前缀在每次清零及结束
检查时都必须保持调试开启；关闭跟踪不能把资源错误隐藏在零计数里。

每端十一项拒绝控制通过。两种产品分别验证结束时泄漏、清零前泄漏和关闭
调试记录，六个程序成功编译后被实际断言拒绝。另四个程序分别移除物理或
逻辑注入，真实操作可以完成，但被同一前缀检查谓词拒绝。最后一个伪造驻留
入口控制先编译，再由对象定义检查拒绝，含 CRLF 对照。

只有消费调用点的 reset 被观察，DLL／SO 内部调用不被替换。这不是生产库
全量 sanitizer、操作系统线程 join 或镜像卸载保证。
