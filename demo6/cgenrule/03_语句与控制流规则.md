## 本轮补充：typed container 成员 func 返回值接管

`array<int> values = maker.values()` 与 `values = maker.values()` 这类写法现在纳入 typed container move 接管分支。成员 func 字段会先保存为 `XL6_Function __xl6_member_fn_stmt_N = maker.values;`，再按静态容器 ABI 生成 `xtarray` direct invoke。该路径与顶层 `makeValues()` 一样接管返回句柄所有权，不进行额外 copy；赋值时先把新句柄写入临时 `__xl6_typed_container_assign_N`，再销毁旧容器并替换目标。对应实现位于 `xl6_cgen_value_object.c:128`、`174`、`xl6_cgen_stmt_decl.c:409`、`xl6_cgen_value_assign_target.c:704`，调用 ABI 类型由 `xl6_cgen_function_value.c:548` 与 `xl6_cgen_expr_support_base.c:92` 兜住。

守门用例为 `cgen_typed_container_for_in_returned.xl`，`test.bat` 已固定 direct `xtarray` invoke 形态，并禁止 typed container 成员调用退回 `xl6_function_call_var` 或 GNU 语句表达式。

## 本轮补充：声明与表达式语句中的 class 返回实参临时化

`readPayload(maker.make(90)) + 1` 和 `expect(readPayload(maker.make(100)) + 1, 101)` 这类写法虽然外层是普通声明初始化或表达式语句，但内层实参来自返回 `class` 的成员 func。当前声明/表达式语句生成器会先扫描表达式树，收集这类需要生命周期管理的 class 返回实参，输出 `XL_Class_Payload __xl6_class_arg_N = {0};` 和 `XL6_Function __xl6_member_fn_stmt_N = maker.make;`，再通过表达式替换表把原始调用点替换成临时变量名。目标表达式生成完毕后，立即输出 `xl_class_Payload__destroy(&__xl6_class_arg_N);`。

该路径对应实现位于 `xl6_cgen_stmt_decl_class_temp.c:125`、`223`、`264`、`443`、`478`、`1158`，表达式替换表定义位于 `xl6_cgen_core_context.c:73`，替换入口位于 `xl6_cgen_expr.c:10`。`test.bat` 已固定 `nestedArgumentValue = (readPayload(__xl6_class_arg_` 和 `expect_i64((readPayload(__xl6_class_arg_`，并禁止重新生成 inline `maker.make.signature` 或 `readPayload(({ XL6_Function ... }))` 形态。

## 本轮补充：表达式语句临时结果丢弃

`mark(1) + mark(2)`、`mark(3) == mark(3)`、`mark(0) or mark(5)`、`2 in [1, 2, 3]` 这类表达式语句现在会先尝试 `xl6CgenTryDiscardExpressionStatement`。如果表达式需要动态值临时、短路求值、membership RHS 临时或条件分支临时，生成器先输出 `__xl6_expr_stmt_N` 目标，再复用 return/声明/实参的语句级 lowering 把结果写入临时。`null` / 无值结果不接管，继续交给原表达式语句路径。对 xvalue 结果，兜底分支也不再直接调用表达式级 `xl6CgenXValueFromExprForTarget`，而是复用 `xl6CgenDeclEmitXValueExprInit`，确保动态二元、动态条件、动态空合并和动态数组字面量都按多条标准 C 语句求值。表达式语句结束后直接输出 `if (__xl6_expr_stmt_N != 0) { xvoUnref(__xl6_expr_stmt_N); __xl6_expr_stmt_N = 0; }`，不依赖 callable runtime 的 `xl6_xvalue_drop` helper。

该路径对应实现位于 `xl6_cgen_stmt_dispatch.c:193`、`xl6_cgen_stmt_dispatch.c:211`、`xl6_cgen_stmt_dispatch.c:241` 与表达式语句分支 `xl6_cgen_stmt_dispatch.c:363`。守门用例为 `cgen_expr_statement_discard.xl`；`test.bat` 要求生成 `xvalue __xl6_expr_stmt_`、`int __xl6_expr_stmt_`、`xvoUnref(__xl6_expr_stmt_`、动态二元/比较/近似/逻辑/membership 的语句级赋值形态，并禁止 `__xl6_expr_stmt_` 路径出现 `({`。

## 本轮补充：动态数组字面量逐项求值

`var values = [a(), b()]`、`return [mark(1) + mark(2)]`、`[mark(9) + mark(10)]` 这类动态 `array` / `var` 数组字面量现在会优先走 `xl6CgenDeclTryXValueArrayLiteralInit`。生成器先输出 `xvalue target = xvoCreateArray();`，再按源码顺序为每个元素生成 `xvalue __xl6_array_item_N` 临时，复用 xvalue 数组字面量、`??`、动态二元、动态条件表达式等声明级 lowering，最后逐项调用 `xvoArrayAppendValue(target, item, true)`。这样避免把复杂元素塞进 `xl6_xrt_array_varargs(...)` 的 C 实参列表，也避免在元素中回退到 GNU statement expression。

该路径对应实现位于 `xl6_cgen_stmt_decl_array.c:1-83`，声明入口接入点为 `xl6_cgen_stmt_decl_main.c:298`，单值 return 接入点为 `xl6_cgen_stmt_dispatch.c:45`，表达式语句通过 `xl6CgenTryDiscardExpressionStatement` 复用 return lowering。动态 `array<var>` 不再绑定专门 runtime generic desc，底层边界位于 `xl6_cgen_core_runtime_state.c:64-78`，只有非 `var` 泛型容器继续生成运行时类型描述。守门用例为 `cgen_array_literal_expr_elements.xl`，`test.bat` 要求 return、声明、表达式语句三条路径都生成 `xvoCreateArray` / `__xl6_array_item_` / `xvoArrayAppendValue`，并禁止 `xl6_xrt_array_varargs(3, ({`、`({ xvalue __xl6_bin_left_` 和动态 `array<var>` 的 `runtime_type_desc_` 回流。

## 本轮补充：前缀数组字面量逐项求值

`array[a(), b()]` 前缀写法在动态 `var` / `array` 目标上也复用 `xl6CgenDeclTryXValueArrayLiteralInit`。生成规则与普通 `[a(), b()]` 一致：先生成 `xvalue target = xvoCreateArray();`，再为每个元素生成 `__xl6_array_item_N`，最后按源码顺序调用 `xvoArrayAppendValue(target, item, true)`。静态 `array<T>` 声明仍优先进入 typed-container 生成路径，不被这个动态 xvalue helper 接管。
