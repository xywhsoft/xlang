# P2 符号命名与类型映射细则

本文细化 `xl6_cgen_core_names.c`、`xl6_cgen_core_types.c`、`xl6_cgen_core_lookup.c` 和 `xl6_cgen_symbol.c`。这些分片多数不直接输出完整语句，但会决定 C 符号名、C 类型名、重载后缀、泛型实例名和声明查找结果，因此属于代码生成形态的一部分。

## CGEN-NAM-001 UTF-8 标识符逐码点读取

| 项目 | 内容 |
|---|---|
| xlang 写法 | 中文标识符、非 ASCII 标识符，例如 `变量`、`类名` |
| 生成规则描述 | C 符号编码前先用 `xl6CgenNextUtf8Codepoint` 逐码点读取 UTF-8。支持 1 到 4 字节序列；无法识别的字节按单字节推进，避免编码循环卡死。 |
| 生成器文件名和行号 | `demo6/src/cgen/xl6_cgen_core_names.c:18` |
| 对应生成的 C 代码 | 不直接输出 C；影响后续所有编码后的 C 标识符。 |
| 中间形态伪代码 | `if ascii return byte; else decode 2/3/4-byte utf8; invalid -> byte` |
| 实现同等功能手写的 C 代码 | 手写 C 不需要这一步；开发者必须自己写合法 C 标识符。 |
| 额外依赖的封装代码 | UTF-8 码点读取 helper。 |

## CGEN-NAM-002 符号 mangling 文本编码

| 项目 | 内容 |
|---|---|
| xlang 写法 | 任意会进入 C 符号名的 xlang 名称 |
| 生成规则描述 | `xl6CgenFputsEncodedCodepoint` 对字母和数字原样输出，`_` 输出为 `__`，BMP 码点输出为 `_uXXXX_`，更大码点输出 `_uXXXXXX_`。空文本输出 `_`。该规则用于防止中文、符号和下划线碰撞。 |
| 生成器文件名和行号 | `demo6/src/cgen/xl6_cgen_core_names.c:79` |
| 对应生成的 C 代码 | `变量` 这类名称会变成包含 `_u53D8_...` 的 C 符号片段。 |
| 中间形态伪代码 | `ascii alnum -> same; '_' -> '__'; unicode -> _uHEX_` |
| 实现同等功能手写的 C 代码 | 手写 C 需要直接选择合法且不冲突的英文符号。 |
| 额外依赖的封装代码 | mangling 编码 helper。 |
