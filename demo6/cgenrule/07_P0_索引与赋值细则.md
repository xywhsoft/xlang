# P0 索引与赋值生成细则

本文细化 `xl6_cgen_value_assign.c` 中的索引访问、索引赋值、普通赋值、复合赋值与时间字面量生成规则。该文件的核心特点是：同一种 xlang 表面写法会根据接收者类型、键类型、目标类型与生命周期策略生成完全不同的 C 代码。

## CGEN-VASSIGN-001 索引赋值统一入口

| 字段 | 内容 |
| --- | --- |
| xlang 写法 | `a[i] = v` |
| 生成规则描述 | 索引赋值先把右值统一装箱成临时 `xvalue`，再交给 `xl6CgenIndexAssignTemp` 按接收者类型分派。这样 typed container 与动态容器共用同一套右值所有权协议：写入成功后容器接管引用，写入失败时生成代码负责释放。typed container 写入兜底要求 array/list/dict，诊断为 `typed container index assignment requires array, list or dict`。 |
| 生成器文件名和行号 | `xl6_cgen_value_assign.c:165`、`xl6_cgen_value_assign.c:177`、`xl6_cgen_value_assign.c:10` |
| 对应生成的 C 代码 | `xvalue __xl6_index_assign_1 = xvoCreateInt(3);`<br>`if (!xvoArraySetValue(a, (unsigned int)(i), __xl6_index_assign_1, true) && __xl6_index_assign_1 != 0) { xvoUnref(__xl6_index_assign_1); }` |
| 中间形态伪代码 | `tmp = box(right); set_index(left.receiver, left.key, tmp)` |
| 实现同等功能手写的 C 代码 | 手写 C 通常直接调用对应容器 API，并自行处理失败时 `xvoUnref`。 |
| 额外依赖的封装代码 | 需要 `xl6CgenXValueFromExpr` 负责右值装箱；不额外生成 helper 函数。 |

## CGEN-VASSIGN-002 typed array 索引写入

| 字段 | 内容 |
| --- | --- |
| xlang 写法 | `array<int> a; a[i] = v` |
| 生成规则描述 | 当接收者使用 typed container storage 且具体类型为 `array` 时，写入使用 `xrtTypedArraySetValue`。数组索引生成时加 `1u`，这是当前 typed array 与 XRT 容器布局约定的一部分。失败进入模块级 `xl6_runtime_fatal(3)`，成功后释放临时 `xvalue`。 |
| 生成器文件名和行号 | `xl6_cgen_value_assign.c:10`、`xl6_cgen_value_assign.c:45`、`xl6_cgen_value_assign.c:69` |
| 对应生成的 C 代码 | `if (!xrtTypedArraySetValue(a, (unsigned int)(i) + 1u, tmp)) { xl6_runtime_fatal(3); }`<br>`xvoUnref(tmp);` |
| 中间形态伪代码 | `ok = xrtTypedArraySetValue(array, index + 1, boxedValue)` |
| 实现同等功能手写的 C 代码 | `xvalue tmp = xvoCreateInt(v); if (!xrtTypedArraySetValue(a, i + 1, tmp)) xl6_runtime_fatal(3); xvoUnref(tmp);` |
| 额外依赖的封装代码 | 无。 |

## CGEN-VASSIGN-007 var 接收者索引写入分派

| 字段 | 内容 |
| --- | --- |
| xlang 写法 | `var v; v[k] = value` |
| 生成规则描述 | `var` 接收者需要运行期分派：静态字符串键按 table 写入；键是 `var` 时运行期区分 text 与 integer；键是静态整数时尝试 array/list 写入。其他键类型报错并释放右值。 |
| 生成器文件名和行号 | `xl6_cgen_value_assign.c:100`、`xl6_cgen_value_assign.c:111`、`xl6_cgen_value_assign.c:113`、`xl6_cgen_value_assign.c:115`、`xl6_cgen_value_assign.c:1077`、`xl6_cgen_value_assign.c:1046` |
| 对应生成的 C 代码 | `if (key_is_text) { ok = type == XL6_XVO_DT_TABLE && xvoTableSetValue(v, textKey, 0, tmp, true); } else { ok = xvoArraySetValue(v, i, tmp, true) || xvoListSetValue(v, i, tmp, true); }` |
| 中间形态伪代码 | `if key is string -> table; else if key is var -> runtime dispatch; else if key is int -> array/list` |
| 实现同等功能手写的 C 代码 | 手写 C 需要先拿 `xvoType(v)`，再按 table/array/list 分别调用 XRT API。 |
| 额外依赖的封装代码 | 无。 |

## 本文件观察到的优化风险

| 编号 | 观察 |
| --- | --- |
| RISK-VASSIGN-001 | typed array 在读取和写入时都对索引执行 `+ 1u`，这是重要 ABI/容器约定，后续若 XRT typed array 改为 0 基，需要同步修改所有生成路径。 |
| RISK-VASSIGN-002 | 多处动态索引读取使用 GNU 语句表达式 `({ ... })`。这对 TCC/GCC 友好，但会影响 MSVC 直编兼容性；若 demo6 后续强化 MSVC 输出，需要把这些表达式沉降为临时语句或 helper。 |
| RISK-VASSIGN-003 | 动态索引 `?=` 读取 `current` 后没有显式释放，是否安全取决于 `xl6CgenIndexExpr` 返回借用还是拥有值。该点应进入稳定性测试矩阵。 |
| RISK-VASSIGN-004 | 已收口：typed container 写入失败路径不再散落生成裸 `exit(3)`，而是进入模块级 `xl6_runtime_fatal(3)`；异常系统成熟后可在该入口切换为统一运行时错误传播。 |
