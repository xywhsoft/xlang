## 整理范围

本轮整理范围限定在 `demo6/cgenrule` 目录：

- `00` 到 `05`：目录索引、主规则入口、表达式/语句/运行时总览、细化清单。

- `43`：本文，记录 cgenrule 文档整理后的稳定口径。
- `44`：文档整理验收报告。

## 当前结论

当前目录已经完成 834 条 `CGEN-*` 规则的对照整理，并完成主干/P0、P1、P2 全部验证矩阵。矩阵文档不再使用批次式推进状态，而统一改为“阶段结论”和“剩余风险与后续增强”。除入口自身外，所有 cgenrule Markdown 文档必须被 `README.md` 索引。

本轮进一步把 `src/cgen/*.c` 中历史遗留的泛化 `code generation error` 占位诊断清零，并把相关边界同步回 `08`、`09`、`12`、`13`、`16` 号规则表和 `35`、`36` 号验证矩阵。当前又把 `unsupported statement/expression kind in C generator` 这类旧式兜底文本纳入静态守门；cgen fallback 诊断必须带具体 AST kind，防止后续重新引入无信息文案。

本轮还补齐 `Main` 大小写敏感与顶层脚本入口组合快照：`cgen_main_case_sensitive_script.xl` 证明大写 `Main(...)` 仍是普通函数，同时文件存在顶层运行语句时 XAPI entry 稳定输出为 `script-main`。

本轮同步刷新 `33_P2_DLL_API动态执行细则.md`：DLL API 的 `XL_Context` 状态、路径快照、默认 XRT object、loaded library 句柄所有权和公开 API 行号引用均已对齐当前 `src/api/xl_api.c`；手动 include/library/link/loadlib 的路径快照边界也已按当前实现写清。

`04_运行时与高级规则.md` 是高级能力总览，不再占用 `CGEN-*` 唯一编号；其内容对应到 `09` 到 `23` 号细则文档中的规则与矩阵证据。

当前没有剩余规则文档整理项。以下内容不视为规则文档缺失，统一归类为非阻断工程增强：

- 把人工矩阵进一步机器化，建立每条 `CGEN-*` 到测试 ID 的一对一索引。
- 为内部状态补更细的生成快照，例如复杂 cleanup 组合顺序、runtime needs 精确注入。
- 扩展资源巡检、标准库错误路径、畸形未知 XAPI value 负例和更多依赖图快照。
- 为泛型签名后缀、ResolveCall 边界、多线程宿主 API 等路径补更细测试。

## 维护要求

后续修改 cgen 行为时，应同步维护三类材料：

1. 对应 `CGEN-*` 规则表。
2. 对应验证矩阵的测试/范例证据。
3. `README.md`、`05_继续细化清单.md` 和本文中的总状态口径。

每轮文档修改后至少执行：

- `powershell -NoProfile -ExecutionPolicy Bypass -File tools\check_cgenrule_docs.ps1`。
- 该脚本会检查 `README.md` 全量索引、`CGEN-*` 计数、重复规则 ID、失效规则引用、占位词与未完成标记、源码行号引用范围，当前规则数应为 834。
