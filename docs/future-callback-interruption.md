# 独占 Future 的可选期限／取消底座

本批为后续 Dial、TCP 等独占操作补充驻留机制；不是完整公开语言 API 的验收。
现行 V1—V6 表布局、共享源和独占源合同保持不变。

## 生命周期

1. V5 Allocate 创建真实捕获帧。初始化拥有槽后，在启动原生工作前 Arm。
2. Arm 将可选父取消 Watch、绝对单调时钟期限绑定到同一个真实帧。
   各源分别拥有真实帧引用；附属状态没有独立引用计数、图节点或中间 Promise。
3. Stopped 可避免已经取消／到期时提交无意义工作，但不是跨线程竞态屏障。
   已停止时 Start 直接发布同一帧的就绪事件，不创建假的原生 Future。
   否则启动实际原生操作，再传其 Future 给 Start。
4. 期限／父取消只记录首个中断原因并请求真实源取消。
   原生仍为 Pending 时输出也保持 Pending；不撤销 Watch 来伪造完成。
5. 固定工作线程从真实终态进入投影。此处选择中断／结果，分离中断源，执行捕获清理后提交输出。
   原生成功但尚未交付的结果可以被先到的中断取代；已经选择的结果不被后来的父取消撤回。
   绝对期限在选择点再次检查，计入排队时间，不依赖定时线程恰好及时唤醒。

父取消为 Cancelled；期限为 Failed／TimeoutError；期限服务错误保留首个诊断，缺失诊断规范化为 InternalError。
输出 Future 自身取消仍遵守具体回调既有的终态选择规则。
未交付原生资源仍由具体操作载体清理，本底座不猜测原生值的释放语义。

## 失败与拥有图

Arm／Start 失败不消费 builder，必须 Discard，不重试已失败的 builder。
已经提交的原生工作由调用方请求取消，并由其真实载体保留至终态。
分配、注册、容量、关闭等失败均可检查；失败清理不覆盖首个错误。
Detach 幂等，不等待源 I/O 或语言回调；原生取消 Watch 的 Unwatch 会同步回收正在执行的机械通知尾部。
已经领取的期限通知可以完成机械尾部，但不能再接触语言捕获。
真实源引用、Promise、取消 Watch、期限服务租约及错误对象全部进入精确 Trace。
未完成通知尾部保留实际帧引用；期限运输不静止时，准备退役返回 Busy。
不在取消／定时线程执行语言回调、捕获析构或同步等待。
这是驻留 provider 的私有协议：源的取消／通知链也必须是机械原生操作，不能把任意外来源的回调当作语言执行许可。

新组件按需选择：普通共享／独占 Future 和基本 TCP 不依赖该期限服务或额外拥有域。
Cgen 没有增加函数名特例；原生 XRT、快照、字符串 ABI 和 release 二进制均不修改。
同时补齐通用回调拥有域到原生 Future／取消拥有域的依赖；不能依赖网络等调用方恰好引入它。
逐边验证实际协议登记；删除本批父取消 Watch 的登记后，该真实节点必须拒绝，而不是被当作叶子略过。

## 验收范围

`check_stdlib_tcp_language_runtime.py --interrupt` 使用实际组件闭包、目录和真实原生实现。
覆盖现有 V1—V6 回归、提交前停止、挂起期间中断、原生成功后排队期间中断、交付后不撤销、
实际引用计数／拥有边、96 个分配预算、服务关闭／容量与执行器关闭拒绝、128 次完成竞争，
并独立反向验证“丢失真实源取消”会被拒绝。
Windows／Linux、GCC／TCC、O0／O2 和 Linux ASan／UBSan 结果以外部证据报告为准。
本批新用例完全离线；复用的 TCP 回归只使用自有字面量 loopback，不做 DNS／公网或安全专项。

后续仍须将该底座接入 Dial 的公开 Until／Cancel 重载及 IR 的运行服务合同，
验证真实未交付连接清理和完整源码 JIT／AOT；不能将本底座通过等同于这些 API 已完成。
长期任务的其他网络、并发、密码学、X.509 和 TLS 未完成范围不缩减。
未决策维持 CRT 0、XRT 11 组。
