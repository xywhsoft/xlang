# 复合赋值的独立调用效果

类操作符的选择已在语义阶段完成，其调用目标带有实际错误合同。类实例使用
xvalue 存储，不意味着所选 `+=` 等操作还会执行一次动态装箱算术。旧分类器却将
两者混合，导致原本合法的调用在降低前被拒绝。

本次只修正 Typed XLIR 的效果分类：选定操作符没有额外的 intrinsic 错误效果，
目标函数仍保留 MAY_RAISE。降低器继续独立检查两个合同，并沿原有显式错误边
执行清理。没有放宽 verifier，没有增加 Cgen 推断或运行时包装。

完整错误清理合同新增两个变异：把所选操作符的 intrinsic 效果改回 MAY_RAISE，
必须拒绝 IR，而且 C 与头文件均不输出。目标函数的可抛错合同仍单独断言。

本批验证结果：

| 完整错误清理变异 | 4,833 项拒绝检查通过，包括 91 项即时结果检查及本批两个新增变异；数字为包含关系 |

`cgen_class_host.c` 原先把 int64_t 手写成 long long，不能满足 Linux LP64 的
实际声明。fixture 改用 stdint 固定宽度类型及对应格式宏。旧 TCP 诊断负例原来
使用已经合法的 `send(data, size)`，改用第三个参数验证真正的参数数量错误。

Windows 使用已核验的 R9 源码构建（1,295 个全新 TU），单独替换本批 IR。
完整变异和语料使用同一 IR 源码的 O2 对象；生成 C 的运行验证仍分别采用 O0/O2。
Linux 使用经逐项核对源码及对象的既有 1,297 对象 cohort，仅重编本批 IR，
不宣称做了全新 Linux 全库构建。两平台输入和结果均在验证后重新计算哈希。

证据位于 Windows 的
`E:/xlang-validation/five-groups-20261027/p7-shipping/ir-compound-*`，以及 Linux 的
`/home/ubuntu/xlang-validation/20261027-p7-shipping/ir-compound-runtime-r3`。

通过；上述结果分别来自修正后完整运行，未抽样或删除变异。
