# 嵌套编译器的独立 AOT 和资源验收

嵌套 Context 已通过 Windows 和 Linux 的真实 CLI、DLL、嵌入资源
及独立 AOT 验收。三个 compiler-import 程序和 Future 元数据程序
都能在没有仓库源码、声明 SDK、TCC 分发目录的环境中构建和运行。
生成的可执行文件单独复制到仅含可执行文件的新目录后仍能运行。
Linux 仍使用目标系统的 libc 头、CRT 对象和动态链接器。

## 修复内容

Future 元数据声明头和 Future 桥接曾引用未打包的
`include/xrt_decl.h`。它们现在复用已存在的 xruntime 声明入口；
已有完整类型声明时，元数据头不再重复包含声明文件。不新增另一份
XRT 头或实现镜像。两处内部头改为同目录引用，消除源码根路径依赖。

嵌入编译器源码清单补齐 `xl6_ir_class_identity.c`。此前原生 DLL 构建
包含该模块，但 compiler-import AOT 漏掉它，最终链接无法解析
`xl6IrVerifyClassIdentityPlans`。清单门禁现在对比普通构建的全部
31 个编译器核心源文件，后续漏项在验收前直接拒绝，不靠运行时查找
或缺失符号回退。原生标准库仍来自已有组件目录。

IR 的拥有者判断显式初始化定义指针并检查空值，消除优化构建的
可能未初始化警告；不改变原有拥有者判定、借用或移动规则。派生的
能力矩阵同步到已提交的接入实现，解除 Linux 发布构建的陈旧清单
拒绝。隔离快照也加入资源校验器需要的合同测试文件。

## 验收结果

两端从隔离源码通过普通构建入口重新生成 TCC、XRT 对象、CLI、两个
共享库和两份资源镜像，没有复用旧 DLL、XRT 对象或空资源包。

| 验证 | Windows | Linux |
| --- | --- | --- |
| 嵌套 Context 和 AOT | 32 阶段通过 | 32 阶段通过 |
| 两个真实共享库的 Sync 清理恢复 | 26 阶段通过 | 26 阶段通过 |
| 实际资源镜像中的头文件闭包 | 201 个运行时头通过 | 201 个运行时头通过 |
| 共享库中资源的逐字节独立解码 | 由无外部资源运行验证消费路径 | runtime 219 项、compiler 1030 项全部一致 |

32 阶段包含四份程序的 JIT、O0/O2 严格 C、AOT 构建、空工作目录
执行和单独移走后的执行，以及两个真实共享库的默认 Context 宿主。
新增程序在内层编译器中验证 NUL、UTF-8 字节范围、bytes、char、时间、
WaitQueue 的 string 和类对象拥有接收；类字段也包含 string/bytes/char。
每轮包含编译失败后的复用，不能借助调用者的 include 配置通过。

资源门禁检查运行时头的同目录引用，以及编译器源码引用的公开声明
在实际资源表中的可用性。旧声明缺口和旧核心源码漏项分别被明确
拒绝。Linux 资源校验器的四项合同测试通过，包括压缩和损坏输入。
所有正式报告均完成输入不变性检查。

正式证据位于 `E:/xlang-validation/stdlib53-b258-` 下的
`shipping-win-dev5`、`shipping-linux-dev6`、`nested-{win,linux}-final2`、
`sync-{win,linux}-final1`、`header-{win,linux}-final2.json` 和
`resource-linux-final1.json`。早期失败或诊断构建不作为通过证据。

## 后续工作

这批证明嵌套编译器及指定清理恢复路径可以使用真实发布候选独立
运行，不代表整个发布候选或所有标准库函数已通过验收。原有三组
301 项源码回归保持上一批已验证结果，本批没有用专项替代其总门。

专用 Promise／对象图退役／析构错误宿主汇总、独立 borrowed 原生
SSA、工作线程及图 OOM、模块卸载与错误压力、53 模块函数覆盖和
更广的真实发布产物回归继续。CRT 无未决策项，XRT 其余 19 组保持
未决策，对象池最后。
