# SSH 与 HTTP 绑定限定复核

这是全生态压实任务的一批进展，不代表完整 SSH 客户端或整个 HTTP 家族通过验收。
未替换正式 CLI/DLL，也未升级仓库 XRT/xruntime。全部修正在扩展库语言绑定边界。

## 修正范围

1. xssh 的结果码使用 C int；固定 64 位参数使用 int64/uint64，不以 long long
   替代所有平台的 int64_t。公开 codeName 在缩窄前检查范围，避免大整数变为成功码。
2. point 绑定采用实际的 void* 原型；借用只读数据交给已有 C 核心，不建立新存储层。
3. protocol 的四类析构、Headers.clear 和 body 的三类析构，返回类型统一为无返回值，
   移除与 XL 声明不一致的 long long 返回及无意义的 return 0。
4. SetCookie.validate 对非法内容返回 false，并仅消费 XERR_VALUE；参数错误等仍留给
   语言异常边界。构建非法 Cookie 仍抛异常，不能通过吞掉全部错误伪造谓词成功。

## 实际验证

| 项目 | 结果与边界 |
| --- | --- |
| 全部已声明原生绑定 | xssh 71、protocol 53、body 27，共 151 个；从真实生成 C 收集，不手写另一套期望签名 |
| Windows | GCC 16.1，严格警告；69 个步骤符合预期，其中 66 个正向通过，3 个故意错误签名被拒绝 |
| XL 入口 | xssh 2、protocol 4、body 1；源码 JIT/AOT、生成 C、正式 JIT；输出对照通过 |
| 输入稳定性 | Windows 1029 个输入前后不变；Linux 输入清单前后相同 |
| Linux C | Ubuntu GCC 15.2，LP64 原型检查和三份负控制通过；HTTP C 测试 ASan/UBSan/泄漏检查通过 |
| C 分配边界 | Headers/Cookies/SetCookie/MediaType 共 96 次失败注入尝试；触发点必须返回空值及内存错误，销毁后计数平衡 |
| 对象寿命 | Body 和 Reader 先销毁后，已取得 Chunk 仍可读；空析构安全；销毁不覆盖调用者错误 |
| XL 边界 | uint64 最大值、含 NUL/0xff 的 Buffer、NEED_MORE 游标、写入拒绝后恢复、Cookie 谓词恢复及对象 clone |

源码驱动仍借用正式 DLL 的 TCC core 和单独暂存资源，不等于完整正式构建重新验收。
Linux 只执行 C 层及生成原型检查，没有据此宣布 Linux XL 或端到端网络运行通过。

## 仍需处理

- xssh 的 XL 公开面仍主要是 wire/banner/key/known_hosts；原生会话后端存在，不等于
  XL 已交付连接、认证、channel 和完整客户端。
- 初次下游补测的 body_decode/multipart/form_data 析构冲突已在
  [后续专项](扩展库HTTP对象绑定复核_2026-09-28.md) 修正。三个包再完成 104 个
  两平台原型检查及 5 个 XL 入口 JIT/AOT 验证；原始六次失败记录仍保留为修正前证据。
- body_async/body_codec/body_stream 的 XLIR、client 的编译耗时/异步 ABI、邮件 TLS
  lease 等仍属独立阻塞，不能从本批通过推导它们已解决。
- 此门禁尚未并入日常集中测试；未完成网络拆包、取消竞争、长时压力和性能基线。
- AI 的 C int 绑定应沿用实际生成原型门禁；RapidOCR 缺后端的占位句柄和结果需要
  明确失败合同及生命周期审计，不以缺库分支通过代替真实推理测试。
