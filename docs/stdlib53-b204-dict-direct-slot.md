# Dict 直接槽读写合同

封闭元素类型的普通 Dict 索引、赋值和复合赋值已接入统一 IR 的直接槽
合同。生成 C 不再先把槽装箱为动态 Value、再投影回原类型。基础值仍是
值语义，可变对象与容器仍共享对象身份；不增加语言借用或参数修饰。
本批不新增公开标准库 API，不代表三组 53 模块或发布动态库完成验收。

## 统一 IR 与物理表示

`dict-read-slot` 发布独立拥有的结果；`dict-set-slot` 观察输入并由原生
存储复制。两者复用完整构造配方，验证精确接收者、元素、键、物理槽和
错误效果。Cgen 共用同步、异步和生成器发射路径，只输出布局与 SSA
参数；缺失键是否要求报错由 IR 合同提供，不由后端重新解释源代码。

标量、char、字符串、nullable 标量／字符串、bytes、类对象和嵌套容器
中，具有精确语言物理表示的封闭槽直接读写。`dict<var>` 是擦除元素视图，
可能接收不同物理值域的原生 owner，继续执行已有转换合同。安全索引、
用于缺失／null 条件判断的读取，以及闭包、Future 等与语言表示不同的
槽，保留显式 Value 投影；指针大小相同不构成直接访问的授权。

直接标量读的生成形式如下，布局标识由已验证的 IR 类型配方确定：

```c
result = (int64_t){0};
(void)xl6DictReadSlotV1(source,
    &(const XL6_DictLayoutV1){dict_id,
        {schema_id, element_id, 1, sizeof(int64_t), xrtTypeInt64()}},
    key, &result, true);
```

调用仍受 checked 错误边界保护。错误诊断分配失败也不能把失败变成
成功；非空标量键缺失报 RANGE，nullable 缺失与现有 null 语义一致。
声明头中的未使用原型不构成装箱调用，也不因此选择该原生符号。

## 原生生命周期与安全边界

运行时先认证真实 Dict 来源、完整捕获布局和操作占用状态，再访问槽。
wire OBJECT、游标和不匹配布局不能进入直接路径；不保留生成代码的
布局地址或回调。源槽与输出槽不形成语言引用，字符串保持精确字节长度，
bytes 后续修改继续执行值语义。

输出是编译器私有、已初始化的空槽。复制后若错误边界或清理失败，
使用真实驻留存储描述符撤回已取得的输出，保留首个失败；无诊断的
边界进入失败也会传播失败状态。旧的 consuming Value 写入合同仍用于
擦除／转换路径，直接写入不消费调用方输入。

标量读取在已有原生 owner 上零分配。原生专项中，字符串读取和已有键
的字符串替换各有一个内容分配点；这不是整个程序或新键插入的分配上限。
插入新键、扩容、类型准入和错误诊断仍可能需要额外分配。

## 验收与范围

Windows／Linux 各完成 225 个专项阶段、480 项损坏 IR 在 C／头文件输出
前拒绝，以及 10 条完整故障前缀、合计 666 次运行。普通语言、借入参数
裁剪、异步与生成器夹具使用新源码编译器，通过 JIT 和严格 O0／O2
裁剪产品验证。借入的标量 Dict 叶产品不选择工厂、wire 转换或 List／Set
组件。四个实际编译的错误实现均被拒绝，覆盖截断 NUL 键、抑制缺失错误、
省略槽复制及泄漏失败输出。

Linux ASan／UBSan 覆盖所选原生闭包 O0／O2 和生成产品 O0；不包括
整个编译器、供应方动态库，也不宣称生成产品 O2 已受 sanitizer 验收。
故障枚举针对当前线程的逻辑分配点，边界进入失败使用链接注入，不等同
真实 OS 上下文耗尽。

主要证据为 `E:/xlang-validation/stdlib53-b204-verify-win-dev4/results.json`
和 `/var/tmp/xlang-stdlib53-b204-verify-linux-dev4/results.json`。旧的不完整
验证批次仍保留为不完整记录，不用其 aggregate 状态代表本批验收。

原生目录仍为 256 个独立组件，新增一个私有读槽导出，实际导出为 1355。
XRT 供应仓库及消费方供应文件不变。完整资源策略、其他载体直接槽、
整体性能基线、发布 DLL／VFS 和三组模块总验收继续；19 未决策组与
对象池最后的安排不变。
