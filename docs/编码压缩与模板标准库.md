# 编码、压缩与模板标准库

更新日期：2026-10-17。X06、X24 的源代码接入及双端专项验收已完成；
release 目录中的现有二进制未覆盖，使用新接口需按正常流程重新构建。
模板类实例只投影 public 存储字段，不执行 getter，不读取底层私有字段。

## 编码：codec

六个主入口：

| 入口 | 输入 | 结果 |
| --- | --- | --- |
| hexEncode | string / bytes | string |
| hexDecode | string | bytes |
| base64Encode | string / bytes | string |
| base64Decode | string | bytes |
| percentEncode | string / bytes | string |
| percentDecode | string | bytes |

共同参数 `size=-1` 按实际字节长度处理，不调用 strlen；非负值截断到
实际输入长度，其他负值抛 RangeError。编码操作可以处理任意字节前缀，
不要求前缀恰好落在 UTF-8 字符边界。解码失败抛异常，不返回半成品。
需要文本时显式调用 `encoding.decodeUtf8`，不能将任意二进制伪装成 string。

```xlang
assert codec.hexEncode("a\0b") == "610062"
assert codec.hexDecode("00ff") == b"\0\xff"
string text = encoding.decodeUtf8(codec.base64Decode("eGxhbmc="))
```

Hex 的 `flags=0` 默认小写；`codec.hexUpper` 选择大写，
`codec.hexIgnoreSpace` 显式允许解码空白。非法／不适用标志由 XRT 检查。

Base64 在 size 后增加 `flags=0, alphabet="", alphabetSize=-1`。
`codec.base64Url`、`base64NoPadding`、`base64IgnoreSpace`、
`base64OptionalPadding` 是独立标志；默认严格检查。
自定义字母表的选定前缀必须恰好 64 个合法且互不重复的字节，
与其他配置的组合继续遵守 XRT Base64 合同。

Percent 编码在 size 后增加
`safe="", form=false, unreserved=true, safeSize=-1`。
解码在 size 后增加 `form=false`。
URI 模式的空格为 %20，+ 保持原义；表单模式空格为 +，原始 + 必须
转义，即使它出现在 safe 中也不能改变这条规则。safe 必须是可见 ASCII
字符集合，unreserved 控制是否同时保留 URI unreserved 集合。
显式保留 % 等特殊字节会改变解码／往返语义，不能用于未经验证的 URI 拼接。

旧裸指针 `*EncodeBytes` 和返回 Buffer 的 `*DecodeBytes` 不再公开。
Buffer 的 Hex/Base64 方法保留，其编码内核与 codec 共用，不绕行临时 Buffer。

## 压缩：compress

`compress.encode(string|bytes, options=null, size=-1)`、
`encodeBuffer(Buffer, options=null, size=-1)` 返回 bytes；
`decode(bytes, options=null, size=-1)` 和 `decodeBuffer` 同样返回 bytes。
只复用 XRT 算法；compress_common 保留内部依赖，不增加命名空间。

DeflateOptions 默认值：format=gzip，level=6，strategy=0，
outputLimit=67108864（64 MiB），windowBits=15。
InflateOptions 默认值：format=gzip，outputLimit=64 MiB，
gzipHeaderLimit=65536，windowBits=15。
两方向默认格式对称；输出限制为 -1 才显式无限，其他非法负值拒绝。

格式常量为 `compress.raw/zlib/gzip`；
`compress.httpDeflate` 仅解压使用。级别 0—10、策略和窗口位数由
XRT 校验，不将其转换为另一套压缩算法。

```xlang
bytes zipped = compress.encode("a\0b")
assert compress.decode(zipped) == b"a\0b"
auto encoder = compress.deflater()
auto compressed = Buffer()
encoder.write("a", compressed, compress.flushSync)
encoder.write(b"\0b", compressed)
encoder.finish(compressed)
auto decoder = compress.inflater()
auto decoded = Buffer()
decoder.writeBuffer(compressed, decoded)
decoder.finish(decoded)
assert decoded.toBytes() == b"a\0b"
```

Deflater/Inflater 由语言管理寿命，绑定创建线程。write 接收 bytes，
Deflater 另接收 string；writeBuffer 借用 Buffer 输入，输出统一写入 Buffer。
同一底层输入与输出区间重叠时，在消耗输入前拒绝。
Deflater 的刷新为 flushNone/flushSync/flushFull/flushFinish；
Inflater 的 final 参数或 finish 显式验证完整流。

done/failed/outputSize/closed 为状态；reset(options=null) 重置并复用，
close 显式释放。失败后的流必须 reset；已交付的输出不会撤回。
整块接口失败不交付结果。析构仅释放，不隐式 finish，不吞掉尾部校验错误。
校验和、尾随数据、截断、gzip 多 member 的处理沿用 XRT 严格合同。

## 模板：template

五个底层模块组成一套语言接口：

| XRT 模块 | 语言能力 |
| --- | --- |
| template_core | compile、render、source、nodeCount、节点快照 |
| template_control | 条件、循环、作用域、渲染步数与深度预算 |
| template_compose | define/include 与显式 resolver |
| template_extension | TemplateEngine 四类注册、TemplateCall |
| template_file | 有界文件输入、编码处理、VFS 输入 |

`template.compile(text, options=null, size=-1)` 返回不可变 Template；
`template.render(text, data=null, options=null, compileOptions=null, size=-1)`
提供一次性入口。无效模板和渲染错误抛异常，没有 valid/error 状态旁路。
source 保留精确长度与内嵌 NUL；选定文本前缀必须是有效 UTF-8。

TemplateCompileOptions 包含 open/close 以及 maxSourceBytes、maxNodes、
maxPathSegments、maxPathDepth、maxExpressions、maxBlockDepth、
maxExpressionDepth、maxArguments、maxCallArguments。
TemplateRenderOptions 包含 root/current/global、maxOutputBytes、maxSteps、
maxDepth、maxLoopIterations、maxIncludeDepth、maxResolvedTemplates、
strictUndefined（默认 true）、escapeHtml（默认 false）及可空 resolver。
resolver 的类型为 `func(string) as Template?`；每次渲染固定其引用和拥有预算。

数据与三个作用域先由同一个 public 投影计划处理，保留共享关系；
支持数据字典／数组、已接入的数据容器和有本模块已验证 schema 的类。
类按最派生的同名存储声明确定可见性：子类 private/protected 字段隐藏
基类 public 字段时，不导出该键；子类 public 同名字段只导出一次。
不执行 getter，也不采用 JSON/XLON 的 rename/include/skip 属性。
未提供 schema 的外部类和未知原生句柄 checked 拒绝。动态附加字段不是
声明的 public 存储字段，不自动导出；`object` 的动态存储槽按 IR 已解析的
声明身份排除，不保留会误伤普通用户字段的名称黑名单。
随后驻留入口还会隔离渲染快照，
避免原生调用者绕过类数据边界；目前不是零拷贝数据接口。

Template.node(index) 返回拥有自身数据的 TemplateNode；
type/output/offset/size/line/column/source/expression/format/name 可读。
`template.errorLocation(error)` 返回 TemplateLocation?，有位置时包含
offset/size/line/column；非模板位置错误返回 null。

TemplateEngine 的 registerFunction/registerStatement/registerBlock/
registerRawBlock 接收名字、`func(TemplateCall) as bool`、minArgs=0、
maxArgs=256。compile 固定注册项与受管理回调快照；后续注册不影响旧模板。
Engine 和带扩展的编译结果绑定创建线程。纯模板不保存语言回调。

TemplateCall 只在当前回调有效；逃逸保存后，方法 checked 报状态错误，
不会暴露原生临时指针。argument(index) 返回独立 TemplateArgument，
eval 返回拥有数据快照；write/renderBody/renderCurrent 操作当前渲染。
name/raw/current/root/global 为安全副本，find 支持精确字节前缀。
回调抛出的原异常保留，不替换成模糊的“模板执行失败”。

Template.appendTo(Buffer, data=null, options=null) 完整渲染成功后事务追加；
writeTo(IoWriter, ...) 流式写出，失败不能回滚已经写出的字节。
compileFile/renderFile 处理宿主路径；compileFileIn/renderFileIn 另接收 Vfs。
Engine 同样有 compileFile/compileFileIn。默认输入上限为 64 MiB，先有界
读取原始字节，再按显式或自动编码和严格／替换策略解码，并独立校验编译预算。
路径含 NUL 时拒绝；不占用 file 命名空间。

## 实现与验收边界

驻留 runtime 实现安全适配；XLIR 使用封闭 ABI 合同验证类型、效果、
checked 错误、闭包及明确的原生拥有字段。Cgen 只发出调用、数据和清理，
旧 codec/template 算法生成路径删除。编码族、压缩／解压、模板输出与
文件入口按组件需求裁剪。

`tools/check_stdlib_codec_template.py --root <候选根> --out <新报告目录>`
使用实际双库、CLI/JIT/模块、严格 C O0/O2、重定位独立 AOT、ABI 反例、
分配失败与按需组件验证。报告区分测试子集与整项完成，不是完整 RC0 门禁。
账本已转为 DONE-XRT-CODEC-TEMPLATE，不代表其他标准库或完整 RC0 已结项。
