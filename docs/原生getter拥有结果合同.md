# 原生 getter 的拥有结果合同

本批修复通用 XLIR 属性调用合同，不是为某个标准库生成包装代码。
不改 Cgen、不增加语言语法、不修改公开运行时 ABI，也不放宽其它外部调用的校验。

## 根因与实现

已登记的原生类结果统一使用 `NATIVE_FACTORY`：它表示原生字段／句柄需要发布成
语言对象，并不只表示 `create()` 语法。普通函数调用已经支持此合同；属性事务却
只接收 INTERNAL／EXTERN_C，并且用语言类结果类型直接生成 C 调用，遗漏物理结果层。

修复两处边界：

- 属性签名允许直接、同步的原生 factory getter。仍要求 GET 声明、借用接收者和
  准确的规范字段／析构合同；不能把构造器、setter 或错误的虚分派冒充 getter。
- 属性 CALL 复用 `xl6IrCallTargetPhysicalResultType` 选择原生返回表示，再进入已有
  `CompleteCall`：原生失败回滚、成功结果装箱、接收者／索引清理及清理失败回滚。

没有按函数名或库名插入特判，也不通过把属性改成函数来绕过问题。静态普通属性、
索引属性和可空 getter 使用相同规则；协议／虚分派仍保持原有的语言结果合同。

## 验收范围

证据根：`F:/xlang-validation/five-groups-20261020/p0-native-getter/`。
固定的完整工作区源码驱动为 Windows 657／Linux 656 编译单元，输入摘要稳定。
驱动包含工作区尚未提交的数据报开发单元；本批测试不依赖这些新 API，提交只纳入
通用 IR 修复和本页列出的 getter 测试，不据此认证整个工作区或独立 HEAD 发布产品。

正式语言轮为 check-win-r6／check-linux-r3：每端 78 阶段，8 个程序均通过 JIT、
模块运行、严格 C O0／O2、独立 AOT 及无 xlang 共享库导入检查。覆盖拥有型普通／
索引 getter、临时接收者、可空结果、继承字段、接收者析构抛错、原错误优先，以及
既有泛型／继承／协议／别名属性回归。新值用例只有数字地址，没有 DNS 或 Socket。

IR 专项每个测试优化级别检查 2 个 factory、7 个属性调用点（2 个可空）、7 个
物理调用和 12 个拥有结果回滚，逐项拒绝 61 个损坏合同。损坏后 C 和头文件均不输出。
测试程序为 O0／O2；编译器驱动自身为 O0，不冒称完整编译器已通过 O2 重建验收。

既有 setter／普通属性另有 setters-win-r1／setters-linux-r1，各 10 项源 JIT／模块
回归，覆盖普通／泛型协议 setter、自身属性读写、属性错误传播和可空导航。

内存轮为 oom-win-r2／oom-linux-r2：每端 180 阶段。对未经改写的实际生成 C，
使用完整源码对象，在 O0／O2 分别逐点执行 0—83 的当前线程逻辑分配前缀；
0—82 触发 MemoryError，83 为无注入命中的成功终点。每个独立进程都要求有效
拥有资源的分配／释放、存活数量／字节和重复释放等计数平衡。

另检查成功 getter 返回后接收者析构抛错、getter 自身先失败后析构再抛错，两种路径
都保持内存平衡，后者保留原 RangeError。测试先预热全局惰性状态，不覆盖冷启动全局
初始化、其它线程分配失败或调度器级 OOM；不替换运行时实现，不作为 shipping DLL／
SO／VFS 证明。早期测试程序语法／构造规则错误保留记录，不计为正式通过。

## 与长期任务的关系

本批关闭已复现的 native getter 合同缺口。旧偶发 module 编译失败仍未查明，不能
归因于本缺口或上一批 Provider 缓存竞态。数据报完整语言验收、枚举标志规则、向量／
批量、Resolver、P3—P7 与其它原批准工作继续保留；没有网络流量或网络安全专项。
