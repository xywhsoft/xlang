# 动态方法的精确回调合同

动态方法支持完整签名的非可空 `func` 参数与返回值。Regex 的
`replaceWith`／`replaceWithTo` 和 RegexReplacer 的 `run`／`runTo`
使用同一合同，不再因回调参数缺少动态适配而不可调用。

## 签名与物理边界

重载选择同时检查 callable 形状和规范函数签名身份，不转换参数、
不分配内存，也不只按“可调用”选择候选。匹配后使用已有 checked
closure 桥接建立拥有的投影。typed `func` 进入动态调用仍需显式
`xcall`；直接 typed 调用不增加这一步。

原生 checked closure 只接纳已登记的精确参数合同；它不能退化为
任意 C 函数指针或任意 extern 的直接参数。原生接入校验与普通调用
共用声明表，不在生成器按 Regex 名称识别能力。

## 生命周期与生成边界

借入参数的投影在目标调用后释放，拥有参数仅在实际进入调用时转移。
匹配、投影、调用、结果装箱或清理失败均沿适配器事务退役，并保持
首个错误。返回函数复用已有 callable 编码器，装箱后释放原生结果
owner。桥接只由可达的具体函数签名选择，未调用声明不增加提供方。

XLIR 固定签名匹配类别、参数拥有合同和原生物理 ABI；验证器独立
检查它们。Cgen 渲染既有投影、调用与释放，不添加正则实现或回调
执行算法。没有增加公开标准库 API 或运行时导出。

## 验收范围

`tools/check_stdlib_dynamic_callbacks.py` 覆盖重载、绑定方法、函数
返回、四个 Regex 回调入口、Buffer 输出、NUL／UTF-8、错误签名、
目标未进入及原始回调错误。float32 舍入／无损读取、二进制默认
参数、泛型登记和完整类目录同时回归。

29 个签名／参数拥有／原生物理 ABI 破坏反例在 C 和头文件输出前
拒绝。O0／O2 各 445 个同步分配前缀包含首次未触发点，模块退役
后账本平衡；故意删除投影 closure 释放的实际生成代码必须被检出。
实际裁剪产物包含需要的 Regex 提供方，不引入 Process。

双端各 310 个三组夹具通过 Cgen／严格 C 编译。Linux 指定插桩
范围为生成 C 与测试宿主，不包括全部链接提供方或额外裁剪产物。
Windows、Linux 普通与 Linux 指定插桩通道各 94 项通过，包括真实
JIT、checked module、生产 AOT 与未剥离裁剪产物。驻留目录双端为
304 个组件、1507 个导出，92416 对依赖闭包与 23 个负控通过。

非字面量默认参数、异步动态返回、可空函数参数和完整动态编解码
继续；工作线程／对象图故障、组合模块、真实卸载及发布总门未关闭。
CRT 0、XRT 19 组未决策、WaitQueue MPMC 拥有接收及对象池最后不变。
