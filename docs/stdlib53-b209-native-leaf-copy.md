# 原生值复制与失败原子性

SlotMapKey 的原生容器读取、装箱和拆箱共用驻留的原生值复制合同。
正常复制只取得原生实例记录的拥有引用，不复制槽表、不装箱，也不分配
新的内容。拥有型记录不能当作普通 C 结构体赋值，复制仍是 MAY_RAISE。

## 直接复制合同

`xl6NativeLeafValueCopyV1(profile, input, output)` 接收永久驻留的不可变
原生值能力、仍然存活的借用输入和私有空输出。输入与输出必须满足
实际类型对齐且完全不重叠。输出已占用时拒绝，不释放或覆盖原有内容；
即使输入与输出都为空，自复制也不取得新的拥有权。

描述符要求非零 ABI 身份、完整记录大小与对齐、Copy 和 Drop，以及
明确的 COPYABLE 非引用类型。描述符探测不改变错误上下文。这不是
对任意 C 地址的内存安全认证：原生发布者与传入记录必须遵守既有的
永久驻留、不可变内容、空状态和无语言图拥有边合同。

实际 Copy 可在写入部分拥有引用后失败，或者只报告无诊断的 checked
失败。复制事务先锁定失败，再 Drop 部分输出，恢复空状态。装箱和拆箱
复用同一事务体，不增加重复的线程错误作用域；键容器不再保留另一套
临时键及复制回滚实现。

## 拆箱的晚期失败

拆箱暂时保留源 Value，以覆盖原生读取的生命周期。该保留的释放也是
完整事务的一部分：即使 Copy 已成功，释放阶段失败仍须清理输出并
返回 checked 失败。否则调用方会同时看到失败状态与已拥有的结果，
导致异常路径上的泄漏或重复清理。已占用或不对齐的输出从不进入清理。

## 验证范围

键专项在严格 O0 和 O2 下检查对齐、重叠、已占用输出、无诊断部分
复制失败、错误上下文和晚期释放失败。每种优化级别连续执行 10000 次
正确复制并释放，在禁止下一次分配的条件下完成，用分配故障探针验证
没有额外分配。这是分配行为检查，不是性能基准。

Windows 与 Linux 源码构建分别完成 300 与 299 个对象。双端键专项各
通过 79 阶段、18 次完整故障前缀和 9 个实际编译错误实现检测；原生
值容器各通过 74 阶段、86 次故障前缀与 4 个错误实现检测。Linux 的
上述原生闭包及相邻 SlotMap、Set 闭包在 O0 和 O2 下通过 ASan 与
UBSan。真实源程序的 JIT 与严格 O0、O2 C 消费者通过，但消费者不是
消毒后的裁剪发布产物。

目录核对 261 个组件和 1389 个实际导出，普通 Set 不选择 SlotMap 键
实现。相邻 Dict 的三个真实裁剪产物各平台通过 225 阶段、480 项损坏
IR 检测和 666 次故障前缀。证据在 `E:/xlang-validation/stdlib53-b209-*`
及 Linux `/var/tmp/xlang-stdlib53-b209-*`。历史文档 14 项及静态门禁
2 项失败保持不变，不算作通过。

语言 SlotMapKey 直接 C ABI、frame、SlotMap 公开构造与方法及三组
总验收仍待完成。本批没有增加 Cgen 库函数体，也没有修改 XRT 供应库、
发布 DLL、SO 或 TCC。可变对象与容器的 Set 身份键规则不变；对象池
仍留到最后，19 个未决策组不扩张。
