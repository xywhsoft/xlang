# 进程文件重定向

B29 的原生文件标准流绑定；不代表整个 process 组、PTY 或 53 模块完成。

## 接口

```xlang
auto command = process.cmd(program, arguments)
command.stdin(inputFile)
command.stdout(outputFile)
command.stderr(errorFile)
// 通用入口：0=stdin，1=stdout，2=stderr。
command.redirect(process.stdout, outputFile)
auto running = command.start()
auto status = running.wait(5000)
```

stdin 要求 File 的读能力，stdout/stderr 要求写能力。关闭的 File、非法
流编号、非创建线程配置、能力不足及不提供原生句柄的 backend 均拒绝。
调用失败不改变上一份绑定，OS 复制错误保留 IO 分类与 SystemCode。

## 生命周期与边界

配置时取得非继承的 OS 句柄副本，Command 独立拥有它；不是保存语言 File、
裸指针或生成代码的释放回调。原 File 可在配置后、start 前关闭。start
再为子进程复制能力；随后销毁/重配 Command 不影响已启动的子进程。
成功替换、stdio 模式重设及析构释放配置副本。析构保留 ambient error。

副本共享内核文件位置与同一打开文件描述，不复制内容，不承诺独立游标。
与原 File 并发 seek/read/write 需要调用者协调；File 的引用计数只保护
寿命，不使其游标操作或显式 close 成为跨线程同步操作。

文件绑定用于 live `start`。`run` 是独立的捕获式操作：其输入 bytes 和
stdout/stderr collector 按既有 XRT 合同设置管道，不消费文件绑定。
Pipeline 也使用自己管理的连接器，add 拒绝 HANDLE/terminal 配置。
真实终端模式与文件重定向不混用；调用 terminal(true) 或反向绑定均拒绝。

恢复普通流模式：

```xlang
command.stdio(process.stdout, process.stdioNull)
```

VFS 没有原生句柄时明确返回 Unsupported，不伪造句柄、不自动退回磁盘。
通过 File.reader()/writer() 与 Process 的 stdinWriter()/stdoutReader()
进行显式流复制；应协调 stdout/stderr 排空，避免顺序阻塞造成背压死锁。
此接口不暗中创建后台 VFS 泵或脚本回调。

## 编译合同

四个门面方法归约到一个 resident 入口 `xl6ProcessCommandFileV1`。
物理 ABI 是 `(command owner, int64 stream, File owner) -> void`，may-raise、
非 pure，不虚标 nonblocking；XLIR 验证两个不同 owner 的精确 native 借入。
绑定组件按需加入 PROCESS_FILE/ATOMIC；普通命令配置不无条件依赖 File/IO。

共享的 `xl6_fs_file.h` 只提取既有 File 资源投影与寿命辅助函数，不改变
ABI 或锁语义。Cgen 包含该私有头并调用封闭入口，不生成进程重定向算法。
虚拟 include 资源同时打入 Windows/Linux 编译器与 runtime VFS。

验收记录、故障注入范围、首次失败与修正以《三组标准库接入长期任务.md》
B29 为准。公共 wait 不是 waiter join；原生账本测试显式退役私有 waiter。
