# 取消观察者的拥有者驱动退役

取消注册现在具备 Clear 之后完成解绑的原生协议。它是 TaskGroup
传递拥有图的前置能力，不等于 TaskGroup 循环对象已经接入。现有
xlang 拥有域继续使用原来的已认证适配器，不自动切换协议版本。

## 为什么不能提前解绑

真实注册拥有者可能在语言终结过程中访问字段，终结也可能中止。
在此之前替它 Unwatch 会改变仍然存活的对象行为。新 Watch V2 和
Token V3 在全图冻结下保留全部物理槽：Clear 只标记退役，阻止
新的通知启动；拥有者在自己的完成阶段移走注册槽并消费 Unwatch
权利。外部祖先令牌仍能收到取消请求，但不能重新启动已 Clear
观察者的 Notify。Restore 保持原有注册和通知行为。

## 完成状态

配套的 `xrtownershipfinishv1` 与适配器按精确身份共同准入。Step
在冻结和 mutation 之外串行执行，整个完成阶段保留每个节点的真实
计划引用。尚有链入注册、活动派发或回调尾部时返回 BUSY，不丢弃
强引用、不分配、不等待其他参与者。调度方必须继续其他节点的
清理，再重试依赖。READY 幂等；FAILED 不依赖错误对象是否能分配。
不能用旧 bool Finish 混淆 BUSY 与失败。

旧 Watch V1 与 Token V2 的语义准备和描述符身份均保持不变。未知
策略、legacy 观察者和活动回调不能因为新接口存在就取得准入。

## 源码同步和验证

XRT 提交 `f0e787f8215645e25a21a93912ba371398779699` 包含新协议、
模块化与单头测试及 API 文档。30 次原生执行覆盖 Windows GCC
O0 和 O2、TCC、Linux GCC、ASan 和 UBSan，以及旧取消和 Future
组合协议的回归。

xlang 仅同步 core 类型和 cancel 的对应增量，保留嵌入式 Future
的微秒超时契约，不整体刷新上游。`lib/xrt/backports/cancel_retirement.json`
固定规范源码和四份消费头的哈希。`check_cancel_retirement.py` 对
两份实际消费单头分别执行 O0 和 O2 测试；提供 public-directory
时还校验完整源码构建输入，再链接真实对象执行同一测试。

生命周期夹具使用真实四节点五条边，保留外部父令牌根；覆盖 16
种 Clear、Finish、Restore 和外部取消组合。BUSY 在分配失败注入
下仍不消耗注册；活动回调被拒绝，最终分配、释放、存活字节和
非法释放计数全部平衡。没有虚构叶子、工作线程折扣或合成引用。

## 后续接入边界

TaskGroup 的活动项和完成 Future 仍需建立真实引用、传递 Trace、
活动拒绝、语义终结和拥有者完成职责。取消协议版本还必须在全部
拥有域一致路由；Future 的未观察取消清理不能绕过链表不变量。
这些接通前，不登记 TaskGroup 叶子策略，也不启用新完成描述符。
正式产品和全部 53 模块的发布验收仍属于长期任务的剩余工作。
