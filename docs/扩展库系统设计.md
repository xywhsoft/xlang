# DEMO6 扩展库系统设计

本文档记录 DEMO6 当前主线的模块化、import/package 和扩展库系统口径。

主线已经移除旧接口 JSON 机制。旧实现、旧测试和历史迁移目录已从 DEMO6 主线删除，不能作为当前设计来源。

## 目标

- `import` 以 `.xl` 源码模块为事实来源。
- 所有可见符号必须通过显式 `import` 进入命名空间，不做项目级全局污染。
- package 是 import 的公共来源，本质上仍提供 `.xl` 声明源和必要的 C/native 构建信息。
- C 是一等公民：`.xl` 可以声明 C 函数，C 侧可通过 xlang 生成头文件调用显式导出的 xlang 符号。
- 多版本 package 可以共存，依赖默认私有。
- 第一版不支持 `.o/.obj` companion，避免提前引入编译器 ABI 兼容问题。

## Source Import

普通源码导入示例：

```xlang
import math

func main(...) as int
    return math.add(20, 22) - 42
end
```

规则：

- `import foo` 优先解析为源码模块或 package。
- 导入符号只进入 `foo.xxx` 命名空间。
- 被导入模块的普通函数、导出函数、类型、变量不会进入当前全局作用域。
- 依赖模块默认私有，不向上层自动暴露。
- import 循环必须诊断为错误。

### 命名空间、别名与选择性导入

普通导入只绑定模块命名空间：

```xlang
import geometry

geometry.Point point = geometry.Point(20, 22)
println(point.length())
```

命名空间可以显式改名：

```xlang
import geometry as geo

geo.Point point = geo.Point(20, 22)
```

需要把少量公开符号直接引入当前文件时，使用选择性导入：

```xlang
from geometry import Point, distance
from geometry import Transform as Matrix

Point point = Point(20, 22)
Matrix transform = Matrix()
println(distance(point, Point()))
```

规则：

- `import module` 只公开 `module.xxx`，不会隐式展开任何符号。
- `import module as alias` 只公开 `alias.xxx`；原模块名不会同时进入当前文件。
- `from module import name` 只导入列出的公开符号。
- `from module import name as alias` 只绑定别名，原符号名不会同时进入当前文件。
- `from` 是上下文关键字，离开 import 语句后仍可按普通标识符解析。
- 第一版不支持 `from module import *`，避免不可审计的全局污染。
- 选择性导入当前面向源码模块和 package；内置能力模块仍使用命名空间导入。
- 导入别名不能覆盖内置类型、当前文件的顶层声明或已公开的导入命名空间。
- 同一模块经过命名空间、命名空间别名和选择性别名导入时，指向同一个内部符号和同一个类型身份，不复制类型。
- 依赖模块仍然私有；给当前模块起别名不会把它的依赖命名空间一并公开。

### 可公开符号

模块使用 `export` 明确公开边界。当前可以公开：

```xlang
export func makePoint(int x, int y) as Point
end

export int mutableValue = 1
export const int version = 6

export typedef Count = int
export extern type NativeCount = c_int
export extern "native_count" func nativeCount() as c_int

export union Number
    int integer
    float64 real
end

export class Point
    int x
    int y
end
```

公开类型可用于所有类型位置，包括变量、字段、参数、返回值、函数值签名、容器泛型参数、泛型 class 实例和 `extends`：

```xlang
import geometry as geo

class LocalPoint extends geo.Point
end

func echo(geo.Point point) as geo.Point
    return point
end

array<geo.Point> points = []
func(geo.Point) as int reader
```

补充规则：

- xlang 函数、直接映射的 `extern` C 函数/变量、变量、常量、`class`、具名 `union`、`typedef`、`extern type` 都有跨模块公开价值，已经进入统一公开符号表。
- 匿名 `union` 没有可引用的类型名，因此不能作为模块导出。
- 非 `export` 类型是模块私有实现；使用 `module.PrivateType` 也必须报错。
- 当前语言没有 `enum` 声明语法，本阶段不添加兼容占位或半成品实现。未来实现枚举时，应直接进入同一公开类型符号模型。
- `export class/union/typedef/extern type` 只表示对 xlang 消费者公开，不等于自动导出 C ABI。
- xlang 成员函数进入 C 仍需显式 ABI 导出；公开类型的 C 布局和元数据由现有 ABI/头文件生成路径负责。

### 接口事实来源

- 当前主线不维护一份需要手写并二次校验的 `.xli` 或接口 JSON。
- `.xl` 源码 AST 是公开符号、类型签名和文档的事实来源。
- import 预解析建立带符号种类的公开符号表，再把公开声明改写为 package instance 对应的内部唯一名称。
- manifest 只保存定位、版本身份、依赖和 native 构建输入，不重复声明函数或类型签名。
- 持久化 ABI 元数据和生成的 C 头文件属于机器产物，不能反向取代源码公开边界。

## 同名 C Companion

当 `foo.xl` 被作为入口或被 import 时，如果同目录存在 `foo.c`，编译器会自动把它加入本次 C 编译。

示例：

```text
foo.xl
foo.c
```

`foo.xl`：

```xlang
extern "foo_add" func add(int a, int b) as int
```

`foo.c`：

```c
#include <stdint.h>

int64_t foo_add(int64_t a, int64_t b)
{
    return a + b;
}
```

规则：

- companion 是 `.xl` 模块的一部分，不需要额外 import。
- companion 只支持源码文件 `.c`、`.cc`、`.cpp`、`.cxx`。
- 第一版不自动纳入 `.o`、`.obj`、`.a`、`.lib`。
- C 函数仍必须在 xlang 侧用 `extern` 显式声明。
- xlang 导出给 C 的符号仍通过 `export` 和生成头文件提供。

## Package Manifest

package 使用 `xlang.package.json`，只作为包索引、版本身份和构建输入清单，不重复维护函数签名。

推荐格式：

```json
{
  "format": "xlang-package-1",
  "name": "counter",
  "version": "1.0.0",
  "abiVersion": "1",
  "artifact": {
    "xlSources": ["src/counter.xl"],
    "cSources": ["src/counter.c"]
  },
  "links": [],
  "loadlibs": [],
  "dependencies": [
    {
      "name": "dep_value",
      "version": "1.0.0",
      "abiVersion": "1"
    }
  ],
  "native": {
    "singleton": false
  }
}
```

规则：

- `format` 固定为 `xlang-package-1`。
- `name`、`version`、`abiVersion` 共同形成 package instance identity。
- `artifact.xlSources` 是 import 注入的声明/实现源码。
- `artifact.cSources` 是随包编译的 C 源码。
- `links`、`loadlibs` 进入最终链接或运行期加载。
- `dependencies` 默认私有。
- `native.singleton=true` 表示同一进程内该 native 资产只能存在一个兼容实例。

## Package Identity

同一个包的不同版本、不同 ABI 版本是不同实例：

```text
packageId = name@version#abi
```

规则：

- `dep@1.0.0#abi1` 和 `dep@2.0.0#abi1` 可以共存。
- 上层代码不会自动看到依赖包的私有符号。
- 如果未来支持 re-export，必须显式声明。
- 类型身份不能只由类型名决定，必须携带 package instance。

## Resolver

第一版 resolver 保持简单确定：

1. 显式相对路径或绝对路径。
2. `XLANG_PACKAGE_PATH` 中的目录。
3. `release/extlibs`。
4. `test/fixtures` 仅用于测试。

规则：

- 目录包只识别 `xlang.package.json`。
- 不识别 `xlang.package.json` 或其他旧接口文件。
- 不做向上查找项目文件。
- 不做远程下载。
- 不做完整版本求解器。

## Extlib

扩展库是 package 的发布形态。它可以由 `.xl`、`.c`、头文件、动态库、资源文件组成。

第一版 extlib 应满足：

- 使用 `xlang.package.json` 描述包。
- 用 `xlSources` 提供 xlang 声明源。
- 用 `cSources` 提供需要随包编译的 C 源码。
- 需要多个 C 源文件的包先保留清单，后续再设计更完整的 native artifact 管理。

## 暂缓项

- `.o/.obj` 自动纳入。
- 二进制接口缓存。
- 远程包仓库。
- semver range 求解。
- 自动 re-export。
- 包级 lock 文件。
- 通配选择性导入。
- `enum` 声明与枚举导出。

## 设计原则

- `.xl` 源码是主线事实来源。
- manifest 是索引清单，不是接口声明语言。
- C 函数进入 xlang 必须显式声明。
- xlang 符号进入 C 必须显式 export。
- 多版本共存优先于全局唯一版本。
- 冲突必须显式报错，不能静默选择。
