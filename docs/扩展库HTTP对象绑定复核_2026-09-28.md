# HTTP 对象绑定后续复核

本批接续 SSH/protocol/body 的绑定检查。修复扩展库原生声明并补边界用例，
不等于整个网络生态、异步运行时或全部 HTTP 协议已经通过发布验收。
正式 CLI/DLL 和仓库 XRT/xruntime 哈希未变，没有升级运行库。

## 修正内容

- HTTP、BodyDecode、BodyStream、Client、FormData、Multipart 和 XWS 中，
  语言析构或 clear 无返回值的绑定，C 实现相应使用 void，移除无意义的 return 0。
- 公开 point 参数与真实生成的 void* 原型对齐；C 内部借用只读数据仍使用 const。
  文本写入便利函数只在薄绑定调用处转换，不增加一套数据复制或存储机制。
- XWS 的十个固定 64 位返回值使用 uint64，不用 c_ulonglong 替代 uint64_t，
  避免 Windows LLP64 恰好可用、Linux LP64 原型冲突。
- XWS、Client、BodyFile 的回调失败路径不再调用没有实现的旧
  xl6ExtlibErrorPending/PublishXrt/Clear。当前生成的回调将失败写入 XRT error；
  继续通过现有 XRT 错误对象取得、保存和传播原因，不提供空实现兼容层。
  此项只恢复了部分集成路径，完整回调错误合同尚未验收。

## 验证范围

| 包 | 原生符号数 | XL 测试入口 | Windows 结果 | Linux 结果 |
| --- | ---: | ---: | --- | --- |
| xhttp.multipart | 67 | 2 | 源码 JIT/AOT、正式 JIT、实际生成原型通过 | LP64 原型和故意错误原型拒绝检查通过 |
| xhttp.form_data | 31 | 2 | 源码 JIT/AOT、正式 JIT、实际生成原型通过 | LP64 原型和故意错误原型拒绝检查通过 |
| xhttp.body_decode | 6 | 1 | 源码 JIT/AOT、正式 JIT、实际生成原型通过 | LP64 原型和故意错误原型拒绝检查通过 |

Windows 两个门禁共 49 步，其中 46 步正向通过、3 步故意将析构返回类型改错后
被正确拒绝。输入快照分别为 876、951 项，前后均未变化；Linux 前后快照也一致。
加上前一批 151 个符号，目前这六个包共有 255 个已声明原生符号完成两平台原型检查。
这是声明覆盖，不是全部输入组合、协议分支或生产行为覆盖。

源码驱动复用正式 DLL 的 TCC core，不是完整正式 CLI/DLL/VFS 重建。
本批 Linux 只做 C 原型编译及负控制，没有运行 Linux XL，也没有把前批
protocol/body 的 sanitizer 结果扩大到 Multipart/FormData/BodyDecode。

另有 21 个受改动影响的原生 C 单元通过 Windows GCC 严格语法检查；
此项不替代实际语言原型检查，也不代表 Client、BodyStream、XWS 运行验收。

## 新边界

- Multipart：局部 Parser 和输入离开作用域后 Part 保活；0/255 二进制字节；
  分段字段与文件头、原始 Part；Reader 重置重放；事件 data/size；
  maxParts 超限后的错误位置、失败状态和显式 reset。
- FormData：配置构造；重复名称替换；空文件名与无文件名区别；空值与未命中区别；
  set(Buffer) 复制字节、set(Body) 保留正文；clear/销毁后已取得 Part 仍可用；
  数量/正文预算失败不改变旧数据，捕获后可继续使用；非法初始容量。
- BodyDecode：既有入口覆盖嵌套 Content-Encoding、Headers 输入、未知编码和
  unchanged 路径。没有因此宣称压缩炸弹、所有截断组合、取消或 OOM 已覆盖。

## 仍未解决

1. BodyStream 既有用例的 async collect 仍被 XLIR 可达未终结块检查拒绝。
   需要在共享循环/异步 lowering 层定位，不能在库里增加伪返回或放宽验证器。
2. XWS 基础对象用例已恢复，但受控 TCP 回环用例仍报 ValueError: invalid argument。
   尚未定位具体失败调用，不认定为某一协议算法错误，也不宣称回调哨兵已经通过。
   TLS 回环、关闭竞争和长时压力本批未验收。
3. Client 和 BodyFile 的回调清理已消除旧未实现符号依赖，完整运行、取消和错误恢复
   仍待专项验证。公共 ABI 头中对应三个旧声明尚待随共享运行时接口清理。
4. 新增边界已登记到包 manifest；专项门禁尚未并入日常集中套件。
   这三个包的独立 C 运行合同、双语范例对照和官网详情仍需继续补强。
