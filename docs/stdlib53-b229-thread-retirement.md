# 线程完成与捕获退役同步

本批修复 Thread 最后一个外部引用释放时的真实竞态。worker 完成现在包括
捕获值、代码租约和错误作用域的清理，再与 worker 引用退役一起发布。
此前 Thread／Stack O2 故障前缀的间歇回收失败已通过确定性复现与修复后的
双端验收关闭。没有新增公开 API，没有修改 XRT，也没有改变 Cgen。

## 根因与状态转换

旧实现先清除 `workerActive`，然后释放捕获值。当捕获析构尚未完成时，
最后一个外部引用可能看到“只剩一个引用但 worker 不再活动”，因此跳过等待。
调用方随即返回，原生值、捕获 backing 或线程仍在退役，立即内存检查就会失败。
同一时间窗口还会使图认领过早地把活动 worker 当成已经完成。

新实现仍先在短暂的 mutation／元数据锁内移除 callable 拥有边，然后在锁外
执行捕获析构、租约释放与错误清理。worker 完成标记和真实 worker 引用的
递减在同一次受保护转换中提交，不能再分开观察。

外部释放、等待转换引用和 worker 完成采用独立的内部角色，避免把构造回滚
或等待后的引用释放误当成 worker 完成。最后一个外部引用仍在锁外等待；
自身释放不能等待自己。没有额外分配，没有以延时或放宽泄漏断言解决竞态。
XRT 的逻辑完成合同保持不变，不将此修复宣称为 OS 线程 join 或 image unload。

## 确定性与真实源码验收

`tools/check_stdlib_thread_retirement.py` 编译完整选定的 XRT／resident 闭包，
不使用旧运行库或模拟 provider。O0／O2 覆盖身份、图、停止、锁外等待、
方法并发、自身释放、租约、错误和完整构造分配失败前缀。

新增握手用例阻塞真实捕获析构，再释放最后一个外部引用。它必须观察到
实际等待而非提前返回，并确认 worker 仍不能被认领、等待未占住自己的
mutation／元数据锁。重建旧的过早完成实现后，该握手断言明确失败。
双端各 45 个阶段通过；Linux ASan／UBSan 覆盖整个选定原生闭包。

`tools/check_xlir_runtime_operand_catalog.py` 的完整线程入口在双端各通过
78 个公共阶段及其内嵌的 140 个线程语言阶段，包含真实 JIT、严格 C、
独立 AOT、导入裁剪、类型／ABI、拥有权和故障回归。源码驱动由 Windows
306 个、Linux 305 个翻译单元构建；供应方库仅提供记录在案的 TCC 核心。

原先失败的真实 O2 Thread／Stack 程序另外在每端进行 128 次进程运行，
并发度 8，合计每端 1664 个分配失败前缀全部保持 checked 失败与拥有值平衡。
故障宿主的立即平衡断言未修改；不以单独重跑偶然通过替代竞态验证。

## 剩余范围

本批关闭线程捕获退役竞态，不关闭 53 模块或发布长期任务。普通 union 的
原生容器配方、成对迭代、WaitQueue 拓扑和后端、其他压力场景及 shipping
DLL／SDK 总验收继续。CRT 未决策 0，XRT 19 个未决策组不变，对象池最后。
