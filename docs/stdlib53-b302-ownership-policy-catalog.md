# 对象图退役的精确策略目录

对象图策略现已从 JIT 宿主的集中分支表拆为 41 个独立能力声明，
覆盖原有容器、类、闭包、Future、任务、句柄及原生服务策略。
JIT 模块创建时构建只读目录，退役时复用共同解析器；独立产物
的编译计划可按实际驻留组件选择同一组能力，不必拉入整个宿主。
独立 main 的拥有记录和退出接线仍待完成，原有 AOT 循环图失败
继续阻塞发布。

## 策略与生命周期

目录有十一组保持真实 C 类型的策略切片。加载只发生在发布前，
数组按需增长，按实际地址去重；没有函数指针强转、不同类型指针
数组的别名访问、名称前缀猜测或固定数量上限。发布后目录不可
追加，查询不分配内存、不运行语言回调，可供并发只读解析。

原生能力以独立源文件和独立组件登记，声明自己的提供方与原生
模块依赖。目录本身只实现共同准入和基础 Value／Error／Cursor
支持，不直接依赖任务、网络、进程或正则。JIT 使用完整的已核验
驻留能力集合；独立部署从已验证的组件闭包取得精确 getter 列表。
策略目录与所有使用它的计划共享同一驻留代码和原生实现实例。

查询识别真实物理身份，在允许 Count／Trace 前校验具体策略。
未知身份被拒绝；部分输出、无适配器却声称识别成功，以及相互
冲突的准备／完成合同也被拒绝，不依赖首个匹配分支的顺序。
Future 使用完整的 V4 准入及准备合同，不退回较弱的旧接口。

目录持有自己的数组，不取得策略对象或语言值的拥有引用。原生
描述符、策略和回调代码必须比目录及计划活得更久。JIT 在初始化
前完成构建，所有退役计划结束且模块销毁时释放目录。

## 错误与失败恢复

构建失败释放所有部分数组。失败事件不依赖诊断对象是否成功
分配；加载方即便忽略 Add 的失败并清空诊断，也不能发布缺少
策略的目录。调用者已有诊断先于本次错误，外围已经捕获的无诊断
失败也不能被后续诊断覆盖。

初轮合同检查发现无诊断加载失败会覆盖调用者原有错误，现已
修复传播顺序；原失败记录保留。诊断阶段的单提供方替换仅用于
快速收敛问题，不作为最终产物验收。

## 编译与入口边界

声明 SDK 只携带头文件。初轮目录声明头曾包含不会随 SDK 交付的
原生登记 inc 文件，隔离 SDK 编译明确复现缺失；现改为纯函数声明，
组件审计校验声明与登记集合相同。私有头守门也拒绝未交付的非头
文件 sibling 引用，不以完整源码目录下编译成功替代声明 SDK 验收。

编译器提供独立的 ownership plan 派生步骤：校验输入闭包，按
精确组件登记选择能力，补齐所需驻留源文件，并保留原有原生模块
要求。损坏输入返回零结果，不输出部分可用计划。该步骤不改变
原有纯标量计划，也不从 AST 或生成 C 回推所有权。

后续 Cgen 只消费 getter 列表和入口合同。仍需创建并绑定独立
模块 owner、接入读边界以及驱动退出；原生合同宿主或源码 JIT
通过均不能替代真实产品 VFS 和独立语言 AOT 验收。

## 验收范围与剩余失败

两端完整源码构建为 Windows 391、Linux 390 个翻译单元。精确
组件审计各核对 352 个实际提供方、1578 个导出、123904 对依赖
组合及 23 个拒绝控制。

策略目录与源码 JIT 专项每端 110 阶段通过，包含隔离声明 SDK
严格编译、首错与无诊断失败、完整策略集合、发布后不可变、未知
节点不触发 Count／Trace、冲突合同拒绝及七个实际错误实现控制。
完整目录构建的 O0／O2 各扫描 19 个分配前缀，首个未触发点 18；
忽略 Add 失败的控制各扫描 4 个前缀，首个未触发点 3。

原有 Stack／Tree／Queue 完整宿主与语言断言不变，每端 78 种
场景、1534 次实际模块生命周期通过。静态模块宿主改用共同目录，
双端及 Linux 全参与源文件 ASan／UBSan 各 48 阶段通过；真实
裁剪实现各 42 阶段通过。两种优化级别均保留 49 次完整退役分配
前缀，首个未触发点为 48。裁剪宿主只选择三个领域及十一份驻留
源文件，不引入 Future、网络、进程或正则。

三组清单各 311 项，完成 run／module 发现批次：Linux 302 项
通过、一项预期拒绝、八项专用宿主／平台／产品条件单列；Windows
301 项通过、一项预期拒绝、同样八项条件单列，另有一项真实失败。
条件项没有算作执行通过；其中三类对象图另由上述完整宿主验证。
本批没有重新证明其他专用宿主或真实内嵌产品 VFS。

Windows 的 terminal_session 在 module 模式未收到调整后的尺寸，
5.672 秒后失败，run 模式通过；与此前已复现问题同类，尚未修复。
批量父门因该失败返回 1，不能以其他专项通过关闭发布验收。

移除旧 Cancel V1 兜底后，生成矩阵中的直接引用从 1810 变为
1809，cancel 从 12 变为 11；低层符号仍完整注册，延期清单不变。
同步的是引用快照，不删除公开标准库功能，也不放宽构建守门。
