# 源码包并发发布的 Windows 共享句柄

完整参数化批次发现：四个初始发布者使用临时文件加原子重命名时，
读取刚发布目标的 `Get-FileHash` 仍可能遇到 Windows 短暂的共享冲突。
这是发布工具的真实并发缺陷，不应归为被测程序错误或跳过并发测试。

目标文件现在以允许读和重命名共享的只读句柄计算 SHA-256。
只对 Windows 原生 sharing/lock violation（32、33）进行最多 5 秒的短暂重试；
缺文件、权限错误、其他 I/O 错误和哈希不一致继续拒绝。
仍逐文件原子发布，不覆写已发布目标，清单仍最后发布；没有把整个过程串行化。
测试子进程使用父进程的 PowerShell 版本，避免把 PowerShell 7 的模块环境
交给另一个版本的宿主。

沿用原有完整断言，在冻结 r5 源码上分别通过 PowerShell 5 和 7：
各 4 个初始并发发布者、4 个只读复用者、2,256 个内容及时间戳一致文件，
以及损坏目标不被替换的负例。60 秒子进程期限保持不变。
另在两版宿主中对原样提取的实际哈希函数强制施加 500 毫秒独占句柄，
确认它确实等待后返回完整哈希；缺文件仍立即报错，共四项控制通过。

`staging-sharing-r1/proof.json`。外部回归只替换源根及受测脚本绝对路径，
