# 可空原生值的容器元素合同

2026-10-13。`SlotMapKey?` 已接通 Array、Stack、List、Dict、Set 和
SlotMap 的元素存储、复制和取值。原生槽保存存在位与独立拥有的键，
容器移除、来源 SlotMap 销毁或模块终结，不会使此前复制取得的键失效。
本批不增加公开标准库 API，不修改 XRT 算法和单头。

## 存储和动态转换

普通原生键与可空原生键使用永久原生元素描述，共用 admission 策略
和拥有元数据的创建引擎。描述明确物理类型、逻辑身份、内容相等与
哈希、空目标、checked 复制，以及认证的动态转换。它不保存语言值、
生成代码回调或模块 lease；可信原生发布者负责描述的永久性和叶值合同。

| 值 | 原生槽 | 动态表示 |
| --- | --- | --- |
| `null` | 存在位为 false，载荷清空 | canonical null |
| 存在的空键 | 存在位为 true，空键载荷 | 认证的 SlotMapKey Value |
| 存在的有效键 | 存在位为 true，拥有实例身份及槽键 | 认证的 SlotMapKey Value |

可空元素身份属于可空类型；存在值的动态身份仍属于普通键。Set 和
序列内容比较消费显式存在位，不根据载荷指针猜测是否为空。缺省增长
产生 `null`，复制独立取得载荷，失败不发布部分元素。不授予排序能力。

动态转换不建立“装箱的 optional handle”：空值直接为 null，存在值
使用已认证的普通键。外国 handle 不能仅凭相同 TypeId 进入该元素域。

统一 IR 选择精确的拥有值槽、复制传输、缺省值和原生供应方。Cgen
只消费这些闭合配方，不添加容器算法、回溯类型拼写或特殊装箱分支。
拥有提取共用一个运行时算法，两种原生描述入口均核对输出空闲、
对齐、完整物理布局与内容策略；拒绝别名输出时不销毁接收者的槽。
wire Array 先成功取得独立值，再移除原项；错误类型保留原项。

## 双平台验收

Windows 322、Linux 321 个完整源码编译单元通过。本批专项分别通过
673、731 个阶段，包含严格独立 C O0／O2、实际 JIT、module 和 AOT。
每个优化等级执行 100 次 checked 主入口与模块清理。

每端 544 次完整复制／分配前缀检查通过，覆盖成功、无诊断复制失败、
分配失败、失败后的清理及完整重试；内存数量和字节平衡通过。原生
单元检查空值、存在的空键、默认增长、内容查找、原生／wire 提取、
占用与未对齐输出、接收者槽别名，以及错误类型拒绝。健康原生提取
在 fail-after-zero 下不触发分配。

两条可空序列配方的 10 项 IR 篡改同时被 IR、C／头文件发射和原生
计划拒绝。一个实际坏供应方忽略存在位并使 null 与存在空键采用同一
哈希，被单元拒绝。Linux ASan／UBSan 覆盖全部 51 个所选供应方、
生成程序及两个宿主；供应方用 O1，生成语言程序用 O0 编译插桩。

普通原生键容器回归每端 631 阶段、598 次故障前缀和五个实际坏实现
对照通过，每个优化等级执行 1000 次调用。可空原生捕获、旧 nullable
闭包和 cell 的 JIT／module／AOT 回归每端 12 阶段通过。

整批三组声明／严格 C 检测每端 293 夹具、585 阶段通过，包括一个
预期语义拒绝。驻留目录通过 283 组件、1456 个精确导出和 13 个拒绝
对照；未使用程序仍仅选择原先三个供应方，不引入可空元素组件。

证据位于 `E:/xlang-validation/stdlib53-b250-*` 和 Linux 的
`/var/tmp/xlang-stdlib53-b250-*`。最终证书核对所选源码、完整编译输入、
产物及日志。诊断部分链接、超时及失败尝试不计入最终验收。
