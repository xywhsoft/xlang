# 拥有型原生值的同步 IR 合同

SlotMapKey 首次接入统一 IR 的直接拥有型记录 ABI。它是不可变基础值，
不是可变 SlotMap 对象，也不是裸指针或无拥有权的 POD。Set 中的基础值
按内容判等；可变对象与容器仍按引用身份，不调用内容哈希。

## 一个声明描述表示与操作

`src/type/xl6_native_value_profiles.inc` 统一声明语言内建类型、精确 ABI
身份、驻留 C 类型、最小声明头、checked 返回载体，以及复制、释放、
判等、装箱和投影符号。语义注册、IR 类型分类与原生值计划复用此表。
外部结构体、同名类型或相同 sizeof 不构成拥有型值的能力认证。

SlotMapKey 的最小 C 记录只有独立实例指针与 64 位槽身份；实例不拥有
槽表，键可以比原 SlotMap 活得更久。C 赋值只观察或转移记录，不能
代替取得独立拥有权。生成 C 包含最小 ABI 声明，不重写驻留库实现。

## 生命周期与失败

复制观察输入、向私有空输出发布一个独立拥有权；返回 false 本身就是
失败，不依赖错误对象能否分配。正常复制不装箱，也不复制整个槽表。
复制和动态投影使用已有 checked 原生事务，装箱使用 NULL 失败合同。
IR 必须立即分支检查结果，成功路径安装拥有权，失败路径退役已安装
的拥有前缀，不能把未取得的引用当成已拥有结果清理。

只读同步参数可以观察调用方仍然持有的记录；会重绑定的参数在入口
先取得独立拥有权，不会改变调用方的变量。拥有型返回、多返回值、
丢弃部分返回值和赋值复用既有显式所有权指令。释放前先分离拥有槽，
再调用驻留按值 Drop；产品的已转移字段重置为准确的类型空状态。

原生值的按需依赖来自已验证的 IR 操作和可达产品类型，不扫描生成
C、不按源代码名称追溯，也不因登记一个未使用的内建类型强制链接
它的实现。checked 键复制目前与 Value 投影共用 KEY_VALUE 永久配置，
会选择该组件的哈希／装箱实现；不能声称此复制单独裁掉了这些实现。

## 验收边界

`check_stdlib_native_value_ir.py` 从隔离源码工具链生成真实 C 与 IR，
用真实 SlotMap 键跨参数、返回和产品传递，检查动态投影、跨实例
判等及 Value Set 去重。对错误 ABI 身份、普通 POD、普通 retain 和
损坏指令合同，应在 C／头文件输出之前拒绝。

Windows／Linux 源码构建分别完成 300／299 个对象。新同步专项两端
各通过 151 个阶段：实际 JIT、严格 C O0／O2、每优化级别 1000 次
生命周期、637 项损坏 IR 拒绝，以及 128 次完整故障前缀运行。
复制、投影、装箱逐个注入无诊断失败；OOM 逐次覆盖至首次不命中，
每次检查完整分配账本，失败后重试原始输入。另有三个真实编译的
错误实现，被同一源程序检查检出：丢失复制拥有权、跳过 Drop 和
跨实例错误判等。
返回值另有独立生存期见证：释放全部原始持有者后，只剩一个实例
分配存活；释放返回值后恢复完整基线。不以偶发悬空访问崩溃代替
拥有权检查，也不依赖或复制不透明实例的引用计数字段布局。

相邻键／原生值／SlotMap／Set 原生专项与旧 Value Set 语言用例通过；
Linux 原生闭包有 ASan／UBSan，新同步源消费者未做消毒、未作为裁剪
发布产物。依赖目录与三个相邻 Dict 裁剪产物回归通过；新语言键的
真实依赖计划选择独立键组件，但不选择 SlotMap 存储组件。证据保存在
`E:/xlang-validation/stdlib53-b210-*` 与 Linux
`/var/tmp/xlang-stdlib53-b210-*`；历史门禁失败不计为通过。

本批只覆盖同步直接记录，不代表 SlotMap 公开构造与方法已接通。
原生值的 nullable、捕获 cell、跨 await／yield frame 和直接容器槽
仍需要各自的拥有权合同；不得近似为普通结构体传输。三组 53 模块
总验收、发布库与性能验收继续；本批不修改 XRT 供应库或推广发布产物。
对象池仍放最后，CRT 与 19 个 XRT 未决策组不因本批扩张。
