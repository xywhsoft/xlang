## 实际修复

`xregex_valid_native` 原来在验证失败后无条件清除原生错误，把内存不足、模式
资源超限也变成 false。现在仅清除 domain 为 `xrt.regex`、kind 为 `XERR_VALUE`、
code 为 `XREGEX_ERROR_PATTERN` 的模式语法错误，其余诊断交给现有外部调用边界。

先增加 C 负例再修复，原实现稳定触发 `XERR_RANGE` 断言失败；未放宽断言或把
全部错误改成 ValueError。新增测试覆盖超长模式、非法视图、非法语法、验证过程
逐点 OOM，以及失败后继续验证。XL 测试检查资源错误可被 RangeError 捕获。

- [实现](../release/extlibs/xregex/xregex_native.c:238)
- [C 负例和分配失败](../release/extlibs/xregex/test/test_xregex_native.c:257)
- [XL 错误边界](../release/extlibs/xregex/test/xregex_lifetime_test.xl:86)
- 原实现失败记录：`build/test/xregex-delivery-20260927-before/results.json`

文档统一了 matcher/splitter 的输入副本、C 借用视图、捕获独立存储、字节偏移、
集合结果顺序、拆分 limit、回调使用限制和明确 error 对象。清除旧连续数组布局
说明，改为公开 xvalue API。C 绑定的物理原型全部纳入真实生成声明检查。

## 尚未覆盖

未验收 Linux xlang JIT/AOT、32 位/ARM、任意线程共享可变 matcher/splitter，
也未建立完整性能基准或全局 CPU/内存预算。正则对象的跨线程使用必须遵守文档，
不是因为通过 ASan 就可以任意并发修改。后端、源码或运行库更新后必须重跑。

下一批优先处理 CSV 的整体异常与 C ABI 边界，不只改一个用例预期。CSV 的
原生错误发布目前会丢失错误码/位置，语言层的 CsvError 分支被通用 RuntimeError
提前截断。后续需覆盖 reader/writer、构造失败、格式错误、IO、资源上限、OOM、
错误原因链与 LLP64/LP64 声明；此处仅记录待办，不表示已修复。
