# 粒子世界的原生拥有底座

本页保留前一批底座的尺寸与验收。后续 [World 声明与碰撞回调](xge3-particle-world.md)
已补入原生持久拥有碰撞、xlang World 与回调期快照／子定义；当前受管对象为
600 字节，普通 C 对象仍为 496 字节。下述 568 字节是前一批的历史测量。

本批补齐同一个 XGE 原生 ParticleWorld 的共享引用、创建线程检查、活动调用保护、
checked 释放和完整拥有图协议。原始 C 创建接口继续使用原有的借用碰撞回调及显式
同步规则；受管创建拒绝借用碰撞指针，不把闭包藏在不可追踪的 userdata 中。

16 个状态返回入口和 Stats 在读取世界前完成受管准入。Visit 中释放最后一个长期
引用时，真实活动引用保护世界到回调和调用尾结束；拥有图在活动中拒绝 claim。
原生状态／EventPoll 的正常非负值保持原义。清理失败即使没有诊断也会报告；
`consumed` 为真后不重试释放已消耗的引用，已有失败优先于后续清理错误。

构造函数在调用任意代码拥有者 Hold 前，分别复制描述符和拥有者合同。回调修改原始
参数不会绕过借用指针检查，也不会把已保留的拥有引用发布成另一份被修改的合同。

普通 C 世界仍为 496 字节；只有受管创建分配含拥有元数据的 568 字节原生对象。
相同小配置两者都分配 5 次，实时请求字节分别为 1232／1304。共享不分配或复制
另一个世界。两者各 1000 对预备 Update(0)／Stats 调用均零堆操作；原始模式仍有
一次模式准入检查，受管模式还有线程／状态检查、原子引用及活动计数、拥有转换和
错误处理，不声称 CPU 等价或整条调用路径零开销。

两端使用完整编译器的唯一 XRT、O2 实际 DLL／DSO 和静态库，独立 GCC O0／O2
客户端分别运行原始／受管内核断言及生命周期、拥有图、线程和 OOM 检查。旧候选
单独验证构造输入快照缺口；上一轮粒子定义也在新 SDK 上执行完整 JIT／动态／
静态回归。详情记录在 `dev/release-materials/provenance/xge-particle-world-ownership-20261114.json`。

这一步尚未公开 xlang 的 World 类。持久拥有碰撞回调、快照／条件输出、渲染器与
GPU 拥有关系还要继续补齐；最终配套发布目录和 IDE 也没有在本批替换。
