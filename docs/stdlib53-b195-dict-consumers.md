# Dict 通用消费者与宿主拥有图接入

原生 Dict 接通静态及擦除遍历、通用浅复制、深复制、计数、成员查询、
动态删除和持久化投影。存储仍复用真实 XRT `typed_dict`，递归处理
复用现有 Value 图引擎。Set 与 Dict 同时登记到实际宿主的拥有图解析器。
语言 `dict<T>` 工厂、静态方法配方和恢复入口仍待迁移，本批不代替
发布 DLL、VFS 或完整 53 模块验收。

## 遍历与精确键长度

Dict 的驻留遍历器持有独立 typed 快照和一个当前 Value。私有键视图
来自游标拥有的快照，不从源容器借用，也不为每步重复分配键；语言
读出仍按 Data 和 Size 创建独立字符串。清空或释放源 Dict 不影响
快照，语言结果可独立于游标存活。空键、内嵌 NUL 和 UTF-8 均保留
精确字节长度。

推进的 checked 成功与 found 分开。真正 EOF 可重复读取，失败保持
sticky，不能把无诊断失败伪装为正常结束。拥有图只追踪快照和当前
Value，不把 View 或键视图重复计为拥有边。静态 Dict 遍历提供者与
擦除分发器分别登记；静态入口不依赖 List 或 Set 的算法组件。

## 复制与持久化

浅复制创建独立 Dict 外壳，保留完整逻辑准入、驻留转换合同及实际
引用子对象。通用成员查询只接受 string 键，错误类型是 checked
失败；缺失、删除和 take 的正常不存在结果保持 false 或 null。

深复制与持久化通过同一个引用映射处理 Array、List、Dict、Set 和
普通动态值。重复子引用仍指向同一个新子对象，原对象及其名义身份
不变。非引用的原生值槽直接复制，无需先装箱再拆箱。引用槽直接
交给已有图引擎，避免获取正在遍历的祖先 Value 外壳。

Dict 持久化结果是 OBJECT，键保留精确长度；不能把 Dict 悄悄变成
序列。活动祖先循环按现有图复制合同 checked 拒绝，不发布半成品。
这与拥有图的循环退役能力不同：复制不接受循环，不表示资源清理
无法处理循环。

Set 的键规则保持已确认的决策：基础值按内容，可变对象和容器按
引用身份。测试在 Dict 插入 Set 后继续修改其子对象，再检查成员
关系，确认内容修改不改变身份键。

## 宿主拥有图

宿主解析器登记两种真实原生适配器，并沿用已有的独立准入策略
白名单，包含 Future 等槽的授权。不能仅因 HANDLE 标签、相似身份
或非空 Trace 就把未知原生节点当作已知容器或叶节点。

专项测试编译实际 `xl_api.c`，用真实 Dict 和 Set 的重复、自引用及
交叉引用构建闭合图，运行现有分阶段计划的准入、提交、Finish 和
销毁。分配失败逐点重试，检查每次资源账本。删除任一种宿主登记
的实际错误实现都会被测试拒绝。此证明覆盖宿主解析器和计划，
不声称已经验证 TCC 代码页删除或所有模块终结组合。

## 验证范围

Windows 和 Linux 完整源码编译分别包含 291 和 290 个对象。原生
Dict 基线、Dict 消费者、Set 消费者和实际宿主计划均运行 O0 与 O2，
分配失败及 checked scope 无诊断拒绝使用完整前缀，不抽样。
Linux 所选原生消费者闭包运行 ASan 和 UBSan；这不表示整个编译器
已做 sanitizer 验收。

语言侧复测 Set、List、动态字段和共享遍历合同，检查严格 C、JIT、
源代码 AOT 及按需组件。组件目录包含 252 项、1334 个实际驻留导出，
逐一核对真实目标文件和 63504 对依赖关系。

证据位于 `E:/xlang-validation/stdlib53-b195-verify-win-dev1` 和
`/var/tmp/xlang-stdlib53-b195-verify-linux-dev1`。源码与最终选择索引
逐项核对；供应方 XRT 内容保持不变。文档总守卫的 14 个历史诊断、
两项静态守卫的历史首个失败保持单独记录，不能计为全仓通过。
