# IDE 编译前置与源码快照错误传播

嵌套编译缺少五个编译单元，导致完整工作区的字符串桥接 AOT 无法链接。
本批已整理用户批准的必要依赖：源码覆盖层、源码报告、构建输入记录、
补全和语义索引，以及它们需要的 AST 来源、诊断、C 桥接和 TCC 输入接口。
不纳入独立 IDE 应用、扩展库或无关测试清单改动。

## 编译单元归属

普通 Windows、Linux 构建和嵌套编译使用一致的来源清单。
`xl6_build_inputs.c`、`xl6_source_overlay.c`、`xl6_source_report.c` 和
`xl6_completion.c` 属于共享编译基础；`xl6_sem_index.c` 仅在包含完整
编译器的配置中加入。runtime-only 配置不因新增可选索引而编入完整索引器。
Windows 响应模板仅增加这些来源，保留原参数顺序，不提交工作区的重排和空白。

AST 来源和范围在克隆、导入及规范化时保留；语义声明类型只在查询模式捕获，
采用深度、访问次数和文本预算。C 桥接的来源映射使用降低后声明的真实语义身份，
不按名称猜测。构建记录通过既有公共入口串行化的 TCC 输入回调及资源读取器
获取首次快照；活动记录与 TCC 磁盘回调、工作目录共用编译器 API 锁，嵌套进入
后恢复先前绑定。普通未启用记录的编译仍使用原来的输入路径。

Windows 独立嵌套程序曾在构建记录的 `__thread` 读取处崩溃：实际 PE 指令使用
ELF 式 FS 段地址，不能依靠系统 GCC 能构建 DLL 来证明内嵌 TCC 的 TLS 正确。
该处取消冗余 TLS，使用已有全局编译锁保护的活动绑定，不引入新的系统 TLS
分配、失败恢复或并发承诺；原有磁盘回调和工作目录本来就要求同一串行边界。

Linux 的完整原生头搜索另暴露旧 4096 项未命中候选预算过小；实际八个上下文
各记录 6174 项、591242 字节的候选路径。候选记录改为
最多 32768 项，并增加独立的 8 MiB 路径字节上限；重复候选不重复占用预算。
数量和字节两项上限均有 checked 拒绝测试，不用无界增长绕过资源限制。

Windows 内嵌 SDK 另补齐 `CompareStringOrdinal` 的正式原型，不添加本地比较
替身。消费者通过实际内嵌 TCC 验证函数指针类型、大小写、前缀和显式 NUL 长度。

## 失败传播

源码身份比较区分相等、不同和失败。覆盖层查找区分找到、不存在和失败，
路径规范化、严格 UTF-8 转换或比较分配失败不能转成“不存在”。存在性查询、
解析、token 输出和多候选 import 解析均传播失败；附属源码报告同时失效。
覆盖层更新、移除在比较失败时保留旧快照。

补全在输出成功 JSON 前解析全部来源身份。末尾条目发生错误时，整份补全
返回不可用和空列表，不发布已经开始的部分成功结果。真正未知的来源仍可
表示为未知，不能与资源错误混淆。

## 验收范围

`check_stdlib_source_identity_faults.py` 在 Windows、Linux 的 O0／O2 下
编译项目实际源码，用一次性故障观察器转发真实 XRT 和解析器。每端六项证明
包括两个修复版本通过、两个旧源码错误读取磁盘的拒绝对照，以及两个 import
吞掉错误的变异拒绝对照。该测试只把实际产品库作为 XRT 提供方，不冒称实际
编译器产品的故障注入或完整编译器 OOM 验收。

Windows 另以同一 AST 和解析适配层对比原生成解析器与当前生成解析器，当前
2946 份语言夹具的接受／拒绝结果完全一致。这是生成解析器改动的源码差分，
不是全部语义行为证明，也没有更新夹具基线或把无关新增夹具纳入提交。

`check_stdlib_ide_cli_shipping.py` 使用同一普通构建的三个实际产品，在不含项目
实现源码及磁盘 SDK 的目录验证精确报告、范围、语义索引、补全、未保存覆盖层和
C 桥接；保留
普通编译拒绝半成品、UTF-8 内部游标、无效 C 公开名及冲突参数的负例。
该门是双平台产品聚合验收的必需子项，不使用源码编译器替代产品。

Windows 的十四项既有 IDE 测试另外覆盖公共 API、范围、覆盖层、报告、索引、
补全、C 桥接、环境及来源映射、包解析、构建输入与配置、TCC 传输和目标查询。
完整产品清单、独立 AOT、严格 C 和原生裁剪使用同一新候选，各自保留结果。

`check_stdlib_build_input_scope_shipping.py` 从四个原生调用线程同时请求真实
编译器构建，分两轮验证八个独立上下文的语言源、C 文件和头文件摘要、其他
上下文排除、checked 构建记录及实际程序执行。它验证 API 串行边界下的
隔离，不宣称 TCC 内部并行编译。

## 最终同源产品结果

普通构建的两端 1020 份生产源码一致，报告、输入、产物和日志分别在各自原生
文件系统复核：Windows 29676 个文件，Linux 25976 个文件。未复用旧产品子门。

| 验收 | Windows | Linux |
| --- | --- | --- |
| JIT 和模块清单 | 328 项人口，319 个适用正例通过 | 同左 |
| 可搬移独立 AOT 清单 | 328 项人口，318 个适用正例通过 | 同左 |
| 产品必需子门 | 28 项全部通过 | 29 项全部通过 |
| 严格 C | 654 个 O0／O2 对象及 6 项拒绝控制通过 | 同左 |
| 原生定位和裁剪 | 53 模块、48 配置、106 对象及 6 项反例通过 | 同左 |

裁剪对象数包含反例使用的变异配置。JIT／模块清单仍单列七项专用宿主、一项
预期拒绝和一项平台条件；AOT 单列八项专用宿主及相同数量的拒绝、平台条件。
专用宿主能力另由必需子门验证，不把编译成功改写为运行通过。

同源码四通道执行用例关联全部 699 项公开签名：142 项原生、228 项静态和
329 项类可调用成员，无关联缺口。这不是全部运行分支覆盖证明。

构建与各验收目录的共同前缀是 Windows 的
`D:/xlang-validation/stdlib53-b350r3-` 和 Linux 的
`/var/tmp/xlang-stdlib53-b350r3-`，后接 `build`、`products`、`aot`、`strict`
或 `pruning` 及平台后缀。Windows 十四项 IDE 专项为 `ide-product-win/results.json`；
两端源码故障专项为 `identity-unit-<platform>/results.json`。跨平台关联记录为
`/var/tmp/xlang-stdlib53-b350r3-cross-certificate.json`。

旧失败、旧 SDK 拒绝及 Windows TLS 崩溃证据分别保留，不改写为通过；本批
完成必要 IDE 前置及完整工作区的上述回归，53 模块仍保留最终逐项完成审计。
Windows DST 仍按用户决定独立待验收；CRT 无未决策项，XRT 其余十九组和
对象池最后的顺序不变。
