# 任务池空闲线程的拥有图准入

Windows clear 续体独立 AOT 的退役失败来自 XRT 任务池：任务已经
完成，部分工作线程尚未首次停驻，拥有图却把 `Parked == false`
当成非法状态。修复落在真实原生池的 Count 合同，不修改 clear
断言，不给生成 C 增加等待或资源特例。

## 根因与不变量

池已完整发布且没有活动任务、finalizer、原生入口或销毁操作时，
工作线程可能尚未进入第一次迭代，也可能处在相邻迭代之间。
拥有冻结会阻止它们进入下一次 mutation；没有必要要求它们都
恰好睡在条件变量上。原检查错误地依赖了操作系统调度时机。

Count 继续拒绝运行任务、finalizer 与清理尾部，继续检查队列
一致性、完整线程发布、初始化及销毁状态。退出线程不能仍被
标记为停驻，Joined 必须对应全部线程退出。线程仍是池独占的
原生资源，没有新增虚构引用或折算引用计数。

Prepare 仍负责关闭、等待退出与实际 join。只有所有参与者准备
完成之后才 Clear／Finish；本次修复不允许提前释放线程或池。

## 核心修复的同步范围

XRT 模块化实现与其生成的核心单头同步更新。xlang 两份已固定
版本的消费头精确移植同一个 Count 函数，并更新各自的快照摘要。
`lib/xrt/backports/task_pool_idle_workers.json` 记录上游树、源文件
摘要、函数摘要及消费头修改前后的摘要；它不是全库升级记录。

上游近期的网络扩展拆分，以及工作区其他文件系统改动，不属于
本批。消费头没有假装与当前整个上游单头一致，也没有改变公开
函数、类型或导出数量。验证同时核对函数与上游精确一致，以及
消费头除这一个函数外保持原样。

## 验证

新的确定性原生向量先冻结拥有域，再创建池，保证线程还没有
进入第一次 mutation。旧 Count 在第一次断言即失败；新版直接
取得精确单节点图，随后完成真实 Prepare、join、Clear、Finish
和引用释放，检查活跃分配数量与字节平衡。

XRT 池拥有、原生入口和延迟资源测试在 Windows GCC／TCC、
Linux GCC 及 Linux ASan／UBSan 四种配置下，各运行六个模块化
和单头测试进程。原有活动任务、finalizer、重入原生调用和资源
尾部拒绝向量保留。消费头另按 O0／O2 分别编译两种头，包含旧头
确定性失败对照；Linux 对选定依赖实现加 ASan／UBSan。

真实产品的 clear 专项、重复搬离执行、三组夹具和附加宿主门
分别记录，不以原生向量通过替代产品验收。

最新 Windows／Linux 产品的 clear 专项各完成 30 个阶段、10 份
生命周期证明；原始错误及错误续体两份搬离程序各重复 50 次，
每端 100 次全部正常退出。重复器不重新编译、不修改生成 C，
也不在失败后重试到通过。数值转换十项原始夹具各完成 61 个
产品阶段，静态／动态安全转换规则不变。

三组普通夹具每端各 311 项，303 项执行通过、一项按预期拒绝，
六项专用宿主要求和一项平台要求继续单独记录。Windows DST
条件用例与 Linux 旧平台进程用例不计入已执行数；宿主专项及
完整汇总门以各自最终报告为准。

## 剩余目标

31 个可达原生拥有入口的布局审计、全局 exit 的完整清理实现、
Windows 终端间歇问题及完整发布验收继续。CRT 未决策仍为零，
XRT 其余十九组未决策不变，对象池仍最后处理。
