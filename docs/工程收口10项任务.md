# DEMO6 工程收口 10 项任务

本轮任务目标不是扩展新语法，而是把已经实现的 DEMO6 能力压实成更成熟的编译器工程骨架。

## 1. canonical type

- 建立统一的类型规范化模块。
- 普通类型、泛型类型、func 签名、类型别名展开使用同一套输出口径。
- ABI 元数据、ABI、语义检查、后端生成后续都应优先复用该模块。

## 2. ABI 元数据 权威化

- ABI 元数据 继续作为机器生成的ABI 元数据。
- ABI 元数据 不要求用户手写，也不引入 `.xli`。
- ABI 元数据 应包含导出、导入、入口点、调用约定、参数形态等稳定字段。

## 3. package/import 第一版

- import 第一版只做本地 package/path resolver。
- resolver 负责把 import target 映射到可能存在的 package manifest 或 ABI 元数据 文件。
- 不解析 C，不从 C 自动生成接口。

## 4. 临时产物管理

- build/run 使用独立临时目录。
- 默认成功后清理临时 C/header/ABI 元数据/wrapper/exe。
- `--save-temps` 保留临时目录，便于调试。

## 5. ABI callable descriptor

- 建立 callable descriptor 地基，统一描述 calling convention、可变参数模式、必填参数数量等。
- xcall、cdecl、stdcall 的后续融合都应基于 descriptor，而不是分散判断。

## 6. cgen 拆分地基

- 不急于大拆 `xl6_cgen.c`。
- 先把类型规范化、callable、构建后端等跨阶段能力移出 cgen。
- 后续再按运行时片段、符号、类型映射、语句/表达式生成逐步拆分。

## 7. 错误诊断增强

- CompileUnit 负责记录当前阶段。
- CLI 输出错误时带阶段上下文，便于长期排查 parser/sem/cgen/backend 问题。

## 8. 测试体系拆分

- 保留现有完整回归入口。
- 增加分层批处理入口，方便只跑 smoke、feature suite 或全量组合。

## 9. 跨平台构建口径

- 建立 build backend 接口。
- 当前实现仍以 TCC 为默认后端，但不再把所有 TCC 路径散落在 CLI 逻辑里。

## 10. 生命周期强化

- `xlInit`/`xlUnit` 使用引用计数。
- xlang main 自动初始化/卸载。
- C main 仍需显式调用 `xlInit`/`xlUnit`。
- DLL/shared 入口保留平台差异处理地基。
