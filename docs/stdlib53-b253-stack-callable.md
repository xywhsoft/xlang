# 函数值 Stack 的存储与验收

2026-10-13。Stack 已接通现有可运输函数签名的必选和可空元素域。
单项、try 系列、clone、equals、reserve、clear、trim、嵌套 Stack 及
Array 批量交换通过双平台执行。本批不增加标准库方法名，不修改 XRT
或 xruntime；新增一个按需选择的编译器私有读取组件。

## 签名和存储

函数的调用表示仍为原生闭包，容器槽则保存拥有的 boxed callable。
XLIR 的 Stack 配方明确两者之间的 closure codec、基础函数签名、
nullable 规则、Value 槽及 retain 传输；不能把闭包地址当作 Value 地址。
成员签名、降低、验证和 Cgen 共用既有 owner 局部合同。

压入先完成带精确签名的 boxing，再交给原生槽；临时 box 在错误隔离
范围内清理。clone、equals 和批量传输沿用已有 boxed 引用语义，不执行
函数，也不复制代码。批量结果保留来源的逻辑准入策略。

## 读取与弹出

独立原生读取组件先核对物理槽、签名和 callable 家族，再创建拥有
Value 引用及入口代码租约的闭包。转换、分配或宿主租约取得失败时，
原栈保持不变。即使租约取得返回成功，只要设置了错误，也会回滚而
不弹出。只有投影成功且无错误后才移动栈顶；移出的 box 在 Stack
pin 之外释放，取得的闭包继续拥有它。

输出必须是空、对齐且与容器存储互不重叠的编译器私有拥有槽。重叠
检查先于输出写入，不允许 found 指针改坏槽内容。它不是公开 byref
能力。try 系列的 found 位独立于 nullable 函数载荷，成功取出 null
与没有元素保持不同结果。必选读取在没有元素时返回 RangeError。

Stack 不保存生成代码的投影回调。返回闭包通过已有运行时取得代码
租约，来源容器销毁后仍能调用。Cgen 只选择已声明的 codec、入口和
结果槽，不生成元素遍历或容器事务算法。逆向入口直接根据可达的
Stack 读取和基础签名选择，不依赖取得的函数随后是否被调用。

## 双平台验收

Windows 324、Linux 323 个完整源码编译单元通过。专项分别通过
312、344 阶段，包含严格独立 C O0／O2、实际 JIT、module 和 AOT。
每优化等级执行 100 次 checked 主入口及模块清理、200 次原生
生命周期和两种元素域的循环所有权图回收。

每端 208 次完整语言分配前缀、32 次原生投影分配前缀通过，包含
成功终止点。失败后检查原栈的数据指针、分配、数量和容量不变，再
清理并重试。宿主代码租约关闭或错误、伪造 callable 家族、错误签名
和 found 存储重叠均被拒绝；代码 pin 和内存计数平衡通过。注入限于
同步调用线程，不代表 executor 线程或图遍历 OOM 已封板。

两种元素域、35 个调用的 78 项错误 IR 被验证器、C／头文件发射及
原生计划拒绝。三个实际错误供应方分别先弹出再转换、跳过签名检查、
忽略转换期间错误，均被拒绝。Future Stack、普通及可空原生键 Stack、
callable/Future 队列和只读最小程序完成每端 15 个实际执行回归。

Linux ASan／UBSan 覆盖生成程序、全部 24 个所选供应方及语言宿主。
原生宿主另显式链接并插桩对象图计划供应方，不将它计入语言程序的
裁剪结果。只读最小程序不选择通用 Stack 组件，基本程序仍只有原先
三个供应方。

三组声明与严格 C 检测每端 297 夹具、593 阶段通过。驻留目录核对
285 组件、1459 个精确导出和 13 个拒绝对照；新入口仅登记一次。
证据位于 `E:/xlang-validation/stdlib53-b253-*` 和 Linux 的
`/var/tmp/xlang-stdlib53-b253-*`。最终证书核对所选源码、完整编译
输入、产物和日志；中途失败的尝试不计入最终验收。
