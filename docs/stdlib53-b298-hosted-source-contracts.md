# 专用宿主验收与终端尺寸观察

六项专用宿主夹具使用当前完整源码提供方重新执行；旧产品记录不能
替代本批源码结果。对象图、真实 Promise 完成时序、首错与析构注入
沿用原宿主，不替换标准库提供方。已核验的完整报告可接入三组
批量清单，未提供报告时仍明确标为需要宿主。

## 六项宿主矩阵

每端 165 个阶段、106 种组合、1682 次计量生命周期，覆盖 O0／O2。
Stack 200 次、Tree 384 次、并发 Queue 950 次；三次 await 的成功、
拒绝、取消和关闭，在 ready、真实 pending Watch、真实 pending
Commit 时序下共 48 次；同步及 async／generator clear 共 100 次。
保留外部根、深复制、完整字段析构、一次性释放及内存账本断言。

缺失 pending Commit、改变夹具、减少生命周期、替换编译器及失败
阶段伪装五种损坏报告均拒绝。消费方重新核对源码指纹、编译器、
夹具和全部输入／产物，不能通过手工设置“已执行”覆盖这些要求。

初版新报告收集器错误地把最后保存前的报告本身纳入产物哈希。
报告不能自哈希；独立认证保留原执行报告及其最终哈希，核验全部
其他产物、日志、矩阵和输入，不重放执行、不改写原结果。后续
直接收集同样排除报告自身。

## 终端观察时序

原尺寸断言在 256 次当前源码重复探测中复现一次：TTY、stderr 和
输入回复齐全，但子程序仍报告 80×24。Microsoft 的公开 ConPTY
实现成功写入 resize 控制包后返回；控制信号和输入是独立通道，
不能把请求接受当作子程序下一次输入读取的观察屏障。参考
[ConPTY 实现](https://github.com/microsoft/terminal/blob/main/src/winconpty/winconpty.cpp)。

本批修改私有测试子程序及用例协议，没有修改 XRT 或 Cgen 生产算法。
Windows 消费真实控制台输入／尺寸事件；POSIX 使用 SIGWINCH 和
实际窗口尺寸。等待有五秒上界，不靠固定延时。父端继续严格验证
三个 TTY、stderr 合流、96×32、完整回复和退出码。

新增确定性顺序用例先收到“完整输入已读”的应用确认，再发送 resize。
两端严格 C O0／O2、JIT、模块和 AOT 通过，各 128 次重复会话；
跳过 resize 和改错尺寸在 JIT／模块共四个反例中必须失败。
每端终端专项 149 个阶段；历史失败原始字节仍保留为归因证据。

## 验收范围

本批是精确源码及生成语言程序验证，不是新的共享库发布验收；
没有证明独立 AOT 对象图退役、完整原生插桩、工作线程 OOM、真实
模块取消映射或 Windows 全进程句柄零增长。此前 Stack 补充 O2
插桩编译超时仍未完成。真实 CLI／DLL／VFS、Windows DST 和完整
53 模块验收继续，CRT 0、XRT 19 组未决策及对象池最后不变。

证据位于 E:/xlang-validation/stdlib53-b298-* 及 Linux 对应目录。
