# 原生拥有值在生成器中的保存和清理

SlotMap 完整键已接入真实生成器帧。成对和仅键遍历可保存键跨越
yield，键参数则复制一个独立拥有值；正常恢复、提前关闭、finally
和恢复后抛错使用同一套经过验证的清理合同。生成器帧不会把原生
结构体当成普通字节或指针，生成 C 不增加键专用析构程序。

本批只完成同步生成器里的原生键保存。generator 的原生值语言级
结果、完整键跨 await、Future 元素遍历、WaitQueue 和三组标准库
发布总门仍待完成；对象池仍放在最后，未决策功能没有进入本批。

## 描述与实际拥有者

GeneratorRuntimeV3 消费 V2 激活和当前元素描述，复用已有生成器
状态机、独立控制引用、帧引用和代码租约。V1、V2 原生入口与旧
Capture V1 描述保持不变；不同版本的描述不能相互强转。

尚未发布的 Capture V2 原生槽改为保存常驻发布函数，该函数返回
相同的永久只读能力。这允许 JIT 和独立 C 产品使用常量布局，
不需要外部数据导入、每帧适配器或额外分配。捕获头只依赖必要
声明，不再间接要求整个文本库的类型声明。

真实帧记录自己的分配长度。拥有值追踪和清理消费该长度；稀疏
标志决定哪些槽已取得拥有权。帧可以被独立 pin，控制关闭会清空
其拥有槽，却不会提前释放仍有独立引用的物理帧。原生当前元素
也可直接转移给原生接收者，在帧和控制释放后继续独立存活。

清理先在同一次 mutation 内将精确类型槽和初始化标志清空，
再在 mutation／freeze 之外释放资源。原有字符串、动态值、
Future、closure 等资源继续使用常驻清理引擎；首个失败、包括
没有诊断对象的失败，不能被后续清理覆盖。

## 统一 IR 与生成 C

封闭的原生值声明增加捕获头和常驻发布符号。XLIR 明确给出
native-value destroy 与 copy-native-value transfer；原生叶子没有
语言对象图出边，但仍有独立拥有权和清理标志。验证器拒绝将它
改成 trivial copy、普通指针、无析构槽或不匹配的追踪种类。

Cgen 只序列化已经验证的布局、动作和符号。键参数复制使用原生
checked copy 的成功状态，失败时回滚已取得的帧拥有值；不能用
空结构体代替失败判定。尚未具备完整失败边界的独立 borrowed SSA
原生值复制 spill 继续明确拒绝，不添加隐式错误路线。

```c
{ XL6_SlotMapKeyV1 xlir_acquired = {0};
  bool xlir_acquired_ok = xl6SlotMapKeyCopyValueV1(a0, &xlir_acquired);
  /* 检查成功状态，之后提交槽和初始化标志。 */
}
```

原生键 copy 和 clone 从装箱组件移入原生拥有值组件，复用真实
xrttype copy，不依赖动态值装箱、哈希或转换器。拒绝非空或未对齐
输出，复制失败不覆盖旧拥有值，调用者的 ambient error 被保留。
成对 SlotMap 快照本身仍有既有的值转换依赖；这不能误计为捕获
层的新依赖，语言生成 C 中也没有新增键装箱调用。

检测，12 组前缀均跑到末端，
覆盖帧和控制分配、键值／键游标、直接键复制及参数复制的无诊断

1000 次；当前键元素的取走、未取走、提前关闭与重复关闭都有检查。
