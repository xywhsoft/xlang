# 构造期明确赋值合同

状态：已实现并完成本项双平台专项验收；五组标准库的整体验收仍在进行。

非空原生资源字段可以在实例 `create` 体中初始化。现有的显式字段默认值先执行，
没有默认值的必赋值字段保留构造义务，不创建空资源、临时 nullable 值或运行时
初始化标志。静态字段、局部和全局原生资源仍须显式初始化；队列的既定声明
初始化规则不变。

Typed XLIR 用 `CONSTRUCTOR_REQUIRED` 记录该义务；所有原生布局齐备后统一关闭
该分类，不能受类型登记顺序影响。语义入口和 Typed XLIR 共用一个不可变的结构化
流分析器，分别表示正常、返回、抛错、break、continue；每个字段使用待初始化／
已初始化两点域，循环求有限不动点，finally 分别作用于各类出口。异常边按既有
效果和潜在分配的保守上界处理，不推断任意用户过程永不抛错。

初始化安全还在实际 Lowered CFG 上独立证明：正常返回的所有路径必须完成赋值；
字段写入经过 `ERROR_TEST.trueTarget` 成功边后才算完成。
读取未赋值字段、在完成前把不完整接收者交给用户代码或闭包均拒绝。分支、循环、
异常、catch、finally 使用同一控制流事实，不依赖源语句先后顺序推测。

基类构造完成只满足它拥有的字段。若基类构造会暴露接收者，调用处还必须证明
其他派生必赋值字段已经初始化；不能因基类的静态接收者类型而忽略派生字段。
构造函数间摘要按真实绑定的基类调用递归关闭，不以函数名猜测目标。显式 create
若需要基类体完成继承字段的义务，必须在正常出口前完成相应的 `base(...)` 调用；
没有显式 create 的派生类沿既有默认基类构造链执行。

构造接收者的规范符号在语义阶段保留到 XLIR，并随单态化重映射。泛型构造体按
每个具体布局的真实字段声明检查；Lowered 端按实际接收者、提升 cell、SSA 值与
编译器临时拥有者跟踪。不完整的 self 不能创建普通局部别名或被闭包捕获；直接
`self.field` 只提供构造期字段地址，不构成 self 逸出。

调用处也验证构造事务：每次实际分配重新建立字段义务，只有真实构造调用的成功
边才能满足它们；生命周期 COMMIT 之前不能公开不完整对象。局部／全局中已经
发布的完整对象与后续循环迭代的新分配分开处理。

失败沿现有构造事务释放已经提交的字段；对象只有在构造成功后才注册用户终结
程序。新增规则必须复用并验证这一回滚合同。普通赋值仍可替换已初始化资源，
其拥有权、错误边和消耗规则保持一致。

Cgen 只消费验证后的操作和控制流，不增加 Pattern 特例、运行时状态机或字段
回溯。多返回值写入实例字段复用既有的受保护元素地址和写入事务，RHS 只求值一次，
各项在检查成功后依次提交。

2026-10-28 专项结果：两端各通过 42 项底层流分析测试、24 个真实语义／Typed／
Lowered 用例、38 项 IR 拒绝变异，以及真实 JIT 和 AOT。组合夹具包含 11 个待赋值
字段、9 处必需字段写入、继承、泛型、多返回值、提前返回、catch／finally，以及
构造中途失败。Windows／Linux 的 O0／O2 四条运行路径各验证完整的 431 个实际
分配失败点，共 1,724 个，均内存平衡；未完成对象不执行用户析构。

增加调用处验证后，生成 C 与此前完成 OOM 验收的版本逐字节一致；保留原始四条
失败前缀证据，并对最终编译器重新运行语义、变异、JIT／AOT。Linux 底层求解器
另通过 AddressSanitizer／UndefinedBehaviorSanitizer。完整 Regex／Pattern 工作器、
正常产品及全部 74 项整体验收仍须继续，不因本项专项通过而标记整体完成。
