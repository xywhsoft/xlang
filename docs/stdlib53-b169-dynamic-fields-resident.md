# DynamicFields 驻留 ABI 与语言拥有图

DynamicFields 的已有语言接口已迁移至驻留实现和声明化调用合同。
本批接通原生字段节点、语言 handle 与宿主拥有图，不等于 Open 恢复事务、
其他容器恢复或标准库发布总门完成。共享默认子对象仍须按声明的 clone
能力隔离并重新认证；没有该能力或结果仍共享则 checked 拒绝。

## 实现边界

22 个既有调用入口及一个策略 getter 在精确符号表中注册。调用声明分别
给出参数、返回值、拥有关系及错误物理 ABI；需要捕获语言回调失败的
入口使用 checked scope，其余使用原生线程错误。Lowering 和 verifier
共用合同，不在 Cgen 按函数名猜测错误语义或生成库函数体。

生成代码采用公开的私有 C 声明头，直接调用驻留入口。四个旧生成桥接体、
生成 handle Ops、隐藏在整包实现中的旧 C-string facade 已移除。
所有字段名称均为指针加精确字节长度，支持内嵌 NUL 和 UTF-8。

驻留 handle 只拥有一个真实 XRT 对象引用；Trace 发出这一条物理边，
字段对象再逐槽追踪 Value，重复边与 backing 均保留。宿主先认证精确
策略和原生适配器，再查询拥有图。原始 point 仍是显式 FFI，任意 C
指针的有效性属于调用者责任；它不是安全的语言引用创建方式。

## 复制、清理与按需体积

复制入口复用已有的语言值图复制器，保留原生 Array 的完整布局、准入
和投影能力。先收集受保护的字段引用，再经单一 XRT memo 复制；从
已复制对象创建字段表时保存其实际拥有边，不再逐字段重复深复制。
values/items 共用隔离快照。非 Array 外来 handle 仍服从其声明的复制
合同；不把引用保留伪称为所有资源的深复制或自动授予 clone 能力。

merge 先隔离源，再复用 XRT 的事务合并和回滚；原生合并对普通 Value
容器仍有自身复制工作，本批不宣称零额外分配。未重新实现字典算法、
分配器、拥有图 memo 或并发容器。

核心字段操作与复制操作分为两个精确原生组件。只用 create/get/set 等
基础操作，不会因组件依赖带入值图复制组件。宿主 checked 清理保留
无诊断失败位；已经完成的物理释放不会在重试时再次执行。

Open 投影描述只保存字段名等静态数据。驻留入口检查实际 handle 的
精确 Ops 后访问 payload，不保存生成函数回调，也不以 Windows JIT
导入跳板地址作为策略身份。宿主只读能力增加字段对象及该驻留 handle
两个明确准入分支；未知策略、外国执行及不完整拥有图仍拒绝。

## 验收

最终源码为 `stdlib53-b169-source-final1/frozen/demo6`，Linux 为同一
index 的 `stdlib53-b169-source-final1/demo6` 镜像。源码编译器分别
构建 256、255 个翻译单元，未复用编译器对象缓存。

双端驻留回归为 `resident-win-final4`、`resident-linux-final4`，各
82 阶段：三类原生合同 O0/O2、七个语言用例、六份严格生成 C 的
平衡账本及真实 TCC JIT。循环用例只走真实宿主，不冒充 init/fini-only
C 验证。丢析构、漏追踪、NUL 截断三种实际实现变异均先编译成功，
再被合同拒绝。每个优化级验证三个工厂和 85 个复制/构造/合并完整
分配失败前缀，失败源内容不变，未泄漏输出。

五个 JSON/XLON 邻接用例的 `restore-win-final4`、`restore-linux-final3`
各 59 阶段通过；九个实际 IR 拒绝变异在输出 C/头文件/组件计划前
被拒绝。混合模块包含 native 闭合恢复和 legacy Open/Set 恢复两条
路径，不能把这解释成所有恢复载体完成。

宿主专项 `read-win-final2`、`read-linux-final1` 各 10 阶段、四组
完整故障前缀（每优化级 31+52 次）通过，包含已知字段准入、复制
scope 和外国策略拒绝。Linux 所选原生闭包 O0/O2 使用 ASan/UBSan；
这不是整个编译器和语言运行时的 sanitizer 验收。两个测试入口修正
作为显式 test-only 差异保留，并由最终 index 溯源检查当前报告哈希。

双端 `catalog-*-final2/results.json` 各 217 个独立驻留组件、
1,178 个实际精确导出及 13 个拒绝负控通过。上述八份报告及全部
源码、工具、产品输入在验收结束时重新哈希。早期 source-dev1 至
source-dev7 和失败 final 报告均保留，但不作为最终通过证书。

本批只复用既有 TCC 工具核心，不代表重新构建发布 DLL/SO、VFS、AOT
裁剪产物、全部语言 OOM 前缀或全仓 RC0。

## 尚待完成

Open 动态字段的恢复事务节点尚未切换；Open/Set/List/Dict 等未支持
的恢复图仍保留各自 IR pending 标记，不能通过删除标记冒充迁移。
闭合图不再仅因为模块存在已认证的动态字段就被判为 opaque。
19 个 XRT 未决策组、对象池最后和三组标准库长期目标均不变。
