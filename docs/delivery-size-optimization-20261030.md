# 运行库与内嵌编译器交付优化验收

后续保持 O2 的合同表与目录优化、当前产品大小见 [O2 优化验收](delivery-size-o2-20261030.md)。本文保留此前薄头、去重与预编译阶段的测量。

2026-10-30。机器可读数据见 [原始统计与验收摘要](reports/delivery-optimization-20261030.json)。

本轮完成最新 XRT 薄头接入、毫秒时间合同、资源去重、分块固实压缩和 TCC 预编译。
Windows 与 Linux 的本地发布产物均已更新。此次完成的是这些交付路径的专项验收；不将历史扩展库缺口算作已完成的全标准库验收。

## 实现边界

- 从 `D:\GIT\xrt` 的独立只读导出生成快照。提交基点为 `2ca1569d8b6ec39c5880b06fa9221aa0e8a84622`，包含当时未提交内容；完整源指纹在 `lib/xrt/upstream.json`。再次从当前生产者导出，五份头文件逐字节一致。
- 核心拥有 3,442 个 API，薄 `xruntime` 拥有 465 个 API，交集为空。预编译器检查每份原生对象具有全部 3,907 个定义，并检查语言/TCC 对象没有重复定义这些 API。
- 宿主常规编译单元使用声明头。完整实现头用于生成程序的模块裁剪；原生实现由核心和薄扩展各提供一次。声明头的虚拟别名共享资源块。
- 时间直接采用当前 XRT 的毫秒合同，见 [时间合同](time-milliseconds.md)。`time(0)` 是公元 0001-01-01 UTC；Unix 秒和毫秒使用显式转换。日历字段、相对等待、缓存 TTL、进程耗时及配置超时均已迁移。单调期限与日历时间分开，高精度计时器和协议明确规定的秒单位保持各自定义。
- 完整原生程序和嵌入编译器采用目标平台的 TCC ELF64 对象。Windows 本轮没有引入 GCC COFF 链接支持。普通语言产物继续按依赖选择运行时编译单元和 XRT 模块。
- 外部 C 输出链接自身拥有的可重定位 XRT 对象。只有进程内 JIT 使用宿主函数地址；外部输出遇到宿主专属符号或宿主编译包会明确拒绝。

## 准确体积

MiB 按 1,048,576 字节计算。受控基线来自修改前的 `67fe240f630b501c85c32440f9307a1eb7b45737`，使用同一套 Windows 构建工具重新构建。它与此前工作区存放的旧二进制有小幅差异，分别列出。

| 产物 | 基线字节 | 最终字节 | 差值 |
|---|---:|---:|---:|
| `xlc.dll`，受控重建基线 | 20,720,640 | 19,574,272 | 减少 1,146,368，约 1.09 MiB / 5.53% |
| `xlc.dll`，原工作区二进制 | 20,696,576 | 19,574,272 | 减少 1,122,304，约 1.07 MiB / 5.42% |
| `xl.dll`，受控重建基线 | 13,943,296 | 14,247,424 | 增加 304,128，约 0.29 MiB |

`xlc.dll` 最终约 **18.67 MiB**。`xl.dll` 增大主要发生在运行时 SDK 增加独立外部输出所需的原生对象之后，不能将本轮概括为所有产物都变小。

四份原有头文件加新增特性头，源文件合计从 21,880,132 降至 11,566,605 字节，减少 **10,313,527 字节**。其中 `xruntime.h` 从 9,729,511 降至 682,392 字节，`xruntime_decl.h` 从 1,625,551 降至 302,039 字节，新特性头 13,516 字节。源文件字节不能直接当作 DLL 节省量：原有 VFS 已有声明别名，实施后还须保留一份完整核心实现供模块裁剪使用。

下表是压缩载荷的顺序归因，尚未包含资源目录、名称、指针重定位和 PE 对齐。每项收益依赖前面的布局，不能与不同输入、不同顺序的压缩比例相加。

| 步骤 | 压缩载荷字节 | 相对上一步 |
|---|---:|---:|
| 原基线，逐文件压缩 | 7,816,405 | — |
| 相同文件按内容共享 | 7,176,601 | 减少 639,804 |
| 移除再次压缩的内层运行时资源 C | 5,830,520 | 减少 1,346,081 |
| 最新 XRT、薄头、毫秒迁移及相应 SDK 布局，仍逐文件去重压缩 | 5,642,743 | 减少 187,777 |
| 同一新输入，1 MiB 固实块 | 4,807,760 | 减少 834,983 |
| 加入 XRT 原生预编译对象 | 5,742,237 | 增加 934,477 |
| 再将 xlang 固定单元换为预编译对象 | 6,529,893 | 增加 787,656 |
| 再将 TCC 固定单元换为预编译对象 | **6,655,953** | 增加 126,060 |

最新源码在原有逐文件、不去重方式下为 6,840,850 字节；相同输入的内容去重单独节省 1,198,107 字节。

**预编译在本次实际交付布局中增加载荷 1,848,193 字节，约 1.76 MiB。** 总压缩载荷仍比受控旧基线减少 1,160,452 字节，约 14.85%。这里没有把预编译包装成体积收益。前期整体合并对象的研究数据不等同于此次保留按编译单元裁剪、声明 SDK 和私有实现资源的实际布局。

最终目录为 2,699 个虚拟资源、67 个压缩块、2,777 个片段。嵌套编译时从共享目录构造所需的子目录，不再保存一份压缩后的资源 C 再嵌入外层目录。固定 `__xl_objects/` 路径不接受磁盘文件或动态挂载的替换。

最终 PE `.text` 文件区为 4,829,696 字节，`.rdata` 为 13,501,952 字节；其他节、头部和对齐合计 1,242,624 字节。压缩载荷包含在 `.rdata` 内，不能再次加到 DLL 总量上。既有 IR 外部调用表约 3,223,784 字节，本轮保持其布局，没有把它误算成 XRT 重复源码。

## 速度与运行成本

以下为同机、相同输入、每次启动新进程进行 AOT 构建，构建后均运行产物成功。不是程序运行速度测试，也没有清空操作系统文件缓存。

| 示例 | 基线构建耗时 | 最终构建耗时 | 样本 |
|---|---:|---:|---:|
| 嵌入 xlang，源码目录之外构建 | 60.30–60.59 秒 | 0.68–0.85 秒 | 各 2 次 |
| 嵌入 TCC，同一个冻结的原始源码工作目录 | 1.798 秒 | 0.561 秒 | 各 1 次 |

原基线的 TCC 示例在完全隔离目录下会因缺少私有 XRT 头失败，不能为它捏造隔离构建速度。最终版本的隔离构建已通过。

示例体积也有成本：嵌入 xlang 的 EXE 从 19,532,288 增至 19,927,040 字节；嵌入 TCC 的 EXE 从 5,940,224 增至 6,389,760 字节。额外 SDK/原生对象支持子程序在创建者进程退出后独立运行。

解压采用 8 个、每个至多 1 MiB 的 LRU 槽，常驻解压缓存至多 8 MiB。替换成功前保留旧块，短时还可能增加一个至多 1 MiB 的新块及解码状态。打开的虚拟文件保存片段信息，不保存会被淘汰的缓存地址。

嵌套编译的冷路径仍有目录遍历、生成临时资源 C、分配与复制文本及 TCC 解析的成本；完成后释放文本。该路径的上述耗时已包含这些工作，没有作“零开销”声明。

## 验收与复现

- Windows、Linux 各 1,375 个生产编译单元通过严格 ABI 语法检查，将隐式声明、指针类型不匹配和整数转换问题作为错误处理。
- Windows 28 个、Linux 16 个最终冒烟阶段通过，涵盖时间、期限、执行器、无网络流量的引擎计时、JIT、AOT、嵌套 TCC/xlang 和生成的原生子程序。
- 两端的 `tools/check_precompiled_delivery.py` 均通过：在源码目录之外生成并运行原生 EXE/共享库、独立嵌入编译器 EXE、二级生成子程序、嵌入编译器共享库以及共享库再次生成的子程序。Windows DLL 和 Linux SO 都实际加载并调用。
- VFS 专项覆盖内容别名、内嵌 NUL、大文件跨片段读取、缓存淘汰、持有打开文件时清缓存、对象路径防替换、目录序列化及重新编译后再次读取。
- Windows 模块裁剪的两个代表程序、宿主空上下文/工作目录、并发宿主、依赖库生命周期和构建输入回执检查通过；构建输入回执为 22 项检查。
- 50 个能在此上下文独立编译的薄头夹具通过语法检查；另 24 个需要其原有生成头/特定构建上下文，未以孤立编译冒充通过。
- BSON、CBOR、MessagePack 的实际原生时间适配通过 8 组普通正负 Unix 毫秒样本，含非零毫秒和 1970 年以前的值。Linux 原生时间/日历专项及纽约、Lord Howe 的 gap/fold 检查通过，没有修改本机 Windows 时区。
- XRT 快照、3,907 个符号和能力矩阵检查通过。必要的验证生产者及夹具已改用核心＋薄扩展的包含顺序；本轮没有执行网络安全、攻击或外部端点测试。

快速复现源码外独立交付：

```text
python -B tools/check_precompiled_delivery.py --xl <已构建的 xl.exe 或 xl 绝对路径> --out <独立输出目录>
```

完整原始日志保留于 `F:\xlang-validation\delivery-optimization-20261029`，摘要与二进制 SHA-256 已随本文保存，避免只依赖临时目录。

## 已存在的验收限制

上游当前开发树仍缺 `net_file_future` 的 `single_tests` 闭包登记；同步工具显式记录该成熟度诊断，并要求五份生成头保持新鲜，未修改上游源码来消除记录。

原有 BSON/CBOR/MessagePack 的部分语言动态容器到 wire 值投影夹具在冻结基线也失败；XMail 的 TLS Lease 调用在基线即缺公开声明。它们与本轮普通原生时间向量验收分开记录。Plist 等独立扩展也未作全量发布验收。

旧 `check_xruntime_language_bridge.ps1` 文本检查仍失败，其 23 条输出与冻结基线逐行一致，包含已过时的 Cgen 函数/分组文本假设。本轮没有通过降低断言来把它改成成功，也没有据此宣称整个标准库已完成发布验收。
