# 原生拥有值的生成器结果

generator<SlotMapKey> 已接通直接产出和消费。yield 转移一个拥有的
完整键记录，消费者通过 take 取得该拥有值；不把键降为整数、
裸指针或动态值盒子。键可在来源容器、生成器帧和控制释放后继续
独立存活，嵌套生成器转发也使用同一合同。

本批只修改统一 IR 与机械 C 渲染，不增加原生运行时函数、适配器
或库算法。完整键跨 await、Future 元素遍历、WaitQueue、53 个
模块和正式发布产品验收继续；对象池仍最后，未决策范围未扩大。

## 统一 IR 与直接拥有转移

新增 move-native-value yield ABI，仅精确匹配已关闭的原生拥有值
声明。其当前元素没有语言对象图出边，但仍拥有独立资源；take
不能被替换为普通 get，也不能按 trivial／pointer copy 处理。
生产者、悬点、当前元素追踪与消费指令分别验证该合同。

原生当前元素的布局包含准确的 sizeof 和已声明的常驻捕获发布者。
即使生成器没有原生帧槽，依赖选择也必须从结果合同选入发布者；
不能依靠其他帧、调用或代码文本扫描偶然带入。

```c
static const XL6_CaptureSlotV2 item = {
    {XL6_CAPTURE_NATIVE_LEAF_V2, 0, sizeof(XL6_SlotMapKeyV1)},
    xl6SlotMapKeyCaptureProfileV1Get
};
```

borrowed 键在 yield 之前通过已有 checked copy 取得独立拥有值，
已拥有结果直接转移。普通帧槽、当前元素和消费变量各自按真实
初始化／拥有标志清理，不用重复引用同一份结构体冒充多份拥有值。
实际复制、稀疏清理、独立帧引用和代码租约继续复用既有运行时。

## 行为和失败验收

完整源码构建 Windows 316、Linux 315 个编译单元。新专项
Windows 488、Linux 543 阶段通过；每端逐个故障位置执行 284 次
检测，10 组完整前缀均跑至末端。包含来源／控制分配、游标和键
复制、参数复制及原生 yield 前复制的无诊断失败，失败后重新执行
成功且精确内存平衡。

5 个原生结果生产者、6 个 yield、7 个 take 和 48 项 IR 篡改
通过验证；错误布局／追踪、错误产出 ABI 和误用 get 都被拒绝。
四种实际坏运行时先编译、链接再运行，由行为断言拒绝。

严格独立 C 的 O0／O2、公开 JIT、module 和 AOT 通过。主用例
和结果专属最小用例每个优化等级执行 1000 次语言生命周期，覆盖
嵌套转发、完整键与序号、提前 break、恢复后抛错、空生成器、
重复产出、逃逸拥有值和来源容器销毁。原生七种场景每个优化等级
各执行 1000 次，包括未取走元素的关闭清理。

主用例按实际计划选择 34 个供应方；结果专属最小用例选择 27 个，
最后的真实符号没有键 box、unbox、converter 或 native leaf box。
纯原生最小闭包仍为 13 个供应方，不引入 SlotMap 存储或装箱。
Linux ASan／UBSan 插桩覆盖主用例和原生两个闭包的全部供应方；
结果专属最小用例本批为严格 C／O0／O2 验收，不扩大插桩结论。

上一轮完整键跨 yield 的帧专项双端各 380 阶段、234 次故障检测
重新通过。旧生成器公开入口及布局合同通过；Windows O0／O2
各 140 次拥有环事务及 3360 个 OOM 预算保持精确内存平衡。
常驻目录双端核对 277 个组件、1432 个真实导出和 13 个拒绝对照。

## 完成边界

本批没有改动 Capture V1／V2、Generator V1／V2／V3 或 XRT／
xruntime 实现。专用容器仍限制临时方法接收者；独立来源测试使用
函数局部容器在返回后正常销毁，不宣称放开该语法。异步原生槽、
独立 borrowed SSA 原生 spill 的完整失败边界、Future 元素及
WaitQueue 继续，专项通过不代表三组或全仓发布验收完成。
