# 扩展库串口边界收口：2026-09-05

这是 [扩展库当前状态](扩展库当前状态_2026-09-05.md) 复核之后的独立修复批次。
本批只修改 serial 实现、测试、范例、门禁和文档，没有同步或修改开发中的 XRT，也没有修改编译器。
并行任务仍在修改默认 XLIR 后端，因此本批使用独立 C 测试运行库和固定构建哈希，不争用共享构建对象。

## 修复与实现

| 原问题 | 本批处理 |
| --- | --- |
| 固定 4096 字节读缓冲读满后补 NUL 越界 | 改为独立拥有型 xbuffer；按实际字节数返回，不追加文本终止符 |
| 真实设备读取长度可超出固定缓冲；负数转无符号 | int64 校验在转换之前；0 不消费数据；单次 I/O 限制在 65536 字节 |
| 回环队列写满后仍报告请求长度 | 返回实际写入字节数；支持短写，满队列返回 0 |
| 全局读缓冲、错误缓冲导致跨对象或线程污染 | 读取结果独立拥有；使用 XRT 当前线程错误槽；每个端口持有自己的 mutex 与有界队列 |
| UTF-8 写入把字符数当作字节数 | 文本入口按 strlen 字节数传输；增加 Buffer 读写接口保留二进制零字节 |
| 设备路径和临时存储各自分配 | 文件对象、UTF-8 路径、字符串、内存、buffer、mutex 统一复用 XRT |
| 创建与读取的失败清理不完整 | 创建失败释放已取得资源；读取先分配，再消费队列；失败保持原队列 |
| C 与 xlang 原型宽度和 const 口径存在漂移空间 | 统一为 int64_t / size_t / bool；保留 C const 输入，增加精确 point ABI 入口；逐项核对生成的 10 条 extern 原型 |
| 类型仅能通过工厂返回 | `Serial` 明确 export，可 `from serial import Serial` 后直接声明 |

`xserial_write_bytes` 是 `point` 到只读 C 写入接口的精确声明边界，不是兼容别名；
没有复制缓冲或引入另一套传输实现。

公开接口、生命周期和全部使用约定见 [serial/README.md](../release/extlibs/serial/README.md)。
`flush` 明确表示清空队列；不代表等待发送完成。`isOpen` 只表示持有句柄，不是设备健康探针。

## 验证

完整命令输出、编译器/XRT 哈希、参与验收的源文件哈希保存在
[extlib_serial_2026-09-05.results.json](extlib_serial_2026-09-05.results.json)。

### Windows

`tools/check_extlib_serial.ps1` 的 18 个步骤全部通过：

- 独立运行库与 serial 的严格 GCC `-std=c11 -Wall -Wextra -Werror` 编译。
- 原生二进制、错误与线程边界测试，以及独立分配故障测试。
- 从实际生成 C 提取 10 条串口 extern，和公开头文件在同一翻译单元严格编译，防止 ABI 漂移。
- C/xlang `xl run` 内存执行。
- xlang 用例 `xl build` 后执行；C 范例同样可以由 xl 编译并执行。
- C 范例额外使用独立 GCC 编译运行，未依赖 xl.dll 或 xlc.dll。
- C/xlang 范例的 12 行输出逐字相同。
- 检查测试前后编译器、XRT 及相关源文件哈希一致，避免在并行更新期间混用构建结果。

`run_platform_extlibs.ps1 -Package serial` 也通过。平台入口现在会执行登记的语言边界用例，
不再只运行范例；未知包名会失败，不会空跑后声称成功。
分配故障属于独立 C 门禁，不在已经运行的 xl.dll 宿主中启用或切换 XRT 分配器。

### Linux

Ubuntu / GCC 使用同一份仓库 XRT 和 serial C 源码：

- 严格 C 编译与生成原型核对通过，验证 LP64 下的 int64_t / size_t 合同。
- 回环、跨线程传输、错误隔离通过 AddressSanitizer 和 UndefinedBehaviorSanitizer；同时启用泄漏检查，未报告异常。
- 分配故障独立程序通过。

这些是 C 回环的 Linux 验证，不是 Linux 版 xlang 验收，也不是 Linux 真实串口支持声明。

### 已覆盖的边界

- 0、负数、int64 极值、4096 字节读满、5000 字节短写、队列满后写入返回 0。
- UTF-8 中文、0 / 255 二进制字节、部分读取、空队列、flush。
- 读取结果跨下一次读取、源对象销毁和语言函数返回保持有效。
- 多个端口隔离、对象别名、200 次语言层反复创建释放。
- 两个写入线程、线程错误隔离，以及 257 字节写块 / 113 字节读块的 64KiB 连续传输，无丢失或乱序。
- 无效配置、NULL 参数、超长不存在设备名、语言侧可捕获的设备打开失败。
- open/read/write 各 32 个分配位置，共 96 组；Windows 和 Linux 均观察到 6 次失败清理、90 次完整成功。
- 故障注入前后存活分配数/字节数一致，InvalidFree/DoubleFree/Overflow/Underflow 计数没有增加。

## 仍未完成

本批不把 serial 记作完整生产级串口库：

- 真实 Windows 设备、热拔插、驱动差异、线缆和流控仍待硬件验收。
- Linux 真实串口尚无实现，当前显式报告 Unsupported。
- 异步串口、设备枚举、可配置超时和硬件流控不属于现有已实现 API。

整体扩展库长期任务仍未完成。xregex 静态容器外部 C ABI、XRT last-error 与未捕获语言异常的
区分、HTTP/邮件异步接入、辅助符号缺失、MQTT 短读等问题仍在队列中。

本批未重跑整个 132 用例集合。此前 94 通过 / 38 失败仍是其对应构建的历史全量复核结果，
不得与本批更新后的 DLL、串口门禁结果合并计算“当前全生态通过率”。
