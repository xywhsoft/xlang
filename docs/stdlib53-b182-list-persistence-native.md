# List 的 JSON/XLON 投影与恢复

List 持久化消费端现在使用明确的原生投影与恢复合同。投影共享
一次 XRT 图遍历和一个 memo；恢复复用已有的事务与准入机制，
不在生成 C 中重建容器算法。本批不增加公开标准库 API。

## 格式和所有权

List 按 int64 键的升序输出为紧凑数组，恢复后生成连续键。这是
已有持久化格式的延续，不是保留稀疏键的归档协议。完整 int64
键参与排序，但不作为数组下标窄化；文本使用精确字节长度，
保留内嵌 NUL 与 UTF-8。

原生 List、原生 Array 与 wire 容器中的重复边使用同一个 memo。
投影得到新的数据图，输入对象不变。同一逻辑 List 类型既可能
来自旧 wire 工厂，也可能来自原生恢复；XRT 只允许经过实际
handle ops 认证的提供者把原生载体投影成数组，不按 TypeId
猜测对象布局。缺少提供者、拒绝处理或返回非数组均 checked 失败。

JSON/XLON 的 parse 与 read 共用闭合恢复计划。目标 List 的
元素 witness、构造 recipe、carrier 和 seed 都由 XLIR 明确提供；
嵌套 Array 的物理转换器由同一构造策略进入裁剪依赖，普通构造
不附带不必要的转换器。Cgen 只渲染验证后的描述和驻留调用。

类字段默认子对象若来自全局或其他共享引用，只能通过声明的
clone 能力复制后恢复，否则 checked 拒绝。恢复不修改共享原对象，
也不自动引入隐式深复制或任意资源复制；此规则沿用前批合同。

## 错误边界

解析、目标准备和操作作用域分别保存失败状态。作用域创建失败
即使没有可分配的诊断对象，也作为失败传播，不 abort、不误报成功。
语法拒绝优先交付解析错误，正常解析后的准备错误优先于后续入口
错误；各阶段拥有的错误引用和目标 seed 均恰好清理一次。

## 验收

Windows 的 272 个、Linux 的 271 个编译单元均从选定源码新编译，
未覆盖生产实现，也不使用旧 shipping 库充当本批运行时实现。
双端各 234 个专项阶段通过，包括 44 项损坏 IR 拒绝、两项先编译
再拒绝的实现负对照、O0/O2 完整及最小裁剪产物执行、两组 JIT。

每端关闭 34 条原生投影与四格式恢复的故障前缀，Windows 1,910 次、
Linux 1,906 次逐点尝试全部平衡。另外，restore-only 最小产物在
O0/O2 各关闭 123 次完整模块分配尝试，覆盖模块初始化与终结。
阶段内每次尝试都有独立内存账本，不用累计余额掩盖单次泄漏。

正式专项报告：

- Windows：`E:/xlang-validation/stdlib53-b182-list-win-final12/results.json`
- Linux：`/var/tmp/xlang-stdlib53-b182-list-linux-final12/results.json`

五项相邻回归双端全部通过，报告位于各端
`b182-regressions-*-final12`。

驻留目录通过 233 个组件、1,223 个精确导出及 13 个负对照。
构造/投影入口从单独产物表移入共享 JIT/产物登记，归属与实现不变，
没有重复登记。产品和测试输入在最终提交门逐一重算哈希。
文档门保留相同 14 项历史拒绝，本批新增为零，不是全仓文档门通过。

Linux ASan/UBSan 覆盖选定原生投影闭包；不认证完整编译器或生成
恢复模块的全部代码。

上游 XRT 的图适配专项双端各 24 阶段、四项模块化和两项单头测试、
旧实现的 O0/O2 编译负对照、Core/runtime maturity 与单头一致性门
均通过。配套修正已提交为 `40908e57`，不新增 XRT 公开 API。

## 尚未完成

List 的普通源工厂与 cast/准入仍生成旧 wire 载体；原生 List
恢复入口已经具备，但不能因此宣称所有生产来源已迁移。
`Array<List<T>>` 与 `List<List<T>>` 的封闭构造 recipe、Set/Dict、
发布 DLL/SO、VFS、打包 AOT 与三组整体总验收仍待完成。
成员表达式直接用于 List 双变量遍历的合同缺口也未在本批修复；
专项使用命名局部变量遍历，不能掩盖这项边界。

Core 时间 ABI 与其他 XRT 模块不迁移。消费方只同步 Value graph
源码段及完整的 sequence 规则声明块，来源和四个前后哈希见
`lib/xruntime/value_graph.snapshot.json`。同步工具要求基线逐条非空
源码精确匹配，拒绝推测重基；公开声明 token、API 符号表不变。

CRT 未决策为零，XRT 19 个未决策组及对象池最后的安排不变，见
[标准库决策清单](标准库决策清单.md)。
