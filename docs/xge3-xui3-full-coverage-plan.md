## 接入原则

- 开发者可以用普通 xlang API 完成原生库支持的全部业务；安全公共 API 不能要求其
  手工维护裸指针、结构体内部地址、回调上下文和引用计数。
- 原生对象映射为 OOP 类型，数据记录映射为精确类型，操作保持原生语义。
  既有 `xge`、`xui`、`xge3d`、`xgeDebug` 分包沿用；是否增加更细子包以实际链接
  裁剪需求为依据，不先重排所有 API。
- 优先直接声明，再使用通用编译期投影。生成 C 直接调用原生函数或函数指针字段；
  不用逐方法 C 转发、操作码分发或动态装箱填补编译器缺口。
- 引用计数、析构、拥有图、存储接管等原生支撑接口，可以由语言生命周期承接，
  但必须逐项记录替代映射及验证。它们不必变成重复的用户方法，也不能直接略过。
- 显式 C 互操仍可保留，但它不能替代尚未完成的安全接口。确实只能由宿主提供的
  平台/后端桥接，公开类型明确的宿主协议、能力查询和失败合同。
- 不声称安全管理没有成本。记录每条路径的复制、分配、扫描、调用、同步、
  生命周期维护，以及冷启动/清理成本；与同版本、同工作负载的 C 比较。
- 同步调用期间的视图、回调期视图、保留引用和拥有资源分别建模；沿用已批准的
  过期 checked 拒绝、闭包保活、线程约束与清理错误合同。新语义必须单独设计。

## 完成标准

每个 API/类型/常量/函数指针字段都有状态记录，至少分清：待审查、合同已定、
声明已实现、ABI 已验证、运行已验证、已交付。不能用“声明已生成”直接标记完成。
每项记录关联原生身份、语言入口或生命周期替代、功能宏、拥有关系、错误/状态、
线程/重入、验证证据和配套发布配置。原生普通 false、未找到、PENDING、BUSY、
UNSUPPORTED 和失败不得混为一个布尔或异常。

每个功能族须具备：

1. 全部原生能力的明确映射；无法直接声明的原因和通用解决方案。
2. 精确 C ABI、记录布局、参数/结果/回调签名及生成 C 检查。
3. 正常行为、边界、失败回滚、OOM、拥有图、回调到期、销毁/退役验证。
4. 实际产品的 JIT、动态模块和静态 AOT 覆盖；不适用路径有明确平台依据。
5. Windows / Linux 配套验证；图形、音频、输入、剪贴板等实际后端验收独立记录。
   无窗口测试不能替代窗口/GPU 验收；原生不支持的平台明确返回能力结果。
6. 新手可读、可运行、结果可观察的示例，以及独立的压力/故障/性能测试。
7. 声明、SDK、库、静态链接输入、IDE 帮助目录与示例的配套发布记录。

“全部能力接入完成”要求范围内没有未处理项，没有用裸句柄占位的业务接口，
且目标平台/配置的验收和交付闭环。原生需要额外能力时先在 XGE 中修复并单独验收，
随后同步配套 SDK；不在 xlang 侧复制另一份引擎实现。

Document 和已有 XUI 接入的单纯声明缺口可以与前面阶段穿插修复；涉及共同资源、

每轮先批量发现问题、按根因成组修复，再统一验证受影响人口。已通过且输入未变的
证据可以按精确哈希复用；源码、ABI、配置变化时重跑相关组，不以复用绕过验收。
每批完成后独立提交；保留其他工作区改动，发布产物继续不进入 Git。
