## 范围与基线

XGE 的 412 包括可选 xge3d / xgeDebug 的 12 / 4 个原生函数；默认包对应 396 个。
没有同名公开声明不必然等于缺少业务能力，例如 `xgeUnit` 由 checked 版本承接，
原生 Create 可由 Owned Create 承接；这些关系仍须经过合同核对才能结项。

四个头另有 1,835 个对象宏定义、316 个独立枚举成员、7 个函数宏和 175 个函数指针
字段。`xnative_transfer.h` 的 3 个类型和 6 个函数指针字段单独记账，不能遗漏。
上述是源码人口，不是最终 xlang 方法数量，也不是功能完成率。类型的记录字段、
联合体、回调签名和条件编译分支均纳入核对；后端和构建配置也属于交付合同。

默认 2D、可选 3D、调试、平台专用功能均在范围内。它们可以分包、按需链接，
但不能因当前 SDK 未启用而从待完成清单中删除。XUI 的组合控件、数据模型、
代理、文档模型与编辑/显示能力和底层渲染能力同等对待。

复算命令（输出目录必须尚不存在，完整报告留在 Git 忽略的开发目录）：

```powershell
python -X utf8 -B tools/check_xge3_full_surface.py --native-root D:/GIT/xge --out build/xge-full-surface-current
```

工具扫描源包 manifest 实际选入的声明文件，包含独立 Document 头，不用主头的
未解析声明数量代替 Document 覆盖。新增公开头、解析错误、核对期间输入变化会
报错。`--require-declarations` 可以约束单批必须具备的函数声明；它不是运行验收门。
报告的 `contractReview=pending` 不推翻历史专项验收，只说明该工具不能自动证明它。

## 接入原则

- 开发者可以用普通 xlang API 完成原生库支持的全部业务；安全公共 API 不能要求其
  手工维护裸指针、结构体内部地址、回调上下文和引用计数。
- 原生对象映射为 OOP 类型，数据记录映射为精确类型，操作保持原生语义。
  既有 `xge`、`xui`、`xge3d`、`xgeDebug` 分包沿用；是否增加更细子包以实际链接
  裁剪需求为依据，不先重排所有 API。
- 优先直接声明，再使用通用编译期投影。生成 C 直接调用原生函数或函数指针字段；
  不用逐方法 C 转发、操作码分发或动态装箱填补编译器缺口。
- 引用计数、析构、拥有图、存储接管等原生支撑接口，可以由语言生命周期承接，
  但必须逐项记录替代映射及验证。它们不必变成重复的用户方法，也不能直接略过。
- 显式 C 互操仍可保留，但它不能替代尚未完成的安全接口。确实只能由宿主提供的
  平台/后端桥接，公开类型明确的宿主协议、能力查询和失败合同。
- 不声称安全管理没有成本。记录每条路径的复制、分配、扫描、调用、同步、
  生命周期维护，以及冷启动/清理成本；与同版本、同工作负载的 C 比较。
- 同步调用期间的视图、回调期视图、保留引用和拥有资源分别建模；沿用已批准的
  过期 checked 拒绝、闭包保活、线程约束与清理错误合同。新语义必须单独设计。

## 完成标准

每个 API/类型/常量/函数指针字段都有状态记录，至少分清：待审查、合同已定、
声明已实现、ABI 已验证、运行已验证、已交付。不能用“声明已生成”直接标记完成。
每项记录关联原生身份、语言入口或生命周期替代、功能宏、拥有关系、错误/状态、
线程/重入、验证证据和配套发布配置。原生普通 false、未找到、PENDING、BUSY、
UNSUPPORTED 和失败不得混为一个布尔或异常。

每个功能族须具备：

1. 全部原生能力的明确映射；无法直接声明的原因和通用解决方案。
2. 精确 C ABI、记录布局、参数/结果/回调签名及生成 C 检查。
3. 正常行为、边界、失败回滚、OOM、拥有图、回调到期、销毁/退役验证。
4. 实际产品的 JIT、动态模块和静态 AOT 覆盖；不适用路径有明确平台依据。
5. Windows / Linux 配套验证；图形、音频、输入、剪贴板等实际后端验收独立记录。
   无窗口测试不能替代窗口/GPU 验收；原生不支持的平台明确返回能力结果。
6. 新手可读、可运行、结果可观察的示例，以及独立的压力/故障/性能测试。
7. 声明、SDK、库、静态链接输入、IDE 帮助目录与示例的配套发布记录。

“全部能力接入完成”要求范围内没有未处理项，没有用裸句柄占位的业务接口，
且目标平台/配置的验收和交付闭环。原生需要额外能力时先在 XGE 中修复并单独验收，
随后同步配套 SDK；不在 xlang 侧复制另一份引擎实现。

## 开发顺序

| 阶段 | 内容 | 主要依赖和验收重点 |
| --- | --- | --- |
| 0 | 全量清单、配套版本、差异检测 | 四个业务头及传输协议；独立 Document 声明；条件分支不遗漏 |
| 1 | RenderTarget、Pass、Shader、Mesh、Material 完整操作；SpriteBatch、ShapeBatch | 渲染上下文、资源拥有/槽引用、线程和 Pass 顺序；批量调用无逐元素装箱 |
| 2 | 资源提供者、资源包、场景管理、异步请求/加载、后端选择和离屏能力 | 先资源拥有关系，再取消/完成竞态和回调代码寿命；平台桥接用明确合同 |
| 3 | FontFace、FontFamily、字形/排版/缓存，音频 Clip/Group/Music/Stream | 拥有序列与字节片段、长期回调、播放资源和引擎关闭顺序 |
| 4 | Shape 剩余查询/遍历、完整 SVG、粒子世界/定义/渲染、Input Actions、Emoji | 对象子图、内部视图和访问失效、批量数据、事件交付 |
| 5 | XUI 全控件和模型；Proxy/Draw/Surface/Font 及全部回调/数据适配器 | 按控件族核对；补齐 IconPicker、FlowGraph、Workflow 等模型；不能以控件壳代替功能 |
| 6 | Document 与 Document UI 剩余能力 | 增量索引、导入导出、事务/撤销、渲染、命中/编辑、取消和资源回调；按原生实际清单逐项处理 |
| 7 | 完整 3D 与调试模块 | 场景/节点/网格/材质/纹理，再模型/动画/地形/空间查询，再渲染与后处理；分包保持按需引入 |
| 8 | 全量集成、性能、示例与配套发布 | 整合前面已通过的证据，补实际后端与跨族验收；独立验证动态与静态裁剪 |

Document 和已有 XUI 接入的单纯声明缺口可以与前面阶段穿插修复；涉及共同资源、
回调、拥有图的改动必须先完成底座，避免各子系统自行添加一层包装。

每轮先批量发现问题、按根因成组修复，再统一验证受影响人口。已通过且输入未变的
证据可以按精确哈希复用；源码、ABI、配置变化时重跑相关组，不以复用绕过验收。
每批完成后独立提交；保留其他工作区改动，发布产物继续不进入 Git。
