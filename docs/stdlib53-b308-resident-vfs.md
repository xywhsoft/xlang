# VFS 的驻留适配与资源清理

标准 VFS 的调用适配、Pack 配置与统计、文件元数据和目录资源
析构已迁入驻留实现，使用统一 XLIR 拥有策略。Vfs 的语言句柄
现在保存私有 namespace 包装，不直接借用宿主任意 xvfs。
原先 31 项入口中尚无策略的剩三项：任务组、IO reader 和 writer。
这不是三组标准库整体完成的声明。

## 私有 namespace 与内建后端

标准 Vfs 自行创建并持有原生 namespace，只通过驻留方法挂载
memory、disk 和 pack 三种内建后端。私有投影仅供对应的原生
适配单元使用，不向语言公开接管任意宿主 namespace 的构造器。
本合同不认证宿主自行注入的 provider、回调或上下文；显式
不安全 FFI 也不能因此获得语言对象拥有边的自动认证。

内存后端只拥有路径索引和复制的二进制 blob，磁盘后端拥有
原生根目录与访问配置，Pack 后端拥有文件、索引、cache 和错误
快照。它们不保存语言对象或生成模块的回调。挂载控制对象和
namespace 的真实原生引用继续由 XRT 管理，不能用语言句柄的
消失来提前销毁仍被挂载、文件或目录使用的后端。

## 元数据与派生资源

Vfs.open、stat 和 openDir 同时迁入原生适配，避免生成代码再
解释 Vfs 私有布局。普通 FS 适配和驻留生产者使用同一份文件
元数据与目录游标物理声明，没有第二套结构偏移或拷贝规则。

FileStat、DirectoryIterator、PackOptions 和 PackStats 增加驻留
析构策略。配置和统计是独立原生快照；目录的原生游标仍拥有
自己的后端引用。这些返回对象不能仅因父 Vfs 已驻留而被遗漏。
原有显式 close、unmount、错误边界和 Pack 文件接管规则保留。

原生资源声明表累计有 35 项策略，其中一项是内部发布标记。
IR 专项逐一核对 34 个语言析构目标和对应字段，不把未知 Handle
或任意 point 视为空叶子。读取准入仍独立于生命周期准入。

## 生成代码与依赖

两份旧 VFS 和 Pack 适配 emitter 已删除。Cgen 只调用已验证的
接口，不再生成 VFS 方法体、析构回调或私有 namespace 布局。
公共物理声明由精确驻留符号登记选择，不依赖 VFS 名字前缀，
也不会为仅需要头声明的标量程序额外生成字符串辅助实现。

Vfs 文件、元数据和目录适配分别列为原生生产单元，避免单一
调用拉入其他两类适配。新增九个生产单元和六个拥有域，当前
目录为 392 个组件、1686 个精确导出、69 个拥有域和 42 项
Handle 策略。未使用的组件继续按需排除。

## 验证范围

原生专项累计使用 35 个真实资源工厂，检查精确拥有节点、70 个
Ops 或 Trace 伪造拒绝及分配失败回滚。新增十条完整 VFS 构造
路径的分配失败闭合前缀，覆盖 namespace、三种后端、配置、
统计、文件、元数据、目录和挂载创建；每次核对分配数量与字节
平衡，而不只测试 Handle 接管失败。Linux 的 ASan 和 UBSan
覆盖 58 个真实生产单元，包括完整 XRT 与 xruntime 核心。

IR 专项包含 136 次输出前拒绝与标量裁剪检查。独立 AOT 专项
为 21 份用例，四份循环对象各搬离执行四次且最终标记恰好出现
一次。VFS 循环对象在析构中读取三种挂载、打开文件、元数据、
目录及 Pack 快照；原有内嵌 NUL、overlay、限额、损坏 archive、
文件切片和 256 个语言层分配失败尝试继续保留原断言。

源码、产品、严格 C 和跨平台门禁分别报告。测试器可以晚于
冻结产品补充断言，生产源文件和 SDK 则必须与验证版本一致。
首轮公共声明缺少依赖头的构建失败保留为失败证据，修正版
使用新冻结目录重建，不覆盖旧候选。

源码导出器改为单个 Git 进程逐对象流式校验，每次读取最多
64 KiB；跨块 CRLF、独立 CR、NUL 和截断拒绝由 88 个向量检查。
它保留索引和导出内容的精确摘要，不再把全部 blob 聚合进内存。
并行导出造成的内存峰值与 Windows 图专项编译内存不足分别
保留失败记录，受影响的产品验收使用相同生产文件串行复测。

## 继续工作

IO 仍含生成代码中的关闭回调，进程流还关联异步 Future；任务
组具有取消观察者、Future、活动项与父子引用。这些需要继续
审计真实拥有图与回调驻留，不能套用本批无语言边的资源策略。
进程等待 Future 的跨模块引用也须纳入后续复核。

Windows 终端 resize 的历史间歇问题、全局 exit 的完整语言栈
清理、函数级覆盖和发布总门仍开放。CRT 无未决策，XRT 十九组
未决策与对象池最后的顺序不变，本批没有扩大公开 API 或修改
canonical XRT、无关扩展库。
