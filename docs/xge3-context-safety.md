# 图形上下文启动与可重试清理

本批先完成拥有式离屏上下文所需的两个原生合同：完整的 GL 函数表事务，和能够保留
未完成释放义务的 EGL checked 清理。实现位于 XGE 原生库，xlang 不增加绘图包装层。

GL 的声明、定义、加载和校验来自同一份精确类型清单。缺少必需函数时保留整张旧表，
成功后才一次提交。3D 允许两种 depth-clear 函数至少具备一种；时间戳查询仍是可选。
这些是上下文持有线程上的冷操作，不支持一边绘图一边替换函数表。

还修复了实际故障注入发现的首帧问题：Sokol 在初始化回调结束后仍会执行首帧，仅调用
quit 不能阻止它。后端准入或 GL 加载失败时，XGE 会先停止运行状态，记录 checked
错误，再退出，避免未就绪函数表进入渲染或语言回调。

`xgeEGLUnitChecked` 按“解绑、上下文、表面、显示连接”的顺序释放，失败即停止。
已经释放的句柄清零，其余句柄和 `bCleanupPending` 留在调用者记录中，允许原记录
重试；不会把失败误报为释放完成。启动失败的逆序回滚也共用此路径。旧 void 清理
同样保留未完成记录，但需要 checked 入口才能取得错误结果。

这增加了原生 EGL 记录字段，SDK／运行库必须配套更新。它仍是显式 C 互操能力，
尚未把裸 EGL 记录作为语言公共资源类型开放。现有语言 EGL 夹具继续只在同步测试
辅助函数内持有记录，并检查正常、禁用配置及 checked 清理；不把它计作拥有式会话。

冷路径成本也需明确：完整校验使用临时函数指针，增加必需项检查；旧加载入口每个
函数名多经过一次间接回调，新 user-aware 入口可直接使用。EGL 清理新增当前上下文
查询和一个状态字段。不增加绘图热路径的扫描、分配、逐方法包装或动态装箱。

原生与语言验证报告见
`dev/release-materials/provenance/xge-context-safety-20261110.json`。本批不改全局
`unit()` 的资源 Busy 合同，也不改当前正式交付索引。拥有式 EGL 渲染会话、Windows
EGL SDK、可替换宿主后端及 TCC ELF 按需依赖裁剪继续属于长期任务的剩余范围。
