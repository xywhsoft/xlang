# XLIR 原生 UDP 发送拥有链

UDP 跨线程发送不再把首个数据报节点借给调度器，而是由独立任务节点拥有
待发送链和一个 UDP 物理引用。首包或整批在回调内完成时，任务上下文仍然
存活到调度器 Drop；不再由首包的生存期隐含保护整个任务。

数据报节点和任务节点分别使用真实引用计数与规范 Ops。Next 是链中的拥有
边；Previous、Slot、SendReady 是游标。开始执行时先发布运行中状态并清空
任务中的 Head，再把链交给活动帧和 Worker。运行中任务以及未知外部 payload
拒绝图接纳，不把不完整的拥有关系伪装成叶节点。

拒绝分配或提交会归还整条链的预算，但不接管调用者的 Take/Ref 数据；已被
接管、却没有执行 Task 的任务仍必须释放数据和资源。当前 Worker 上的同步
发送保留直接转移路径，不增加跨线程任务分配。

持久专项为 tests/network/test_net_udp_send_jobs.c，通过单头包装器检查真实
私有命令和链表：复制、Take、Ref、向量、批量、部分前缀、空数据报，队列
拒绝、真实任务分配失败、Drop-without-Task，以及 UDP/Engine 创建者先退休
后再释放保留任务。所有场景要求精确内存配平，未知外部释放回调保持不透明。

这不是完整 UDP/Engine/服务拥有图或语言集成验收。Future/TLS、payload、回调
收集适配、混合生命周期、DLL 卸载、发布和默认 Cgen 评估仍需分别完成。
