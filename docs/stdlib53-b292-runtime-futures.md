# 动态调用的 Future 合同

本批接通显式 xcall、动态方法和绑定方法的 Future 参数及返回值。
非空与可空载体共用非空 Future 的精确类型身份，保留已有引用语义；
不增加语言语法、标准库函数或第二套引用计数。

## 公开签名与 worker 签名

异步函数的公开返回值是 `future<T>`，不是 worker 返回的 `T`。
语义层命名函数值、重载匹配、泛型代入和动态方法登记都使用这一
公开调用签名。XLIR 的命名适配器产生 ASYNC_START，并在调用后
立即观察已有结果载体；动态方法使用同一物理调用和 launcher 原型。
Cgen 不根据源码名字、async 关键字或字符串类型补推调用合同。

已解析为 var 的 callee 表达式统一登记动态调用计划，包含
`xcall(f)()`，不要求先存入局部变量。`await` 按降低后的拥有权接纳
checked Future 转换等表达式；独立 owner 在成功和失败分支均退役。

## 编解码与转换

Future 桥接有独立的 COPY／REF 编解码及 DESTROY_FUTURE 清理合同。
输入检查底层 Future 身份后取得独立引用，返回值装箱后清理原生
返回引用。可空形参支持默认 null 和显式 null；错误类型在进入
方法体前拒绝。nullable 外壳不创建额外 Future 身份。

`var as future<T>` 为 checked 精确身份转换，类型不符时报 TypeError；
`var as future<T>?` 为 try 转换，不匹配或动态 null 返回 null，真正
的资源／checked 失败仍传播。Future 内部的失败不会在投影时被
消费，`await` 继续观察原有错误。

私有驻留读入接口先验证参数、标签和身份，再发布独立拥有的输出。
成功读取不分配；失败不改写输出，清理保留首个 checked 失败，
包括没有诊断对象的失败。类型信息、立即状态边、编解码、presence
和销毁规则由 IR 验证器检查，坏合同不得生成 C 或头文件。

## 验收范围

Windows、Linux 普通与 Linux 指定插桩通道各完成 267 个阶段，
覆盖严格 C 的 O0／O2、JIT、模块加载、AOT 和确定性生成。
459 个 IR 破坏反例在 C／头文件输出前拒绝，遗漏 Future 清理的
坏实现被内存账本检出。专项覆盖精确 NUL／UTF-8
字符串结果、命名异步函数值、相反方向的高阶回调、可空 Future、
动态／绑定异步方法、错误身份及原异常传播。原生测试覆盖零分配
读入、装箱失败前缀、伪造标签拒绝和 producer／transport 退役后
读入 owner 的寿命。

O0／O2 各完成函数用例 65 个、方法用例 57 个、错误用例 49 个
同步分配前缀，首次未命中点分别为 64、56、48。所有命中必须以
MemoryError 失败，无宽松恢复例外；正常、失败和重复退役后账本
均平衡。原生装箱另外完成 2 个前缀，成功读入在 fail-after-zero
下不分配。条件 await 同时覆盖借入与临时拥有分支。

双平台各 310 个三组夹具通过严格编译。驻留目录验证 306 个组件、
1511 个精确导出、93636 对依赖闭包及 23 个拒绝负控。三份独立
裁剪产物通过构建、运行和符号核对；数组展开产物不含 Dict 提供方，
Future 用例不引入无关 process／regex／file 模块。

普通与可空函数参数、默认程序、整数／float32／bytes 及变长帧
作为回归。sanitizer 仅覆盖生成 C 和测试宿主，不代表全部驻留
提供方插桩。证据位于 `E:/xlang-validation/stdlib53-b292-*` 与
Linux 对应目录；增量诊断不作为冻结源码验收或发布证明。

异步多返回值按用户决定继续由语义检查禁止，保留现有负例测试，
留作后续语言结果载体设计，不属于本轮标准库阻塞项。其余动态／
Native 组合、工作线程／对象图故障、模块组合／真实卸载、时区
以及 CLI／DLL／VFS／RC0 发布总验收继续。53 模块目标不结项，
CRT 0、XRT 19 组未决策与对象池最后的顺序不变。
