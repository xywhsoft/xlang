# 原生容器的统一动态投影

Array、Stack、List、Set、Dict 和 OrderedMap 的动态 `as` 投影共用
一个 XLIR 操作及严格／nullable 两类转换合同。成功保留同一受管理
对象，不复制元素，不修改其身份或重新绑定元素策略。

## 完整类型与失败边界

目标必须有闭合的原生构造配方。投影校验真实 private owner、容器
家族、逻辑身份、物理布局和完整不可变策略。OrderedMap 还校验键
顺序以及键和值的两套策略；相同 TypeId 或相同物理槽位都不足以
授权转换。wire 容器和伪造句柄不能冒充对应的原生对象。

严格错配抛 `TypeError`；nullable 错配返回语言 null。工厂、策略
保活、返回值保活和清理失败均保持独立 checked 状态，不把原生
NULL 或无诊断失败当作 nullable 错配。整个事务成功后才提交输出。
见证对象在两条路径都消费，临时源在成功和异常路径均释放。

Tree 的新捕获入口独立拥有键和值的元数据，不保持原 Tree 存储或
生成代码引用；失败不发布部分策略。匹配只观察不可变元数据，
不读取槽位，也不需要源对象处于空闲状态。

## 实现与裁剪

List、Set、Dict、Tree 共用一份原生投影事务，各自的策略捕获／匹配
适配器属于独立组件。只用 List 不选择其他三个投影提供方。
Array／Stack 继续复用既有 Sequence schema 边界，统一的是 IR 的
完整目标、工厂、所有权、效果及状态合同，而不是容器存储实现。

Cgen 只按已验证的家族选择物理符号并发出调用、空输出初始化和
成功状态判断，不新增类型匹配算法或源语义回溯。目标工厂见证
仍可能分配内存，不能宣称整个 `as` 零分配。

## 字面量的成员查询

`127 in set<int8?>` 与 `.contains(127)` 使用现有的编译期整数范围
证明和目标值构造，再执行统一装箱；不在 Cgen 添加特殊转换。
`-128` 等边界字面量可归入目标元素类型，越界字面量和需要缩窄的
变量仍拒绝。null 查询和类对象按引用身份作为 Set 键的规则不变。

## 验收条件

专项门覆盖六类容器、NUL／Unicode、窄整数、nullable、类对象、
嵌套引用、临时源寿命、完整策略错配、无诊断失败、清理错误及完整
同步 OOM 前缀。IR 破坏和不合法输入必须在 C／头文件输出前拒绝。
严格 C O0/O2、JIT、checked module 和生产 AOT 均需实际运行。

生产 TCC AOT 可能没有符号表，不能把 `nm` 未找到符号当作裁剪证据。
门禁另外使用同一 IR 的实际组件／原生模块计划生成独立实现，构建
并运行未剥离的产物，要求符号表存在且只包含所需投影提供方。
仅看生成 C 或候选组件计划不构成这项实际产物验收。

Linux 插桩覆盖生成 C、测试宿主、本批共享事务、四个适配器和 Tree
实现；其他链接的编译器／XRT 提供方以及额外裁剪产物不在插桩范围。
该专项不关闭其他资源转换、`as float32`、其余动态／Native 编码、
工作线程与对象图故障、模块组合、真实卸载和 CLI／DLL／VFS 发布总门。
WaitQueue 保持 MPMC 与 `(status, T?)`，对象池最后，未决策范围不变。
