## 本轮修复

- 恢复 TinyCC 缺失的 `conftest.c` 构建输入，使用固定上游提交/文件 blob，
  在 `lib/tcc/xlang_bootstrap_sources.json` 登记来源；没有升级 TinyCC 核心。
- Linux 运行库源清单补入 `xl6_task_file.c`；TCC 构建不再扫描/烙入父仓库的脏树 Git 状态。
- lexer 使用非交互扫描且不依赖 `unistd.h`，移除生成命令的强制 `--wincompat`，
  使同一份已生成扫描器可以在 Windows 与 Linux 编译。
- XRT Win32 Console 常量回退移到 Console 内部头，在所有 Console 实现之前提供，
  不再偶然依赖随后可选的 logger 实现；增加模拟旧 SDK 的真实单头回归。
- string 转换、容器取值和键删除、动态值/nullable 投影、动态字段、TypeId 名称和
  Future 调试名称使用双字段 string；原生明确要求 C 文本的边界拒绝内嵌 NUL。
- async 源租约清理复用已验证类型的统一释放/槽位清零；product/嵌套 frame 迁移使用
  类型正确的独立空值对象，保持既有有序原子槽位写计划，解决严格 C 初始化诊断。
- 原生 C callback 的 string 参数经过显式 C 文本边界校验；转换失败不调用 callback，
  沿外部错误作用域返回失败。
- 共享 string 辅助函数在统一 prelude 声明，之后再定义；callback 与 Stack 适配器
  需求分析包含其确实使用的 string 支持，解决缺声明/缺依赖，而不是复制第二套实现。
- 已确认双字段 ABI 的旧文本断言按实际合同更新；保留禁止 Cgen 名称猜测、严格 C、
  运行错误和所有权门禁，未通过删除测试或关闭诊断获取通过结果。

综合 fixture 为 `test/cases/stdlib_release_string_abi.xl`，覆盖数值/时间转换和
NUL 拒绝、动态值与 nullable 投影、列表读取与容器 take/pop、NUL 字典键和动态字段、
product move、类型名称、Future 名称和实际异步 string 结果；接入两平台的正式测试入口。

## 批量验收机制

`tools/rc0_guard.ps1` 对静态/接线门逐项采集失败，不再因为前一项失败隐去后续项，
也不把包含失败子项的外层步骤显示为成功。
`tools/run_xlir_guards.ps1` 保留所有选定独立门结果，再调度参数化场景并汇总失败。
参数化 runner 登记 69 个场景 worker，补齐 HTTP async 的所需输入目录。

`tools/run_release_core_batch.ps1` 为本轮修复执行 26 个核心门，创建一次当前源码 driver，
冻结源文件、门禁脚本、用例与 Windows 产物哈希，单独保存日志/真实退出码并继续采集。
这不是完整 RC0；没有声称所有 supplemental 或参数化组合已执行。

最终 `core-final3/results.json` 为 **14 项通过、12 项未通过，输入未改变**。
命名函数/callback adapter、collection algebra、默认后端边界、checked time/float、
string conversion 与 Future payload 门已通过；其余失败不能忽略。

生成 C 确定性/严格编译的批量 fixture 失败由初期 26 项降到 5 项。其间 9 个明确的
错误程序转入“必须精确拒绝且不输出 C”清单，不是将其跳过。余下为四个
`unused-but-set-variable` fixture 与 `xlir_system_bridge_continuation` 的拥有权重绑定拒绝。

运行矩阵准备一次对象/声明后，**完整执行 127 行：123 通过、4 失败**，证据为
`core-final3/check_xlir_cgen_runtime_matrix.ps1.log`。4 项分别是 AvlTree 的实际断言失败、
async generic expression planner 的分配错误、extern Future string capture 的执行失败、
class JSON persistence 的删除文件错误。原因需要分别审计，不能都认定为旧 ABI fixture。
命名函数 adapter 同样改为整批只准备一次工具链，其最终门通过。

`core-final2` 的旧运行矩阵子任务在重复准备阶段被明确中止；该行没有完整覆盖，
保留失败/中断记录，不能加入已通过统计。完整运行矩阵结论只引用 `core-final3`。

`tools/check_stdlib_fs_posix.sh --host-only <新证据目录>` 与默认严格 GCC 路径共用
同一个 38 用例数组，分别记录 JIT、构建和 AOT 退出码，不因第一项失败停止收集。
原始 archive 向量由 Windows 专项独立生成，缺少向量时明确失败。
宿主执行在独立工作目录进行，避免目录 fixture 与并行编译门互相干扰。

   尚未在 IR 中完成明确转换；必须修复和覆盖，而不是把 struct string 当 C 指针传递。
3. **严格 C 与 IR 状态门**：部分未使用的条件结果导致 `unused-but-set-variable`；
   source-lease 与若干 ownership/collection/product 门存在未对齐断言或真实状态差异。
   必须逐项判断，不能统称“测试过时”，也不能关闭严格诊断。
   另外，127 行运行矩阵的 4 项失败和 extern global 公共头边界仍未关闭。
4. **完整 Linux 回归**：`test_linux.sh` 在 xregex 包出现 `xrtRegexErrorOffset`
   重复定义后停止，后续条目不能算通过。基础 import/package、UTF-8 路径及早期
   string 综合用例已运行，但不代表全套 Linux 回归。
5. **全仓 RC0**：初始批次另有标准库覆盖/文档/范例/fixture 接线、扩展库 ABI 与
   旧 dev 项目迁移等失败；不能以本轮核心专项替代这些结果。

优先先修语言与宿主的真实 ABI/拥有权缺陷，再更新可证明过时的断言与用例清单；
随后冻结单一源码和产物跑完整 RC0/两平台套件。扩展库未提交工作需要独立审计，
不能一并提交或据少量专项宣称所有扩展库可发布。

### 修复内容

- Random/SipHasher 的 41 个操作身份、依赖和物理 ABI 移入可验证 XLIR；
  Cgen 按枚举机械消费，不再根据 C 名字猜语义。
- C 可变参数明确展开物理 ABI 与默认提升；原生 C 文本校验失败不调用 callback。
  nullable char/time、擦除集合转换和 imported private global 的公共声明边界补齐。
- 删除未使用的平凡 CONST 写入，覆盖 sync/async/generator；没有关闭严格 C 诊断。
- XRT 增加拥有型、精确长度的 StringView 类型合同，复制失败原子化、move/drop 清零。
  修复 typed AVL/queue 与动态值的 NUL 保真；同步正式生成快照，没有手改产物头。
- Buffer.appendBytes、dict.remove、xlang.Context 与全局 run 桥改为双字段 string，
  按实际长度截断/校验；明确 C 文本边界先拒绝 NUL 再执行或申请资源。
- Race 的“取消请求”与“终态完成”分开；不将 cooperative cancellation 伪造成即时终态。
- Linux 嵌入 libtcc 继承实际配置的 target triplet；在包含任何头前启用 Dl_info 所需
  特性；移除 POSIX 的 CONFIG_TCC_STATIC，避免 vendor 将 dlopen/dlsym 替换为 stub。
  Windows 选项未变。临时诊断插桩没有留在 TinyCC vendor 源码中。
- xregex 语言包装采用明确长度/拥有型输入和公开 xvalue 数组接口；SDK 模式选择
  唯一 resident regex 引擎，独立 C 环境仍由包提供实现。这是必要 ABI 前置，
  没有据此决定 X09 的标准库公开面。
- 标准库范例门收集完整批次；符号门覆盖 native class 及 tcc/xlang 桥，保留真实失败。
  核心门准备一次工具链后统一验证，避免子项重复准备同一运行对象。
  C fixture 接线检查将有限字面量矩阵只展开一次，避免按每个资产重扫全量门脚本；
  保留相同匹配合同，并通过独立一致性探针和完整接线清单复测。
