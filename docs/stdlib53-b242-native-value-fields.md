# 原生拥有值的类字段读取

SlotMapKey 作为类字段的普通读取和隐式字段读取已接通精确拥有结果。
读取取得独立键值，字段替换、临时接收者释放和函数返回后的 finally
不改变已取得的键。本批修复一个可复现的语言核心缺陷，不增加公开
标准库函数、Cgen 算法或新的运行时组件。

## 原因与实现

原生拥有值已经有完整的登记、装箱和 checked 投影，但类字段的 IR
分类遗漏了 native-value。SlotMapKey 字段因此落入动态对象读取路径，
结果不是 xvalue 指针时，lowering 拒绝生成 C。

字段分类现在通过 xl6IrNativeValuePlanForType 核对封闭登记，选择已有
class-field-exact-value 合同。未登记的布局仍拒绝，不凭类名、相同
宽度或外部 C 指针推测能力。已有 lowering 固定字段身份和精确类型，
checked 投影返回独立拥有结果，现有接收者生命周期与退出清理继续
负责暂存、发布和释放。生产修改只有 IR 分类中的三行。

显式 self.value、普通 holder.value 和隐式字段读都使用同一条路径。
临时接收者先保持拥有引用，成功投影后释放；返回值在 finally 修改
原字段前取得独立拥有权。错误计划保留 may-raise，false 状态不依赖
能否分配诊断对象，部分复制失败使用既有原生投影事务回滚。

跨 await 的示例保留现有受保护借入：SSA 视图引用活跃的拥有型帧槽。
这些通过的示例不是独立 borrowed 原生 SSA-copy spill 的完整验收；
后者仍需另行闭合，不能由本批的普通读取或受保护视图推定。

## 双平台验收

Windows 317、Linux 316 个完整源码编译单元通过。字段专项分别通过
655 和 720 阶段，每端 496 次故障位置检测，十组完整前缀覆盖投影、
typed 复制、部分复制后无诊断失败、成功状态伴随诊断和实际分配失败。
同步字段夹具在调用线程注入，失败后完整清理并成功重试；不代表
executor 线程分配注入。

两份语言程序每个优化等级各执行 200 次模块生命周期，验证字段默认
值、读取、替换、显式／隐式 getter、临时对象、数组观察所得接收者、
提前返回、finally、异常及跨 await 的受保护拥有值。分配、释放、存活
字节和错误释放等计数保持平衡。

十个原生字段读取节点、十一处实际投影和 105 项 IR 篡改通过验证。
finally 重放可以产生多个投影，因此不把节点数当成指令数。错误类型、
借入冒充拥有、错误效果和投影 payload 不能越过 IR、C／header 输出
门与原生计划。遗漏字段分类的真实坏编译器、返回空结果的真实坏
投影实现经编译和链接后均被验收拒绝。

两份程序分别选择 25、32 个实际原生供应方，独立 O0／O2 执行不链接
编译器或 MODULE_ALL；公共 JIT、module 与实际 AOT 执行通过。
Linux ASan／UBSan 覆盖两份程序各自的全部选定供应方。相邻回归
Windows 71、Linux 47 阶段及旧 producer／取消／拥有环压力通过。
常驻目录保持 278 个组件、1437 个真实导出和 13 个拒绝对照。

## Channel 状态与剩余工作

Channel 的公共拥有接收与旧 Into 清退已在此前实现，并非当前待开发
项。本批使用当前完整源码在双端各复测 34 阶段、17 个普通接收与
3 个等待接收，以及错误源码和损坏 IR 的拒绝门。最近摘要中把公共
切换列为未完成的表述已更正。更广的无诊断故障和拥有图压力仍保留。

WaitQueue 的原生 backend 与拥有接收继续，旧说明的 MPSC 与详细
设计的 MPMC 冲突已请求用户确认。本批未替用户选择。独立 borrowed
原生 SSA spill、并发队列压力、53 模块与正式 DLL／VFS 总门仍未完成。
对象池最后，CRT 0、XRT 19 组未决策范围不变。复测入口为
tools/check_stdlib_native_value_fields.py。
