# CSV 限定交付与共享默认参数修复

这是扩展库长期压实任务的一批进展，不是全生态或全平台 RC 结论。
没有替换正式 CLI/DLL，也没有同步开发中的 XRT；五个正式产物/运行库快照哈希保持不变。

## 实现与交付

- CSV 核心继续分为公共配置、Reader、Writer 和语言声明桥四个 C 单元；不复制 XRT 流、
  文件、UTF-8、错误和缓冲实现。
- 分隔符增加 TAB，和逗号、分号、竖线采用同一条语法路径；引号仍限单字节可打印 ASCII。
- C 内存读取器借用输入，语言 Buffer 入口拥有快照；字段返回值、结果提取和文件提交
  的所有权已写入公共头及 README。没有把析构当作成功 close。
- 新增 C/xlang 两组对照范例：内存表格/字典/TSV/严格错误，以及文件显式提交/未提交清理。
- README 和官网正文覆盖公共函数、默认参数、五种配额、对象状态、错误类型、流所有权、
  UTF-8/NUL、线程边界和未验证范围。四个文档代码块按原文生成 EXE，在隔离目录执行。
- 官网只更新本地 csv 详情页与生成入口，没有部署线上网站，也未全量覆盖其他包页面。

合同：[README](../release/extlibs/csv/README.md)、[C 头](../release/extlibs/csv/include/xrt_csv.h)、
[语言声明](../release/extlibs/csv/src/csv.xl)、[官网正文](../release/extlibs/csv/docs/site.html)。

## 共享编译器修复

默认实参来自被调函数的声明，但在调用方求值，异常清理必须使用调用方作用域。
原路径混用了声明作用域，且泛型实例化仍以原始位置而非已经绑定的参数顺序推导类型。

本轮统一为以下规则：

1. 默认表达式 lowering 保留其声明来源，但失败出口使用调用方 exit plan；普通实参不改变。
2. 泛型推导读取 CallSite 的参数绑定，涵盖命名实参重排和默认参数，不按源码位置猜测。
3. 实例化后的默认表达式直接由已知克隆声明取出；不向原始语义符号表查找合成符号。
4. 克隆内部调用时，只保留目标不变且确实来自外部声明的默认表达式；自调用使用克隆节点映射。
5. 命名函数值适配器保留自身失败出口，没有放宽 monomorphic ABI 或所有权验证器。

实现：[默认参数作用域](../src/ir/xl6_ir_lower.c:4505)、
[泛型参数绑定与实例化重定向](../src/ir/xl6_ir_lower.c:15220)、
[用例](../test/cases/xlir_default_argument_unwind.xl)、
[分配失败用例](../test/cases/xlir_default_argument_allocation.xl)。

验证使用 `build/test/default-argument-20260928-source-v3/public_source.exe`，直接链接当前
编译器源码，但借用正式 xl.dll 的 TCC core，并使用隔离 AOT 资源布局。不是重建后的正式产品。

| 范围 | 结果 |
| --- | --- |
| 当前源码通用门禁 | 12 组重复 C/H/IR 确定性、内存运行、模块重定位通过，另有上下文失败后恢复 |
| 产物门禁 | 18 组 EXE/DLL、C 混编和预期 ABI 拒绝用例通过；拒绝时保留既有输出 |
| 默认参数扩展 | 显式/推断泛型、命名参数、递归、嵌套默认调用、可变参数、默认表达式抛错及托管对象清理 |
| 分配失败 | 384 个 failAfter 尝试，验证失败捕获和后续恢复；不是 384 个独立缺陷 |
| Windows CSV | 65 个检查步骤通过，856 个输入哈希前后不变 |
| C 核心 | 四单元严格 GCC 编译，七组测试；短读短写、版本、游标、状态、重入、配额、文件和 OOM |
| Windows 故障注入 | 普通 143、文件 47 个拒绝位置；恢复与所有权检查通过 |
| 独立线程 | 四个独立对象工作线程共 1000 次往返，验证线程局部错误隔离 |
| CSV XL/C | 四组 XL JIT/AOT，17 个实际生成 C 原型，另有两组 XL/GCC/TCC JIT/AOT 黄金输出对照 |
| Linux C | GCC 15.2，七组测试、两组 C 范例、LP64 原型；ASan/UBSan/泄漏检查未报告问题 |
| Linux 故障注入 | 普通 143、文件 38 个拒绝位置；与 Windows 不同，不相加为独立覆盖数 |
| 独立互操作 | 两平台分别与 Python 标准库 csv 双向验证 454 项 |
| 文档 | 四个代码块编译运行并校验输出；包内和本地官网正文哈希一致 |

互操作覆盖空输入、零字段与单空字段、尾部空字段、UTF-8/中文/非 BMP 字符、引号、
内嵌 CR/LF、BOM、大字段及确定性随机数据。四种分隔符、两种引号、两种输出换行、
quoteAll 两种配置分别组合，额外拒绝无效 UTF-8、NUL 和引号语法。
对照比较解析后的字段，不强制不同合法写入器生成逐字相同的 CSV。

v4 门禁的文档项曾因测试驱动依赖仓库工作目录而无法加载 TCC；这是隔离测试设置问题，
未改语言源或换运行库规避。现改为在仓库编译、隔离目录执行，v5 全部通过。旧记录保留。

## 未完成范围

- 正式 CLI/DLL 未包含共享修复，复杂 CSV 默认参数/异常路径仍需在下一正式构建复验。
- Linux xlang JIT/AOT、专门 DLL 宿主上下文、32 位/ARM、TSan、长期与吞吐基准未验收。
- 含 NUL 的语言 string 长度/桥接、class 字段数组迭代仍为共享未完成项。
  Buffer/C 显式长度测试通过不能消除这些问题。
- 同一 CSV 对象不可无锁并发；普通输出流不能回滚；文件事务不承诺断电持久性或远程原子性。
- 尚未在本轮重跑全生态；05:43 的 52 入口配对是之前的选择集，不能在没有重跑时改写其通过数。

因此 CSV 可升级为“当前源码双语/两平台 C 限定专项与资料交付通过”，不是“正式发布完整准入”。
后续继续处理运行库缺符号、C ABI、文本长度等共性问题，再以同一正式构建验收首期名单。
