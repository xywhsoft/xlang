# 整数转换默认值的统一 IR 合同

动态方法、绑定方法和 `xcall` 支持可以完整证明的整数转换默认值，
包括 `uint64(0)`、嵌套整数转换及整数范围端点。File 的 `map()`
与 `lock()` 可省略默认参数，不再因默认值写成转换表达式而被拒绝。

## 登记与默认值

类方法先登记身份，供类优先的 intrinsic 解析使用；建立完整表达式
合同后才确定动态调用能力。初次登记、泛型实例重绑定、最终目标
链接与验证器共用同一来源能力判定，避免阶段间标准不同。

默认值常量化只消费已验证的整数转换合同，不依据函数名称。
字面值必须能表示在转换链的每个中间类型及最终参数类型中，
不能把越界 wrapping 转换或普通函数调用误当成常量。
有符号最小值以标准 C 可表示的表达式输出，无符号值保留 ULL。
普通上下文字面量的准入规则没有因此扩大。

## C 输出顺序

动态适配器在所有选中的物理桥接定义之后输出。原生桥接保留
其规范固定宽度 ABI，不从归一化语言存储类型另造一份原型。
该顺序适用于全部桥接类别，不按 File 名称补声明。

## 验收范围

`tools/check_stdlib_integer_defaults.py` 执行常量默认值、typed
副作用与越界转换、真实临时文件 map／lock，以及已有回调、
bytes 默认值与 float32 规则。夹具使用确定性 C、严格 O0／O2、
JIT、checked module 和生产 AOT；整数及文件用例另生成实际
裁剪产物。纯整数产物不选择文件模块，文件产物选择 map、lock
与临时文件模块，两者不引入 Regex 或 Process 提供方。

整数默认值、ABI、转换接纳、结果类型与输入表达式的破坏反例
必须在 C 和头文件输出前拒绝。完整同步分配前缀只覆盖本批整数
用例，不能当成文件系统全部失败路径覆盖。Linux sanitizer 范围
为生成 C 与测试宿主，未插桩全部提供方或额外裁剪产物。

Windows、Linux 普通和 Linux 指定插桩通道各 95 项通过；53 个
输出前 IR 破坏反例通过。O0／O2 各 26 个同步分配前缀包含首次
未触发点 25，模块退役后账本平衡。双端各 310 个三组夹具通过
Cgen 与严格 C 编译；驻留目录维持 304 组件、1507 导出，92416
对依赖闭包和 23 个负控通过。

任意运行时默认表达式的动态求值、异步动态返回、可空函数参数、
其他动态编解码、工作线程／对象图故障、模块组合与真实卸载、
完整时区和发布总验收继续。该专项不代表三组 53 模块或发布完成。
