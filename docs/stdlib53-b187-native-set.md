# Set 原生存储与稳定引用键

Set 底座已使用真实 XRT typed Set 存储，拥有独立的语言类型域、生命周期和拥有图。
基础值按内容作为键，可变对象／容器按引用身份作为键，Future 按控制块身份作为键。
这一批不切换语言 Set 的生产者和方法，也不关闭三组标准库的总验收任务。

## 键的规则

字符串和 bytes 的内容比较包含完整长度，内嵌 NUL 不截断；C NULL 与动态 null
表示同一个缺省值。原生基本值继续使用精确类型描述，不授予引用类型排序能力。

可变 XRT 容器使用实例外壳身份，而不是可因 COW 改变的 backing 地址。独立克隆
是另一个实例。原生句柄使用实际 owner、生产者策略、上下文和类型域；多个外壳
包装同一 owner 时表示同一个引用。键哈希不调用对象的内容哈希或自定义相等回调。
因此普通内容修改不需要冻结、复制键或重建哈希表。该身份只在当前进程有效，不能
作为持久化标识。原生 C 强行提取句柄或重新解释类型不属于语言允许的修改操作。

此规则取代上一批驻留引用键的结构相等规则；不修改 XRT 通用 Value Hash/Equal
或其他容器的比较方式。XRT 回调保护中的 BUSY 值仍按 checked 规则拒绝观察，
不会通过读取私有 Value 内存绕过保护。

## 存储与生命周期

`XL6_SetLayoutV1` 同时保存 Set 身份和独立的值域。创建时消费一个空的、已验证的
Array 域见证，只保留驻留的完整准入元数据，不把 Array 当 Set 存储。元数据独立
于生成模块存活；复制、集合代数和快照均保留完整逻辑域。

驻留接口提供添加、查找、删除、复制读取、取走、容量管理、克隆、合并、四种集合
运算，以及忽略插入顺序的内容相等／哈希。输出槽属于原生调用协议，不恢复语言
byref。失败与“没有找到／已存在”分开；移除已提交后发生的清理错误会报告，不能
承诺回滚已执行的用户析构。

快照迭代器拥有独立的 typed Set 存储，保持插入顺序或反向顺序。源集合修改和释放
不使它失效。已进入迭代操作后的失败会封闭迭代器；EOF 与失败分开。引用元素仍
按引用共享，快照不是对象图深拷贝。

拥有图追踪实际元素引用及 Future 控制块，不用临时 boxed 对象代替。退役遵守
Hold、Claim、Restore、Clear、Finish 阶段；Finish 的边界进入失败可以重试，普通
析构即使无法安装错误边界仍释放存储和元数据，保留父边界的首个失败结果。

`SET_NATIVE` 和 `SET_KEYS` 分开按需登记；键策略不再依赖 Sequence 的递归机制。
未使用 Set 的程序不会因这批接口自动引入它。尚未提供语言 Set carrier 切换、
递归 Set 准入／持久化配方、Dict 迁移和发布产品的全量验收。

## 验证范围

`check_stdlib_set_native.py` 使用真实供应方与驻留代码，覆盖严格 C O0/O2、精确
整数／文本／char／bytes 域、nullable 与原生宽度、集合代数、快照、共享及循环
拥有图、Future、错误边界和完整分配失败路径。四个实际源码变异分别破坏哈希
顺序独立性、失败迭代器、拥有边和逻辑域，必须成功编译后被相同测试拒绝。

`check_stdlib_set_keys.py` 增加可变实例、COW 分离、同 owner 多外壳和无回调测试。
四条完整 OOM 路径仍各自闭合。Linux sanitizer 仅覆盖选定的原生闭包，不代表
整个编译器或发布 DLL 均已完成 sanitizer 验收。

证据使用 `E:/xlang-validation/stdlib53-b187-*` 与 Linux 对应目录。编译器由当前
选定源码重建，按需组件登记和相邻 List／持久化路径单独回归，失败尝试保留。
共享默认子对象仍只按声明 clone 隔离，否则 checked 拒绝。CRT 0 项、XRT 19 项
未决策不变；signal 显式注册线程事件泵、对象池最后开发的决策不变。
