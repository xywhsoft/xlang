# XLIR 多视图发送拥有关系

## v232 实现

原生 SendBuffer 现在使用一个规范的共享批次身份。私有构建过程、每个真实缓冲视图及独立保留者各自持有实际引用；Count 直接读取物理引用计数。Views 仅决定发送资源何时完成，不充当引用计数。

每次创建视图先取得批次引用，再通过明确的不可变策略转交给缓冲块。所有视图构造成功后，源块链和视图链在拥有关系变更域内发布，然后释放构建过程的引用。任意分配失败只回收私有视图，源缓冲及其释放责任仍属于调用方。

最后一个视图完成时，立即在变更域外 Unit 原始载荷，然后释放该视图的物理引用。额外保留批次外壳不会延迟用户载荷释放回调。载荷释放期间 Trace 拒绝快照；完成后仍存活的批次继续保留真实 Stream 引用，不被冒充为叶节点。

移除逐视图反向索引数组后，当前 Windows／Linux x64 的批次元数据固定为 88 字节，不随视图数量增长。原始块继续保持各自的缓冲池引用；批次中的 Owned 只保存已有块，不再借用源缓冲池分配器。

内部缓冲遍历器只读取块上实际保存的拥有描述，未知借用或未声明的释放上下文仍拒绝。公开 V1 遍历接口继续执行完整的精确策略白名单检查。Cgen、生产 XLIR planner、生产单头和发布文件均未修改。

## 已验证范围

- 初次发现批次：34 个 Windows／Linux GCC 组合、8 个裁剪编译配置通过。
- 扩大定向批次：86 个组合、8 个裁剪编译配置通过。包含 Windows／Linux GCC、GCC O2、TCC，以及 Linux ASan／UBSan／泄漏检查。
- 新批次拥有关系测试在 7 种配置中执行 162 个场景：覆盖 108 条真实视图边、54 次额外外壳保留、18 次旧式不透明载荷拒绝、54 次 OOM 回滚、54 次公开 SendBuffer 成功发送，以及 108 次释放回调中的异线程冻结探测。
- 特别检查了部分消费、退休的原始缓冲池、回调期间重新保留／释放批次、载荷释放后保留 Stream／Engine 外壳，以及精确内存平衡。

上述新增测试中的内部构造／链接部分在真实 Stream Worker 上、IO 调度前检查拥有边，再使用生产消费函数推进完成；它不等同于 OS IO 完成证明。公开发送行为另由 OOM 分组和原有 TCP 字节顺序、慢消费者、并发及生命周期测试覆盖。
