# 网络服务基座补全设计

本文档记录本轮网络能力补全的当前口径。目标是让 xlang 具备开发 xserver 的完整网络能力，同时把已经验证过的服务端通用能力下沉到 XRT，使 C 与 xlang 都能直接复用。

## 总目标

本轮不把 XRT 改造成某个具体 Web 框架，而是把网络服务所需的稳定基座补齐：

- XRT 提供完整 TCP、UDP、TLS、HTTP/1.1、路由、静态文件、虚拟主机、reload、配置与统计能力。
- xlang 标准库只做薄封装，尽量不重复实现 XRT 已经具备的功能。
- C 与 xlang 使用同一套底层语义，避免 xlang 有能力、C 无法复用，或 C 能力暴露不完整。
- 不引入 WebSocket、XTP、bus 协议作为本轮目标。

## 分层边界

### xnet_base / xnet_engine

职责：

- 网络地址、结果码、错误对象、配置结构。
- 事件循环、worker、timer、post、future/wait。
- 不理解 TCP 业务协议，也不理解 HTTP。

补齐方向：

- 增加更完整的错误描述结构，保存 result、系统错误码、操作名、远端/本地地址和简短消息。
- 增加 engine/listener/stream/dgram 的基础统计接口。

### xtcp / xudp

职责：

- 面向 C 直接好用的 TCP/UDP 同步、异步、协程等待 API。
- 提供文本与二进制两条路径。
- 提供简化 API 与配置型 API。

补齐方向：

- TCP 增加 `ConnectEx`、`ListenEx`。
- UDP 增加 `BindEx`。
- stream 增加二进制 `RecvBytes`、`SendBytes`、`ReadBytes`。
- datagram 增加二进制 `SendBytes`、`PacketBytesCopy`。
- 继续保留现有 text API，作为脚本和工具层便捷接口。

### xhttpd

职责：

- HTTP/1.1 协议解析、连接生命周期、keep-alive、请求/响应、流式 body。
- 不负责路由、业务 handler、虚拟主机和应用 reload。

补齐方向：

- 当前固定容量 request/response 结构需要逐步升级为动态结构，限制由配置控制。
- request body 和 response body 需要支持流式读写。
- 增加 header/body/idle/write timeout 与 limit。
- chunked 请求和响应不能只作为 whole-message 处理。

### xweb

职责：

- XRT 的通用 Web 服务基座。
- 提供 app/router/middleware/static/vhost/reload/error handler/stats。
- API 必须 C 友好，xlang 只做薄封装。

补齐方向：

- 从 `xwebserver` 中拆出 `xwebapp` 和 `xwebrouter`。
- server 持有 app 快照，reload 时原子替换 app。
- 增加 virtual host，统一 HTTP Host 与 TLS SNI 分发。
- 增加中间件链，用于日志、鉴权、CORS、压缩、限流等通用能力。
- 静态文件补齐 ETag、Last-Modified、Range、HEAD、安全路径检查。
- 增加默认 404/500 handler 与可替换错误 handler。

### xlang 标准库

职责：

- 暴露 `tcp`、`udp`、`http`、`http.server` 的完整能力。
- 不在 xlang 层重复写路由、静态文件、HTTP util、TLS 分发等底层逻辑。
- xlang API 应比 C API 更易用，但语义必须能映射回 XRT。

补齐方向：

- `tcp` / `udp` 增加二进制 buffer 能力。
- `http.server` 由“server 直接注册 route”升级为“app/router/server”模型。
- 增加 HTTPS、虚拟主机、reload、配置对象、stats、错误 handler。

## 阶段验收

### P0：传输层补齐

- XRT 提供 TCP/UDP 配置型 API。
- XRT 提供 stream/datagram 二进制便捷 API。
- C 测试覆盖 TCP 二进制收发、UDP 二进制收发、配置型 listen/connect/bind。
- xlang 标准库能使用这些能力，至少有 C/xlang 对照范例。

### P1：HTTP/Web 基座补齐

- XRT 提供 `xwebapp`、route、static、error handler。
- `xwebserver` 能 attach/swap app，实现不重启监听的 reload 基础能力。
- XRT 提供 virtual host，按 Host 分发请求。
- C 测试覆盖路由优先级、参数、静态文件、404/500、reload、vhost。

### P2：生产级服务能力

- xhttpd request/response 固定容量限制逐步替换为动态结构。
- 支持流式 body、chunked 流式响应、大文件发送。
- 增加超时、limit、stats、graceful stop/drain。
- xlang `http.server` 暴露完整配置、app/router/vhost/reload/stats。

## 口径约束

- 能用 XRT 实现的功能必须在 XRT 中实现。
- xlang 标准库不复制 XRT 的网络、HTTP、路由和静态文件逻辑。
- 所有新能力必须同时考虑 C 使用舒适度和 xlang 封装舒适度。
- API 优先简单直接，避免为了兼容旧写法增加回退路径。
- 已经暴露的 text 便捷 API 可以保留，但新增能力必须以二进制安全为基线。
