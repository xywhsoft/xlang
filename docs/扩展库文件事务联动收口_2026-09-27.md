### 隔离构建与测试

`build.bat`/`build_dll.bat` 支持 `XL6_RELEASE_DIR` 和 `XL6_BUILD_TMP`；默认仍为
`release` 和 `build/tmp`，源码 SDK/范例路径不随输出位置移动。XRT 对象默认
跟随中间目录，也可继续显式设置 `XL6_XRT_OBJ`。例如从 demo6 目录执行：

```bat
set "XL6_RELEASE_DIR=%CD%\build\candidate\runtime"
set "XL6_BUILD_TMP=%CD%\build\candidate\intermediate"
call build.bat
```

三个压缩库门禁、文件运行层门禁及相关 CLI/VFS 检查接受 `-RuntimeDirectory`。
压缩门禁为子进程设置明确的包搜索路径，记录实际 EXE/DLL 哈希，C 范例运行器
也使用同一目录。`-XrtInclude` 仍只覆盖独立 GCC C，不改变 JIT/AOT 的运行库。

后续先审计取消的确定性合同与 DLL 标准库桥接，再完成统一发布回归。当前
三个正式发布程序哈希与本批开始前一致；下面保留候选构建前的历史记录。

## 候选构建前的源码结论（历史）

压缩库的隔离修复版专项也通过。随后只把四个相关源码块定点同步到 demo6 的
两份运行库实现头，没有整包升级开发中的 XRT。

**源码修复已经进入 demo6，但发布运行库仍未完成同步。** 新增同一 C 用例直接
对比：独立 GCC C 和当前源码 AOT 通过，现有 `xl.dll`、`xlc.dll` 及 `xl run`

## 修复范围

- XRT `src/fs/file.c`：在 OS 创建/截断前分配文件对象，接管句柄本身不再分配。
- XRT `src/internal/xrt_file.h`：统一私有预分配与初始化入口，删除事后分配入口。
- XRT `src/fs/file_root_posix.c`、`file_root_windows.c`：采用同一顺序，补足
  符号链接分支、打开/验证失败、append 句柄处理的对象释放。
- gzip、Brotli、BZ2：不覆盖模式使用 `xrtPathStat` 区分不存在和查询失败。
  Brotli 另保留首个文件/内存/回调错误，禁止查询 OOM 后继续并返回成功。
- 新增共享文件事务故障测试，压缩/解压分别测试替换已有目标与新建目标，检查
  原文件保护、临时文件、内存平衡、无效释放及越界计数；保留既有正常/取消测试。

普通/root-relative 的保证仅限这里验证的分配失败，不声称所有 OS 失败都具有
回滚能力，也不等同于断电持久性保证。Windows 符号链接创建因权限 1314 跳过；
Linux 原生文件系统上实际执行了符号链接故障注入。
