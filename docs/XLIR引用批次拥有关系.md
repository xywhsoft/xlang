# XLIR 引用批次拥有关系

## v234 实现

SendRefs 不再把多个条目的完成数量当作一份共享资源引用。批次负责共享存储与调度；每个条目具有独立、真实的引用计数，并持有一份批次引用。批次继续持有真实 Stream 引用，因此额外保留条目也能保护 Stream／Engine／Worker 的存储。

发布前，批次拥有各条目的初始引用，临时缓冲视图另行取得条目引用。任何视图构造失败只释放临时引用，不调用用户释放过程；放弃未受理批次时，清理条目并归还完整预算，外部引用仍归调用方。全部视图成功发布后，初始条目引用和构建过程的批次引用归还，调度器保留其独立引用直到任务返回。

每个缓冲块保存精确条目身份。释放条目时，在变更域内标记正在释放并摘除上下文，再于域外调用该条目的原始 Release；完成后清除外部载荷和代码指针。额外引用仅保留条目外壳，不延迟载荷释放。正在执行 Release 的条目拒绝 Count／Trace，已退休条目仍枚举真实批次引用。

新增 `xrtNetStreamSendOwnedRefsV1` 与 `xnetownedrefv1`，以显式 `xnetbufownershipv1` 描述上下文。非空条目在成功时各转移一份真实引用；零长度不转移，任何拒绝也不转移。旧 `SendRefs` 继续兼容，但其未声明上下文的活跃条目仍拒绝 Trace。拥有型条目枚举上下文与批次，批次仅在发布前枚举实际拥有的条目。

已测 x64 布局中，条目由 40 字节变为 48 字节；批次头保持 64 字节。新旧公开条目类型均为 32 字节，旧公开结构未修改。增加的 8 字节用于条目真实引用计数与生命周期状态，不复制载荷、不增加逐条目堆分配。
