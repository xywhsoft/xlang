# 动态数值构造的反射身份边界

反射 `type` 令牌与无符号整数使用相同的 UInt 物理载体，但不属于
数值。动态 C 数值构造必须拒绝反射令牌，不能因为底层标签相同
就转换类型身份数字；普通语言及 C 数值仍按既有安全规则转换。

## 合同

规范运行时类型表升级为版本 3，增加反射类型的语言身份。身份由
Typed IR 的已有规范类型哈希生成，与 uint64 的身份分离；验证器
核对完整表。Cgen 仅传递验证后的数字，不重算哈希、不按名字猜测。
Typed／Lowered 的文本及 JSON 同时公开这项合同，坏版本、空身份
或混用整数身份的表不得生成 C 或头文件。

动态原生转换入口升级为 V2，必须收到非零反射身份。读取真实标签
失败时直接捕获原失败；反射身份匹配时返回 TypeError，不进入数值
转换，也不发布输出。实际数值继续调用共用转换核心，目标宽度、
舍入、范围检查和截断规则不变。旧 V1 动态入口移除，不保留不安全
回退；精确 `as`、可空投影和原生纯匹配接口不变。

## 验收范围

冻结源码证据位于 `E:/xlang-validation/stdlib53-b295-*` 及 Linux
对应目录。专项核对全部 20 个 C 数值目标对反射令牌的拒绝、复制
和 Array 保存后的身份、动态方法返回、精确 type 读取，以及普通
UInt／C 数值仍能转换。原生合同额外检查反射拒绝在 fail-after-zero
下零分配、保持 TypeError 且输出不变，并拒绝缺失反射身份的 ABI 调用。

Windows、Linux 普通及 Linux 指定插桩通道各完成 390 个阶段，覆盖
严格 C O0／O2、JIT、模块、AOT、四份独立裁剪产物与 2490 个坏 IR
输出前拒绝。反射用例 O0／O2 各完成 23 个同步分配前缀，首次
未命中点为 22；既有三个用例分别保持 36、27、16 个前缀，失败和
退役后账本平衡。四个 Typed／Lowered JSON 阶段核对规范反射身份。
双平台各 310 个既有三组用例严格编译通过；驻留目录各验证 308
个组件、1515 个精确导出、94864 对依赖闭包及 23 个拒绝负控。
插桩仅覆盖生成 C 和宿主，不扩大为所有原生提供方。
