扩展库的实现范围已经明显扩大，但当前默认 XLIR 后端存在公共接入缺口，历史“已压实”标签不能作为本次构建的发布依据。

- 当前活动目录 225 个，其中内部包 7 个，公共包 218 个。

- 当前默认 `xl run`：106 个重点/第一阶段聚焦用例中，25 通过、81 失败。
- 另测 HTTP/WebSocket 包内 19 个用例，全部失败；合计默认路径 125 个用例，25 通过、100 失败。
- 这些是用例结果，不是“只有 25 个库具备真实实现”的统计。不同库会共享同一个编译器缺口。
- 没有替换 XRT、重建编译器或改动扩展库实现；分析使用当时 release 内的现成构建。

### 协议编解码与完整客户端要分别记账

## 当前最重要的问题

### P0：extern 借用字符串被当成拥有字符串释放

`semver_native.c` 第 33 行的返回值来自静态 ring buffer。
当前默认生成的 C 在 `xsemver_prerelease` 返回后未建立拥有副本，调用者随后用 `xrtFree` 清理这个地址。

从当前 Cgen 输出截取的关键路径：

```c
/* xlir_fn_14 */
v20 = xsemver_prerelease(v19);
xrtFree(s43); s43 = NULL;
return v20;

/* caller */
v178 = xlir_fn_14(v177);
s4294967268 = v178;
/* ... compare ... */
xrtFree(s4294967268); s4294967268 = NULL;
```

对照后端在同一调用使用 `xl6_xrt_external_string_copy(xsemver_prerelease(version))`。
相同 semver 测试在当前默认后端失败，在诊断用 legacy 后端通过。

应在 typed/XLIR 的外部返回值 ABI 中明确 borrowed/owned，并在边界生成所需的复制/接管。
不要逐个把扩展库静态返回缓冲改成另一套临时约定来绕开编译器缺口。
106 个聚焦用例中有 56 个出现 invalid argument；这里只确认其中至少 semver 存在上述所有权错误，不把所有相同报错自动认定为同一根因。

证据：[semver_native.c](../release/extlibs/semver/semver_native.c:33)，以及附录中的默认/诊断对照结果。

### P0：标准库辅助符号未形成完整链接闭环

典型失败为：

- `xl6_xrt_string_byte_len`、`xl6_xrt_string_byte_at`、`xl6_xrt_string_slice`；
- `xl6_xrt_string_starts_with`、`xl6_xrt_string_replace`、`xl6_xrt_string_split`；
- `xl6_xrt_os_args`、`xl6_xrt_dir_list`；
- `xl6ExtlibErrorClear`。

迁移前的 `src/cgen/xl6_cgen_std_string.c`（现已退役，见 Git 历史）曾定义相关生成规则，
[标准库符号表](../src/stdlib/xl6_stdlib_data.c:6048) 仍引用这些名字；
当前默认 XLIR 产物调用这些符号时没有得到对应定义。

应把依赖及物理调用 ABI 纳入统一 XLIR lowering/模块需求计算，并验证 run/build/DLL 路径一致。
本轮默认路径共 28 个用例报缺失符号。不同符号可能有不同接入点，不能仅修 byteLen 后认为整面完成。

### P1：复杂 native/异步产物仍有拒绝和非法 C

- `xhttp.body_async`、`body_file`、`body_stream`：transferred return 缺少 exact source LOAD ABI。
- `body_codec`：async task 缺少结果所有权 ABI 或显式 captures。
- `xhttp.client` transport：async suspension result ABI 未接纳。
- `xws` TCP/TLS 回环：生成 C 重复定义 struct/union/enum。
- `xmail`、`dotenv`：当前生成 C 出现 identifier expected。
- 诊断用 legacy 路径的 `xmail` 也失败，报 `xl6_xrt_net_stats_destroy` 重定义类型不兼容。

这些需按生成 C、call target、类型定义去重、错误模型和任务帧边界分别收口。不能全部归因于扩展库算法。

### P1：已登记平台库仍有独立实现缺陷

[serial_native.c](../release/extlibs/serial/serial_native.c:26) 使用全局 `read_buf[4096]`：

- loopback 满 4096 字节时，read 路径写入 `read_buf[4096] = '\0'`，存在越界。
- 真实 ReadFile 路径把用户 maxLen 直接传入固定缓冲区，没有按容量夹紧；负值和大值都需要限制。
- loopback write 缓冲区满后仍返回请求长度，无法体现实际写入的短写结果。
- 全局读缓冲与错误缓冲没有线程/对象隔离。
- [serial.xl](../release/extlibs/serial/src/serial.xl:42) 的 write 使用 `string.len`，会把字符数当字节数传给串口，UTF-8 非 ASCII 数据可能被截断。

这些是源码审查证据；本次未额外触发越界运行，也未连接实体串口。现有平台门禁使用 loopback，不能替代设备、边界长度和并发验收。

### P1：真实后端成功路径的测试不足

`onnxruntime` 聚焦用例主要测试 available、SessionOptions、TensorZerosF32、缺失模型和 release；
`rapidocr` 聚焦用例主要测试运行库、字符集和不存在的模型/图像。
对应的 C smoke 也包含缺失模型路径，没有构成固定模型与已知输入输出的端到端推理验收。

它们有真实实现，应继续补强；这与“占位库新增实现超过 10000 行则暂缓”的预算规则无关。
需要固定小模型、确定性输入输出、重复创建释放、并发/取消以及可复用的后端测试环境。

## 建议实施顺序

1. 先收口默认 XLIR 与扩展库的公共合同：外部返回字符串、标准库符号、错误传播、复杂 native 类型与 async ABI；优先用本报告失败组建立复现矩阵。
2. 将现有包内 `coverage.tests` 接入测试调度。验收记录绑定编译器构建、平台、后端、测试层级与结果，目录成员身份只描述候选范围。
3. 对协议层增加拆包、粘包、短写、断连、重试/取消和本地真实服务门禁；同时修复 serial 的独立边界缺陷。
4. 给模型/平台库补真实后端成功路径，继续维护有条件可用的范围，不按总代码量排除已有实现。
5. 按实际 API 完成官网详情页并移除失效入口；同步后再选择少量性价比高的新库。

10000 行预算只评估占位库的新增实现，不把已有 ONNX、RapidOCR、xbot 等实现计入预算，也不以当前测试失败为由将它们重新归为占位库。

当前清单中仍有 52 个 deferred-large、36 个 deferred-platform、2 个 existing-hardening（xge/xge_shape_ex）和 7 个内部包。
这些是处置分类，不是完备性证明；例如 nats/mysql/faiss 当前源码仍包含名称映射和小型帮助算法，不能视为完整 NATS/MySQL/FAISS 后端。
