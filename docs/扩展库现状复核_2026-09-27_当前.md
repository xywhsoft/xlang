## 结论

当前生态已经有很大的真实实现储备，不能继续把大量网络、GUI、AI 包统称为占位。
但是，**实现广度明显领先于接入一致性、真实场景测试和交付文档**。225 个活动包
不是 225 个成熟库，116 个测试登记也不是 116 个已压实库。

本次重新读取全部活动 manifest、测试登记及本地官网，审查重点实现，复跑选定入口。
没有声称逐行审核全部包，也没有根据包名、文件数或历史标签自动判定暂缓。

最新固定构建结果：**50 个 Windows JIT 用例，31 通过、19 失败、0 超时**。
这 50 个用例涉及 49 个包，xregex 有两个入口；它们不是随机抽样，不能推算全生态
通过率。测试前后 1964 个记录输入未变。另有 6 项旧候选诊断为 5 通过、1 失败，
以及 xregex 独立专项；这些结果不混入 50 项统计。

后续收口只修改了 xregex 的实现、测试和交付材料；其余这批记录中的包源码未变。
本文的整体 JIT 数字仍指上述固定批次，正则的最新 37 项专项、169 个分配失败点及
官网交付另外记录，不把不同范围相加为整体通过率。

## 能力分层

### 1. 有专项基线的基础库

`aho_corasick`、`argon2`、`bloom`、`blake2`、`blake3`、`sqlite`、`xxhash`、
`crc32`、`md5`、`murmur3`、`sha3`、`siphash`、`mqtt`、`gzip`、`brotli`、`bz2`。

这 16 个包拥有此前范围明确的专项和交付记录，本次所选 JIT 入口也全部通过。
既有专项的 Windows/Linux、OOM、回调、文件事务和并发范围并不完全相同，
本次没有重跑全部专项，不能描述成 16 个包在所有平台、所有 API 下无条件成熟。
它们适合作为第一批固定发布验收对象。

### 2. xregex 新增专项与交付闭环

最新固定构建通过包内综合用例与新增生命周期用例；独立 Windows 专项 **37 项**
通过，包括以下范围：

- 独立 GCC C 构建，matcher/splitter 输入所有权、对象释放与 169 次分配失败路径。
- 5 个 XL 测试/范例的 JIT、AOT 和生成 C；JIT/AOT 输出一致。
- 49 个实际生成的外部声明与真实 C 实现共同编译，覆盖全部当前 xregex 原生绑定。
- C 范例经 GCC、`xl run`、`xl build` 和包运行器运行，与 XL 范例的黄金输出一致。

Linux 独立 C ASan/UBSan、泄漏检查、相同 169 次分配失败路径、范例黄金输出和
49 个实际声明的 LP64 编译检查也通过。这不是 Linux 上整个 xlang 编译器的验收，
也没有据此宣称任意线程共享、无限输入规模或全部性能指标已验证。

较早的 C AOT 重复正则实现失败已不能作为这个受测构建的当前失败项；此前记录
保留为历史证据。新包装中 matcher/splitter 持有稳定输入，错误位置 API 接受明确的
`error` 对象，不再依赖已被下一次调用清除的线程局部错误状态。

**后续交付已补齐**：README 已统一为 `VALUE_CONTAINER`/xvalue、明确错误对象、
输入所有权和字节偏移口径；新增包内官网正文并生成详情页，接入目录搜索。
3 个页面范例实际执行通过，桌面/移动端、链接与资源检查通过。

本次还发现 `valid()` 吞掉全部原生错误，而非只处理语法错误；修复后，非法语法
返回 false，内存不足、资源超限和参数故障保留诊断。新增分配失败检查使专项从
139 个失败点增至 169 个。计数变化是新用例，不是此前 139 个用例失败。
完整范围见专项记录；仍不宣称全平台、全部性能边界或整生态已达到 RC。

### 4. 名称覆盖的领域大于当前公开能力

- **mysql**：当前语言层是命令/类型/状态名称、转义、DSN 等辅助函数，不是完整的

- **faiss**：当前入口为名称查询和字符串向量距离计算，不是完整的索引构建、

前四个包本次所选测试通过，只能证明这些有限辅助能力。其余未选中的包在逐包
矩阵中保留“not selected”，不自动标为通过、失败、占位或超预算。

## 当前实测失败

| 类别 | 包 | 已确认的当前阻断 |
| --- | --- | --- |
| bool / long long ABI | barcode、color、graph、json.patch、semver、sitemap、slugify、units | 生成外部声明与真实 C 返回类型不一致，共 8 包 |
| C int / XL int ABI | onnxruntime、rapidocr、xssh | 外部声明未表达 C 的真实物理类型，编译被正确拒绝 |
| 析构返回 ABI | xhttp.client，依赖 xhttp.protocol | `xhttp_protocol_headers_destroy` 返回类型不一致 |
| 缺失运行时符号 | cli、xmail | 分别缺 `xl6_xrt_os_args`、`xl6ExtlibTlsLeaseRelease` |
| 异常合同 | csv、xhttp | CSV 的错误引号输入返回 RuntimeError，用例期待 CsvError；URL 的非法输入返回 ValueError，用例期待 RuntimeError |
| 运行时类型错误 | srt、statistics | 抛 TypeError，仍需独立定位，不能直接与 CSV 合并根因 |
| XLIR 控制流 | xhttp.body_file | 可达非空返回函数存在未终结块 b439，未进入正文文件行为测试 |

这些合计 19 个失败包。HTTP client 在约 72 秒后给出具体编译错误，没有发生
网络请求；不能将编译时间或旧批次的短超时解释成网络死锁。

新构建已越过较早的部分 SDK feature 检查，xmail/xhttp/xssh 暴露的是后续问题。
CSV 也越过了原生类字段默认初始化路径，不应再用旧 TypeError 概括当前失败。
URL 的这一项主要是错误分类/测试合同问题，不能据此认定 URL 解析算法不正确。

graph 的 `xg_is_dag` 真实返回 `-1/0/1`。修复时应准确声明整数状态，并在语言
包装中映射为 bool/异常，不能把 C 返回类型随意改为 bool 来消除报错。

另有 9 个工具包的所选入口通过：`ansi`、`gettext`、`ical`、`memcached`、`money`、
`qr`、`rss`、`shellwords`、`vcard`。它们不因此自动进入前述专项成熟名单。

## 成功路径之外的风险

以下为源码审查结论，不能冒充本轮已运行的破坏性/并发测试。

1. **Agent 工作区边界不严。** [Resolve](../release/extlibs/xbot.agent/src/agent.xl:131)
   只比较字符串前缀，没有路径分量边界。`work-other` 也可能通过 `work` 前缀检查。
   `writable` 参数在该函数中未消费；路径别名、符号链接和大小写规则需要明确合同。
2. **Agent 资源策略未完整生效。** `max_command_seconds/timeout_seconds` 没有进入
   执行逻辑；`fs_read` 先全量读取，再按字符数截断，不是真正的字节读取上限；
   `start_line/end_line/recursive` 声明后未使用；Trace 直接拼 JSON，缺少统一编码。
3. **Memcached 的网络合同未完成。** [包装](../release/extlibs/memcached/src/memcached.xl:79)
   用字符长度填协议字节数；每次只 recv 一次，没有处理分段/合并/长响应；空串混同
   未命中和命中空值。当前测试仅覆盖报文辅助，不代表真实客户端已通过。
4. **共享可变返回缓冲。** color、semver、units、Memcached 使用进程级静态字符串
   缓冲。后续调用、重入和多线程可能改写结果，应明确所有权并复用 XRT 的结果模型。
5. **图算法内存与复杂度。** [XGraph](../release/extlibs/graph/graph_native.c:43) 使用
   固定大数组，在 x64 下结构约 544 KiB，多个函数将其放在栈上；部分遍历对每个
   节点重复扫描全部边。需要按需堆存储、邻接结构、规模上限和 OOM 测试，而非只修 ABI。

## 建议的后续顺序

1. **先统一接入合同。** 对全部外部声明检查整数宽度、bool、析构返回值、const、
   容器和所有权；用真实生成原型与 C 实现共同编译，不关闭类型检查或添加旧 ABI 回退。
2. **修复共享阻断并固定发布输入。** 运行时符号、原生类初始化、错误映射、XLIR
   控制流及 SDK 功能可见性集中补测；源码、XRT、SDK、程序一起形成可追溯的测试输入。
3. **形成首个可交付批次。** 优先 16 个基础库，加新完成文档/网站交付的 xregex；
   在同一构建完成 C/XL、JIT/AOT、Windows/Linux 和各库必要的破坏性测试。
4. **接通已有高价值能力。** CSV、CLI、小工具、HTTP 客户端和邮件先行，再推进
   SSH 完整语言对象、AI 成功推理、GUI 实际事件与生命周期，不从零重写已有后端。
5. **逐库决策占位与暂缓。** 只有真占位库才估算新增 10000 行预算，列出缺失 API、
   依赖和实现成本；历史的 52/36 等候选分组不是已经完成的延期结论。
6. **范例和官网随验收交付。** 每个公开 API 的范围、依赖、最后受测构建和限制
   都应可查，不把清点页、import 成功或名称查询测试当作完整产品能力。

当前最有价值的投入是让已有功能稳定、完整地交付，而不是继续增加包名称。
本报告不覆盖整个生态的 C/AOT/Linux、GUI、真实邮件/SSH 服务或模型成功推理验收；
xregex 的独立专项不能外推到其他包。长期生态压实任务仍未完成。
