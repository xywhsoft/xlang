# Set 语言入口与原生载体迁移

本批将语言 Set 工厂、静态方法、集合代数、checked 导入和受支持的
JSON/XLON 恢复切换到真实 XRT typed Set。键规则不变：基础值按内容，
可变对象和容器按实例身份，Future 按控制块身份。修改对象内容不改变
成员身份，也不要求对象声明内容 hash/equal。

## 统一 IR 合同

Set 和 List 共用完整值域配方，含逻辑元素域、物理槽、codec、所有权、
nullable 准入和独立键 ABI。Set 创建使用消费式元数据 witness，不把
Array 存储当作 Set。静态方法、导入及恢复均由已验证配方选择驻留提供方；
Cgen 只输出描述数据、物理调用和既定错误边，不生成标准库实现函数体。

Set 的四种集合代数返回独立 owner；分配失败必须在读取结果前进入错误
路径。关系判断使用独立错误作用域，正常 false 不是失败。普通赋值与
复合赋值共用这份 IR 效果合同，失败不能提交替换后的集合。

nullable 元素按完整类型域准入：允许对应非空元素和真正的 null，
不隐式扩大整数宽度，不以删除 nullable 包装代替域检查。`set<uint64>`
可值遍历完整范围，Set 不提供索引键遍历。

## 导入、复制与持久化

从真正的 erased Set 到具体 Set 的 checked 转换创建独立根存储，引用
元素仍按既定身份规则保留。输入先认证驻留 ops、完整类型域和状态，
使用拥有元素的快照；BUSY、错误类型、外来 handle 和旧 wire-Set 不
因“内容碰巧适合”而退化准入。导入成功或失败都消费事务 seed。

浅复制保留元素引用但拥有独立集合存储。深复制复用 XRT 同一图 memo；
闭合 Set 图不选择 List 提供方，混合或开放图才选择两者。JSON/XLON
以紧凑序列保存 Set，恢复使用原生工厂和完整元素准入。尚走旧恢复计划
的 Dict 混合根也不能输出 wire-Set；本批不迁移 Dict 存储或宣布其验收。

新增七个按需驻留组件：Set 方法、Set 导入、开放集合计数、Set 图复制、
Set 持久化投影、Set 类恢复及混合类恢复。封闭 Array 程序不引入 Set，
封闭 Set 叶程序不引入 List。公开语言 API 未增加兼容别名。

## 验收边界

Windows 和 Linux 的 13 组专项与回归通过；源码构建分别链接 288 和
287 个新对象，不以旧编译器 DLL 代替编译器输入。最终语言专项每端
239 个阶段，拒绝 125 项损坏 IR 合同，检查独立选择的 O0/O2 C 闭包
及真实 JIT。完整语言夹具、Set 专用恢复叶夹具、Array 对照在每种
优化下分别执行 1,927、278、10 个完整分配前缀。Set 叶无 List，
Array 叶无 Set；旧字典恢复混合根中的 Set 也通过原生成员操作。

原生方法与导入每端 126 个阶段，13 条操作在 O0/O2 各执行完整分配
和无诊断作用域拒绝前缀，共 52 条扫线；两个已编译错误实现被拒绝。
Linux 的选定原生及生成代码闭包通过 ASan/UBSan，不涵盖整个编译器。
退役的 `set<uint64>` 拒绝夹具改为实际消费完整无符号值的正向夹具，
两端各七个 IR/C/JIT 补验阶段通过。Windows 另有四个实际源码 AOT
及独立执行阶段，通过已有清单部署原生源码包；不是发布 VFS 验收。

专项门为 `check_stdlib_set_source.py` 和
`check_stdlib_set_source_native.py`；复测 Set 消费者、遍历、配方以及
List 的复制、索引、恢复和动态字段。两份旧文本守门的首个失败与
基线一致，不记为守门通过；文档守门仍有 14 个历史失败，无新增诊断。

证据目录为 `E:/xlang-validation/stdlib53-b192-*` 和 Linux 对应目录。
源码驱动器复用既有供应方 TCC 内核，不代表发布 DLL 已重建或通过发布
验收。DEV-XRT-53 继续；CRT 0 项、XRT 19 个未决策组、对象池最后及
共享默认子对象按声明 clone 隔离否则 checked 拒绝的决策均不变。
