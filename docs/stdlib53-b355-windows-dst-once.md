# Windows 夏令时一次性实测

2026-10-17，按用户授权临时切换本机系统时区，纽约一小时和 Lord Howe
半小时的 DST 转换已通过实际产品验收。两个时区共十六个运行配置全部通过，
另有四个严格 C 对象及两个原时区拒绝对照。此前延期的 Windows DST 实测项
已补齐，三组标准库任务不再保留这项延期。

## 实际产品与验证范围

使用此前整体验收的同一组冻结 CLI、xl.dll、xlc.dll，无生产实现修改、
提供方替代或时区注入钩子。每个时区分别运行：

- xl.dll 和 xlc.dll 的 O0／O2 原生消费者，共四个配置。
- CLI JIT、编译器 DLL JIT、模块执行及可搬移独立 AOT，共四个配置。

两个语言夹具另经真实 CLI 生成 C，分别以 O0／O2 严格编译。独立 AOT
导入中没有 xl.dll／xlc.dll。原系统为 China Standard Time；相同夹具在
切换前必须因断言失败而拒绝，排除只编译不执行或未使用指定时区的假通过。

两组历史向量检查春季不存在的时间、秋季重复时间的默认拒绝及 earlier／later
选择、切换前后的一微秒边界、实际 UTC 偏移和往返精度。重复时刻分别相差
一小时和半小时。Windows 当前合同的 IsDST 为 -1，表示未知；实测验证偏移
和转换规则，不将 POSIX 专用的 0／1 标志当成 Windows 合同。

## 错误与资源

八个原生配置合计触发十六个真实逻辑分配失败点，覆盖 gap／fold 诊断构造；
各前缀运行至首次不命中，并确认下一个不命中点。非法 fold 参数使用静态
RangeError，单独确认零分配，不要求不分配的路径产生 OOM。

原生配置在真实计数清零前及退出时检查完整堆账本，均为分配释放相等、
无存活字节和对象、无非法释放、重复释放、UAF 或残留调用线程错误。
第一次一次性宿主对非法参数路径错误地要求发生分配，因而拒绝；核对静态
错误实现后修正了宿主断言并重测，产品代码未变，首轮证据保留。

## 系统恢复与维护约定

两次运行均由 finally 恢复原时区，另有独立隐藏进程监测父进程及恢复期限。
最终 China Standard Time 的动态时区键、偏移、转换规则和禁用标志均与原始
备份一致，独立进程复核通过；未调用修改系统时钟的接口。

依用户要求，本次不增加永久测试夹具、总门或回归开关。一次性程序、日志及
带输入摘要的结果保存在仓库外：

`D:/xlang-validation/stdlib53-b355-dst-once/attempt2/results.json`

该记录的 Complete、InputsUnchanged、WindowsDstSystemZoneAcceptance 和
TimezoneRestored 均为 true。旧 B354 报告保留当时延期状态，不改写历史。
这次补验不扩大为全仓 RC0 或任意未来时区规则更新的持续验证。
