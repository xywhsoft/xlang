# SlotMap 的原生键和值快照

SlotMap 原生底座新增独立的键、值快照，供后续公开语言方法和迭代接线使用。
它们复用 XRT 槽表迭代和 typed Array，不在 Cgen 中生成遍历、复制或存储实现。
本批仍不是 `SlotMap<T>` 公开 API 的完成声明。

## 类型和生命周期

值快照复制原表捕获的精确 Sequence 布局与独立拥有的准入元数据。
标量按值复制，字符串按精确字节长度复制；可变对象和容器保留引用身份，
Future 保留实际控制块，拥有型原生记录遵守其 Copy／Drop 合同。
快照保留集合结构，不承诺深复制可变子对象。

键快照保存完整实例记录与代际槽身份。键不拥有原表或元素；销毁原表后，
快照里的键仍可判等、装箱和释放。稀疏槽遍历采用供应方槽位顺序，
不承诺插入顺序。键和值的两个独立调用不代表同一时刻的成对快照；
公开成对迭代仍需要独立的原子配方。

## 构造与失败

整个复制过程持有原表的操作 pin，重入修改被 checked 拒绝。
结果在全部复制和清理成功后发布，失败释放所有已取得的拥有权，
原表保持不变。保留原有错误，独立识别无诊断失败；提前结束的供应方
迭代不能伪装成完整快照。

键的 schema witness 在成功和失败路径都被消耗，但从不原地填充。
其别名不能看到部分输出。拒绝非空 witness、错误元素／装箱身份、
错配角色和物理布局，以及冒用原表身份的键数组。
转换器是受信任 C 生产者提供的永久驻留元数据；共享 Sequence 边界
检查回调形状与 Context，不能把这个约束当作对任意 C 回调的沙箱认证。

## 按需组件

值快照留在已有 SlotMap 原生组件，复用捕获的策略，不选择键装箱、
键哈希或键数组工厂。键快照使用独立的 `SLOT_MAP_KEYS` 组件，
显式依赖原表与已有键准入工厂，不复制另一份键实现。

## 验证范围

冻结源码专项在 Windows／Linux 各通过 75 阶段、32 次完整分配失败
前缀及同操作重试。覆盖五种传输域、空表、稀疏复用代际、NUL／UTF-8、
销毁原表后的结果、schema 别名、错误身份、重入和无诊断失败。
三个实际编译的坏实现分别省略代际、装箱身份检查和完整迭代检查，均被检出。

值快照的独立 O0／O2 程序各执行 1000 轮，实际符号表排除键快照、
键装箱、键哈希和键数组工厂。Linux 对这些选定原生闭包使用 ASan／UBSan。
这不是发布 DLL／SO、完整 VFS 或整组 53 模块验收。

证据位于 `E:/xlang-validation/stdlib53-b212-*` 和 Linux
`/var/tmp/xlang-stdlib53-b212-*`。探索失败保留，不作为通过证据。
公开 SlotMap 构造／方法、成对迭代、统一 IR 接线及三组总验收继续；
对象池仍最后，CRT 未决策 0、XRT 未决策 19 组不变。
