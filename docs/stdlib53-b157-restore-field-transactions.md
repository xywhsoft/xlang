# 对象字段恢复事务

日期：2026-10-10。共享默认子对象仍按用户决定处理：仅通过声明的
clone 能力隔离，没有能力则 checked 拒绝。本批完成并同步 XRT 的
字段事务前置能力；它复制字段存储，不执行语言 clone，也不证明
现有 JSON/XLON 语言入口已经安全隔离共享默认对象。

## 先准备再统一发布

每份事务记录拥有实际接收者、独立观察外壳和准备值三个真实引用。
观察外壳持有原 backing；期间普通写入发生 COW 分离时，提交检查
能够拒绝失效观察，避免覆盖其他写入。准备和字段赋值不改变接收者。

提交在一次非阻塞 ownership freeze 内认证完整物理拥有图。事务记录
只有一个实际拥有句柄，不通过采样引用数制造根。调用者提供的内部槽
也必须是实际独立拥有引用，按 multiplicity 计数；未知 native 策略
在 Count/Trace 之前拒绝，不因此推断对象可复制。

所有记录的私有性、未变化观察和组合 Value 容器图全部通过后，才统一
交换准备好的存储。发布阶段没有分配、释放、生产者回调或可失败步骤。
共享接收者、共享析构 backing 或忙碌边界不写字段；输入错误、循环、
未知策略及 OOM 也在第一处接收者写入前结束。

有析构职责的对象保留实际 backing 和唯一职责，不制造替代析构接收者。
不同外壳指向同一析构 backing 时，组合图检查按实际 backing 跟随计划，
能拒绝自环及两个对象互相引用的环。普通 COW 别名保留旧 backing。

调用者在 freeze/mutation 外释放记录，依次退休旧字段、观察外壳和
实际接收者。旧值回调能够看到整批新状态；即使释放外部根，事务的
接收者引用仍覆盖回调尾部。清理保留最先出现的操作或退休错误。

## 专项验收

原生向量覆盖实际强引用、COW 别名、弱提升、native 游标、唯一析构职责、
失效观察、重复及二次提交、忙碌重试、长键与内嵌 NUL、组合容器环，
以及在外来 Trace 前拒绝未知参与者。退休回调检查整个批次已经提交，
且运行在 freeze/mutation 外；实际分配账本检查存活数、字节、释放数、
非法释放、重复释放和释放后访问。

四种连续分配失败模式分别是全流程字段替换、仅提交、长 NUL 键新增
和带析构职责的全流程。每次从零开始逐点注入，直到首次无命中成功，
关闭的前缀分别为 21、7、28、24，共 80 个；失败时两个原对象都不改变。
这不是任意选取几个失败点，也不把未关闭的前缀计为通过。

`tools/check_xrt_restore_fields.py` 编译两个实际嵌入产品及两种声明顺序，
采用 O0/O2；Linux 可进一步完整插装所选实现的 ASan/UBSan。可选原生
XRT 根执行既有模块化回归，复制的向量正文必须与该根相同。报告保留
全部输入、日志、产物哈希及原始命令，并核对未选择的嵌入头内容不变。

快照仅导入 `include/xrt/value.h` 和 `src/value/value_container.c` 的本次
差量，保留其他核心与扩展实现。同步器合并相邻差量的重叠上下文，
仍要求旧段或已应用新段精确匹配；8 项单元检查包含冲突拒绝和幂等。
五个原生函数进入声明头及原生符号表，不增加公开语言标准库函数。

最终双端报告共 44 个驱动阶段通过，20 次嵌入实现执行覆盖 1,600 个
完整分配失败前缀；另各执行 25 项实际模块化回归。Linux 四次完整所选
实现的 ASan/UBSan 执行通过。所有报告输入未变化，未选嵌入头内容与
上批快照一致；日志、可执行文件、模块对象及编译器输入均保留哈希。
三种 xlang/XRT 头包含顺序、快照及 3,647 个原生符号的一致性检查通过。
次数包含产品、声明顺序及优化模式重复，不是独立缺陷数。

Windows 报告为
`E:/xlang-validation/stdlib53-b157-fields-win-final6/results.json`，Linux 为
`/var/tmp/xlang-stdlib53-b157-fields-linux-final6/results.json`。代码来自
`stdlib53-b157-source-dev6` 的独立 Git index 快照；原生 XRT 来自
`stdlib53-b157-xrt-frozen2`，Windows 和 Linux 使用分离的构建目录。

## 仍需完成的语言接入

恢复控制器尚须统一暂存整图字段，并接上 XLIR 声明的 clone 调用；
clone 在 freeze 外运行，返回值按精确类型和完整拥有图再次认证。
返回 self、另一个共享全局对象或仍共享的待修改子对象，不能获得成功。
模块 owner 的活动边界、memo 的源实例独立引用、开放对象和泛型 class
持久化也仍须完成，之后才能切换 Cgen 的实际 JSON/XLON 恢复入口。

本批不是 AOT、发布 DLL/SO/SDK/VFS 或完整 53 模块验收。List/Set/Dict
语言载体、SlotMap、WaitQueue/Channel、OrderedMap 和产品总门仍在长期
任务内；19 个未决策 XRT 组不变，CRT 无未决策，对象池最后。
