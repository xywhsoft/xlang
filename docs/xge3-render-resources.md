# XGE 渲染资源接入：第一批

2026-11-09，原生版本 `c6a1d58ee2d44aa4d5999567fb5df7b5f55b2ea1`。
本批完成 CPU 存储和直接调用路径；不是整个渲染阶段或 GPU 验收的完成声明。

| 类型 | 新增能力 | 原生拥有关系 |
| --- | --- | --- |
| GpuBuffer | bytes/Buffer 创建、范围更新、上传、关闭 | 独占外壳；原生释放内部存储 |
| Mesh | Buffer 与类型化数组创建/更新、计数、绘制、关闭 | 独占外壳及复制的顶点/索引存储 |
| ShapeBatch | 创建、三角形/矩形入批、清空、提交、关闭 | 独占批存储 |
| SpriteBatch | 创建、纹理切换与保留、描述记录投影、清空、提交、关闭 | 原生批真正保留纹理 |
| Material | 颜色、混合状态、简式/完整绘制描述 | 沿用既有拥有策略；本批不公开借用 Shader 槽 |
| Texture | UV 变换/映射、绘制、上传排队 | 沿用原生共享记录拥有协议 |

业务入口都是声明，直接调用 XGE。新增头只实现冷路径的外壳销毁策略，并按资源
分开，避免引入一个类型时定义其他类型的销毁引用。公共头经 C11/C++17 严格编译。

Buffer 片段直接提供指针与长度，调用期保护仍存在；Mesh 原生会复制到自身存储。
`array<Vertex>` 使用通用值数组投影，需要快照和复制；不宣称该路径没有成本。
描述记录在 C 栈上构造，不经过逐字段动态装箱。原有视图的线程/到期检查和调用期
保护成本仍存在。200 次清空、三角形入批、预先创建的 bytes 更新循环，实测两种
链接方式的 XRT 分配次数均为零；这不代表初次创建、数组投影或真实 GPU 提交无分配。

接入时发现原生 Mesh 更新在分配失败时丢失旧数据、自身存储作为输入时可能先释放
再读取。已在 XGE 独立修复：先校验索引和长度，再完成两次分配/复制，最后提交。
Windows O0/O2、Linux O0/O2 的 ASan/UBSan 检查通过；原生提交见上述版本。

`tools/check_xge3_render_resources.py` 本次执行 15 项检查：两项夹具和一个新手示例
分别生成 C/头、JIT 运行、静态 AOT 构建/运行、检查 PE 导入。三个独立程序均不依赖
`xge3_host.dll`、`xl.dll` 或 `xlc.dll`。OOM 夹具覆盖四种构造各 32 个故障前缀及
Mesh 更新回滚，检查实际共享 XRT 的 live count/bytes 与错误计数。

完整证据在 `F:/xlang-validation/xge-full-20261109/render-suite-r1/`；小索引见
`dev/release-materials/provenance/xge-render-resources-20261109.json`。
原生库为最新修复源码重新构建；XRT 定点使用 xlang 的当前配套版本，未覆盖 XGE
仓库原有依赖。编译器仍是诊断替换构建，未更新正式 release 或 IDE。

尚待处理：引擎关闭时的外部 GPU 资源策略、Shader/Material 真实共享拥有、
RenderTarget 内嵌纹理的存储寿命、Pass 栈顺序及实际窗口/GPU 测试。无图形上下文
的绘制调用仅核对 ABI/清理路径，不能证明像素结果或跨引擎关闭安全。
