# JSON、JSONL、XLON、XLONL 标准库

这四个命名空间以 XRT 的同名模块为唯一编解码实现。XLON 是「xlang Object Notation」；本轮将原 XSON/XSONL 的模块、C 符号、特性宏、头文件和语言入口统一改名为 XLON/XLONL。此项是 API 命名迁移，不是线格式迁移；原有数据内容不因名称变化而重编码。

## 语言入口

| 命名空间 | 值类型 | 公开入口 |
|---|---|---|
| `json` | 单个 `var` 值 | `parse`、`valid`、`stringify`、`read`、`write`、`writeTo`、`visit`、`writer`、`quote`、`quoteTo` |
| `xlon` | 单个 `var` 值 | `parse`、`parseWith`、`valid`、`stringify`、`read`、`write`、`writeTo`、`visit`、`writer`、`options` |
| `jsonl` | `var` 记录序列 | `parse`、`valid`、`stringify`、`read`、`write`、`writeTo` |
| `xlonl` | `var` 记录序列 | `parse`、`valid`、`stringify`、`read`、`write`、`writeTo` |

四者的 `parse(text)`、`read(path)` 在失败时返回 `null`，`valid(text)` 返回布尔值；`stringify(value)` 返回文本，`write(path,value)` 返回布尔值。`jsonl`/`xlonl` 的 `parse/read` 返回可索引的动态记录序列，写出时每条记录占一行。单值格式的 `visit(text, visitor)` 返回 `visitComplete`、`visitStopped` 或 `visitInvalid`，回调接收动态事件表并以布尔值表示是否继续。

除旧有的简写参数外，四个命名空间的 `parse/valid/stringify/read/write` 均接受一个高级 `var` 选项字典。`writeTo(value, sink, options = null)` 不经中间完整字符串，XRT 将输出块交给 `sink: func(var) as bool`；回调参数是独立拥有的 `bytes` 动态值，返回 `false` 表示失败，抛出的语言异常继续传播。`json.quote(text, options = null)` 和 `json.quoteTo(text, sink, options = null)` 只执行 JSON 字符串引用与转义。`json/xlon.visit(text, visitor, options)` 将读取选项传给 XRT 事件访问器。

```xlang
var source = {"a": 1}
string text = json.stringify(source, {"pretty": true, "indent": 2})
assert json.parse(text)["a"] == 1
var records = jsonl.parse("{\"a\":1}\n")
assert jsonl.stringify(records) == "{\"a\":1}\n"
```

## 高级选项

选项可以省略或传 `null`，此时使用 XRT 初始化的严格、有限额默认值。未识别的键、错误类型与越界数字被拒绝；预算项传 `-1` 表示保持 XRT 默认值，并非无限制。

| 格式/方向 | 可用字段 |
|---|---|
| JSON 读取 | `comments`、`trailingComma`、`duplicate`、`bigInteger`、`maxDepth`、`maxInputBytes`、`maxStringBytes`、`maxValues`、`maxContainerItems` |
| JSON 写出 | `pretty`、`escapeSlash`、`escapeHtml`、`escapeNonAscii`、`containerCompat`、`nonFinite`、`unsupported`、`maxDepth`、`indent`、`maxOutputBytes` |
| XLON 读取 | 同 JSON 读取，另有 `maxDecodedBytes` |
| XLON 写出 | `pretty`、`escapeSlash`、`escapeHtml`、`escapeNonAscii`、`unsupported`、`maxDepth`、`indent`、`maxOutputBytes` |
| JSONL/XLONL 读取 | `record`（对应单条记录的 JSON/XLON 读取选项）、`rejectEmptyLines`、`maxInputBytes`、`maxRecords`、`maxTotalValues`；XLONL 另有 `maxTotalDecodedBytes` |
| JSONL/XLONL 写出 | `record`（对应单条记录的 JSON/XLON 写出选项）、`maxOutputBytes`、`maxRecords` |
| JSON 引用 | `escapeSlash`、`escapeHtml`、`escapeNonAscii` |

`duplicate` 是 0=拒绝、1=保留首项、2=以末项替换；`bigInteger` 是 0=拒绝、1=有损转浮点。JSON 写出的 `nonFinite` 为 0=拒绝、1=`null`、2=字符串；`unsupported` 为 0=拒绝、1=`null`、2=跳过。XLON 写出的 `unsupported` 为 0=拒绝、1=跳过。数字与 XRT 枚举保持精确对应，尚未引入第二套实现。

`valid(text, options)` 为保证重复键等 DOM 策略与 `parse(text, options)` 一致，会实际解析并释放临时值；无选项的 `valid(text)` 保持 XRT 快速验证路径。`parse/read/write/valid` 的高级重载均在选项不合法时抛出，语法、文件或写入失败仍分别返回 `null`/`false`，不会把上一次 XRT 错误遗留给下一个调用。

## 流式与 XLON 扩展值

`JsonWriter`、`XlonWriter` 以 native-backed class 管理 XRT 写入器生命周期。二者允许逐项写入并在 `finish()` 取得字符串；错误状态或未闭合容器返回空字符串。JSON 增加无符号整数写入；XLON 另支持无符号整数、`char`、`bytes`、时间、扩展标签，以及对象键/稀疏索引重载。`visit` 事件表包含类型、深度、键、索引、值和字节位置；XLON 自定义标签事件额外携带标签。

`xlon.parseWith(text, decoder, options = null)` 在解码自定义标签时调用 `decoder: func(var) as var`，传入 `{"tag": string, "payload": string}`；回调返回的动态值成为解析结果，回调抛错按原异常传播。手工编码标签可用 `XlonWriter.writeTag(...)`，不需要伪装成 JSON 字符串。`bytes` 与字符串都按实际长度进入 XRT，内嵌 NUL 不截断；文件路径仍是显式 C 字符串边界，不接受内嵌 NUL。

语言层的 `writeTo` 对应 XRT 一次性回调写出；`writer()` 对应 XRT 内存型增量写入器。XRT 的原生配置结构体、错误位置提取 helper、自定义值编码回调和回调型增量写入器不直接暴露为语言对象：目前相应语言外观分别由选项字典、访问事件位置、`writeTag` 与 `writeTo` 承担，不能把它们描述成逐个 C API 同形导出。
