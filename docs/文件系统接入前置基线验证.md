# 文件系统接入前置基线验证

日期：2026-09-30。用户明确批准先整理、验证并单独提交必要前置改动。
此前仓库 HEAD 仍是旧字符串 ABI，工作区已有双字段 string、char/bytes、
参数语法收缩和标准库接入实现。VFS 不能建立在旧 `char*` 长度推导之上。

## 纳入范围

- 编译器、XLIR、Cgen、语言运行时的 char/bytes 和双字段 string ABI 闭包；
  字符串参数、返回、存储、闭包及 Future 都必须使用同一物理表示。
- 为该编译器闭包所需的既有标准库注册、直接调用效果合同、结构化数据、
  随机、XID、IO/Console 声明和适配器；不是重新批准未决策库。
- XRT/xruntime 源码生成快照、公开声明与符号表，构建/打包清单和对应核心测试。
- XRT 所需的既有 IO/Console 支撑与 XSON -> XLON 命名同步单独提交；
  不纳入无关邮件、网络扩展库或 `release/extlibs` 的实现更新。
- 本次 VFS 的 19 项桥接合同、工厂、语言测试和公开实施记录另作后续提交，
  前置编译器导出不包含这些语言入口。

## 本轮修正的前置验证残留

旧 `xlir_string_bridge_abi_host.c` 仍用 `char*` 调用已经接收 `xstrview` 的函数，
已迁为显式视图；原始字节夹具明确提供 255 字节长度。
旧数学效果门以 hash 仍调用 `strlen` 为正确条件，已改为验证实际指针/长度，
不能因历史测试而恢复 NUL 截断行为。少量新增文件末尾空行已清理。

## 隔离验收

从待提交 index 导出源码，不依赖其他未提交扩展库，独立构建 `xl.dll/xlc.dll/xl.exe` 成功。
导出的标准库登记为 959 项（不含后续 VFS 4 个工厂）。本轮 Windows x64 实测：

- char/bytes ABI 门：严格生成 C、Unicode scalar、复制提交索引写、别名隔离、
  NUL、迭代、XValue/XLON、闭包/Future/generator、非法字面量及确定性 IR/C。
- string 桥接门：严格 C/JIT/AOT、并发只读拼接 2,000 轮、分配失败与账本平衡、
  UTF-8/原始字节遍历、语言失败边界及 C/xlang 范例一致性。
- CRT 直接调用门：41 个数学符号的 `no_raise/nonblocking` ABI、精确 C 输出指针，
  hash 不再借助 `strlen` 推导输入长度。
- IO/Console 门：严格 C/JIT/AOT、NUL/截断、Reader/Writer/Lines/Buffer/协议、
  EOF/UTF-8、4 个错误 ABI 负例、真实隐藏终端与 return/finally/error 模式恢复；
  高级 `file` 命名空间独立回归。
- XRT 的 IO/Console/JSON/JSONL/XLON/XLONL 10 个 suite，共 45 个 modular/single
  测试程序使用 `-Werror` 通过；公开结构 ABI 3 项检查通过。
- 从隔离 XRT 源码重新生成的 core/runtime 实现头、声明头及 feature 文件与
  待提交快照逐一一致。

这是文件系统接入所需的已验证前置基线，不是“全部语言/标准库已发布”结论。
完整发布门、Linux 宿主和未决策标准库仍按原清单继续，未把本轮有限回归冒充全量验收。
