# TaskGroup 的 Done 生产者关系

未完成的 Done Future 现在实际持有一份 TaskGroup 引用，拥有图直接枚举
这条生产者边。它与创建者、取消观察者和活动项的引用分别计数；终态
发布在通知等待者之前归还生产者权，不增加辅助节点或隐藏引用。

外部持有 Done 时，组及实际可达的资源保持存活。只释放 Done 观察
引用不会取消组；Close、Cancel 和 Destroy 的职责仍由组所有者承担。
组关闭且活动项归零时，Done 按原合同成功完成。构造失败完整回滚已
转移的生产者引用，并保留最初的内存错误。父令牌已取消而同步完成
构造的路径也只归还一次生产者权。

Future 准入需要明确登记原生生产者策略。未知身份拒绝且不改输出；
准备阶段不能把尚有生产者的 Done 当作普通端点提前关闭。基础图从
5 节点 7 边修正为 5 节点 8 边，单活动项为 8 节点 13 边，嵌套组为
11 节点 21 边。独立检查器在收集器加引用前核对真实计数和外部根。

`check_task_group_physical.py` 覆盖双消费单头、O0/O2、实际源码链接、
未知策略拒绝、生产者准备 BUSY、构造分配失败扫描和同步取消构造。
退役用例区分 32 个无根循环与 32 个外部 Done 保活场景；聚合器和
桥接句柄测试也使用新生产者的闭合集合，不省略真实边。

这一步修正物理图和 Future 准备条件。语言等待分析还需接入组的
关闭及活动项依赖，回调和 continuation 仍需正常执行 catch/finally；
完成协调前不能开启 TaskGroup 的全局循环准入。53 模块发布验收
继续推进，对象池仍留在最后。
