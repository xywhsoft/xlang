# WaitQueue 原生 MPMC 等待底座

WaitQueue 已建立独立的 typed MPMC 原生组件，复用队列的类型、拥有值
和图退役逻辑，并以条件变量提供等待和关闭唤醒。它不再需要把新的
原生实现建立在 Channel 数据通道上。本批完成原生底座验收；语言
WaitQueue 仍使用旧生成实现和 Into 接口，接线与清退必须继续完成。

## 传输与等待合同

底座直接使用 XRT typed MPMC queue。容量必须为正并遵守该队列的
容量规范，零容量报 checked 范围错误，不提供 Channel 会合语义。
队列不提供 reset 或批量操作。普通 MPMC 队列的提供方保持独立。

发布、接收谓词和 close 使用同一个 mutex，消除通知与入睡之间的
丢失唤醒。等待释放 mutex，也不持有拥有图 world mutation。
MPMC 表示多生产者、多消费者拓扑，并不宣称 WaitQueue 无锁；
try 模式不等待容量或元素，但可能等待内部 mutex。

接收具有 OK、EMPTY、CLOSED、TIMEOUT 四种正常状态。NULL 可空
元素的 OK 与无元素的 EMPTY 不混淆。输出是新鲜的私有取得槽，
不是语言 byref；成功直接移动拥有值，不在弹出后进行可失败复制。
checked 失败不发布正常 status；若移动已经发生，调用方仍负责
释放取得槽。成功入队后的通知失败同样必须报错，不能伪装为 FULL。

超时只构造一次单调截止时间，虚假唤醒不重新计时。超时返回前在
同一 mutex 下重查队列，所以已发布元素或 close 可以先于同时发生
的超时。close 广播唤醒等待者，保留队列内容供排空。

## 生命周期与清理

每个操作都有原生活动和引用 pin；图观察遇到活动状态直接拒绝，
不在 world freeze 下等待锁。最后一个语言包装引用丢失也不会让
仍在执行的接收访问已释放的原生对象。

内部 mutex 和 cond 使用现有 Sync 拥有对象，而不是丢弃销毁失败
的原始指针。队列图显式访问这两个真实 Value 边。物理清理失败
进入已有宿主 checked 恢复账本，可重试，不自动解锁、不 abort。
绝对截止等待只增加一个隐藏的原生组合函数，不扩展语言 Cond API。

## 验证结果

完整源码编译器在 Windows 由 325 个翻译单元构建，在 Linux 由
324 个构建。原生专项分别通过 55 和 72 阶段，包括：

- O0/O2 严格 C；每组四生产者和四消费者传输 1024 个整数，再
  独立传输 1024 个含 NUL 和 UTF-8 的字符串，逐项检查无重复和遗漏。
- 关闭与排空、空队列和零毫秒超时、错误输入、可空引用、Future
  拥有移动、直接自环及 Future 回指队列的循环图。重复 Future 边、
  真实外部 root 和缺少注册 policy 的 checked 拒绝均检查。
- 创建的 11 个实际分配失败点、字符串发送的一个实际失败点及
  两条首个无故障完成路径；O0/O2 均检查整个操作的分配平衡。
- 虚假唤醒保持截止时间、通知失败时已提交项仍可取得、内部 mutex
  清理失败的账本恢复，以及实际操作 pin 保活最后引用已丢失的对象。
- 三个已编译错误实现分别破坏 EMPTY 状态、通知错误传播和截止
  时间保持，均在实际执行中被拒绝。

Linux 对选定原生宿主及全部供应方进行 ASan/UBSan 检查，覆盖正常
传输、循环图、并发和分配失败前缀；逻辑故障注入另以 O0/O2 执行。
这不是完整运行时插桩或线程竞态检测。

真实按需计划选择 12 个 resident 提供方，不含 Channel 或普通
MpmcQueue 提供方；底层 typed MPMC 直接编入选定闭包。目录校验
为 286 个组件、1468 个精确导出，13 个拒绝控制通过。

## 仍需完成的接入

语言层必须接通 `(status, T?)` 拥有接收，移除 WaitQueue 的 Into
写回，并由 IR 明确类型、等待模式、超时、拥有和 checked 错误合同；
Cgen 仅装配该合同，不再保存模块回调或生成等待算法。
本批不标记 WaitQueue 公开接口、全部 53 模块或发布 DLL 完成。

三组批量回归使用同一完整源码编译器。独立 borrowed 原生 SSA、
工作线程与图 OOM、专用宿主汇总、嵌套编译器 SDK 和发布/VFS 总门
仍继续。CRT 未决策为零、XRT 其余 19 组保持未决策，对象池最后。

证据保存在 `E:/xlang-validation/stdlib53-b255-` 前缀下的
`native-{win,linux}-dev6`、`resident-{win,linux}-dev5`、
`discovery-{win,linux}-dev5` 和 `runtime-{win,linux}-dev5`。
提交前证书核对冻结源、产物和日志，不将未执行或失败项算作通过。
