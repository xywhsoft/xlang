# xlang DEMO6 命令行设计

本文档记录 DEMO6 的命令行口径。

## 1. 基本原则

DEMO6 依然使用 flex 和 lemon 作为词法/语法解析器。

命令行应服务于两个目标：

- 面向使用者：能直接运行脚本、编译 native 程序、参与 C 混编。
- 面向开发者：能清晰观察词法、语法、中间表示、C 代码生成等阶段，方便定位问题。

DEMO6 使用一个主入口 `xl.exe`，用子命令区分能力。阶段 dump 纳入 `xl.exe` 的统一命令口径，不再把主能力拆散到多个入口。

## 2. 统一四阶段编译管线

DEMO6 统一采用四阶段口径，不再同时维护“三阶段”和“四阶段”两套解释。

四个可观察阶段为：

```text
source.xl
  -> lex
  -> parse
  -> ir
  -> cgen
  -> tcc run/build
```

`ir` 阶段是 DEMO6 的正式阶段，不作为可有可无的兼容回退。它用于承载语言语义、控制流、异步/生成器、C 混编与后续优化的调试边界。

`check` 命令用于语义校验，可视为 parse 之后、ir 之前的诊断命令；它是便捷命令，不属于主四阶段之一。

## 3. 日常使用命令

### 按后缀分派输入

```bat
xl.exe run <file.xl|file.c|file.xlp> [-- <program-args>...]
xl.exe build <file.xl|file.c|file.xlp> [-o <output.exe|output.dll>] [--res file.json|file.xlon]
```

含义：

- `.xl` 按 xlang 源文件处理。
- `.c`、`.cc`、`.cpp`、`.cxx` 按 C 源文件处理，由内嵌 TCC 运行或编译。
- `.xlp` 按 xlang 工程文件处理，工程文件必须指定 `kind` 和 `entry`。
- 不做向上查找 `.xlp`，输入后缀决定行为。

### 运行 xlang 脚本

```bat
xl.exe run <file.xl|file.xlp> [--backend xlir] [-- <program-args>...]
```

含义：

- 将 xlang 作为脚本语言运行。
- xlang 输入只使用 XLIR；省略 `--backend` 与显式指定 `--backend xlir` 等价，其他值会被拒绝。
- 默认通过 TCC 内存编译路径执行。
- 适合开发期、嵌入式脚本、快速验证。
- `run` 只能运行 `kind: "exe"` 的 `.xlp`。

示例：

```bat
xl.exe run release\examples\hello.xl
xl.exe run tools\build.xl -- input.txt output.txt
```

### 编译 native 程序

```bat
xl.exe build <file.xl|file.xlp> [-o <output.exe|output.dll>] [--backend xlir] [--res file.json|file.xlon]
```

含义：

- 将 xlang 程序编译为 native 可执行程序。
- xlang 输入经已验证 XLIR 生成 C；无法接纳的语义在 lowering/verifier 阶段失败，不存在后端回退。
- 这是 TCC 支撑的核心目标之一。
- `.xlp` 的 `kind` 决定生成 exe 还是 dll；`kind: "dll"` 不需要额外 `--shared`。
- Windows 目标可通过 `--res file.json|file.xlon` 附加版本信息、图标和 manifest。编译器在内存中生成 COFF `.rsrc` 对象并挂载到动态 VFS，不生成磁盘 `.obj` 中间文件。

示例：

```bat
xl.exe build app.xl -o app.exe
xl.exe build app.xl --res app.res.json -o app.exe
xl.exe build app.xlp -o app.exe
xl.exe build lib.xlp -o lib.dll
```

### 工程文件 `.xlp`

第一版 `.xlp` 使用 JSON：

```json
{
  "format": "xlang-project-1",
  "kind": "exe",
  "entry": "src/main.xl",
  "cSources": ["src/native.c"],
  "resources": ["app.res.json"]
}
```

规则：

- `kind` 必须是 `exe` 或 `dll`。
- `entry` 必须是 `.xl` 文件。
- `cSources` 只接受 `.c`、`.cc`、`.cpp`、`.cxx`。
- `resources` 只接受 `.json` 或 `.xlon` 资源配置文件，当前用于 Windows 版本信息、图标和 manifest。
- 所有相对路径都相对 `.xlp` 所在目录。
- 第一版不支持 `.o/.obj`。
- `xl build app.xlp --shared` 与 `kind: "exe"` 冲突时直接报错。

### 只检查不运行

```bat
xl.exe check <file.xl>
```

含义：

- 执行词法、语法、语义检查。
- 不生成最终程序。
- 用于 CI、编辑器集成、重构期快速验证。

建议输出：

- 默认输出人类可读诊断。
- `--json` 输出机器可读诊断。

示例：

```bat
xl.exe check src\main.xl
xl.exe check src\main.xl --json
```

## 4. 阶段调试命令

### 词法阶段

```bat
xl.exe lex <file.xl> [--format text|json] [--emit <tokens.json>]
```

含义：

- 只运行 flex lexer。
- 输出 token 序列、位置、原始文本、字面量值、错误 token。

示例：

```bat
xl.exe lex src\main.xl
xl.exe lex src\main.xl --format json --emit dump\tokens.json
```

### 语法阶段

```bat
xl.exe parse <file.xl> [--format tree|json] [--emit <ast.json>]
```

含义：

- 运行 lexer + lemon parser。
- 输出 AST。
- 不做最终代码生成。

示例：

```bat
xl.exe parse src\main.xl
xl.exe parse src\main.xl --format json --emit dump\ast.json
```

### 中间表示阶段

```bat
xl.exe ir <file.xl> [--format text|json] [--emit <module.xlir>]
```

含义：

- 输出 DEMO6 的中间表示。
- 用于观察类型解析、控制流、函数调用、C 符号绑定、异步/生成器 lowering 等。
- 建议扩展名使用 `.xlir`。

示例：

```bat
xl.exe ir src\main.xl
xl.exe ir src\main.xl --emit dump\main.xlir
xl.exe ir src\main.xl --format json --emit dump\main.ir.json
```

### C 代码生成阶段

```bat
xl.exe cgen <file.xl> [--backend xlir] [--emit <output.c>] [--emit-header <output.h>] [--dump-dir <dir>]
```

含义：

- 输出 xlang 到 C 的生成结果。
- 不指定 `--backend` 等价于 `--backend xlir`；其他后端名会被拒绝。
- 用于检查 TCC 最终接收的 C 代码。
- 是 C 混编与 native 编译问题的关键调试入口。
- 当源码包含 C ABI export 时，可同时输出给 C 使用的 `.h` 头文件。

示例：

```bat
xl.exe cgen src\main.xl --emit dump\main.c
xl.exe cgen src\main.xl --emit dump\main.c --emit-header dump\main.h
xl.exe cgen src\main.xl --dump-dir dump
```

### ABI 信息输出

```bat
xl.exe abi <file.xl> [--json] [--emit <abi.json>]
```

含义：

- 输出模块 ABI 元信息、signature id、internal ABI symbol 和 C export symbol 的映射。
- 用于检查重载函数、泛型实例、class 方法、native-backed class extern 方法和 C ABI wrapper 的最终符号。
- 文本输出面向人工调试，`--json` 输出面向工具和测试。

示例：

```bat
xl.exe abi src\main.xl
xl.exe abi src\main.xl --json --emit dump\main.abi.json
```

## 5. C 混编相关命令

C 混编是 DEMO6 的核心能力之一，命令行需要直接支持 include path、library path、link library、load library。

### 运行/编译时传入 C 环境

```bat
xl.exe run <file.xl|file.xlp> --inc-path <dir> --lib-path <dir> --link <lib> --loadlib <dll>
xl.exe build <file.xl|file.xlp> [-o <output.exe>] [--res file.json|file.xlon] --inc-path <dir> --lib-path <dir> --link <lib>
xl.exe build <file.xl> -shared -o <output.dll> --emit-header <output.h>
```

示例：

```bat
xl.exe run demo.xl --inc-path D:\GIT\xrt\include --lib-path libs --link xrt
xl.exe build app.xl -o app.exe --inc-path include --lib-path lib --link user32
```

### 从 C 头文件生成/检查绑定

建议保留独立绑定命令：

```bat
xl.exe bind <header.h> --emit <binding.xl>
xl.exe bind-check <header.h>
```

含义：

- `bind` 从 C header 生成 xlang extern 声明。
- `bind-check` 只检查 header 是否能被当前绑定器理解。
- 第一阶段暂不实现 `bind` / `bind-check`，只保留命令口径。
- 第一阶段 C 混编先通过手写 `extern` / `export` 声明完成。

示例：

```bat
xl.exe bind D:\GIT\xrt\lib\xrt.h --emit std\xrt_binding.xl
xl.exe bind-check native\demo.h
```

DEMO6 主口径使用 `xl.exe bind`。是否继续生成独立 `xlbind.exe` 作为工具程序另行决定，但不作为 DEMO6 命令设计的主入口。

## 6. 调试器边界

首个发布版本不提供 `dbg`、`dap` 或独立 `xldbg.exe`。此前的 probe 与 DAP smoke 不能执行真实断点控制，也不能提供真实栈帧和变量，因此已从正式 CLI 删除，不能作为兼容命令或隐藏回退重新进入。

后续调试器必须完成真实被调试进程、暂停/恢复、调用栈、作用域、变量快照和 DAP 映射后，才可以重新设计公开命令。调试器仍不得进入 `xl.dll` 运行版。

## 7. 通用选项

建议所有阶段命令尽量支持同一组通用选项：

```text
--json                 输出 JSON 诊断或 JSON 结构
--format <name>        指定输出格式
--emit <path>          输出到指定文件
--dump-dir <dir>       输出多个调试文件到目录
--trace                输出编译管线 trace
--verbose              输出详细日志
--quiet                只输出错误
--inc-path <dir>       C include 搜索路径
--lib-path <dir>       C library 搜索路径
--link <lib>           链接库
--loadlib <path>       运行期加载动态库
--package-path <dir>   xlang 包搜索路径
--target <triple>      目标平台，第一阶段可先保留
--debug                生成调试信息
--release              release 编译模式
--keep-temp            保留临时文件
```

## 8. 与 DEMO5 的对应关系

DEMO5 中：

```bat
xl.exe run <file>
xl.exe build <file> --emit <path>
xl.exe run-c <file>
xl.exe build-c <file> --emit <path>
xldbg.exe lex <file>
xldbg.exe parse <file>
xldbg.exe sem <file>
xldbg.exe lower <file>
xldbg.exe cgen <file>
xldbg.exe dbg <file>
xldbg.exe dap
```

DEMO6 第一阶段对应为：

```bat
xl.exe run <file>
xl.exe build <file> [-o <path>]
xl.exe check <file>
xl.exe lex <file>
xl.exe parse <file>
xl.exe ir <file>
xl.exe cgen <file>
xl.exe abi <file>
```

首发版本不建立 `dbg`、`dap` 或独立 `xldbg.exe` 兼容入口。

DEMO6 不为这些 DEMO5 命令自动建立兼容回退。命名调整如下：

- `sem` 改为 `check`，更符合用户心智。
- `lower` 改为 `ir`，让中间表示成为正式可观察产物。
- `build --emit` 统一为 `build -o`，贴近常见编译器。
- `run-c/build-c` 不进入 DEMO6 主口径；相关能力由 `bind`、`run --link`、`build --link`、`cgen` 覆盖。

## 9. 推荐的帮助信息

```text
Usage:
  xl run <file.xl|file.c|file.xlp> [--backend xlir] [-- <args>...]
  xl build <file.xl|file.c|file.xlp> [-o <output.exe|output.dll>] [--backend xlir] [--res file.json|file.xlon]
  xl check <file.xl>

Inspect:
  xl lex <file.xl> [--format text|json]
  xl parse <file.xl> [--format tree|json]
  xl ir <file.xl> [--format text|json]
  xl cgen <file.xl> [--backend xlir] [--emit output.c]
  xl abi <file.xl> [--json]

C interop:
  xl run/build/cgen <file.xl|file.xlp> --inc-path <dir> --lib-path <dir> --link <lib>

Planned:
  xl bind <header.h> --emit binding.xl
  xl bind-check <header.h>

Debugger:
  not included in the first release
```
