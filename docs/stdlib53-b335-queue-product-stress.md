# 并发队列真实产品验收

SPSC、MPSC、MPMC 和 WaitQueue 的并发角色、拥有型传输与线程局部分配失败，
已在真实 runtime／compiler 动态库上验证。测试调用原生导出，不重新编译或
替换这些提供方，也不以源码编译器对象代替实际产品。

## 并发与数据合同

非阻塞队列使用同步起跑屏障，分别运行一生产一消费、四生产一消费、四生产
四消费。每种角色都覆盖整数／含 NUL 与 UTF-8 的字符串、单项／批量传输。
逐项标记检查无丢失或重复；单消费者场景同时检查每个生产者的 FIFO 顺序。
MPMC 不把调用返回后的外部记录顺序误认成队列内部的线性化顺序。

WaitQueue 使用四生产者和四个真实阻塞消费者，验证完整接收、关闭唤醒、
关闭后排空以及整数／精确长度字符串。拥有图、重复 Future 边、模式准入、
错误输出、活动操作 pin 和最后外部引用释放复用既有原生断言及完整堆账本。

每端 runtime／compiler 两份库分别以 O0／O2 编译原生观察程序，每配置重复
两轮，共 112 次传输场景、311,296 个唯一数据项。这里的优化级别属于观察
程序；被调用的是普通构建的原始动态库，不是改编译选项后替换的实现。

## 线程局部故障与清理

每端完成 104 条完整的一次性分配故障前缀，共 448 次真实失败、104 次成功
边界。每个失败点使用独立进程，避免前一个错误缓存或分配状态改变下一点。

| 前缀类别 | 每端数量 | 范围 |
|---|---:|---|
| 非阻塞队列 | 60 | 构造、单项／批量 push、Array 批量输入／拥有型输出 |
| WaitQueue | 8 | 构造、拥有型字符串发布 |
| 实际操作线程 | 36 | 三种非阻塞队列的单项／批量发布与拥有型输出 |

线程故障测试同时运行另一条独立队列的健康操作线程，核对 TLS 错误与失败点
隔离，并在 join 后检查角色交接、重试、已发布数量和精确文本。分配／释放、
活跃字节、无效释放、重复释放和 use-after-free 账本均平衡。

共享库内部调用不能通过调用方的链接器 `--wrap` 注入。因此产品模式明确禁用
旧 copy／partial／diagnostic 包装，只声明真实分配失败覆盖；旧源码闭包的
这些拒绝控制仍保留。调度器启动／收尾及所有线程的同时分配故障不在本矩阵内。

## 语言路径与按需组件

四个公开程序分别覆盖 SpscQueue、MpscQueue、MpmcQueue、WaitQueue；每端
通过无源码目录的 JIT、模块、独立 AOT 和迁移后执行，保存 C 在 O0／O2
严格编译。迁移程序不依赖 xl／xlc 动态库，Linux 不带 RPATH／RUNPATH。

Linux 真实编译器 SO 的 artifact plan 对四个程序逐一核对：只选择本族队列
提供方，不引入其他队列族或 Channel。Windows 的该项不以源码对象或 TCC
空符号表替代，跨平台功能与原生库调用则都实际运行。

314 项，AOT 正例各 313 项；两种清单分别保留 7／8 项专用宿主要求，并各有
