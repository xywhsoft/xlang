## 一、deferred-platform（36 个）—— 按处置路径再分类

### A. 编解码架构改造候选（10 个）

六轮批次验证过的模式：协议编解码下沉 C 层离线可测，连接走标准库
tcp/udp。与 redis/ntp/socks/modbus/mqtt/memcached 同族，协议本身不依赖
外部状态：

| 库 | 协议 | 难度 | 备注 |
| --- | --- | --- | --- |
| `ftp` | 文本命令 + 数据通道 | 中 | 控制连接可完整离线测试；被动模式数据通道需真连接 |
| `nats` | 文本 INFO/PUB/SUB | 低 | 协议极简，最优先 |
| `nsq` | 文本 + 4 字节帧长 | 低 | |
| `mdns` | DNS 组播报文 | 中 | 查询/响应报文可离线构造 |
| `snmp` | BER 编码 | 中 | GET/GETNEXT/SET 报文可离线往返 |
| `ldap` | BER 编码 | 中高 | 绑定/搜索报文可离线；schema 复杂 |
| `coap` | 二进制紧凑头 + CBOR | 中 | RFC 7252，报文构造清晰 |
| `enet` | UDP 可靠传输 | 中高 | 自有协议栈，帧可离线 |
| `zeromq` | ZMTP 帧 | 中 | ZMTP 3.0 帧解析可离线；拓扑语义需真端点 |
| `opentelemetry` | OTLP（gRPC/HTTP） | 中 | 走 HTTP/JSON 变体可离线编码 |

### B. 平台门禁收编候选（9 个）

与已收编的 clipboard/com/daemon 同族——本机桌面会话或设备即可验证，
无外部服务：

`op`（Win32 自动化，纯 user32/gdi32，最大缺口）、`procps`（Linux /proc，
Windows 门禁下跳过或双平台）、`portaudio`（音频设备回环）、`pcap`
（网络接口权限）、`canbus`、`gpio`、`libusb`（硬件在场或模拟器）、
`webview`（WebView2 运行时）、`passkey`（认证器/TPM）

### C. 真外部服务/凭据（15 个，维持暂缓）

`acme`（CA 验签）、`clickhouse`、`docker`（daemon）、`etcd`、`minio`、
`neo4j`、`prometheus`（被采集方）、`vault`、`volc.phone`、`volc.sts`
（云凭据）、`rtmp`（推流服务器）、`upnp`（路由器）、`sciter`（商业
SDK）、`ssh`（需 openssh-server，可容器化后转 A 类）、`git`（依赖外部
git 二进制，非协议库）

### D. 实为模型/权重依赖

`clip` 依赖 CLIP 多模态模型权重，建议继续采用 `deferred-large` 口径。
原 `xbot.all` 已随完整自动化层迁至 `dev/deferred/xbot.full`，不再计入活动
发布扩展清单；`xbot` 只保留稳定核心模型，`xbot.agent` 独立发布。

## 二、deferred-large（52 个）—— 按依赖性质分组

### 数据库与存储客户端（9 个）
`duckdb`、`mongodb`、`mysql`、`postgresql`、`rocksdb`、`leveldb`、
`lmdb`、`tdengine`、`influxdb`

> postgresql/mysql 若纳入计划，走 A 类编解码架构（协议离线可测）+
> 容器化门禁；嵌入式 KV（rocksdb/leveldb/lmdb）受 vendor 体量限制维持暂缓。

### AI/推理/向量化（17 个）
`embeddings`、`faiss`、`ggml`、`libtorch`、`llama`、`mnn`、`ncnn`、
`openvino`、`stablediffusion`、`tensorrt`、`whisper`、`libsvm`、
`sentencepiece`、`tokenizers`、`vectordb`、`hnswlib`、`dataframe`

> onnxruntime + xbot 已覆盖在线推理主线；tokenizers/sentencepiece 若
> 需要离线分词可评估纯算法实现（预算内）。

### 媒体编解码（4 个）
`ffmpeg`、`opus`、`sox`、`libsndfile`

### 图形/字体/GUI 栈（5 个）
`freetype`、`glad`、`harfbuzz`、`imgui`、`ratatui`
> 受 Spec 排除条款约束：与 XGE 竞争的 GUI 库不纳入。`_xge_native`
> 已完成新 XRT ABI 迁移，后续工作是 XGE/XUI 真实后端与平台门禁。

### 文档与数据格式（7 个）
`docx`、`pdf`、`pdfium`、`pptx`、`xlsx`、`parquet`、`flatbuffers`

> `xlsx` 有组合路线（zip+xml 均已压实，类 epub），可纳入编解码批次。
> `flatbuffers`/`protobuf` 是纯 wire 格式，可走 A 类离线编解码。

### 文本/NLP（4 个）
`icu`、`jieba`、`treesitter`、`html5`

### 协议栈（3 个）
`grpc`、`quic`、`webrtc`
> 工程量大且 http/tcp/TLS 基座已由标准库覆盖，长期维持暂缓。

### 其他（3 个）
`kubernetes`（REST API 可容器化）、`rabbitmq`（AMQP 可离线编解码但
帧模型复杂）、`taglib`（音频元数据，依赖媒体解析）

`xws`

> XRT 侧 `xhttp`、`xws` 扩展产品已经完成模块化、裁剪、单头、文档、协议 fuzz
> 和 Windows/WSL 产品门禁；此处统计的占位仅指 xlang 高级语言包装。按当前范围，

> `xregex` 已完成 Windows/WSL JIT、AOT、C smoke 回归，正式进入
> phase1-verified，不再属于占位队列。

## 五、处置建议汇总（按优先级）

1. **A 类协议改造首波**：`nats` → `nsq` → `ftp`（协议最简，复用六轮
   成熟模板，每库约半天）
2. **xhttp/xws 语言包装延期**：保持 XRT 产品与快速路径门禁，不在本任务扩张非快速路径
3. **XGE/XUI 后端压实**：以真实渲染、输入和平台资源边界取代旧 ABI 迁移任务
4. **B 类平台收编**：`op` 最优先（自动化测试刚需，纯 Win32 无服务依赖）
5. **组合路线**：`xlsx`（zip+xml）、`flatbuffers`/`protobuf`（纯 wire 格式）
6. C 类真外部服务与 deferred-large 主体维持暂缓，等待真实需求驱动
