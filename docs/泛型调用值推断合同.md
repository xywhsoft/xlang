# 泛型调用的值类型与返回代入

日期：2026-10-20。修复五组标准库长期任务中复现的共用泛型可空基线，
不是 Channel 特例；生产修改仅在 IR lowering，不修改 Cgen 或运行时。

## 两个独立事实

泛型参数来自已经绑定的参数值，不能来自保存该值的较宽存储。
`Union? stored = value` 的 NAME 可以同时拥有 nullable 的 storageType 和
语义证明后的非空表达式类型。推断调用统一使用既有的
`xl6IrNodeMaterializedValueType`，与实际实参 materialization 保持一致。
命名／默认参数仍遵循 canonical CallSite 绑定，不按源码位置重新配对。

返回类型验证参数推断，不再作为第二次推断的输入：所有参数完成绑定后，
用实际特化声明的共用 substitution 代入 formal result，再要求精确 canonical
TypeId 等于语义调用结果。`T` 已经可空时 `T?` 与 `T` 相同，不剥下一层后
尝试把 `T` 重新绑定为不同类型；这也涵盖不同 nullable 物理表示。
async 先将公开的 `future<R>` 与 worker 的 `R` 分层，再验证同一代入结果。

这不是新增返回值上下文推断、隐式转换、嵌套可空语法或参数引用规则。
未能从参数求出具体类型仍拒绝。错误名义 union、缺失 nullable 层和错误
async 结果层也不能仅因 ABI 同宽而被接受。
