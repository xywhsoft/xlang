## 实现边界

- 21 个公开 API 保留简短 color 命名空间；C 核心、拥有字符串的薄桥和 XL 声明分开。
- C 核心由调用者提供输出缓冲；8 个文本桥返回独立的 XRT 字符串，语言侧显式接管。
  不再依赖可覆盖旧返回值的全局环形缓存，没有增加第二套内存或字符串设施。
- C 核心正常路径不分配，不保存可变共享状态。长度包含末尾 NUL；容量不足时报告
  XERR_RANGE，能写时置空输出；空指针/零容量报告 XERR_ARGUMENT。
- 普通无效颜色仍按公开约定返回 false、-1 或空串，和调用缓冲错误分开。
- 修正 HSV 饱和度/亮度在运算前的钳制；拒绝 NaN/Inf；有限色相归一化到 [0,360)。
- saturation/value/lightness 直接计算所需分量，不再计算随后丢弃的完整 HSL/HSV。
- toName 不把透明或半透明颜色误认为不透明命名色；fromName 使用有界 ASCII 匹配。
- RGB 混合不是线性光空间混合；normalize/mix 返回 RGB，luminance/contrast 忽略 alpha。
  这些范围已写进用户说明，没有把简单颜色工具宣传成完整 CSS 颜色解析器。

## 本轮验证

| 范围 | 实际结果 |
| --- | --- |
| Windows 门禁 | 47 个步骤通过，847 个输入前后哈希一致；另记一次正式 OOM 失败观察 |
| C 编译/单测 | GCC 16.1 严格警告；21 API、缓冲边界/别名、非有限数、无分配核心、8 个拥有结果的 OOM 路径 |
| 独立数值对照 | Windows/Linux 各 18320 项，不合并成独立用例数 |
| 命名色 | 冻结的 148 名/139 个不同 RGB 参考表；每名三种大小写及反向查询，共 592 项 |
| 并发 | 两平台各四工作线程共 8000 轮，检查保留结果、独立缓冲及线程局部错误 |
| xlang | 五个入口的源码 JIT、AOT、C 生成；输出一致；其中四个另与正式 JIT 对照 |
| C ABI | 21 个实际生成 extern 原型与 C 头共同编译；Windows LLP64、Linux LP64 |
| 双语输出 | XL 与 GCC/TCC C 的黄金输出一致；package C runner 通过 |
| DLL 宿主 | 正式 xl.dll、xlc.dll 各在宿主重复运行边界脚本三次；不含正式 OOM 通过结论 |
| 文档 | README、包内网站正文的两个 XL 代码块执行并验证输出 |
| Linux C | Ubuntu GCC 15.2，ASan/UBSan/float-cast-overflow/泄漏检查、双语对应的 C 范例及输入稳定性通过 |

数值对照由 Python colorsys、独立亮度公式和冻结命名表产生预期，不从被测 C 实现
复制结果。4568 个标量、4568 个精确往返、8592 个 HSL/HSV 转换、592 个命名查询。
HSL/HSV 分量量化仅容许一个字节的半舍入差异；往返和名称不放宽。

验证驱动为 `build/test/default-argument-20260928-source-v3/public_source.exe`。
它链接当前编译器源码并借用正式 DLL 的 TCC core，不等于重建后的完整 CLI/DLL/VFS。
门禁已核对驱动构建输入和独立产物资源，未关闭类型/所有权检查。

## 尚未完成

   分配失败，但没有捕获到异常。源码 JIT/AOT 同一用例通过。记录保留原始断言，
   没有把正式失败改为通过，也没有在包内吞错绕过共享编译器问题。

   单独的 C 测试通过不能证明语言内嵌 NUL 已正确保留。

   本地生成不等于线上部署，不把页面发布列为完成。
