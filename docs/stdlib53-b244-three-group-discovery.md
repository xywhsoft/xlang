# 三组声明检测与 Stack 原生子容器

系统、文本和容器的现有语言夹具已完成一次统一生成与严格 C 检查。
整批发现并修复了 Stack 对原生 Array 的过时拒绝规则，以及遗漏的
Dict 子容器准入。修复只调整统一 IR 的闭合构造合同；复用既有原生
配方、拥有存储和生成调用，不增加 Cgen 分支、库函数体或运行时组件。

## 整批发现与修复

首次双平台检测各尝试 287 个夹具，发现同样的两项失败。进程引号
夹具仍把 bytes 错误输出直接传给 string.trim，现改为显式 stderrText。
这项修正验证声明类型，不据此声称已运行该 Windows 发布 CLI 场景。

另一个旧拒绝夹具使用 Stack<array<int>>，本来用于防止 wire Array
冒充原生 Sequence。Array 的源生产者迁移后，这种源类型已经具备
完整配方；Stack 的额外合同却仍只接受 Stack 子项，继续拒绝 Array。
同一合同还遗漏了已登记的 Dict 引用域。现在分别核对完整 Array
配方和完整 Dict 构造合同，仍有递归深度上限，不按指针布局放行。

旧拒绝夹具改为包含 generator 的不可复制子域，在语义阶段精确
拒绝并保持输出为空。检测器显式登记这一负例的诊断，不把任意
编译错误或进程超时算作通过。其余失败均完整保留，独立分批尝试。

修复后双平台各检查 288 个夹具，共 575 个阶段：287 个正向夹具
通过生成与严格 C，一个已登记负例按预期拒绝。该范围按公开功能
夹具命名族选择，候选及实际选择列表均固定在报告中；它不是所有
公开函数的逐项覆盖，也不是所有这些夹具的运行或 53 模块总验收。
复测入口为 tools/discover_stdlib_three_groups.py。

## 子容器运行与失败清理

新增语言用例覆盖类字段默认 Stack、Array 和 Dict 的共享引用语义、
入栈后继续修改源、pop 后保留引用、独立批量结果、nullable Array、
多层 Array／Stack／Dict，以及提前返回后 finally 清空原容器。
包含 NUL、UTF-8 的 Dict 键和值仍按精确长度处理。

Windows 317、Linux 316 个完整源码编译单元通过。子容器专项分别
通过 500、532 个阶段，O0／O2 每端共 418 次完整调用线程分配位置
检查。失败后完整清理再成功重试，分配、释放、存活数量和字节平衡。
普通独立程序每个优化等级各执行 100 次模块生命周期。

三个 Array 域、两个 Dict 域及 31 项 IR 篡改通过核对；错误布局、
元素身份、槽 ABI、输送方式和子角色都被 IR、C／header 与原生计划
拒绝。恢复旧 Array 门或删掉 Dict 门的两个真实坏编译器，经编译
链接后均被验收拒绝，不仅是对日志做字符串判断。

实际原生闭包选择 28 个供应方，独立 C 不链接编译器或 MODULE_ALL。
公共 JIT、module 和实际 AOT 通过，Linux ASan／UBSan 插桩覆盖全部
选定供应方。既有九个动态与静态容器回归每端通过 156 个阶段，
包含实际 JIT／AOT、同步分配前缀、外部侧车和独立产物导入核对。
常驻目录保持 278 个组件、1437 个真实导出及 13 个拒绝对照。
专项入口为 tools/check_stdlib_stack_native_children.py。
