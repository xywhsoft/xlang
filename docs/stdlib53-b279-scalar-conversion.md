# 动态标量装箱与 float32 显式转换

`float32(var)`、`float32(string)` 和普通 `float64`／`c_double` 的缩窄
使用独立的 XLIR 转换合同。动态调用也允许直接装箱 `float32` 和现有
C 标量／type profile，不要求用户先赋给中间 `var`。

## 转换与投影

2026-10-14 确定的显式缩窄规则是正常舍入、有限值越界抛
`RangeError`、保留 NaN 与正负 Infinity。负零和次正规数保持目标
浮点格式的语义。typed callable 和容器的 float32 读取仍要求无损；
显式转换的宽松规则不进入投影。本批不扩展 `as float32` 的准入。

动态转换复用 XRT 的读取与显式标量转换；64 位整数直接转换为
目标 float，避免先经过 double 带来的二次舍入。动态 string 和静态 string 则直接
借用完整 `xstrview`，经 XRT 数字解析后缩窄。内嵌 NUL 不截断，
语法错误映射为 `ValueError`。bytes 与非标量不会被当作文本解析。
现有 C profile 的动态装箱保留原始身份；这不表示已新增所有
C profile 到其他数值类型的动态转换。

## 生成代码与生命周期

XLIR 分别保存 string、动态 Value、double 来源的转换操作，校验
来源类型、目标类型、按值或借入参数以及错误合同。Cgen 只发出
对应的物理函数调用和成功状态判断，不追溯调用名称选择语义。

驻留函数只在成功时写入输出。成功状态独立于返回数值和诊断对象，
所以零值不是失败，诊断无法分配也不会被当作成功。临时 string／
Value 在成功和异常路径都释放；诊断清理保留第一个失败。

三个转换入口归属独立 `FLOAT_CONVERT` 组件。未使用转换的程序
不会引入该组件；生成 C 不包含完整解析／转换实现。

## 验收范围

专项覆盖源码构建、严格 C O0/O2、JIT、checked module、独立 AOT，
并检查 IR 损坏在 C／头文件输出前拒绝、丢失成功状态的生成 C
反例、诊断分配故障前缀和裁剪。Linux 对生成 C／宿主及本批转换
实现进行 ASan／UBSan 插桩，链接的其他编译器与 XRT 提供方不在
该插桩范围内。GCC 关闭调试变量赋值跟踪，保留 O2 和 sanitizer。

这项专项不关闭完整容器转换、其他动态／Native 编解码组合、
工作线程与对象图故障、模块组合、真实卸载，以及 CLI／DLL／VFS
发布总验收。WaitQueue 保持 MPMC 与 `(status, T?)` 拥有接收合同，
对象池仍在最后；CRT 无未决策，XRT 19 组不变。

驻留导出目录总门另有五个既有 Stack／Sequence 符号未登记，旧源码
基线与本批候选得到相同结果，仍需收口；float32 专项不替代该总门。
