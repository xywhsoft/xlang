## 本批实现

- 增量编码器/解码器统一状态和错误处理，补齐累计计数、成员边界、drain、finish、
  输出移交、低内存解码以及终态/可恢复参数错误的区别。
- 字符串按 UTF-8 字节长度传递；原生声明使用物理 C 类型，23 个实际 cgen 原型
  与公共头同编译验证，不以强制转换掩盖宽度冲突。
- Reader/Writer 保持借用所有权，处理短读短写、未知总长、已定位 reader、回调
  取消/异常、最终通知取消和同对象 writer 重入。
- `xrt_bz2_file.c` 提供 C 可直接调用的压缩/解压文件事务。临时文件与目标同目录，
  关闭 reader/writer 后再提交，支持源目标同路径，保留首个错误与已有目标。
  `overwrite=false` 覆盖目标在最终通知期间被其他写者创建的竞争场景。
- 两组 C/XL 对照范例覆盖 UTF-8/二进制/增量/损坏输入，以及文件/进度/取消/目标
  保留；输出由黄金文件比较。重写旧教程中不准确的错误分类和临时目录写法。
- 补齐包 README、维护型官网正文，登记进 featured 专项门禁。官网仅完成本地
  文件生成、哈希一致与相对链接检查，不声称已远程部署或经过浏览器视觉验收。

## 共享 XRT 缺陷

`xrtFileOpen` 原先先调用系统创建/截断文件，再通过 `__xrtFileTakeNativePair`
分配文件对象。后一步失败会关闭 OS 句柄，但文件已经创建/截断；`xrtFileTemp`
无法返回路径，调用者也无法清理。Windows/POSIX 都有这一分配顺序问题。

上游 `D:/GIT/xrt/src/fs/file.c` 改为先分配对象，再打开系统文件，并共用无分配
的句柄初始化。失败时释放预分配对象；公开 API、ABI 和成功路径语义不变。
新增 `tests/file/test_file_open_allocation.c`，通过逻辑分配注入测试临时创建和
已有文件截断，并接入模块清单。普通路径的对象 OOM 保证已写入上游 File API。
上游单头文件已重新生成且 `tools/amalgamate.py --check` 通过。

隔离验证没有整包升级 XRT：从冻结头中严格匹配且仅匹配一次旧 `src/fs/file.c`
正文，替换为当前修复正文。只统一换行、移除内部 include，其余全部保留。
`lib/xruntime/xruntime.h` 自带完整 XRT 实现，所以隔离目录中的两份头都必须
替换此片段；仅更改隔离 xrt.h 不能证明 XRUNTIME_IMPLEMENTATION 已用到修复。
确切基准 commit、源文件与两组头哈希见回移元数据。

## 待收口

1. 在固定源码版本上安排正式 XRT/xruntime 同步及发布 EXE/DLL 重建，不擅自把
   上游全部开发中改动复制进来。然后用默认门禁验收，不再使用隔离覆盖参数。
2. `gzip_native.c` 和 `brotli_native.c` 同样调用 `xrtFileTemp`。本缺陷影响它们的
   晚期 OOM 保证；原有常规取消/目标保护证据仍保留，但必须补同类文件故障注入，
   不能维持“所有失败条件下无残留”的绝对表述。
3. 静态审查发现 `file_root_posix.c:199`、`file_root_windows.c:481` 的 root-relative
   打开仍在 OS 打开后分配包装对象。本批没有改动和实测这些入口，记录为待验证
   的同类风险；需分别覆盖创建、截断、链接/根边界、句柄接管和内存失败。
4. 既有 XLIR return-through-finally/container cleanup 失败探针仍独立保留。
   BZ2 通过不代表该编译器边界已修复，不关闭验证器或添加库专用编译绕行。
