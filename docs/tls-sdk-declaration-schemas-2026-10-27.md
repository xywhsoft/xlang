# TLS SDK 声明字段表闭合

普通产品的私有 SDK/VFS 验收发现：两个 TLS 私有头包含 `.inc` 字段表，
但 SDK 只自动收集声明头，导致离开源码树后字段表缺失。这是打包缺陷，
不是 TLS 算法、语言接口或拥有权语义需要变化。

修复采用单一声明源：两份字段表改为带 include guard 的 `.h` 宏列表，
调用点显式展开。内部布局、驻留声明、公开符号、标准库与 IR 合同仍共享
同一份字段顺序和类型。没有复制字段表、嵌入实现 `.inc`、放宽打包检查，
也没有扩大 VFS 的实现源码范围。

`tools/check_tls_sdk_fields.py` 用原冻结源码中的旧字段表建立显式 A/B 对照，
只回退本次字段表改动，不回退其他工作区内容。9 个真实编译单元分别以
GCC O0/O2 编译旧、新两版。Windows 与 Linux 各 18 对对象文件逐字节相等，
保留完整命令、日志、输入及输出哈希。该证据证明本次声明变换没有改变
这些布局、函数、注册或 IR 的编译结果，不代表完整产品验收已经完成。

证据目录：`F:/xlang-validation/five-groups-20261027/p7-shipping/` 下的
`sdk-fields-win-r1` 与 Linux 同批 `sdk-fields-linux-r1`；分别有独立重读证明。
原 `build-*-r1` 产品保留为失败基线，不向其补拷贝头文件。
新的普通构建仍需重新生成两种 VFS 并通过原 SDK 闭合检查及实际语言用例，
通过后才能将本项产品验收标为完成。
