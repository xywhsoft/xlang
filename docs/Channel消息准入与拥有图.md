# Channel 消息准入、递归编码与拥有图

日期：2026-10-20。属于五组长期任务的 P0/P1，共用层修复，不是整组封板。
生产修改仅为 SEM、canonical IR 和 Channel value plan；没有修改 Cgen、
驻留运行时或 XRT，也没有向生成 C 加入消息、回收、同步或分配算法。

## 语言值合法性与执行许可分层

消息遵循已有的语言值复制／对象共享规则，与函数结果能力保持一致。
不再扫描类字段并使用“只有扁平标量类才可发送”的旧白名单。泛型类、
继承视图、协议值、复合对象和容器不会因为来源语法不同而被人为排除；
泛型工厂与直接构造使用相同的规则。

这不是允许任意指针作为消息。具体实例仍须闭合 canonical schema、逻辑
元素、物理槽、codec、复制／释放和名义准入集合；模板本身没有执行许可。
例如 generator 虽可作为语言结果，但目前没有 Channel 消息槽，其构造仍
在输出 C 前被拒绝。共享对象不等于共享调用者变量，也不自动为可变字段
或捕获加锁；本批没有引入 byref、借用语法或新的线程安全保证。

Channel 方法的接收者复用普通成员调用的 flow-proven 类型选择。
`if optional != null` 后使用的是已证明的非空值，而非 NAME 较宽的可空
声明。缺少非空证明的接收者仍被拒绝，不用 Cgen 特判或裸指针转换绕行。

## 嵌套资源保留同一证明

嵌套 Channel 引用递归验证实际子 Channel 的消息合同，不再无条件限制其
叶子为 DIRECT。因此闭包、union、可空 union 可以通过两层／三层 Channel
传递；外层仍传递拥有的 Channel 引用，不把叶子的语言槽当作 xvalue 槽。

递归 construction recipe 与纯 representation description 分开：前者使用
一个深度预算闭合依赖，后者只证明已闭合 schema 的逻辑／物理表示，不重新
从零启动递归。根 Channel、原生调用、嵌套资源共用同一表示证明。已有的
SlotMap DIRECT 限制没有顺带放宽；错误 schema、codec、slot、循环类型事实
和损坏的名义集合都不能因指针宽度相同获得许可。

## 真正的循环回收边界

当前语言不承诺普通作用域退出时立即回收循环。真实宿主测试创建三种闭环：
Channel → 对象 → Channel、对象的 Array 元素回边、以及闭包捕获回边。
不手动清除边，不用模拟图或伪造引用计数代替真实语言对象。

宿主通过公开 API 编译、激活和销毁模块，验证：

- 外部 `xrtValueRetain` 是真实根；存在该根时不提前调用任何对象析构。
- 释放外部根后，checked 模块退役完成三种对象各一次的析构。
- 析构抛错时 `.ok` 与 `.ready` 分别处理；失败可先被交付，保留计划再重试，
  不假定首次失败就已完成，也不重复已经完成的析构。
- 每轮完整生命周期的 LiveCount／LiveBytes 精确恢复。仅在隔离进程开始时
  开启调试；先用不含消息的简单语言程序预热公用编译器／原生加载器，
  不把其惰性进程缓存算成消息泄漏，不按固定字节数豁免未知分配。

独立 AOT 另验证在进程退出前完成三个不同对象的析构。纯 CRT 观察器通过
已有源包 manifest 声明 `xrtModules: []`；没有以未声明的额外 C 源强制选入
完整运行库后冒称裁剪通过，也没有修改该保守 FFI 回退合同。

## 验证入口及范围

`tools/check_stdlib_channel_message_graphs.py` 冻结完整源码编译器、头、对象、
驱动、工具、测试／manifest、日志与产物。四个常规专项涵盖泛型／复合／
继承／协议、Array/List/Dict/Set/Stack/SlotMap、嵌套 codec 及真实生产线程
退出后的独立接收；检查严格 C O0/O2、JIT、module 和独立 AOT。
循环程序另有严格 C、AOT、公开宿主及精确账本检查；16 个常规回归保留
原编码／分配失败／TaskPool／泛型验证，两项未支持／无非空证明的负例保留。

独立 C 合同的每种优化验证 19 个实际 Channel owner、4 个嵌套域和 6 个名义
域，拒绝 86 个无效 IR 变体，执行 172 次 C/header 零输出拒绝；计划输出在
拒绝时保持不变。宿主的每种优化分别完成 4 次退役、12 个实际对象析构，
覆盖有／无外部根以及有／无析构异常。

旧 signal gate 的两项历史拒绝改为有内容断言的正例；脚本语法和所迁移的
正例在本轮验证，但没有重跑整个 signal 发布专项，不能扩大其验收范围。
证据根为 `F:/xlang-validation/five-groups-20261020/p1-channel-message-graphs/`。
发现期失败／局部对象替换不计为正式验收，不替换 release 或推送。

最终完整源码构建为 `source-win-r1` 624 单元与 `source-linux-r1` 623 单元；
正式报告为 `language-win-r2/results.json`／`language-linux-r1/results.json`，
各 80 阶段，共 160 阶段通过（其中每端两项预期拒绝）。输入、日志和产物
哈希复核一致。Windows 首次整轮在发现观察器的未声明 C 依赖后未通过裁剪，
其 38 阶段不计入最终结果；没有跳过裁剪断言或复用失败轮次作成功证据。

本项不代表所有 P0/P1、新 shipping DLL/SO/VFS 或五组目标完成。继续其余
