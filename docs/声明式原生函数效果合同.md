# 声明式原生函数效果合同

更新日期：2026-09-22

## 目标

标准库和普通 C FFI 使用同一套声明语义。函数效果必须由 `extern` 声明进入
AST 和 XLIR；Cgen 只消费已验证的 Lowered XLIR，不按函数名猜测，也不维护
标准库特例。

```xlang
extern "fabs" @pure @no_raise @nonblocking func nativeAbs(float value) as float
```

未写合同的 `extern` 保持保守默认：副作用未知、可能产生 xlang 错误、可能阻塞。
三个合同彼此独立，不允许由其中一个推导另外两个。

## 合同语义

- `@no_raise`：调用不会建立或传播 xlang/XRT 错误。Lowered XLIR 使用
  `errors=no-raise/none`，Cgen 不生成 foreign error scope 和 `ERROR_TEST`。
- `@nonblocking`：调用不会等待外部事件或执行无界阻塞。XLIR 使用
  `execution=foreign-nonblocking`；它不表示纯，也不表示不会失败。
- `@pure`：结果只依赖显式输入，并且不修改语言可观察状态。XLIR 使用
  `effect=pure`。当前优化器不会仅凭该字段折叠、删除或重排 C 调用；在
  `errno`、浮点环境和其他 ambient state 被统一建模前，这个限制必须保留。

FFI 声明是调用方对原生实现作出的 ABI 承诺。原生函数违反已声明合同时，属于
FFI 合同违约，编译器不为其补回运行时探测。

## 编译链

1. Parser 只在 `extern "symbol"` 与 `func` 之间接受三个固定注解；未知注解报错。
2. AST 以独立 flag 保存三个事实，普通 AST 到 Typed XLIR 的复制不得丢失它们。
3. CallTarget 分别保存 side effect、failure ABI 和 execution boundary；lowering
   只在精确的 `XL6_AST_EXTERN_FUNC` 声明上采信合同。
4. XLIR verifier 从声明重新计算预期合同，拒绝声明、CallTarget 和物理错误 ABI
   不一致的模块。
5. Cgen 不读取 AST 和标准库表。`no-raise/none` 自然选择直接 C 调用；保守目标
   仍生成 foreign error scope。

## 当前标准库接入

现阶段 `XL6_StdlibForeignContract` 是生成标准库 `extern` 源码的过渡声明目录。
它只负责写出同样的源码注解，未评审函数不会继承任何乐观默认。标准库迁移到
正式 xlang 模块后，合同应直接写在模块声明中，编译链无需改变。

首批审计结果：

- `math.sin`：`@no_raise @nonblocking`。生成 C 是直接 `sin` 调用；暂不声明
  `pure`，因为 C `errno/fenv` 尚未纳入 xlang 效果模型。
- `math.abs(float)` / `fabs`：`@pure @no_raise @nonblocking`。
- 其他现有入口：维持保守默认，等待逐项标准库评审。

典型输出保持为普通 C 标量：

```c
extern double sin(double);
double value;
value = sin(argument);
```

不会出现 xvalue 装箱、标准库转接函数或针对 `sin` 的 Cgen 分支。

## 验收

`tools/check_xlir_foreign_effect_contract.ps1` 同时验证：

- 三个合同从声明进入 Lowered XLIR；
- `math.sin` 和 `fabs` 生成直接标量 C 调用；
- 未标注的 `cos` 仍保留保守合同和唯一 foreign error scope；
- 未知效果注解被 parser 拒绝。
