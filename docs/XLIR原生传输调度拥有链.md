# XLIR 原生传输调度拥有链

2026-09-20，v225 候选。在 v224 显式回调绑定之上，继续补齐调度器实际持有的
传输对象引用，不把普通引用或 RuntimeHeld 自动解释为队列/Timer 的拥有槽。

TCP Stream、Listener 启动命令取得独立引用；TCP/UDP 控制命令、Future 唤醒、
Listener 关闭及连接/接受重试 Timer 将现有引用在成功受理后转移给调度器。
失败只回退本次引用；成功任务由调度器在回调或丢弃之后唯一释放，移除各回调
出口重复承担的释放职责。同一对象的 Port、任务、Timer、Future 唤醒使用同一
物理 Ops 身份，Count 读取真实 RC，完整 Trace 尚未建立时继续明确拒绝。

持久测试读取实际队列和 Timer，检查出队前的拥有策略、真实计数、嵌入槽在回调
前清空，以及回调释放创建者引用之后调度器仍持有对象。通过真实关闭 Future
覆盖 TCP/UDP 唤醒路径；每个受理的测试任务/Timer 回调和 Drop 均只执行一次。
单头测试额外进入实际 Listener 重试调度函数并经公开 Close 取消；不将此宣称
为操作系统资源耗尽触发路径已经验证。

首轮相关旧回归保持通过。新测试发现自己的 Stop 时序早于 Worker 最后清理：
Close 通知尚不能证明 Future 与调度器已经释放。修复使用串行 Worker 栅栏和
零 LiveObjects 断言，保留原失败证据，不放松精确内存平衡。最终验收以本批
checkpoint 为准，定向结果不能替代扩展回归。
