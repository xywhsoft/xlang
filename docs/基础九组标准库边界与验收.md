# 基础九组标准库边界与验收

日期：2026-10-29。用户批准最后九组的分层方案；它们不等于九套新库。
本轮不改参数语义、不添加借用、不重建错误模型，不重新包装 XRT 算法。

## 系统查询

```xl
string system = os.platform()
string architecture = os.architecture()
int pointerWidth = os.pointerBits()
bool littleEndian = os.littleEndian()
int processors = os.logicalProcessorCount()
```

以上查询描述**实际执行当前代码的进程及其运行环境**。例如 x86 进程在
x64 系统运行时，architecture 为 x86、pointerBits 为 32；不能据此推断
宿主内核架构。platform 使用 windows/linux/macos/freebsd/unknown；
architecture 使用 x86/x86_64/arm/arm64/riscv64/ppc64/s390x/unknown。
`unknown` 是诚实的未识别值，不冒充支持保证。逻辑处理器数是系统在线
数量，不承诺等于 affinity、容器 quota 或调度器默认线程数。查询失败
为 checked 错误，不静默猜测 1。

`platform` 从旧 point → C string 接管包装改为直接拥有的双字段 string。
字符串查询每次有一份结果分配；数值查询不装箱、不分配。Cgen 仅发出调用。

## 显式内存诊断

```xl
import memory
memory.enableStats(true)
MemoryStats counters = memory.stats()
MemoryDebugSnapshot allocations = memory.debugSnapshot()
string report = memory.reportJson() // 默认最多 16 MiB
memory.enableStats(false)
```

`statsEnabled/enableStats/resetStats/stats` 直接复用进程级 XRT 统计。
改变 enable/reset 会影响同进程的其他使用者，应由应用或宿主统一协调。
统计快照提供全部 API 请求、块、池、backing 流量计数和 64 个尺寸类的
`classCalls/classBytes`；索引必须在 0..classCount-1，否则 RangeError。

`debugEnabled/debugSnapshot/reportText/reportJson` 是只读诊断。调试是否
启用由产品配置及宿主决定；语言不在已有分配时切换调试器、不开放地址操作、
借用 File 指针或故障注入。报告可含原生格式化的诊断地址，不交付可操作的 point。
关闭调试时快照的 enabled 明确为 false。
报告输出上限可显式传入，负数或超限 checked 拒绝，不交付半个报告。
原生报告算法、事件环和捕获的一致性均由 XRT 承担。

两类快照先取得一致的原生计数，再分配拥有的不可变载体；不把载体自身
纳入该次快照。Getter 不分配。报告做一次完整 UTF-8 校验，使用一个可增长 Buffer，并转移其存储
为 string；没有最终文本复制。统计、调试、报告三个组件独立裁剪。

## 对象池：排在最后实现的生命周期能力

用户明确选择：清理池释放池自己的强引用，外部对象继续有效；最后引用
消失时才回收。`ObjectPool<T>` 和 `ObjectArena` 因而是**拥有组**，不是
强制失效对象的 arena allocator，也不是将仍有引用的对象重置后交给别人
使用的对象复用缓存。

```xl
import memory
auto pool = ObjectPool::<GameObject>()
auto actor = pool.make(func() as GameObject
    return GameObject()
end)
pool.clear() // actor 继续有效；没有外部引用的对象运行正常析构
pool.close() // 关闭后不能 make/keep；close 可重复调用
```

- `ObjectPool<T>` 的 make 接收返回 T 的工厂，keep 持有一个已有 T。
  T 的创建/持有使用既有空结构协议约束，只接受 class；不要求继承动态字段 object。scalar/Future 不能充当对象。
  `ObjectArena.make/keep` 的每次调用可使用不同的类类型。
- `length` 是池持有的根引用数；重复 keep 会持有多个根引用。
- clear 交付释放的根数量，解除拥有后池可复用。close 先关闭准入再清理。
  失败以 checked 错误报告；已执行的用户析构或工厂副作用无法回滚。
- 工厂同步运行，不保存闭包。工厂期间同池 make/clear/close 及 length
  读取均以状态错误拒绝；closed 可读，keep 可追加根。finally 恢复准入。
  失败工厂不发布一个伪成功的对象，工厂自身的 keep 等副作用不回滚。
- 池操作限制在创建线程，避免为管理器根集合的每个访问添加锁；外部对象
  可按既有语言线程合同传递。原生控制块保留 managed thread 身份；宿主
  外部线程须在使用池期间存活。最后引用析构仍由现有运行时管理。
- 根引用位于普通 typed Array 字段中，原生控制块只保存线程/状态，是叶子；
  池↔对象循环由现有完整拥有图处理，不能把原生 point 当作隐藏的 GC 根。
- clear 先交换掉旧根集合，再在无原生锁的情况下释放旧集合。析构失败
  和重入不会导致旧根重复释放。析构遵循现有声明顺序，不承诺全图拓扑顺序。

本轮复用 XRT 已有共享堆（16 字节步长、64 个小块尺寸类）。没有增加独立
分配域，没有让 xrtPool/xrtMemPool 的裸地址冒充可由 xrtFree 释放的对象。
固定类型拥有组也**不声称独立固定槽位分配**。每次成功 make 仍执行正常
构造并增加池根引用，根 Array 可能扩容；收益是明确的批量生命周期管理，
不是未经测量的分配提速。独立分配域若日后确有性能需求，属于另行设计的
分配器功能，不能靠当前两个类型的名称推断已经实现。

## 实现与验收口径

`gen_stdlib_foundation.py` 是声明、效果、物理 ABI 的唯一表。新增驻留源
独立进入 compiler/runtime 两套普通构建响应文件和按需组件图；不增加
Cgen 库实现。内核组主要复核既有合同，未为覆盖表凑数增加公共函数。

本轮集中检查额外修复两处既有内核缺陷：

1. checked `var as string` 输出仍按 char* 写入，现改为完整的双字段拥有结果；
   覆盖 NUL/UTF-8、空值、nullable、异步返回、源释放后的寿命和失败分配。
2. 结构化恢复只绑定 primitive TypeUID，遗漏已要求的 scalar domain，导致
   typed Dict/Array 拒收已经恢复的字符串等标量。现使用统一的不可变标量域
   绑定；不修改原 wire shell，保留 var 的实际域和共享默认子对象的隔离。

错误 file 的空值在已有 `xlir_error_location_abi` 门中是明确合同；本轮未
把缺失的来源文件表伪造成有效文件名，继续验证可选文件和有效 throw 行列。

验收在隔离的本轮源码候选上进行，批量收集错误后统一修复。用例覆盖
实际 JIT/模块/AOT、严格 C、拥有清理、失败分配、线程拒绝和组件裁剪。
最终执行结果见 [2026-10-29 验收收据](foundation-acceptance-2026-10-29.json)。
