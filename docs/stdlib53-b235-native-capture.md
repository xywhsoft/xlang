# 原生拥有值的版本化捕获底座

原生拥有值已具备独立的 V2 捕获描述和常驻清理能力，为挂起帧保存
完整 SlotMapKey 提供底座。旧 Capture V1、ActivationCapture V1 的
结构和入口保持不变；本批没有把新描述强转为旧描述，也没有在 Cgen
增加键专用析构程序。语言层携完整键跨 yield 和 await 仍待接线。

## 原生值能力和布局

NativeCaptureProfileV1 由永久驻留的可信原生发布者提供，声明精确的
runtime type、语言身份及 typed detach cleanup。它只适用于不可变、
独立拥有资源、无语言对象图出边的原生叶子值；任意类型 ID、外部句柄
或生成代码回调不能因此取得该能力。

V2 描述保留旧种类的含义，新增原生叶子记录。原生记录的尺寸、对齐、
Copy 和 Drop 必须满足完整类型合同；其他种类不能附带原生描述。
完整帧的清理顺序为反向声明顺序，稀疏激活帧则消费明确的清理顺序。

Trace 和 Cleanup 从所有者取得实际分配长度，不把描述里的 bytes
当成分配凭证。整个描述、初始化标记、偏移和元数据区间先被校验，
再开始观察或清理；不合法的描述 checked 拒绝且不改变载荷。
原生描述、type 和 type ops 不允许与载荷区重叠。

SlotMapKey 的常驻发布者在一次 mutation 内取出完整原生记录、写入
类型化空值，并清空初始化标记，再在 mutation 外释放实例记录。
健康清理没有分配；重复清理只看到已空字段。键仍只拥有独立实例身份，
不保活 SlotMap 本身或其元素。

## 错误与旧资源语义

输入的 checked outcome 与线程已有错误分别保存。首个物理失败即使
没有诊断对象也保持失败，后续清理继续执行，但不能替换首个错误。
普通 pointer/string 资源复用 V1 的真实 detach 和释放程序。

新底座同时验证了旧 string、xvalue、Future、closure、error、cell、
ValueIterator 和 generator 八种拥有资源的跟踪和释放。未初始化字段
可以保留毒值，但不能被读取或析构；非拥有字段不参与清理。

## 双平台验收

Windows 和 Linux 分别从 316 和 315 个当前源码单元构建编译器。
原生专项在 Windows 通过 50 个阶段，在 Linux 通过 67 个阶段，后者
包含所选完整原生闭包的 ASan 和 UBSan。O0 和 O2 均通过 23 组行为
用例、31 组拒绝用例，以及 18 次原生资源释放和跨线程 freeze 探测。

用例覆盖独立键的拥有、16 种稀疏组合、旧资源混合、清理顺序、首个
无诊断失败、原始错误和 ambient 错误、重复清理、元数据别名、实际
长度、对齐、标记和范围拒绝。健康清理处于 fail-after-zero 状态仍
不触发分配。错误描述的拒绝也验证载荷未被修改。

漏掉原生 Drop、析构未初始化原生字段、倒置清理顺序、忘记清空原生
键字段四种实际坏实现均被拒绝；观察毒字段的坏实现对应确定的访问
违规，其余由语义断言拒绝。

独立程序按生产组件计划选取 13 个原生供应方，O0 和 O2 均执行且
内存平衡，不使用 MODULE_ALL，也不链接编译器或发布运行时。
nm 确认不带键装箱、拆箱、converter、NativeLeaf box 或 SlotMap
存储构造器。新底座只增加两个按需原生组件和四个符号；双端常驻
登记核对 277 个组件、1431 个实际导出和 13 个拒绝对照。

既有 SlotMap 语言专项重新通过每端 878 个阶段、510 个故障前缀、
10 个独立程序和公共 JIT、module、AOT。证据固定源码、SDK、编译
对象和产物哈希；不是重新认证 shipping DLL、内嵌 VFS 或全仓 RC0。

## 后续接线

下一批将 V2 描述接入真实 activation/frame 和 generator 所有者，
再补统一 IR 的原生值保持、转移和退役合同，验证完整键跨 yield
和 await。原生生成器结果、SlotMap Future 元素遍历、WaitQueue、
三组标准库及发布总门继续。对象池最后，CRT 未决策为 0，XRT 19
个未决策分组不变；XRT 与 xruntime 原生库没有修改。

专项入口为 check_stdlib_native_capture.py，要求新的证据目录；Linux
可使用 --sanitize。语言挂起执行不能由这个底座专项推定完成。
