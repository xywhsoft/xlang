# 语言数值构造的精确文本与反射边界

整数的文本及动态构造使用驻留提供方，复用 XRT 的有界解析和 typed
数值转换。字符串按完整字节长度消费，内嵌 NUL 属于无效数字文本，
不能作为结束符。语法失败为 ValueError，范围失败为 RangeError。
类型令牌即使以 UInt 载体装箱，也不能进入数值转换。

## IR 和生成代码

整数的目标宽度沿用闭合的 IR 合同，并以静态断言核对原生 profile；
动态转换和 float32 构造从已验证的运行时类型表取得反射身份。文本
及动态整数、文本 float 的物理错误 ABI 改为独立状态和输出参数，
分配不到诊断对象仍然失败，输出只在成功后提交。

Cgen 不再生成这些路径的 strtoll、strtoull、strtod 或动态解析函数体，
只输出对应调用和已确定的错误边。新的整数转换组件按符号精确
选择依赖，float 文本解析归入已有浮点转换组件；没有复制 XRT 算法。
同一冻结输入使用前一版本和本批源码编译器生成 C，精确长度用例
由 114927 字节降到 107443，反射用例由 63206 字节降到 57323。
这是生成 C 大小对比，不是发布 DLL 的体积结论。

本批不改变静态语言整数缩窄的既有 wrapping 合同。它不同于已批准
的 c_* 安全显式构造；as 和 typed 读取仍然保持精确、无损。普通
float 的动态入口当前仍是精确投影，本批没有把它扩成新的隐式解析。

## 验收

专项覆盖内嵌 NUL、ASCII 空白、八种整数宽度、最大和最小值、浮点
向零截断、装箱类型令牌、未对齐输出及诊断分配失败。48 组驻留
成功转换无堆分配，16 个拒绝案例保持输出事务；新增 183 个坏 IR
反例在 C 和头文件的任何字节输出前拒绝。

Windows、Linux 普通和 Linux 指定插桩专项各 455 个阶段、3227 个
坏 IR 反例，八个用例 O0／O2 共 16 条完整分配前缀。新增反射／
文本用例各为 11／48 个前缀。六份独立裁剪输出实际编译、运行。
插桩覆盖生成 C 和测试宿主，不代表所有原生提供方。

双平台各 310 个三组夹具严格 C 编译，整批 JIT／模块各 604 个
阶段，其中 301 个用例实际执行、1 个预期语义拒绝及 8 个专用
宿主、平台或产品要求。驻留目录为 309 个组件、1518 个精确
导出、95481 对依赖闭包及 23 个拒绝负控。

既有 float32 故障宿主与调用清单迁到 V2，专门检查有效零值、
失败零值、空诊断和独立清理；去掉生成代码的状态检查必须被
实际运行拒绝。错误装箱夹具保留完整诊断及 clone 检查，只将
旧的生成式解析消息改成 XRT 的数字解析诊断。

证据位于 E:/xlang-validation/stdlib53-b297-* 及 Linux 对应目录。
