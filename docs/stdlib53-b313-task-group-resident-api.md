# 任务组驻留接口与拥有图边界

TaskGroup 的现有接口由驻留实现直接接入 XRT。原先只有声明的子组、
加入任务、父取消绑定、计数、回收、同步等待和异步等待入口补齐，
不再依赖不存在的生成 C 辅助函数。本次不增加公开 API。

## 声明合同

XLIR 的封闭声明表记录每个入口的物理参数、返回类型、动态借入、
原生资源拥有者和错误载体。`add`、`bindParent` 接受任意动态值，
不是 Future 时返回 false；原生分配或资源失败沿 checked 边传播，
不能因为无法分配错误对象就当作普通的未接纳。

`joinAsync` 明确返回 `future<null>`。它使用已有的异步结果 ABI 验证，
不能把 `future<int>`、错误效果合同或不相符的原生字段投影带到 Cgen。
后端只消费已经验证的调用和清理边，不根据函数名补写实现。

## 父取消绑定

绑定先在句柄锁内保留唯一槽位，再创建取消观察者。已经绑定或正在
绑定时，不允许第二个父 Future 的同步通知先执行再拒绝绑定。创建
失败会释放保留槽，后续可重试；接受的父取消仍传播到原生任务组。

## 独立异步等待

任务组仍只有一个原生完成 Future。每次 `joinAsync` 用驻留回调帧创建
独立消费者，取消其中一个消费者不取消共享完成状态、其他等待者或
任务本身。取消仍是协作请求，不把请求等同于立即发布终态。

原生完成状态发布后，消费者得到精确的 null 结果。回调没有语言
捕获或生成代码地址；构造失败完整拆除部分帧，并保留第一次失败。
入口不会等待任务结束，但关闭原生组可能同步通知已有观察者，因此
不声明 nonblocking，也不能把“返回 Future”当作无阻塞证明。

## 按需组件

同步任务组只依赖 XRT 任务组核心，不因桥接头的模块选择顺带引入
任务池、协程组适配器或调度器。异步等待使用独立驻留组件，只有
`joinAsync` 才引入 Future 回调底座。`task.spawn` 自己的执行器需求
继续由它的已验证组件闭包决定。

## 验证与剩余工作

`check_stdlib_task_group.py` 分别验证原生方法、分配失败前缀、语言
严格 C、JIT、模块执行、普通作用域释放和移动后的独立 AOT。任务组
夹具使用显式队列屏障保持任务活动，不用任意睡眠猜测计数。

任务组、活动项、父观察者和共享 Future 的传递拥有图仍需原生接入。
当前不登记叶子策略，也不把普通作用域释放当作全局循环对象的退役
证书。全局任务组循环、原生观察者的协作退役、正式产品和全部
53 模块的发布验收，继续按原目标完成。
