# 可空原生值的默认值、转换与空值合并

2026-10-13。`SlotMapKey?` 的全局、局部及类字段默认空值，显式提升、
checked 解包、动态尝试转换和惰性 `??` 已通过双端实际运行。本批
复用既有拥有值记录；不新增公开标准库 API，不修改 XRT 算法或单头。

## 统一 IR 合同

三种转换有独立的封闭 ABI：原生键提升为可空键，可空键 checked
解包，以及动态值尝试恢复可空键。前者的表示转换不抛错，独立所有权
取得仍经过 checked 复制；后两者具备立即失败边。不存在的值解包
产生 TypeError。动态类型不匹配返回空值，但复制或资源失败仍报错，
不能把所有失败解释为“不匹配”。

默认初始化要求精确的可空原生配方和 tagged-null 合同，不用相同大小、
布局或 C 类型名字替代类型证明。动态存储即使已有流分析收窄，也直接
观察实际动态载体，不先投影再重新装箱。全局、局部与默认类字段均
使用同一存在位表示；读取类字段的 fallible 投影具有立即错误边。

解包和空值合并先锚定来源；要取得独立拥有值时 checked 复制，然后
结束借入生命周期。`??` 只执行被选中的分支，支持非可空结果和保留
可空结果两种配方。结果不依赖原 SlotMap 的存活或清空状态。

Cgen 与原生依赖计划消费统一 IR 的确切符号合同，不重建源名称语义。
新增一个私有认证尝试投影入口，继续选择已有可空键组件。它验证
genuine leaf profile；外国 handle 即使伪造相同 TypeId 也不能被当作键，
更不能解引用其原始指针。已有枚举编号保持不变。

151、183 阶段，实际 JIT、module、AOT 以及独立严格 C 的 O0／O2
均成功。每端完成 54 次完整调用线程分配前缀检查，每个优化等级执行
100 次模块生命周期，故障后清理、重试及内存数量／字节平衡通过。

原生认证专项每个优化等级执行 1000 组向量：真实键、整数、动态空值、
同 TypeId 外国 handle、非法参数、非空目标保护和继承诊断恢复。
复制失败、部分取得后失败及“成功但留下错误”的注入完整检查；O0／O2
共 14 次原生前缀运行。真实原生解箱是 retain-only，本用例的原生 OOM
前缀首项未触发分配，不声称它覆盖不存在的堆分配。

1 个提升、2 个解包、3 个尝试转换、3 个默认初始化及 3 个投影的
24 项 IR 篡改均被拒绝。三个真实坏编译器分别破坏符号选择、输入
观察合同和语义准入；两个真实坏供应方破坏外国值认证或失败返回
状态。坏符号选择检查实际生成 C，不以 IR 验证代替生成验证。

Linux ASan／UBSan 插桩覆盖生成程序、全部所选供应方和两个测试宿主。

严格 C 检测每端 291 夹具／581 阶段通过，包含一个预期语义拒绝。
此前可空键／Stack try 回归每端 116 阶段和 38 次分配检查通过。

程序仍只选择原先 3 个供应方，不选择可空键组件。

故障验收还纠正了测试语法：单名称 `catch TypeError` 是捕获变量，
