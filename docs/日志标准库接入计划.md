# 日志标准库接入计划

状态：12 个 XRT 日志模块的已批准语言公开面均已实现；验收范围和证据见文末。
Windows 与 Linux x86_64 日志专项已完成，不等同于全仓 RC0 或全平台生产验收。

## 结构与模块对照

语言层统一为 `log`。XRT 是唯一日志算法/输出实现；独立编译的适配器固定物理 ABI、
长度和所有权；XLIR 验证参数、返回值、错误与效果合同；Cgen 只发出调用和声明头，
不向生成 C 注入日志适配器实现。未使用的输出组件不进入独立产物。

| XRT 模块 | xlang 公开面 |
|---|---|
| logger_core | Logger、LogSink、LogRecord、字段/来源/错误快照、默认 Logger、同步自定义 Sink、统计 |
| logger_printf | log.printf、Logger.printf/printfRecord；受检 C printf 子集 |
| logger_format_text | LogTextOptions、log.text/textToWriter/textWriterSink |
| logger_format_text_buffer | log.textToBuffer |
| logger_format_json | LogJsonOptions、log.json/jsonToWriter/jsonWriterSink |
| logger_console | LogConsoleOptions、log.consoleSink |
| logger_format_json_buffer | log.jsonToBuffer |
| logger_file | 原生文件配置/轮转/reopen/closeFile/fileStats；VFS/FileRoot 通过 IoWriter 组合 |
| logger_file_text | log.textFileSink |
| logger_file_json | log.jsonFileSink |
| logger_async | log.asyncSink、stopAsync/asyncError/asyncStats、受检 flush |
| logger_ring | log.ringSink、stopRing/ringError/ringStats、受检 flush |

默认不创建 Logger、Sink、文件或线程。`log.default()` 为 `Logger?`；
无默认 Logger 时全局写入返回 skipped，flush 无操作，但非法级别/长度仍报错。
`fatal` 不退出程序。`enabled` 仅做 Logger 阈值预检查，不保证有接受该记录的 Sink。

## 基础与结构化记录

- `LogLevel`：trace/debug/info/warn/error/fatal/off。
- `LogResult`：written/skipped/dropped；真正失败走异常，不伪装成 dropped。
- `log.create(name="xlang", level=LogLevel.info)`、default/setDefault/shutdown/levelName、
  write/writeRecord/六个级别快捷函数/flush。
- `Logger`：name、getLevel/setLevel/enabled、addSink/removeSink/clearSinks/sinkCount、
  write/writeRecord/tryWrite/tryWriteRecord、六级快捷函数、printf/printfRecord、flush/stats。
- `LogSink`：name、getLevel/setLevel、flush/stats，以及相应工厂类型的文件/队列方法。
- `LogStats`：submitted/written/skipped/dropped/failed，独立只读 uint64 快照。

`tryWrite*` 捕获写入失败并返回 false；正常 skipped/dropped 不算异常失败。
Logger/Sink attach 和默认配置持有独立原生引用；全局写入直接借持默认引用，不逐条创建
语言 Logger 包装对象。nativeHandle/原生句柄构造仅用于内部接入和显式 C 互操，不是
安全的任意指针入口。

`log.record(level, message, size=-1)` 返回独立拥有的 LogRecord。
读取 message/logger/file/functionName/level/time/line/threadId/fieldCount；
clone 深复制记录文本与字段，错误原因链引用不可变 xerror。
source(file,line,functionName)、metadata(logger,time,threadId)、field(name,value,size=-1)、
error(name,error) 在失败时不破坏已有内容。字段支持 null/bool/int/uint64/float/time/string，
char 使用无符号数表示；不隐式序列化 bytes/数组/对象。
fieldName/fieldType/fieldValue/fieldError 使用从零开始的字段索引，越界报错。
fieldType 编码：0=null，1=bool，2=int，3=uint，4=float，5=string，6=time，7=error。
fieldValue 返回独立动态值；error 字段必须用 fieldError，类型不匹配报 TypeError。
writeRecord 使用实际目标 Logger 名，不让记录伪造目标身份。

消息、名称和字符串字段保留完整字节长度和内嵌 NUL。
size=-1 取实际长度；非负值按 min(size, 实际字节长度) 截断；其他负值报 RangeError。
字节截断不自动变成 Unicode 字符截断。直接写入借用输入；拥有记录必须复制输入以允许留存。

## Formatter 与输出目标

LogTextOptions：style(full/simple/message)、flags、utcOffsetSeconds(-86399..86399)。
flags=-1 使用预设；其他值组合 textTime/textLevel/textLogger/textSource/textThread/
textFields/textNewline/textRawMessage。默认转义 NUL、换行和控制字节；rawMessage 显式关闭。

LogJsonOptions：flags、escapeFlags、fields(object/array)、nonfinite(reject/nullValue/stringValue)、
maxErrorDepth。flags=-1 使用默认，其他值组合 jsonTime/jsonLevel/jsonLogger/jsonMessage/
jsonSource/jsonThread/jsonFields/jsonNewline。未知位或非法配置拒绝。

log.text/json 返回独立 owned string。textToBuffer/jsonToBuffer 先完成格式化，再一次追加；
格式化或分配失败保持原 Buffer 不变，成功返回追加字节数。textToWriter/jsonToWriter
流式写出，失败可能已输出前缀，不能承诺撤销外部 IO。
textWriterSink/jsonWriterSink 强持 IoWriter，工厂校验并复制配置；后续修改选项不改变 Sink。
这些是同步、创建线程亲和的 Sink，不可作为原生 async/ring 的工作线程目标。
它们不拥有关闭底层 Writer 的权限；先 closeCustom，再由调用者关闭 Writer/File。

LogConsoleOptions：level、target(stdout/stderr/split)、color(automatic/never/always)、
errorLevel、flushEachRecord、text。可配置原始输出；日志库本身不是 TUI 框架。

LogFileOptions：level、mode(append/truncate)、sync(manual/record/interval)、maxBytes、
backupCount、recordLimit、bufferLimit、syncIntervalMs。
textFileSink/jsonFileSink 只接受原生路径，拒绝路径 NUL；
轮转由 XRT 完成，Sink 提供 filePath/rotate/reopen/closeFile/fileStats。
closeFile 受检、幂等，关闭后写入/flush/rotate 报 XRT closed 错误，reopen 可重新打开。
fileStats 是同一时刻的独立快照：currentBytes/writtenBytes/records/rotations/reopens/syncs。

VFS/FileRoot 必须先显式 open，再将 File.writer() 传给 Writer Sink。
这条同步路径使用已有文件 Provider 能力，不把 VFS 路径偷换为原生路径；
不宣称 Provider 已获得原生文件 Sink 的 rotate/reopen 能力。

## 自定义与异步生命周期

customSink(write, name="custom", level=trace, flush=null)：
write 类型 func(LogRecord) as LogResult；flush 类型 func() as bool。
每次回调得到独立拥有的记录，可在回调后保存；回调原始异常保留。
只允许创建线程调用，跨线程报 XRT state 错误。closeCustom 先 flush，再释放回调捕获；
即使 flush 失败也进入终态，不二次释放。重复 close 成功；活跃回调内 close 拒绝。
原生 opaque 捕获图不是语言 GC 自动可见的：回调捕获自身 Sink/Logger 时，调用者必须
显式 closeCustom 或使用无环/弱捕获；不声称自动回收任意原生跨边界循环。

LogAsyncOptions：name/level/full(block/dropNewest/dropOldest)/shutdown(drain/discard)、
capacity/recordLimit/byteLimit/stackSize。
LogRingOptions：name/level/capacity/recordLimit/batch/stackSize/idleWaitUs。
二者快照复制入队记录，不从工作线程直接执行脚本；ring 是有界异步队列，不是历史记录容器。
异步 written 只表示入队成功，不表示已落盘。flush 提供受检屏障，错误通过异常及
asyncError/ringError 的独立 error 快照观察。asyncStats/ringStats 是统一的独立计数快照，
某队列不适用的计数为零，kind=0 表示 async，kind=1 表示 ring。

stopAsync/stopRing 关闭入队并等待完成最终 flush，保留配置的 drain/discard 语义；
成功终态可重复调用，已发生的后台错误仍报告。关闭后写入是 XRT closed 错误，
不是容量不足的 dropped。stop/flush 可能等待底层 IO；不是 nonblocking。
工作线程自身不得等待自身 stop。正常析构释放资源，但检查输出失败应显式调用 flush/stop。
XRT closed/state 在现行语言异常体系中映射为 RuntimeError，不新增同名异常类。

log.setDefault 产生普通语言模块清理作用域；模块正常卸载时原子取走仍属于该模块的
默认引用并受检 flush，普通 main 返回与 finally 后的记录会排空。宿主后来换了其他默认
Logger 时不会被旧模块清理。log.shutdown 显式原子清空当前默认配置并 flush；
仍持有的 Logger/LogSink 引用不失效。强制终止进程不保证清理，不新增 CRT exit 接口。

## 检查型 printf

可调用入口索引：`log.record(...)`、`log.writeRecord(...)`、`log.customSink(...)`、
`log.setDefault(...)`、`log.text(...)`、`log.json(...)`、`log.textToBuffer(...)`、
`log.jsonToBuffer(...)`、`log.textToWriter(...)`、`log.jsonToWriter(...)`、
`log.textWriterSink(...)`、`log.jsonWriterSink(...)`、`log.textFileSink(...)`、
`log.jsonFileSink(...)`、`log.asyncSink(...)`、`log.ringSink(...)`、`log.printf(...)`。
文本标志：`log.textTime`、`log.textLevel`、`log.textLogger`、`log.textSource`、
`log.textThread`、`log.textFields`、`log.textNewline`、`log.textRawMessage`。
JSON 标志：`log.jsonTime`、`log.jsonLevel`、`log.jsonLogger`、`log.jsonMessage`、
`log.jsonSource`、`log.jsonThread`、`log.jsonFields`、`log.jsonNewline`。

格式必须是编译期字符串字面量；XLIR 根据 C 默认参数提升逐项验证转换与参数。
支持整数 diouxX、实数 fFeEgGaA、c/s/p、%%，固定数字宽度/精度及合适的 h/hh/l/ll/j/z/t。
拒绝 %n、动态格式、星号宽度/精度、位置参数、宽字符/long double、不适用的格式标志、
参数数量/类型不匹配以及格式内 NUL。格式长度和数字宽度/精度最多 1 MiB。
%s 遵守显式 C CString 互操规则，含 NUL 的字符串参数报错；需要二进制安全消息用 write/record。
%d 用 c_int；%lld 用 c_longlong；%jd 用语言 int；%ju 用 uint64；
%s 用 string，%f 用 float；不把语言 int 冒充 C int。va_list 不进入语言层。
适配器运行时也检查格式语法，但原生 C 可变参数入口仍要求 C 调用者传递正确类型。

```xlang
auto logger = log.create("app", LogLevel.debug)
auto options = LogConsoleOptions()
options.text.style = LogTextStyle.message
logger.addSink(log.consoleSink(options))
auto record = log.record(LogLevel.info, "a\0你")
record.field("count", 7)
logger.writeRecord(record)
logger.printf(LogLevel.info, "%jd", 42)
logger.flush()
```

旧 int 级别常量、log.addFile/addRollingFile、Logger.custom/makeDefault 等接口已迁移，
不保留兼容桥。旧测试、发布示例和套件入口使用现行注册方式。

## 验收与范围

```powershell
cmd /d /c build_dll.bat
./tools/check_stdlib_logging.ps1
bash tools/check_stdlib_logging_posix.sh <fresh>
./tools/build_xlir_public_source_driver.ps1 -Directory build/test/log-public-<fresh>
./tools/check_xlir_artifact_runtime.ps1 -PublicDirectory <public> -Directory <fresh> -Cases <logging fixtures>
```

统一门冻结源码/编译器/DLL摘要，批量验证长度、NUL、owned 克隆、配置拒绝、回调异常/
留存/重入/捕获释放、Buffer 回滚、Writer/VFS/FileRoot、文件轮转/关闭、队列正常和后台
失败、模块清理、printf ABI 拒绝与合同破坏，以及严格 C/JIT/AOT、确定性和 C 对照示例。
独立产物门验证全部 resident 组件的实际导出归属、依赖闭包和所选原生实现；
核心产物不得保留日志 console/file/async/ring 实现。基础语言错误输出使用的 console
不在此裁剪承诺之内。

独立故障分配器扫描 39 个预算，实际触发 8 个底层分配失败点；每轮逻辑分配归零、
Buffer 内容保持不变，允许 XRT 小块池缓存稳定 backing pages。不是“全路径 OOM 已证明”。
XRT 12 模块的 Windows modular/single 两种形式测试均通过（24 个测试程序）。
Linux modular/single 同样通过（再 24 个测试程序）。Windows 固定输入门共 170 项通过；
Linux x86_64 的 15 组严格 C、TinyCC JIT 与独立 ELF AOT 通过。清理失败不会丢失原始
ValueError，默认原生引用仍被清空；完整格式化/Writer/文件/队列发布示例有双平台验证。
独立产物门通过 39 个组件、1521 对依赖闭包、286 个实际导出归属及 10 组原生闭包；
所有所选实现均与实际 AOT 产物一致，核心产物不带日志 console/file/async/ring 实现。
