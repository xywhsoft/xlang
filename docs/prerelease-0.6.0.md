# xlang 0.6.0 发布前检查

版本：`0.6.0`；版本代号：`0x00000600`；宿主 C ABI：`1`。

## 发布判定

本轮检查发现的核心发布阻塞已经修复。Windows x64 与 WSL Ubuntu x86-64 使用普通 GCC `-O2` 产品验收；本地产品、最终结果与 SHA-256 见下方机器可读报告。本记录只签收列出的检查范围，不代替完整 `test_all`、全部标准库入口或其他平台验收。没有创建 tag、推送或对外发布。

## 本轮解决的问题

- **原生对象退役合同不完整。** 新增九份经过持有关系审计的叶对象策略，覆盖控制台会话／事件、JSON／XLON Writer、文件统计和日志记录／统计等十种类。`Logger`、带语言闭包的 `LogSink` 和 `XLangHandler` 分别实现真实拥有图，未将这些对象误登记为叶节点。验收选择的 17 种类不再缺少析构策略。
- **日志拥有图缺少原生物理边。** XRT Logger、不可变配置快照、Sink、异步与环形 Sink 按真实引用计数公开持有边，Sink 合同在发布前绑定。回调在短暂图变更范围与 Logger 锁之外执行，静止检查递归验证目标 Sink 的线程能力。语言闭包形成的环能够 checked 退役。
- **嵌套编译器对象缺少完整模块关系。** `XLangHandler` 迁入驻留 API 实现，跟踪实际 Context／Module、类和回调；增加可选原生快照边界与目录发现合同。原生图冻结只持有短暂 API 边界，语义终结、Finish 和释放回调不跨越该锁；代码租约防止回调仍可达时卸载模块。
- **SDK 异步退出偶发失败。** 根因是原生工作线程在 ThreadKey 析构尾部释放最后代码租约，此时语言任务活动已结束，却仍试图 join 自己。新增只读原生当前工作线程查询；非阻塞退役返回 `BUSY`，由外部完成物理 join。保留原生直接 self-join 的 checked 错误，没有加长等待或忽略错误。30 轮强制重现测试通过，旧实现负对照可确定失败。
- **TCC 生成实现仍依赖符号名猜测。** 改为显式实现提供方合同，覆盖十个生成实现，独立验证参数、结果、借用与错误 ABI。Cgen 只读取已经验证的提供方标记，保留正常 C 字符串转换和 foreign 错误范围。40 个伪造／缺失合同负例在输出 C／头之前拒绝。
- **声明与交付工具残留问题。** 修复 `log.customSink` 的可空可选 flush 声明；同步标准库登记参考、测试依赖与 SDK 头搜索路径；修复根目录迁移后的隔离快照路径。XRT 单头快照和 IR 生成数据统一 LF；Linux 在冻结输入前先生成 IR 表，避免首次检出的行尾转换污染构建记录。

XRT 必要改动单独提交为 `5c852a799`（日志拥有图）和 `3fde6da57`（原生工作线程查询），xlang 固定到后者并使用毫秒时间合同。独立 XRT 工作区原有 HTTP／网络等改动和已暂存文件保留，未混入提交。xlang 核心修复为 `ed78373dd`，交付工具与生成文件规范修复为 `d90d56891`，语义析构记录验收为 `a8063e909`。IDE 并行修改不纳入本轮提交。

## 最终验证结果

最终机器可读结果以 [检查摘要](reports/prerelease-0.6.0.json) 为准。验收包含：

| 检查 | 结果与范围 |
| --- | --- |
| 普通构建 | 两端 GCC `-O2`；Windows 基础库继续使用 TCC 预编译，无 `-Oz` 或 LTO |
| 语言批量回归 | 两端各 321 阶段：96 个正例的 JIT／构建／独立 AOT，33 个拒绝用例 |
| 版本与 C SDK | Windows 12 项、Linux 9 项；初始化前查询、Windows VERSIONINFO、双库独立 C 宿主 |
| 定向运行时与导出 | Windows 10 阶段、Linux 12 阶段；格式化、进程参数、分配失败前缀及完整驻留登记符号 |
| 隔离交付 | 空工作目录、复制产品与 SDK、C／嵌套 xlang JIT/AOT、双库宿主 |
| 原生拥有门禁 | 每端 36 个步骤，17 种类缺失策略为零；日志环、嵌套模块、异步文件自动／显式关闭各经双库 20 次 SDK 运行及 bounded drain |
| 确定性退出回归 | 双 DLL／双 SO 各 30 轮原生 ThreadKey 尾部 self-poll；只允许 BUSY，无残留错误，外部完成 join |
| VFS／文件系统 | 38 个正例的严格 C、JIT/AOT、确定性与依赖裁剪；10 个 ABI 负例及 6 个公开示例 |
| 实际内嵌资源 | Windows `xl.dll` 601 项、`xlc.dll` 2,756 项；Linux `libxl.so` 503 项、`libxlc.so` 2,650 项；从实际产品逐项解码与源文件核对 |
| IR／Cgen | 全部 3,700 个直接合同与逻辑字段对照；496 个 RuntimeOp、3,968 个效果检查、57 个 consume 及 40 个非法输入拒绝；完整 Cgen 单元通过 |
| 图清理与故障 | 400 个环、96 个准备状态迁移、140＋40 个故障前缀；1,632 次分配全部退役，活跃分配差为零；新增原生日志／线程专项通过 ASan／UBSan／LSan |
| 静态门禁 | 文档、源码／测试／工具接线、ABI、快照、声明、尺寸、XLIR 源断言共 34 项；源码断言与已编译 RuntimeOp 验收分别记录 |

321 阶段回归、SDK、VFS 和隔离交付使用普通发布产品；IR 单元、故障注入与 sanitizer 使用各自独立编译的专项程序。源码断言不计作运行验收。

最初的失败日志保留。Windows 原生拥有门禁首次新增 C 测试因缺少 `release/include` 搜索路径而编译失败，修正后完整复验；Linux 首次构建成功，但输入记录捕获到生成 IR 表的 CRLF→LF 转换，确认只有行尾变化后，修正规则并从新 Git 导出重建，未把首次失败记录改成通过。标准库参考和嵌套子脚本接线也由门禁发现并修复。

## 验证与交付边界

本轮执行正常离线用例、类型与 ABI 拒绝、内存故障、生成 C、拥有图和 SDK 交付检查。没有执行攻击、模糊测试、外部网络或 TLS 握手测试，也没有重复修改本机时区。既有网络／TLS 平台支持限制、未覆盖平台和标准库逐入口验收不由本轮扩大签收；本轮范围内无已知剩余阻塞。

原创部分继续采用 MIT；TCC 主体及衍生修改沿用原 LGPL，逐文件许可及链接例外不变。没有把 XRT 的 development 来源标记改写成全面生产安全认证。

六个命令行／DLL／SO 产品完成验收后同步到 `release/`，按现有规则由 Git 忽略；源码、头、构建和验证工具参与提交。IDE 二进制和原有安装回执不在本轮重签范围。第三方 TCC 仍存在既有 `fread` 返回值警告，未作为构建失败或静默修正其算法。
