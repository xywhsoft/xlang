# LZ4 标准帧与限定交付

这是扩展库长期压实任务中 LZ4 的进展记录，不是全部生态或全部平台的 RC 证明。
当前正式 CLI/DLL 与 XRT/xruntime 单头快照未替换，测试使用活动包的唯一源码。

## 实现与合同

- 复用官方 LZ4F Frame 接口，XRT 提供内存、缓冲、IO、错误和资源限额。
- 压缩独立 64 KiB 块及双校验；解压支持关联块、四种标准块大小、拼接帧、跳过帧，
  明确拒绝非零外部字典 ID，不额外实现私有外层兼容。
- C 文件事务是独立编译单元，XL 绑定只负责物理 ABI、计数范围和借用 callable。
  C 核心使用普通进度回调，不依赖 xlang；没有另复制一套文件或对象运行库。
- 实际生成的 23 个 XL 原生声明与公开 C 头一同严格编译，包含 unsigned64、size_t、
  bool、文本/字节视图和析构。与 xxhash 包同用时内部哈希符号已隔离。
- 参数错误允许纠正；解码、限额、IO、重入错误进入终态。drain 分配替换缓冲失败
  不丢失原输出；finish 幂等，数据到达帧边界与最终封存是两个状态。
- 文件在完整处理、最终回调和关闭成功后提交；同路径、覆盖与非覆盖提交竞争、取消
  和回调异常均保持原目标。错误清理保留首个错误，xcall 因果链不被压成通用错误。

公开合同与完整签名见 [README](../release/extlibs/lz4/README.md) 和
[C 头文件](../release/extlibs/lz4/include/xrt_lz4.h)。

## 实际验证

| 范围 | 结果 |
| --- | --- |
| Windows 专项 | 63 个检查步骤通过，输入哈希前后不变 |
| C 编译与行为 | 自研实现严格 GCC 编译；状态、限额、分块、拼接/跳过帧、每字节截断/损坏 |
| 分配失败 | Windows：基础 22、原生回调 26、文件四路径 78 个拒绝位置，恢复后无额外 live 对象或非法释放 |
| IO / 回调 | 短读短写、原错误因果链、单调/最终进度、取消、无返回/错类型、重入及失败恢复 |
| 并发 | 四个独立对象工作线程共 1000 轮，验证线程局部错误隔离；不代表共享对象可无锁并发 |
| C/XL | 三组 XL 用例 JIT/AOT、三个 XL 范例、两组 C 范例 GCC/JIT/AOT 和 package runner，黄金输出一致 |
| 文件故障 | 附加 C 文件故障程序经 TCC JIT/AOT 执行，包括中文路径及提交竞争 |
| 独立互操作 | Windows 驱动、Linux C 驱动各 514 检查；参照为系统 liblz4 1.10.0，不是本包重新编译的副本 |
| Linux C | GCC + ASan/UBSan/泄漏检测；同六个 C 程序、独立互操作、两组黄金范例 |
| 文档 | README 与官网的两个 XL 代码块实际运行通过；包内与本地官网正文哈希一致 |

互操作组合含空输入、NUL/非 UTF-8 字节、中文、重复与随机大输入、压缩加速边界、
标准块大小、关联/独立块、块/内容校验、声明长度、全部跳过帧 magic、串联和损坏拒绝。
不同平台的故障注入位置数不同，不能把两平台的拒绝位置相加为独立缺陷或覆盖率。

复验脚本为 [Windows 门禁](../tools/check_extlib_lz4.ps1)（完整范围加 `-Interop`）与
[Linux C 门禁](../tools/check_extlib_lz4.sh)。Windows 门禁纳入 featured RC 套件，
独立系统库互操作需另显式启用；没有静默把缺失参照库视为成功。
本次验证时也修正了 PowerShell 参数名/变量名大小写碰撞和多个 wsl.exe 命令路径选择问题。

## 仍需保持的边界

1. 任意二进制使用 Buffer。共享 string 桥的嵌入 NUL 截短仍未消除，不能将本库的
   Buffer/C 显式长度测试通过扩大为全语言文本拥有权已经收口。
2. 基础 lz4.c/h 是仓库原有文件，声明 1.10.0，但不是对应标签的逐字副本；精确来源
   待进一步确认。[VENDOR](../release/extlibs/lz4/VENDOR.md) 明确保留此项，不虚构提交。
3. 未覆盖 Linux xlang JIT/AOT、32 位/ARM、TSan、两份 DLL 的专项宿主回调与长期压力；
   本次没有跑全部 featured/phase1，也没有进行吞吐或二进制体积基准。
4. 已 drain 的前缀无法回滚，校验和不是加密认证。限额不是 CPU 超时或完整工作内存配额；
   文件事务不等于断电持久性，也不能保证文件系统拒绝删除时仍能清理。
5. 源码依赖预算只针对占位库新增实现。本次利用既有库与上游帧实现，不按第三方总行数
   把已实现压缩库重新判定为超预算占位。

因此本库可列为“标准帧与限定专项通过、资料已交付”，不能写成“无剩余项、全平台 RC”。
整个扩展库长期目标继续进行。
