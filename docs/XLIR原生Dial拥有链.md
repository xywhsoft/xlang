# XLIR 原生 Dial 拥有链

2026-09-20，v226 候选。延续 v225 的真实调度拥有关系，将 Dial 的三个命令
和两个 Timer 纳入同一物理对象身份，不以 Resources 计数代替对象引用计数。

Start、Resolve 命令各持有独立引用。解析先到达时，Resolve 只发布就绪状态，
初始解析资源继续存活到 Start 完成处理；排队命令自己的引用在回调返回后释放。
Cancel、Deadline 与 Fallback 则把已有资源引用移交调度器，回调不再自行执行
最后一次 ResourceDrop。投递失败回退本次拥有权；现有同步后备路径保留相同的
独立引用保护。

Dial 终态只退休 Engine 活动登记，不提前释放物理 Engine 拥有权。保留的终态
Dial 可以跨越 Engine 的 Stop 和创建者 Destroy；最后一个 Dial 引用释放后才
归还它持有的 Engine 壳引用。构造阶段解析提交失败也走配平的回收路径。

持久测试覆盖正常顺序、解析先于启动、取消、超时、Done 中释放创建者引用、
终态 Dial 跨 Engine 创建者退休，以及真实引用增减与 Count 的一致性。单头
测试额外直接进入私有 Fallback 调度并取消，不宣称自然网络竞速已被该测试覆盖。
首次新测试在同步嵌套的 Timer 取消中重复观察 Resolve，已修正测试观察逻辑，
原失败记录保留，未用修改运行时的方式迁就测试。最终验收以本批 checkpoint 为准。
