# C 互操作前端对齐（M7a2b107）

本阶段将外部语言服务适配到 `current-c-interop-20261102` 前端，继续复用编译器的解析、类型、语义、IR 和 XRT 实现。C 结构体、定长 C 数组、外部句柄及声明式 C 调用均是 **xlang 代码中的互操作能力**；IDE 的 C LSP 开关仍默认关闭。

构建和故障注入在 `ide/build/Release/lsp-c-interop-alignment-20261102/` 内进行，用于保护正在使用的根 `release/`。本阶段尚未部署发布程序，也未更新当前交付索引。

## 输入与边界

`native_c_interop_profile.py` 固定 356 项实际前端／包含依赖。相对上一前端，有 26 项逻辑新增或修改，其中四项是新文件；另有 294 项只有换行编码差异。新摘要来自捕获的原始字节。

`native_frontend_inputs.py` 在构建前处理 Git 检出的换行差异。LF／CRLF 转换只有在结果精确匹配已登记摘要时才被接受；Lemon 混合换行文件另外保存了与原摘要绑定的换行位图。需要恢复时，工具在构建目录生成输入副本，并将原始文件摘要加入最终输入守卫。工作树和 SDK 元数据保持原样，非换行内容改动或准备期间源文件变化均使构建拒绝继续。

选择新表示同时要求 AST 头和 XRT 匹配，不能仅依赖与旧 unified 前端共用的 XRT 摘要。解析、语义、IR 等角色仍分别验证；新角色同时绑定完整的已捕获包含闭包。正常构建还核对 GCC 的实际依赖与构建前后摘要。

原始 AST 对象仍为 272 字节；私有所有权字段由原有适配器统一追加。IR 节点从 336 增至 368 字节，类型项从 384 增至 408 字节。所有原生、服务端及测试消费者均需重新编译，不能混用旧对象。

## 原生数据适配

- 查询分类追加 `C_RECORD`，字符串直接使用编译器实际输出的 `C record`；所有消费者看到相同枚举，已有分类序号保持不变。原生点查询、声明容器、名义类型候选及折叠识别 C 结构体，文档符号使用 LSP `Struct` 类别。
- 类型前缀键追加 `foreignHeader` 的内容和空值状态、`foreignBase`、完整的 `nativeArrayExtent`。头文件字符串继续由原生类型池通过 XRT 拥有和释放，IDE 不再建立一套分配规则。
- 原生聚合布局改名后，派生阶段的上下文键仍覆盖类型池、运行时类型图及布局，并记录字段的 owner/type/declaration、语言名称和 C 成员名称。
- `XL6_ForeignCallFacts` 的五个逻辑标量全部保留。编码器仅将私有副本的四字节尾部填充清零，不修改原始节点；解码器继续保留任意原始字位的独立边界测试。
- 回滚函数参加原有词法／实体符号重绑定。新表示使用五个符号槽，包文本标志移至第 10 位，避免与实体标签冲突；旧表示保留四槽／第 8 位的原格式。这些格式仅用于当前进程的私有缓存。
- 新语义检查器的 74 处原生类型查找均进入原有读取观察器。新增两处分别处理定长数组注册和别名构造的规范类型。原有全局状态前后比较仍拒绝重放产生新注册项的函数。

新增 C 声明属性不会作为可执行 IR 子节点发布。因此原始构建器的 `sourceChildCount` 遍历边界和新增外部类基类型阶段均有对应取消检查，完整原始验证器仍执行。

Lemon 的 AST 联合成员从 `yy270` 改为 `yy230`，同时新增拥有 attributes 的按值 `XL6_PExternContract`（`yy166`）。适配器保留编译器原有的复合记录析构体，再为 AST 非终结符补充释放；不会把复合记录当作 AST 指针。新增复合析构使生成器启用编号下界 138；适配器同时扩展该边界，确保 import_name／import_target（132／133）也能在解析结束时被释放。

## 缓存与尚未扩展的能力

本阶段没有重新启用已否决的 canonical 共享缓冲区实验，也没有把模块重建描述为真正的最终 IR 局部生产。

完整最终 IR 的已有持久化快路径仍要求 AST／IR 节点一一对应。新外部声明省略属性节点时，该证明会拒绝复用并回到原始构建；没有放宽位置或所有权验证。C 结构体专属成员补全和更完整的成员大纲也仍需后续扩展，不能由前端语义样例通过推断为已完成。
