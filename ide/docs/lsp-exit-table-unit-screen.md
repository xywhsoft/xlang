# 函数退出表单元：重定位与性能筛选

2026-10-30，M7a2b72a。完整的退出计划、清理动作和路由表已在隔离原型中实现函数单元所有权及重定位，但端到端筛选失败，**不合入默认分析路径**。开发服务仍为 0.99，本轮未替换根目录发布程序；长期目标保持 active。

## 实现与边界

原型从实际 0.99 原生 IR 生成源中机械提取原始单节点退出计划生产代码，保持原有规则及“先全部计划／清理动作、后全部路由”的模块顺序。每个不可变单元独立拥有完整计划、动作、路由及准入键，使用 XRT 容器与原子引用计数；新单元不保留旧 AST、check、完整 IR 或旧 memo。

当前原生父子关系划分根级函数子树，嵌套函数属于该单元。节点引用、局部符号、执行区域和表内偏移映射到当前生产结果。局部符号的相对槽由当前 `symbolNodes` 绑定及节点原生符号共同证明，不通过名称推断；跨函数区域冲突拒绝准入。旧 memo 退休后，当前单元继续持有独立资产。原始完整验证器保留。

准入比较完整原类型池及运行时映射，并重新编码该阶段读取的当前函数节点事实、文本、有序孩子和 initializer 失败效果。原型暂拒绝名义 CLASS、枚举表及 lowered 指令／函数上下文；变化或不可用的证明走原生产路径。退出表以外的最终 IR 生产没有变为函数局部生产。

32 MiB 是原型退出单元缓存的已知保留容量上限，包含键及表向量；不包含完整模型、临时范围／区域索引、当前证明键、allocator 或 RSS，不是服务全局预算。新增分配失败恢复和所有临时容量核算尚未完成。

既有 GCC 类型树清单定位到该阶段的 47 个函数及字段读取，辅助构造投影和回退边界。本轮没有将其当作完整源码人工审计、一般 C 数据流分析或形式证明，也未绕过固定编译器源守卫。

## 原生与实际协议结果

以实际 0.99 的固定前端和依赖构建：重新编译一个 IR 对象及一个测试对象，其余 63 个核心成员逐成员验证未变，宿主对象沿用匹配构建。这不是全新完整构建，也没有冒领 109 个原生 fixture、52 套协议或 GUI 验收。

原有 939 项原生检查通过，逐项比较独立 fresh 的完整 XLIR JSON，覆盖语义／声明编辑、节点和孩子偏移、Unicode 位置、类型／绑定守卫、旧 owner 退休及四线程。父线程记录到 603 次完整函数退出表复用；该数字不是服务请求的生产统计。第一版脚本在启动测试之前因打印单参数命令而失败，修正后另存第二版记录，旧失败保留。

真实 stdio 筛选使用同一路径、正文和版本，32／512 辅助函数、单文件／导入、字面量／声明编辑，8 进程 ABBA／BAAB 顺序，共 **64 进程、960 请求**。每个场景每侧有 48 个后续编辑样本；冷、首次编辑和精确命中各 4 个。所有标准结果与 0.99 基线一致，仅排除 analysis／durationMs；所有进程正常退出。当前原型尚未向协议暴露逐结果退出表创建来源，不能冒充该项产品验证。

## 分段诊断与后续生产边界

筛选结束后，另行构建仅用于诊断的两个计时程序，4 进程、16 请求，对约 9.8 万个节点的导入工程比较。原始退出阶段约 10–16 ms；原型热编辑的计划／路由生产约 2–4 ms，但每次重新构造准入键花费约 20–31 ms，另有上下文与范围工作。这是带计时器的定位证据，不能替代前述普通程序筛选，也不能将差异全部归因于单条操作。

这个边界确实复用了完整派生表，却再次扫描和编码了已物化的函数 IR，证明成本覆盖了局部生产收益。后续应将**完整有类型函数输入与其准入证据一起持久化**：将已验证的 facts、读集合、当前 header／type 版本和绑定映射带入最终 IR 的函数生产边界，减少重复扫描和物化。不能再为单个廉价阶段叠加完整后置证明键。

现有 `function_unit` 的显式独立快照尚未接入普通生产，且公开契约仍明确不承诺跨编译的原生 ID 新鲜性；M71 的 `typed_module` 管理完整树所有权，也没有完成函数／类型注册表重绑定。下一阶段必须落实这些边界及完整函数最终节点／交叉表的生产依赖，不能将本实验计为该目标完成。

完整工作空间、其余适用 LSP／静态检查／编辑态补全、全局内存与 OOM、默认诊断并发／IDE 按键链路、大规模长稳及最终 compiler／SDK／release 对齐仍待完成。保持外部服务，不加入 DAP、运行／调试补全或立即合并 `xlc.dll`。
