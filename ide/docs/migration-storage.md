# 迁移正文所有权与维护

项目清单和目录迁移将未保存的 C/xlang 正文、磁盘基线及工程模型存入全局会话目录。当前正文引用在 `blobs` 中，全部已发布的不可变正文快照在 `ownedBodies` 中；后者包含历次检查点和连续迁移产生的旧副本。每行记录 GUID 相对引用、长度、卷号、文件索引、属性、修改时间和 SHA256。重复内容在完整校验后复用，包括 A→B→A 编辑。

项目和工作空间全部保存且当前会话发布成功后，事务变为 `retired`，同时保存退休时间 `retiredAt`。未保存的 `prepared`、`pending` 和 `aborted` 事务不参加回收。旧版退休记录只接纳其明确列出的 `blobs`，不能仅凭 GUID 文件名推断历史正文所有权。

## 使用入口

会话打开后在独立后台线程启动全局迁移维护，此后每小时执行一次。原生“会话与恢复”窗口的维护按钮也清理退休迁移正文，并分别报告本地恢复与迁移副本数量。手动会话维护使用相同实现。后台工作不读取或修改活动编辑器模型；退出时取消并等待线程结束。

当前迁移尚待保存时，显式维护入口继续拒绝清理。后台全局维护逐个检查记录，只处理已退休事务，不影响其他窗口仍使用的未完成事务。

## 删除条件

只对本机固定磁盘执行删除。全局目录、迁移根目录和作用域锁固定其身份；标记必须是可识别、未损坏的退休记录。退休时间、正文创建时间和已记录修改时间均需满七天，时钟回退保留数据。

每个候选以同一个 Windows 文件句柄打开、校验及标记删除。文件必须普通、非只读、非重解析点且只有一个硬链接；卷号、文件索引、长度、属性、修改时间和 SHA256 都与所有权清单一致。打开时拒绝共享写入和替换；实际文件大小不符时不会读取大文件。取消、锁定、陌生副本、被替换文件和内容变化均保留。

删除成功后才移除所有权和当前引用。标记发布失败时保留原退休记录，下一轮可清除已经不存在的已知引用；退休记录不再用于恢复。源文件、项目及工作空间清单、当前会话正文、未知文件、备份及退休标记本身均不删除。

## 有界工作与游标

迁移根目录仍最多枚举 1024 项。每轮最多访问 64 个存储、检查 128 个正文及读取 64 MiB 正文。全局 `maintenance.json` 保存最后访问的存储，事务的 `maintenanceAfter` 保存正文游标；下一轮从后续记录继续，再循环到开头。锁定、损坏或陌生的前缀目录不会长期阻挡后续已知存储。

根目录的维护标记和锁不计入迁移事务发现上限。正文存储仍限制每个正文 16 MiB、每个存储 512 MiB/10000 文件；未知文件也占容量。维护不会放宽这些写入限制。

## 验证与保留边界

`tests/migration_store_test.c` 通过真实生产准备、迁移、检查点及退休 API，覆盖宽限期、历史去重、只读/硬链接/共享锁、身份替换、同身份正文变化、损坏清单、旧格式、陌生文件、发布失败后重试、取消、真实目录联接、后台线程和文件/字节/存储预算。用户 C/xlang 文件及主恢复副本保留。

`tools/check_migration_store.py` 操作真实生产窗口，分别通过手动维护、自动后台维护和恢复面板按钮清理已退休副本，并重新检查 C/xlang 草稿、语法覆盖、选区、工程属性、稳定身份及磁盘原文件。测试将真实副本文件时间调到二十天前以验证七天策略，不改变正文内容。

没有持久所有权记录的旧历史副本、未完成事务、退休目录及标记的整目录回收仍保留。网络共享自动清理及突然断电持久化保证尚未验收。
