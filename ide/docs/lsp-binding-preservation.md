# 重命名候选的原生绑定比较

`semantic_binding_check` 比较同一编译配置在修改前、修改后产生的完整原生引用分片。它不按名称猜测绑定，也不以“修改后可以编译”作为成功依据。来源先按既有原生词法路径身份排序匹配；编辑文件分别核对计划的完整 before/after 正文，其他文件核对完整原文。任何来源增减、重复身份、正文或类别不符均拒绝。

比较器把原有每一条引用的出现区间和目标声明区间端点都映射到候选正文，再按修改后来源编号排序，与修改后整张引用表逐项比较。既包括被改名符号，也包括未参与改名的符号。新增、缺失或改变的行均拒绝，不能用一个仍然能找到的目标引用掩盖其他绑定变化。

例如，在已有外层变量 `kept` 的内部作用域，把局部变量 `value` 改为 `kept`，可能让未编辑的 `print(kept)` 转而绑定到新名字。另一个例子是把函数加入已有重载名后，未编辑的调用选择了新重载。专项测试确实对修改前、修改后都运行原生语义和 typed-IR 分析，两者均接受，而绑定比较明确拒绝这两种变化。

所有偏移均位于不含物理 BOM 的原生正文。原来源的类别和 BOM 坐标约定必须与候选计划一致；修改后检查可能把磁盘文件变成覆盖输入，其 LSP BOM 前缀约定可以不同，不影响原生字节身份。跨文件限定名称仍比较完整原生 token，不把它误当作只包含末尾 IDENT 的区间。独立检查的来源编号和路径大小写/分隔符变化不会改变语义身份。

比较只借用不可变分片与计划，不保留 AST、检查、缓存或工作线程，不读取/写入文件，也不修改编辑器。每份来源正文只按需要比较一次，不按引用数重复比较正文。每个出现/声明端点通过已有计划的二分映射转换；只保存一份待比较引用数组。已准备的路径键只构造一次，排序比较时不再规范化或查询文件系统。

默认 32 MiB、最大 64 MiB 额度计入临时路径/来源映射/引用数组及持有的原生路径键；借用的分片、计划和路径转换/分配器/排序内部成本额外。按路径、引用和 64 KiB 正文块检查取消。额度内库排序不可抢占。这里给出算法与已知计费范围，不把它当作实测延迟或 RSS 指标。

该阶段是可独立复用的比较器，尚未接入工程重命名 actor 的候选批准流程。原生复核测试目前通过现有检查 API 构造输入；生产流程仍需实现不受普通 64 个覆盖输入限制的完整候选复核，以及同配置、全范围、来源/解析环境/发布时序的新鲜度证明。分片未记录的未绑定/生成事实不属于本比较器的覆盖范围。完整泛型来源、外部符号策略、物理别名/可写性和 IDE 版本化原子应用仍待完成，`renameProvider` 保持关闭。

本阶段通过 183 个原生测试程序、12 组协议测试和 29 项配对 GUI 检查。新增专项 212 项检查覆盖真实原生分析前后的局部遮蔽/重载变化、跨文件限定 token、来源编号及路径拼写变化、完整来源证明、增长/缩短与 Unicode 名称、BOM/CRLF、额度边界、临时数组及每个路径键的分配拒绝、全部观测取消位置和独立四读者。150 来源容量用例只针对比较器，不宣称突破现有原生检查的 64 覆盖输入限制。

跳过整表比较、忽略正文变化、误用原编译文件编号和丢失目标声明偏移映射这四个实际实现变异均被测试拒绝。资格检查核对 295 个实际编译消费者与 184 个程序，配对同一候选服务及匹配 SDK 重编译全部 116 个 GUI 对象，覆盖 C/xlang 输入、删除、撤销、Unicode/IME、焦点及既有语言功能；浅色、深色和属性引用窗格完成复核。

验收材料见 `dev/release-materials/provenance/lsp-binding-checks-20261111.json`。本阶段不替换默认发布程序，不进行上线推送，也不宣称全目标性能准入完成。
