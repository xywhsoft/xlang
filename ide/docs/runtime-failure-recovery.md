# 可处理渲染错误的恢复检查点

原生主程序的帧函数返回错误时，会记录原始错误码并退出运行循环。退出前现在尝试以 `cleanExit=0` 保存当前会话检查点，保护仍处于 750 毫秒自动保存等待期内的 C/xlang 草稿。该路径调用现有会话存储，不保存或覆盖项目源文件，也不触发用户正常关闭时的“放弃修改”语义。

存储保护继续适用：会话锁、原始摘要、损坏状态、正文额度和原子发布仍由 `xideSessionSave` 核对。保存失败向诊断输出记录具体原因，旧检查点继续保留；禁用会话时不创建恢复目录。保存失败不会把渲染错误改成成功。检查点保存期间，当前内存正文、选区、版本和撤销历史继续存在；跨进程恢复沿用原有会话协议，不宣告持久化整个撤销栈。

`frame_failure_test` 使用真实 XGE 窗口和生产 `xideAppFrame`。测试在两份真实未命名 C/xlang 草稿修改后，通过渲染代理返回 GPU 或内存错误，验证失败发生在等待期内，并用新进程恢复最新正文、语言、稳定文档身份和选区。锁定会话文件时新进程仍能恢复此前检查点；外部损坏状态的原字节和禁用会话均另行检查。原生窗口位于独立 Windows 桌面，未切换用户桌面。

这是对可处理帧错误退出的保护。进程访问异常、强制终止、断电、实际内存耗尽时的写入成功率及历史 GPU/最大化/静默失败的原始原因仍须独立调查；注入返回码不会证明这些原始原因已解决。


## GUI 故障提示和诊断报告

直接启动 `xlang_ide.exe` 时，启动参数、窗口初始化、工作空间/项目、文件或工作界面发生不可继续的错误，会先完成资源释放，再通过独立 XGE / XUI 环境显示 `xuiMsgBox` 错误提示。提示包含失败原因、原错误域和代码、恢复检查点的实际状态，以及诊断文件路径。工作空间加载使用其原始模型错误，不把文件不存在误报为内存不足。可恢复的 SDK 缓存警告继续遵循原处理方式。

恢复状态区分未生成、已关闭、已保存和保存失败。初始化阶段尚未退出恢复流程时，`xideSessionSave` 的成功空操作不能被描述为新快照。已有恢复区受到保护或被锁定时，提示明确说明新检查点未保存；诊断文件和提示本身不会保存源文件或未保存的编辑器内容。

默认诊断目录是可执行文件旁的 `option/diagnostics`。该位置不可写时，会尝试 `%LOCALAPPDATA%/xlang-ide/diagnostics`。可用 `--diagnostic-root PATH` 指定完全隔离的目录；显式目录失败时不会转写到其他位置。报告使用 UTF-8，只包含 UTC、进程号、阶段、错误域/代码、帧数、受限长的原因/操作及恢复结果，不收集参数列表、环境、任务输出或文档正文。

报告以独占的新文件名创建，不覆盖或删除已有文件。目录中的所有普通文件计入容量限制：最多 64 个文件、总计 512 KiB，单个报告不超过 8 KiB。`.diagnostic.lock` 串行化同目录的写入，其字节仍计入容量。达到容量上限、写入者正持锁或内存不足时不另找目录扩大存储。目录包含子目录或重解析点时拒绝写入。部分写入失败的文件也保留并占用额度，供人工检查。

`xlang_ide_console.exe` 保留 stderr 和退出码，不弹窗。`--hidden` 或 `--frames` 的自动化运行也不弹窗，默认不生成诊断文件；给出 `--diagnostic-root` 时仍写入隔离报告，包括参数解析提前失败的情况。报告写入失败不会替换最初的错误、恢复状态或退出码。

原生验收在从未切换到前台的独立 Windows 桌面中启动真实 GUI/console，读取并确认XUI 错误窗口、关闭属于该测试的对话框，记录图像、stderr、退出码和进程身份。验收覆盖中文/emoji 路径、初始化未写快照、参数错误、隐藏模式、已有文件保护、默认目录和回退、目录额度、长路径及持锁写入。原有注入帧故障和三次独立进程恢复验收继续检查实际文本恢复，并校验提示对应的检查点状态。

直接 XGE 帧开始/结束及 PNG 导出与 XUI 操作分别记录错误域。帧验收只替换真实应用源码的帧开始/结束调用，其他 SDK 和应用行为均实际执行；分别注入 XGE -8/-15 后保存、退出并重新启动，校验域、原代码和最新 C/xlang 恢复文本。XUI GPU/内存注入保持其原域。

窗口与消息框迁移细节见 [迁移清单](window-dialogs.md)。当图形 / 字体系统本身无法启动时，紧急报告窗口使用独立 Win32 实现保留可见诊断；正常失败路径使用 XUI。
