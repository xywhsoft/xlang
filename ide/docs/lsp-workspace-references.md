# 完整工作区引用与后台响应编码

M7b6p，2026-11-16。标准 `textDocument/references` 现在遍历完整 catalog：选中与未选中的工程、关闭成员、登记的散文件，以及未归属工程的打开文档。独立 `.xl` 文件仍可在没有工程或工作空间时查询。关闭文件可与其他文件的未保存内容一起分析，不创建虚构的打开文档或编辑器版本。内部服务版本为 `0.104`，IDE 和更新通道的显示版本不变。

查询先由现有原生 key worker 解析光标，再让原有成员调度器在每个范围复用已经检查的 shard。使用原生声明身份和完整声明源文本匹配，不按名字搜索，也不套用重命名的函数族或写入策略。只读库和未配置为可编辑成员的导入声明仍可返回；不同声明的同名符号不会混入。保留标准 `context.includeDeclaration` 语义，基础结果仍是 `Location[]`，扩展来源证明仍按客户端能力协商。协议入口见 [LSP references](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/language/references.md)。

完整范围复用现有 catalog/rename-scope 元数据、XRT 不可变文本、成员索引和原生检查缓存，没有另建扫描器或线程池。提交只处理有界标签、元数据和文本引用，不读盘、不散列正文。关闭文件的正文读取和 UTF-16 位置验证在 worker 完成，验证使用已检查 shard 的源文本；合法的无符号位置返回空数组，越界或半个代理对的位置不能伪装成空结果。无法完整检查任一范围时返回失败，不发布部分引用。未归属工程的错误打开文档现在也会使完整工作区查询失败。

完整 JSON-RPC 帧在原有 coordinator 编码，随后验证所有参与来源、正负编译入口选择证据和独立 catalog 发现证据。验证包含没有命中符号的工程/成员；不能只验证最终选中的入口。编码后的源码变化、库内容变化、清单改写、新增散文件或先前未导入光标文件的入口关系变化，都会丢弃旧帧。目录/清单的物理校验要求 catalog 携带发现验证器；普通客户端 catalog 仍由主机维护成员完整性与配置代次。即使没有符号，也保留光标源、入口选择和范围证明。

主线程继续检查请求身份、输入队列、文档身份/版本、输入与配置代次，只发送已编码的帧。关闭光标没有文档槽位，但仍受全局输入和配置屏障保护。大型结果的 DOM、行、证明和图在 worker 释放，调用者只取得一次 malloc 帧和统计。原来的单范围引用、准备重命名、函数族和重命名 API 保留。公共请求 ID 验证与空 catalog 构造复用到符号/重命名入口，保持现有行为。

沿用现有 64 范围/打开文档、65536 绑定、16 MiB 上下文、128 MiB 已知守卫载荷、32 MiB 合并行与证明、7 MiB 结果和 8 MiB 帧等限制；请求 ID 延续 65535 UTF-8 字节且不含 NUL 的约束。guard 去重使用短期 XRT map。分配器、map scratch、AST/IR、并发快照、缓存和调用者保留载荷另计，这些数值不是进程 RSS 总预算。源码与目录校验不是原子文件系统快照，管道写入仍由主线程执行。

新增 19 场景原生夹具覆盖三个工程、关闭成员、散文件、只读导入库、虚拟未保存文件、原生声明去重、无符号、非法位置、ID/提交边界、编码失败、早期/编码后失效，以及清单句柄真实打开时的取消。取消期间保持 pending 和非 Idle，实际句柄关闭与 worker 清理后才确认退出。新增 24 个真实协议场景覆盖有类型的精确 ID、完整范围、关闭光标与其他 overlay、有符号版本号、协商证明、无工作区操作、BOM/CRLF/Unicode/UTF-16 和队列中的取消/输入/配置/根目录失效。

重新构建 122 个原生单元、140 个 GUI 单元及 72 成员核心归档。协议回归同时执行既有引用/证明、符号/导航/刷新、配置/文件、重命名、绑定/泛型/属性、补全和诊断检查；IDE 回归包含 C/xlang 编辑、删除/撤销、Unicode/IME、焦点及引用跳转。实际编译的反例覆盖只搜当前工程、漏前/后范围校验、漏源/负路由证明、误用写入策略、忽略 includeDeclaration、改变 ID、提前 Idle 和接受非法位置。验收计数、实际依赖与外部原始材料以 `dev/release-materials/provenance/lsp-workspace-references-20261116.json` 为准。

本阶段没有安装默认 IDE/语言服务、替换 SDK 或发布线上更新。默认运行库与当前选中 SDK 仍需要对齐，根编译器资产与冻结前端/XRT 的差异也必须处理。自动发现接入、其余 LSP/静态检查/编辑态补全，以及整体延迟/RSS/长稳/Linux/故障准入继续；不包含 DAP 和运行/调试态补全，也不声称已经达到整体无迟滞目标。
