# 文件关联与后台启动

Windows IDE 在“设置 → 文件关联”管理当前用户的文件登记。操作按钮仅有“关闭”和“确定”：

- “关闭”、标题栏 X 和 Escape 均丢弃本次草稿，不修改文件关联或提示设置。
- “确定”按全部勾选结果应用：勾选建立或修复登记，未勾选取消本路径拥有的登记，全部不勾选则全部取消。成功后保存选择和提示设置并关闭；失败时保留草稿供重试。
- “不再自动提示”位于固定底栏左侧，与右侧按钮垂直居中；只有确定才保存它。默认窗口约 486 × 298 DIP，内容超出时单独滚动。
- 当前关联状态直接显示在各复选框右侧；“当前已关联”为主题中的绿色，“当前未关联”沿用正文颜色。状态来自实际有效关联，不随尚未确定的勾选变化；已登记但尚待 Windows 确认仍显示未关联，查询不可用时显示状态未知。
- 复选框使用与填充色不同的内部对勾颜色，适应四种内置主题。这是 IDE 主题映射的修正，XGE 原生对勾绘制保持不变。
- 文件关联窗口不提供最大化按钮，双击标题栏和拖动边角均不改变尺寸；字号、DPI 和视口变化仍由布局系统适配。

| 文件 | 默认选择 | Explorer 打开命令 | 内嵌图标资源 |
| --- | --- | --- | --- |
| `.xlw` 工作空间 | 是 | `"xlang_ide.exe" --workspace "%1"` | 203 |
| `.xlp` 工程 | 是 | `"xlang_ide.exe" --project "%1"` | 202 |
| `.xl` 脚本 | 是 | `"xlang_ide.exe" --open-file "%1"` | 201 |
| `.c` C 源文件 | 否，独立选项 | `"xlang_ide.exe" --open-file "%1"` | 204 |

实际命令包含 IDE 的完整路径，脚本通过关联打开时只进入编辑器。
SVG 源文件和九种尺寸的 ICO 在 `ide/data/file-icons/`，由 RC 编入 GUI
可执行文件，无需额外部署图标。开发时可用 `python ide/tools/make_file_icons.py`
重新生成（需要 Pillow 和 Windows Consolas 字体）。资源 ID 保持稳定。

登记仅写 HKCU 下的 ProgID、OpenWithProgids、Capabilities 和
RegisteredApplications；不覆盖已有扩展名默认值，不写 Windows 保护的
UserChoice。Windows 10/11 需要用户选择默认应用时，建立登记后打开系统页面。
状态列表分别显示“登记完整”和“当前有效默认应用”。便携目录移动后重新登记即可
修复命令和图标路径；取消勾选只移除本路径拥有的记录，保留其他编辑器与未知元数据。
登记失败回滚已经写入的值；本程序的多个实例使用互斥锁串行登记。

用户可关闭自动提示；文件类型选择和提示开关保存在
`associations.types`（位掩码，默认 7）与 `associations.prompt`（默认 true）。
关闭开关后仍可从设置进入。登记过程中暂不允许关闭操作或退出 IDE。

启动按以下顺序执行：

1. 命令树先显示 `【命令列表加载中 ...】`。工作线程读取、解析目录，准备索引、
   补全详情和树描述；主线程通过批量节点接口交付，恢复稳定条目和阅读状态。
   第一帧不等待目录；加载失败保留已有快照并允许重试。
2. 目录交付后，工作线程检查文件关联。需要提示时排队等待其他模态窗口结束，
   不抢走当前对话框的焦点。
3. 关联检查结束后，工作线程准备并启动独立更新器。更新器继续负责网络与验证，
   UI 只轮询完成结果。手动命令可以主动发起相应操作。

所有 XUI 控件操作留在 UI 线程。后台任务拥有自己的输入和结果，不保存 app 或
控件指针；目录重载与关闭会退役旧任务。按需渲染期间用有限频率的下一帧请求
接收后台结果。隐藏诊断不自动检查关联、弹提示或启动更新器。

专项验收（`build.ps1 -Tests` 负责链接；测试程序不随发行包交付）：

- `file_association_test.exe`：仅在独立 HKCU 测试树写入，覆盖失败回滚、路径修复、
  C 选择、其他编辑器默认值及未知字段保留；真实默认应用查询只读。
- `catalog_job_test.exe <commands.json>`：后台准备、拥有交付、取消和错误。
- `startup_catalog_view_test.exe <可暂时重命名的目录副本>`：首帧占位、加载时编辑、
  待交付查询、稳定 ID、重载失败与关闭；不要传入发行目录的原文件。
- `association_view_test.exe <独立验收目录>`：模拟登记后端，验证关闭不写入、确定混合／全部取消、失败不保存、三种字号及三种尺寸下的底栏对齐、滚动和字体更新；不修改真实关联。
- `startup_services_test.exe <独立验收目录>`：该目录必须放置由
  `startup_update_stub.c` 编译的 `update.exe`，使用离线子进程验证顺序与退役，
  不访问线上更新服务。

组件测试通过 `catalog_ready.h` 等待目录交付；生产启动与首帧延迟由专项测试独立验证。
