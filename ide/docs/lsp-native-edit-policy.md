# 原生候选与编辑事务的来源策略

M7b6c，2026-11-14。`editor/native_edit` 将已经通过实际原生 RPC、覆盖率与完整来源校验的候选，连接到已有混合编辑事务。当前提供分线程调用接口及真实集成夹具；尚未启用菜单、标准 rename/applyEdit，也没有自动写入用户文件。

调用顺序为：后台 Prepare → owner Capture → 后台 Stage → owner Arm → 后台 Apply → owner Publish → 后台 Finish → owner TicketDestroy → 后台 Destroy。单个宿主调度器必须串行驱动这些步骤。UI/store/编辑器仅在 owner ticket 内；后台对象不保存 GUI 指针。候选新增独立引用计数，控制器释放自己的引用后，事务仍可保留计划、来源与原始调用，完成检查、撤销和退役。

Prepare 用 XRT 打开并保留所有未编辑的磁盘依赖，允许其他读取、禁止普通写入和删除，再完整验证原始候选。关闭的编辑目标交给现有事务固定。Stage 完成后核对实际文件 pin、原始物理身份、完整元数据、原始字节长度与 SHA-256，拒绝 Prepare 与 Stage 之间发生的同字节替换。所有命名模型都进入物理别名检查，包括保留但已经关闭的模型；原始请求的全部模型顺序、身份、版本、语言、路径和状态仍在 Capture、Arm、Publish 前后比较。

原始来源守卫不能在事务持有独占字节锁时再次从另一句柄读取目标，也不能要求已由事务写成 after 的目标仍等于 before。新增私有的单次证明替代接口只供拥有已核验 pin 的宿主使用：以原始不可变磁盘报告填入本次 memo，逐字段比较，路径仅允许同一规范名称的不同拼写。其他来源、缺失路径探测、环境与解析配置照常验证。替代不跨调用复用，不从协议输入建立权限，不能创造覆盖率、pin 或写入授权。

Apply 的组边界重新验证依赖句柄及名称元数据、真实目标 pin 与当前已核验 writer 状态，然后验证全部原始守卫；逐目标仍由原有 writer 独立完成完整 before 检查、日志意图、实际写入、截断、flush 与完整 after 检查。原始来源图不按目标数量反复读取和哈希。RESTORE 使用事务已经持有的身份、恢复数据与宿主恢复许可，不以旧请求仍然有效或取消已经解除为条件。界面已经提交的 outcome 优先，即使随后取消也不能回滚已发布编辑。

宿主仍须提供完整保护路径、原始连接/工作空间/配置门槛、确认结果和实际源码读取屏障。原生来源守卫验证的是明确捕获的包路径与解析上下文；IDE 进程环境发生变化的准入由必需的宿主门槛检查，不能把不可变上下文当成对当前进程环境的重新读取。发现日志或恢复不确定时，保持屏障并保留恢复目录，交由明确恢复决策或最终关闭处理；销毁对象只释放资源，不回放日志，也不代表可以恢复其他读者。现有事务支持的本地固定文件、普通共享规则及字节锁并不是跨进程文件系统原子事务；预先建立的可写映射、内核过滤器、恶意卷重映射仍不在用户态保证之内。

默认组合已知存储预算为 256 MiB，上限 512 MiB，包含候选、策略和原有事务预算；策略预留 16 MiB，目标最多 512、原始唯一来源最多 65,536。共享请求文本、XRT/OS 句柄、allocator 和编译器内存另计。没有整体时延、进程 RSS、Linux 或完整性能资格声明。

验收使用真实服务返回的五目标候选、实际 XUI 文档和语言进程租约，后台执行 Prepare/Stage/Apply/Finish，owner 执行 Capture/Arm/Publish。覆盖成功提交、原候选引用释放后继续执行、其他依赖的已有/新增写句柄冲突、同字节身份替换、保护根、隐藏命名模型的真实卷 GUID 别名、C 文本变更、宿主环境门槛、中途取消、部分写入、取消后的回滚和提交后日志 flush 失败。Apply 内的 XRT 来源正文读取计数为零；这不代表没有 writer 的完整字节验证或系统 I/O。隐藏别名夹具显式构造保留名称但关闭的模型槽位：普通 Open 会规范化别名，普通 Close 会清除路径，不能把人工构造的对抗状态描述成常规关闭行为。恢复不确定的场景使用最终关闭，绝不自动恢复读者。

最终专项通过 747 项检查，原生与配对 GUI 的批量证明夹具各通过 1,378 项；另执行 85 个协议场景、55 组 GUI 回归及实际 C/xlang 启动检查。8 个独立错误实现被断言拒绝，实际选择的源码、头文件、对象和链接输入均记录身份。

验收记录见 `dev/release-materials/provenance/lsp-native-edit-policy-20261114.json`。后续仍需把异步事务调度、完整宿主保护集合、确认/应用/回滚/恢复界面接入真实 IDE，再启用标准协议操作。引擎资产对齐、泛型与外部来源资格、整体性能/资源及跨平台验收继续开放。C LSP 仍关闭，不包含 DAP 或调试态补全。
