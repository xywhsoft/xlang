# 当前异步工厂前端与 AST 替换所有权

本阶段接入 2026-11-03 已提交编译器前端的异步工厂、回调结果和泛型绑定语义，继续直接使用原始检查器及 IR 生产者。公开 AST／IR 布局、原缓存预算和未知输入拒绝规则保持。

## 精确前端组合

原 C interop 表示族保留两组完整、独立验证的源文件身份。新组只更新 `xl6_sem.c`、`xl6_sem_c_owned.c`、`xl6_ir_bound_method.c` 和 `xl6_ir_lower.c`；其余 352 项仍须匹配原固定字节。版本选择只是候选选择，完整准备和角色校验才允许使用。已知 LF／CRLF 对应可以恢复原固定内容，任一混合版本或未知改动都会拒绝。旧组继续支持历史比较。

异步 worker 的真实声明生成被接入既有有序副作用记录。实际调用方改写标记不纯，即使原生产者返回已经存在的 worker，也继续观察这次改写。声明分配或检查失败留下不完整记录时，沿用完整原生检查，不把它当作可以回放的标量结果。

## 节点替换的分配身份

原检查器有四处在固定地址整体替换表达式。原生 AST 使用普通堆分配；LSP 私有森林还允许使用 XRT 内存池。直接复制整个结构体会把池身份转移给堆上的旧载荷快照，并使目标池槽丢失归属。

真实旧生产者已复现无效 `xrtPoolFree`，分别覆盖普通回调、可空回调和上下文方法绑定。私有适配现在在原结构体赋值之后、任何释放之前恢复目标分配的池身份，并清除堆快照上的私有存储字段。该操作不分配、不复制载荷，也不更改原生语言规则、源文本或子节点释放语义。仅适用于独占构造期间的表达式，不能用于共享类型叶。

四处适配分别位于普通回调、可空回调、异步开放泛型绑定和上下文方法绑定。每处都有真实前端回归；故障工具逐个移除实际生产者中的归属恢复，要求在真实池释放边界被检测。

当前已通过两个前端各 11 项的精确输入／EOL／混合版本校验。定向当前语义生产者验证完成 520 次有效池释放，重复分析后没有新增滞留分配。30 项编译器及私有正反语料通过 2,779 项完整 AST／索引／IR、Unicode／坐标／声明／字面量编辑、精确命中和旧结果退休对照；包含多个调用方复用同一异步 worker。

完整全新构建 233 个编译单元、135 项原生程序、141 个私有 AST 消费者，835 项输入与 137 项产物身份核验通过。63 条验收命令覆盖既有 56 套协议、当前语料 188 进程／240 检查、424 项导航和 38 项补全对照；四个实际节点替换遗漏均在真实池释放边界被拒绝。定向旧支持核心比较仅用于提前排查，最终以完整重编译结果为准。源与验收工作区为 `ide/build/Release/lsp-current-async-frontend-20261103/`。首次完整构建在补充发现第四处所有权问题后主动取消，原日志和取消原因保留。

## 已确认的后续问题

对真实 `Reader` 做空前缀成员补全时，除 `Read`、`Factory` 外，还返回了编译器生成的 `__xl_c_owned_async_*` worker。这不是增量与全量结果比较能够发现的问题：两条路径会给出相同的错误可见性。原协议结果保存在本阶段 `async-member-probe-v1/result.json`，下一阶段需要按原生生成声明身份处理可见性，保留合法用户名称；同时核对异步方法详情的返回类型／异步标记展示约定。该问题尚未修复，不将本阶段原生一致性通过描述为完整补全正确性通过。
