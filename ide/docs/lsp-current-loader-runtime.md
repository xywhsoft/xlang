## 加载与失败传播

新版共享加载器返回三态结果：命中为 1，未找到为 0，身份比较或来源报告失败为 -1。IDE 的借用文本构造、检查与语义入口直接保留这个区别，失败时终止构造或分析，避免把资源不足当成未找到后继续读取磁盘。绝对路径、Unicode、大小写、长路径及解析回退仍由共享编译器实现。

依赖观察只记录原查找成功完成后的命中或缺失。报告失败仅使绑定该报告的使用范围和拓扑证明失效；检查旧结果或其他报告不会污染当前查询。原解析器缓存边界和完整回退路径保留。

包的 `packageInfos`、`runtimeSymbols`、编译接口解码与释放继续使用上游代码。九个名称映射／声明准备辅助函数与旧基线逐正文相同，既有有界索引仍观察原有追加及重命名。注册的编译包接口包含虚拟来源，目前没有对应的完整快照与图证明；正常完整展开保留，同时拒绝未证明的函数体、输入范围和模块图复用。这不表示 IDE 已完成编译包目录及其全套增量依赖管理。

准入额外固定加载、报告、包、公共声明及实际包含闭包的 30 份资产；与基础类型索引组合合并后为 46 份。正常入口不会接受旧报告与新加载器等混搭。

已核验的新 XRT 相对等待接口采用有符号毫秒，旧 SDK 使用微秒。项目引用和语言客户端继续保持原来的 10 毫秒及 1 毫秒恢复检查间隔；测试时钟和截止时间也保持原时长。识别使用已核验的公共接口标志，不能依赖两者均为 2 的主版本号。实际未触发事件的 20 毫秒等待在两个运行时上通过，属于单位适配检查，不作为性能指标。

Windows 进程树修补仍只改动原来的停止函数。Job 的创建、平台启动、终止和句柄释放正文保持一致；新版销毁函数新增的所有权变更作用域保留。真实父进程先退出的测试确认旧、新运行时均清理子进程并保留父进程退出状态；未修补运行时被同一断言拒绝。

新版文件证明使用 Common Era UTC 毫秒字段，旧版使用 Unix 微秒字段。IDE 诊断接收器接受完整的一种字段对，拒绝混用、缺失、溢出和非规范十进制；旧版本兼容保留。引用协议测试同步识别这两个明确格式。新增毫秒用例能拒绝旧诊断接收器，真实 stdio 的诊断依赖和流接收也已通过。
