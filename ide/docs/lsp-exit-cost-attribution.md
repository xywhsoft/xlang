# 退出计划复用的开销定位与计时校准

本轮仅完善诊断和采样控制，不替换已交付的 0.109，也不放行退出计划缓存。此前正式矩阵的 94／96、88／96 结果保持原样。

## 构建和程序身份

生命周期工具现在可读取正常构建目录之外的完整原生验收记录。记录必须覆盖全部原生程序，并匹配实际路径、摘要和退出码；修正夹具只能使用构建元数据显式登记的源文件、链接和输出。实际链接对象和 core 归档成员仍逐一核对，不能用“拟编译”的同名对象代替。

```powershell
python -X utf8 -B ide/tools/build_lsp_lifecycle_profile.py `
  --build ide/build/Release/lsp-exit-production-20261122/native-stable-v1 `
  --native-acceptance ide/build/Release/lsp-exit-production-20261122/native-stable-accepted-v1.json `
  --output <新的诊断构建目录>

python -X utf8 -B ide/tools/profile_lsp_lifecycle.py `
  --profile <诊断构建目录> --runtime-root release/win_x64 `
  --functions 32 --pairs 2 --output <新的采集目录>
```

派生构建可以显式传入 `--build-metadata`。工具不改写历史构建或验收文件。`--runtime-root` 为正常和诊断程序建立排他创建的临时文件名，核对字节并在子进程结束后清理；不覆盖 `xlang-ls.exe`。异常、失败复制和只读源文件均有检查；如别名被外部改写，则保留该文件并报告错误。

本轮正常程序分别为：

| 配置 | SHA-256 前缀 | 状态 |
| --- | --- | --- |
| 原生退出计划、独立节点 | `13ab5b9d3cc2` | 已交付的保守 0.109 |
| 64 KiB 规模准入的退出计划缓存 | `470841ad853a` | 功能通过、性能未放行的候选 |

两组诊断程序分别重编十个真实 TU。各自通过 11 项检查，包含 8 项真实 C 计时／取消／错误变体／签名检查和 3 项无效记录拒绝。32／512 函数、单文件／导入、字面量／声明改动共 64 个进程、960 次请求；每种配置下，正常与插桩程序的诊断、规范化输入摘要、版本、上下文和结果状态一致。工作统计、耗时和请求号未作为这组相等对照的条件。每个进程严格要求 15 个 check、15 个 snapshot 及至少 14 个 retire 帧，不把退休序号当作请求号。

## 已观察的阶段开销

以下是显式关闭空闲工作空间索引时的包含式诊断中位数。父子阶段重叠，不能相加，也不等于正式程序或 IDE 的端到端性能。每种配置只有两对进程。

| 512 函数场景 | 原生退出计划（ms） | 缓存退出计划（ms） |
| --- | ---: | ---: |
| 单文件，字面量改动 | 10.85 | 4.51 |
| 单文件，声明改动 | 12.96 | 4.73 |
| 导入，字面量改动 | 12.38 | 4.35 |
| 导入，声明改动 | 13.20 | 4.69 |

完整验证、raw IR、语义和索引仍各有成本，整体时间并未在所有场景一致改善。小文件也没有出现一致的单阶段回退。因此，目前不能把旧矩阵的所有失败归因于缓存本身、某一个字段或一次分配。

## 同图像校准

先用同一保守图像的两份副本采集 16 个进程、1,040 次原始查询和 6,144 次补充查询，28 项门限有 4 项失败。随后使用当前工具预登记四组控制，每组保留同样计数、原有 5% 相对限制、0.5 ms 墙钟容差及 CPU 精度要求：

| 后台工作空间索引 | CPU 分配 | 同图像失败项／总数 |
| --- | --- | ---: |
| 保留程序默认值 | 不限制 | 7／28 |
| 显式关闭 | 固定 | 4／28 |
| 显式关闭 | 不限制 | 1／28 |
| 保留程序默认值 | 固定 | 0／28 |

这些结果说明旧的小文件计时存在需要控制的变异，不能证明具体因素的因果关系。四组按预定顺序采集，运行机器不独占；单轮 0／28 不能证明整个协议已经可靠。此次校准采用连续查询，不覆盖旧正式矩阵的 500 ms 编辑间隔。

新增诊断选项：

- `--background-workspace-symbols default|on|off`：默认不改变服务设置。显式关闭的观测不能代替正常后台功能下的资格。
- `--server-cpu-mask` 和 `--client-cpu-mask`：只作用于本次测试进程，要求独立进程模式、两个正数且互不重叠。校验实际生效的掩码，并在成功和异常退出时恢复驱动程序原值；不修改系统电源或优先级。

本机通过 Windows 拓扑 API 选择四个不同物理核心各一个逻辑 CPU 给服务，另两个物理核心给驱动；掩码分别为 `0x154` 和 `0x401`。这是本机采样参数，不能作为其他机器或发行程序的常量。35 项来源／别名检查、9 项 CPU 控制检查及 60 次协议功能查询通过；非法程序启动也验证了 CPU 分配恢复。

下一步仍需验证原编辑间隔下的校准，并继续消除缓存接入对已有热路径的额外工作。不能通过重复原失败图像、放宽门限、忽略慢样本或关闭发行功能来放行优化。原生回退、完整验证和当前可打包程序保持。
