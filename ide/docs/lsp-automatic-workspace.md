# 标准客户端的工作区自动发现

M7b6s，2026-11-16。原生服务 0.106 将已有后台发现组件接入标准 stdio 生命周期。标准客户端提供根目录即可加载 `.xlw`、`.xlp` 和闭合 `.xl` 文件，不再依赖 IDE 私有配置包来建立全局分析范围。IDE 自己仍以完整显式配置管理工作空间、工程、文件和构建配置，自动发现不会覆盖它。

## 配置与执行边界

`initializationOptions.automaticWorkspaceDiscovery` 在原生后端默认开启，可以显式关闭；CLI 后端不启用这一能力。有效的 `analysisConfiguration` 总是优先，并终止自动发现及其等待请求。自动 catalog 使用内部 epoch 0，客户端显式配置继续使用原有的正数、递增 epoch；多次自动发现不会占用客户端下一次要发送的编号。

初始化只保存根元数据和包路径。收到 `initialized` 后才调度目录及清单工作，重复通知幂等。复用既有 XRT task pool、项目/工作区解码器、分析上下文和 guarded catalog，不另写项目解析器。根集合、清单或相关成员变动会合并调度，输入通知尚未处理完时不启动/安装发现结果。

stdio owner 不枚举目录、不读取清单或源码正文。worker 生成不可变 catalog，完成目录及原始清单验证后，owner 仅准备最多 64 个打开文档的绑定并提交新范围。普通源码内容编辑沿用原生增量分析，不重扫目录。默认忽略目录、清单/目录容量、完整性失败和别名策略沿用[发现组件](lsp-workspace-discovery.md)；这些限制没有被放宽，也不等于最终的进程 RSS 或大型工作区指标。

## 请求、通知与新鲜度

发现尚未完成时，依赖工程上下文的请求保留不可变消息引用，不在 owner 上深拷贝或序列化请求正文。等待队列最多 16 个请求，单项 128 KiB，累计 1 MiB 已知传输字节；DOM/分配器开销另计。根、输入、配置或租约变化取消旧请求；成功安装元数据后仍核对原输入 serial 和根修订。取消请求保留原 ID，满队列明确返回忙状态，发现失败不返回部分全局结果。

服务声明 `workspace.workspaceFolders`，并在支持动态注册的客户端上注册 xlang 清单、源码及 C/头文件变更通知。依据：[初始化](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/general/initialize.md)、[工作区文件夹变更](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/workspace/didChangeWorkspaceFolders.md)、[文件变更注册](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/workspace/didChangeWatchedFiles.md)。注册失败不会阻塞原生分析，也不会反复注册。服务接收注册响应时不把响应再次当作请求回复，避免错误回声。

过滤器使用既有的原生词法路径和忽略规则，不探测文件属性。工作区显式引用的工程可以位于 `extlibs` 等忽略目录内；相应清单通过已准备的 catalog 元数据识别，不能被目录过滤规则丢弃。

没有通知时也不通过目录时间戳猜测成员。全局引用、重命名和符号的既有 worker 发布守卫会验证目录与原始清单；失败永久标记共享证据。owner 只观察这个原子标记并重新调度发现。原请求可返回内容已变化错误，后续查询使用新范围。缺失根/损坏清单停止自动重试，下一次相关输入或查询可在修复后重新发起，不建立空转的文件系统轮询循环。

`xlang/workspaceDiscoveryState` 只返回有界计数、模式、错误和线程身份；它在源码租约期间也可读，不重置后台符号索引的安静等待时间。它不提供新的文件系统有效性证明。

## 源码租约和停止

发现任务纳入原有源码读取屏障。取消 future 或删除请求引用都不代表目录句柄已退出；只有 executor 的物理 Idle（含清理/finalizer）才允许确认租约。租约期间继续延期输入通知，恢复后重新发现并按顺序处理通知。显式配置和关闭服务也取消旧发现；服务退出等待实际 worker 结束。

测试专用目录门闩先真正打开目录再阻塞 worker，验证 owner 仍可响应、租约不能提前确认、父范围取消后新范围不会被覆盖，以及退出必须等待实际句柄清理。门闩仅存在于独立测试链接变体，不进入发布服务。

本阶段还修正了独立工作区符号入口的包路径释放：`xideLanguageCheckPackagePath` 返回 CRT 分配的缓冲区，应使用 `free`。环境路径仍区分未设置和显式空值；不把 CRT 指针交给 XRT 私有分配器。

## 验收与后续

最终候选通过 220 个原生程序、21 组既有协议回归（374 项）、26 项自动发现、6 项真实目录门闩以及 19 项当前所有权协议检查。IDE 使用匹配 SDK 完整重编译 140 个单元，通过 55 组配对测试和 47 个真实编辑器模式。安装到本地 `release/win_x64` 后，重新验证 26 项自动发现以及 C、xlang 各 24 帧启动渲染；其余运行文件、引擎、配置及原有临时目录均保留。

材料索引：`dev/release-materials/provenance/lsp-automatic-workspace-20261116.json`。记录原生/协议/IDE 回归、真实目录门闩、旧 0.105 无自动发现能力的对照、源/头/对象/链接身份和本地运行程序摘要。早期快照缺少夹具材料、测试局部变量冲突、路径分隔符错误及错误的夹具路径假设均保留原始记录；只在输入和全部公共头验证一致后续用已有对象，修复的夹具和生产单元独立重编译。

本阶段不宣告整体性能、内存/耐久、Linux、物理 Windows 7 或完整 LSP 目标完成。64 角色等既有范围限制、大型工作区增量发现、共享正文捕获、补全尾部延迟及其他适用协议能力继续推进。仍是外部程序，保留可嵌入的原生组件；不包含 DAP 或运行/调试态补全。
