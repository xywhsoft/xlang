# SDK48 极长行排版与绘制诊断

2026-10-11，当前完整 IDE 候选使用的 SDK48 已完成独立排版计时和原生窗口主线程采样。结果支持继续检查整段排版及首次绘制缓存生成的遍历成本。此次诊断没有改动应用或 SDK；极长行性能仍待验收。

可运行候选、双语法预览与完整回归结果见[集成候选验收](integrated-editor-sdk.md)。此前的 SDK46 采样见[早期绘制诊断](large-source-paint-profile.md)，其耗时不能直接代表当前版本。

## 当前排版计时

严格 O2/Werror 编译的原生夹具通过公开 SDK 接口排版同一份 16 MiB xlang 单行及其 2 MiB 前缀。主字体为 Noto CJK 20 px；前缀保持完整 UTF-8 边界。夹具不绘制，不创建窗口，实际退出 0，完成 16 条观测。

## 原生窗口主线程采样

匹配 SDK48 的原生窗口探针在从未切换的私有 Windows 桌面运行。GDB MI 明确选择窗口主线程，完成 168 次调用栈观察；调试器退出 0，原生进程正常退出并完成 45 条检查。

| 调用栈包含的函数 | 样本数 |
| --- | ---: |
| 整段排版 `__xgeTextShape` | 52 |
| 流式绘制 `xgeInternalTextPaintStream` | 45 |
| 候选收集 `__xgeTextPaintCollectPosition` | 10 |

栈中相互包含的函数不能相加，也不能换算为时间占比。观察最多保留 15 层调用栈；调试暂停和 Windows 调试堆改变运行行为，退出清理也占据较多样本。该运行验证诊断过程和原生探针正常结束，不计作无调试性能测量。

## 后续改动范围

当前字形查询使用哈希桶，字体缓存从字体对象直接取得；没有发现先前怀疑的全局字体或字形线性查找。单次排版还保留有界的码点、字偶、Emoji 和原始字形度量复用，已有的活跃字体比例及图集状态规则继续有效。

流式绘制在首次生成可见缓存或缓存失效后，仍会完成整段排版、字形图集准备和最终度量。现有记录支持把这条完整遍历作为下一次实验的重点；尚不足以证明新增某一种查询缓存会改善整体交互。

改动须保留最终升部、行高、画笔浮点相加顺序、字偶调整、Emoji 与 SVG 的裁剪及失败回退。字体或资源状态变化、取消、非法 UTF-8、检查点恢复与内存不足仍应走正确路径。验收继续使用同批 C/xlang 实际窗口用例、逐像素比较和原生响应测量，不能以独立排版计时代替。
