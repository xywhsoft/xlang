# IDE 语义着色的请求与绘制

2026-11-10，M7b3b。在 M7b2 服务协议和 M7b3a 后台解码基础上，IDE 主连接现在协商并请求 `semanticTokens/full`、`full/delta`，将后台验证过的不可变字节范围用于可见标识符的颜色覆盖。尚未替换默认发行程序，完整 LSP 与性能准入继续。

## 绘制接口

XGE 上游增加 `xuiCodeEditSetTokenStyleResolver`／`GetTokenStyleResolver`。回调在拥有者绘制线程借用文档及词法 token，返回主题样式 ID；未知、透明或失败结果回到原词法主题／CSS。正常跨度、保留跨度和长行分块共用实现；回调获得文档级 UTF-8 字节偏移，绘制内部保留行内偏移。设置回调只请求重绘，不复制 token、不改词法缓存，也不把样式变化转成文本布局失效。

IDE 通过实际已加载 XGE 模块查询这两个函数，避免新增静态导入入口。缺少接口时不协商语义 token，继续词法编辑。正常发行仍必须更新匹配的 SDK、DLL 和 IDE；此可选查询不代替匹配集规则。

只有 IDENTIFIER／TYPE 的完整词法跨度与语义范围精确一致时才覆盖。类型、类、接口、枚举、结构、类型参数和属性使用 TYPE；函数、方法、枚举成员和 readonly 使用 NUMBER；其他变量／参数使用 DEFAULT。保存的是角色，不是主题颜色，因此切换主题不重新分析。关键字、注释、字符串、折叠及原来的 token 缓存保持各自所有权。

绘制中的守卫只读取活动文档、文档身份、版本、语言、外部冲突、输入／配置代次和连接代次，以及该编辑器的 IME 标志，再做精确范围二分查找。不在每个可见 token 上遍历模型、检查磁盘、扫描正文或改变引用计数。

## 请求、来源与失效

复用已有的原生主连接、工程配置、文档同步及输入收据；不启动第二份服务。着色也不拥有连接的启动／恢复策略，不能在用户取消自动检查后自行重启它。当前 UI 对已命名 `.xl` 文档启用，服务能力或样式接口缺失时保持词法颜色。

稳定输入合并 75 ms 后发出请求。字符串 ID 使用独立命名空间，延迟或取消后的着色响应仍可识别并交由后台释放。正文从 `xlsSyncRetainText` 获得与已发送 URI／wireVersion 一致的不可变租约，UI 不复制或重新验证整份正文。

每次最多一个当前逻辑请求、一个当前整数历史和一个待处理完成结果，继续使用解码器的单个运行任务、有界等待及退休槽；取消后的旧任务仍计入这些物理槽。旧 JSON、旧结果数组及未等到响应的文本租约都在 XRT 工作线程释放；新增的 `DiscardInputs` 不分配任务对象，也不改变当前 token。只有最终销毁会等待线程。

只有同一文档身份、同一连接的旧整数历史可用于 delta；未知历史由服务返回 full。接收 full 请求的响应时不给解码器旧 base，因此错误返回的 edits 不能借用其他历史。发布重新核对当前身份、版本、代次和同步／输入收据；ID 或历史不是新鲜度证明。

文档修改、其他打开输入变化、语言／路径变化、真实配置或连接重置、磁盘通知和服务失效通知，都会先撤销旧颜色。IME 事件按 XUI 的事件派发时序使旧颜色失效，组合期间不发着色查询。绘制额外检查版本和代次，防止未消费的旧回复露出。源错误 null 是合法的空层；错误、超时和无效结果保留词法编辑，并对同一输入停止重试，下一输入代次可以恢复。

## 构建与验收

材料位于 `ide/build/Release/lsp-semantic-color-render-20261110`，F 盘保存源／对象／日志和截图。程序以拥有的临时 EXE／DLL 别名在真实 `release/win_x64` 执行，保护默认运行程序和用户数据。测试 DLL 字节与新 SDK 完全一致；仅测试导入库把 DLL 名改为唯一别名，正常候选仍链接 SDK 的 `xge.lib`。

- 匹配的 IDE XGE 配置完整重编 173 个单元。公共 ABI 指纹更新，未将新头文件与旧 SDK 对象混用。沿用该 SDK 的原有常规警告配置，不宣称整个 SDK 通过 Werror；新代码另对当前上游头进行 Werror 编译。
- 8,721 个既有预处理声明及打包 pragma 保持；只增加一个回调 typedef 和两个 API，PE 只增加两个函数导出，无导出删除或新增 DLL 依赖。
- `xui_token_style_resolver_test` 的 44 项检查和原有全局配色夹具通过，验证第二行的文档级偏移、词法缓存逐字节保持、CSS／透明／未知样式回退、视区、两种跨度绘制、70,000 字节分块长行、不重新 shaping 和清除回调。
- 解码器原有 175／332,391 项断言（含大输入构造）及新增 18 项暂停线程检查通过，验证未收到回复的文本租约也由工作线程释放；四个原有真实 C 破坏对照继续检出。
- 在最终匹配 SDK／GUI 对象上，另四个实际 C 破坏对照分别删除绘制的输入代次、连接代次、文档身份及词法种类守卫，均由真实联调以退出码 1 检出。
- GUI 完整重建 116 个共享对象。新联调使用真实服务／真实 CodeEdit，从标准 full/delta 走到实际绘制回调和浅深截图；覆盖立即编辑撤销、撤销恢复、其他打开输入、IME、语言切换、源错误恢复、磁盘依赖及关闭，并验证 full 请求不能接受依赖旧 base 的 edits。最后一份新夹具 71 项检查，要求第 12 行中文／emoji 后的实际函数跨度命中绘制；两种主题各检出 72 个暖色函数像素，区别于原词法中性色。配套原有输入／补全／签名／引用等 GUI 回归一并执行，最终清单和结果见阶段 provenance。

初期失败均保留：测试曾把磁盘 BOM／CRLF 字节偏移当作编辑器规范化后的偏移，并把排队的 IME 事件当作已派发事件；已改用真实编辑器快照和事件时序。完整回归另检出着色逻辑绕过用户取消状态、重新启动连接的生产问题，已删除独立启动逻辑。

初版 27 项 GUI 虽通过，截图复核仍发现函数名没有变色：回调误用了绘制内部的行内 token，且原夹具只统计调用次数。新增第二行原生断言和实际目标函数跨度／像素证明后，旧 SDK 和旧 GUI 均明确失败。随后将回调恢复为文档级字节偏移，重新全量构建 173 单元 SDK 和全部 GUI。旧绿色资料作为覆盖不足的中间尝试保留，不用于最终着色准入。XGE 上游分别提交接口和全局偏移修正，阶段索引记录两个提交。

这些是功能、所有权、既有交互和绘制成本边界的验证，不是整体性能达标。原正式矩阵及 A/A 失败保持；重命名、格式化、引擎资产对齐、完整端到端性能、大工程和长期运行验收仍未完成，DAP／调试／运行态补全仍不在本任务范围。
