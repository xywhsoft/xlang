# IDE 默认自动诊断（开发服务 0.27）

命名 `.xl` 文档打开、未保存正文变化后，IDE 的现有主诊断／导航连接自动同步和接收文件级诊断。服务使用共享原生前端，不调用 `xl.exe`。不要求工作空间或工程。独立补全连接继续禁止自动诊断，防止双份后台分析。工程编译／执行入口及 C 的 clangd 连接沿用既有职责；本阶段不包含 DAP、运行态补全或最终语义增量验收。

## 协商及旧服务

主连接声明 `publishDiagnostics.versionSupport:true`，以及 `experimental.diagnosticInputProof/diagnosticDependencyProof/diagnosticOverlayProof:true`。初始化选项发送 `automaticDiagnostics:false`、`automaticDiagnosticsIfSupported:true`。新服务在完整能力链满足且使用原生后端时启用自动模式；缺少能力或选项类型错误返回 `-32602`，允许修正后重新 initialize。

旧服务忽略条件选项，仍遵守 `automaticDiagnostics:false`，因此不会先启动不受控的自动发布再重启。IDE 仅在确认自动模式和全部证明能力后接通控制器；未满足时继续显式检查及原有复查。用户可用 `--no-auto-diagnostics` 显式选择兼容路径。没有新增常驻服务进程。

## 发布的因果证明

协商 overlay 能力的客户端在每份 `params.xlang` 获得规范 uint64 十进制字符串 `serial`。非撤回通知还带 `overlays:[{uri,version},...]`，精确列出该发布时服务已接受且仍在线的全部文档（最多 64）。撤回不带 overlays。原文件输入证明及共享完整依赖字典继续必需，未协商客户端保持 0.26 格式。

serial 仅随服务接受的 `didOpen/didChange/didClose/didSave/didChangeWatchedFiles` 递增；非法／重复打开、过期或失败修改、非法保存、未知关闭及空文件通知不计入。后台磁盘观察可以改变有效证明而不改变客户端 serial，不能把 serial 当磁盘修订。owner 对在线元数据按全局文档代次缓存一份只读 XRT 数组，复用引用，不扫描正文或访问磁盘。

同步器在每个连接内对实际打开及正文变化分配全局单调的正 LSP 版本。关闭重开、本地文档槽位复用不会复用版本；相同身份的同字节新修订可保留版本。版本到 INT_MAX 时必须建立新连接。原按文档版本的同步 API 保留供旧调用者使用。同步后台任务返回实际发送操作的 URI／关闭元数据，主连接按真实线上顺序计算 serial，不重解码正文帧。

后台接收器先验证整个批次，包括 serial 不大于已经发送的输入边界。每份非撤回通知必须提供 overlays；仅保留其完整依赖字典覆盖的绑定，严格匹配当前已发送不可变同步快照，记录本地身份／修订。缺少、增加或错版的相关绑定使候选失效；无关文档变化不使有效 A 丢失。owner 再比较当前模型身份、修订、路径、语言、外部冲突及尚未发送输入。URI 以线上原拼写核对，路径相关性复用原生规范键。

关闭到磁盘、非 overlay 文件保存／重载、显式跳转发现磁盘证明失效时，还建立该路径的最低 serial。新证明必须来自服务器处理该输入之后；避免关闭后相关在线集合变空，从而误把旧磁盘结果重新激活。失败跳转也发送标准 watched-file 变化，要求新磁盘证明。文件证明仍验证当前文件的原始字节、身份和 LF 规范化正文；serial 不代替这些检查。

## 界面与预算

当前模型变化先按依赖撤销受影响分组及范围，保持无关文件结果。缓存区分待验证候选和可显示分组；编辑器范围仅在模型及证明当前时安装。问题列表被动更新，不抢当前文档或命令帮助焦点；中央底栏仍在左右 dock 之间。C／构建等外部问题列表 owner 及其标注不被自动诊断清空。

每份分组使用连接内唯一的路由 token。关闭／重开、换连接、旧列表点击无法跳到新文档的旧范围。磁盘文件打开前复用既有原始及规范化摘要／身份检查；跨文件依赖的未保存修改由相同主连接更新。

接收线程继续使用现有 8 MiB 单帧、64 MiB／2048 消息传输界限。后台 actor 内部最多两个批次，每批 128 条／32 MiB 原始消息体；owner 另保留一个待提交批次及一条因背压暂存的消息。已完整解码结果按约 0.5 ms 循环预算逐份接纳，安装按约 1 ms 循环预算推进；单次 SDK 操作不被这些预算抢占。单个无效通知使整个批次拒绝，合法前缀不能显示。

候选缓存最多 4096 文件分组、64 MiB 原始通知字节；模型元数据最多 4096 项，路径输入门槛最多 128 项，问题列表显示前 4096 条并注明截断。缓存、字典、正文引用、JSON 堆和已取出结果另外计量，这些不是进程 RSS 上限。超限重建连接并重同步；基础设施／协议错误暂停当前会话，编辑、配置变化或显式查询可恢复。取消检查暂停自动会话，静止文档不会立即把它重新启动。

服务诊断收集器确认入口的磁盘依赖失效后，立即取消该入口旧的导航守卫，避免在下一轮检查前从旧缓存返回类型事实。客户端接收仍有效分组的撤回时，同时撤销共享该依赖范围的悬停、大纲、高亮和待决定义，并重新建立导航收据。已被本地编辑失效的旧分组撤回不能取消更新后的导航输入。默认模式的真实悬停回归覆盖磁盘依赖从 int 改为 string 的场景。

主线程不等待解码／文件读／映射完成，也不在普通模型变化时 join 或重置仍在线的注册表。大对象经同一 XRT 工作线程释放，最终关闭才 join。接收端格式验证、磁盘读取和正文映射复用原有 XRT／快照／坐标模块；GUI 继续由 xge.dll 独占 XRT，独立服务使用编译器 XRT，不混合链接两套运行时。

## 验证入口及限制

`automatic_diagnostics_view_test` 使用真实隐藏桌面、XGE/XUI、实际主连接和缺失的执行编译器，验证默认打开／编辑、跨文件依赖、磁盘替换及跳转、负候选恢复、取消恢复、关闭重开、外部标注／问题列表 owner、385 条真实格式帧的背压、工作线程阻塞期间输入，以及旧结果排空和畸形 serial 隔离。legacy 参数单独验证旧服务的手动兼容路径。

`check_lsp_overlay_proofs.py` 使用真实 stdio，逐份核对发布 serial 对应的完整在线集合，验证无关文件保留较早证明、无效通知不推进、保存／文件通知、连续关闭重开、磁盘转 overlay 再回磁盘、严格初始化类型及失败后重试。组件测试在 GUI SDK 和独立 XRT 两种配置执行。构建、回归及本轮实际帧数据记录在 [长期进度](lsp-development.md)。

自动诊断接入不代表完整 LSP、真正语义／IR／依赖增量、百万行规模或内存验收完成。此前 1 MiB 实际界面补全 P95 仍未达到 50 ms，必须继续优化和复测。
