# 文档符号：函数作用域与能力协商

本阶段修复两个实际复现的问题：异步函数未显示在文档大纲中，其局部变量反而显示为顶层符号；服务没有依据客户端能力选择层级或扁平符号结果。外部函数声明也纳入本次修复。

`async_func`、`extern_func` 在原生索引与兼容字符串索引中统一归入已有的函数查询类别。保持查询枚举值、原生 AST 布局及编译器 ABI，不新增缓存。既有父链过滤因此能正确排除异步函数内部的局部变量，类中的异步函数仍按方法展示。

服务读取 `textDocument.documentSymbol.hierarchicalDocumentSymbolSupport`。仅在显式为 `true` 时返回 `DocumentSymbol[]`；省略或 `false` 返回 `SymbolInformation[]`。非法值拒绝初始化，客户端可修正后重试。规则依据 [LSP 3.17 文档符号规范](https://raw.githubusercontent.com/microsoft/language-server-protocol/gh-pages/_specifications/lsp/3.17/language/documentSymbol.md)。

两种结果直接从同一份已检查、已验证坐标的声明节点生成，不经过内部 JSON 的二次解析。扁平结果保留客户端文档 URI、声明完整范围和最近可见声明的 `containerName`，沿用 4,096 个符号上限、父范围包含检查及完整失败语义。对重复 URI 和名称按最坏 JSON 转义字节保守计费，限制在 7 MiB 响应预算内，超限整体失败。检查版本、来源、配置、取消和后台导航调度保持原有路径。

IDE 显式声明层级大纲能力，自动诊断开关不影响这一声明。能力对象构建失败时中止初始化，避免失去层级能力后继续使用树形解析器。服务和 IDE 必须配对验证。

边界验证另外复现了既有重试风暴：检查成功后，大纲超过符号上限，服务反复开始检查并发送空诊断，原请求一直没有结束。已检查的来源仍有效而无法生成完整符号结果时，现在以 `-32603` 结束请求；来源失效仍走原有失效路径。回归同时检查不发生额外分析，以及修改为较小文档后的恢复。

验证材料记录于 `dev/release-materials/provenance/lsp-document-symbols-20261109.json`：

- 原生索引验证异步／外部函数的事实与查询分类，兼容分类使用同一别名表。
- 实际序列化实现测试层级／扁平结果、局部变量排除、方法类别、父范围、4,096／4,097 边界，逐一注入实际分配和 DOM 操作失败并验证恢复。
- 实际 stdio 验证缺省／关闭／开启／非法能力值、初始化恢复、无 `xlang/check` 的标准查询、未保存内容、BOM／CRLF／Unicode 位置及改名后的新大纲。
- 旧正常服务作为错误生产者：分别复现函数／局部变量错误和缺省能力仍返回层级结构；保留最初测试辅助函数用错的失败记录。
- 完整原生回归、既有协议回归，以及相同服务、冻结 SDK、真实发布 DLL 配对的 IDE 输入／补全／大纲与跳转检查。

最终完整构建为 239 个编译单元、141 项原生测试、146 个私有 AST 消费者，1,404 个输入及 143 个产物一致；21 组协议通过。113 个 GUI 对象与冻结的 180 文件 SDK 匹配，实际发布 DLL 一致，9 项正式服务 GUI 检查通过，包括符号超限后停止请求和恢复。另以仅关闭自动诊断、声明不支持按需查询的受控服务验证旧能力分支。首次直接用新版服务运行 `legacy` 夹具的测试前提错误与超时保留，修正夹具后重新验证，不将它计为产品故障或性能样本。

这是正确性及协议修复，不代表全量性能或完整 LSP 已验收。前阶段性能校准和 P95 失败仍保留，本阶段不重跑原矩阵取优，也不替换默认发布程序。

后续声明投影仍需完整审计字段、枚举成员、导出变量等声明类别，建立可复用的轻量声明视图，再用于工作空间符号索引。多项目编译选项、全局预算、规模和耐久性验收仍在长期任务范围；DAP 与调试／运行态补全继续排除。
