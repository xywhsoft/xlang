# 文档坐标缓存与大文件编辑

2026-10-10，独立 SDK13 新增文档坐标转换缓存；新旧模型等价检查、原生 C／xlang 文件矩阵和相关应用回归通过。16 MiB 超长单行编辑仍有数秒延迟，性能尚未验收。当前应用、固定 SDK、编译器及便携候选保持不变，长期任务继续。

前一阶段见[可见范围缓存](large-source-viewport-cache.md)。本轮以当前状态栏优化后的 83 个应用对象分别链接 SDK11 与 SDK13；两边对象、公开头、编译器版本和文件夹具相同，避免把应用状态栏优化计入 SDK13 的效果。SDK13 的 237 个材料中，仅 `src/xui_code_document.c` 相对 SDK11 改变。

## 缓存规则

文档模型保存一个版本绑定的转换结果，新增六个 32 位字段，共 24 字节字段状态。查询命中时复用行号、字素列与规范字节位置；未命中继续运行原有行索引和真实字素遍历，不改变公开 API 或列的定义。

输入字节位置可能位于 UTF-8 或字素内部，也可能指向换行。原始输入不一定等于对应行列的反向结果，所以缓存分别保存查询位置与遍历得到的规范位置。反向查询返回后者。超范围列仍按原规则钳制到行尾，缓存记录实际遍历列；无效行仍先报错。

仅查询行号时，可以命中现有完整结果，但未命中不会覆盖它。正文替换、装入或间隙缓冲区内容修改前先使结果失效，不仅依靠版本递增；这处理同版本中间修改、撤销／重做、回调内查询以及 32 位版本回绕。移动间隙而不改变逻辑正文、修改脏标记不需要清除坐标结果。缓存不增加正文、字形或逐字符数组。

## 实际验证

两套真实文档模型改名后在同一比较程序中运行，共 336,188 项断言。覆盖每个字节位置、正反转换、可选／别名输出、中文、组合字符、ZWJ、区域指示符、Hangul、Indic、RTL 字符、Tab、空行、换行归一化、负数和极大坐标，以及 480 次随机修改、分组修改、撤销／重做、脏标记、版本和回调观察。还覆盖待处理行偏移、同版本底层修改、间隙移动、版本回绕及非法 UTF-8 拒绝。32 次重复正反查询之间插入行号查询，实际字素扫描计数保持为零。测试没有注入分配失败，原有底层修改事务的分配失败问题仍未解决。

SDK13 完整冷构建退出 0，耗时 140.859 秒，237 个源材料前后相同。它沿用 `-O2 -Wall -Wextra` 和既有警告排除，不是全 SDK 的严格警告构建。修改的 Document 编译单元另外以 `-Werror` 编译成功。原始 Unicode、Emoji、文档三项 SDK 测试通过；文档测试第一次缺少相对保存目录 `build` 而退出 1，补齐测试工作目录后，原始测试源码不变重跑成功，失败记录保留。

现有 `document`、`editor_view`、`goto_view`、`find_view`、`input`、`reading` 六项 IDE 测试在独立目录使用新 DLL 全部退出 0。它们复用当前可执行文件，覆盖保存／冲突／恢复、状态栏、Unicode 定位、搜索替换、输入事件和阅读恢复；定位含 93 项、查找含 53 项原生断言。这不是应用重新严格构建，也不是完整标准回归或便携包验收。输入事件测试不代表实体键盘或 IME 验收。

原生对照为新旧 SDK × C／xlang × 2／16 MiB × 多行／单行，共 16 次独立运行，每例完成 43 项检查，总计 688 项。操作覆盖打开、定位、插入、撤销、绘制、空闲帧和捕获。每例使用从未切换到前台的私有 Windows 桌面、1600 × 1000 窗口、1.25 DPI 覆盖及 2 GiB 私有提交限制；语言服务未配置。
