# 从独立工作区范围重建提供者配置

M7b5v，2026-11-13。既有 `rename_scope` 的配置/成员管理现在同时供 GUI 和独立服务使用，原生目标选择接口仍保留在编译器宏内。GUI 不引入语义编译器或另一套工程解析器。

`xideRenameScopeProvider` 接受已捕获的本地范围及不可信提供者 context。它先验证 `.xl` 入口是显式登记的成员，再逐个考虑所有候选所有者；当前选中的工程不会隐藏其他所有者。目录前缀、同名文件、C 文件和未列出的库/导入不成为提供者入口。显式列出的外部路径仍可属于工程；路径关系沿用现有原生词法键，不代表物理身份或写权限。

预期配置从本地 scope 的完整 spec 构建，只采用已经核准成员关系的入口拼写，并移除 MEMBERS。这与原生 actor 的逐文件配置变换一致，其他字段和未来加入 spec 的字段由 core 构造器、完整 canonical equality 继续核验，不以哈希或几个识别字段替代。kind/project/configuration 仅用于提前拒绝，不能独自批准结果。返回位图包含全部配置兼容的所有者。

当完整已登记 context 与声明相等时，直接保留其不可变引用，不重新构造 context。专项观察这一分支没有提供者构造调用；它仍有路径准备、查找、比较和引用计数成本，不宣称整个函数零分配或硬实时。需要变换成员/入口时才构造投影；单个 context 继续受 core 的 16 MiB 上限约束。scope 的 64 范围及 128 MiB 已知保留收费规则保持。

任何分配拒绝或取消均不返回部分所有者位图，也不遗留本次拥有的预期引用。构造器失败会令匹配未知而整体失败；超过 core 限额的投影不可能等于已成功构造的声明。取消在循环及最终返回边界检查，覆盖最后一次构造期间新出现的取消。

调用者可以把独立重建的预期 context 交给上一阶段的 `xideLanguageInputGuardImport`。真实四范围候选专项使用捕获的原始 scope（不是响应里的 context 自证），依次重建配置、与原生提供者对照，再严格导入来源证明；范围包含没有目标的工程。原 scope、查询和生产者销毁后，保留的证明仍可读取/验证。

最终独立 XRT 和 GUI DLL 专项各通过 318 项检查，涵盖所有 context 选项及列表顺序、空/缺失包输入、显式成员、路径别名、选中工程无关性、第 64 位、64 个相同独立文件角色、构造失败和取消的全部观测前缀、直接引用与构造混合前缀，以及四读者生命周期。故障探针观察提供者构造接口和释放调用，不是 XRT 内部所有分配点或进程泄漏测量。

真实候选链路通过 732 项组合检查，既有原生范围专项通过 1121 项，130 文件候选复核通过 418 项。另验证原有输入/来源报告、50 个协议用例、55 组 GUI 回归及有界 C/xlang 窗口。十个实际变体分别放松完整配置、登记入口、语言边界、成员投影、选中工程策略、失败位图、失败释放、直接引用复用、最终取消或第 64 位，均被实际断言拒绝。

本阶段先完整重编 109 个原生单元，随后更新一个私有提供者实现单元以加入不可变引用复用，公共头文件/布局保持同一组。最终源码核对发现继承快照缺少既有工具链租约查询函数；同步该函数及其新增声明，并重编全部 19 个相关消费者（含辅助夹具单元），保留其余已验证对象及新建核心归档。先重编 18 个消费者并完成回归，随后补编提供者单元；该对象及重新链接的最终服务与已验收字节完全相同，有独立摘要记录。GUI 保持完整重编的 129 单元及匹配 SDK，与最终服务重新配对通过回归；初始构建配对和最终验收配对的身份分别记录。最终夹具追加最终取消检查后独立冻结并绑定，较早的未执行测试副本不作为最终夹具。源码、实际依赖、对象、程序和原始回执位于外部资料包，入口为 `dev/release-materials/provenance/lsp-provider-scope-binding-20261113.json`。
