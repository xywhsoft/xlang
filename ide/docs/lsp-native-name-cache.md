# 隐式成员名称的原生阶段复用

原生流水线的第 18 阶段现在支持跨版本复用 `implicitNameAbi`、`implicitReceiverType`、`implicitFieldDeclaration` 三项节点结果。实际切换一个隐式字段引用的输入中，21 个声明区间复用 20 个，重新生产 19／550 个节点；仅修改字段初值或增加 Unicode 注释与空行时全部复用。完整 IR 与独立原生构造一致。

这是显式原生组件中的生产能力，尚未接入普通 LSP。构造计时未通过筛查，不能默认启用；发布目录继续使用已配对验收的 0.110，三个原有 IR 实验保持关闭。它也不是整个最终函数 IR 已经增量化。

## 原生输入和输出

生成器审核完整来源、头文件和依赖组，并匹配十个真实函数的正文，包括现有分类器的快速入口、原始完整入口，以及字段绑定辅助函数 `xlsIrImplicitTargetAllowed`。复用与实际编译相同的字段绑定变换，避免生成一份遗漏已解析字段身份的旧算法。普通原生函数保持不变。

该阶段只有入口写入上述三个节点结果。所有辅助函数读取的节点字段投影与这三个输出分离，生成器对此作明确检查；因此先前产生的三个值不参与命中证明，也不会把捕获后的结果误当作生产输入。

缓存记录以下输入：

- 实际读取的节点及 12 项保守字段投影，文本复制完整内容。入口遇到非名称节点时只记录节点种类，后续辅助读取仍可升级到完整投影。
- 实际查询的类型编号、存在性、`kind` 和 `nominalSymbol`，不比较整个类型池。
- 当前根、节点数、完整符号映射／容量、分类器入口选择、类布局所用的五项字段，以及类字段的所有者、类型、声明和完整名称。这部分公共输入每次阶段比较一次。

命中不依赖先生产一份新的最终 IR。未命中才执行审核后的真实原生循环；命中恢复三个标量输出。所有其他阶段继续正常运行，最终统计、调用契约和完整原生验证仍保留。

区间按根级声明的实际节点顺序划分，类可以包含多个成员，不能把区间计数直接解释成函数计数。当前仍要求精确原生编号和公共结构，结构编辑、编号重排或公共布局变化可能造成较大范围的拒绝复用。

## 接口、所有权和失败处理

`ir_native_name_cache.h` 提供显式的 `FinishCachedNames` 入口。它要求独占流水线，最晚从第 18 阶段开始，不能接续该阶段中途的节点扫描。完成状态下再次调用是无新缓存的幂等成功。

旧缓存只是调用期间的不可变借用。新容器拥有独立公共输入及 XRT 分配的不可变单元；共享单元采用 XRT 原子引用计数，不保留 AST、模块、旧容器或结果链。单元仅保存精确输入及三个标量结果。只有整个模块完成且通过完整 verifier，公开入口才发布新缓存。

保留预算上限为 16 MiB，包含共享单元的保守记账；阶段暂存另有相同上限，两者都不是进程或完整分析的内存上限。零预算关闭复用和捕获；声明数组需求在分配前检查。可选元数据失败回退到原生生产，后续原生输出所需分配失败或取消仍退休部分模块，不发布半成品。

调用缓存与名称缓存共用有界字节序列化、文本复制和载荷区域计算，继续使用既有 XRT 数组、字符串、分配和原子能力。当前两个阶段各有显式实验入口，尚未提供普通请求中的组合缓存或整体预算调度。

## 验收证据

49 个完整语义输入通过 6,889 项普通检查。六代调用绑定／默认值／源码移动输入及四代真实隐式字段输入，对照完整原生 JSON 与 verifier；其中隐式字段输入明确要求非默认 ABI 结果，避免只验证全零输出。

名称缓存的冷／热路径分别枚举 52／49 个外部 XRT 分配或 API 拒绝点、45／48 个取消点。契约夹具通过 7,413 项检查，包含普通夹具、736 次退休单元清零、四个并发读取者各三代及外层读取状态恢复；计数不相加作为独立语料数。

额外契约检查直接改变原生类字段名称，比较缓存阶段与独立原生阶段的三个输出，确认公共布局依赖会失效；这属于原生元数据对抗检查，不把变动后的中间模块宣称为合法源程序。另一项检查预先污染所有三个输出槽，要求命中恢复后完整模块仍与原生结果一致。

共用工具抽取后，调用缓存原有 6,803 项普通和 6,924 项契约检查也重新通过。默认构建保持 1,862 个已有函数正文及两个私有布局的令牌一致；20 项来源策略、相关原生回归、默认不可用入口和实际编译缺陷检查另见小材料索引。首轮编译的缩进警告原样保留，修正后使用冻结源码重新编译、验证。

缺陷注入工具首轮完成六个反例及正常对照后，因组件／默认桩存在同名入口而定位失败。原结果保留；后续只改工具的唯一发布锚点，对未改变的最终产品完成其余用例，不把这次准备失败算作产品通过。

## 性能失败及后续边界

同一组件核心分别使用类字段密集输入和普通函数对照，各进行 24 轮交替顺序的三个模式，每次都对照完整原生 JSON。移除故障注入链接包装；计时包括已完成语义检查之后的原始 IR 准备、全部原生阶段和完整 verifier，不含解析／语义检查、清理、LSP 通信或 IDE：

| 输入 | 原生中位数 | 首次捕获中位数／比值 | 跨版本中位数／比值 |
| --- | ---: | ---: | ---: |
| 32 个类，重复隐式字段读取 | 7.09915 ms | 7.87510 ms／1.10930 | 7.90330 ms／1.11327 |
| 32 个普通函数，重复直接调用 | 5.41880 ms | 5.72775 ms／1.05701 | 5.26570 ms／0.97175 |

类输入预设首次不超过 1.15、跨代不超过 0.98，跨代失败；普通文件对照预设两个模式均不超过 1.02，首次捕获失败。两组均未放行，不重跑同一图像消除失败，也不根据其他分位数替换门槛。原始每轮数据、P95、编译命令、程序及输入摘要均保留。这不是完整 LSP 或 IDE 的性能验收。

后续需要减少名称入口的无关字段捕获、重复类型查询和无适用类布局时的元数据成本，并在多阶段组合中共享完整函数的输入证明。仍需其余产物的选择性生产、结构编辑的引用映射、普通服务与配对 IDE 接入以及端到端性能／平台／耐久验收。材料索引为 `dev/release-materials/provenance/lsp-native-name-cache-20261123.json`，大型源码及验收载荷保留在外部开发材料包。
