# 跨符号重编号的 IR 输入证明筛选

2026-11-09，M7a2b126m。原型完成正确性对照，但组件筛选的同图像、前阶段和发行版累计对照分别有 **6／22／6 项门槛未通过**。原型没有合入正常分析路径，也没有替换发行程序。完整 LSP 与性能目标继续。

## 试验边界

在一个函数中增加局部声明，会使后续未改函数的原生符号编号变化。既有完整键会正确重编码；如果已经拥有同一语义单元及其完整最终标注，可以另外证明部分重编号后的规范键仍相同。

原型保持原有精确最终标注收据，增加独立的规范化收据及显式的局部编号映射。局部符号只能在原分配器已经证明属于当前函数的区间内作仿射映射；全局编号、实体存储／配置域、当前实体查询及词法声明顺序仍检查。事实类型子树的编号保持精确；未命中的实体查询留下的是原生编号，不能因为两次都未命中而允许重编号。任何不满足条件的路径继续原完整键编码。

最终版本直接读取既有稀疏标注记录和不可变生产单元的类型几何，避免再扫描实际 AST。精确标注和原生编号框架均未变化时直接保留已有规范收据。数据及引用使用 XRT，额外已知容量计入原语义／IR 缓存额度。没有扩大原额度，也没有省略原始 IR 恢复、后处理或完整验证；这还不是最终 IR 的函数局部生产。

## 正确性和代价

- 真实局部声明修改案例中，完整 IR 键复用从 4 个函数增加到 21 个；全部 217 次独立完整键重编码对照一致，完整 AST／诊断／IR 与全新分析一致。
- 当前私有生产者和消费者分别通过 1,068、184 项检查，覆盖事实类型的绝对编号、18 个标注字段、区间／词法顺序／实体未命中、预算、实际分配失败及独立寿命。计数包含继承夹具，不当作新增断言数或完整原生回归数。
- 三个实际 C 遗漏变体均成功编译、链接，并由运行期检查拒绝：遗漏事实类型记录、遗漏精确未命中查询的重编号守卫、遗漏生产语义单元身份。实际编译依赖确认变体进入了对应翻译单元。
- 普通原生分析、当前编译器／包变体、语义读集合及多模块语义四套协议回归通过。组件只替换了匹配的 IR／语义实现对象，并执行相关夹具；没有冒领一次完整重建、150 项原生重跑或 IDE 配对验收。

六份私有版本及所有中间结果均保留。第一版的精确最终环境先因参数编号变化而失效，没有增加命中；后续版本证明了重编号复用，但普通热路径出现额外成本。最终处理还恢复了字段投影的内联边界，四个原有热函数的 COFF 指令字节及重定位记录与基线一致。这只证明该局部代码生成边界，不能代替整程序计时。

原型增加了证明资产，却没有减少仍在执行的整份 AST／IR 工作。最终前阶段对照的 512 函数普通热编辑中，两侧都仍有 **47,105 个物化节点、856 页、16,248,384 字节已知物化容量**；一个相同检查点的语义 memo 从 28,435,896 增至 31,999,316 字节。这些是指定资产的统计，不是整个进程 RSS 或瞬时峰值。
