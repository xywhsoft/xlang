# 原生光标到完整候选分析入口

M7b5y，2026-11-13。`xideProjectReferencesSubmitRenameAt` 将打开文档的 UTF-16 光标和新名称接入已有的原生重命名候选流水线。调用方提供独立捕获的完整范围和明确选择的原始上下文；上下文必须与一个 `ScopeAt` 完全相同，且显式拥有光标文件。单文件不需要工程或工作空间。

提交只保留不可变上下文、文本引用和有界标签，不在调用线程读取源码或运行编译器。现有单线程 XRT 引用协调器先按原来的依赖展开规则选择实际拥有该文件的编译入口。入口可以未打开，光标可以位于导入文件；不把导入文件强行作为独立程序检查。

新增显式 RenameCapture 模式，在同一个成功的原生检查、原始源码向量和导航投影上，捕获原生声明目标、引用源库和声明关系图。光标必须位于原生绑定对应的精确 IDENT；限定名、Unicode、BOM 和 CRLF 沿用既有坐标与源码身份规则。普通诊断、补全和引用模式没有新增目标捕获。目标、图和原始守卫均有独立所有权；不保留借用 AST。

协调器将首次捕获的提供者记录放入原来的有界缓存，然后同步调用已有全部范围的候选流程；不向自己的单线程队列再次提交并等待。复用全部原生声明关系、精确引用收集、完整成员检查、假想源码静态复检和最终守卫扫描。另保留并复核首次光标提供者的输入与依赖归属证明，其完整守卫随候选导出。共享源码/图、目标/键、文本、活动编译器、导航、缓存与编码器内存另外计入原有各自预算；没有全进程内存或零分配声明。

范围之外的声明、错误上下文、非法新名称、不可导航位置、失败的无关成员、输入变化和取消均拒绝完整候选。结果不写源码、不修改编辑器，也不代表客户端批准编辑。候选仍须通过独立客户端来源/范围覆盖、完整输入时序、物理文件与事务/确认/恢复门槛。
