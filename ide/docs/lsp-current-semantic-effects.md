# 当前检查器的特化声明与复用条件

2026-10-30，M7a2b80a。接续固定前端提交 `9192a99f96ecd83bd57ca6e53df6dfcdda7d2f15` 的语义事实适配，补齐 C owner 特化产生的声明环境和快速声明比较。开发基线仍为 0.99，正常当前语义／IR 构建守卫继续关闭。

## 实际变更的观察

原检查器会把特化声明追加到模块或类正文，分配符号、注册名字，必要时在原类作用域检查特化方法，并改写调用表达式。这些工作由原实现执行。普通平面 fact 不具备重放这些结构变化的能力；发生实际改写的函数继续执行原检查器，不把结构变化缓存成标量事实。变更标记沿同一检查上下文的嵌套调用传播，也清除完整输入相同的资格。

每次实际新增特化声明时，memo 独立保存一份精确字节记录：容器身份／名字、新增声明的完整语义键（递归正文、类型、标量、文本和来源路径）、原生符号与类型分配状态。坐标沿用原有来源与移位条件；该语义键不编码坐标。记录不借用原 AST 或检查上下文，不采用有碰撞风险的摘要替代内容比较。

后续函数的 entry 保存当时的声明记录数量。只有记录前缀与旧版本逐项相同、数量相同、没有未完成的写入，且原有输入／读取／来源／符号等条件也满足时，才允许复用。原检查器在每个版本重新产生声明，适配器没有跳过声明生产。重复命中已有特化不新增记录，但仍标记调用改写。

记录内容有变时，当前实现保守地拒绝后续前缀的复用。没有变更时继续保留后续函数复用；不因模块使用过 C owner 就关闭整模块缓存。记录只在实际新增声明时构造、比较一次，后续函数检查记录数量和已确认的前缀状态，不重复扫描全部声明。记录容量与数组容量计入原 64 MiB memo 预算，数组扩容同时限制临时新旧数组的占用；预算或分配失败会拒绝复用并保留原检查路径。

## 前端与字段边界

当前私有派生固定核对 `xl6_sem_c_owned.c`、`xl6_sem_special_collection.c`、`xl6_sem_constructor.inc` 三个包含文件，再派生 C owner 的实际声明写入／调用改写观察点。源仓库与冻结前端均保持不变。

本阶段检查了这三个文件中的直接 registry 查询、全局／作用域查询、根声明遍历及写入。它们没有额外直接的 `xl6TypeRegistryFind` 调用：集合辅助代码使用原作用域／类型助手；take 的释放函数遍历先经过实际全局名字查询；特化和 spawn 的结构变更通过上述观察点；构造器完整流程仍由原模块末尾执行。这个局部检查不替代所有间接读取、其他检查器副作用、注册表及签名／补全路径的完整准入审核。主 TU 的 71 处查询替换也不是整个服务的读取覆盖证明。

快速声明值比较现在递归比较 `compiledPackageLink`，与序列化键一样区分 NULL、空串和非空文本，避免新字段被快速命中路径忽略。旧 AST 布局不新增字段或操作。

## 验证
