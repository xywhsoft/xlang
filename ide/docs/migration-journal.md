# 项目迁移中断恢复

实现：`src/services/migration_journal.h`、`src/services/rename_journal.c`、`src/services/session.c` 和生产迁移窗口。共用现有不可变正文、摘要校验及状态文件写入机制。适用项目清单和整个项目目录的同卷、不覆盖迁移；恢复不会自动保存用户清单或源文件。

## 记录与发现

迁移前先保存完整会话，再将独立事务记录写入全局会话目录的 `migrations/<16 位标识>/migration-journal.json`。默认全局目录为 `%LOCALAPPDATA%/xlang-ide`，自定义时使用 `--session-root`。该目录必须位于待移动目录之外。

记录包含移动前模型、预演后的完整模型、原始清单 JSON 基线、项目及文件标识、未保存属性、会话路径、布局和独立正文/原始字节副本。正文使用已有 `recovery/rename-<GUID>.body` 格式；每项最多 16 MiB，会话总量最多 512 MiB，JSON 标记最多 8 MiB，发现记录最多 1024 个目录。标记在所有正文写入和校验完成后发布。

记录保留原始、当前和连续迁移的工作空间或独立项目路径。显式打开旧路径、新路径或通过最近项目启动，均可在读取旧工程清单之前发现未完成事务。默认会话目录随项目目录移动、自定义会话目录因所有者路径变化而改变，由恢复阶段重新绑定。无会话模式和没有路径变化的操作不创建事务。

未命名工作空间使用 `ownerKind=none` 和空所有者路径。启动时恢复完整工作空间—项目—文件模型，而非把空路径解析成当前目录。当前会话与配对布局已发布但事务更新失败时，这一空身份也参与较新检查点比较，以保留后续 C/xlang 草稿。

## 正文存储上限

项目迁移记录按正文长度和 SHA256 在持久所有权清单内寻找相同内容，实际读取并校验原文件后才复用引用。正文保持不可变；重复保存和 A→B→A 编辑不再生成相同副本，正文变化时仅新增变化的内容。文件改名事务仍使用其既有存储策略。

在写入新的迁移正文前，持有该存储的检查点锁并核算 `recovery` 目录。每个存储最多 512 MiB、10000 个文件；未知文件也计入，子目录或重解析项会阻止新增。已有文件达到容量上限时，经过校验的相同正文仍可复用。容量拒绝保留现有事务和正文，不授权删除文件。主会话先于事务更新发布时，启动仍按较新配对检查点恢复。

此上限约束迁移副本存储，不限制用户源文件。持久所有权清单保留历史副本身份；已退休满七天且完整快照仍匹配的已知正文可以后台或显式回收，未知旧副本及退休标记保留。详见 [迁移正文维护](migration-storage.md)。

## 恢复顺序

1. 校验原生进程 PID 和创建时间。仍在执行的 `prepared` 事务不会被另一个 IDE 回滚或恢复。
2. 检查移动前后真实文件/目录身份及准确大小写。目录使用卷号和文件索引，清单使用完整文件快照。连续迁移同时检查先前目标的身份。
3. 校验每份工作空间/可用项目清单仍匹配已记录的磁盘基线或预演后的导出内容。损坏标记、正文、外部清单修改及目标替换会阻止恢复，保留原文件。
4. 在独立模型内解码完整工程并校验所有正文后，才替换活动模型。移动完成使用迁移后的显式路径；移动尚未发生恢复移动前模型和属性，保留 `aborted` 记录直到工程保存。
5. 将已校验正文副本放入当前会话目录，恢复 C/xlang/纯文本语法及覆盖、选区、折叠、活动文档、未命名文档、外部文档和布局。恢复后的正文可以继续编辑和撤销。

保存会话后更新事务中的当前模型、正文、布局和身份。会话与配对布局已经发布、事务更新失败时，恢复优先使用同一所有者且布局代号不同的有效当前检查点，保留后续编辑。工程清单全部保存且当前会话发布成功后，事务转为 `retired`。未完成事务期间，当前会话正文维护停止；独立全局副本也不会被当前作用域维护删除。

## 验证与边界

`tests/migration_checkpoint_test.c` 在实际生产迁移窗口加入观测点；父进程只终止自己启动的原生进程。`tools/check_migration_journal.py` 覆盖三个中断阶段、内外及未命名工作空间、独立项目、默认/自定义目录、大小写、连续迁移、恢复后编辑/撤销、较新正文及外部冲突。正文去重使用两轮各 20 次实际会话保存验证；容量拒绝使用实际 512 MiB 未知文件，并确认较新 C 正文仍恢复。保留上一版真实业务对象和生产窗口的复现结果：旧实现丢失未保存模型、自定义会话路径改变后草稿不可见，以及未命名工作空间错误恢复旧正文。

本次验证进程中断恢复，未验证突然断电的持久化保证。跨卷迁移、资源配置正文的目录迁移重写、源代码 import/include 字符串改写、没有所有权记录的旧副本及退休目录整目录回收仍不在本次实现范围。已有文件改名事务尚未保存时，继续沿用迁移前保护，先保存涉及的工程和资源文档。
