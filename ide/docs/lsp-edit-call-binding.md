# 编辑调用与连接、请求和回复的绑定

M7b5x，2026-11-13。新增 `edit_call` 连接已有不可变请求、完整工作区范围、后台编码和实际 stdio 队列。本阶段是路由准入，不是来源、静态分析或编辑许可；服务还没有实现 `xlang/renameCandidate` RPC，标准 rename/applyEdit 保持关闭。

每个成功分配的传输实例具有进程内不回绕、不重用的 64 位连接身份；失败的后续构造可以消耗身份。耗尽后拒绝创建，不以地址、时间或随机值替代。一次构造增加一个字段和原子计数工作，普通发送保留原有接口。身份只能从实际客户端复制，不能从响应自证。

后台准备调用时核对请求同步器内精确 URI、版本、模型身份/修订、语言及 UTF-16 位置，独立构建完整范围并保存原始意图。新名称是最多 4,096 字节的 UTF-8 意图，不代表已通过原生标识符/冲突检查。数据包携带原请求 ID、固定方法、十六进制 64 位令牌、输入回执、原 catalog 和独立根路径；令牌不经 JSON 浮点数传递。复用既有 batch/framer 一次编码，没有正文复制或重新哈希。共享文本/catalog、上下文和编码器临时内存另外计算，仍受原有范围及 8 MiB 帧规则约束。

一个请求只允许一次成功的调用准备，销毁未发送调用也不会恢复这个权利。发送前，UI 再次执行完整 Current 核对；随后只在原连接的传输锁内，将调用状态从 prepared 原子转换为 queued，再公开同一已编码队列节点。失败不接管 batch、不消耗状态，重试前必须重新核对。没有锁内编码、分配或用户回调。重复调用或旧连接不能复用同一个请求编号。

回复从实际输送通道及解析器取得连接身份和原始 Content-Length。路由要求精确 JSON-RPC2.0、整数 ID、queued 状态；成功结果还必须匹配方法、令牌、输入回执和范围数量。标准错误单独接收，错误码 0 与成功候选不会混淆。错误结构和消息长度/UTF-8 有界。一次 CAS 只允许一个回复成功接管调用；错误来源、未发送、错字段和重复回复均保留来信的调用方所有权。接纳的根沿用原解析对象，没有深克隆或再编码。

`Candidate` 明确返回仍不可信的 DOM。本阶段只检查候选外壳；测试中的正向对端故意提供不合格的来源守卫，证明路由不会冒充完整来源审批。后续必须独立导入守卫、核验配置/成员覆盖、静态重检和 WorkspaceEdit，执行完整 owner/物理输入/确认/恢复与事务门槛。局部 `ReplyCurrent` 也只看不可逆标记，不能代替完整 Current 或来源守卫。

取消只使本地调用及请求不可逆失效，尚不发送协议取消。实际客户端、app 或 GUI 销毁不在共享调用中留下裸指针；最后的调用/回复/文本释放在 worker 或最终关闭阶段进行。

验收中，独立 XRT 与匹配 GUI DLL 各通过 1,047 项连接检查（其中 1,024 项核对并发分配身份）及 65 项真实 stdio/解析器调用检查。真实 IDE 专项本次通过 167 项：实际后台准备、完整 Current 失配拒绝、原连接入队、现有服务的真实 `-32601` 错误接收和后台退役；同时保留 C/xlang 输入、删除、撤销、IME、焦点和六参与者检查。原有路径范围、请求所有权、接收器及分析租约分别通过 69、58、3,426 和本次 2,387 项检查。完整 GUI 重编 131 单元，55 组回归及各 24 帧 C/xlang 窗口通过。十二个实际错误实现均被断言拒绝，编译错误、崩溃或未执行的变体不计数。

服务字节未改变。复用检查只统计实际链接到服务的 101 个对象（含核心归档成员）及其 284 个当前源码/头文件条目；先前完整构建中的 8 个未使用客户端/辅助对象不作为当前证据。新的独立测试重编 6 个支持单元和 2 个测试单元。客户端 private 布局及实际消费者均使用新代码，未把旧客户端对象混入测试。

原始失败和修正保留：最初测试注册定位断言与当前列表顺序不一致；生产构建已开始，后续只修正未启用的 Tests 分支，生产 sources/flags 前缀完全相同，单独绑定差异。初次调用夹具有两个 `-Werror` 缩进诊断；初次独立调用夹具重新定义了预包含的 Windows 版本宏；旧分析租约夹具首次调用缺少其规定的三个参数。最终夹具单独冻结，仅重建变更的调用测试；其余已通过程序及最后调用程序按明确清单组合验收。失败不计入成功数。
