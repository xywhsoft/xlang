# IDE 构建的发布前校验

2026-11-01。`build.ps1` 在编译前核对当前编译器与命令目录，链接后再次核对，并在资源发布后、程序替换前复核。GUI 和新生成的 LS 都先保留在构建目录；目录、字体、源码／SDK 或指定 LS 身份校验失败时，不替换发布目录中的 IDE、LS 或 XGE，也不覆盖已有构建记录。

通过全部校验后才发布程序及对应构建记录。新 LS 先复制到构建目录并核对 SHA-256，再替换目标；`-GuiOnly` 指向现有根目录 LS 时保留该文件。此调整不声明多个程序的替换具有跨文件系统事务原子性。

普通构建仍使用根 `release/`；只有发布顺序的故障测试使用独立运行目录，防止旧实现的提前写入破坏真实程序。默认仍禁用 C LSP，只生成 `xlang_ide.exe` GUI 入口。

验证工具为 `ide/tools/check_build_publication.py --output <新的验证目录>`。它使用真实构建脚本流程和真实 SDK 校验，编译／LS 生产器则产生明确标记的不可执行合成产物，用于检查发布先后关系，不能作为 GUI／LS 功能或性能验收。

本轮证据在 `ide/build/Release/ide-publish-gates-20261101/`：

- `faults-v4/result.json`：12 个新实现的拒绝／合成成功场景和两个旧实现反例。覆盖默认／GuiOnly 两条路径、早期与链接后目录拒绝、字体拒绝、资源处理后的再次目录拒绝、LS 输入改动；失败时程序、设置、用户文件和先前记录保持。旧实现的链接后拒绝会改写程序，两个反例都被检出。
- `real-preflight.json`：真实根目录程序与真实检查器在当前编译器／目录不匹配时拒绝构建，受保护文件和构建记录的 SHA-256 不变。没有用合成工具通过真实发布校验。
- 首轮编码别名错误、第二轮合成编译器干扰 SDK 预处理的失败记录保留。最终工具将 SDK 预处理委托真实编译器，并验证预期拒绝原因，避免把无关失败算作通过。

编译器正在并行更新，完整匹配目录及 IDE 的重新发布仍待后续验收；本页只确认发布保护，不证明整个 LSP、当前编译器或发行包已完成。
