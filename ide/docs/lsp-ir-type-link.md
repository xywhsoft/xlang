# 最终 IR 类型池的跨批次链接

M7b6z 是最终 IR 选择性生产的基础组件。`ir_type_link` 把来自不同捕获批次的独立类型记录链接到当前类型池，处理类型引用、嵌套布局、符号及类型参数来源身份。普通服务尚未调用它，默认版本仍为 0.106；当前完整类型池仍由全量分析提供，不能据此宣称编辑速度改善。

## 原生数据边界

组件直接使用 `XL6_IrType` 和独立 `types.items` 单元，不另造类型表示。实际头文件的 54 个顶层字段及嵌套 `sequenceLayout` 的 14 个字段封闭审核，生成 67 个完整字段／载荷比较项及 12 处标量引用重定位。后者包含 11 处类型引用和 1 处 nominal symbol；`params`／`returns` 的每个元素另外重定位。源码类型 ID 和运行时 ABI／类型值身份是不同域，不根据名字或整数宽度猜测转换。

每个绑定必须持有匹配的单元生产者标记，并提供纯粹、确定、显式的来源到当前 ID 映射。类型、符号和源码类型 ID 都使用一基编号，零哨兵不调用映射；非零结果不能为零，须符合 32 位表示，类型 ID 另受当前数量限制。不存在映射失败时沿用旧值的回退。绑定可乱序，但必须双射覆盖全部当前类型记录，不能重复或遗漏。

原生 `sourceTypeId` 对具体类型是诊断来源，对 `TYPE_PARAM` 则参与身份。前者采用当前来源值；后者必须显式映射并与当前记录一致。64 位 ABI／公开类型值身份保持原值并完整比较，不把它们当作需要重编号的索引。

## 派生信息与完整比较

C 回调、数组、product 和 nullable 等原生表示可能把类型编号写入 `cName`／`errorResultCName`。这些名称必须来自当前生产者，不能仅移动整数后复制旧名称，也不在 LSP 里重复实现原生表示生成器。类型 `hash` 和完整查找槽也采用当前生产者数据。查找槽作为不透明原生元数据原样复制，不假定每个机器字都是类型编号。

重定位后，逐字段核对当前记录的全部值、固定数组、文本、可选载荷存在性及向量内容，忽略 C padding 的身份。严格比较保留诊断拼写差异；无法匹配的旧单元由调用者改选当前单元。类型参数来源身份不会被“刷新诊断来源”的分支绕过。原生完整验证器仍保留。

这些比较不证明文档输入或依赖新鲜度，也不生成映射。当前类型池必须由调用者持有、验证且在调用期间保持不变。测试里的新旧类型对应来自独立完整分析的受控语料；它不是产品可用的实体版本准入或类型身份匹配器。

## 所有权、预算和失败

结果使用一块 XRT 分配，拥有平面类型行、当前查找槽和重定位后的 `params`／`returns`。文本及参数 ABI／模式向量只读借用单元，结果独立保留每条选中记录；不保留父图、旧模块、AST、当前布局、映射或旧结果链。调用者保证读取期间的结果生命周期，不能并发销毁、修改，或对借用池调用原生模块析构器。

另外一块临时 XRT scratch 保存放置位置，成功后释放。预算检查乘法、对齐与加法溢出，覆盖结果加 scratch 的申请字节峰值，零预算拒绝；不包括已有单元、分配器开销或整个进程 RSS。所有构造失败均不发布部分结果或残留引用。遍历、长引用向量和发布前轮询取消；单次文本／向量比较和固定块复制不提供字节级抢占。

## 验证范围

合成所有权夹具使用独立手写预期映射和归一化原生记录／载荷字节对照，覆盖全部引用角色、乱序放置、可选空向量、零哨兵、当前派生名称／散列及不透明查找字节。两个真实分配失败点、十个小夹具取消点逐一拒绝；4,097 元素的引用向量另外抽查取消。四读线程各构造／退休 16 次，32 代独立结果每代只剩结果、四条单元和一个来源标记六块分配；退休原始输入后仍可读，最终申请全部归零。这些合成记录验证所有权和链接规则，不是语言接受性语料。

实际 typed IR 语料在完整原生验证器和完整 JSON 上比较，另在八个原始分析退休后重复验证。真实编辑增加 `array<float>` 局部值，在两个独立原生模块中分别通过原生 interner 构造 C 回调指针。16 条旧记录与 1 条新记录混合，12 个类型 ID 发生变化，回调后端名称也变化；两个原模块、AST、图和映射退休后，结果仍与独立当前模块一致。

首次候选错误地把查找槽解释为类型编号。审查后改为保存不透明元数据，补上任意机器字对照，并明确取消旧构建，冻结新输入重新验收。保留最初严格编译告警、回调夹具尚未显式形成签名、额外 interning 后统计未同步、插入字符串没有改变类型编号等失败记录；用真实 callable 类型、准确的新增类型计数和泛型数组完善夹具，不修改编译器语言规则。

本组件仍依赖当前生产者的派生信息；其他非节点表、实体／依赖准入、选择性最终 IR 生产、端到端性能、全局资源和长稳验收继续推进。此前 0.107 的尾延迟失败仍开放，不以本阶段正确性验证替代。

新冻结输入全量重编 367 个对象／76 个 core 成员，生成 225 个原生测试程序与服务。构建为 build-only，实际执行相关的 10 个原生程序；链接器通过 8,012 项检查、134 次完整原生对照、14 组实际头文件角色守卫。24 种单项 C 缺陷被拒绝；另外同时移除后端名称刷新和组件比较守卫，以独立原生专用驱动验证，完整原生验证器在源对象退休后拒绝旧回调名称，未修改的对照通过。损坏的私有 core 副本在 C 编译前被拒绝，原始 archive 未变。

原有 590 个生产文件／公共头不变，新组件未被普通服务链接。发布目录保持 7,094 条文件路径，其中 7,092 个文件字节不变；并行 XRT 09d 更新的两个公开声明头与已提交快照摘要一致，原样保留并单独记录。八个受保护程序／运行库、SDK 和交付索引均未变；没有新的协议、GUI 或性能验收，没有默认安装或上线。开发材料位于 F 盘，由 `dev/release-materials/provenance/lsp-ir-type-link-20261116.json` 索引。
