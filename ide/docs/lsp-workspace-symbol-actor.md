# 后台工作空间声明收集

2026-11-09，M7a2b126e。在常驻索引内核及零打开声明捕获之上，新增 `workspace_symbols.c/.h`，用独立的 XRT 任务协调器和已有语义 worker 收集真实工程成员。准备好的项目／独立文件上下文、未保存覆盖和查询可异步提交；结果包含全部已验证声明的有界模糊查询。

这是后台服务层，尚未接通 `workspace/symbol`／resolve、IDE 符号搜索、初始化时的主动索引及文件监视器触发。工程成员仍由现有项目上下文提供，不额外解析工程清单，也不递归猜测目录成员。本阶段不替换默认发布程序，不公布尚不可用的协议能力。

## 覆盖与输入身份

一次任务最多 64 个完整项目／文件语义上下文、65,536 个入口／成员绑定、64 个编辑覆盖。提交线程仅校验有限标签及引用捕获，不读磁盘、不复制正文、不做哈希或编译。工作线程按平台词法路径排序、合并重复 `.xl` 成员；C 成员不进入 xlang 声明索引。

优先检查每个配置的正式入口，保持真实程序角色。其余成员可由自己的原生完整检查或某个真正检查成功的导入者覆盖；已被覆盖的库文件不必再作为独立可执行程序验证。只有编译器原有源码诊断可暂缓，等待之后的真实导入者；无覆盖源码错误、基础设施失败、额度和取消均不能产生部分成功。配置入口不能使用这一暂缓规则。声明仍来自完整检查后的独立投影，不创造语法推测事实。

每份记录保留完整语义上下文、词法入口、独立声明、原有 detached 输入守卫和共享的覆盖路径／BOM 元数据；不在每份分片里保留源码正文、AST、IR 或完整导航表。复用要求完整上下文相等，不能只信路径、指针或哈希。

复用前核对实际文件报告的磁盘／覆盖来源；对实际用到的覆盖，用 XRT SHA-256 核对去 BOM 后的原始／文本摘要、长度和 BOM 状态。每个本次覆盖最多计算一次摘要，未用覆盖不做正文哈希。新增／关闭覆盖若命中曾观察的导入候选，即使该文件以前不存在，也重新分析。磁盘、清单、包路径及负候选沿用原输入守卫验证，不放宽原始准入。

另复用 `xls_input_batch` 的全输入版本历史，防止缓存命中时绕过同身份版本倒退、同版本替换正文等规则，包括未使用覆盖。批次捕获仅保留已有不可变正文引用，成功准入后历史可以在后续成员分析失败时前进；这与成功发布声明事实是不同状态。空工作空间释放历史并移除旧分片。

完整覆盖和输入守卫核对后，使用索引事务增改分片、移除旧成员，一次发布新版本。未改的声明记录和索引分片共享，不因分析 worker 的 8 会话 LRU 淘汰而丢失。查询完成后再次核验输入，拒绝查询期间发生的磁盘变化。后续宿主仍须核对编辑覆盖、配置及文件监视代次；结果拥有快照引用不等于永久新鲜度。

## 调度与资源边界

一个协调器任务线程，独立于现有前台补全／诊断 actor；一个语义 worker，最多 8 个保留会话／64 MiB 已知会话输入，复用原模块资产和编译器。队列最多 8 个等待任务，future 提供取消和事件唤醒，销毁取消并等待后台线程结束。已转移的结果可在服务销毁后继续读取。

当前索引已知保留载荷默认 128 MiB；紧凑记录及守卫额外最多 128 MiB，共享覆盖路径集合按实际指针计费一次；原输入历史另限制为 64 MiB 已知存储。待执行任务保留的输入引用、调用者旧结果、编译器活动 AST／IR／投影、临时排序、容器容量与分配器开销另计，不是全进程 RSS 额度。每个实际语义输入仍遵守原有单文件 8 MiB、正文总量 32 MiB 等准入。

成员和记录指针排序为 O(N log N)，未采用逐项插入排序。仍有明确限制：每次查询会遍历全部成员并验证保留的实际输入，索引提交仍重建／排序引用向量；成员排序最多 65,536 项的库排序期间没有逐比较取消回调。本阶段证明后台隔离、正确覆盖和声明复用，不宣称大型工作空间首次扫描、增量调度或整体尾延迟目标已经完成。下一步需结合配置／文件变更事件进行主动更新及任务优先级管理。

## 当前验证

新模块、头文件、包含实际实现的测试及直接链接普通生产对象的公开 API 测试独立新增，既有生产源码／公共头文件／编译器输入均未改变。核对并保留上一阶段 144 项原生验证产物，新增实际执行 981／21 项检查的两个后台用例，汇总为 146 项记录；不是重新执行全部 146 项。编译历史 252 次，1,426 个输入／148 个产物，147 个既有私有 AST 消费者身份不变。

新增检查包括：

- 与另一个真实原生 worker 新鲜捕获的完整声明集合逐行比对，包含未打开文件、真实导入及声明位置。
- 多项目／配置共享同一来源、成员缩减、空工作空间清理、旧结果在服务销毁后继续读取。
- 磁盘编辑、覆盖增加／关闭、同版本正文替换、版本倒退／重开、无关覆盖、BOM 改变；实际使用覆盖每任务仅一次哈希，无关覆盖零哈希。
- 包解析记录中的真实缺失 `a_library/xlang.package.json` 候选，新增该路径的覆盖后不能直接复用旧记录。此用例是清单负候选，不把它描述为缺失 `.xl` 源文件测试。
- 未覆盖类型错误失败、真实导入者覆盖库程序角色错误、配置入口仍需自身合法、查询返回前实际写盘变更被拒绝。
- 三个构造器拒绝点，零覆盖／真实覆盖两模式的 57／61 个实际服务边界申请、路径、容器及摘要拒绝点；全部无成功旧结果，native 路径所有者配对释放。未声称覆盖编译器或 XRT 内部所有 OOM。
- 52 个真实成员入口／51 份独立检查分片／103 条声明，温热刷新复用全部 51 份且无语义任务，即使分析缓存只有 8 个会话。最终测试路径下索引已知载荷 89,515 字节、紧凑守卫 96,884 字节；这是小源码功能观察，不是大型工作空间内存验收。

首轮严格编译缩进失败、故障注入时测试误对空提交注册唤醒而中止、负候选 fixture 先误要求直接文件回退及 `.xl` 后缀均保留精确输入和日志。最后以真实包清单候选验证；没有将早期失败改成成功。SDK 快照期间，复制来的路径保护仍绑定旧任务目录，正确拒绝了重定向；随后只修正任务内路径，重新核对已冻结的 180 文件并完成自有 junction 重定向。

七个实际 C 保护遗漏反例全部被拒绝：缺少查询后最终守卫、忽略实际覆盖摘要、缺少完整上下文比较、允许配置入口使用库覆盖规则、丢失输入版本历史、忽略覆盖增减与负候选、允许未覆盖成员成功。首轮“删除摘要比较”反例未被检出，因为原编辑还改变了长度；保留原通过／未检出资料并增加等长 `number`→`amount` 编辑，最终确认摘要确实参与缓存判定。

22 套既有协议、9 项真实服务 GUI 及 1 项受控旧能力兼容通过；113 个 GUI 对象与冻结 180 文件 SDK／实际 DLL 匹配。这些是既有宿主功能的回归，不能替代尚未接通的 workspace/symbol 端到端验收。随后仅增加测试／构建注册，生产源码、公共头文件、普通对象、服务及 GUI 二进制不变，原配对结果继续有效；另以普通生产模块实际执行 21 项公开 API 检查。所有旧验证回执保留，后续补全回执明确记录测试范围变化。收集脚本的目录重名、断言计数误写及最终输出变量遮蔽另留日志；复用了实际已通过的编译／执行记录，没有重跑以取更好结果。
