# xlang IDE 架构与交互设计

本设计固定新 IDE 的工作台、工程模型与实现边界。状态为 2026-10-05 定版。实现工作区为 `D:\GIT\x-lang\ide`，主要实现参考为 `D:\GIT\auto_test_ide`。

窗口与消息框的当前实现规范见 [XUI 窗口与消息框迁移清单](window-dialogs.md)。

## 产品范围

首版提供独立可用的传统 IDE：工作空间与多项目管理、多文件编辑、C 与 xlang 双语法高亮与折叠、查找替换、命令浏览与集成帮助、基础补全、问题定位、构建、运行、输出、终端和本地任务状态。使用 C、XGE、XUI 与 XUI CodeEdit。

AI 对话、代码代理、FIM 服务、Android 设备管理、手机画面、电脑助手、图像采集、OCR、窗口探测和自动化业务任务不进入首版。任务面板仅管理 IDE 发起的检查、构建、运行和测试进程。

Windows 为首个验收平台。模型、协议和服务接口保持平台隔离；其他平台的窗口、输入、字体、进程与终端需要单独验收。

## 默认工作台

主窗口依次包含菜单栏、工具栏、工作台和状态栏。横向分割表示左右排列，纵向分割表示上下排列。工作台的逻辑树固定如下。

```text
workbench                     横向分割
├─ commands                   左侧命令列表
└─ center_and_right           横向分割
   ├─ center                  纵向分割
   │  ├─ editors              中央编辑区
   │  └─ bottom               中央底栏
   │     ├─ command_help      默认活动页
   │     ├─ problems
   │     ├─ build_output
   │     ├─ terminal
   │     ├─ tasks
   │     └─ outline            当前文档大纲（实现增量）
   └─ right                   纵向分割
      ├─ workspace            上方工作空间
      └─ project_properties   下方项目属性
```

底栏属于 `center`，不能挂在整个 `workbench` 下方。左右 Dock 从工作台顶部延伸到底部；底栏左右边界与中央编辑区一致。右侧工作空间与属性是同时可见的上下分区，不能改为互斥标签页。

沿用已确认的外观、菜单、工具栏和面板安排。初始宽度参考命令列表 190 个逻辑像素、右侧 242 个逻辑像素；右侧上下比例参考 3 比 2；中央使用剩余空间。底栏初始高度参考 180 个逻辑像素，允许拖动调整。布局使用 96 DIP 逻辑坐标；Windows 窗口适配负责最小客户区，渲染代理统一映射 XUI 的字体、表面与输入至物理像素。

Dock 支持调整尺寸、移动、隐藏、停靠和恢复默认布局。首次启动及恢复默认必须生成上述树。持久化使用稳定的逻辑面板 ID，XUI 运行时编号由适配层映射。恢复布局时过滤不存在的面板，修复空分区，保证编辑器和隐藏面板仍可访问。

## 命令与帮助联动

命令列表展示语言结构、基础命令、标准库和扩展库，支持分类及名称检索。条目使用稳定 ID，记录模块、签名、适用版本和文档来源。

单击条目更新底栏帮助，并激活帮助页。浏览命令不修改代码，键盘焦点保留在列表，便于连续浏览。只有显式插入示例或确认补全才修改文档，并形成一次可撤销操作。

帮助采用 AutoTestIDE 的单栏纵向文档结构：标题、功能说明、语法或签名、参数列表、返回值、范例和必要的附加章节依次排列。没有参数或返回值的语言结构省略对应章节。说明与范例不分左右两栏，章节共用一个纵向阅读滚动区。

描述按宽度换行，支持长段落、列表、代码块与章节跳转。范例使用只读代码展示和 xlang 高亮。参数表支持列宽调整，窄窗格合理重排说明列。切换命令重置阅读位置，同一命令刷新时保留合理位置。

命令列表、帮助、静态补全和示例插入共享 `CommandCatalog`。语义补全来自语言服务；目录补全只代表静态可查阅条目。正式数据来自语言文档、标准库和扩展库元数据，不凭名称猜测签名，也不另行定义编译器语义。

## 工作空间与项目属性

采用工作空间、项目、文件三层结构。项目下提供源代码、扩展库和资源分组，工作空间可包含额外说明文件。树是模型视图，节点编号和展开状态不能进入项目业务对象。

选择项目或其文件更新右下项目属性。选择工作空间级文件时保留上一个有效项目，并明确显示属性所属项目。当前选中项目与启动项目分别维护，查看其他项目不能隐式改变运行目标。

双击文件打开文档，同一规范化路径复用同一文档。启动项目通过工具栏或项目菜单明确设置；启动项目标记、入口文件标记和构建目标应区分。

项目属性包含名称、描述、根目录、输出类型、入口、构建配置、输出位置、C 源、资源配置、include 路径、library 路径、链接库、运行参数与工作目录。编译器未支持的选项不能展示为已生效设置。修改时先验证，再更新模型与项目脏状态，保存后写入项目清单。

## 编辑文档与动作

编辑器按 `.xl` 选择 xlang、按 `.c` / `.h` 选择 C，其他文件选择纯文本。语言模式属于文档会话状态，可手动覆盖；切换不会改写文本或文件扩展名。高亮、折叠、注释操作及后续语言服务使用同一语言 ID。

`DocumentService` 管理文本、路径、版本、编码、换行、脏状态和撤销历史；`EditorService` 管理标签、光标、选择、折叠和视图。多个视图共享同一文档，不创建相互独立的文本真相。

首版支持多标签、未命名文件、打开保存、另存为、全部保存、关闭确认、撤销重做、剪切复制粘贴、缩进、查找替换、跳转行、高亮、折叠与基础补全。项目清单的文本编辑和属性编辑通过文档服务协调，有未保存文本时不能静默覆盖。

文件监视器处理外部变化：未修改文档可以重载，有本地修改时提供保留、重载或比较选择。重命名、保存和服务请求关联文档版本，避免异步结果作用于错误文件。

菜单、快捷键、工具栏和右键菜单统一调用 `ActionRegistry`，根据当前模型和任务状态判断可用性。常用动作包括工程管理、文件编辑、保存、构建、运行、停止、面板显示、主题切换和恢复布局。

## 模块架构

```text
XGE 与 XUI 工作台
        ↓ 动作与模型通知
应用服务层
  WorkspaceService   DocumentService   CommandCatalog
  EditorService      TaskService       LanguageService
        ↓ 明确接口
平台与协议适配层
  文件和路径   进程与管道   文件监视   终端   LSP
        ↓
编译器进程   语言服务进程   用户程序进程
```

UI 层只更新控件，不组装编译命令或持有编译器上下文。模型层不依赖 XUI。服务拥有模型并执行业务动作，平台层封装路径、文件、进程、管道和终端。

应用上下文只装配各服务和管理生命周期。模块使用独立 `.c/.h` 编译，明确初始化、销毁、所有权和错误返回，避免通过包含大量业务 `.c` 文件共享隐含状态。

工作空间、项目、文件、文档、命令和任务使用稳定 ID。使用动态容器，不沿用旧 IDE 固定项目或文件数量的数组上限。异步任务持有请求快照或稳定 ID，不能持有可能因容器扩容失效的指针。

## 进程与线程

GUI、编译分析和用户程序分进程运行。首阶段通过进程适配器调用已配置的 `xl.exe`；后续编译辅助进程及语言服务可调用 `xlc.h`。不在 UI 主线程执行长期编译或用户程序。

GUI 中唯一的 XRT 实现由匹配的 XGE IDE 配置 DLL 提供。GUI 首版不直接加载 `xl.dll` 或 `xlc.dll`，防止不同运行时、分配器、全局状态和 ABI 混用。独立编译与用户程序进程使用各自匹配运行时。

后台线程处理管道、文件扫描和协议消息，通过有界队列交给 UI。只有 UI 线程修改控件。请求带项目 ID、文档版本和代次；过期诊断、已关闭文档的结果应丢弃。退出时先结束请求和子进程，再释放服务与 UI。

## 构建运行

`ToolchainProfile` 保存编译器位置、版本和能力；`BuildRequest` 保存项目配置、工作目录与输入快照。适配层生成参数列表，平台层处理中文、空格和引号，不让控件拼接 shell 命令。

当前工具链支持 `xl build <file.xlp> -o <output>`。运行优先执行本次成功构建的产物，也可提供明确的直接运行模式。DLL 项目可构建，没有运行宿主时不能直接运行。

构建前处理相关未保存文档；首版默认保存相关输入后构建。编辑中诊断使用内存快照，不为分析悄悄改写用户文件。运行使用启动项目。构建失败不得执行上一次遗留产物。

任务状态为排队、执行、取消中、成功、失败或已取消。重复构建同一项目时合并或排队，避免交叉覆盖产物。停止结束关联进程及其子进程，记录退出码、耗时和日志。

构建输出保留原始日志，问题页展示可跳转的结构化诊断。终端提供运行会话输入输出，不能将只读日志称为交互终端；完整系统 shell 会话需独立终端后端验收。测试任务使用项目显式配置的程序，不与 xlang 运行时 `task` API 混同。

## 语言服务

先接 CodeEdit 高亮折叠、目录静态补全和保存后编译器诊断。`xl check <file.xl> --json` 以当前文件为入口，不能直接当作完整 `.xlp` 多输入项目检查接口。

已经实现 C 编写的 `xlang-ls` stdio 基础、后台客户端及保存后真实单入口诊断。原生检查/取消动作、CodeEdit 标注和中央问题定位已接入；编辑、路径和文档版本变化会撤销旧结果。详见 [语言服务与保存后诊断](language-service.md)。

后续继续递归依赖覆盖和编译器语义查询。参考 AutoTestIDE 的传输、文档同步、请求关联、诊断与定义跳转，替换其 Python `ty` 服务及环境定位。

服务需要编译器提供源码范围、符号索引、类型查询、定义位置和未保存文件覆盖层。现有 `xlcAddSourceString` 与检查接口是起点，不能据此认为查询能力完整。覆盖层必须作用于依赖模块，不只覆盖入口文件。

明确 UTF-8 字节、CodeEdit 字符和 LSP UTF-16 位置转换，支持中文、组合字符和非 BMP 字符。语义能力按诊断、大纲、悬停、补全和定义跳转逐步交付；未实现能力不宣告支持。改名、引用查找和跨语言 C 语义后续扩展。

## 调试与工具链现状

本次核对的 DEMO6 文档表明：完整调试器仍为后续设计，正式 CLI 不提供完整 `xl dbg`、`xl dap` 或独立 `xldbg.exe`。首版不能使用合成栈帧、占位变量或 Python debugpy 会话宣称 xlang 调试可用。

保留独立 `DebugService` 扩展边界。源码断点、暂停继续、单步、调用栈和变量在编译器支持完成后另行验收；未就绪时不显示可用调试入口。普通构建运行不依赖调试器完成。

## 设置与持久化

设置分为程序默认值、用户偏好、可共享工作空间配置和本机会话状态。项目与工程定义可入版本控制；窗口、主题、光标、展开状态、历史任务和本机编译器路径进入用户或会话文件。

主题统一覆盖编辑器、菜单、表格、Dock、弹窗与帮助。沿用 AutoTestIDE 的角色令牌体系，UI 与代码字体分别配置，并验收 DPI 缩放。

布局与会话带版本号，损坏时回退默认并保留原文件。保存使用同目录临时文件和原子替换，保留未知扩展字段。清单使用 UTF-8 JSON。

## 动作注册实现映射

现有公共动作由 app/actions.c 的不可变描述表统一提供名称、快捷键、状态与执行。菜单、工具栏和属性按钮按稳定动作 ID 绑定；执行再次验证当前文档、项目、任务及模态状态。编辑器目标按键、COMMAND 和已注册的原生右键命令按真实目标文档路由，普通输入框保留自身编辑行为。绑定拥有者是应用动作对象，模型和后台线程不持有 XUI 指针。

本次落实 44 个现有内建动作，完整 Release 回归已通过；动态动作扩展、快捷键定制和未注册 SDK 命令仍属于后续范围。细节与原生验收见 [动作注册与统一路由](actions.md)，长期 IDE 目标继续进行。

现有工程引用编辑通过项目菜单和右侧属性进入独立草稿窗格，底栏及 Dock 树保持定版关系。FileEntry 与独立 Document 分离，C/资源编译字段从明确文件种类同步，库管理元数据与真正 import/链接独立。注册表当前 58 个公共动作，事务和原生验收见 [工程文件、资源与库引用](project-references.md)。

新建项目使用独立 services/project_templates 准备项目和文件计划，ui/template_view 持有独立工作空间基线与原生草稿。目录生成成功后加入模型，工作空间引用继续按已有保存协议持久化；失败不添加半成品。入口沿用公共动作，向导加入字体、DPI、模态保护和文件协调暂停协议，定版 Dock 不变。完整协议见 [项目模板与新建向导](project-templates.md)。

文件另存为的模型路径补丁由 services/file_rebind 准备，文档服务通过完整 saveFinished 生命周期报告结果。成功后无分配地替换工程路径，ui/editor_view 失效旧构建并刷新稳定树阅读；失败仅释放准备数据。其他线程不写 UI 模型，当前操作保持同步，不跨事件回调保留可变模型指针。协议与源码语义重构边界见 [文件另存为与工程引用协调](file-save-as.md)。

物理文件重命名通过 ui/rename_view 保存独立草稿基线，editor/documents 预分配元数据并调用 platform/file_rename，成功后复用同一引用补丁事务。文件字节与编辑器正文分离，未保存修改及撤销保留；旧任务失效，监视和会话使用新路径。原生菜单、F2 与模态/字体保护见 [文件物理重命名](file-rename.md)。

工程树重命名由稳定 FileEntry ID 解析当前路径。ui/rename_view 对未打开文件直接采集流式磁盘基线并调用 platform/file_rename，经 ui/editor_view 共用 prepare/finish 路径事务；已有 Document 使用指定源路径重命名，保证移动实际选中的硬链接。模型与磁盘基线都独立保存，不为二进制资源创建 CodeEdit，其他活动标签保持。SHA-256 使用 Windows BCrypt，SDK 未改动。

项目迁移后端由 services/project_migration 保存独立模型/集合基线与预分配路径补丁，清单移动和整目录移动分别使用平台文件摘要及目录身份保护。磁盘成功后只应用准备好的模型路径，保留 ID 与原 JSON 保存基线；整个目录中的未知文件由单次目录移动保留。现已通过项目菜单接入文档预分配批量绑定、监视 epoch、旧任务失效和默认/外置会话迁移，事务及已执行验收见 [项目清单与目录迁移](project-migration.md)。

editor/documents 的 relocation 计划只处理已打开文档的元数据：独立捕获全部打开文档，验证后由调用方完成物理操作，再一次转移预分配路径/标签，最后通知 UI。它不执行文档保存、不改代码对象或语法缓存，与 services/project_migration 的模型补丁共用一次确认边界；关闭窗口释放两个计划，磁盘失败不应用任一个绑定。Retarget 保留初始源身份，防止重新准备目标接受后来替换的源。完整 Release 已验证 44 应用模块、37 类测试、49 动作和 73 张原生图。

## 旧格式导入实现映射

services/legacy_import 持有独立旧清单字节/身份基线、转换草稿、稳定新身份和 JSON 预览，不借用当前 Workspace、Document 或 XUI 指针。选择先生成全部替换预览，提交在源清单只读锁与父目录身份保护下发布新目录，原资产不变。ui/import_view 负责显式分析、报告复核与当前模型/文档基线，app/actions 的 project.importLegacy（37）进入原生模态。生成模式只发布清单；打开模式先执行未保存确认和检查点，再发布、切换并调用 Session 的旧提示应用。已有原生会话/布局受到保护，缺失文件进入 unavailable 文档集合，原提示保存为 legacyImportHints 扩展。定版 Dock 保持原关系。完整协议见 [旧格式导入](legacy-import.md)。

资源配置的字段与素材检查位于 model/resources，原生 ui/resource_view 冻结项目、打开文档和目标文件基线。表单应用交给已有 CodeDocumentReplace 与文档保存服务，不另建磁盘写入通道；固定 xge.dll 持有所有值对象，编译器仍作为独立后台进程。版本、素材模式、类型保留和无损写出的协议见 [Windows 资源属性](windows-resources.md)。

## 库检查与文档往返实现映射

services/library_info 只读查找磁盘包候选并拥有检查结果，不持有 XUI 控件或改变项目元数据。ui/references_view 使用同一个独立草稿，在字段加入列表后查询所选项目与 TaskView 当前编译器；版本信息与 CommandCatalog 的静态包声明分别显示。候选清单存在、声明文件存在与真实编译成功是不同事实，递归依赖和链接仍由 TaskService 处理。

包文档使用原有中央底栏及单栏 HelpDocument。暂时收起引用窗格时保留原草稿与完整项目基线，CatalogView 的返回按钮只恢复窗口；重新加载目录后根据稳定包名重新查找，不保留借用的 command 指针。阅读期间允许正常操作，返回草稿可查看和取消，应用继续执行原项目/清单/属性保护。工作台 Dock 空间关系不变。协议见 [工程引用与包文档](project-references.md)。

## 工具链档案实现映射

services/toolchain 从具体命令帮助行识别能力，以 platform/file_rename 的只读流式快照记录编译器及两个兄弟 DLL 的身份。版本读取实际 PE 资源。任务的实时帮助与信息窗口查询共用线程安全、容量和年龄有界的观察缓存；真实构建不使用缓存替代当次批准。发布产物前重新比较工具链指纹，任务保留独立档案。

ui/toolchain_view 拥有异步请求与独立观察；取消/关闭只请求结束，轮询完成后释放，退出时先结束查询再销毁 TaskService/cache。只读摘要与原始帮助按纵向排布；UIFont、DPI、模态与按钮视觉状态沿用工作台接口。窗口只读，不改变文档、工程或中央帮助布局。缓存范围、失败提示与原生图见 [工具链信息](toolchain-profile.md)。

2026-10-07 实现增量：当前文档大纲复用中央底栏，默认活动页仍是命令集成帮助。原生悬停和 Ctrl+I 使用同次成功检查的真实声明及类型，保持左右 Dock、原事件链与版本/来源守护。旧十面板存档可恢复，新页通过视图菜单打开。见 [大纲与悬停](outline-hover.md)。
