# 编译器包搜索目录与阶段保护

实现状态：开发候选，2026-10-09。任务提交时捕获 IDE 进程的 `XLANG_PACKAGE_PATH`，保留未设置、空字符串和原始非空字符串的区别。实际构建进程仍接收这份原始环境值，调用快照和实际输入收据使用相同值；阶段租约只解析独立副本，不改写编译器参数或环境。

## 目录语义

Windows 使用分号分隔目录，空项忽略，空格保持为路径的一部分。普通相对项（例如 `../packages`）以实际编译器工作目录解析。IDE 构建进程的工作目录是保存项目清单所在目录，与 IDE 启动目录及配置的运行/测试工作目录分别管理。绝对目录继续指向原位置；重复目录不重复保留阶段引用。物理别名由阶段保护层进一步核对。

解析与占用保护在任务工作线程、开始编译器进程前执行。若目录位于有效的 `.xlang-ide-build/<GUID>` 中，活动任务及其完成历史保留该阶段租约，历史销毁后释放。编译器随后报告的实际源/候选路径仍由现有收据校验与保护机制处理。

首个版本曾以 IDE 当前目录查找相对包目录，可能保护同名的无关缓存，而漏掉项目实际使用的缓存。修复改为以 `task->directory` 解析租约查找目录，原始环境不变。

## 原生回归

`tests/package_stage_test.c` 已纳入严格构建与默认回归入口。真实子进程充当可控编译器，报告实际工作目录、原始包字符串及 Windows 路径解析结果，在不打开缓存文件的情况下等待。测试让 IDE 当前目录、项目目录和运行目录不同，并创建同名的项目缓存和启动目录缓存，从文件系统行为验证：

- Unicode 普通相对目录、绝对目录、空项和重复项按同一原始列表传给构建进程。
- 提交后改变 IDE 进程环境，已提交请求继续传递捕获值。
- 活动及故意失败后的完成历史保护实际项目缓存；无关启动目录缓存可以正常清理。
- 销毁任务历史后清理实际缓存，项目清单和源码继续保留。

同一原生测试与原业务对象重放时在项目缓存保护断言失败；修复后的业务模块通过该测试。旧程序、原始失败及源码/对象摘要独立保留。本测试验证任务服务的预先租约，完整回归另行验证真实 xlang 编译器的混编和实际输入收据。

## 仍需扩展的矩阵

普通 `.`/`..` 相对目录与完整绝对目录已经验证；2026-10-09 后续增量补充驱动器相对缓存的实际保护，并用 Win32/XRT 子进程核对当前盘根相对、跨盘目录和继承盘目录项，见 [Windows 路径工作目录](windows-path-context.md)。真实 UNC/映射网络驱动器、任意深工作目录和外部工具路径预算继续随发布矩阵验收。网络缓存的自动删除保持禁用。阶段清理的总大小配额、工程规模和崩溃重放见 [任务阶段目录保留](task-stage-storage.md)。
