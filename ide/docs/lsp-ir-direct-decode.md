# 原始 IR 片段恢复的成本与解码实验

2026-11-16，M7b6v。原始 IR 片段直接解码候选未通过性能筛查，优化实现移出产品源码，默认程序仍为 0.106，先前的 0.107 候选状态保持。产品保留独立预期值的深度／重定位／未发布计数回归。完整候选、旧函数对照和测量保存在外部材料，协议和公共分析结构没有变化。

## 外部候选的实现边界

稀疏节点解码直接填充已经预留、尚未发布的目标节点。先清零目标，再用 `memcpy` 放置每个经过原有掩码和长度检查的机器字，避免中间结构体的清零及整块复制。最后一个机器字只写入结构体剩余字节，读取游标仍消耗完整编码字；不要求输入对齐，也不通过整数指针别名访问结构体。

截断机器字会清零整份未发布记录，保留既有测试要求的零记录和所有指针清理。完整头部之后仍使用原来的符号掩码、字符串、二进制和包路径读取、分配与回退。节点／子节点计数及符号绑定仍在整个片段的所有可失败操作完成后才发布。

候选另将精确原生符号 ID 的映射直接返回原 ID。这与原有词法解析器的 `kind == 0` 分支一致；局部槽位和稳定实体身份仍使用原来的当前表解析及版本检查。候选没有增加持久缓存、分配、AST 引用、依赖库或平台 API。

## 成本定位

四种 512 辅助函数场景分别比较普通和临时计时图像：单文件／导入、字面量／声明编辑。每轮完成 120 次 stdio 检查、8 个进程，并核对完整标准结果。临时图像不作为性能准入图像。

词法表构造在热检查中约为 3.6–5.6 ms。逐节点验证分段计时自身开销明显，不能把观测到的分段时间当成原程序成本。进一步测量确认，普通编辑没有执行最终整图输入键编码；原始类型前缀编码约为 0.53–0.56 ms，片段恢复约为 12.1–16.2 ms。因此没有把未启用的最终输入键或较小的类型前缀编码作为本轮优化目标。独立函数身份／键段的准备性草案留在外部材料，没有进入产品源码。

实际对象反汇编确认中间节点数组消失，编译器同时将解码器内联进递归放置函数。不能据此宣称总栈用量下降：当前 Win64 对象的递归帧变大。新增对照验证接受深度 512、拒绝深度 513，并比较重定位后的全部节点、游标、触碰计数及未发布的模块计数。其他平台的栈和性能仍需实际验收。

## 正确性

候选的完整 221 个原生程序通过。八个直接包含生成 IR 实现的测试消费者重新编译，其余对象沿用公共头逐字节匹配的 0.107 构建，重新链接到修改后的核心。随后只扩充解码夹具的独立递归对照，使用相同公共头重新编译该夹具；原有完整结果保留。

外部候选的最终解码夹具通过 316,979 项检查，保留原有截断零记录断言，新增完整旧解码器／符号解析器和递归放置函数作为对照。覆盖所有机器字位、稠密／随机／未对齐编码、每个截断前缀、拥有／借用载荷、包路径、前后哨兵、读取游标、原生和稳定符号绑定及最大递归深度。三种实际 C 破坏分别省略截断回滚、错置机器字和返回错误原生 ID，均由当前夹具以逻辑断言拒绝。

提交到产品的回归只保留独立预期值的递归深度检查，并针对未修改的 0.107 核心单独重编译运行，合计通过 133,006 项检查。它逐节点核对行列、父节点和子节点偏移、未触碰节点及模块计数，覆盖拥有／借用两种模式、深度 512 接收与深度 513 拒绝。另三种实际 C 破坏分别改变深度门槛、源行映射和子节点重定位，均被保留的测试拒绝。扩展的旧函数对照和候选实现保留在外部材料。

21 组既有协议回归通过。IDE 使用匹配的 XGE SDK／私有 DLL 重新编译全部 140 个单元，通过 55 组配对检查及 47 个实际编辑器模式，包含 C／xlang 可编辑性、撤销、Unicode／IME 状态和焦点等既有检查。实体输入法和跨平台完整体验仍不在这些自动测试的证明范围内。

## 性能与交付

固定四组计划进行相同图像 A/A、上一份 0.107 与修订构建 A/B、默认 0.106 与修订构建的普通编辑 A/B，以及默认版本与修订构建的尾部注释 A/B。各组使用四对独立进程，32 函数执行 128 代，512 函数执行 14 代，并保留精确重复；先后顺序按进程对反转。计时期间不运行本轮编译、GUI 检查或材料归档，启动／运行的可用物理内存与提交额度门槛分别为 5／3 GiB。

共完成 16,128 次检查、224 个进程，四组原始结果全部保留。

| 对照 | 请求／进程 | 原门槛结果 |
| --- | ---: | --- |
| 候选自身 A/A，普通编辑八类 | 4,608／64 | 79／80 |
| 上一 0.107 与候选，普通编辑八类 | 4,608／64 | 79／80 |
| 默认 0.106 与候选，普通编辑八类 | 4,608／64 | 75／80 |
| 默认 0.106 与候选，尾部注释四类 | 2,304／32 | 40／40 |

A/A 唯一失败是 32 单文件字面量的一条 CPU 链仅为 984.375 ms，未达到原定 1,000 ms 精度下限；相对速度门槛没有失败。后续计划应预先为小场景留足链长度，本轮 128 代数据和精度失败保留。

同一 0.107 基线下，512 单文件字面量热 P95 为 160.5607→170.925 ms，超过 168.588735 ms 上限。四个大场景的热 P50 为 152.514→152.097、178.929→180.481、189.172→189.071、191.093→191.758 ms；这组测试没有显示值得引入该实现的普通编辑收益。0.106 对照包含既有 0.107 变更，归因以同一 0.107 基线对照为主。

默认版本对照的五项失败涉及 512 单文件字面量首次 P50、热 P95、CPU 交互链，以及 512 导入字面量首次 P50 和 CPU 交互链。尾部注释通过仍不足以完成普通编辑的性能验收。因此恢复产品原有解码器，保留默认发布程序和既有候选记录。材料索引为 `dev/release-materials/provenance/lsp-ir-direct-decode-20261116.json`。

下一步重点是减少最终 IR／派生表的完整重建，结合不可变函数输入与完整验证边界处理增量生产。大型工作区、全局内存、IDE 全链尾延迟、耐久和跨平台目标继续；不加入 DAP 或运行／调试态补全。
