# 私有 SDK 成套组装与公开接口兼容检查

本阶段将 SDK48 的实际严格构建产物组装为独立的消费者 SDK，供完整 IDE 集成验证。固定 SDK、现有应用和便携包保持原样；这份材料不宣告完整 ABI、许可、性能或正式发行验收。

## 成套来源

`tools/prepare_experimental_sdk.py` 核对原 SDK 清单、SDK48 实际构建报告、源清单摘要、全部 241 份源码材料和 DLL／导入库／资源对象。消费者公开头取自该次构建的源码树。新的源码描述指向实际 241 份材料，另存父清单和构建证据，不沿用旧 236 份描述宣称新 DLL 来源完整。

XRT 完整实现头与消费者声明头用途不同。实现头、配置和生成信息与原生成快照相同，声明头摘要也符合该快照的 `upstream.json`，因此继续使用该份生成声明。直接把源码完整头放入消费者 SDK，会引入不同的公开声明集合；首次检查正确拒绝了这种组合。

最终组装工具在新目录再次运行，并通过现有 `verify_xge_sdk.ps1`。两次组装的 15 份载荷和 SDK 清单逐字节一致；单独的准备报告含不同输出路径。XRT 继续由 `xge.dll` 单独拥有。

## 已完成的比较

`tools/check_sdk_public_compatibility.py` 使用当前 GCC 对两套公开头进行预处理，比较完整顶层 C 声明和 pragma 流，再编译原生大小／对齐探针。V5 的实际进程退出码为 0。

| 检查 | 结果 |
| --- | --- |
| 原有完整公开声明 | 9,070 条全部一致，包括出现次数 |
| 新增声明 | 11 条，限于 6 个类型和 5 个访问接口 |
| pragma 流 | 一致 |
| 公开具名结构 | 371 个 `sizeof` 和 `_Alignof` 一致 |
| 导出名称 | 原 5,949 个全部保留，新增 5 个，共 5,954 个 |
| 原导出序号 | 2,946 个变化，不能宣称序号稳定 |
| 现有原生 PE 文件 | 105 个应用／测试产物与 3 个冻结编译器产物 |
| XGE 导入 | 46,637 次按名称导入；没有按序号导入 |
| Windows 原生加载 | 私有桌面加载候选 DLL，解析全部原 5,949 个名称，退出 0 |

108 个 PE 的现有导入均能对应候选导出。检查器会比较序号导入的原有含义；当前真实产物没有这种导入，因此本次正向证据不覆盖实际序号消费者。原生加载探针运行于独立且从未切换的桌面和所属 Job。

## 拒绝混用材料

五个独立私有副本测试均以实际退出码 1 拒绝，并且未创建目标输出目录：公开结构字段修改后与源码不符、换入旧 DLL 后与构建不符、组装使用过期源清单摘要、兼容检查使用过期源清单摘要，以及 XRT 声明生成信息不匹配。副本清单中的文件摘要已相应更新，检查不能仅靠载荷哈希碰巧发现这些不一致。有效候选与固定材料在前后复核中保持一致。

早期 V1、V2、V3 的实际失败保留原脚本和报告。V1 揭示实现头／声明头混用；V2 的新增声明识别把引用的回调类型算作声明自身名称；V3 未发现先前向声明、后单独定义的两个结构。修正后 V4 和加强构建来源绑定的 V5 通过。完整原有声明必须相同的要求未放宽。

## 验收边界和证据

大小和对齐探针使用当前 GCC 16.2。原固定 DLL 的编译器为 GCC 16.1；本次不是两个工具链的全量交叉 ABI 证明。没有逐个调用全部函数，也未核对每个字段偏移、所有调用／错误约定和不透明内部状态。完整应用重新构建、标准回归及候选便携验收仍是后续步骤；干净 Windows、实体 IME 和混合 DPI 等原有发布缺口继续保留。

实际证据位于 `build/sdk-public-compat-v5/result.json`、同名控制器退出记录、`build/sdk-public-compat-rejections-v1.json`、`build/sdk48-consumer-payload-reproduction-v2.json`。阶段封存记录保存脚本、报告、日志、组装材料和三个新文档／工具快照，并复核原 1,619 份冻结材料、83 个正式对象、105 个运行产物和 3 个编译器产物。
