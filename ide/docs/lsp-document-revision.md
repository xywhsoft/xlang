# IDE 文档正文的 64 位修订

M7b4y，2026-11-11。后续 WorkspaceEdit 应用需要精确识别请求时的文档正文。检查发现，现有 UI 把 XUI 的 32 位版本投影为 xls_sync 的 64 位 revision，并且快照复用/结果接收也只比较 32 位值。底层类型宽度不能弥补上游时钟回绕；同一文档身份下的旧正文可能因此复用。

xide_document 现在持有独立的 uint64_t revision。每次成功初始化文档身份时从 1 开始，每个正文变更通知递增；撤销和重做同样推进，不因回到相同正文而倒退。suppressChange 只抑制模型刷新，不能抑制修订推进，所以外部快照替换也有正文围栏。保存、语言切换和相同正文的重载不人为推进正文修订；路径、语言、外部状态及文档身份继续单独比较。

达到 UINT64_MAX 后的下一次变更把修订置为 0，后续编辑、保存和重载保持失效，不重新变成 1。0 表示关闭/耗尽，不能授权快照；关闭再打开会获得新的文档身份和修订 1。文档身份分配也拒绝 nextId 耗尽，不能回绕复用旧身份。此为一个文档存储生命周期内的规则，未给跨存储销毁、应用重启的指针或序号赋予持久身份。

补全及语言分析的捕获、缓存复用和接收围栏均记录/比较此修订。实际同步提交入口向既有 XRT 工作线程传递完整 64 位值，保留 XUI 版本作为额外检查；线上 LSP 文档 version 仍为连接内单调正整数，两种时钟各自负责正文身份和协议传输。兼容的保存文件检查入口另有根文档修订围栏。诊断模型、注释绑定、语义颜色、引用与工作空间搜索的独立绑定也采用同一规则；这不是只修改一个公共结构字段。

普通变更回调增加一次常量时间整数更新，不新增正文扫描或分配。每个文档及相关捕获记录增加一个 64 位字段；既有脏标记、语法刷新和正文比较成本保持，不能宣称零开销。没有改动语言服务算法或改变协议版本，服务镜像及此前 192 个原生程序、13 套协议验收在本阶段未重跑。

专项实际使用公开 DLL 文档生产者及两个私有 UI 控制器，覆盖 C/xlang 输入、撤销/重做、保存、语言切换、受抑制的外部替换、64 位上界及关闭槽复用。控制器检查故意使旧捕获的 32 位版本等于当前版本，再验证正文修订能够拒绝旧缓存/结果；不是执行了数十亿次编辑的计时试验。真实同步工作线程的结果保留超过 UINT32_MAX 的修订，并为随后正文变化生成新的线上版本。复用相同正文时保留快照对象；耗尽时不保留可用输入前缀。

首次完整 GUI 回归发现引用和工作空间搜索的两个独立构造器漏写新字段，使有效查询被拒绝。修复原实现，并增加这两个构造器的直接正/反例，不放宽现有回归断言。第一批及第二批构建、失败运行与最初定向检查分别保留；最终匹配构建和回归以阶段材料索引为准。

最终重编全部 118 个 IDE 对象，通过 38 项 GUI/配置回归；三项新程序分别通过 28、17、28 项断言。15 个实际实现变异分别破坏正文推进、抑制通知时推进、两个时钟的耗尽策略、双控制器缓存/围栏/同步投影、兼容入口、自动诊断、注释和两个独立绑定构造器，均在预期断言拒绝。匹配 SDK 没有改动或重编，其前一阶段生产输入、对象和 DLL 身份复核保持。
