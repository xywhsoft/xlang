# 编译器语义索引接入边界

DEMO6 `xlcCheckWithIndex` 与 `check --json --semantic-index` 将真实语义 AST、作用域声明、引用目标和类型事实放入同一次编译检查的来源/解析观察报告中。协议与限额见 [编译器合同](../../docs/IDE语义索引接口.md)。

索引使用编译器真正创建的声明 ID，区分同名遮蔽，保留 CALL 选中的重载目标；声明名称范围来自原 token，导入后的内部重命名不会改写文件位置。auto 等临时符号类型使用 AST 独占副本，避免语义上下文结束后的悬空指针。缺少语义事实、隐式实体或生成节点时保持 null/0，不采用名称匹配伪造定义。

2026-10-08 增加独立的 `declaredTypeId`/`referencedTypeId`。protocol 与泛型参数可以没有运行时声明符号，类型参数 ABI 保持零；基类和 CLASS/PROTOCOL 泛型约束的引用身份来自真实检查。新增字段保持 schema-1，以全表一致的字段存在性区分能力，旧工具链保持此前的 TYPE 导航。根项目和隔离编译器仅调整语义检查/索引两份 C 源文件，未添加 AST 字段或公开 API，未分配额外运行时 SymbolId；兼容门禁比较同一源码的原 SymbolId 和普通/C 桥接生成头字节。

2026-10-07 已接入 `xlang-ls` 和 GUI F12，完整成功索引纳入同批次诊断的版本及输入守护，真实/异常 JSON 范围验证和独占生命周期已实现。索引仍最多 8 MiB，服务整体响应最多 12 MiB；旧快照路径保持 4 MiB。协议与原生导航边界见 [定义跳转](definition-navigation.md)。

已确认既有边界：显式文件名导入的未保存覆盖可能与失败包探测的磁盘来源记录冲突，旧工具链也会拒绝。26 项索引门禁保留该安全拒绝场景，并单独验证普通模块导入覆盖成功；没有将未解决的来源观察问题记为通过。接入阶段继续完善该记录模型和守护，详见编译器合同。

索引现保存在同一个已验证的 language snapshot 中。定义/类型查询必须核对入口请求、文档版本、每个来源摘要与持续输入守护状态；打开新依赖、改写正文、源身份替换或工具链变化都不能继续使用旧目标。从去 BOM 的原始 UTF-8/CRLF 范围转成 GUI UTF-16，保持已存在的中央编辑器问题定位规则，已接入实际定义动作、大纲和悬停，详见 [大纲与悬停](outline-hover.md)。

C/xlang 双语法、左命令 Dock、中央编辑器及其下方单栏帮助/底栏、右侧上工作空间下项目属性保持。后续已接入的 C 语义、语义补全和实际构建输入记录各有独立验收，见 [实施进度](progress.md)；完整 ABI 矩阵、性能与首版发布仍属于原长期任务，编译器基础验收不代表长期目标完成。
