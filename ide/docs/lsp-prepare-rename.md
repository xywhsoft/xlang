# 准备符号重命名

M7b6h，2026-11-14。原生服务实现 `textDocument/prepareRename`，返回实际语义绑定对应的 `{range, placeholder}`。支持准备操作的客户端收到 `renameProvider: {prepareProvider: true}`；未声明或关闭 `textDocument.rename.prepareSupport` 的客户端继续收到布尔 provider。CLI 后端不开放此功能。位置没有有效目标、源码检查失败、成员范围不明或不支持重命名时返回错误，不猜测光标下的词，也不请求客户端自行决定范围。

请求只需要 URI 和 UTF-16 位置，不需要新名称或私有输入回执。借用标准重命名已有的后台协调器、完整配置及在线正文快照，沿原生入口归属规则找到实际提供者，捕获精确原生 IDENT，检查目标与本地声明族的显式成员归属和已知外部声明策略。范围支持限定名称的后缀、BOM、CRLF 和非 BMP 字符，placeholder 来自原生声明，禁止用类型名称、客户端猜测或新名称替代。

准备阶段不遍历其他工程、不收集全工作区编辑，也不构造虚拟新名称做一次完整重命名。所选提供者仍执行原有完整语义/索引/IR 检查，本地声明图沿用现有捕获和缓存；入口归属可能需要解析其他候选入口的依赖元数据。这些元数据查询不等于其他提供者的语义检查。正式 `textDocument/rename` 独立重新检查全部范围、声明族、新名称冲突、假想正文和绑定保持；一次准备成功不保证之后任意新名称都有效，更不授予写入权限。

归属查询中，成功与未成功的入口探测都是新鲜度输入。准备结果保留原有依赖捕获或缓存来源守卫，覆盖实际提供者以外的负向路由证明。编码完整响应帧之后，再验证这些捕获及全部来源守卫；相同字节的文件替换也使旧准备失效。owner 继续检查文档身份/版本、inputSerial、配置 epoch、入站输入、取消、关闭和分析租约。目标存储可以脱离检查器和缓存独立存在，但存储有效不表示事实仍新鲜。

专项计数发现，将归属元数据与语义目标查询放在同一 key worker，会对未被入口导入的成员反复切换上下文，使同输入的第二次准备重新构建语义模型。准备操作现在让现有第一成员 worker 处理归属探测，保留 key worker 的语义上下文；没有新增线程、常驻解析器或路由缓存。实测专项的冷/暖构建计数由 `1 → 2` 修复为 `1 → 1`，暖查询产生命中。这是固定输入的语义缓存证据，不是端到端延迟或整体性能准入；其他操作的配置缓存计数问题未因此宣称修复。

协调器仍为四个请求，最多 64 个在线文档、2 MiB 复制标签和 64 个范围。准备增加 128 MiB 已知保留量门限，保守计入路由源码/原始大小、路径/探测行、目标、本地声明族和守卫；共享银行可能重复计费。捕获/缓存/分配器内部和临时开销不构成总 RSS 承诺。placeholder 限制为 64 KiB。准备失败、取消或容量不足不返回已处理前缀。

原生专项检查精确范围、一个实际提供者、暖缓存、零工作区/假想源码检查、冷及缓存负向路由的新鲜度，以及独立目标寿命。后台帧检查覆盖编码后来源替换、编码失败、取消和真实物理空闲。协议检查覆盖声明和限定引用、首行 BOM、Unicode 和半代理项拒绝、库成员与外部声明策略、其他工程错误的延后检查、旧客户端、精确类型的请求 ID、配置/目录变更和租约。实际编译的错误实现分别验证这些保护，原始失败及修正过程保留。

IDE 保持原来的原生候选预览、确认与异步混合写入流程，本阶段未增加准备结果的名称预填。IDE 的准备接入、完整工作区/项目/独立文件范围加载仍须继续；根目录会话缺少完整 analysisConfiguration 时依然明确拒绝。完整泛型/未绑定/生成事实和外部来源资格、引擎资产对齐、通用编辑应用、全目标延迟/RSS/耐久、Linux 和 sanitizer 验收保持开放。现用运行程序、SDK、active delivery 和线上更新不替换。材料入口为 `dev/release-materials/provenance/lsp-prepare-rename-20261114.json`，长期任务不在本阶段结束。
