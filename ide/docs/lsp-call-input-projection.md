# 调用缓存的输入投影与构造开销

调用表复用现在只复制生产函数实际消费的节点字段，并合并同一区间的重复节点读取。只移动源码坐标的第六代编辑能复用全部 19 个声明区间，最终完整 IR 仍与独立原生构造一致。它继续属于显式启用的原生组件，尚未进入普通 LSP 请求；根发布目录保留已配对验收的 0.110。

## 精确输入与生命周期

生成器对 17 个原生函数正文及完整依赖来源保持原有审核，同时从真正的 `XL6_IrNode` 声明和全部函数正文提取字段交集，要求恰好符合以下 14 项：

`callKind`、`childCount`、`firstChild`、`flags`、`implicitNameAbi`、`kind`、`lvalueKind`、`opcode`、`parent`、`sourceKind`、`storageType`、`targetSymbol`、`text`、`type`。

数字字段按实际 C 类型逐项精确记录，`text` 复制完整内容，孩子序列保持原顺序。源码坐标、字面量载荷和其他未读取的 ABI 字段不再复制到调用缓存键。此处不是通过最终输出相等猜测依赖；字段来自审核过的实际生产正文，原生完整构造仅用于独立验收。

入口的五字段投影是该集合的子集。在只读调用阶段内，同一节点的入口读取及完整辅助读取利用原有标记数组的两个状态合并，不添加第二张标记数组；入口后发生辅助读取仍补记完整投影。区间代号溢出时清零标记，保留原有失败回退、取消和所有权规则。类型查询、公共绑定／分派输入、参数基址重定位、独立名称所有权、最终契约与完整 verifier 不变。

生成器额外拒绝字段集合缺失、字段形态改变及入口直接读取改变，并将使用的模式解析工具纳入构建依赖摘要。仍要求精确原生编号和公共结构；结构编辑或编号重排可能拒绝复用，不能据此宣称已经实现完整函数级 IR 增量分析。

## 正确性范围

49 个完整语义输入通过 6,803 项普通检查；包括前五代调用／默认值编辑，以及增加 Unicode 注释与空行的坐标移动。后者调用阶段复用 19／19 个区间，重新进入的节点为 0；独立完整 IR JSON 同时验证新坐标。冷／热路径仍枚举 52／46 个外部 XRT 分配或 API 拒绝点、45／48 个取消点。

契约夹具通过 6,924 项检查，包含普通夹具、676 次退休单元清零、四个并发读取者各三代、实际查询类型变化、公共上下文变化及外层读取状态恢复。原有 1,862 个默认函数正文和两个私有布局的令牌对照一致。八个相关原生回归、两个默认不可用入口、16 项来源策略及实际编译缺陷结果见材料索引；不将包含式检查计数相加为语料数。

## 性能观察及发布边界

保留先前完整节点键图像的首次构造筛查失败：首次捕获／跨代中位数比值分别为 1.09755／1.03444，未达到跨代不高于 0.98 的预设筛查线。没有重跑同一图像消除失败。

本次字段投影及去重改变了实际构造代码，使用新的编译图像，保持原来的 24 轮交替顺序、三个模式及筛查线。每次结果都和完整原生 JSON 比较；同一进程共 72 次完整构造，移除故障注入链接包装：

| --- | ---: | ---: | ---: |
| 原生构造 | 5.44495 ms | 7.85310 ms | 1.00000 |

首次捕获不超过 1.15、跨代不超过 0.98 的两条局部筛查线通过。计时从已完成语义检查的 AST 开始，包含原始 IR 准备、全部阶段及完整验证；解析／语义检查、清理、LSP 通信和 IDE 不在计时内。单进程观察不代表所有工作负载、端到端性能或发行准入，也不把不同轮原生耗时直接比较。

本轮未替换发布程序，三个原有 IR 实验仍默认关闭。后续继续其他生产阶段、结构编辑的引用映射、普通服务接入及配对 IDE／完整性能验收。来源、真实编译命令、对象复用依据、旧失败和新观察均保存在外部开发材料包，小索引为 `dev/release-materials/provenance/lsp-call-input-projection-20261123.json`。
