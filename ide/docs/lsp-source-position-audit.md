# 语义坐标优化验收审计

2026-10-28 / M7a2b66a。两个开发服务 0.96 候选均未验收，IDE 继续使用已验收的 M7a2b65a / 0.95。所有候选源码、二进制、转录和结果保留在本机构建目录，当前生产源码已恢复为 1182 项基线输入的原始字节。长期任务 active，完整高性能 LSP 目标未完成，发布目录未替换。

## 尝试及原语义边界

第一版将语义恢复原先先求 UTF-16 列再重新扫描源码标量列的路径合并，复用 XRT 不可变行索引，ASCII 前缀减少解码调用。其正确性通过，但声明变化的补全 P50 235.499→231.359ms，仅改善约 1.8%；签名 254.166→235.804ms，检查 704.323→711.112ms，补全 P95 283.484→311.466ms，未通过预设门槛。240 次请求原样保留；下一阶段字面量计时前的内存预检停止。

第二版在现有行索引偏移字的空余位保存 ASCII 行属性，开头 BOM 单独处理；超大偏移使用不带标记表示。容器元素大小、容量、分配次数和逻辑字节偏移不变。原函数字节相等证明产生的旧／新函数行号只提出候选行，必须符合当前行索引的准确半开字节区间，否则完整二分查找。列仍从当前文本获得，UTF-8、CRLF、BOM、整数范围及来源／类型／符号／输入版本证明保留。增加的是暂存行号字段，没有新增语义缓存或持久类型／模块／最终 IR 生产器。

经验证的 ASCII 行候选可以直接求列，Unicode 行仍可能扫描行前缀；构造文本仍完整验证和建立行索引。这项改动没有减少语法复制、原语义证明、索引和完整 IR 处理本身。候选 API 及测试只在保留的实验源码中存在，未作为新产品接口交付。

## 正确性通过不代表性能验收通过

第二版通过 572753 项生产候选坐标／候选行检查，覆盖原算法和独立原始字节流参考、全部短文本位置、ASCII 控制字符、边界 Unicode 标量、BOM／中文／emoji／LF／CR／CRLF、512 组生成文本、长行、错误／边界／溢出候选行、失败输出不变、四线程读取和观测到的零 XRT 查询分配。另用实际 0.95 的原构造器建立独立旧快照，通过 777223 项 UTF-16／源码坐标／候选行／偏移／容量对照，避免让旧实现误读新内部索引标记。

最终候选的 190 个原生对象生产者中，7 个当前修订对象实际重编，183 个基线对象逐项验证当前依赖后复用；重新归档 62 成员、重新链接并执行全部 102 个原生夹具，核验 103 个 PE／104 项输出。100 个 AST 对象闭包对应 99 个独立 C 源文件，普通和受限索引从同一源文件按不同参数生成。GUI 文本对象重编，106 个原对象按 232 项实际 C／头文件依赖验证，42 个程序重新链接／编译内联夹具源。不能把它称为 190 个全新原生对象或 107 个全新 GUI 对象。

候选的 48 套协议、28 组 IDE、四组完整 AST／类型／索引／来源／报告／IR、标准导航、不同包上下文和查询体 fresh 对照全部通过；45 个补全场景／49 个服务进程在最终候选上重跑。公开候选头文件可独立以 C11 编译。它们证明已测正确性，不证明全平台、稳定 DLL ABI、完整 LSP 或最终性能目标。
