# 工作区符号的后台响应编码

M7b6o，2026-11-16。`workspace/symbol` 和 `xlang/workspaceSymbolNavigation` 的完整 JSON-RPC 响应改由原生 coordinator 编码。主线程保留输入队列、请求身份和配置代次的发布屏障，只发送已经编码的帧，不再遍历大型符号结果构造响应。标准结果和导航证明的数据格式不变，服务内部版本为 `0.103`；这不是 IDE 或更新通道的显示版本。

新入口以 catalog 为配置权威，补齐全部工程和已登记的独立文件范围，再合并额外的未归属独立文件。调用者即使没有重复传入工程列表，也不会只搜索当前工程或打开文件。提供的工程上下文必须与 catalog 完整一致；把工程成员伪装成额外独立根、外来工程或不完整 catalog 会失败。无 catalog 时仍支持独立文件，不引入工作空间前提。元数据处理复用既有 rename scope、XRT 上下文及成员索引，提交不访问文件系统或散列正文。

worker 在分析前验证外部范围证据，在完整响应编码后复核全部来源守卫及范围证据。校验覆盖没有命中本次查询的工程和成员。新增未打开文件、原始清单改写、同字节清单身份替换和源码正文变化都不能返回旧帧。后台刷新也携带相同的完整范围和证据，刷新结束后再次验证。缓存仍以不可变分析上下文保存事实；后续失败前内部索引代次可能已经推进，索引代次不能代替对外新鲜度证明。

响应包装保留已有结果节点，不深拷贝整份结果；请求 ID 独立捕获，保持整数/字符串类型和精确值。延续当前 ID 的 65535 个 UTF-8 字节及无 NUL 约束。成功的 framed 查询在 worker 释放排名结果和 JSON DOM，只把 malloc 帧及工作统计交给调用方；旧的普通、wire 和导航组件 API 保留。编码失败返回内部错误，范围失效返回内容变化错误，取消返回取消错误。字节计量 `encodedFrameBytes` 表示实际生成的帧，`scopeValidations` 是范围验证调用次数，不代表成功发布或系统调用次数。

沿用 64 个范围、65536 个绑定、16 MiB 上下文、128 MiB 已知范围载荷、64 MiB 输入存储和现有队列限制。ID 载荷计入标签预算；allocator、并发快照和其他持有者另计。两次范围验证不在每次按键补全中执行。传输仍由主线程写出，管道写入等待、配置回收和完整端到端延迟/RSS 验收继续，不声称所有主线程等待已经消除。

新增 15 个原生场景，使用两个工程、关闭成员、工作区独立根和额外独立文件，覆盖完整范围、精确 ID、导航、编码失败、编码后的源码/清单/目录变化、分析前失效、刷新和真实清单句柄中的取消。编码在实际worker执行；文件句柄打开时取消保持 pending 和非 Idle，关闭后才确认退出。补充 9 个真实协议场景，覆盖空字符串、零、int64 两端、Unicode/转义及最大长度 ID、导航源证明、空结果与无工作区独立文件。

本轮重新编译 122 个原生单元和 140 个 GUI 单元，执行 6 套原生专项、18 套协议检查（290 个场景）、55 项 GUI 回归、47 个实际 IDE 交互场景以及 C/xlang 的 24 帧渲染。原有符号专项还覆盖 52 个根和分析缓存、共享前台分析、刷新、导航、编码边界失败和取消。旧测试的固定 `build/` 数据路径仅在私有 fixture 中重定向到 F 盘，实际测试程序仍从根 `release/win_x64` 执行；不在发布目录创建测试数据。

8 个实际编译的反例分别验证：跳过前/后范围校验、只遍历部分工程、改变 ID 类型、提前宣布物理 Idle、漏掉刷新最终校验、把源码校验移到编码之前，以及回退主线程编码。反例编译和错误 include 路径的原始尝试保留，仅最终正确包含变更的执行计入。材料入口：`dev/release-materials/provenance/lsp-workspace-symbol-frames-20261116.json`。

默认程序、SDK、当前交付索引和线上通道未替换，匹配 SDK 的测试别名校验后从发布目录删除。继续实现引用的完整范围和编码后校验、服务自动发现状态机、资产对齐、其余 LSP/静态检查/补全及整体性能/平台准入；不包含 DAP 或运行/调试态补全。
