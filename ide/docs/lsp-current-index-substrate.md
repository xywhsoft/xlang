## 原生资产与身份

索引和类型适配器移入 `tools/native_index_overlay.py`，分别绑定旧资产与固定当前资产的完整摘要集合。集合包含前一阶段 Parser／AST／XRT 契约，以及索引、类型模型、类型注册表、原检查器和当前新增的构造流／原生值 profile／路径比较依赖；不允许只替换某个摘要后混用。

当前索引收集器的语言规则没有变化，其路径比较改为复用原生三态接口。当前类型模型新增共享构造流实现，并将默认 `Queue` 规范化为 `MpmcQueue`；别名声明选择、扫描顺序、原规范字符串构造及其几何分配规则保留。已有原生类型化索引继续按实际 arena 容量及 canonical 文本预算增长，JSON 路径继续保留自身规则。

当前注册表新增原生值和 C 拥有型标记，并调整部分集合类型；不能假定旧版本的原生数字 ID 保持不变。当前 `XL6_TypeInfo` 数据字段布局相同，也不代表跨上下文的编号可以直接复用。

声明版本键现包含 `semanticReceiverSymbolId`、`compiledPackageError`、`compiledPackageRoot` 和拥有型 `compiledPackageLink`。接收者复用原有的“已证明稳定实体／原生编号”区分；链接比较保留 NULL／空串区别，递归覆盖普通子节点、推导类型及声明类型。原函数体排除规则保留，超出原键预算仍拒绝这个可选版本资产。

这些是表示及声明身份规则；编译包信任、实际依赖有效性、完整语义 fact 重放和 IR 编号重绑定仍是独立工作。原检查器实际在特殊类成员作用域记录接收者编号，本轮使用含 `create` 的类验证该真实字段；没有将普通方法的 `self` 引用误当成相同字段。

## 独立原始检查器基线

新增 `tools/build_lsp_semantic.py`，复用 AST／语法构建目标的 Release 配置、全部依赖摘要、同一私有 AST 头文件和原生库。直接编译固定的原检查器、注册表、协议、文档／字段属性、标准库与 callable 源码，保留原类型规则；这里尚未启用 LSP 语义 memo 适配器。

检查器先从原 Parser 的源码生成真实已检查 AST，再交给 C 类型化索引和原 JSON 收集器。独立改名编译的原 JSON C 保持自身字面量 8 MiB 预算；适配后原生目标使用已有 32 MiB 配置。在两者预算都允许的用例中比较完整 JSON 及每个类型化字段，不借助模拟语义结果。

32／512 函数用例均执行原检查器并遍历比较实际类型化事实；大用例不以越过原 JSON 预算冒充 JSON 对照。新增值、变参函数类型、`@owned` 及其拒绝条件、Queue 别名、构造器、Unicode／BOM／CRLF 和不完整报告均有专项检查。

声明键 fixture 将真实索引 TU 的公开导出私有改名，直接验证实际序列化器。覆盖四种树位置的每个新属性、稳定实体映射、不同实体分离、NULL／空链接、超长键拒绝与恢复、原函数体排除。没有给产品增加测试 API，也没有替换其依赖实现。

本轮没有验证当前模块加载器生成的图、语义 memo 重放、完整 IR 或 IDE，也没有正式性能结论。独立目标仍使用前一阶段明确的语义 raw-body 终止护栏；它不会模拟未安装消费者的成功行为。

当前资产最终全新编译 48 个对象，12 个 fixture 共 65,932 项检查通过。其中 18,617 项复跑前一阶段 AST／语法检查，47,252 项检查原检查器、索引和注册表，63 项检查声明键；大量计数来自逐节点字段对照，不将它解释为完整语言服务覆盖。
