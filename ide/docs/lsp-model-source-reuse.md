# 复用上轮模型中的不可变函数

M7a2b126p，2026-11-10。普通增量检查现在可以直接复用上一轮检查仍然拥有的不可变函数，即使该函数没有进入可选的原生缓存。保留原来的语义、来源、坐标、类型／符号编号及最终 IR 检查。默认发行程序和线上更新通道没有替换，完整长期目标继续。

## 问题与实现

原生可选缓存的 32 MiB 额度只能覆盖部分大模块。一个 512 函数夹具原先保留 279 个函数；上一轮有类型模型其实仍拥有其余函数，但新检查会重新物化它们。扩大缓存到 64 MiB 的诊断试验减少了复制，也出现尾延迟和 CPU 上升，没有采用该办法。

新的 `frontend_model_source.h` 保存同步构造期间的控制信息，生存期覆盖整个 raw scope；调用者继续持有上一轮检查。`xlsSemNativeAcquire` 优先沿用已有可选缓存，未缓存的函数则从准确匹配的上一轮有类型模块取得一个独立引用：

- 检查上下文、入口、捕获模式、输入拓扑及原来源有效性仍先于复用。
- 检查原 memo、模块根、输入所有者身份、槽位、函数所有者及最终证明；C-owned 验证可能写入的树保持完整分析。
- 原始正文、全局环境、读取／效果、编号、坐标及最终 IR 准入规则不变。放入结果根之前再次核对来源，完整原生 IR 验证仍执行。
- 新有类型模块成功接管函数引用后，立即释放 memo 中的构造引用并清除标记。新 memo 不持有整份旧检查；构造失败或取消时，私有结果正常释放，保留原来的完整重试路径。

没有增加 TLS 对象。新增控制指针改变了私有 raw-scope 布局，因此依据实际依赖闭包重新编译全部 28 个消费者，没有把旧布局对象混入新布局测试。数据结构、分配及引用管理使用既有 XRT 和有类型函数接口。

## 避免导入入口造成重复分析

最初的模型复用原型在“入口保持不变、导入文件增加局部声明”时过早省略入口正文。依赖分析随后发现编号不能保持，原安全守卫正确拒绝并重做整次检查，复制量因此翻倍。

当前预检在投影当前文件时检查排在前面的其他输入：其不可变原始函数身份尚未到场时，新增的未缓存函数借用保持完整分析。当前输入内部的变化仍经过原来的完整语义守卫，仍可能重试；预检没有把语法形状当成编号等价证明，也不以函数名或语言特例放行。

小函数和不可缓存函数原先没有 raw-body 缓存事实；现在只为这些缺口补充原始单元身份，复用已有 owner map，并将指针表、原始单元完整计费和记录开销计入原 raw-memo 的同一个 32 MiB 额度。缺少证明、额度或分配失败时保守拒绝新增借用。原生可选缓存仍为 32 MiB。这不代表整个进程或全部瞬时内存已经受到统一预算约束。

## 验证

`analysis_model_source_test.c` 自包含实际生成的原生语义 TU，使用真正超过可选缓存额度的模块及未缓存函数。逐项比较完整 AST（包括原生 ABI／包字段）、来源报告、每一条索引事实及位置、完整 IR；沿用既有大夹具的直接事实比较，不提高 JSON 导出额度。覆盖错误所有者／memo／输入身份、缺失证明、可写 C 标记、跨输入预检、构造后发布清理、组合失败重试、取消及独立函数生存期。

私有候选和精确落盘源码各通过 1,230,488 项专项检查。七个实际编译的 C 破坏对照分别删除根归属、输入身份、只读条件、发布清理、放置前来源检查、跨输入预检、不可缓存函数身份捕获，全部由同一正常夹具以明确的 CHECK 失败检出。编译失败、崩溃和输出标记不能代替检出。

本阶段 155 项原有原生测试全部重新链接并实际运行；落盘后另编译并运行新增夹具，共 156 项。冻结的前端／私有 AST 组合与上一阶段一致，不声称重新准入并行修改中的当前引擎工作树。额外通过八套协议和十次真实导入声明检查：首次物化原／新均为 97,843 个节点，后续热修改为 47,017／4,793；完全相同请求不增加分析次数。IDE 全量重编 115 个普通对象、GUI 入口及资源，26 项联调通过，包含 C／xlang 输入、删除、撤销、Unicode／IME、焦点、补全、导航、引用、诊断和工作空间搜索。浅色补全、IME 预编辑及深色搜索截图已检查。

常规验收索引收集实际生效的 258 单元闭包和 749 项输入；原先合并报告中的历史、已被替换输入单独保留。落盘后的首次元数据核对因沿用旧根路径绑定被拒绝，随后只修正新索引的绑定，不重跑测试或改写原始报告。中间夹具和链接失败均保留在开发材料包。

## 固定的组件性能筛选

预先登记四对进程、512 函数、单文件／导入及字面量／局部声明四种案例、14 个版本和一次完全相同请求：32 个进程、480 个请求。默认后台开启，一次只运行一个服务链，统计整段交互链 CPU；启动至少 5 GiB、运行至少 3 GiB 可用物理内存及提交额度。计时期间本任务不进行构建或其他 QA；宿主并非独占。

原 40 项门槛全部通过；额外要求四类热 P50 至少改善 10%、物化中位数至少减少一半，也全部通过。
