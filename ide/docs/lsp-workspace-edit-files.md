# WorkspaceEdit 关闭文件的物理校验

M7b4v，2026-11-11。`platform/workspace_edit_files` 接收[不可变编辑准备对象](lsp-workspace-edit-staging.md)，为其中关闭的磁盘文件取得实际句柄，保留到显式销毁。它补齐来源证明与物理文件的联系，不写入源码，不改变编辑器或撤销记录；标准重命名与 `workspace/applyEdit` 仍未启用。

构造器先准备全部路径及祖先目录，排序去重后固定普通祖先，再固定可读写、单链接的普通源文件。文件和祖先均使用只读共享，源文件仍通过持有的读写句柄进行校验。最终文件与每一级祖先的重解析属性都检查，目录联接不能以“叶文件是普通文件”为由通过。整个构造失败会关闭已取得的全部句柄并释放路径和原计划租约，不返回已完成前缀。

当前适配器只接受 Windows 本地固定磁盘，拒绝网络/可移动盘、设备、备用数据流、尾空格/尾点等不明确组件、只读文件和多硬链接文件。源码文件最多 512 个、唯一祖先最多 4,096 个；排序前祖先候选最多 32,768 个，祖先路径存储最多 8 MiB。关闭文件按已验证证明计入每文件 8 MiB、合计 64 MiB 的原始正文额度。没有向独立语言服务器增加平台依赖，原生构建将本单元登记为客户端测试来源。

复用现有 `xideFileSnapshotInspectHandle` 与 XRT SHA-256 检查原始字节摘要和大小，再通过既有 UTF-8/BOM/EOL 解码器核对准备对象的 before 正文。两种证明都必须一致：只改 CR 为 LF、长度与规范化正文保持，也应因原始摘要不符而拒绝；原始摘要正确但正文声明不同，同样拒绝。没有另写文本编码器或散列实现。

成功后对象释放构造时的临时计划租约；调用者可以释放自己那份计划引用。借用元数据返回原计划行号、文件快照和同次解码的 BOM/EOL，不暴露可写句柄。对象由一个工作线程顺序使用，校验与销毁不能并发，也不保存取消回调、AST、JSON 或 GUI 对象。

M7b5c 增加已固定原始字节的分块导出，供[持久化准备包](lsp-edit-spool.md)复用。调用者提供新的空普通目标句柄；先拒绝与任意固定源码的物理身份重合，再核对完整源元数据、流式摘要和读后元数据。失败/取消留下的部分目标归调用者负责，导出不 flush、关闭或发布目标。

提交前 `Validate` 再检查持有句柄、当前路径指向及祖先身份，并重新计算全部原始摘要、比对元数据。只比较长度、时间或文件 ID 不够。普通 Win32 共享规则不是文件系统事务，也不保证抵抗已有映射写入者、文件系统过滤器或盘符重映射；最终检查仍与真正的磁盘提交/恢复机制配合。已固定的文件仅允许属性写入的句柄仍可能改变时间等元数据，实际测试确认这会使后续校验失败。

打开的覆盖文档明确跳过。本层因此不证明覆盖文档与磁盘目标之间没有物理别名，也不代替 GUI 身份/修订围栏、项目/连接/配置代次、注释批准、全局可写策略或 XUI 的提交/回滚。后续仍须完成这些边界，不能以固定文件成功作为编辑授权。

该工作仅在按需文件准备/复核路径运行，没有加入普通输入或增量分析循环。准备会多次读取/散列文件，解码器还复制原始和规范化正文；现有快照帮助函数及解码器包含不可抢占部分。局部取消点和静态额度不能解释为已通过端到端延迟、峰值内存或大工程性能准入。

新增程序通过 65 项主要检查；39 个观测到的冷态分配拒绝点分别在独立进程运行，29 个取消点逐点检查资源平衡。实际覆盖中文文件名、BOM、CRLF/CR、硬链接、只读属性、目录联接、已有写句柄、删除/祖先改名受限、正文变化、属性时间变化、原所有者释放及句柄/分配平衡。五个实际变异分别破坏原始摘要、解码正文、写入共享、重解析拒绝和最终快照比较，均在预期断言处失败。

匹配 SDK 下重新编译 118 个 IDE 对象，32 项 GUI/配置回归通过，包含 C/xlang 输入、删除、撤销、Unicode/IME、焦点及新物理校验程序。最后增加的原始换行反例只修改测试源码；该源码不在 GUI 产品依赖闭包内，GUI 测试直接编译最终源码并单独记录身份。已有 192 个原生程序与 13 套协议材料只按未变化的依赖保留，没有重跑冒领。服务程序、默认发布程序和交付索引未替换。
