# 光标可见区与自动换行布局修正

当前可运行包仍为 [SDK52 完整 IDE](row-index-integrated-editor.md)。本阶段在私有 SDK59 中修正光标可见区、自动换行行数测量、窗口尺寸变化后的光标跟随，并保留显式滚动的位置。C／xlang 原生用例通过；16 MiB 单行的行末文字仍然空白，尚未修复整段绘制的大坐标问题。

## 修正内容

原来的光标坐标以文本为原点，滚动模型却包含边栏和内边距。SDK52 在普通 8 KiB 长行上也会让 Ctrl+End 光标越过编辑区右边界。先前 SDK55 的直接增加边栏偏移尝试，使 Ctrl+Home 留下 66 的滚动偏移，因此没有采用。

本修订保持光标的文本坐标，使用扣除边栏和内边距的本地滚动模型判断可见性，再将偏移应用到原滚动模型。真实滚动条范围保持原有定义；行首依然是零偏移。

自动换行采用延迟测量的行索引。稳定刷新从此前已确定的滚动条宽度开始，避免每次刷新重建索引；索引重置后，若旧滚动位置超过临时估计的行数，测量最后一条已知行，而非直接跳过所有行。定位先测量光标所在行，更新内容范围和可用宽度。

还修正了两项回归中发现的问题：输入请求可能先于本帧的新布局，需要在尺寸变化后重新保证光标可见；移动到未测量视区时，新增换行行数会移动后续行的视觉位置，需要先稳定测量再绘制。后一调整最多进行八轮可视区测量，以避免无界重复；这里的通过范围由下列实际用例限定。

滚轮、滚动条、小地图和公开 SetScroll 入口均通过显式滚动取消光标跟随。测试确认视图主动回到零偏移后，再次缩放不会拉回行末，选择模型仍保留精确的行末字节位置。没有修改文档、选择、撤销或语言模式来满足滚动检查。

消费者使用同次公开头、DLL 和导入库，应用探针连接当前完整 IDE 的相同 83 个应用对象，运行时只有 DLL 一份 XRT。所有 GUI 用例均在自有、未切换的 Windows 桌面中启动真实进程，并记录实际退出码、UTF-8 输入、帧状态、位置、截图和日志。

早期失败记录保留：SDK52／SDK55 的行末或行首失败，SDK56 的自动换行垂直滚动失败，SDK57 的窗口缩放失败，SDK58 的多行换行位置漂移。准备阶段日志命名冲突与控制脚本检查计数错误也保留，未将它们伪报为原生引擎失败；未执行的分析脚本不作为验收记录。

## 尚未解决的行末文字

8 KiB 的行末文字可见。16 MiB 单行的光标虽然进入可视区，文字仍空白；相同亮色文本行裁剪区的暗墨像素只有光标附近少量像素。光标检查通过，不能替代文字绘制验收。原有[整段绘制路径记录](large-source-spans-pipeline.md)保留，下一步继续核对布局宽度与绘制位置的大坐标累积，并验证完整文本、字素和字体行为。

本修订存入 [私有源码补丁 v21](../third_party/sdk_patches/large-source-experiment-v21/README.md)，可用 `tools/prepare_caret_wrap_sdk.py`、`tools/prepare_caret_wrap_app.py` 向新目录准备材料；`tools/test_caret_wrap_sdk.py` 重新编译并运行完整引擎夹具。完整应用原生 C 夹具也保留在该补丁包中。尚未替换当前可运行包，未宣称整个 IDE 回归、极长行性能、干净 Windows、实体 IME、混合 DPI、许可或正式 SDK 验收完成。长期目标仍 active。
