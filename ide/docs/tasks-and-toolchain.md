# 构建运行与任务

实现状态：2026-10-22。C／xlang 单文件、独立 `.xlp` 与 `.xlw` 工作空间均可构建运行，无需先创建工作空间。单文件保存、产物位置和目标规则见 [四种构建形态](standalone-builds.md)。原生项目构建／运行／测试配置和编译器路径持久化已接入；系统 shell 后端仍待完成。

## 使用

- F7 / 工具栏“构建”：有项目时构建所选项目；无项目时构建当前 `.c`／`.xl` 文件。
- F5 / 工具栏“运行”：有项目时构建启动项目，无项目时构建当前 `.c`／`.xl` 文件；成功后运行本次产物。当前选中项目不改变启动目标。
- “项目 → 构建当前文件／构建并运行当前文件”：在已有项目时显式选择当前源文件。
- Ctrl+F7 / “文件 → 运行所选项目测试”：执行所选项目当前配置中的显式测试程序；见 [项目测试](project-tests.md)。
- Shift+F5 / “停止”：取消活动和排队任务，结束关联进程树。
- 问题页的双击或 Enter：打开文件并定位。xlang 的列按 DEMO6 Unicode 字符计数换算为编辑器 UTF-8 偏移，含中文和非 BMP 字符；C 后端当前可靠定位到行首。
- 任务页选择历史条目：查看该任务输出、问题和运行回滚。状态包含排队、执行、取消中、成功、失败和已取消，显示阶段、退出结果及耗时。
- 运行页支持键盘/粘贴输入；Ctrl+C 停止当前会话，Ctrl+D / Ctrl+Z 或“文件 → 关闭会话输入”关闭 stdin。当前是程序管道会话，不是完整系统 shell 或 ConPTY。

工具链选择顺序为 `--compiler PATH.exe`、`XLANG_COMPILER`、便携设置中的编译器路径、开发目录相邻的 `release/xl.exe`；也可通过“文件 → 选择 xlang 编译器”指定并保存。每个构建任务在后台执行 `--help`，核对构建和请求选项的实际声明。当前 CLI 没有被假定提供 `--version`；编译器路径保存到程序旁的 `option/settings.json`，保留未知字段；原子写入并拦截外部修改、损坏文件和锁定目标。保存失败仍可在当前会话使用刚选中的编译器，并明确提示无法保存。文件菜单的“工具链信息…”已提供后台 PE 文件版本、能力与指纹观察缓存；未提供版本资源时明确显示未知，刷新与失败保留已接入。每个构建仍执行当次能力检查，详细协议见 [工具链信息](toolchain-profile.md)。`--settings PATH.json` 可指定独立设置文件；隐藏验收默认不读写实际用户偏好。

```powershell
.\release\xlang_ide.exe --workspace .\workspace.xlw --compiler D:\GIT\x-lang\release\xl.exe
.\release\xlang_ide.exe --project .\app.xlp --configuration development
.\release\xlang_ide_console.exe --hidden --frames 3 --project .\app.xlp --compiler D:\GIT\x-lang\release\xl.exe --task run --wait-task --screenshot .\build\run.png
```

`--task build|run|build-file|run-file|test` 明确发起任务；单独打开文件或工程不会执行用户程序。`--wait-task` 仅用于有界验收，要求 `--frames` 和 `--task`，最长等待 30 秒，成功或失败均实际绘制最终面板。普通 GUI 运行没有该测试超时。

## 配置与保存

每个项目分别保存 `ide.activeConfiguration`。右侧项目属性中的“当前项目配置”可切换；旧项目未设置该字段时使用第一个配置。`--configuration ID` 可显式覆盖当前配置。构建使用配置输出路径、include 路径、library 路径和链接库；运行使用参数数组、工作目录和环境覆盖。没有通过字符串拼接生成 shell 命令，中文、空格、引号及尾部反斜杠已验收。通过项目菜单“构建、运行与测试配置…”或右侧属性按钮打开原生模态编辑页。支持新建、复制、删除和命名配置，编辑输出、工作目录、include/library 路径、链接库、运行参数及环境变量。列表提供添加、更新、移除和参数排序；空参数、空环境值、空格、引号及反斜杠原样保留，环境变量区分名称与值，拒绝重复名称。

页面使用独立深复制的草稿和基线；切换配置保留已有草稿，取消不改变模型，应用时整体校验后提交，并将当前配置设为该项目的活动配置。配置、运行配置的未知字段仍然保留，另存为重新计算相对路径。清单文档有未保存修改或配置基线已改变时拒绝应用。已排队任务保留提交时的快照，不跟随界面切换更换配置。

构建前保存项目文件、项目目录下已命名的相关脏文档，并保存脏项目模型。现有文档的外部修改保护和清单/属性冲突保护继续生效；有冲突时中止任务，不静默覆盖。若项目清单文本保存改变了模型定义，需要重新打开工程刷新模型后构建。

DLL 项目允许构建，但没有宿主时不能直接运行。DEMO6 会拒绝包含 `main` 或顶层执行语句的共享库；IDE 保留该真实错误。

## 产物与失败保护

提交任务时复制项目 ID、配置、绝对输入路径、参数及环境。每个任务在配置输出目录的 `.xlang-ide-build/<GUID>/` 下建立独立请求清单和阶段产物；编译器读取同一批已保存源文件，快照清单将入口、C 源和资源位置写为绝对路径。

只有编译器正常退出且本次阶段产物确实存在，才再次核对输入基线与编译器/兄弟运行时指纹，并通过同卷临时副本和原子替换发布到配置输出。编译失败、缺少本次产物、输入被修改、取消或发布失败时均不运行。旧输出可保留在磁盘上，但不能作为成功依据。

运行从新发布的配置输出路径启动，保留输出目录的兄弟 DLL 搜索语义。当前任务串行执行，运行中的程序结束后才处理后续任务；构建并发、运行期间构建和按项目产物锁需要后续调度扩展。

已保存的直接输入、列出的项目文件和资源配置引用的图标/应用清单在构建前后比较字节，内存编辑通过路径通知使相关排队/构建任务失效，硬链接身份检查由后台完成。资源发现期间保留编辑通知，目录外脏素材文档在工作线程启动前加入守护，完整协议见 [资源构建输入](resource-build-inputs.md)。新编译器声明 `build --input-report` 时，再读取同次构建的实际 xlang/C/头文件/包/链接/资源输入及搜索候选，后台复核身份和摘要。发布及运行前重新校验，发现图前尚未匹配的编辑通知不会丢弃。旧编译器仍只提供直接文件与资源守护，界面明确显示此范围。

## 日志与边界

实际依赖协议与边界见 [构建输入记录](build-input-receipt.md)。提交时冻结包搜索环境 `XLANG_PACKAGE_PATH`，构建明确使用该快照；运行配置中的环境覆盖仅作用于运行。不同包环境请求不会合并。独立阶段目录的 `inputs.json` 必须匹配本次阶段产物，`build-invocation.json` 保存实际参数、环境和工具链指纹。声明能力却未提供有效记录时失败，不回退旧范围。

任务保留 `compiler-help.log`、`build.log`、`run.log`、请求清单和阶段产物；构建输出显示日志路径。原始进程输出完整写盘，UI 使用有界队列和 256 KiB 显示尾部，溢出明确标记，避免输出不断增长占满界面内存。问题解析只作用于构建阶段，支持 Windows 盘符路径及编译器的行列前缀。

直接输入字节基线限单文件 16 MiB、总计 128 MiB；实际记录另限正文 32 MiB、1,536 个文件、单文件 64 MiB/总计 320 MiB，校验使用流式读取。超限明确失败。完成后释放直接输入字节基线；工作线程确实退出后，另释放请求快照、参数和校验对象。任务页保留最新 64 项完成记录，并保护当前选择和自动跟随的任务；活动及排队任务另计，最多 32 项。日志缓冲从 4 KiB 按需增长，每个通道上限 1 MiB；详情见 [任务历史](task-history.md)。磁盘阶段目录和原始日志不会随内存历史裁剪而删除，磁盘保留策略仍待实现。完整系统 shell、伪终端尺寸协商、C 诊断精确列、工具链版本持久化及协议范围外的依赖覆盖继续实施。

任务服务不加载编译器 DLL，也不在 UI 线程运行编译分析或等待进程。唯一 XRT 由固定的 XGE IDE 配置 DLL 提供。

## Windows 长目录

项目模型、清单、任务参数和界面继续使用普通绝对 UTF-8 路径。IDE 在磁盘 I/O 边界转换为 Windows 扩展路径，覆盖项目清单保存/读取、直接输入基线、请求快照、调用记录、实际输入收据、原始日志及产物发布；校验仍保留原句柄身份与摘要检查。SDK 和 XRT 实现未改动。

测试覆盖快照路径 254 个 UTF-16 单元、调用记录 264 个单元，以及 430 个单元的目录下清单、收据、产物、日志和程序。真实 C/xlang 混编必须完成构建、输入核验及运行；发布目标被锁定时必须失败并保留旧输出字节。显式指定的超长绝对程序路径在启动边界转换，运行参数保持配置值。

深工作目录在已有短名可用时，后台进程服务核对原目录和短名的卷号、文件身份及目录属性，再用该短名启动。配置、项目模型和日志中的原工程路径保持原值。目录句柄保留至子进程退出；父 IDE 的工作目录不变。短名仍属于原目录层级，实际子进程检查了相对文件、`..`、盘符根路径和盘符相对路径、参数、环境、标准流、退出码及原始日志。真实 C/xlang 混合项目从普通项目目录构建，配置的运行目录位于带已有短名的深目录；运行通过 C 的相对 `fopen("input.txt")` 读取该深目录内原文件。

没有可用短名的深工作目录仍不支持。在新建私有 NTFS 目录中仅移除该夹具目录的短名后，普通路径和 `\\?\` 扩展路径均在真实 `CreateProcessW` 中返回错误 267；扩展路径 I/O 的成功不能绕过工作目录限制。[Microsoft 的工作目录说明](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-setcurrentdirectory)也确认这一边界。任务现在保留 Windows 系统错误码，已有深目录缺少核验短名时还显示 UTF-16 长度，并建议缩短工程位置或配置的工作目录。启动失败不运行旧产物；专项实际核对旧产物字节和所有输入文件未变。IDE 不创建目录连接来替代工作目录，因为连接会改变 `..` 等路径的含义。

早期固定编译器在已有短名的深工程中启动成功，但以 `cannot read xlp` 拒绝超长绝对请求清单；原始清单、调用记录和日志继续保留。2026-10-10 的独立适配修复 Win32 文件访问和 CLI 的 512 字节项目路径缓冲，真实深工程的 C/xlang 混合构建、产物发布与运行专项通过。输入报告绑定原深目录清单、源码、带中文/emoji 的头文件和产物摘要。无短名深目录的文件访问从普通工作目录另行通过；无短名工作目录的 IDE 启动依然拒绝并保留旧产物。路径超过编译器的 4095 个 UTF-8 字节边界时明确拒绝。修复补丁、复现工具和范围见 [编译器深路径](compiler-native-paths.md)，不能由这些结果推断所有卷、外部工具或动态库加载路径均已支持。

`tools/test.ps1` 默认运行 SDK 任务路径用例；提供 `-BuildInputCompilerPath` 时，再运行真实 C/xlang 编译器及收据校验用例。该编译器须声明实际输入记录能力。


## 保存后语言检查

语言服务使用独立协议进程调用真实 `check <file.xl> --json`，结果进入 CodeEdit 和既有中央问题窗格。任务诊断与语言诊断有明确来源；选择任务会恢复该任务列表。进程服务默认仍合并 stderr，协议模式将 stderr 隔离并公平读取两个输出流；stdout 丢弃不会被当作有效协议。检查服务不代替 `.xlp` 构建或递归依赖版本覆盖，详见 [语言服务](language-service.md)。
