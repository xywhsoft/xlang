# IDE 原生候选后台控制器

M7b6b，2026-11-14。`edit_controller` 已接入 IDE 的正常语言轮询、传输接收回调和源码屏障。它复用已有请求捕获、原生 RPC、来源守卫和 WorkspaceEdit 准备模块，取得经过数据校验的只读候选。标准 rename/applyEdit、菜单和事务写入仍未启用。

每个主语言视图拥有一个 XRT 常驻线程，同一时间只保留一个操作及一份待处理回复。UI 捕获已确认的完整请求并复制有限的 URI、新名称、位置；后台准备调用和编码请求。UI 在发送前重复完整 Current 门槛，将同一连接的已编码数据送入原有队列。传输回调只按实际连接身份、整数请求 ID 和原始帧长度移动回复所有权，不解析来源证明或重新编码正文。回复路由、文件读取、哈希、来源/编辑校验及大对象释放均在控制器线程完成。

初始化只有原生后端明确声明 `experimental.renameCandidate: 1` 才允许进入新控制器。候选返回后，UI 再核对完整模型、配置、工作空间、请求及连接；不能用后台完成状态替代本地时效检查。后台 READY 只是数据准备结果。`xideLanguageEditCandidate` 在借出候选前仍重复完整 Current；借用不能跨 End、重置或其他改变状态的 UI 事件。

`edit_call` 同时预先编码原始 ID 的 `$/cancelRequest`。取消立即使本地请求不可逆失效；UI 对原始连接尝试发送预编码取消通知，队列满则保留它供重试。未发送的请求不产生取消通知；成功取消不会重复排队，同数值 ID 的其他连接也不能收到通知。发送和取消的 UI 路径不创建 JSON 或扫描源码正文。

控制器操作登记到 sourceJobs，使用新增的持久工作线程 probe。登记前后仍有同步构造 admission；不改变其他生产者基于真实 Win32 HANDLE 的规则。源码语言租约显式关闭控制器 admission，取消未完成工作；已经 READY 的候选保留供后续事务门槛使用。probe 要求 admission 已关闭、没有排队工作且后台已物理离开读取/准备/释放过程，不能把取消标记或已取消 future 当作静止。恢复仍由原有六参与者屏障显式驱动，没有超时自动解锁或隐式写入。

End 把退役交给工作线程，视图只移除自己的共享请求引用。已保留的计划继续拥有不可变正文，原候选释放不会破坏它。重置时先使旧请求失效；关闭时先停止传输回调，移除 sourceJobs probe，再等待控制器线程。没有后台回调借用已销毁 UI 状态。

原有 URI 262,144 字节、新名称 4,096 字节、帧 8 MiB，以及来源/目标/计划预算继续适用。新的 owner 提交只分配一份有界操作元数据，不复制编辑器正文。线程、mutex/cond、共享文本、DOM、编码包、编译器及其他内存另计；没有进程 RSS、整体时延或零开销资格声明。

验收包括：

- 原生及配对 GUI/XRT 控制器各 76 项检查：真实五目标 RPC、整数 ID、原始连接及帧上限、重复操作拒绝、READY 保留、构造/验证入口与实际源码读取完成后的受控阻塞、取消后真实静止、恢复及后台退役。
- 取消专项验证真实 stdio 顺序、仅一次通知、其他连接隔离、未发送抑制、发送队列拒绝后重试，以及取消时没有 owner JSON 编码。
- 真实 IDE 专项验证两处完整 Current 门槛及能力协商、候选在屏障中保持有效、C 输入使原请求失效、计划独立保留、取消与重试，并保持 C/xlang 输入、删除、撤销、IME 和焦点；另跑持久线程、源监控、六参与者及双连接租约回归。
- 完整 55 组配对 GUI 回归和 C/xlang 各 24 帧启动截图。8 个独立错误实现被断言拒绝，涉及物理静止、连接/容量、实际取消发送、取消连接隔离及三个 UI 门槛。

旧文件监控测试对任意线程的下一次 malloc 注入失败，首次完整回归在其 resume 断言停止；当次未记录消耗故障的线程，不能断言具体原因。诊断运行的失败正确落在 owner，恢复保持关闭。现在把该测试明确限定为恢复调用方，并用受控异线程分配确认不会消耗 owner 的故障，再执行完整回归。生产文件监控实现没有变化。

具体构建、最终夹具、失败历史和运行库身份见 `dev/release-materials/provenance/lsp-edit-controller-20261113.json`。本轮原生服务全量重建后与上轮已验收服务字节相同，既有 85 个协议场景按同一服务、编译器及协议工具身份引用；新控制器和取消使用本轮真实传输执行。IDE 对应的 134 个单元已全部重编译，保护现用发行程序而使用根 release 下的临时匹配 DLL/程序入口，验证后移除。

后续仍需完成命名模型/物理别名及固定文件策略、原有守卫与事务自身写入的协调、确认/应用/回滚/恢复接入，再启用标准重命名操作。当前引擎资产对齐、完整泛型/非绑定/外部来源资格、其他同步读取点、整体性能/资源/长时间运行、Linux 及 sanitizer 验收仍开放。C LSP 保持关闭；没有 DAP、运行态或调试态补全。
