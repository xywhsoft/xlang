# WorkspaceEdit 的光标与选区映射

M7b4z，2026-11-11。`editor/workspace_edit_positions` 为后续 IDE 批量应用编辑准备不可变的位置映射。工作线程从已验证的 WorkspaceEdit 生成索引；读取方按原 UTF-8 字节位置查询，不重新扫描全文或按编辑数量线性遍历。

复用文本同步原有的公共前缀/后缀差分算法，将其抽到内部 `analysis/text_span.h`。原 `xlsTextDiff` 和新映射构造器调用同一实现，保持 UTF-8 标量及 CRLF 边界。对每项替换裁掉未变的首尾，只保存实际变化区间；未改变的编辑不生成映射项，整个文档未改变时保持位置不变。before/after 正文借用原准备计划，计划由映射对象持有，不再复制或创建正文快照。

每个文档的区间保持原计划的排序与同起点顺序。LEFT 在同点插入之前，RIGHT 在同点插入之后；落在变化区间内时分别映射到前/后边缘，结束边界及相邻编辑单独处理。区间之外按已有长度差平移。单次查询为 O(log edits)，只检查常量个字节的标量边界，不分配或解码整行。空文档、文末、无操作和多次同点插入有明确行为；非法文档/位置、UTF-8 连续字节内部或非法 affinity 不改变输出。

折叠光标的两个端点均采用 RIGHT，插入后仍保持折叠。非空选区的前缘 LEFT、后缘 RIGHT，保留正反方向；删除后可以折叠。这里只返回 anchor/caret，XUI 的其他选区标志由调用者保留。不能把 UTF-8 标量边界当作完整字素、折叠、滚动或语义光标策略。

只裁掉每项替换的公共首尾，不在变化中段执行完整 diff。一个包含多个内部变化的全文替换，中间的未变文本仍可能按区间边缘映射；格式化/代码操作应优先给出细粒度编辑，完整阅读位置策略仍随应用器继续验收。该模块不直接修改控件、文档模型、撤销或磁盘，也不表示标准 rename/applyEdit 已启用。

构造复用 XRT 分配器，保留计划租约，最多 512 文档/65,536 编辑。默认/最大已知额度为 128/256 MiB，包括 plan.Info.bytes 和映射的实际请求存储；分配器及运行时开销额外，不是 RSS 上限。失败立即清理，不返回前缀。取消在文档、编辑及首尾扫描的 64 KiB 位置检查；只覆盖本构造器，不能声称端到端取消上界。销毁可能释放最后持有的大计划/快照，应在工作线程退休；读取期间由调用者保持对象生命周期。

专项通过 72,132 项断言，覆盖明确输出的字节/Unicode/格式化首尾例子、正反及折叠选区、12,000 个逆序编辑和原计划所有者释放后的四线程读取。分配观察确认三个直接分配点、三个独立进程冷态拒绝、八个取消点和精确额度边界，查询无直接分配。故障程序还有约 20 万次字符串准备循环检查，不把它们计作新增语义覆盖。原文本与文档同步程序重新链接并通过 1,029/895 项检查。

旧的边界夹具在 main 内使用返回 false 的 CHECK，可能把断言失败返回成进程成功；现改为由 main 转换真假，原 97 项断言保持，并用故意失败的夹具证明退出码为 1。这与十个真正破坏实现的变异分别记录：左右边界、首尾裁剪、标量边界、折叠/反向选区、计划额度与扫描取消均在预期断言检出。

抽取差分核心后重新编译的 Text 对象有变化，不能称对象等同；使用原有精确依赖重新链接的语言服务与已验收 df290f26 镜像逐字节一致。新映射为客户端单元，没有加入独立服务的链接。原有其他原生及协议材料不在本阶段重跑冒领。匹配 SDK 沿用前阶段，最终 GUI 编译/回归和完整输入身份以材料索引为准。
