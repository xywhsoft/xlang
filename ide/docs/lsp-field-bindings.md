# 字段的原生声明与引用身份

M7b4b 为现有定义跳转、引用、高亮、悬浮信息和文档符号提供字段绑定事实，并补齐重命名目标捕获的字段基础。仍未开放 `renameProvider`；可写范围、族闭包、冲突及改名后绑定证明和 IDE 编辑事务继续实施。

字段使用编译器原有符号分配器，在原有实体遍历中获得身份。索引选择原字段名称 token，空名称不产生选择范围。点查询分类枚举仅在末尾增加 FIELD，旧枚举值和公开事实结构保持。LSP 的字段 SymbolKind 为 8。跨编译批次仍使用完整声明来源与字节区间作为引用键，不依赖批次内数字 ID。

静态、普通、泛型、安全和聚合字段的使用事实来自原类型解析函数已经选中的字段。类型克隆或代换成功后记录该结果，不重新查询字段，不在主机层按名称查找，不增加 AST 遍历；原访问规则、继承顺序和 getter／方法计划保持其职责。隐式 `self` 使用同一次原生查找选中的字段。字段身份由现有语义事实及实体投影携带。

执行表示需要区分函数类型字段与方法引用：具体字段保持 MEMBER 值，不因它现在带有目标身份而被转换为普通函数 NAME。另一个边界是隐式字段的接收者相对 ABI：旧分类器拒绝任何正目标；现在允许实际 FIELD_DECL 目标，再要求原布局、类型、名称与声明身份同时匹配。越界目标、非字段目标及另一个字段均不能借此获得 ABI；没有目标的旧路径保留原规则。补充测试对照清除新增目标后的原算法输出，覆盖全部可选输出参数和错误目标。

观察字段结果本身没有新增分配或类型查询。完整模型会多保留字段实体、引用和符号槽，继续受现有 XRT 容器及各层预算约束；这不意味着整条分析路径零分配、全局内存有界或最终性能目标已经达成。新的正式性能准入仍待完成。

本轮保留了几类实际失败：误把普通绑定方法当作 NAME、未真正移动编译批次 ID 的测试输入、要求字段没有声明 ID 的旧断言，以及历史编译入口仍指向旧源码快照。最终资格检查须证明当前源码进入实际编译对象及链接程序，不能只提交未参与构建的根源码。`tools/check_native_receipt_bindings.py` 核对实际依赖摘要、主测试对象、全部直接链接对象、core 成员和指定当前源码；冻结副本只能有换行差异。

详细材料以 `dev/release-materials/provenance/lsp-field-bindings-20261110.json` 为入口，原始日志、对象、尝试源码、协议往返和 GUI 记录保留在开发材料中。普通运行与测试入口使用根 `release/win_x64`；默认发行程序和 SDK 未因此替换。

最终验证为 165 个原生夹具、10 套协议和 27 个 IDE 夹具；字段专项 6048 项、重命名目标 642 项、隐式 IR 分类 36308 项、声明投影 4360 项、索引存储及匿名选择 12655 项检查通过。五个真实 C 变体分别破坏字段选择、使用绑定、同名字段区分、函数字段表示或隐式字段身份校验，均被拒绝；前一匹配服务不能通过新增字段协议用例。配对 GUI 重新编译 116 个对象，使用同一语言服务和匹配 SDK，浅色、深色原生图已复核。源码资格检查绑定了 272 个消费者、166 个程序及 core 的每个成员，包含普通和 1024 字节预算的索引变体。
