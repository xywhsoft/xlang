## 来源与接入

ABI、AST、Parser、类型、索引和 XRT 基础资产继续使用固定提交 `9192a99f96ecd83bd57ca6e53df6dfcdda7d2f15` 的 2,447 份冻结文件。IR C 采用共享修复提交 `ee9a87a73dd2db55cda388409ff2d6395a140817`，摘要为 `e1ea31c336278b6729369e9f6a1bb4d86a4e945018a88f8c672c0a643e089628`。这是一项明确记录的源码组合，不把旧基础提交声称为当前整仓库 HEAD。

- 提取旧构建器已有的候选扫描适配，供旧、新 IR 共同使用。旧分支仍应用原十五处改写，生成 C 与正式 0.99 IR 对象均逐字节一致；新分支应用十四处。
- 当前编译器已将区域包含查询改成有界祖先遍历，并按原规则选择编号最小的匹配块。保留该实现，不再应用已经移除的全节点扫描替换。已有区域索引的工作计数因此为零。
- 清理候选、调用来源、退出计划、单次验证中的成功证明与初始化表查询，继续复用原 XRT 数据和既有预算／线性回退。类型声明查找、作用域动作检查、初始化查询、隐式转换和刷新阶段的原函数正文已与旧基线逐段核对。
- 递归取消在当前子节点构建结束、`auto` 存储类型处理之前释放临时子节点列表。顺序变换链从 26 项普通条件加一项 dispatch 条件，更新为 28 项普通条件加一项 dispatch 条件；仍沿用原失败分支释放模块。
- 统计阶段在取消前退出初始化表借用作用域。验证器的四个前置节点循环、两个拥有 incoming 临时数组的循环和释放后的循环，保留各自正确的清理路径。

准入同时核对从实际 GCC 依赖中取得的 184 份 IR 包含文件。补齐这些只读准入检查后再次派生的正常 C，与已验收编译输入逐字节一致；生成器历史输入及新的准入记录分别留存。

正常 `prepare_native_ir` 只对上述已修复 IR 的精确当前组合放行；未修复的冻结当前 IR、未知源码和旧 AST／类型／XRT 混搭仍被拒绝。正常入口生成的 C 与独立验收目标逐字节一致。旧 IR 分支保持原准入规则。

## 共享前端修复

完整旧扫描回归检出了当前原始编译器中的访问异常：`xl6IrVerifyOwnedReadResults` 在完整调用表验证之前计算构造效果，经由 `xl6IrCVarargCallSiteHasText` 读取空调用表。

共享查询函数现先检查调用表容量和指针，再检查变参实参表的容量、指针、切片和固定参数数量。不可读取的描述不提供文本构造效果；完整验证器继续拒绝损坏的表。新增检查只有常数次边界比较，没有新建集合、分配或额外全表扫描。

这项修复已先行单独提交。20 项直接原生检查覆盖有效变参后缀、固定参数排除、空表、缺失来源、容量、越界切片和整数溢出。同一夹具链接未修复原实现时以 Windows 访问异常退出，修复后通过；原始异常调用栈与产物保留。
