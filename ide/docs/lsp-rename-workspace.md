# 重命名的全工作区引用收集

`xideProjectReferencesSubmitRenameWorkspace` 在已有工程引用 actor 上遍历不可变范围快照中的全部工程和独立文件，复用原语义 worker、成员覆盖和缓存。没有新增线程池，也没有向同一个 actor 递归提交任务；子范围在该后台线程直接执行，成员检查仍使用原有的有界 worker。无相关引用的工程也必须检查完成。

各范围返回已排序的原生位置、独立拥有的来源证明和输入守卫，不先生成各自的 Location JSON。工作区按原生路径键和区间合并，先核算唯一行与预算，再转移路径和键的所有权。重复行在保留的数据中即被去掉，而不是只在最终序列化时隐藏。每个文件共用一份兼容证明，最终只序列化一次合并后的结果。

证明比较沿用 XRT 的 DOM 相等接口，保留来源报告中的所有字段，包括以后新增的字段。仅允许已由同一个原生路径键证明等价的路径拼写不同；文档路径和磁盘 input 路径之外的来源、版本、摘要、长度、元数据等都必须相同。输入是原生捕获器生成并校验过的行，不接受任意外部 Location JSON 注入这个比较边界。

每个范围仍在其自身返回前校验输入。完成最后一个范围后，工作区再次验证全部贡献的输入守卫；无引用工程的守卫也保留。较早完成的工程随后发生变化、同字节文件被替换、来源证明不一致、未覆盖成员错误、配额或基础设施失败以及取消，都不能发布部分成功。

新增统计给出配置范围总数、完成数、消除的重复行数和保留守卫的已知收费。原始累计 worker 统计保留最后一次快照，不能把多个累计值相加当成独立工作。范围的数量和顺序必须与同一配置快照一起使用，主机仍需核验当前输入、配置和发布 epoch。

合并行、路径、原生键和序列化证明收费上限为 32 MiB；保留的序列化守卫、上下文和指针容量收费上限为 128 MiB；最终 wire 仍有 7 MiB 上限。合并期间旧行、新行和当前子范围同时存活，子范围的活动模型、DOM 内部、分配器元数据、原缓存、输入、目标和范围快照另计。没有据此声称进程内存上限、无分配或最终性能准入。

原生专项使用真实编译器和四个配置范围，覆盖共享声明、路径大小写别名、未打开成员、没有引用的工程及其成员错误、空结果工程排在第一位、前序无引用工程的晚期修改、同字节磁盘身份替换、最终发布前修改、确定性阶段取消和排队后的独立生命周期。故意省略最终守卫、无引用工程守卫、原生行去重或完整来源比较的四个实际 C 变体均被拒绝。初次测试把 XRT 等待成功枚举当作布尔值而失败的源码与日志保留，随后按 `XWAIT_OK` 修正。

这仍是准确声明的全工作区引用收集，不是完整重命名。物理别名和可写性、完整库/外部符号策略、继承/重载族、精确标识符编辑、冲突及改名后的绑定证明、版本化 WorkspaceEdit 和 IDE 原子应用仍需实现，尚未注册 `renameProvider`。新的正式性能、规模和内存验收也仍待完成。材料入口为 `dev/release-materials/provenance/lsp-rename-workspace-20261110.json`。

最终通过 168 个原生夹具、10 套协议和 27 个 IDE 夹具，工作区专项 138 项检查。资格检查绑定 276 个实际消费者、169 个程序及 core 的全部成员；配套 GUI 完整重编译 116 个对象，使用同一候选服务及匹配 SDK，C/xlang 输入、删除、撤销、Unicode/IME、焦点和语言功能通过，浅色与深色帧已复核。正常发布程序未替换，未推送线上更新。
