# 编辑器状态栏行列与空闲刷新

状态栏显示当前语言、UTF-8／BOM、换行方式和“行:列”。行列从 1 开始，列使用编辑器原生 Unicode 字素簇规则：组合字符和 emoji 序列占一列，Tab 在这里占一列；显示结果与 Ctrl+G 定位一致。

本轮优化发生在应用层。此前每次刷新都会遍历当前行到光标前的文本，即使光标与正文没有变化。现在活动文档对象、原生模型、文档 ID、内容版本、光标字节偏移一致时复用行列，只保存固定大小状态，不复制正文或增加字符数组。内容修改、光标移动、切换文档或关闭后槽复用会重新计算；初始化、无文档和查询失败使缓存失效，失败结果不保存。

语言、BOM、换行方式与脏状态仍逐次刷新。手动语法切换可以保持相同正文版本与光标位置，因此这些元数据没有一起缓存。

## 验证

新增到既有 editor_view_test 的真实模型用例检查中文、组合字符、家庭 emoji、Tab、CRLF、空行、同一字节偏移的正文修改、C/xlang 手动切换、撤销／重做、文档标签切换、关闭后槽复用和无活动文档。严格 Release 重编译实际构建脚本中的全部 83 个模块，生成 105 个运行文件；12 项邻近检查、标准全量回归与新包五个专项门实际退出 0。

诊断夹具编译旧／新完整 editor_view 模块，链接到相同的其他 82 个当前应用对象和固定 SDK。适配层统计真实模型的行列查询，并注入一次失败，验证下一次刷新重试；没有改写模型字素簇规则。32 次空闲刷新从 32 次查询降为 0；约 64 KiB（65,534 字节）Unicode 单行的 24 次刷新，本机一次记录约 60.126 ms 与 0.011 ms。计时包含状态栏轮询，不包含绘制，运行次序固定、没有统计采样，不能据此宣告 16 MiB 长行或整体编辑器性能已验收。

诊断首轮对象通配选取误带独立语言服务器入口、漏掉原生路径适配，链接失败；修正为构建脚本实际清单后重新执行通过。原日志与清单保留。原生窗口截图检查行列与 Ctrl+G 一致，左右 Dock 和中央底栏保持定版布局。
