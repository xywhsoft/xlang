## 注册与结果

固定 32／512 个辅助函数、单文件／导入、字面量／声明修改八种组合；每次进程链包含 14 个版本和一次精确重复。完整 A 链退出后才运行 B 链，每对反转先后次序，不让另一个存活服务的后台工作只干扰一侧。工具、输入、程序及默认运行时身份在测量前后核对；开始要求 5 GiB、运行中要求 3 GiB 可用物理内存与提交额度。没有修改既有 64 项门槛，没有重跑取优或删除慢样本。

| 组别 | 测量数／进程数 | 门槛结果 |
| --- | ---: | --- |
| 上一阶段、发布版功能预检合计 | 320／64 | 返回结果一致 |
| 同一候选 A/A | 960／64 | 9／64 未通过 |
| 上一阶段与候选 A/B | 1,920／128 | 6／64 未通过 |
| 发布版与候选累计 A/B | 1,920／128 | 3／64 未通过 |

共 5,120 次实际 `xlang/check` 请求、384 个进程完整结束，返回结果对照和退出清理通过。累计对照未通过的是 32 函数单文件字面量冷 P50、热 P95，以及导入字面量冷 P50；上一阶段对照的全部六项失败和 A/A 的九项失败均保留在材料中。A/A 本身未通过，不能把两次不同负载状态下的分布差异归因于实现，也不能据此标记整体性能准入。

## 分段诊断

诊断构建复用上一阶段已通过的 304 个原生消费者、189 项产物和 188 个原生 fixture 的实际配方／依赖闭包，不声称本轮重新执行了这些 fixture。静态库逐成员提取并比对真实对象，宿主选择实际参与链接的对象；只替换十个生命周期插桩单元，使用同一核心与前端。重新检查原始输入、实际生成件、对象及链接身份。诊断程序仍在根 `release/win_x64` 以临时别名运行，未加载执行编译器。

普通候选与诊断候选在八种组合中各运行五次顺序检查：cold、first、hot、hot、exact，共 80 次／16 个进程。标准返回值和主要原生工作计数逐项一致。诊断明确关闭后台工作空间索引，以分离检查工作；TLS 时间包含嵌套调用和销毁，不能把父子时间相加，也不能用这些数值作正式速度承诺。
