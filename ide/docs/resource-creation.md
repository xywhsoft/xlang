# 新建 Windows 资源配置

选择可用项目，在项目菜单或右侧下方项目属性中打开“新建 Windows 资源配置…”。没有资源引用的项目也能创建。项目清单须已保存到普通文件；未应用的属性草稿、其他模态窗口和未保存的项目清单正文会阻止创建。

资源表单在第一次打开时创建控件，默认工作台启动不初始化这些控件。首次打开使用当前界面字体、字号和控件度量；后续字体切换继续绑定该窗格。

## 创建流程

1. 选择 JSON 或兼容 XLON。默认路径 `app.res.json` 相对于所选项目清单；也可填写绝对路径。切换格式会调整已有 `.json` / `.xlon` 后缀，保留其他字段。
2. 填写版本、图标与应用清单。版本默认 `1.0.0.0`，产品名取项目名，资源语言为 1033，代码页为 1200。素材的相对路径以新配置文件所在目录为基准。
3. 点击“检查素材并预览”。窗口单栏展示即将写入的完整正文，不创建文件或引用。字段、文件名、目标不存在、已保存清单、父目录和素材读取都要通过检查。
4. 点击“创建并加入项目”。配置按 UTF-8、无 BOM 保存；生成的实际字节与当前字段序列化结果一致，目标不会覆盖。项目新增 `resource-config` 文件引用并标记为未保存。
5. 保存项目清单后参与构建；也可正常执行构建前保存。现有 C/xlang 编辑器、未保存正文、撤销记录、选区和独立启动项目保持。需要继续编辑资源时打开“Windows 资源属性…”，沿用一次正文撤销及 Ctrl+S 保存流程。

取消和关闭前的预览不写入文件。默认名称已存在时请改用新名称；已有文件应使用引用表单加入项目。创建不会合并或覆盖旧文件，不会自动创建父目录。路径已有打开文档或项目引用时，请先处理原文档/引用或选择其他路径。扩展名须与所选格式一致。

## 提交与状态保护

打开窗口冻结完整项目导出、清单身份与 SHA-256，以及全部打开文档的版本/状态。确认前再次核对。模型、属性、选择、打开文档或磁盘清单已变化时拒绝提交，表单字段保留；取消后重新打开可重新取基线。

`services/resource_creation.c` 提供只读创建计划。准备阶段验证配置和素材，复制精确正文并预先生成文件引用、C 源列表和资源列表。现有文件 ID、引用扩展字段、库引用、入口与配置保持。提交时复核模型、项目清单和父目录身份，锁定普通目录的每个祖先及清单，拒绝目录连接点/符号链接，随后以 `CREATE_NEW` 创建同目录暂存文件、写入并刷新，使用不替换目标的句柄改名发布。目标在最后一步被其他程序创建时同样失败；只清理本次拥有的暂存句柄。发布成功后直接转移预分配引用，不再执行可失败的模型分配。

项目清单保存和资源文件创建是两个正常工作步骤。创建成功后关闭窗口，工作空间树刷新并恢复原阅读状态；若树刷新失败，状态明确告知文件及引用已经创建。未保存项目就退出可能留下未被持久清单引用的新配置，仍可通过引用表单重新加入。没有实现文件发布瞬间进程崩溃的自动事务重放。

文件名在 Win32 规范化前检查，拒绝设备名称、非法字符、首尾空格及尾部句点，防止路径规范化静默改变名称。配置和素材限制 16 MiB。图标校验与清单 XML 的边界沿用 [资源属性](windows-resources.md)；实际编译验证最终资源语义。

新建配置以同一资源字段编辑层生成并重新核对字段投影。默认字段都可以由 JSON 表示，因此选择 XLON 时生成的 `.xlon` 也可由 JSON 解析器读取。现有现代 XLON 配置的资源属性编辑会保留扩展值原文，支持 char/time/float/intmap/set/bytes，见 [资源属性](windows-resources.md)；创建窗口不提供任意扩展类型的表单控件。

## 原生验收

`resource_creation_test` 在隔离 Windows 桌面操作实际项目菜单、属性按钮、格式选择、预览和创建，覆盖零资源项目、取消、不写入预览、中文与 emoji 路径、精确输出字节、无效字段/素材/保留名称、目标竞争、模型/清单/父目录替换与共享锁、真实祖先目录连接点拒绝、已有 C/xlang 脏文档/撤销/选区、独立启动项目以及 125% DPI、40 DIP 窄窗口两向滚动。两种新配置分别进行真实混编运行，读取 PE 版本 `9.8.7.6`、图标和原字节应用清单。

当前完整回归与候选证据见 [实施进度](progress.md)。
