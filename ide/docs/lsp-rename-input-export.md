# 改名候选的完整原生输入证明导出

M7b5t，2026-11-13。`xideProjectReferencesRenameResult` 在 worker 上将已有的完整原生候选计划与全部贡献的输入守卫编码为一个独立结果。它没有新增分析、重新收集引用或改写文件，也没有启用标准重命名入口。

schema1 结果具有 `workspaceEdit`、`inputGuards` 和 `scopeCount`。每个输入守卫包含完整显式分析 context、实际源码 files 和整个 resolution 报告，包括不存在的导入候选。上下文编码复用 `analysis_context_wire`；源码与解析报告深复制完整 DOM，保留未来增加的字段。没有目标引用的工程也必须保留守卫，不能从编辑文件列表反推完整输入集合。

`xideLanguageInputGuardExport` 只接受当前、带显式 context 的原生守卫。它在深复制前先核算借用报告的编码收费，再核算完整包装。它不访问文件系统或源码正文；导出结果的独立所有权不代表输入仍然新鲜。普通诊断、引用和补全路径不主动调用这个导出接口。

完整候选接口仅接受成功完成所有配置范围、具有计划和完整守卫的查询。它把各守卫编码进同一个结果，在完整结果编码后，再逐个调用原有输入验证器；取消、大小、分配或输入变化都返回失败，不能返回成功前缀。最终验证复用上一阶段的流式磁盘摘要读取。逐个观察不是文件锁，也不是跨文件的原子快照。

单个证明及完整结果的默认、最大编码上限均为 7 MiB；完整结果不是每个守卫各享 7 MiB。最终 JSON 包装、数组及键名也计入上限。工作区计划本身、DOM、context 编码、JSON 编码器、分配器和并存的查询/临时结果成本额外，不据此声称进程内存或延迟上界。JSON 回调和守卫边界检查取消，底层完整深复制等操作不能中途抢占。

调用方必须在 worker 上执行导出，并在调用期间保留查询，排除同一查询的 Take/Destroy。结果独立拥有所有嵌套元数据，在原查询、输入、scope、actor 和工具链缓存销毁后仍可读取。调用方可以修改返回 DOM，不会修改原守卫。

## 验证

真实四范围候选覆盖一个打开文档、磁盘成员、共享来源和没有目标的工程。专项检查完整 context 往返、所有守卫、缺失导入候选、每个文件报告，以及单证明和总结果的精确最小成功长度；少一个字节必须拒绝。返回 DOM 的深层修改不影响后续导出。

专项通过 656 项检查，包含原候选准备断言。覆盖六个确定性取消位置及取消后的重新导出；19 个实际顶层深复制调用和 248 个接管所有权的对象插入调用逐点故障拒绝。包装器只在本测试线程的导出期间触发；接管插入失败时按 XRT 契约释放传入值。这些探针证明所列调用边界，不能解释为已覆盖分配器内部的全部 OOM 路径或泄漏测量。

编码期间对无目标工程执行相同字节的物理文件替换，最终输入复核拒绝整个结果。四个实际实现变体分别漏掉守卫、跳过最终复核、跳过总结果编码上限、导出错误解析报告；都必须被断言拒绝。已有 130 文件完整原生候选复核通过 418 项检查，输入守卫和来源报告回归继续通过。

本轮重新编译 109 个原生单元，包括原生 core、host 及原有两个辅助夹具对象，沿用已验收的编译器资产及修正，不混用新公共头文件与旧消费者对象。另完整编译 128 个 GUI 单元，并以同一候选语言服务和匹配 SDK 验证协议及 GUI。最终结果、精确输入、实际 include 闭包、对象、程序和失败尝试存放在外部材料包；入口为 `dev/release-materials/provenance/lsp-rename-input-export-20261113.json`。

首次专项因误用 XRT JSON 字符串化接口的参数数量而编译失败；按实际声明改为三个参数，保留失败原件。最终专项夹具在原生及 GUI 源码冻结后增加故障注入，单独保存并绑定实际编译的精确夹具与依赖；生产源码保持同一组字节。

归档核对曾使用 `ar.exe p` 的标准输出比较二进制成员；Windows 的文本输出换行转换造成误差。已保留失败验证器及字节数/摘要证据，最终直接读取 archive 的成员头及原始载荷（含 GNU 长名称表），与新对象逐字节摘要核对，不对二进制做换行归一化。
