# IDE 可用的原生输入证明严格导入

M7b5u，2026-11-13。`xideLanguageInputGuardImport` 在 worker 上导入上一阶段的单个 schema1 原生输入证明，复用已有输入守卫、XRT context/DOM、路径规则、SHA-256 和严格磁盘读者。它可在独立 XRT 与 GUI DLL 两种运行时中使用，不另建文件系统或摘要实现。

调用方必须另行建立准确的预期提供者 context，不能从同一份待验证响应中读取 context 后直接当作预期值。导入器检查完整 context 字节相等，接受至多 64 个独立持有的请求时正文覆盖；这些参数和响应 DOM 在调用期间保持稳定。它不访问 GUI 模型或获得写权限。

导入器先检查 7 MiB 编码上限，再深复制报告和 context。来源至多 512 个，单文件至多 8 MiB，post-BOM 总量至多 64 MiB；覆盖正文另有 32 MiB 上限。它验证绝对规范路径、来源类型、角色、尺寸、完整摘要和入口覆盖；预先准备并排序路径键，拒绝重复后再读源码。源码/上下文路径沿用 context 的 262144 UTF-8 字节边界，由现有路径库处理平台字符与键限制；解析候选仍遵守既有报告的单路径及总量限制。

覆盖证明必须匹配请求时的真实正文，保留 BOM/CRLF 约定。已经提供覆盖的路径不得被磁盘证明替代，即使磁盘自身的尺寸、身份和摘要全部正确。磁盘证明复用流式读者，核对实际 raw/post-BOM 摘要、身份、句柄/路径元数据及 UTF-8；解析报告继续核对完整候选集合，包括不存在的普通文件。

共享检查视图现在也能在 GUI 保留显式原生 context。显式包输入由 context 确定，不重新解释成 GUI 进程的环境变量；既有无 context 的旧证明继续使用原有环境检查。GUI 的 context 比较和已知存储收费同时覆盖新导入的证明。共享检查对象布局变化后的原生及 GUI 消费者已重新编译。

返回的守卫独立拥有报告/context，保留来源及解析报告的附加字段，已识别的元数据仍按现有 schema 严格验证。原响应、参数及预期 context 可随后销毁。后续 `Validate` 验证磁盘/解析输入，取消不会毒化守卫，实际失败则永久失效；请求覆盖、配置、连接和当前模型仍须由宿主另外设栅栏。

## 验证

最终独立 XRT 和 GUI DLL 专项各通过 1321 项组合检查，其中包含既有磁盘读者的 757 项。新增覆盖完整配置不匹配、缺失入口、未知来源/摘要/尺寸、重复路径、伪造身份、覆盖被磁盘替代、缺失/重复解析候选、全部实际观测到的导入取消位置，以及取消后继续验证和新建负候选后的永久失效。还验证 7 MiB 精确成功、再多一字节失败及报告附加字段的独立所有权。

长 Unicode 路径对照使用 UTF-8 字节数超过 32767、宽字符数仍在平台范围内的覆盖路径，防止把 Windows 字符限制误用为 UTF-8 字节限制。它只验证数据和路径键，不证明编译器或深层工程清单支持相同路径；既有深层未加前缀工程路径问题仍保留。

真实四范围原生候选执行导出—导入往返，使用原始生产者的各自 context 和独立请求正文，通过 689 项组合检查；原对象、查询和 actor 销毁后仍验证保留的证明。已有 130 文件候选复核通过 418 项；原有输入守卫、来源报告、协议和 GUI 回归也使用最终配套服务重新验证。

九个实际变体分别省略重复检查、覆盖保护、覆盖摘要、磁盘证明、解析报告、入口覆盖、配置绑定、总编码上限，或恢复过短的 UTF-8 路径限制，均被实际断言拒绝。第一批七个有效拒绝的原件保留；该批后续驱动把覆盖 include 放在原目录之后，导致变体未生效，原批次整体保持失败。修正优先级后，只补验剩下两个变体，并以显式回执合并九个有效拒绝，不把驱动错误计入变异测试通过。

本轮先完整重编 109 个原生单元和 GUI。路径边界审查后，原生只更新一个私有实现单元，保持相同的公共头文件和布局并复核所有继承对象；最终 GUI 再完整重编 128 个单元，使用同一最终服务及匹配 SDK。精确源码、实际依赖、对象、程序、原始失败和验收回执位于外部资料包，索引为 `dev/release-materials/provenance/lsp-input-proof-import-20261113.json`。

首次编译保留了缩写语句触发的 `-Werror` 缩进诊断；专项初版分别误用了零 context 额度及独立文件配置字段，按实际 context 契约修正夹具并保存失败原件。原生往返夹具最初的嵌套 main 宏冲突也保留，改用显式测试入口开关。最后实际编译的夹具单独绑定，不能把较早冻结的测试副本当作最终夹具。

## 边界

这是单个证明的严格导入，不是对编译器分析结论、完整工作区范围、传输方法/ID、请求令牌或用户同意的批准。完整消息解码与 scope/catalog 对照、请求绑定、事务宿主、确认/恢复及启动重放、标准 rename/applyEdit 激活、其他同步读者、引擎对齐和最终发行仍待继续。

上述额度是编码和已知正文规则，不是 DOM/分配器/OS 的堆、RSS 或取消延迟上界。导入在 worker 上读取文件并扫描/摘要覆盖正文；深复制及摘要等帮助函数有不可抢占区间。没有本阶段的新导入分配器内部穷尽 OOM、Linux/sanitizer 或全目标性能/资源/长期稳定性结论。正常发行程序和 SDK 保持原状，C LSP 关闭，不包含 DAP 或运行/调试态补全。
