# IDE 多参与者源码屏障

M7b5p，2026-11-12。`services/source_barrier` 将已有的六类暂停接口组合为一个显式的所有者流程，供后续 WorkspaceEdit 宿主使用：文档模型、模板/恢复任务、任务服务、工具链查询、文件监视，以及主语义与补全/签名双连接和它们的本地磁盘读者。

此协调器没有新增调度线程、容器、正文副本或后台轮询，也没有启用标准重命名、`workspace/applyEdit` 或源码写入。其 `ready` 只证明登记的参与者达到约定状态，不能代替完整来源集合、物理别名、请求/项目/配置时效、注释确认及恢复策略。资源表单等其他同步入口仍须由完整宿主管理。

## 调用与所有权

调用方提供一次清零的 `xide_source_barrier` 存储。所有接口由同一个 UI 所有者串行调用。协调器借用 app、context 和参与者，不拥有它们，也不自动结束其生命周期。活动期间不得复制协调器、替换/销毁参与者、重置 Document store，或向其他调用者转交子令牌。调用方必须先完成显式恢复和 Release，再销毁借用的对象。令牌属于同一个协调器存储的初始化生命周期，不回绕。

1. `Begin` 依次取得文档、源码任务、任务服务、工具链、监视器和语言功能的令牌。它不等待、不派发 UI 事件、不取消活动工作。文档准入推进来源代次，旧准备结果不会因随后放弃而重新有效。
2. 非零返回值表示调用方拥有一次操作，包含某个参与者拒绝后的失败前缀。即使 `error` 非零也必须保存令牌并完成 Resume/Release。返回零才表示没有取得任何持有；已成功的前缀不隐式恢复。
3. `State` 汇总准确令牌、参与者身份、实际静止与失效情况。`pending` 标明未静止的参与者，`lost` 标明参与者替换或令牌不再属于该操作。它先检查对象身份，再访问对应参与者。新增的三个 `SourceLeaseCurrent` 查询只检查所有者元数据，不把“令牌仍有效”和“线程已退出”混为一谈。
4. 正常使用需要 `ready`；`quiet` 与 `failed`、`invalidated` 分开。线程退出之后，连接失败、用户编辑或成员变化仍可能使旧输入不可用。用户撤销回原文不会重新授权旧请求。

普通语言功能 Poll 仍需运行，驱动控制消息、线程退役和恢复回执。协调器没有向每次键入加入扫描。任务及工具链状态检查仍可能遍历历史/请求并执行非阻塞内核探测，语言暂停也保留已有的展示撤销、元数据清理及锁竞争成本；不宣称整个 Begin/State 零分配或硬实时上界。

## 显式恢复和重试

只有在源码写入、回滚或明确恢复协调已经完成后，调用方才可执行 `Resume`。如果修改了输入，应先按实际路径通知任务服务失效。也可以在未开始写入时放弃尚未静止的等待；这不会取消、等待或销毁原来的任务。

`Resume` 启动语言功能的异步恢复，其他准入保持关闭。`Release` 返回 0 表示仍在等待监视器暂停确认或语言恢复；返回 -1 表示错误并保留可重试状态；返回 1 只表示本次拥有的准入全部开放，不能把原先失败的操作重新当作有效计划。

释放顺序如下：

- 先完成监视器的新订阅。实际分配失败时，尚未开放的所有参与者继续持有。
- 再共同释放语言连接。若该步失败，记录已经完成的监视器步骤，重试时不重复为它 Resume，也不错误使用旧令牌。
- 最后开放工具链、任务、源码任务及文档准入；这些步骤之间不派发 UI 事件。

部分开放只发生在调用方已声明写入/回滚/恢复完成之后。协调器不把开放过程当作新的原子写入窗口。错误或被替换的参与者不会得到一个替代令牌；破坏借用生命周期需要由宿主处理，不能用超时自动解锁。健康连接恢复时保留原有进程和缓存；失败连接只在显式恢复后重建。

## 实际验证

完整重编译 126 个 GUI 生产单元，沿用已验收的原生服务及完整匹配的 SDK。正常发行程序、SDK 和交付索引保持原状。测试在根 `release/win_x64` 使用精确私有别名，防止候选 GUI 加载旧默认 DLL；结束后移除所有测试入口。

`source_barrier_view_test` 使用实际 XGE/XUI、Document、IOCP 监视器、任务服务、工具链查询、恢复服务和两个原生 LSP 进程。真实工具链、任务和恢复 worker 返回结果后，测试 trampoline 暂缓线程返回，验证三个独立参与者同时 pending，不能提前报告静止。还覆盖逐个参与者拒绝后的全部前缀、外部持有不被窃取、准确/过期/耗尽令牌、提前放弃、实际监视器订阅分配失败、部分恢复重试及单个语义连接退出。

C 与 xlang 编辑器在持有期间执行点击聚焦、输入、删除、撤销和 Unicode/IME；编辑导致原输入失效，撤销不撤回该事实。正常恢复保留两个进程，单个补全连接退出后保留健康主连接。五种实际实现变异必须被断言拒绝，覆盖提前静止、忽略失效、丢失失败前缀令牌、丢失恢复前缀及漏开文档准入。另运行 55 组既有 GUI 回归、模板与工具链专项，以及有界的真实 GUI C/xlang 启动。

首次夹具把捕获点放在提交任务之后；源码确认任务提交会立即启动 worker，故修正为提交前捕获。首次宽回归缺少私有 DLL 导入库，在执行测试前链接失败；补齐经过摘要核对的同一导入库后重新验证。原始失败记录保留，不计入通过数量。
