# 依赖函数体报错时的语义补全

M7b5n，2026-11-12。

此前，导入文件中的 `export func value() as int` 即使签名有效，仅因函数体写了 `return "bad"`，也会使调用文件中的 `dep.val` 补全整体不可用。本阶段让这类可隔离错误保留诊断，同时允许补全有效的声明。签名帮助使用同一个语义前提边界。结果仍明确标记 `checkedCompilation: false`，不表示程序可以编译。

## 边界与实现

复用原生检查器的原始参数、默认值、返回类型和函数体检查，保持检查顺序、诊断列表和检查返回值。没有清除诊断、复制检查规则、执行编译器进程、使用过期候选或退化成词法匹配。

仅在原生当前前端能力组中，满足全部条件的错误才允许从后续光标查询的前提错误中隔离：

- 是另一个源码文件中的模块直接子自由函数，普通、异步或导出函数；不包含类方法、嵌套函数或查询文件自己的函数。
- 原始签名及默认值检查成功；此前没有尚未隔离的前提错误，且光标尚未被访问。
- 函数体实际产生了诊断；没有发出共享声明或修改调用目标，没有改变模块子项、类型注册数量或类型编号分配状态。
- 模块没有可携带赋值或流状态的全局值，检查后没有遗留流事实；仍能证明函数属于当前模块。
- 原生路径身份比较明确返回不同。转换、分配或比较失败都不能证明来源不同。

签名、类型、默认值、导出 ABI、全局初始化、继承、当前文件光标前的错误继续阻止补全。产生错误的函数不会因为这次隔离获得成功的缓存事实。原有输入、路径、来源、UTF-8 坐标、缓存与结果发布验证保持有效；普通静态检查和 IR 检查仍完整拒绝同一错误程序。

上下文仅增加私有诊断计数，调用栈帧和现有声明变更观察器记录边界，不增加公共 AST/协议字段。普通静态检查直接调用原始函数；正常函数的查询路径增加有界标量检查，不增加堆分配、路径转换或 AST 遍历。错误后的来源证明可能沿用 XRT 分配长路径转换缓冲区，也会检查全局符号及模块成员。本阶段没有宣称这些检查为零成本。

`native_completion_errors_overlay.py` 在摘要验证过的原生构建中检查五个明确接点。`build_lsp_core.py` 登记该生成器及实际包含文件；生成的编译器副本属于构建材料，未修改仓库中其他任务维护的引擎源码。

## 验证与交付

原生测试比较常驻会话、独立新分析、相同输入命中及生产会话销毁后的保留结果，并检查普通静态错误诊断。真实 stdio 测试覆盖磁盘依赖、未保存覆盖、声明错误和函数体错误的互换、重复报错、签名帮助及关闭覆盖后的磁盘重新验证。IDE 的实际双进程测试在读者暂停、恢复后同时断言错误诊断和补全列表存在，并继续验证 C/xlang 输入、删除、撤销、IME 和聚焦。

本轮通过 216 项定向原生断言、12 组原生回归、4 个应被拒绝的实现变异、8 个新增协议场景、原有 50 个协议场景、55 组配套 GUI 回归及实际双进程 IDE 的 122 项检查。定向测试同时使用发布优化对象和单独以 O0 编译的原生检查器；GUI 全部 124 个生产单元重新编译。

单次 ABBA 顺序的本机抽样使用 64 个有效导入函数，每进程 5 次新会话和 40 次依赖函数体改动。基线/候选的新会话中位数为 1.869/1.706 ms，依赖改动中位数为 1.151/1.129 ms，P95 为 1.718/1.477 ms。此工作负载未观察到回退；样本不构成稳定提速结论或全量性能验收，也不代表包含 UI 渲染的响应时间。

构建、验证、负向变异、配套 SDK、默认运行目录与实际源码摘要见 `dev/release-materials/provenance/lsp-completion-error-isolation-20261112.json`。为保护仍使用旧 XGE 的最后可用交付，候选服务和全量重编译的 GUI 使用仓库运行目录中的临时别名及完全匹配的 SDK 验证，验证后移除别名。没有覆盖默认运行程序或发布线上更新。

本阶段是保守的错误隔离子集，不是完整的错误恢复语义。包含模块全局值、共享语义变更、类方法和同文件其他函数体等情况仍可能不可用；声明间依赖切片、更多错误恢复、完整源码事务宿主、标准 rename/applyEdit 激活、长路径编译器限制及长期性能与最终交付验收继续保留为后续任务。
