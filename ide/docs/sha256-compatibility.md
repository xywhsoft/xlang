# SHA-256 与系统兼容

2026-11-02：IDE 的 SHA-256 统一复用匹配 XGE SDK 中的 XRT，由现有 `xge.dll` 提供实现。未加入另一个 XRT 实现或新的依赖库。

命令目录与来源快照、重命名日志正文使用 `xrtSha256`。构建输入、文件重命名基线、原始状态备份、启动文件副本和启动缓存使用 `xrtSha256Init/Update/Final`，保留 64 KiB 分块、文件身份／元数据复核、大小限制、取消、写入与回滚规则。XRT 上下文位于栈中，无须另开系统哈希提供者或分配其对象缓冲。

`catalog_sources.c` 原先直接调用 `BCryptHash`，使整个 EXE 在启动时就要求系统提供该入口。新 GUI 的导入表已无任何 BCrypt 哈希入口，四个 XRT SHA-256 接口从 `xge.dll` 导入。`bcrypt.dll` 仍因启动目录命名使用的 `BCryptGenRandom` 而保留，本次没有改动随机数实现。

`sha256_test` 的 47 项检查使用独立 Python hashlib 生成的固定摘要，覆盖空输入、标准 `abc`、二进制 NUL、55／56／63／64／65 字节填充边界和 65,535／65,536／65,537／131,089 字节文件。内存命令摘要和实际文件快照流式摘要均与固定结果逐字节比较。

另九项现有回归通过：命令目录、状态备份、重命名、迁移存储、启动副本、启动缓存、构建输入校验、编辑器和原生输入。包含损坏／替换数据、取消、实际 OS 失败回滚以及 C／xlang 输入、删除、撤销、焦点和 Unicode IME。根 `release/xlang_ide.exe` 已重新编译并完成隐藏 C／xlang 启动及截图检查；临时测试 EXE 已从 release 清除。引擎、LSP、SDK、用户设置和命令目录数据均保持原字节。

## 本轮构建边界

常规 `build.ps1` 在替换程序前拒绝了现有命令目录：其引擎绑定仍为旧产品，root release 的引擎已由另一个已记录阶段更新。目录生成器还要求当前开发源码与旧发行源码一致，当前源码已继续演进。该检查没有被修改，也没有将它记为通过。

本轮仅用匹配 SDK、现有 GUI 编译配置和固定的全部 GUI 源码／头文件独立重建 101 个编译单元，保持原目录资料。实际构建输入在前后核对，替换 GUI 前通过十项定向测试，再完成 root release 的启动验证。本次为 GUI 兼容性修复，不构成完整命令目录／引擎／发行验收；旧 Windows 目标机器尚未实测，不能据单个入口移除推断所有系统 API 均兼容。

首次界面回归因构建目录缺少字体资源失败；转到正常 root release 后，又发现缺少重命名测试要求的 `task_test.exe` 辅助程序。提供同批编译的辅助程序后测试通过，之前失败及其原报告保留。
