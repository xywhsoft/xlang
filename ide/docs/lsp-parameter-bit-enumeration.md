# 原生参数掩码的有效位枚举

当前前端的外部参数验证会访问完整节点表，并对每个节点扫描全部 64 个参数位。未使用外部参数的节点也会执行该循环。细分原生验证器的诊断采样将这部分定位到 `xl6IrVerifyForeignParameters`；512 函数单文件用例中，该辅助函数的热 P50 约为 2 ms。诊断计时用于定位工作，带有观测开销，正式性能仍单独测量。

本阶段保留完整节点扫描和原有逐行验证，按升序遍历 `physicalPairs | retainedCallbacks` 的置位项。掩码为空时不进入参数循环；同一位在两个集合中同时出现时仍只访问一次。沿用原始 IR 解码器已有的非零位扫描辅助函数及其 C 回退，调用前保证掩码非零。

所有行校验、重复检测、缺失记录检查、顺序及诊断文本保持。没有新增内存分配、缓存、TLS 域、持久状态或运行库依赖。完整原生验证器照常执行。

## 来源与构建边界

适配器只准入已审核的当前 IR 源／头文件组合及完整 457 项前端依赖契约，并核对被包含的原生参数验证文件的实际摘要。复用既有依赖契约验证。未知依赖组合继续原枚举，已匹配版本中异常的包含文件拒绝生成。

编译器原文件保持。私有 IR 单元包含原文件时仅重命名原验证函数，随后生成改过循环的函数；原函数正文保留为独立 C 对照。普通发行图像不使用这个只供对照的静态函数，链接器可以移除它。

旧版本的源文件、正常构建回执与二进制保持原样。修改构建控制器之前，复制并逐项验证旧构建的全部仓库内输入；派生回执明确记录原路径、原摘要及冻结路径。比较仍使用原来的旧程序，不把后来修改的控制器冒充旧程序的构建输入。

## 正确性验证

新增原生夹具将优化函数与实际原函数比较，覆盖全部 64 个参数位、低位与最高位、稀疏和满掩码、Span、retained callback、两个集合重叠、越界容量、缺失与重复记录。核对接受／拒绝、完整诊断及实际访问顺序。计数钩子观察有效位的函数体执行次数，正式图像中的钩子为空操作。

额外 C 检查覆盖 retained-only 掩码在每一位缺失记录的情况，并编译遗漏 retained 集合、截断高 32 位、遗漏记录要求的错误生产者，要求同一夹具拒绝它们。源依赖准入另逐项检查 457 个摘要变化、依赖增减、未知 IR 对和实际包含文件变化。

最终普通构建通过 237 次编译、139 项原生回归和 144 个私有消费者，1,401 项输入／141 项产物一致。新增普通夹具为 682 项检查，附加实际 C 夹具为 938 项；控制与三个错误生产者合计五案例／13 条命令。九组协议和八项当前 IDE 配对检查通过。

完整重建、协议、当前已提交 IDE 的配对检查、诊断采样与正式矩阵以阶段回执 `dev/release-materials/provenance/lsp-verifier-candidates-20261109.json` 为准。IDE 与语言服务执行使用仓库 `release/win_x64`；原生单元检查、对象、私有源与证据位于 `ide/build/Release/lsp-verifier-candidates-20261109/`。

## 更细的诊断工具

`build_lsp_lifecycle_profile.py --ir-verifier-detail` 可以给完整原生验证函数直接调用的辅助函数增加诊断计时。当前图像共 174 个标签，使用独立的诊断程序和 256 单元的线程本地计时槽；常规服务不包含这些计时器。既有嵌套作用域、多线程、取消与错误生产者检查继续适用。

512 函数四类用例中，该参数辅助函数的诊断热 P50 从 1.990～2.003 ms 降至 0.211～0.220 ms。正常／观测图像的完整标准结果匹配。这是单函数的诊断样本，不能代替端到端性能结果。
