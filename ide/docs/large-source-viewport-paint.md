# 可见字形绘制缓存实验

2026-10-10，SDK27 将上一轮完整长行缓存改成最多 4,096 项可见绘制记录，保留原路径逐次浮点累加得到的笔位置。整套 SDK 严格冷构建、605 组成功像素比较、3 项 SDK 测试、6 项相关应用测试和 16 组实际窗口测试通过；8 对窗口截图逐像素一致。大文件编辑仍有明显停顿，本候选不选入当前应用，性能未验收。

上一轮见[长文本绘制复用](large-source-draw-cache.md)。SDK27 相对 SDK23 的 237 个源材料只修改 `src/xge_emoji.c`、`src/xge_text_run.c` 和 `src/xui_proxy_xge.c`。累计补丁仍为 8 个源材料，包含新增字素表，不包含未采用的 SDK19 度量补丁。

## 保留内容与失效条件

Windows IDE profile、启用文本时，原始 XGE 绘制代理保留一项结果，适用于 4,096 字节至 16 MiB 的 `drawTextSpans` 输入。键包含实际物理字体 wrapper、精确自有文本字节、长度、默认内置 Emoji 包及其变更代数、实际像素裁剪矩形和绘制原点。颜色与 paint span 在复用时重新应用，保留字形的原始 cluster 位置，避免旧颜色被缓存。

首次绘制沿用完整整形结果，执行原来的有序笔位置累加和换行重置，同时收集实际可能落入裁剪范围的绘制记录。普通字形采用原绘制路径的墨迹 bounds 和两像素边缘；Emoji 同时考虑 SVG 的可见性及潜在字体回退墨迹。无法确认回退 bounds 时放弃缓存。捕获后的每项笔位置直接按浮点位模式保留，不通过累加被跳过的 advance 重建。

记录数组从 128 项增长，上限 4,096。collector、字形数组、笔位置数组或正文副本分配失败，以及可见重叠记录超过上限时，本次完整原绘制仍执行一次，释放部分缓存。整形失败则返回原错误，下一次可以重试。接受结果时仅移动 backend 的字体／Emoji 引用，随后释放完整临时字形数组。保留记录容量为 `4096 × (sizeof(xge_glyph_position_t) + sizeof(xge_vec2_t))`，另有至多 16 MiB 正文副本、结构体和 backend 引用；这不是整个进程内存上限，字体 atlas、布局簇、文档、临时整形仍另行占用。

原点、裁剪、正文或字体变化先清除旧项，再整形绘制。短文本不挤掉长缓存；长布局／测量前清除，避免旧物理结果与新逻辑整形叠加。匹配字体销毁先释放 backend 引用再释放 wrapper；不匹配字体销毁保持现有项。没有正尺寸裁剪范围、未加载默认包或可变自定义默认包时走原路径。首轮懒加载不会为了缓存资格改变原来的加载与重试过程。

默认 Emoji 的显式设置、清除和懒加载赋值均在原全局锁下递增代数；达到 `UINT64_MAX` 后保持饱和并永久停止此种缓存资格，避免回绕。形状捕获前后身份与代数均相同才可保存，已经覆盖整形中先切到自定义包再切回内置包的情况，也覆盖重复设置同一个包。缓存持有强引用，避免包身份悬空。

SRW 锁只保护私有缓存生命周期。代数检查验证捕获期间的默认状态变化，不表示字体、atlas、渲染设置及整个 SDK 获得了线程安全或所有操作的原子快照保证。本轮没有广泛线程压力测试。非 Windows／非 IDE／禁用文本构建保持对应原路径；本轮严格构建针对 Windows IDE profile。

公开头保持逐字节一致，新增辅助入口没有公开声明或 DLL 导出。SDK21 与 SDK27 实测 5,949 个导出名称和序号一致，此检查不代替完整 ABI 验收。

## 实际失败与修正

SDK25 首次整套严格构建实际退出 1，耗时 69.625 秒：新增的内部 Emoji 绘制可见性参数没有在一个调用处补齐。完整源材料及构建日志保留；SDK27 在新目录只补齐该参数，没有重写失败记录。SDK27 严格冷构建实际退出 0，耗时 135.812 秒，使用 `-O2 -Wall -Wextra -Werror` 与既有三项警告排除。

前两版像素夹具严格编译均退出 0，原生及控制器均退出 1。夹具误把 `xui_rect_t` 的整数成员当成浮点成员：初始化 `12.25` 实际为 `12`，却预期二者产生不同缓存原点。第二版日志确认 `shapeDelta=0`、`cacheX=12`，第三版根据实际初始化后的整数矩形判断复用，不修改 SDK 实现。失败夹具、引擎副本和日志均保留。

第三版原生退出 0，完成 36,434 项断言、605 组成功像素对照、96 组相同错误返回和 216 次不再次整形的长结果复用；缓存路径整形 314 次，实际 widget 用例最大保留 96 项。另有合成的 400 项零 advance 重叠、后续数组增长失败，以及 8,192 项重叠超过上限后的原绘制回退；这些合成检查不计入 605 组成功像素计数或 widget 最大记录数。

独立参考代码保存 SDK21 原 Emoji／字形绘制及 XUI 代理函数；新路径使用 SDK27 实际私有结构和函数。每个夹具只有一个可执行程序 XRT 所有者，不链接 SDK DLL。完整引擎复制后仅在三个可选缓存分配调用点加入诊断分配器；SDK27 源材料本身不含测试钩子。

覆盖六种物理字体大小（8.5、16、20、24、32、39.75）、ASCII／Tab、中文／Emoji／组合字符／ZWJ、CRLF、多种 RTL／Indic 字节、非 BMP、嵌入 NUL 和非法 UTF-8，长度 4,095／4,096／8,192／32,768，颜色、原点、裁剪及 0／3／20 个 span。成功输入比较真实非空像素，错误输入比较返回码和无绘制结果；另逐项核对保留字形字段和笔位置位模式、完整数组释放后的 backend 所有权、字体切换／销毁、各次分配失败、默认包 ABA 切换和代数饱和。等价性不代表新增 RTL 或复杂文字排版能力。

原始 SDK 的 Unicode／Emoji／文档三个测试和现有 IDE 的 `document`、`editor_view`、`goto_view`、`find_view`、`input`、`reading` 六个程序均在独立目录加载实验 DLL，退出 0。当前应用核心对象没有重新编译；本轮不是完整应用回归或正式便携验收。

## 可复现材料

补丁位于[第九版实验包](../third_party/sdk_patches/large-source-experiment-v9/README.md)。[准备入口](../tools/prepare_paint_cache_sdk.py)核对固定输入源、补丁和材料哈希，输出新目录；237 个输出逐项匹配实际 SDK27。已有目标拒绝覆盖且内容不变；受控修改输入代理后退出 1，在创建输出前拒绝。没有再次构建 SDK，也没有安装到当前应用。

[绘制重放入口](../tools/test_paint_cache_sdk.py)要求已完成的私有构建报告及新目标，核对 237 个源材料、构建输出和三份对照材料后，在诊断副本中严格编译完整引擎并运行实际像素对照。Windows 只读字体允许合法多硬链接，但拒绝 reparse 文件；源和补丁维持严格普通文件规则。运行前后都核对输入未变。

```powershell
& 'C:\Program Files\Python312\python.exe' -X utf8 tools/prepare_paint_cache_sdk.py --source-root 'D:\GIT\auto_test_ide\build\sdk-candidates\theme-20260916\xge-source' --output build/my-private-paint-source
& 'C:\Program Files\Python312\python.exe' -X utf8 tools/test_paint_cache_sdk.py --build build/editor-sdk-paint-v27-build.json --output build/my-private-paint-replay
```

落盘重放的严格编译、原生和控制器均实际退出 0，得到相同的 36,434／605／96／216／314／96 六项计数，结果在 `build/editor-paint-durable-v1/result.json`；阶段证据在 `build/editor-paint-evidence-cohort-v1.json` 和 `build/editor-paint-final-v1-witness.json`。本轮保护原有 800 对材料、83 个核心对象、105 个运行输出、3 个已暂存现代编译器输出及已有便携包。前一阶段通过其清单哈希及已成功的见证衔接，不递归重哈希整个历史 build。

仍待处理的是改变正文／原点／裁剪后重新执行完整整形的停顿、干净 Windows 与实体 IME、多显示器 DPI、原始 GPU／Emoji 根回归、完整 SDK 许可和推广流程、C 输入依赖图／ABI、TCC 扩展库，以及没有 8.3 别名时的深目录工作目录支持。正式发布和性能验收状态保持未通过，长期任务继续。
