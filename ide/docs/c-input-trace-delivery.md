# C 输入观察的默认便携交付

此阶段沿用 SDK67 和定版布局，把已经完成独立源码构建的输入观察提供者加入默认便携工具链。编辑器仍同时支持 C 和 xlang，普通 clangd 也可通过“偏好 → C 语言服务器”或 `--c-server` 选择。

## 行为

默认后端协商 `capabilities.experimental.xlangInputTrace=1`。真实 clangd 的物理 VFS 读取、失败探测、目录枚举以及响应文件展开会进入观察。IDE 在发布语义结果前和会话运行期间复核输入；发生变化时撤回诊断、悬停、大纲、补全和旧定义目标，再重新分析。未打开、未列入工程但已经观察到的实际头文件可用于守护后的 F12 导航，来源项目上下文由既有导航规则维护。

目录枚举改用统一的 Windows 原生路径转换，支持中文、emoji 和超过传统 MAX_PATH 的实际目录。新原生夹具检查短路径与 422 个 UTF-16 字符的深目录：子文件添加、移除、空目录变化及子目录创建使旧枚举失效；仅改变未读取文件的正文不会被误报成候选列表变化。此前版本在真实深目录上拒绝观察的失败材料保留。

`complete` 只表示当前待发观察通知已经发完，不能据此宣称整个项目、所有后台未来操作或 TCC 输入图完整。未保存文档仍使用 IDE 不可变快照。本阶段不把 Clang 的观察范围等同于 TCC 预处理或所有扩展库的 ABI；`cPreprocessorGraphComplete` 和 `abiEquivalenceGuaranteed` 继续为 false。协议容量、顺序和状态规则见 [C 语言服务](c-language-service.md)。

## 来源与材料

后端上游固定为 `ea7d852a70e8bdfaf601d6626a760f9771b2c4b4`，运行文件 354 个，实际服务器 SHA-256 为 `4e1601afb4a56e87bdbc812f6964fbd47dceb232b96ea8afc8da20e9d3e107bc`。本阶段复用此前真实退出码为 0 的源码构建，核验实际文件和记录后冻结；没有把复用记录称为本轮重新编译。

便携包保留 6 份修改源码、5 份新增源码及对应差异、重建说明，位于 `sources/clangd-adaptation/`。`provenance/clangd-adaptation/` 包含实际构建命令、日志、退出码、编译器记录及二进制绑定；`notices/clangd/` 包含 LLVM、MinGW 和 GCC 运行库文本。包内是准确的适配差异和既有构建材料，完整 LLVM 上游源码需按固定提交获取。

打包前统一核验命名空间、普通文件类型、字节长度、摘要、上游提交和二进制绑定。源码或记录缺失、被改动、错误后端、路径越界及重复目标在复制前被拒绝。材料存在与通过开发验收不代表正式发行核对已经完成。

## 本阶段核验

默认便携 C 后端已加入实际输入观察，未打开的间接头文件变化会撤回旧语义结果并重新分析；目录守卫支持超过 MAX_PATH 的 Unicode 深目录。SDK67 沿用已严格构建的匹配材料，应用重新严格构建为 84 模块／104 产物，含渲染的完整回归及六项实际便携门通过。真实输入观察 113 项接口、21 项界面及 52 项导航上下文检查，69 项短／长目录观察检查和 13 项材料拒绝检查通过；普通 clangd 的五项兼容门和修正后草稿启动门也通过。当前候选和最终状态以 [候选入口](../CURRENT-CANDIDATE.md) 与 `build/c-trace-delivery-final-v1.json` 为准。

干净 Windows、实体输入法与混合 DPI、复杂 C 输入及扩展库的系统验收和正式发行材料核对继续进行。
