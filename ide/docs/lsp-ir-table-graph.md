# 最终 IR 表记录的独立所有权

M7b6x，2026-11-16。补齐节点图之外的原生表数据所有权：从选中编译器头文件生成 107 张表的记录处理代码，每条结构记录独立拥有其文本、二进制和向量载荷。稠密标量表按向量保存，避免为每个整数分配对象。当前仍是最终 IR 局部生产的基础组件，没有在普通分析之后追加全量捕获，也未替换默认 0.106。

## 数据与引用

`ir_table_graph` 直接使用实际原生 C 类型。完整复制记录字节及全部标量／数组值，显式处理 25 类记录的 70 个指针字段；不维护另一份 XLIR 结构声明。生成器支持选定头文件中的命名值记录、简单类型别名和定长值数组，实际大小／对齐由 C 编译器决定。未知指针、回调、指针数组、隐藏值记录指针或不匹配的向量计数明确拒绝；213 个实际值类型的 C11 断言补充验证数值别名。固定前端源契约仍是构建准入条件，这不是任意 C 语法分析器。

每个不可变单元使用一块 XRT 分配，并持有独立的来源标记。保留一条记录不保留父图、相邻记录、AST、原模块或上一代结果链。单元之间的原生整数 ID 不变，来源标记仅证明捕获出处；它不证明当前输入、依赖版本或跨模块 ID 兼容。类型、符号、区域及表索引的重定位仍须下一阶段建立。

原生持久化验证会比较键的指针身份。投影字段、恢复字段和恢复 claims 三类键在捕获时按原始指针确定其类字段选择器，物化后重新指向对应类字段的名称／JSON 键／XLON 键。独立单元自身仍保存完整键文本，保持单元独立生命周期；只有完整表视图恢复跨记录借用关系，不按相同名称猜测身份。

显式平面适配器拥有全部表数组并保留图，其载荷借用图中独立单元。节点／子数组由调用者另外持有，数量必须与捕获命名空间一致；只通过数量检查不代表已经证明语义匹配。视图只读，不能交给原生模块析构器。增长容量规范为实际活动记录数；类型哈希槽和稠密符号绑定容量同时是逻辑数据范围，完整保留。

## 资源与构建

调用者在捕获期间保持已验证模块不可变。所有新内存使用 XRT；申请前检查乘法、对齐和加法，零预算拒绝，失败不发布部分图。预算覆盖申请的图／单元字节，不包含原输入、分配器开销或 RSS；固定表计数和偏移栈数组也不作为服务全局预算。取消在入口和记录循环周期轮询，单次字符串扫描／向量复制不提供字节级抢占。

标准构建通过实际 GCC 依赖选择原生头，生成实现及测试辅助代码，纳入全部输入散列。完整重编 363 个目标文件：构建器登记 362 个，另有一个原语义索引边界夹具；静态库 74 成员、225 输出／224 PE。原有 586 个生产源码和公共头逐字节不变，新的拥有表组件未被普通服务链接。原生 lowerer 只在专项测试工具中编译，静态库和普通服务均不包含它。

完整构建冻结后，新增了一份仅测试用的 JSON／XLON lowering 夹具。最终夹具分别按普通模式及额外 lowering 模式重新编译、链接和执行，使用同一组未变公共头及静态库，不将旧夹具伪装为新源码的验收。

## 验证

- 普通夹具通过 1,734 项检查：全部表的原生记录／指针载荷对照、非空零长度向量、内嵌 NUL 二进制、空字符串、跨表键别名、四读线程、32 代保留、单元独立退休、预算和取消。
- 原分配追踪逐一覆盖 109 个真实分配失败点及小夹具三个取消点。单独保留一条记录时只剩单元及来源标记两块申请；不把申请字节等同于进程内存。
- 134 次实际 typed IR 图克隆分别经过完整原生验证器及完整 IR JSON 比较；另有八个编辑模型在原结果和 AST 退休后再次验证。
- 额外原生 lowering 夹具通过 1,744 项检查，实际生成动态对象的投影、恢复和 claims 表。在释放原始全部非节点表和 AST 后，克隆仍通过完整原生验证器和完整 JSON 对照；调用者按约定单独持有节点数组。
- 16 组实际头文件模式检查通过。四种实际 C 变体分别清空文本、清空向量、遗漏来源标记释放、跳过键别名恢复，均被拒绝。最后一项另用原生 lowering 专用驱动，在正常对照通过后，由完整原生验证器拒绝，无需依赖合成键的指针断言。
- 八个相关原生程序通过。没有将上一阶段的全量原生、协议、GUI 或性能结果重新计作本次运行。已安装程序、匹配 SDK、交付索引及全部 7,094 个运行文件保持原值。

保留首次测试包装函数的严格编译告警，以及持久化夹具的两个错误假设：typed 阶段没有 lowering 键表；恢复 claims 只为动态对象生成。改用真实原生 lowering 和动态对象后，保持三类非空表及完整原验证器要求。原失败源码、程序、日志和材料路径均保留，未修改编译器规则。

专项工具 `check_ir_table_graph_lowered.py` 接受完整构建报告、外部输出目录和真实根发布目录，核对源码／头文件／静态库身份后运行普通及 lowering 两个控制程序。损坏的私有静态库副本在编译／运行前被拒绝；没有修改实际静态库。
