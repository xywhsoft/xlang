## 实际开销与选择

当前类型注册表的名称查找已经使用原生哈希槽，没有新增名称索引。私有诊断分别复核检查流水线、原生语义／IR 阶段、类型查找调用来源和类型规范字符串格式化；三轮共 32 个进程、128 个请求，与同一工作区的正常 M94 程序比较，标准结果一致。带探针的时间不是正式性能成绩。

512 函数单文件诊断的冷检查有 1,525,536 次外部注册表名称查询，其中 1,142,467 次来自 `xl6SemAliasTargetType`；持续编辑时相应为 34,497 和 32,899 次。此语料没有注册表按 ID 查找或原生值 ABI 分类调用，因此没有实现先前假设的额外查找索引。索引中有 67,602 次规范字符串请求，61,456 次是原子类型，只有三种不同原子输入；采样估算的格式化开销远小于整个分析，未将它选为本阶段主要改动。

## 读取与记录

原生 `AliasTargetType` 检查查询结果是否存在、类型种类，以及别名的声明／首个目标子节点。它不读取 `TypeInfo` 的 ID、ABI 名称、ABI ID、泛型开关和泛型元数。当前正常构建只将这个已固定源码的入口改接到投影观察器；其他 70 处主语义翻译单元查询继续观察完整记录。原生注册表查找、原条件和返回值始终执行。

投影使用独立的内部查询种类 2，值／函数查询为 0，完整类型查询为 1。它精确保存存在性和种类；对于真正的别名，保守保存整个声明 AST，覆盖目标及其类型、来源和语义标注。普通非别名不会序列化没有读取的声明树。记录拥有原有的名称和键缓冲区，不保留可变注册表值指针。

后续若发生同名完整类型读取，先验证此前投影，再原位升级记录。它与此前完整读取记录合并，不为同一名称额外占用一条类型记录，原 256 条上限保持。完整读取和函数结束／跨版本复用时的完整键验证继续执行，不能用一次别名查询证明整个 `TypeInfo` 不变。

已有完整记录即使包含声明树，也额外拥有小型种类投影。这使类等非别名查询能检查当前种类而不反复编码未读取的类声明。声明在后续完整读取或最终验证时变化仍会拒绝复用；别名查询看到种类／声明变化也会拒绝。标识符只定位候选槽位，确切名称和当前实际字段始终参与判断。

额外的捕获位置表为 32 个 `size_t`，三个计数器为 `uint64_t`，均在现有同线程捕获对象内。四个记录字段通过 `sizeof(xls_sem_read)` 纳入原有记录字节记账。记录、键、值和语义缓存的既有上限保持，分配／预算失败只拒绝可选捕获。原有上下文、输入、拓扑、未知读取、声明变更及副作用准入检查继续执行。没有修改语言规则、IR 处理、独立验证器或 LSP 协议。

`typedComparisons` 统计实际执行的类型值比较，包括完整值快照和此处的存在性／种类投影。关闭原有类型值优化，或值存储初始化／分配失败时，投影比较也使用原序列化回退；已有完整类型记录继续包含该查询，不能因此新增重复记录。读取次数仍代表结果的创建来源，精确命中不增加工作计数。

## 正确性证据

`analysis_semantic_alias_reads_test` 包含本轮实际新生成的原生语义翻译单元，467 项检查通过。覆盖真实入口接线、别名目标、种类和声明变化、无关 ABI 字段、完整记录升级与包含、缺失类型、值／类型命名空间、稀疏 ID 与槽位冲突、256 条上限、嵌套／外来上下文、无值优化回退、实际分配失败和分配回收平衡。类声明测试同时验证：别名查询不消费的瞬时声明变化可由最终完整快照确认；持续声明变化、种类变化仍会拒绝复用。

四个既有实际目标通过：读取定位、类型值、语义证明和语义读取。四种实际源码变体分别遗漏别名声明快照、升级前的原投影证明、类的实时投影检查、关闭类型值优化时的序列化回退，均被正常测试拒绝；编译器依赖输出确认测试确实使用了变更文件。旧正式 0.99 的 IR 和语义对象使用当前 IDE 头文件重新编译，均保持字节一致。

首次全量构建的 217 个对象和 120 个原生目标通过，但协议首轮在语义读取断言失败：新投影比较未计入 `typedComparisons`。修正计数后，原有类型值原生对照进一步发现投影比较没有遵守关闭开关。补齐序列化回退后，467 项新检查、四个既有原生目标和原语义读取整组协议通过，原有断言未修改。两次失败记录保留，当前完整验收重新构建，不能以旧二进制代替修正后的正常程序。

历史诊断脚本中，函数定义误被计时宏包裹、不存在的字符串追加 API，以及误认为生成器使用宏而非直接替换调用的失败已保留。修正后的独立诊断均完成正常程序结果比较。早期未加入类投影的正常候选与 M94 完成 32 进程、160 请求的功能控制比较；小样本延迟并不一致，没有据此认定提速。
