# 名称输入记录、结果恢复与性能边界

名称阶段的实验组件现在将节点／类型依赖去重，原生生产结束后再保存稳定输入，并在命中校验遍历中恢复三个结果。无类布局时直接执行原生阶段，不创建缓存元数据。完整正确性检查通过，但两个构造性能筛查仍未通过；普通服务、IDE 和已交付的 0.110 保持不变。

## 输入证明与有界记录

十个原生／字段绑定函数的审核正文保持不变。生成器按真正的节点指针别名提取 11 项输入字段，排除之前由类布局记录别名引入的多余 `type`；它仍检查这组输入与三个输出分离。

名称入口只记录六项标量和文本是否非空。进入原始分类器的祖先、完整拼写和类字段处理之前，明确升级到完整节点投影，保留完整文本依赖。非名称入口只记录节点种类。没有根据新的完整 IR 输出来推测命中资格。

每个节点／有效类型用有界的代次与记录位置索引，同一区间只保留一项依赖。辅助读取可以原位升级入口记录，实际查询的类型去重；无效类型查询仍记录存在性。只有所有所属节点都被覆盖才捕获该区间。

生产函数只写三个结果，不写这组输入、公共类布局或类型池。因此记录过程中仅保存编号，生产结束后才序列化输入值。这个顺序依赖明确的读写分离，不能直接套用于会读取先前输出的其他阶段。

暂存根据节点／类型规模申请，保留原来的调用方上限，最大 16 MiB。超长输入键可以拒绝捕获，原生结果仍完整；保留缓存、暂存、分配器开销和进程内存的范围继续分别描述。无类布局时的原生路径不申请可选缓存元数据，专门检查其分配／API 调用数与原生构造一致。

## 合并遍历的失败边界

校验读取所属节点时恢复其三个标量结果，减少单独的整段恢复遍历。某个较后输入失配时，当前模块可能已经写入旧值；未命中路径必须对整个区间的每个节点重写三个结果。它们不参与输入计算，所以不影响正确的原生重产。

新增对抗检查选取真实字段引用，改变拼写并先填入非法输出哨兵，确认失配前确实发生了恢复；随后由实际未命中路径覆盖，与独立原生阶段逐节点比较三个输出。旧缓存仍能供下一次完整构造使用。取消和后续分配失败仍不得发布部分模块或缓存。

## 正确性与范围

最终冻结构建通过四个新编译的组件程序：名称夹具 8,526 项普通检查、9,998 项契约检查（包含普通检查），1,837 次退休单元清零及四线程读取。基础 49 个语义输入中有 4 个包含适用类布局并捕获缓存，其他输入走原生路径；不将它们都算作缓存命中语料。另有真正产生非默认 ABI 的 `base.value()`、泛型隐式字段、真实字段切换和源码移动输入。

资源语料扩大到包含类和多次隐式字段读取的代码，避免无类快速路径掩盖元数据分配及中途校验的取消检查。冷／热分别枚举 203／197 个外部 XRT 分配或 API 拒绝点、114／109 个取消点；这些不是分配器内部所有分配的覆盖。

编号稳定的绑定编辑复用 22／23 个区间，重新生产 20／688 个节点；真实字段切换保持复用 20／21 个区间、生产 19／550 个节点。仅改初值或源码坐标可以全部复用，完整原生 JSON 检查更新后的内容。

一次新增用例最初假设切换不同参数形态的调用目标后仍可局部复用。实际诊断显示类型数 18→19、类布局编号 12→13，符号映射未变，当前公共布局证明必须拒绝。这个原输入保留为完整回退的正向检查，同时另测编号稳定的绑定编辑；没有放宽精确编号的约束，类型编号重定位仍未实现。

正向语料曾使用当前后端拒绝的 `base.item`，另一个诊断的裸 `base` 返回也被现有语义检查拒绝。其记录保留，未计入正向覆盖；有效的 `base.value()` 和泛型字段已通过后端及完整组件检查。首个语料诊断工具的 JSON 参数数量错误也保留，不算作产品通过。

默认原有 1,862 个函数正文及两个私有布局保持令牌一致；21 项来源策略、调用缓存原有 6,803／6,924 项检查、相关原生回归、普通不可用入口及实际编译缺陷结果均在材料索引中记录。实验没有默认接入，也没有新做普通协议／GUI 验收或替换发布程序。

一个预期反例省略了显式的完整节点读取，但仍通过所有检查。原生祖先查找本来就从同一名称节点开始读取，仍会升级记录，因此该删改实际无害。保留通过的程序及错误预期，不将它计为被拒绝的缺陷；后续反例改为丢失真正的记录升级，并继续验证重复类型记录和未命中重写。

类输入实际复用 35～36 个区间、重产 0～82 个节点，但这些计数不能代替速度证据。首次路径的局部收益也不构成默认启用依据；这仍不是端到端 LSP／IDE、所有工作负载或跨平台的性能放行。
