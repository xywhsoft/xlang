# 资源素材与构建输入保护

F7 构建及 F5 构建运行现在同时核对 Windows 资源配置所引用的图标和应用清单。无需将素材再次加入项目文件列表。素材相对于各自资源配置所在目录解析，支持中文、空格、emoji、绝对路径和 JSON Unicode 转义。

提交仍先保存已有项目相关文档。目录外已打开、未保存的素材文档会使本次任务失败，保留正文并提示先保存再发起任务；无关的脏 C/xlang 文档不因此保存或丢弃。测试任务继续仅执行显式程序，不新增隐含构建或资源分析。

## 实际依赖

与 DEMO6 `src/resource/xl6_win_resource.c` 的 `xl6LoadBlob` 一致：

- `icon` / `manifest` 为字符串时，该字符串是文件路径。
- 素材对象中 `path` 为字符串时，路径优先于 `base64` 和 `text`。
- `path` 不是字符串时，不作为文件依赖；Base64、直接清单正文和 null 不产生素材文件输入，其实际有效性由编译器决定。

`services/resource_inputs` 从已经捕获的配置字节提取这两个根字段和素材对象的 `path`，使用匹配 SDK 解码 JSON 字符串。其他 XLON 容器、标签和载荷只确定边界，不转换为旧 GUI 值对象。因此 char、time、float、bytes、set、intmap 及未知扩展不会因收集输入而被重写或降为 JSON。源正文和未知字段没有修改；资源整体语法、类型、ICO 和 XML 语义仍由实际编译器验收。这不是完整 XLON 表单编辑器或另一份语言解析器。

投影拒绝不能确定边界的结构、超过 512 层嵌套、重复的相关素材/path 键、无效路径字符串或路径 NUL，失败时不提交部分路径列表。读取配置支持 UTF-8 BOM。路径按规范化拼写去重，同一个素材已有直接项目引用时共用该输入；不同硬链接拼写分别计入字节预算，通知匹配会核对实际文件身份。

## 后台与过期结果

任务工作线程先捕获清单、源码和资源配置，再从捕获的资源正文发现素材路径、读取素材，并核对整个输入批次。资源文件路径加入同一输入集合及原有 16 MiB 单文件、128 MiB 总基线预算。所有读取、路径身份检查和投影在后台进行。

输入数组扩容与 UI 的编辑通知访问共用锁，公共查询返回路径副本。发现依赖之前收到的未匹配编辑通知不会提前丢弃；发现完成后，再核对排队和准备阶段的路径及硬链接别名。UI 在启动工作线程前复制仍脏的命名文档路径，防止目录外素材的既有修改遗漏。编译后和运行前仍比较整个输入集合；素材缺失、超限、内容变化、取消或输出路径与素材相同，均不能发布新产物或运行旧程序。

保留的任务历史可通过 `xideTaskInputCount` / `xideTaskInputPath` 查询本次发现的路径，正文基线在结束时释放。配置和文件没有加入另一套写入事务，图标/清单改名后的正文重构仍需显式编辑。

重复请求只在完整已保存项目快照、配置、任务种类、工具路径和脏文档守护一致时合并。新传入的脏文档路径也通知已有请求；新工程快照或不同守护另行排队，不能被旧请求替代。

这是构建前后字节比较及内存版本保护，不是文件系统隔离快照，不能检测外部写入者在两次检查之间改动后又恢复相同字节的所有情况。源码 import、C 预处理头文件、链接库和驱动输入的完整编译器依赖图仍按后续计划实施；这里的资源闭包不能代表整个项目依赖图完成。

## 验收

`resource_inputs_test` 操作真实文件、事件门控编译进程、任务队列和硬链接，覆盖路径优先级、Unicode/BOM、未知 XLON 边界、失败原列表不变、素材变化后的旧输出保护、内存编辑、发现前排队通知、未保存路径守护、缺失文件、单文件和总预算、输出保护。带 `CompilerPath` 时实际 C/xlang 混编并运行 typed XLON 资源项目，核对 PE 应用清单原字节。

`task_view_test` 通过真实 XUI 编辑器和统一构建/运行动作验证目录外脏清单的拒绝、显式保存后的成功、无关 C 文档保留及所选项目/启动项目独立。完整运行和候选证据见 [实施进度](progress.md)。
