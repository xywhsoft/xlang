# 语义重命名的目标捕获

本阶段提供原生标识符校验和不可变语义目标，供后续 `prepareRename`、跨工程引用闭包及重命名事务复用。标准重命名能力尚未开放；目标捕获本身不能授权编辑。

`analysis/identifier.h` 在严格 UTF-8、非空、无内嵌 NUL、最多 65535 字节的范围内，调用实际编译器词法 DFA 和原关键字判定。构建工具从真实 IDENT action 和匹配循环提取规则、meta 和 jam 常量，在构建目录派生一个 lexer TU，保留原文件全部字节。没有第二份关键字表、扫描器、拷贝、分配或 locale 状态。内建类型的拼写也可能是词法 IDENT；能否改名必须由后续语义策略决定。

`services/semantic_reference_shard.h` 的 `KeyCreateAt` 在原导航绑定决策完成时一并捕获当前出现范围，避免再构建一次导航表。`KeyTarget` 读取 key 独立拥有的声明来源与字节区间。跨 owner 身份仍是路径、完整原始 post-BOM 来源和声明字节区间，不使用编译批次内数字 ID 或按名称搜寻。

`services/semantic_rename.h` 捕获查询路径、精确标识符区间和声明名称，持有原引用 key，不保留 AST、check 或导航缓存。对于 `dep.compute` 一类范围，以原生标识符字节规则细化光标所在部分，并要求它与原绑定声明名称逐字节相同；前缀不能因此成为另一个声明的编辑范围。UTF-16 位置沿用调用者核验过的 BOM 转换约定，字节偏移对应 post-BOM 来源。换行、Unicode 标量内部位置及越界请求不产生目标。

构造在后台进行。默认 16 MiB、上限 64 MiB 的预算只计返回目标、引用 key 和查询路径的已知拥有容量，不含导航的临时构建及分配器元数据。名称扫描由 65535 字节上限约束；其他扫描按已消耗字节轮询取消。原导航构建仍有不可抢占部分，不能据此声称整个查询可随时取消或已经达到最终性能目标。

后续仍需在现有 project reference actor 上完成：可写成员与库文件策略、继承及重载族的闭包、名称冲突和捕获检查、改名后的绑定保持证明、完整来源/配置/epoch 校验，以及版本化 WorkspaceEdit 和 IDE 的原子应用。尚未注册 `renameProvider`，也没有加入 DAP 或调试期补全。

新增测试实际暴露了未实例化泛型类字段的原生事实缺口：该字段没有 declaredSymbol、targetSymbol 或 selectionRange，原导航同样不能绑定。因此目标捕获明确返回无目标，测试保留这组原生事实断言；后续需要补齐该身份资产及相关成员绑定，才能宣称完整的字段重命名。

原生阶段验证了 32678 项标识符断言、631 项目标捕获断言及共 164 个原生夹具；四个实际 C 变体分别删除关键字判断、破坏 IDENT 规则、漏计查询路径预算或偏移 UTF-16 坐标，均被夹具拒绝。四种未知 lexer 结构被构建派生器拒绝。首次错误期待泛型字段可绑定的失败与原生事实定位原件保留，未将该字段算为已经支持。

配对验证重新编译了 116 个 GUI 对象，使用同一候选语言服务及匹配 SDK，9 套协议和 27 个 IDE 夹具全部通过，包括 C/xlang 输入、删除、撤销、Unicode/IME、焦点、引用及语义颜色；浅色和深色原生截图已复核。测试入口位于根 `release/win_x64` 并在结束时移除，默认六个程序/DLL 的摘要保持。实际对象和完整来源依赖绑定记录在 `build/Release/lsp-rename-target-20261110`，可恢复材料索引位于 `dev/release-materials/provenance/lsp-rename-target-20261110.json`。没有运行新的正式性能准入，也没有发布更新或将整体长期目标标为完成。

后续 M7b4b 补齐了上述字段身份缺口，见[字段绑定](lsp-field-bindings.md)。本页关于缺失字段的说明及前一阶段原件保留为历史状态；字段可捕获不代表完整重命名已经开放。
