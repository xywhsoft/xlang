# 工程重命名候选的完整原生复核

后续已加入[外部声明策略](lsp-rename-foreign-policy.md)：保留普通引用查询，对含原生 ABI 或编译包声明的连接族拒绝构造改名候选；其他未完成边界继续保留。

工程 actor 在构造版本化候选计划后，逐个复核原有声明图的实际提供者。每个提供者使用对应输入防护中保留的完整不可变编译配置，包括实际入口、构建目录、包环境和原生选择设置。不能根据当前编辑文件或所选项目重新猜测配置。

受影响的提供者通过 `xlsSemanticCheckCreateFrozenInContext` 重新执行原有解析、导入/标准库扩展、语义、索引和 typed-IR 检查。候选输入来自原有完整源码银行；改名文件替换为计划的 after 字节，其他源码保持原始正文。随后捕获原生引用分片，使用[绑定比较器](lsp-binding-preservation.md)核对完整来源及全部已捕获引用，而非只查改名目标。

新检查入口支持原生来源报告的完整上限：512 个来源、每文件 8 MiB、源码总量 64 MiB。已知输入所有者存储上限 128 MiB，包含正文副本、规范化路径、已准备的原生词法路径键及条目；AST/IR、来源报告、引用分片和分配器等内存额外。它独立于普通输入批次、工作线程历史、原有根与增量 memo。普通分析仍保留 64 个覆盖输入及原有 32 MiB 覆盖正文限制；候选模式不产生可用的 64 位输入掩码或增量拓扑证明。

实现没有改动引擎的 `XL6_SourceOverlay` 布局，也没有另写解析器或导入器。现有受审计的原生来源适配器在原有三态查找和来源报告读取边界查询同一个作用域候选银行，复用现有前端调用栈的 TLS。显式路径导入会先把同一 `.xl` 当作清单探测，再作为源码解析；这两条路径必须看到同一候选正文，并保留原生来源角色的合并。未绑定时继续原有读取；绑定时用事先排序的原生路径键二分定位候选。失败保留原有 `-1` 语义并使来源报告失效，不能变为“未找到”再静默读取磁盘。路径准备与比较复用原有输入拓扑的 XRT/平台身份实现。

候选银行深复制正文并保留到检查退出，来源报告仍由原生加载器生成。普通调用只多一次未绑定分支和空指针字段，不建立候选银行，也不增加该模式的堆分配。候选捕获逐路径及按 64 KiB 正文块检查取消；完整 UTF-8 验证、至多 512 条路径排序及原生解析/导入中的未插桩帮助函数仍不可抢占。这些是实现边界，不是已测得的延迟或 RSS 保证。

如果提供者未包含任何改动，actor 在完整来源、配置及解析环境防护通过后复用已检查的不可变分片，并仍调用独立比较器证明没有漏掉计划文件。不能只依赖路径索引的“未命中”计数来决定跳过。命中的提供者执行完整候选检查，不把逐文件或逐名字的检查拼成完整证明。

所有提供者在复核前后检查原始输入防护；所有范围在结果发布前再做一次最终防护，包括零目标范围。原生候选检查自身仍验证其实际磁盘依赖、解析候选和包环境；没有进入源码覆盖查找的依赖、清单和外部输入沿用原生读取、完整来源比较及原始防护。任何来源变化、诊断、基础设施错误、额度或取消均丢弃整个计划，不返回已完成前缀。

`SubmitRenamePlan` 的成功表示已通过上述来源及已捕获绑定复核，仍是候选数据。完整泛型来源、未绑定/生成事实、外部符号策略、物理别名/可写性和 IDE 的版本化原子应用尚待完成，`renameProvider` 继续关闭。全部适用 LSP、当前引擎资产对齐及全目标性能/内存/长期运行准入保持原范围。

已有原生解析报告还限制 2,048 个解析候选。512 个裸名称导入会先触及该上限；专项同时验证候选检查和原有磁盘检查都明确拒绝这一情况。512 来源成功用例采用显式路径导入，单独验证完整来源银行容量，不能解释为取消了原生解析报告额度。扩大/改善大型工作空间的解析追踪仍属于后续全目标准入工作。

上述为 M7b4o 的验收状态。后续[调用内候选索引](lsp-resolution-report-index.md)阶段扩大候选行额度，并增加 512 来源裸名称导入的成功对照；原阶段的失败材料和记录保持原样。

工程候选请求允许零打开文档和空触发键：只使用已捕获的原生目标、配置范围和磁盘输入防护，不伪造编辑器版本。相应的 keyless 原生来源捕获进入快照检查路径，不能误入要求保存正文的旧检查路径。

本阶段通过 185 个原生测试程序、12 组协议测试和 29 项配对 GUI 检查。新增底层专项 6,288 项检查覆盖实际 130/512 来源分析、完整磁盘原生索引对照、跨文件改名绑定比较、64 MiB 正文边界、分配/身份失败、取消、嵌套作用域及原输入释放后的四读者。工程专项 402 项检查覆盖 130 文件的裸名称/显式路径导入、零打开文档、受影响复核与未改动提供者复用、遮蔽/重载冲突、暖缓存、检查后来源变化及独立结果生命期；既有候选计划专项 90 项检查同时通过。

五个实际实现变异分别截断来源容量、跳过来源报告候选读取、丢失来源角色、跳过整表绑定批准及把关闭文档误送保存检查，均被测试拒绝。资格检查绑定 298 个实际消费者、186 个程序及 core 的全部成员；同一候选服务和匹配 SDK 重编译全部 116 个 GUI 对象，覆盖 C/xlang 输入、删除、撤销、Unicode/IME、焦点及既有语言功能，并复核浅色、深色和属性引用界面。

本轮还将原生 `check.c` 的实际编译入口从与此前提交一致的历史副本切回当前工作区源码。构建/诊断期间的失败原件和最终独立资格记录一并保留；最终矩阵重新核对完整源码、头文件、对象、archive 和程序身份。材料索引为 `dev/release-materials/provenance/lsp-frozen-recheck-20261111.json`。默认运行程序及线上通道保持原样，本阶段不进行全目标性能准入。
