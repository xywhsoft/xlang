# 统一 XRT、回调语义与缓存文本稳定性

2026-11-01，M7a2b104。本阶段为独立原生服务增加一组经过验证的前端组合，并修复语义事实缓存对可变词法文本的判断。根目录 IDE、LSP、引擎和设置均未替换；候选不具有性能／GUI／完整发行准入。

前端组合固定在 `eb61b68f14f3f05bfb52dcad830ef79a1f70ce82` 已提交源码：相对原服务实际消费的 352 项前端输入，349 项规范化字节相同，实质差异只有统一到 XRT `93347eb5` 的实现，以及 `xl6_sem.c`、`xl6_sem_c_owned.c` 两份语义源码。解析器、AST、IR、公开头和其他包含契约仍分别核对，不能因为某个补丁位置吻合就接受任意新源码。此组合不覆盖随后合入的 C 记录／类型化指针视图等前端变化；当前仓库源码还需另行对齐。

新的语义规则沿用编译器原实现，覆盖 C-owned 回调结果及可空提升成本、受约束绑定方法的重载选择、match 值域合并，以及在已检查模式作用域中使用原符号身份。新增的类型注册表读取也进入既有读取观察器。语义、上下文、IR、AST／解析器及运行时校验共享明确的组合摘要；旧组合继续可用，混用或篡改必须拒绝。

真正发现的缓存错误来自编译器改写词法类型文本。旧准入记录文本指针，检查后仍用指针相等判断词法形态未变化。释放后重分配可能复用地址，因而把已经改写的函数误认为可以仅重放语义属性。十组编译器语料揭示了 21 处索引差异：增量结果保留 `string/bytes`，全新检查则产生 `cstring/cbytes`，包括可空类型的 ABI 差异。

修复直接利用已有不可变输入键：编码词法节点时同时收集原有节点记录和文本的字节偏移／长度；捕获事实前比较当前文本与键中的原始字节。键增长不会使偏移失效，也不读取已经释放的旧文本。类型属性树仍参与完整输入编码，但不计入词法节点表。键字节格式保持原样，省去原先额外的节点收集遍历，没有再复制一份文本。每个临时词法记录增加两个 `size_t`；原语义 memo 容量不变，这不构成全局或瞬时内存界限。

无法证明词法文本稳定时继续使用编译器的完整检查，不缓存不完整的变换结果。既有来源、版本、环境、类型、符号、取消和发布证明均保留。本阶段没有让最终 IR 或所有语义编辑成为局部生产。
