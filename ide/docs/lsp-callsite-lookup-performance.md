# IR 调用查找的作用域索引

2026-10-30，M7a2b88a。定位并修复固定当前前端的 IR 调用查找热点，功能验收通过；正式性能验收仍等待资源条件。开发基线保持 0.99，候选继续隔离，长期目标 active。

## 原因与实现

沿用 M87 从提交 `a845a3471` 冻结的完整前端组合，包含引擎 `003dd48ea`；本轮以同一组合定位差异，未混入正在修改的引擎和 XRT 工作树资产。

阶段追踪将额外开销定位到成员 ABI、循环 ABI 和模块验证。当前构造效果查询对每个 IR 节点调用 `xl6IrCVarargCallSiteHasText`，后者使用线性的 `xl6IrCallSiteGet`。约十万节点和数千调用记录在多个阶段重复扫描，造成额外开销。类型化模块接管和持久结果准备本身各约 0.03 ms，不是这次热点。

在已审核的当前前端分支中，给原调用查找、成员 ABI 构建和循环 ABI 刷新增加三处定义改名。所有原函数正文及 C 变参参数／边界谓词保持不变。原来的查找实现保留为独立回退；实际调用表不修改。

公共查找复用已有的 XRT 调用来源索引：按来源和物理序号排序、二分取得第一条记录，返回实际原表行。重复来源保持原物理首条匹配，ABI 和参数字段始终读取当前值，没有缓存派生效果或负结果。两个构建阶段增加短生命周期索引作用域；已有验证作用域使用同一查找，结束后释放索引并恢复前一作用域。

索引仍有 8 MiB 上限。无匹配作用域、表描述无效、预算不足或可选分配失败时执行原查找。当前构建阶段可以修改节点或类型，但不修改索引使用的调用来源／行次序。旧前端不启用这三处改写，旧正式 IR 和语义对象逐字节一致。

## 正确性验收

新增 `analysis_ir_callsite_test`，在真实成员／循环构建阶段比较全部节点注解：无序表、重复来源、零来源、两种实时首条 ABI、空参数区、非法参数容量、非法调用容量，以及真实 `xrtArrayReserve` 分配失败，共 24,686 项检查。已有完整 IR 原始扫描／诊断对照 12,211 项及 C 变参边界 20 项继续通过。

四种实际遗漏反例分别旁路索引、取消成员作用域、取消循环作用域、选择较后的重复记录，均由新测试拒绝。三个定义边界的漂移被构建改写器拒绝；四个原函数正文经独立提取比较保持一致。

完整服务全新编译 206 个对象，111 组原生测试通过；配合当时根发布目录引擎的 52 套协议回归通过。重新核对完整构建 717 份输入、113 份产物，以及协议 219 份保护输入，均一致。旧 IR／语义对照使用当前 IDE 头文件和旧匹配前端，GCC 实际依赖记录证明使用了当前适配代码，两个对象仍与正式 0.99 相同。

## 计时诊断与正式验收边界

私有诊断程序只在原调用边界增加计时，标准结果保持一致。相同 512 函数语料的三个版本给出下表；这是热点定位数据，不是配对验收或 UI 延迟成绩。

| IR 阶段 | 修复前私有计时 | 修复后私有计时 |
| --- | ---: | ---: |
| 成员 ABI | 382.0～423.0 ms | 10.7～12.1 ms |
| 循环 ABI | 358.4～463.1 ms | 10.0～10.7 ms |
| 模块验证 | 401.2～435.6 ms | 41.2～44.9 ms |

正式测试预登记八种场景、八组独立进程对、14 个版本和一次精确重复，每轮 1,920 次请求／128 个进程。M87 的 A/A 有相对门槛波动，本轮增加独立进程样本；原 64 项门槛保持不变，启动至少 5 GiB、每请求至少 3 GiB 的可用物理内存与提交余量也保持不变。

`perf-aa-v1` 和用户再次释放内存后的 `perf-aa-v2` 均在启动资源检查被拒绝，可用提交余量分别约 3.95 和 3.51 GiB，均为零请求／零进程。未产生正式 A/A 或 A/B 性能结论，也未覆盖 M87 的失败结果。资源满足后需完成同程序校准及与正式 0.99 的完整比较，保留全部成功慢样本。

本轮没有将候选安装到根 `release/`。完整当前 SDK／IDE、尚未接入的适用 LSP 能力、工程规模、内存及交互延迟验收继续。
