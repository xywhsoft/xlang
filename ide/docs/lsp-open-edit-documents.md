# 打开文档的 WorkspaceEdit 协调器

M7b5b，2026-11-11。`editor/workspace_edit_documents` 现在串起真实文档模型、不可变编辑计划、位置映射和 XUI batch-v2。它是完整应用器的打开文件部分：整份计划必须都是已打开且带版本的文本文件；关闭、未知或无版本目标使整个捕获失败。没有开放标准重命名或 `workspace/applyEdit` 入口，也没有把混合文件组当作已完成事务。

UI 的 Capture 只捕获身份、修订、控件版本、基线租约、路径/语言、选区和滚动偏移，以及 XUI 的平面布局元数据。路径比较仍使用已有路径转换；不扫描或复制正文。后台 Work 只含不可变计划、保存基线、平面选择/布局数据、位置映射及构造载荷，没有 GUI、模型或存储指针。Stage 可以在真实工作线程完成；原 Ticket、模型和 Context 销毁后，后台仍能完成 Stage 并独立退休。

Ticket 必须在 UI 所有者线程销毁。调用者须保持 store 的地址有效，并使 Work 活到 Ticket 销毁且 Stage 结束；允许清空 store，不能提前释放 store 地址。Ticket 不拥有 Work 中的大计划/基线引用，销毁 Ticket 不会释放后台最后持有的正文。Work 使用方负责线程间交接和同步，不能并发 Stage/Commit/销毁同一对象。

Stage 在后台构造位置映射、计算相对保存基线的 dirty、构造完整 XUI 载荷。模型修订、基线身份、路径/语言/覆盖、外部状态、只读、原控件版本及捕获的选区/滚动必须仍一致。常规 store 槽查询验证身份后直接命中；槽重排时回退查询，不能把旧槽当作可复用的模型指针。

Commit 必须提供宿主 guard。它负责连接/请求代次、配置、项目和完整来源覆盖、物理别名/文件权限、注释批准等外层条件；这里没有默认批准。模块在 guard 前后复核整组本地状态，XUI 再检查自身正文/历史围栏。任何发布前失败都不应用前缀。通过后先一次发布全部正文，再在第一个普通通知之前发布全部模型修订和模型/SDK dirty；每个变更文档只推进一次修订，保留原撤销历史，仍逐文件撤销。

必须独立检查 `outcome.committed`。它为 true 后，不论后续返回状态或位置恢复结果如何，均不能重复应用正文。变更通知结束后逐文件清理发布标记，并尽力恢复映射选区与原绝对滚动偏移；回调若改变了正文、阅读位置、语言、路径/保存基线、只读或外部状态，该文件跳过恢复。窗口在第一个通知中请求关闭时，后续通知可能跳过，已发布正文仍有效，未消费标记仍会清除。阅读失败通过独立计数和状态报告。

折叠选区采用右亲和；非空选区保持方向并采用首尾边界亲和。XUI 仍负责其公开选择 API 的标量/字素规范化。保留 preferred-column 和 flags 的意图，没有复刻私有选择结构；不声称字素、折叠或按文本锚点重定位视口已全部解决。全文替换中部多个变化仍受位置映射仅裁公共首尾的限制。

最多 512 目标、4096 个 store 文档、4096 个合计选区和 1 MiB 路径/语言元数据。默认/最大已知存储预算为 128/256 MiB，统一计入 plan、保存基线、元数据、选区数组、映射和 XUI Capture/Stage 存储，避免把剩余额度 0 误传成库的默认额度。`xideEditPositionsStorage` 暴露包含 plan 的已知存储，供协调器只计一次。分配器、路径帮助函数、通知/缓存和外部调用者存储额外；这些不是进程峰值或端到端取消上界。

后台构造和未接受载荷可以后台退休，但接受后放弃的 XUI 载荷仍需 UI 清理，Commit 还比较原正文、复制旧撤销前缀并处理通知/语法刷新，选择规范化可能扫描行或字素。尚未完成整体延迟准入，不能称整个操作已无迟滞。

专项通过 2,209 项检查，用真实 C/xlang 模型、实际 DLL、工作线程和宿主回调验证多文档发布、干净/脏文件转换、撤销/重做、相反/多重/折叠选择、槽重排、错误线程、陈旧修订/身份/基线、仅编码变化的同正文重载、相同长度的错误请求正文、宿主重入与拒绝、取消和分配失败。还验证空计划、Context 关闭后的后台构造/释放、store 清空及预算准入边界。GUI XRT 没有通用堆统计；直接分配观察不包含 DLL 内部调用，不冒称全堆平衡。

全部 120 个 IDE 对象重编并通过 42 项 GUI/配置回归，包含 C/xlang 输入、删除、撤销、Unicode/IME、点击焦点和既有语言功能。11 个实际实现变异分别破坏模型发布、dirty、映射、阅读/基线/修订围栏、宿主检查、回调保护、跳过通知清理和版本要求，均在预期断言失败。映射原生程序、独立冷态故障和 Text/Sync/边界程序另行复核；服务重新链接仍与 df290f26 镜像逐字节一致，其他原生/协议套件没有在这里重跑冒领。

仓库匹配 SDK 与本阶段 GUI 使用同一批次：保留原有元数据，补齐语义颜色和 batch-v2 公开头、DLL、导入库、清单及来源材料。沿用先前严格编译的 173 个 SDK 单元，重新核对实际对象/依赖身份、791 份源材料和 766 份预处理依赖；18 项材料验收另行通过，不把 SDK 单元说成本阶段重编。保留候选/非正式发行和未完成法律审查标记。默认发布程序与用户交付索引保持，SDK 更新不能当作运行目录已同步。

仓库默认构建入口以更新后的完整 SDK 另行重编成功。真实 GUI 主程序还以仅服务/DLL 名称改变的私有链接运行于根发布目录，分别打开 C/xlang 文件、各渲染 24 帧并保存截图，检查实际窗口布局与两种语法着色；这不替代交互测试或性能验收。
