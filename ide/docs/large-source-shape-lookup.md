# 单次整形中的字形查找复用

2026-10-10，独立 SDK17 在单次长文本整形中复用重复字符的字体与字形编号。完整 SDK 严格冷构建、真实新旧整形及像素对照、C／xlang 原生文件矩阵和相关回归通过。16 MiB 超长单行仍有数秒响应延迟，性能未验收，长期任务继续。当前应用、固定 SDK、编译器与便携候选保持原样。

前一轮见[SVG 外层裁剪](large-source-outer-clip.md)。本轮用相同的当前 83 个应用对象分别链接 SDK15 与 SDK17；237 个源材料中，仅 `src/xge_text_run.c` 改变，公开头相同。

## 查找规则

真实栈此前显示输入处理进入整行整形并反复调用字体查找。本版为 `xgeTextShape` 增加固定 128 槽的调用内查找表，每槽记录字符键、字形编号和实际字体指针，Win64 共 2,048 字节。仅当实际文字长度至少 256 字节时初始化并使用；较短输入继续原始解析路径。

命中复用该次调用中已确定的字体／字形编号；冲突调用原始字体回退解析器后替换该槽。失败解析不缓存，不改变原有未写入的字形输出。表在返回时消失，不跨字体重新装载、字号、DPI、回退顺序或不同线程保留新增状态。现有度量读取、字距、Emoji 匹配、字体引用管理、正文扫描和整段结果分配继续原规则，没有新增正文、逐字符或字形副本。

比较夹具的 GCC 栈使用报告记录新 `xgeTextShape` 为 2,448 字节，旧比较函数为 400 字节，增量恰为表的 2,048 字节；这些是该诊断编译的静态栈帧数据，不是整个调用链的最大栈用量或跨平台保证。

## 实际验证

真实 SDK17 引擎与 SDK15 原始整形函数在同一比较程序中运行，共 4,801,138 项断言、2,822 组完整整形、3,365,718 项标量查找和 108 组新旧像素对照。比较程序是唯一 XRT 所有者，没有链接 SDK DLL，SDK 没有诊断钩子。

使用实际 Consolas 与 Noto 字体，覆盖四个字号、三种回退顺序、所有 Unicode 标量及重复命中／散列冲突、255／256／257 字节附近、缺字、中文、组合字符、RTL 字符、非 BMP、Emoji 和 ZWJ 序列、不同整形标志与 Emoji 策略、CR／LF／Tab、嵌入 NUL、非法 UTF-8、1 MiB 重复文字，以及无后端的深度受限回退循环。对照核对完整字形结构、宽高、基线、行高、簇范围、字体顺序和引用恢复；像素对照还有 12 个明确非空的 ASCII 控制用例。

原始准备的第一版夹具没有执行；执行前新增非空像素控制，第二版严格编译及原生运行退出 0，耗时 0.844 秒。落盘的独立测试入口随后实际再次完成同样的检查并退出 0，耗时 0.766 秒，分别保留日志。当前限定的字体与策略不能证明所有字体、复杂 Bidi、GPU 或内存分配失败路径正确；本版保留旧整形语义，没有新增完整复杂文字整形能力。

SDK17 整套冷构建使用 `-O2 -Wall -Wextra -Werror` 及既有三项警告排除，实际退出 0，耗时 144.281 秒。237 个输入前后相同，严格构建脚本在实验根目录，原始构建文件不变。DLL、导入库和资源对象成套保存，5,949 个导出名称及序号与 SDK15 一致；这不代表完整 ABI 验收。

原始 Unicode、Emoji、文档三项 SDK 测试退出 0。现有 `document`、`editor_view`、`goto_view`、`find_view`、`input`、`reading` 六项 IDE 程序在独立目录使用 SDK17 DLL 退出 0。没有重新编译应用、执行完整标准回归或验收新便携包，输入事件测试也不代表实体 IME 验收。

原生矩阵为新旧 SDK × C／xlang × 2／16 MiB × 多行／单行，共 16 次独立运行，每例完成 43 项检查，总计 688 项。覆盖打开、定位、插入、撤销、绘制、空闲帧和截图；使用未切换到前台的私有桌面、1600 × 1000 窗口、1.25 DPI 覆盖及 2 GiB 私有提交限制，语言服务未配置。
