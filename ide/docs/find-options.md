# 查找选项与转义修复

SDK66 阶段补齐 C 和 xlang 编辑器的查找选项验收，并修复普通替换、正则替换及无效查询的实际问题；这些修复已并入当前开发 SDK67。后续[正则 UTF-8 边界修复](find-boundaries.md)补齐空匹配及非法字节校验。工作台布局与单栏命令帮助沿用定版设计。

在编辑器中按 `Ctrl+H` 打开替换窗口。查找 `item([0-9]+)`、替换为 `value$1`，勾选“正则”和“区分大小写”，会替换 `item12` 和 `item56`，保留 `ITEM34`。“全字匹配”要求整个词匹配；勾选“选区”后只修改所选范围，正向或反向选取均可。

勾选“转义”后，`a\tb` 匹配含实际制表符的文本。替换中的 `\u4E2D\u6587\uD83D\uDE00` 产生 `中文😀`；UTF-16 代理对合并为单个 Unicode 标量，孤立、错配或不完整代理项拒绝。`\n`、`\r`、`\t`、`\\` 和有效 UTF-8 字节转义保留原有用途。普通转义中的 `\0`，以及两种替换模式中的 `\x00`、`\u0000` 均拒绝，避免把匹配内容误当作空替换删除。

正则替换保留 `$1`、`\1` 分组引用，`\0` 在正则替换中表示整体匹配。正则与转义同时开启时，查找表达式先进行转义解码，例如 `item(\\d+)` 将正则的 `\d` 传给正则引擎。非法替换在开始匹配前校验，即使没有匹配也返回错误。

无效正则显示“无效查找表达式”，点击“查找全部”后仍保留该提示，同时清空旧匹配、搜索高亮和结果行。跨标签查找失败时，所有成员的旧结果一并清理，失效结果无法再次激活。非法替换不改变正文、文档版本、脏标记或撤销/重做状态。成功的“全部替换”仍是一笔撤销事务，其他文档和磁盘文件保持原样。

## 已执行的验证

接入前使用已验收应用的精确 84 个对象和新 SDK 执行实际窗口测试：`find_options_view_test` 通过 164 项原生断言，覆盖明暗主题、C/xlang 的实际复选框和按钮、大小写、全字匹配、分组替换、转义、反向选区、单次撤销/重做、非法输入、跨标签旧结果清理，以及文档与磁盘隔离。八张原生截图已查看。[窗口证据](../build/find-options-b8dff1990b6e/evidence.json)。

实际 DLL 的公开 API 通过 49 项断言；另有 36 个独立进程将截断转义的 NUL 放在最后一个可读字节，保护下一页，验证普通查找、普通替换和正则替换均安全拒绝。[API 与保护页证据](../build/find-options-0f7ed8b7fc91/evidence.json)。这组保护页测试没有在旧 SDK65 上复现访问异常；已复现的问题是 NUL 空替换、无效代理项、错误提示及旧结果残留。

SDK66 的完整源树保留 243 份材料，只改动 `src/xui_find.c` 与 `src/xui_code_edit.c`。完整 SDK 严格构建、119 个翻译单元的实际预处理材料收集均通过。9,081 项公开声明、372 项公开类型和 5,954 个导出保持一致；102 个已冻结运行产物中的 XGE 名称导入均可解析，无序号变化。[SDK 构建](../build/editor-sdk-find-escapes-dde90d0584cc/sdk-build.json)、[来源闭包](../build/sdk66-find-options-materials-v1/result.json)、[公开接口比较](../build/find-options-public-compatibility-v1/result.json)。这项比较的范围不等同于完整 ABI 或正式发布验收。
