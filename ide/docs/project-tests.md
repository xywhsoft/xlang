# 项目测试任务

实现日期：2026-10-08。首版传统 IDE 的测试入口运行项目明确配置的程序，沿用任务队列、输出、管道会话和停止操作。

## 配置和使用

选择右侧工作空间中的项目，打开“项目 → 构建、运行与测试配置…”或项目属性中的对应按钮。在配置窗口选择“测试参数与程序”，填写测试程序和测试工作目录，并逐项添加参数；“测试环境变量”编辑该程序的环境覆盖。点击应用后保存项目，或在发起测试时由 IDE 保存。

Ctrl+F7 或“文件 → 运行所选项目测试”使用所选项目的当前配置。F7 仍构建所选项目；F5 仍构建并运行启动项目。测试允许 DLL 项目填写独立测试宿主。打开、导入项目、切换配置和应用草稿均不会执行程序。测试程序留空关闭测试入口。

程序须为明确的 `.exe` 路径，相对路径以项目清单所在目录为基准。运行脚本时明确填写解释器程序，例如 Python 或 PowerShell 的完整可执行文件路径，再通过参数数组传递脚本路径和参数。IDE 不推断解释器，不拼接 shell 命令，不隐含构建步骤。需要先构建测试程序时，由开发者先发起构建；测试结果仅表示配置的进程及其实际退出结果。

参数数组保留顺序、空参数、中文、空格、引号和反斜杠，不需要额外 shell 引号。环境变量覆盖继承的进程环境，允许空值，名称不能为空、包含等号或 NUL；同一配置中拒绝大小写重复名称。运行和测试各自保存参数、工作目录和环境。

```json
{
  "id": "development",
  "name": "开发配置",
  "output": "build/development/app.exe",
  "run": {"workingDirectory": ".", "arguments": [], "environment": {}},
  "test": {
    "program": "build/tests/tests.exe",
    "workingDirectory": ".",
    "arguments": ["--filter", "parser tests", ""],
    "environment": {"XLANG_TEST_MODE": "local"}
  }
}
```

`test` 位于 `ide.configurations[]` 内，属于 IDE 元数据；不改变编译器根字段。缺失 `test` 的旧配置保持可打开且不会自动新增测试入口。测试对象的未知字段保留，草稿、验证失败和取消均不提前修改项目。项目另存为重新计算测试程序与工作目录的相对路径；文件引用改名和整项目目录迁移协调已声明的测试路径，不解析任意参数中的路径文字。

## 执行和结果

测试前保存所选项目的相关已命名脏文档及脏项目，沿用外部变化和清单冲突保护。任务复制项目、配置、程序、参数和环境，后台核对已保存清单与直接输入；排队或准备期间的已知输入编辑使请求失效，需重新发起。进入测试进程阶段后允许继续编辑文档。

测试与构建、运行共用串行队列；相同未完成测试请求合并。测试不会探测 xlang 编译器，也不发布或声称产生构建产物。进程正常退出且退出码为 0 时成功；非零退出、启动失败或 IO 失败时失败。测试进程实际启动标志与构建、运行标志分开记录。Ctrl+C 或 Shift+F5 停止任务及关联进程树；排队测试可以取消。

底栏任务条目和状态栏保留“测试”类别，历史输出可重新选择。终端支持输入、粘贴及 Ctrl+D / Ctrl+Z 或“关闭会话输入”关闭 stdin。完整进程输出写入独立 GUID 目录中的 `test.log`，输出窗格显示路径；界面保留有界尾部并标明省略。配置窗口沿用两轴滚动与界面字体设置。

当前输入基线仍有单文件 16 MiB、合计 128 MiB 限制。直接列出的输入守卫不代表完整递归依赖图；已启动进程、测试数据和外部解释器依赖不属于完整版本审计。尚未提供测试发现、用例树、结果协议或后台并行调度。详细任务边界见 [任务与工具链](tasks-and-toolchain.md)。

## 验收

`project_test_test` 覆盖显式 DLL 测试宿主、无编译器执行、原样参数和 stdin、退出 13、启动失败、队列合并/取消/失效、环境校验、未知字段及实际另存为/目录迁移；提供真实编译器时，还构建 C/xlang 工程并执行其明确配置的测试产物。

`project_test_view_test` 操作原生类别菜单、配置字段和按钮，验证取消与应用不执行、独立启动项目、Ctrl+F7、C/xlang 文档保存和终端输入、关闭及历史输出，并检查 125% DPI 与 40 DIP 两轴滚动。完整回归的结果见 [实施进度](progress.md)。
