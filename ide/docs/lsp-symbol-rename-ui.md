# IDE 符号重命名窗口

M7b6f，2026-11-14。编辑菜单新增“重命名符号…”（`Ctrl+F2`），使用已协商的原生候选、完整来源证明、宿主保护集合和异步混合事务。原来的文件改名仍使用 `F2`。C LSP 保持关闭；这项重命名操作只适用于可编辑、已同步的 `.xl` 文件。

窗口首次使用时创建，不增加普通启动的后台工作。打开时固定源文档身份、修订和光标位置；输入新名称后，生成候选与来源验证在既有常驻工作线程和语言服务中进行。没有工作空间的单文件也使用同一流程。新名称按有界 UTF-8 意图传递，是否合法由实际语言服务检查，不在界面复制一份语言词法规则。

生成预览和确认阶段保持模态，列出全部受影响文件、修改位置数、编辑器修改或磁盘写入方式，并可选择查看完整路径。列表最多 512 项、已知展示文本最多 1 MiB，失败时取消整个预览；不截断文件集合，也不把预览当作写入许可。确认调用 M7b6e 的宿主保护入口与精确令牌，重复完整 Current，再取得真实六参与者屏障。正文与大型候选不复制到窗口对象。

应用阶段窗口没有背景遮罩，继续允许编辑器输入、删除、撤销、Unicode/IME 和焦点切换。输入使原始请求失效时，未提交的磁盘写入在独立恢复许可下回滚。保存、文件操作、工程操作和新构建的菜单动作暂时禁用，底层文档屏障继续保护直接调用。已打开文档保留为未保存编辑，可用各编辑器的撤销；未打开文件由事务写入磁盘。

取消和窗口关闭按钮会等待后台异步收尾。主窗口关闭先取消当前候选或事务，待物理活动结束、源文件资源关闭、屏障释放后，才重放普通退出流程。不会在普通窗口关闭回调里同步等待工作线程，也不会在屏障仍持有时进入普通保存/丢弃流程。最终退出仍由既有 `xideLanguageEditApplyShutdown` 在参与者销毁前处理。

不确定状态保留屏障和原始恢复资料。窗口提供完整恢复路径、打开恢复目录、返回编辑器和退出入口；不自动重放日志、不把状态不明的文件当作已恢复，也不释放其他持有者的令牌。用户可以先复制未保存正文。退出必须再次明确确认放弃全部未保存文档和工程修改；既有消息决策机制额外绑定事务令牌与打开文档修订，旧确认不能覆盖后来修改的正文。此入口不会声称恢复资料备份了所有未保存内容。自动恢复、核验后继续本次会话仍待后续实现。

通用业务窗口默认仍为模态。新增 `xideDialogSetModal` 只能在关闭时修改模式；符号窗口在模式转换时关闭再打开。禁用名称输入和预览按钮后，模态阶段将焦点交给取消按钮，保证 Esc 能到达窗口的取消处理；非模态进度和结果不抢编辑器焦点。

正文按自然高度布局，空间不足时滚动，底部按钮固定。文件列表行高在创建时按当前字体缩放，随后复用现有全局字体更新机制。40 DIP 验收不只检查页脚，还检查列表实际高度、行高、滚动后的可见区域，并检查实际截图。首轮仅检查页脚的断言曾漏掉列表零高度，失败历史和修正记录完整保留。

验收运行真实 XUI 输入和点击、实际原生 RPC、五文件修改及单文件模式。覆盖生成与预览取消、标题栏关闭、Esc、源作用域变化、非法新名称、构造失败后重试、列表分配/构建失败、写入期间输入、主窗口退出异步协调、不确定日志的拒绝/再次确认/旧确认失效、连续两次公开窗口重命名、字体缩放及 C/xlang 编辑回归。错误实现通过实际编译和执行检验，源码、依赖、对象和链接身份分别记录。

额外运行的三项旧弹窗夹具仍失败，并在上一阶段的完整配对构建中复现相同断言：`dialog_layout_test` 的引用窗口在 40 DIP 下页脚越界，`dialog_message_test` 的新建项目窗口断言失败，`modal_open_latency_test` 的第二轮关于窗口打开被拒绝。这三项不计为通过，也不据此作性能结论，保留为后续问题。

当前接入是 IDE 的原生重命名操作；标准 `textDocument/rename`、通用 `workspace/applyEdit` 及其他客户端的写入接入没有因此开启。引擎资产对齐、完整泛型/外部来源资格、其他同步读者、全链路性能/RSS/耐久、Linux 与 sanitizer 验收仍开放。现用发行程序、SDK 和 active delivery 不替换；阶段源码与外部验收索引见 `dev/release-materials/provenance/lsp-symbol-rename-ui-20261114.json`。长期任务不在本阶段标记完成。
