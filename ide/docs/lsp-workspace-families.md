# 工作空间声明关联闭包

工程引用 actor 新增显式的工作空间声明关联查询。它逐一覆盖范围快照中的全部工程及独立文件，复用已有成员调度、导入覆盖、输入防护、取消和 LRU 缓存；普通补全、导航及引用不会主动生成声明图。缓存记录可保留与原引用分片共享同一源码库的声明图，仅额外计入图自身载荷。旧引用记录在关联查询需要图时重新捕获并升级；已有图记录可直接复用，包括每个工程的初始所有者。

所有成功所有者的图参与一次批量合并。先按既有原生路径比较规则排序源码，逐个验证同路径的完整正文、来源类别和 BOM 转换约定；再按合并后的源码身份与声明字节区间，合并各所有者的原生连通分量。局部数字 ID 和分量序号不跨检查使用，不按同名猜测关系。排序与并查集一次得到全工作空间观察到的派发、重载、属性关联闭包，无须对新发现的每个声明再执行原生分析或图查询。

每个分量的不可用标记在跨所有者合并后仍作用于整体；不能因某个所有者没有映射生成节点而丢掉这一限制。输出去重源码声明，并在结果载荷中对每份贡献源码只复制一次，保持原有独立 `family` 与成员 key 生命周期。`FamilyMember` 可无分配读取一个成员的来源和精确区间。关系计数是各提供者的观察次数，未将重复检查中的边去重。

本阶段的批量工厂在调用期间借用全部提供者图。默认及最大 128 MiB 预算保守计入这些图的完整载荷、排序/并查集数组、持有的原生路径键和最终结果；重叠输入图仍可能被重复计费。actor 的全局缓存仍有原有的 128 MiB 已知存储预算，查询钉住的旧记录、输入防护和临时分析成本另计。这些不是进程 RSS 上限。路径转换、分配器及库排序内部临时成本额外，库排序和完整正文比较不可中途抢占。当前实现选择一次批量排序，后续可进一步在流入时共享跨提供者源码银行，减少很宽工作空间的重复输入持有。

每个范围完成时保留全部输入防护，包含没有目标声明关联的范围；合并之前及之后都再次核验。选中的声明族必须全部位于明确登记的 `.xl` 成员中，导入库本身不授予成员资格。任何来源失配、不支持的连通成员、范围外成员、额度失败、取消或失效防护均拒绝完整结果，不发布前缀。

`xideProjectReferencesSubmitFamilyWorkspace` 的成功结果不含 Location 数组；调用方通过 `xideProjectReferencesRetainFamily` 取得独立不可变结果。这仍是当前原生关系在全部配置范围中的闭包。完整泛型来源、物理别名与操作系统可写性、外部符号策略、整个声明族的引用位置收集、改名冲突与改名后的绑定证明，以及版本化编辑和 IDE 原子应用仍待完成。标准 `renameProvider` 继续关闭。

本阶段通过 178 个原生测试程序、12 组协议测试和 29 项 GUI 检查。新增合并专项 181 项检查，覆盖跨所有者传递关系、重复提供者、独立的不同签名方法、完整来源失配、Unicode 路径与名称、BOM/CRLF、最小成功额度与少一字节拒绝、两处真实结果分配拒绝、全部观测取消位置和脱离原所有者的四读者读取。工作空间专项验证温热查询零捕获、零成员任务，检查不含目标关系的项目成员，拒绝未登记的关联库文件，并在合并后修改无关文件或取消时拒绝结果。遗漏跨所有者连接、丢弃不可用标记、忽略完整正文失配及跳过最终防护这四个实际实现变异均被测试拒绝。

资格检查绑定 289 个实际原生编译消费者、179 个程序及所有 core 成员；IDE 配对同一候选服务与匹配 SDK 重编译全部 116 个对象，完成 C/xlang 输入、删除、撤销、Unicode/IME、焦点与现有语言功能检查。浅色、深色和属性引用窗格已复核。材料索引位于 `dev/release-materials/provenance/lsp-workspace-families-20261110.json`，包括最初错误的结构协议测试假设和编译失败原件。默认发布程序保持，未运行本阶段全目标性能准入或线上发布。
