# 多入口诊断存储

`services/diagnostic_store` 为自动检查多个入口提供独立的诊断存储。一个 XRT 任务池线程串行管理记录、合并结果和输入复核；调用方提交有界操作，通过 Future Watch 唤醒后读取结果。诊断记录使用 [独立输入守卫](lsp-diagnostic-inputs.md)，不保留检查任务、源码正文、AST、IR 或导航表，也不为每个入口创建观察线程。

每个入口独立贡献本次实际加载的文件和包清单结果。捕获集合中没有参与分析的打开文档空组会被排除，因此检查另一个文件不会用空组覆盖原文件的有效诊断。移除入口只撤回该入口的贡献；共享依赖仍保留其他入口的诊断。宿主观察到打开、编辑或关闭时，可按实际输入及已观察的解析候选路径撤回受影响入口，不必撤回无关入口。

合并先按预先准备的平台路径键排序，同一路径使用既有平台的 Unicode 大小写比较规则。排序／二分查询不反复规范化路径或分配字符串。多个贡献的版本、来源、正文指纹及磁盘身份必须一致，否则操作失败，不能发布混合版本。平台比较收口于 `platform/path`，存储模块不直接调用系统路径比较 API。

诊断使用必需的消息／范围标量建立 XRT 哈希表候选桶，再通过 XRT 完整结构相等判重。它不要求为可变 JSON 容器绑定身份哈希；桶内冲突继续逐项核对，因此字段顺序变化不产生重复，而不同的可选字段也不会被丢弃。输出为独立只读快照，后续修改或存储销毁不会改变已经完成的查询结果。

默认最多保留 64 个入口、32 MiB 编码报告，单次合并发布最多 4 MiB，后台队列最多 8 项。还限制实际输入每入口 512 项、合并文件 4096 项、每文件诊断 4096 项和单次合并去重后诊断 16384 项。入口键、解码路径及消息文本各限 65,535 个 UTF-8 字节，平台自身的路径限制仍适用。编码报告预算包括输入报告、诊断贡献和入口键，属于数据表示预算，不能当作堆／RSS 上限。

预算通过 XRT 流式 JSON 写出接口计数，并在复制或扩展合并结果前检查剩余容量；不会为了计量构建完整 JSON 字符串。超出入口／报告／发布容量或发生版本冲突会返回明确失败，保留先前存储状态。原子输入守卫已经确认的永久失效仍会保留，下一次操作不能重新发布该证明。取消不能撤销已经完成的提交，宿主仍须按当前输入代次和操作顺序丢弃过期结果。

统一 Sweep 复用原输入守卫的磁盘身份、内容、包环境和解析候选验证，返回需要重查的入口键；宿主负责选择轮询间隔及调度。提交操作转移独占结果所有权，不在调用线程复制正文／JSON、合并、访问文件系统或等待工作线程。队列满直接拒绝；销毁会取消并等待后台退出，因此仅用于关闭流程。

`diagnostic_store_test` 使用实际原生检查及独立输入守卫，覆盖多入口共享错误、独立文件、未使用覆盖排除、字段重排和同桶可选字段差异、Unicode 路径别名、版本冲突、报告／入口容量、原快照跨更新／销毁保留、真实 4 MiB 文件复核期间的队列／取消／关闭，以及实际源码包的清单结果和身份失效。可选字段差异是收集器的受控表示用例，没有伪称编译器生成了该额外字段。

服务 0.21 已将存储接入 [自动诊断调度与发布](lsp-automatic-diagnostics.md)，IDE 默认自动策略仍待接入。`xideDiagnosticQueryTake` 在完成后仅可调用一次，直接转移独立 publication 及失效键；之后不能再读取原 query 结果。publication 拥有已准备的路径键和只读分组，可以跨 query／存储销毁保留，查找／比较不复制整份报告。`Clear` 通过相同队列事务移除全部贡献，避免交互路径销毁并等待 actor。

失败合并可返回借用的 `conflictPath`，指出新旧贡献实际使用了不同输入的文件；宿主必须在 query 销毁前捕获或提交该路径的失效。它用于精确重查，不能把不同输入拼接为同一发布快照。新增专项验证一次性转移、路径查找、完整分组比较及跨 Clear／query／存储销毁所有权，共 102 项断言。最终进程峰值、完整工程规模及 UI 时延仍需后续验收，长期任务继续。
