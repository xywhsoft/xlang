# 导入候选的目录通知

阶段：M7a2b126k，2026-11-09。

之前 IDE 的目录通知只触发已订阅文件的快照检查。工程入口导入了尚不存在的 `candidate.xl` 时，后来创建该文件不会改变入口文件，因而可能无法触发自动分析恢复。本阶段为现有监视器增加可选的递归源码名称通知，并接入主语言连接。

工程清单继续决定显式成员。新文件的导入关系由原编译器解析；通知不会把目录里的每个 `.xl` 文件加入工程或符号索引。标准 LSP 工作空间目录管理、全量目录发现及工程外依赖订阅仍属于后续工作。

## 通知和所有权

`xideFileWatchSetTargetsWithSources` 为订阅父目录开启递归通知。既有 `xideFileWatchSetTargets` 保持原模式。仅当 IDE 有 xlang 源码订阅时启用；C 编辑、构建和默认关闭 C LSP 的策略保持。

同一个 IOCP 监视线程维护文件变化和目录名称变化两种句柄。文件流只转发未订阅 `.xl` 路径，已订阅文件继续通过原稳定快照、保存去重和冲突处理。目录流单独识别带点目录的创建、删除、重命名；目录变化、8.3 路径、损坏记录、缓冲区覆盖不足和订阅交接缺口会产生复查提示。

复查提示让当前订阅的 xlang 源码根通过原 watched-files 通路重新验证实际依赖及缺失导入候选。普通小工程沿用现有连接；超过既有监视历史上限时仍按上一阶段的规则合并重同步。复查提示本身不取消构建，只有真实文件或编辑输入变化才继续进入原任务失效规则。

磁盘输入失效同时释放旧悬浮和大纲结果对象。仅关闭提示窗口或取消请求会留下旧结果，且已失效的诊断组不会再次触发原撤回路径；本轮的实际 `int`→`string` 导入文件修改回归已覆盖这个问题。

通知记录只有有界路径和类型，不读取源码正文。已知路径键在监视线程构造一次排序索引，逐通知二分查找；没有逐查询目录扫描。结果仍通过原同步线程编码并受发送前的输入／连接／逐路径修订保护。

## 边界和恢复

- 继续使用原 4,096 事件、128 MiB 正文上限；新增源码通知路径另有 4 MiB 总额度。同一路径合并通知，创建后修改保留创建类型，删除和重命名按实际动作转发。丢弃事件时也唤醒所有者，使既有丢失计数恢复通路能够及时运行。
- UTF-16 名称按记录字节长度转换，检查记录跨度、对齐、截断、无效标量、嵌入 NUL、绝对路径和父目录逃逸。OS 缓冲区明确保证 DWORD 对齐；完成数据复制后重新提交异步读取，再处理副本。
- 递归源监视保持现有句柄，避免每两秒重建时丢弃未知文件事件。原已订阅文件的定期稳定快照检查保留；句柄失效时重新寻找可用父目录、重建并请求复查。关闭前取消并排空两种待完成操作，再释放目录记录。
- 文档打开／关闭只协调变化的目录订阅，保留仍适用的句柄。退休句柄在各自的待完成操作排空后释放，不阻塞其他目录的通知；活动与退休目录记录合计最多 40,000 个。已排队的源码提示迁移到新代次，通知跨越尚未应用的代次时补一次复查。协调器通过排序查找保留同路径已知快照，避免订阅替换把真实内容变化误作首次基线。这些有界记录和载荷额度不等于进程 RSS 上限。
- 工作空间外的包／导入目录尚未自动加入此订阅。本阶段不把该范围外的变化声称为已经主动监视，实际查询的原来源验证仍保留。

Win32 行为依据 [ReadDirectoryChangesW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-readdirectorychangesw) 和 [FILE_NOTIFY_INFORMATION](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-file_notify_information)：文件名是长度限定的相对 UTF-16，可能使用短文件名；覆盖不足需要重新确认实际状态。这里的工程成员与导入状态通过已配置源码根的原分析流程重新确认。

## 验收

精确源码、构建、回归及失败记录见 `dev/release-materials/provenance/lsp-import-watch-20261109.json`。新增解析器夹具覆盖类型／合并、Unicode、已知路径排除、错误记录、分配拒绝、代次、路径额度及队列溢出唤醒；真实 IOCP 夹具覆盖未订阅和嵌套源码、带点目录重命名及已订阅保存去重。IDE 生命周期夹具验证未打开、未列出的实际导入文件创建／修改／重命名／删除恢复，清单成员数不变；构建夹具验证复查提示不误取消正在进行的构建。

最终 26 项回归通过；解析器 4,271 项检查、构建保存监视 164 项检查、生命周期 183 项检查，以及两个实际 C 遗漏对照均留存。最后两个修复只涉及私有实现：在已完整构建的 115 对象／匹配 SDK 基础上，核对全部 674 个原输入和 77 项实际编译依赖，保留 113 个对象，补编文件协调器与语言视图，并重新编译 GUI 入口进行链接。共享头文件未变；根工作副本与冻结输入间的纯 CRLF／LF 差异另记原始摘要。

服务原生实现本阶段没有修改，不将其保留测试计作重新执行。整体端到端性能准入仍未完成，本阶段没有改写既有性能失败或发布默认程序。
