# 代码字体设置

“视图 → 代码字体…”提供原生模态设置页，可选择 TTF/TTC/OTF 文件和 8–40 的整数字号。默认优先使用 Windows 字体目录中的 Consolas 16；缺失或损坏时使用随包中文等宽字体。中文字形优先由微软雅黑补充，再回退到随包字体；路径通过 Windows API 获取。建议选择等宽字体，C、xlang 和纯文本使用相同偏好。“填入默认值”只更新草稿，取消不修改已应用的字体。预览显示当前实际字体效果。

应用覆盖已有和新建文档、关闭后保留的编辑器、语法演示、只读帮助代码块、构建输出及终端。CodeEdit 的文本、撤销文档和选区不重建；字体度量刷新只改变显示。帮助代码块根据实际行高重新计算高度，即使文档宽度未改变；终端使用实际字符宽度、行高，并遵循 SDK 的整数像素对齐规则。

## 保存和失败保护

字体偏好与编译器偏好共用应用持有的 settings 对象，保存在程序旁 option/settings.json；诊断参数 --settings PATH.json 可以隔离测试。JSON 格式仍为 xlang-ide-settings-1，新增 editor.font.path 和 editor.font.size，保留根、editor 和 font 内的未知字段。启动可读取相对于设置文件的字体路径，外部字体保存规范化的绝对路径；默认 option/settings.json 中选择 data/fonts 下的字体会保存相对路径，便于迁移。

加载先读取最多 64 MiB 的文件，检查字体容器及表范围，再通过严格内存接口加载实际字体。固定 SDK 的按文件加载接口会在失败时静默采用备用字体，因此不能用它证明用户所选文件有效。内存接口复制字体字节，应用释放临时字节不会影响已加载字体。容器检查不替代 SDK 的字形解析。

应用时先加载新字体、更新控件，再比较磁盘设置基线并原子保存。若设置被其他程序改变或写入失败，控件重新绑定原字体并恢复编辑器原滚动位置，原偏好和原设置文件保留；提交成功后才释放旧字体。启动时已保存的字体不可用会明确记录错误并依次尝试系统默认和随包中文字体，不覆盖原设置文件。损坏设置文件同样不被静默覆盖。

固定 SDK 的 CodeEdit.SetFont 不更新曾创建的补全列表。IDE 通过公共补全弹层 getter 更新列表字体，包含已经关闭的复用列表，避免释放字体后留下无效引用。内建查找窗口由 SetFont 自身更新。

## 验收和范围

font_test 在真实 XGE 窗口和运行循环内使用实际 Windows 字体及中文路径，通过真实按钮点击验证草稿取消、默认值、字号和文件校验、应用、保存冲突及长文档滚动回滚、重启读取。覆盖 C/xlang 版本、语言、Unicode 选区和撤销、关闭及新文档、补全列表、帮助重新排版、输出及终端网格。settings_test 验证字体与编译器先后更新不会丢失对方配置及未知字段。

字号使用 96 DIP，界面字体默认 16 DIP，现可从独立的“界面字体…”设置修改；窗口比例变化时渲染代理更新物理字体，逻辑度量保持稳定。窗口、Dock、字体及输入的 DPI 映射已接入并通过 100%–200% 原生注入比例验收；实体跨显示器切换继续验收，详见 [DPI 与界面字体](dpi-and-ui-fonts.md)。文件浏览使用原生 Windows 对话框，实体点击选择路径和不同机器字体仍需设备验收。

诊断版本支持 --font-settings，便于在隔离设置文件下验证设置页。浅色和 900×600 深色原生截图进入完整回归。
