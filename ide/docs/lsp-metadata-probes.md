# LSP 元数据读取与 XRT 错误状态

## 修复边界

可选字段缺失、类型不匹配和有效访问失败需要分别处理。项目已有 `model/metadata_read.h`：缺失或类型不匹配的探测保持当前 XRT 错误，合法类型上的实际访问失败继续传播。本阶段复用这些读取函数，没有增加另一套包装层，也没有在产品代码中清除错误来掩盖失败。

实际 SDK 检查复现了三个问题：快照的 `documents` 被替换为对象后，容器数量检查仍会进入数组访问；诊断跳转中，已验证条目数量与异常原始数组不一致时仍会访问数组；文件回执的时间戳为数值而非字符串时，直接取字符串会设置类型错误。这些失败会污染调用线程的后续 XRT 错误状态。

快照读取和诊断跳转现在先确认数组类型，跳转还核对原始数组下标。回执使用既有对象与字符串探测函数，继续支持原来的 Unix 微秒 schema 1 和公元纪元毫秒 schema 2，不改变换算、六字段形状或有效文件证明的要求。

实测表明，当前 SDK 的空值类型查询、缺失的可选能力，以及已有整数／字符串辅助函数本来就可以安全探测。因此删除了此前尚未提交的重复空值保护和整数包装，引用能力协商保持原实现；不把这些已正常的行为描述为本阶段修复。

## 验证方法

新增 `language_optional_fields_test` 使用真实 SDK、生产读取代码、能力协商和 owner poll，仅替换传输队列以输入确定的 JSON。151 项检查覆盖缺失／空值／错误类型、引用能力的布尔与选项形式、同步能力、有效／异常快照，以及两种时间戳。直接探测同时验证无错误及已存在错误两种起点。合法类型上的访问仍使用 XRT 原函数，未设置忽略访问失败的分支。

自动诊断夹具保留真实语言服务、输入证明和条目路由，在有效通知上替换原始诊断数组，验证拒绝异常数据、保留先前错误，并恢复正常跳转。正常 owner poll 也检查是否意外留下 XRT 错误；此检查的清错只用于隔离测试观测，不进入产品代码。

旧快照读取、旧时间戳读取和旧跳转代码均通过实际 C 编译后的失败对照验证，不能只靠构造 JSON 后检查测试自身。缺失能力的旧实现仍通过，作为保持既有行为的对照。

完整原生重建、真实 stdio 及当前 IDE 全对象重编译的结果和身份，记录在 `dev/release-materials/provenance/lsp-optional-fields-20261109.json`。GUI 执行使用仓库 `release/win_x64` 的真实 DLL 和编译器，开发产物、测试数据和日志放在 `ide/build/Release/lsp-optional-fields-20261109/`。

本轮完整构建为 236 次编译、138 项原生回归和 143 个内部消费者，1,399 项输入／140 项产物一致；九组协议和八项 GUI 专项通过。GUI 固定到已提交的 `6186e26e1` 加本阶段源码，全部 111 个普通对象重编译，未混用旧应用头文件。并行尚未提交的 DPI 优化没有纳入本轮资格。测试程序与候选服务以同一发布目录中的临时名称运行，验证后清除。

## 交付范围

本阶段是元数据正确性修复，不代表完整 LSP 或性能验收完成。没有新的正式性能矩阵，前一阶段的 P95 失败继续保留，不据此宣称性能无回归。默认语言服务和更新通道保持；后续继续小编辑尾延迟、最终 IR 重复工作、其余适用 LSP 与完整 IDE 的整体验收。
