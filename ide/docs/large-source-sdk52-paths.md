# SDK52 集成后的长行路径复测

当前可运行候选仍为 [SDK52 完整 IDE](row-index-integrated-editor.md)。本阶段重新测量其实际源树中的五条路径，确认行级索引之后的剩余开销。诊断 SDK53 不进入便携包，不更换 SDK52 或固定 SDK。

## 首版范围核对

重新读取定版架构、工程格式和实施计划。新版完整标准回归中存在原生布局、三层工程、文档双语法、命令帮助、构建运行、阅读恢复和真实补全证据；对应具体夹具的断言仍是覆盖范围。检查没有把这些功能结果推定为干净设备、实体 IME／混合 DPI、完整 C 项目输入／ABI或整体发行条款通过。独立真实 DAP 是设计中明确的后续阶段。

范围核对：[audit](../build/editor-row-path-trace-scope-audit-v1.json)。首版完成仍未证明，长期目标 active；范围保持原计划。

## 测量方法与功能检查

诊断 source 从实际通过整应用回归的 SDK52 复制 241 份材料，只在 `xui_code_edit.c` 与 `xui_cursor_layout_internal.inc` 添加原函数外的五个 QPC 计时包装及路径标记。原始函数体和唯一的标记改动逐项记录，行级索引、读取有效性、失败回退、字素和布局算法均保留。计时 helper 在记录前后保留 Windows LastError 与 errno。

完整 SDK53 严格构建实际退出 0，用时 263.485 秒；全部 5,954 个导出名称和序号与 SDK52 相同。消费者使用同次构建的公开头、DLL／导入库和原生成 XRT 声明，运行时继续只有 DLL 一份 XRT。

控制版 SDK52 和诊断版 SDK53 都链接当前完整严格构建的同一组 83 个应用对象，使用逐字节相同的原生探针源码及数据。此前五路径实验使用混合工厂对象，本阶段直接使用新版整应用对象。历史 `shared-` 与明确的 `cursor-src_platform_dpi_proxy.c.o` 名称只用于映射到当前对象名；全部当前输入摘要仍核对。

C／xlang 各使用精确 2 MiB 和 16 MiB UTF-8 单行文本，含中文、emoji、组合字符。在自有、未切换的 Windows 桌面与 Job 中完成八个原生进程，360 项功能检查退出 0。四组控制／诊断截图在 1600×1000 RGB 像素上完全相同。文件上限没有降低，语言服务未配置；不据此宣告同尺寸语义分析或实体键盘验收。

第一次链接准备因历史对象别名未识别而退出 1，第二次误要求原探针并未使用的 EXE 资源对象而退出 1，均未调用原生链接或运行探针。修正映射与实际 DLL 资源链接策略后，两个原生链接都退出 0；已成功准备的消费者不重复生成，失败脚本和空阶段目录保留。

范围缓存未直接命中时，三次可视范围查询合计约 0.05 ms；同版本的长行列查询约 0.006 ms。输入／撤销使内容版本变化，仍需一次约 123 ms 的可视列扫描。读取复制约 1–3 ms，布局更新的整段公共前缀为 16,777,216 字节，约 33 ms。冷布局约 643–661 ms，已包含在冷绘制约 1,219–1,250 ms 中。

当前暖绘制仍约 576–597 ms。已检查 SDK52 的 `__xuiCodeEditRenderStyledLine`：即使可视字节范围很窄，已有 layout 的分段分支仍将整段 `pLayout->sText + pSegment->iStart`、长度 `pSegment->iEnd - pSegment->iStart` 交给 `drawTextSpans`。当前无 Tab 的长行是一个完整分段。此处是下一步细分测量／优化的入口；本记录不把整个父调用耗时直接归为某一个未计时的内部函数。

因此下一步从已有布局到 spans 绘制的边界推进，验证是否能利用现有字素／整形上下文跳过屏幕外处理，同时保留字体回退、SVG 溢出、全行度量、裁剪、选择与错误回退。不会继续用已经很小的范围查询耗时解释剩余暖帧，也不复制 SDK49 的未选用 Atlas 小缓存。

记录 I/O、嵌套调用和背景负载都影响数字；每用例一次观测，无整体百分比／统计性能通过声明。诊断不是新的可用发行版。
