# 混合编辑的文件监视器暂停握手

M7b5g，2026-11-12。[混合文档事务](lsp-edit-mixed-transaction.md)需要在写入关闭文件前，协调普通磁盘读者和已经缓存的正文。本阶段把现有 IOCP 监视器接入显式、异步的暂停/恢复握手，并让 FileSync 拒绝旧缓存回流。它是完整宿主屏障的一个参与者，不暂停语言服务、任务、索引器或预准备打开操作；标准重命名入口仍未启用。

`xideFileWatchSuspend` 发布一个新的空订阅 epoch，立即禁止旧事件 Take 和普通订阅替换。请求不等待工作线程，不遍历或释放正文队列，也不在所有者上释放被替换的待处理订阅。旧的待处理元数据只转移所有权。已有 epoch 检查及 `CancelSynchronousIo` 使旧扫描停止；工作线程依照原有 IOCP 生命周期关闭目录订阅、退出读取、退役旧批次和完整旧事件队列，最后才发布 readyEpoch。

调用方轮询 `xideFileWatchSuspended(watch, token)`，不能把“已请求”当作“已停止”。令牌只属于当前 monitor 实例的存活期。恢复必须提供准确且已确认的令牌及新的完整订阅集合；错误、重复、过期、未确认的恢复和分配失败都保留暂停状态。恢复后强制重新扫描当前目标，启用 xlang 源码通知时还发送保守的覆盖失效提示，包含暂停期间可能创建或删除的未登记名字。它不把这些名字自动加入项目。

请求只修改固定大小状态、转移批次及发布控制通知，常规 API 的互斥锁竞争和系统调用成本仍存在，不宣称硬实时上界。队列中最多 128 MiB 正文的实际释放、待处理批次的元数据遍历和目录取消完成均在工作线程上进行。整个暂停期间 worker 可以处理空 epoch 的控制消息，不能启动新的目标正文读取。

FileSync 的 `Suspend / Suspended / Resume` 在所有者线程配对调用。等待和持有期间，自动协调轮询、重新绑定、人工重载/保留和 before-save 准入均暂停；普通键入、撤销和阅读仍可继续。before-save 对 C/xlang 普通文件及显式覆盖标志同样生效。Stop 仍按既有生命周期释放服务；调用方必须取消其外部操作，不得把令牌用于新的服务实例。

恢复通过现有订阅构造器重新建立完整目标，失败保留旧模型、旧订阅记录和持有状态。旧的 `file_change` 正文可以继续作为只读展示材料保留，但 epoch 置零；自动协调、人工重载及保留均拒绝它。随后普通重订阅也不能恢复其权限，只有监视器的新读取结果才能更新或清除该行。这样既不在请求路径批量释放缓存正文，也不会让窗口关闭、打开其他文件或模型重绑定重新授权旧快照。

测试使用真实后台 ReadFile 的阻塞点。暂停请求在该读取仍被夹具持有时返回，确认状态必须为假；释放读取后才允许确认。探针检查请求线程零次直接 malloc/free，记录原始队列正文确实由工作线程释放，以及 128 个旧待处理路径在工作线程退役。覆盖准确令牌、持有期间拒绝 Take/替换、错误恢复、暂停期间创建源码、恢复后 fresh 正文及覆盖失效、持有中销毁和 Win32 句柄平衡。

真实 XUI/FileSync 集成测试先产生一份待处理外部正文，暂停期间保留 C 编辑器原文并允许 xlang 输入/撤销。恢复时再次阻塞监视器，确保新正文尚不可用，再尝试旧行重载、保留、自动轮询和打开另一个文档后的重新绑定；均不能应用旧正文。释放读取后，只应用实际最新磁盘正文。另检查恢复分配失败的持有、before-save 拒绝和带租约的关闭流程。

这些检查不建立整体 IDE 延迟、完整来源/物理别名政策、任务或 LSP 静默期，也不代替用户确认或启动恢复写回。匹配 SDK、具体检查结果、实现变异和大材料索引见 `dev/release-materials/provenance/lsp-edit-watch-20261112.json`。
