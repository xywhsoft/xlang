# 限定类型名称的原生区间

`Box::<dep.Marker>` 的原生 TypeId 已正确指向 Marker，但 `xl6PQualifiedType` 创建类型节点时只保存首个 token 的区间，导致导航末端名称没有结果，引用也可能只覆盖 `dep`。现在在该原生创建函数释放后半段名称节点前，调用现有 `xl6AstRangeInclude` 合并前缀 token 与后半段 `import_name` 的原生归约区间。多段名称、空白及 Unicode 的终点均来自同一解析器，不按名称长度、推断类型或全文搜索补造区间。

适配器检查原生生成文件与对应 grammar 中的创建函数完全一致，并要求原有归约区间栈存在。只修改一个已审核位置；移除新增语句会精确还原原生成文件。共享引擎源码、语法规则、解析表、AST 布局和原有分配路径均保留。构建工具在现有解析器栈所有权适配之后生成实际编译的 C 文件，记录来源、grammar、派生文件与消费者摘要，为后续合并到共同前端保留明确位置。

这增加一次限定类型创建时的固定成本区间合并调用，没有新增分配、源文本扫描、类型查找、AST 遍历或查询期缓存。既有名称区间字段和索引记录直接使用完整终点；UTF-8 字节偏移与 UTF-16 位置继续由原转换器分别处理。普通源码名称的长度仍计入现有导航预算，不把整个进程的分配或时延据此宣称为零。

修复后，限定类型实参可从末端名称定位，完整引用与高亮区间保留限定前缀，重命名名称投影只取末端 IDENT。外层泛型类与实参类型仍使用各自原生声明身份，不互相重定向。

原解析器对照覆盖 13 组用例，包括普通/多段/带空白/Unicode/CRLF 名称、可空类型、固定数组参数、嵌套泛型和错误代码。9 个限定名称中修正 7 个原前缀区间；已正确的区间保持一致。原成功/失败结果、诊断、完整原生非坐标语义键，以及正规化这项预期差异后的所有节点坐标相同。原解析路径中观测到的 malloc/calloc/realloc/free 调用次数逐例相同。固定数组类型实参在当前语法中仍被原样拒绝，未借此修改语言规则。

增量专项执行六次构建与六次热命中，实际发生五次函数片段解析、十次声明复用，覆盖插入 emoji、限定名称空白、更换类型、错误代码及恢复。每次对比独立全量检查的完整索引与 IR，并在会话销毁后读取原持有结果，验证旧区间与身份没有被修改。

本项补齐上一阶段发现的限定类型实参范围缺口。完整符号族闭包、可写性/外部符号策略、重命名冲突与改名后绑定证明、版本化编辑及 IDE 事务，以及全目标性能与规模验收仍须继续，尚未开放 `renameProvider`。

最终通过 172 个原生夹具、11 套协议与 28 个 IDE 夹具；范围/增量专项 3,019 项、泛型导航专项 2,304 项检查通过。遗漏区间、只更新字节终点以及误用后半段首 token 的三个实际解析器/core 变体均被拒绝，三类未知派生位置也被拒绝。资格检查绑定 280 个消费者、173 个程序及 core 全部成员。IDE 完整重编译 116 个对象，配对同一语言服务及匹配 SDK；C/xlang 输入、删除、撤销、Unicode/IME、焦点与相关语言功能通过，浅色、深色和限定类型引用窗格已复核。默认发布程序未替换，未做全目标性能准入或线上推送。材料索引为 `dev/release-materials/provenance/lsp-qualified-type-ranges-20261110.json`。
