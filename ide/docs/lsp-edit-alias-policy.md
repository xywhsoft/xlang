# 混合编辑的完整命名模型与物理别名策略

M7b5q，2026-11-12。`platform/workspace_edit_aliases` 将编辑目标、全部已命名打开模型以及宿主明确给出的受保护路径放入同一物理身份检查。`editor/workspace_edit_transaction` 已实际使用这个门；标准重命名与 `workspace/applyEdit` 仍等待完整事务宿主和其他策略。

## 目标与身份

工作线程构造门时只借用计划、模型 ID/路径和保护路径，返回后只持有独立路径、句柄和物理元数据，不保留计划正文、DOM、store、widget 或 context。模型清单必须包含所有已命名打开文档，包括未编辑的 C 或 xlang 文件。打开目标须匹配原模型 ID 和路径；关闭目标不能同时是已打开模型。重复模型 ID 或词法路径拒绝。

目标仍遵循已有关闭文件门的本地固定磁盘、普通路径和单链接策略。打开目标允许只读文件和缺失文件；不把文件只读属性传成编辑器只读。目标的重解析点及重解析祖先拒绝。未编辑模型可以通过别名读取身份，但只要一个物理重复组涉及编辑目标，就拒绝整个计划。

保护文件按物理身份排除。保护目录既排除词法后代，也与目标的全部祖先比较物理身份，因此不同盘符或卷名拼写不会绕过保护。缺失模型、覆盖文件和保护路径作为明确的缺失声明保留；后续出现对象同样使检查失败，不能略过或自动重捕获为新基线。

已有路径和目标祖先用带读取权限、允许读写共享但不允许删除共享的句柄固定。仅属性权限的句柄在本机没有阻止目录改名，已由实际失败用例确认并修正。这里没有 ReadFile 正文读取或哈希；读取权限用于实际名称固定。既有字节锁、原始/规范化摘要和 UI 正文修订检查仍由原来的模块承担。内容变化本身不使本物理身份门失效，专项用实际原位写入验证这一边界。

共享的 `workspace_edit_physical_internal.h` 提取原有普通对象、身份和本地路径规则；关闭文件门继续使用原来的可写与单链接条件。没有另写 SHA、路径解析器或内存容器，数组和对象复用 XRT；原生路径缓冲区继续遵守原有 CRT 所有权。

## 实际事务消费链

Prepare 默认保护本次专用恢复目录。宿主可在尚未附加 UI ticket 时，通过 `xideEditTransactionProtect` 一次性复制额外保护路径；一次调用失败不保留成功前缀。运行目录、配置、项目缓存等仍须由完整宿主明确提供，不能把默认恢复目录说成完整保护集。

Capture 在 UI 上仅复制全部已命名打开模型的 ID 和路径；Arm/Publish 在宿主回调前后重复核对完整清单。打开无关文件、关闭、改名或重开模型同样撤销这个基线。模型存储仍由调用方保证生命周期，工作线程不访问它。

Stage 先准备完整恢复包及固定关闭来源，再构造全组物理门，随后才构造写入器、取得字节锁和建立日志。专用恢复目录此时已由 Spool 创建，不会把本次合法创建误判成缺失声明失效。Apply 在写入前和整组写入后重新检查物理门；每个文件仍使用原有不透明固定句柄写入器及必需的宿主策略。

物理策略失败会拒绝或恢复整个组。恢复已写入文件不依赖旧请求仍有效，也不要求变化后的无关模型或保护路径重新有效；它通过本次固定写入器恢复原字节。GUI 已提交后，后续错误不改变 committed，也不会回滚磁盘。门在工作线程退役时释放，不通过 UI 析构隐式写回。

## 准入与成本

最多 512 个目标、4,096 个命名模型、256 个保护路径、32,768 个祖先候选及 4,096 个去重祖先。门保留的原生路径最多 8 MiB，已知对象/数组/路径存储最多 16 MiB，另有固定 32 KiB ID 排序栈及分配器、系统句柄和内核成本。混合事务增加 16 MiB 保守预留；UI 模型元数据最多 1 MiB，额外保护路径计费贯穿 Stage，失败 Capture 恢复原计费状态。

模型及文件身份排序和保护范围比较在工作阶段执行。UI 清单复核会扫描受限的模型与路径元数据，不扫描正文；普通键入、增量分析和常规 IDE 启动没有新增此门的调用。这些上限不是 RSS、峰值、文件系统 I/O 或硬实时保证。

句柄固定及重复检查不构成全局文件系统事务。映射写入、过滤驱动和最后一次工作线程检查之后的外部变更仍有既有边界；完整宿主仍需来源闭包、解析候选、请求/连接/项目/配置、所有读者、用户确认及恢复协调，不能凭这个门单独写源码。

## 验证与证据

`workspace_edit_aliases_test` 使用实际 NTFS 卷名别名，验证目标与未编辑模型、保护文件及不同拼写保护目录的物理冲突。覆盖只读/缺失覆盖、硬链接、目录改名/删除拒绝、缺失声明、4,096 模型边界、18 个可观测直接分配拒绝、30 个取消边界，以及逐次失败的句柄平衡。没有把 DLL 内部数组增长或整个 XRT 堆说成已做分配故障覆盖。

混合事务专项覆盖新增无关命名模型的 Arm/Publish 拒绝、额外保护目录拒绝，并继续验证真正的工作线程、C/xlang 整组发布、纯打开/纯关闭形态、部分写入、逆序恢复、输入及阅读状态变化、回调重入、context 关闭和 committed 后错误。关闭文件门的原有专项单独运行。

初始测试错误地使用原子替换辅助函数来改变被固定文件的内容；名称固定正应拒绝这个替换，故改成原位写入。另用独立 SDK 对照观察到既有文件原子替换的进程句柄数先增加 8、再增加 1，随后三次稳定；原始逐段记录证明本门每次销毁回到基线。未将该辅助调用的冷启动成本计为物理门泄漏，也不据此声称整个 IDE 无额外资源成本。

三个专项中，前两个的实际通过回执来自 focused-v6；该批最后一个关闭文件夹具要求新目录，批脚本预创建目录导致其在进入门前失败，修正目录参数后单独补跑。原回执保持失败状态，最终资格明确组合实际执行记录，不冒称整批重跑。原始构建、失败测试和 SDK 对照均保留。
