# XUI 的预备批量文档发布

后续 [M7b4x 工作线程准备](lsp-xui-batch-worker.md)已拆分 Capture/Describe、Stage 和 Accept，新增宿主提交围栏与模型发布钩子。本文保留第一版阶段记录；其所有者线程 Prepare 成本及三个导出的描述只对应该历史阶段。

M7b4w，2026-11-11。XUI 新增 `xuiCodeDocumentBatchPrepare/Commit/Destroy`。实现位于 XGE 的 Document 生产者，IDE 不复制其私有结构，也不使用“逐文件修改，失败再 Undo”来模拟原子应用。上游提交和精确匹配的 SDK/消费者身份记录在阶段材料索引中。

Prepare 接收每个文档的 before/after LF UTF-8 视图及精确内容变更版本。先取得全部文档调用保护，拒绝重复文档、嵌套编辑、版本/正文失配、无效 UTF-8、NUL/CR 与额度超限，再准备替换缓冲、完整行索引、可直接读取的快照、一个完整撤销组和撤销表容量。原有正文、版本、脏标记及历史不改变；输入不在调用结束后借用。每一行通过 XUI 原有弱生命周期观察失效，不因准备对象延长控件/文档所有权。

Commit 为单次尝试。它先固定全部文档，再运行所有预编辑观察者，最后复核整组状态；后面的观察者关闭先前检查过的文档，也会使整组拒绝。全部检查成功后，无分配、无用户回调地切换所有文档的正文、索引和撤销记录，随后才发出编辑/变更通知。第一个通知可以读取全部新正文；重入修改参与文档、重入提交或销毁批次均返回 BUSY。

`committed` 输出必须独立于返回码处理：false 表示本批次未发布任何载荷，true 表示全部载荷已发布，包括空/无变化批次。通知或退出清理可以在发布后失败，不能把错误返回解释为“可以再应用一次”。真实 Context 的检查式关闭在操作内先返回 DEFERRED 且不消费所有者；调用方在操作结束后按现有合同重试关闭。裸 Document 的延后销毁与发布后错误也单独验证。

每个改变文档获得一次独立撤销，早先的撤销项保留，普通新编辑语义清空重做；不建立跨文档全局撤销。未变化的文档保持版本和历史。文档身份/64 位状态与 next-state、32 位版本、撤销数量和生命周期共同复核，不能仅凭一次正文长度或折返后的版本接受过期批次。

最多 512 个文档、每正文 8 MiB、before/after 分别合计 64 MiB；默认/最大已知暂存额度 128/256 MiB。缓冲、快照、完整行表、撤销表及撤销字符串均提前计入。分配器、输入及观察者/缓存成本额外；不是 RSS 或延迟保证。before 复制到撤销字符串，after 分别保存在缓冲、快照和撤销字符串中，不能称零复制。

当前 Prepare 在文档所有者线程扫描/复制正文并生成行索引。工作线程载荷预构建、UI 绑定成本及真实大规模交互延迟仍需后续性能准入；“提交核心不分配”不能代替这些验收。现有普通输入/分析路径没有接入新构造器，也未给既有 Document 增加字段、缓存或额外遍历。

预编辑观察者可以清理可重建的派生缓存，准备失败不承诺缓存字节完全相同。批量发布对 Document 观察者表现为各文件的一次全文替换。IDE 仍需映射光标/选区及其他范围状态，联合检查打开/关闭文件的物理别名、64 位 IDE 修订、请求/连接/配置/项目代次、注释批准，并实现磁盘写入及恢复。该原语不是完整 IDE WorkspaceEdit 事务，`renameProvider` 和 `workspace/applyEdit` 继续关闭。

`ide/tools/xge_document_batch_overlay.py` 及其 `.inc` 仅为固定历史 IDE SDK 来源派生同一上游实现的兼容材料。XGE 当前 Document 生产者与匹配 SDK 的生产者正文完全相同；当前上游生产者另经严格编译，但没有冒称完整当前上游 SDK/发行验收。SDK 导入器只在头文件实际提供接口时登记三个必需导出。

匹配 IDE 配置完整重编 173 个 SDK 单元，Document 单元按最终精确编译选项加 Werror 后的对象与实际生产对象逐字节相同；沿用 SDK 既有常规告警配置，不声称全部第三方/SDK 代码通过 Werror。公开接口比较保留 8,724 个既有声明及打包指令，仅增加两个类型声明和三个函数；PE 只增加三个导出，DLL 依赖保持，受保护运行程序的 XGE 导入均可解析。这是限定的源码/名称兼容检查，不是完整二进制 ABI 或发布准入。

专项通过 677 项检查和 16 个独立进程冷态分配拒绝点，验证精确额度边界、先前撤销/重做、空/删除/Unicode/行索引、512 文档、同长度过期正文、错误线程、弱生命周期、前后观察者关闭及重入。原有文档回归分别用原生产者和新生产者验证；测试消费其预期失败的文件删除所留下的 XRT 错误，原断言保持。未适配的原/新生产者均返回 CALLBACK_FAILED 但已完成下一次插入的对照记录保留，不能把这类返回码当作未修改证明。

六个实际变异破坏整组最终围栏、版本/状态围栏、通知顺序、先前撤销项、重做清理和 committed 输出，均在预期断言处被检出。真实 DLL/CodeEdit 专项通过 32 项缓存/渲染、C/xlang、Unicode、撤销和 Context 关闭检查；匹配新 SDK 重编全部 118 个 IDE 对象后，33 项 GUI/配置回归通过。新增最终围栏用例只改变未被 GUI 产品依赖引用的专项测试；最终程序、原成功前缀和适配后的旧测试分别记录。
