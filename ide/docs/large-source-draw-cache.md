# 长文本绘制结果复用实验

2026-10-10，SDK23 在物理绘制字体这一层保留一份长文本字形结果，减少相同文本重复绘制时的整形。严格构建、绘制像素对照、相关回归、16 组原生文件测试和落盘重放通过。16 MiB 单行的重绘观察有所改善，但编辑仍有约两秒停顿，保留整行数组明显增加内存。本版不选入当前应用，性能未验收。

上一轮见[可见范围两份结果](large-source-viewport-pair.md)。SDK23 基于 SDK21，相对其 237 个源材料只修改 `src/xge_emoji.c` 和 `src/xui_proxy_xge.c`，不包含未采用的 SDK19 度量补丁。公开头保持一致。

## 为什么放在绘制代理

XUI 的 `xui_text_shape_t` 保存布局簇和度量，代理在提取这些信息后已经释放完整 `xge_glyph_run_t`，因此它不是可直接绘制的字形对象。IDE 的 DPI 代理还分别持有逻辑布局字体和物理绘制字体，不能直接拿逻辑字体的布局结果替代物理字体绘制。

SDK21 的两次已结束、已核对进程身份的原生栈观察分别落在字形绘制和 Emoji／整形调用中；它们用于定位，不计入本轮基准，也不能证明各调用占用的总时间比例。

## 缓存与释放

Windows IDE profile 的原始 XGE 代理仅保留一项绘制结果，适用于 4,096 字节至 16 MiB 的 `drawTextSpans` 输入。键包含实际 `xui_font` 实例、文本长度、精确的自有字节副本和已经加载的内置默认 Emoji 包身份。完整字形结果通过结构体移动接管，没有再复制一份字形数组；自有文本副本用于识别同一指针上的原地修改。

字体、正文或串行默认包状态不匹配时，先释放旧的长结果，再执行原来的整形。短文本仍走原路径，不逐个挤掉长文本结果。超过上限的长输入释放旧结果并走原路径。缓存文本分配失败时，仍绘制并释放本次临时结果；整形失败不保留结果，后续调用可以重试。

内置 Emoji 包禁止公开注册，适合串行状态下的复用。自定义默认包和未加载的默认状态不缓存，也不会为了判断资格主动加载内置包。首次整形若触发了内置加载，本次先走原路径，后续调用才可保留结果；因此没有改变加载失败后的重试路径。键持有自己的包引用，避免缓存身份指针随默认引用释放而失效。

在大文本 `textShape`／`textMeasure` 之前，全局绘制缓存先释放，避免旧的物理字形数组和新的逻辑整形数组同时保留。短文本测量不清除长缓存。匹配字体销毁时，先释放引用其内嵌主字体／回退字体的字形 backend，再释放字体 wrapper；其他字体销毁不清除此项结果。

SRW 锁保护私有缓存的访问和释放。该锁不覆盖 SDK 的字体、渲染和设置 API，也不构成整个 SDK 的线程安全保证。本轮只验证默认 Emoji 包的串行切换；前后包身份相同不能排除整形期间其他线程先切换为自定义包再切回的情况。后续推广前须使用稳定的整形包快照或变更代数并补充此类检查。

非 Windows／非 IDE profile 保持原绘制路径。新增 Emoji 资格函数只在内部链接，实测 DLL 的 5,949 个导出名称及序号与 SDK21 一致；这仍不是完整 ABI 验收。

## 实际对照

首版夹具严格编译退出 0，原生／控制器退出 1：它把非法 UTF-8 的旧、新一致错误返回也当成失败。本版保留原程序和日志，第二版对失败输入比较错误和无绘制结果，对成功输入比较实际像素。整形和缓存分配的受控失败只放在提取后的诊断代码中，没有加入 SDK 钩子。

第二版原生运行退出 0，完成 787,058 项断言、305 组成功像素比较、48 组相同错误返回和 144 次不再次整形的长结果复用。落盘入口随后在新目录严格编译、运行，增加两个存活物理字体之间的直接切换和新路径首次触发默认包加载，退出 0，完成 803,481 项断言、307 组成功像素比较、48 组错误比较、144 次复用，缓存路径整形计数为 125。两次测试内容不同，不要求计数或日志哈希相同。

对照采用 SDK21 的原始绘制函数与 SDK23 的实际私有代理结构和函数，调用实际完整引擎。每个比较程序仅有一个 XRT 所有者，不链接 SDK DLL。覆盖四种物理字体大小、中文／组合字符／Emoji／ZWJ、RTL／Indic 字节输入、CRLF／Tab、嵌入 NUL、非法 UTF-8、4,095／4,096 边界、不同颜色／位置及 0／3／20 个重叠 span。已加入有实际字形像素的检查，避免两个空画面造成虚假一致。结果仅证明原渲染路径的等价性，不代表新增复杂文字排版能力。

还检查原地修改、文本精确副本、字形数组直接接管、短绘制和短测量、长布局／测量前失效、默认包串行切换和自定义包重新注册、分配失败后的原绘制回退、整形失败后重试、匹配／不匹配字体销毁和引用恢复。超过 16 MiB 的预分配失效检查使用注入整形失败，没有在该夹具中实际申请更大的字形数组。

SDK23 整套严格冷构建使用 `-O2 -Wall -Wextra -Werror` 和既有三项警告排除，实际退出 0，耗时 134.750 秒。原始 SDK 的 Unicode／Emoji／文档三个测试，以及现有 IDE 的 `document`、`editor_view`、`goto_view`、`find_view`、`input`、`reading` 六个程序，在独立目录加载实验 DLL，均退出 0。本轮应用没有重新编译，没有执行完整标准回归、便携验收或实体 IME 验收。

## 实际窗口观察与内存代价

相同的 83 个当前核心对象：参考程序使用已经保存的 SDK21 链接产物，新程序严格链接 SDK23。两者在本轮重新测量：旧／新 × C／xlang × 2／16 MiB × 多行／单行共 16 次原生运行，各完成 43 项检查，总计 688 项。使用未切换到前台的私有桌面、1600 × 1000 窗口、1.25 DPI 覆盖和 2 GiB 私有提交限制，未配置语言服务。

| --- | ---: | ---: | ---: | ---: |
| 重绘候选空闲帧中位数 ms | 1505.430 | 439.805 | 1507.633 | 456.351 |
| 插入 ms | 2075.378 | 2254.553 | 2021.996 | 2238.382 |

| 整个观察程序耗时 s | 29.875 | 19.328 | 29.610 | 22.093 |

“重绘候选”取每次运行 12 个空闲帧中大于 20 ms 的样本：SDK21 C／xlang 各 6 个，SDK23 C 为 6 个、xlang 为 10 个。其余样本含未触发绘制的帧，不能当作重绘耗时。2 MiB C 新版没有大于阈值的样本，记录为缺失值，不能写成零毫秒。

这些是同一主机每组一次的观察，没有隔离后台负载。采样私有内存不是峰值提交，峰值工作集也不是私有提交。全部通过 2 GiB 限制只能说明本次输入在该限制下运行成功。

重绘下降符合复用整形的作用，但输入和最大编辑帧没有相应改善；保留完整数组让 16 MiB 单行的采样私有内存增加约 640 MiB。这个代价目前不接受。实际绘制函数仍先准备字形 atlas 并逐个访问整行字形，屏幕外裁剪不能消除整行遍历。下一步应减少屏幕外字形访问，并缩小保留范围；需保持浮点笔位置、字形 overhang、Emoji 回退和裁剪像素等价，不能直接删除屏幕外字形后继续按原 advance 累加。
