# 点位导航生产的归因

M7a2b126r，2026-11-10。本阶段只扩展诊断工具，补齐快照路径中此前没有单独计时的导航生产及清理。正常语言服务、IDE、分析规则和缓存容量均不改变；前阶段 39/40 的性能失败与整体性能门槛保持。

`build_lsp_lifecycle_profile.py` 在实际 `xideLanguageSnapshotRun` 中记录导航捕获、绑定、点位准备及释放，在实际 `preparePoints` 中记录键生成、查询、`nativePointsCreate` 和发布。使用原有线程嵌套计时框架，没有增加生产计时或隐藏后台开关。所选十个对象、实际依赖、23 个链接对象和 66 个归档成员仍按原构建身份核对。

私有探针重编十个对象，四个原生回归重新链接并运行，包含原始 IR 复用、检查会话、worker 缓存及导航缓存／点位边界。链接实际替换三个 host 对象与核心，而不是仅使用旧 host。正常／探针默认后台开启，四类 512 函数案例、各两对且逐链运行，共 16 个进程、240 次请求；逐次比对完整分析事实，保留 360 帧并检查线程、序号、计数及有限非负计时。落盘工具与执行过的私有工具字节完全相同；没有重建或安装正常图像。

下表为各类全部快照帧的包含子调用时间中位数。每类 30 个快照样本包含冷启动、首次修改、热修改及完全相同请求；`nativePointsCreate` 每类有 28 个实际构造样本，两个完全相同请求复用原点位视图。

这组数据定位了仍在同步快照路径上运行的生产工作。宿主非独占、插桩会扰动执行，各组存在嵌套；没有将快照帧逐个绑定到请求，也没有将表中中位数相减、相加为 CPU、热请求延迟或提速收益。它不能重新判定任何失败的性能筛选。清理当前快照 graph 的中位数不足 0.021 ms，不能据此判断整个模型或投影退休成本很小。

后续优先评估不可变点位资产的增量复用，保留全部事实／范围／Unicode 坐标核验、内存额度、原生 owner、失效与退休规则；单纯跳过验证或推迟到用户首次悬浮不构成完成。语义／IR 的整份生产也仍需继续减少。完整 LSP、错误恢复、静态检查、编辑态补全和最终发行继续推进，不加入 DAP 或运行／调试补全。
