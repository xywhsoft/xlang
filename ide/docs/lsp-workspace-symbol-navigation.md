# 工作空间符号的安全导航接口

2026-11-09，M7a2b126g。为 IDE 搜索的下一步接入补齐所选符号的来源证明。标准 `workspace/symbol` 结果不改变；原生后端另声明实验能力 `workspaceSymbolInputProof`，提供 `xlang/workspaceSymbolNavigation`。不声明标准 workspace symbol resolve，也不把内存索引的代次／序号当作可长期信任的位置。

请求携带原查询、相同的 `xlangLimit`（默认 200）及完整的 `symbol` 行，即原列表里的名称、协商种类、URI、范围和可选父名称。选择行有严格的字段、类型、非空 UTF-8 字符串和递增范围校验；标签最长 262,144 字节。无效输入在启动分析前拒绝。

后台按当前完整项目配置、编辑覆盖和磁盘输入重新执行原查询。只有新的结果中仍存在完全相同的行，才根据该结果的实际拥有者和完整语义上下文找到输入守卫。名称、种类、父名称、路径或位置变化均不能直接导航；查询条件已经不同或目标不在当前有界结果中，也不会回退到旧列表。

随后仅读取选中的一份来源：磁盘来源复用 `xideLanguageReadDiskProof`，核对实际句柄／名称身份、时间、原始及去 BOM 摘要和编码；编辑覆盖使用本次已通过完整输入历史与内容摘要守卫的不可变文本。两者均复用 `xideLanguageReferenceDocument` 生成现有引用功能使用的文件证明，包括换行归一化长度和 XRT SHA-256，或完整 int32 编辑版本。不会往常驻声明索引中加入源码正文、AST 或 IR。

返回对象只有 `symbol` 和 `document`。相同声明在函数体等非位置内容变化后可以继续导航，但返回的是重新验证的内容证明。所有结果构造、选中源码读取、归一化和摘要工作都在后台协调器上；所有语义输入在返回前再次验证，stdio 宿主继续执行排队输入、配置代次和取消守卫。新方法与普通查询共用 8 个请求槽、原有上下文／正文／索引额度及精确 JSON 帧限制。

调用方仍须在应用结果时核对当前打开文档、配置和输入状态，并验证目标文本；来源证明不等于永久导航许可。本阶段完成服务端接口，尚未增加 IDE 搜索窗口或替换现有跳转实现。下一步将使用现有语言服务连接、后台同步规划器和 XUI window，接通零打开文件的搜索及点击／键盘选择；结果解码、正文核对和大对象退休也应离开界面线程。

实际核对全部 247 个既有编译单元的 GCC 头文件依赖闭包，重编译 6 个受影响消费者及 1 个新夹具，重新链接并执行 31 项原生测试；117 项未改产物及 147 个私有 AST 消费者身份保持，汇总为 148 项原生记录。普通生产 API 新用例 34 项，编码／选择行校验用例 234 项。8 套受影响／新增协议检查、11 类导航场景和两个实际 C 保护遗漏反例通过。IDE 的 113 个对象按匹配 SDK／DLL 重新编译，9 项真实服务 GUI 及 1 项受控旧能力兼容回归通过；这是既有 IDE 功能回归，不代表搜索窗口已完成。

验证与精确来源见 `dev/release-materials/provenance/lsp-workspace-symbol-navigation-20261109.json`。首次测试中的整数比较警告、路径分隔符断言错误、CLI 夹具误带原生分析配置，以及被 SDK 所属目录保护拒绝的旧快照跨目录链接均保留；它们不计为通过。首轮旧能力夹具的构建助手选中了历史编译对象，九项真实服务 GUI 已过而旧能力测试正确拒绝；改为最新对象后单独重建该夹具，GUI 回归全部通过，生产程序未改变。既有正式性能矩阵不重跑、不放宽，本阶段不作全链路性能准入声明，默认发布程序保持。
