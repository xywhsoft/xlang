# WorkspaceEdit 混合文档事务

M7b5f，2026-11-11。`editor/workspace_edit_transaction` 连接已打开文档的 XUI 批量发布、关闭文件的固定句柄写入和追加式事务日志。它是可复用的协调模块；标准重命名和 `workspace/applyEdit` 入口仍关闭，尚未连接生产请求控制器、整组来源/物理别名策略、注释确认和启动恢复界面。

## 线程与所有权

调用方按以下顺序切换工作线程与 UI 所有者线程，步骤之间必须同步；除原子 `Cancel` 外，操作、查询和销毁不能并发。

| 阶段 | 线程 | 行为 |
| --- | --- | --- |
| Prepare | 工作线程 | 保留完整不可变计划，筛选打开成员，复制索引与路径元数据 |
| Capture | UI | 捕获实际文档身份、修订号、基线租约和阅读状态，检查关闭目标没有已打开模型 |
| Stage | 工作线程 | 准备 XUI 正文、完整恢复包及全部磁盘写入器，再取得源码读取锁并建立日志 |
| Arm | UI | 宿主前置策略检查，随后重复本地模型及阅读状态检查 |
| Apply | 工作线程 | 整组宿主策略、逐文件持久化意图、应用与结果验证，最后持久化 publishing |
| Publish | UI | 再次执行宿主及本地检查，整组发布已打开模型，记录明确的 committed 结果 |
| Finish | 工作线程 | 已提交则确认日志；明确未提交则逆序恢复关闭文件 |

Work 不保存 store、ticket、widget、context 指针。UI ticket 借用 Work；store 存储必须比 ticket 活得久，即使 context 被关闭。ticket 的 context 生命周期通知只设置原子取消，不在通知中执行文件 I/O。工作线程先完成最后一次操作，UI 销毁 ticket，再由工作线程退役 Work。销毁不隐式应用或回滚源码。

`xideWorkspaceEditSelect` 只复制选中成员的 URI、路径、编辑和被引用注释元数据，重排局部文档/编辑/注释索引，保留原始 input、ordinal、身份、修订、来源证明和确认要求。before/after 共享原有 `xls_text` 租约，不读取、复制、哈希或重新分析正文，也不通过保留父计划间接保留未选中的大正文。关闭文件基线及未保存编辑器基线仍完整写入恢复包。

## 写入、取消和异常

所有关闭成员的写入器在首次源码写入前构造完毕。磁盘变更依次通过真实写入器，使用原包行号而非筛选后的局部下标。每个实际写入前，先调用必需的工作线程策略，再持久化日志意图；结果来自不透明写入对象。所有关闭成员重新精确验证后才记录 ready、publishing。UI 发布没有日志或磁盘 I/O。

Apply 期间失败、用户取消或宿主拒绝，在日志仍可确认时自动逆序恢复；恢复不会因旧请求已经取消而中断，宿主 RESTORE 策略必须独立允许恢复本次操作。发布前用户继续输入、移动阅读位置、保存、关闭或重新打开文档，会使 UI 检查拒绝；Finish 保留用户的新编辑并恢复关闭文件。ticket 在 ready 后被销毁，明确标记 UI 未发布，仍必须完成 Finish。

必须独立检查 `outcome.committed`。即使发布通知关闭 context，或者后续日志 flush、阅读恢复、文件锁释放失败，只要 GUI 已提交，就绝不回滚关闭文件。日志结果不确定、恢复失败或释放锁失败均报告 needsRecovery；已知 committed/rolledBack 字段不被该错误抹去。日志冻结后不再尝试制造确认或隐式恢复，保留全部恢复资料。调用方必须完成恢复协调后才能恢复受影响读者；重启后的源码写回尚未实现。

## 读者与宿主边界

Stage 使用 `LockFileEx(EXCLUSIVE | FAIL_IMMEDIATELY)` 取得固定源码句柄的整文件字节范围锁，失败立即撤销已取得的前缀，不阻塞等待其他进程。普通、既有及同进程其他句柄不能读取中间状态，自己的固定句柄仍用于验证和写入。完成或成功回滚后释放；销毁 gate 也会关闭残留句柄。此功能只由显式混合事务调用，原有来源固定接口不自动取得字节锁。

字节锁不隔离映射视图或应用内缓存。工作线程宿主策略仍必须覆盖完整来源集合、物理别名、连接/请求/项目/配置时效、注释同意，以及索引器、监视器、工具链、缓存/预准备打开操作的静默期。后续 [M7b5g 文件监视器握手](lsp-edit-file-sync-lease.md)已提供监视线程停止与旧缓存失效这一参与者；完整宿主屏障仍待组合。UI 宿主策略仍为必填；本地检查在回调前后重复，并防止回调重入。没有用固定返回 true 的产品策略或日志代替这些条件。Windows 行为依据 [LockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) 和 [UnlockFileEx](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-unlockfileex)。

## 准入与性能边界

默认 256 MiB、最大 512 MiB 的保守已知存储准入，子模块仍保留各自最大 256 MiB 等约束。初始计划/元数据扣除后的剩余额度一半交给打开文档模块；Stage 后将这整个额度作为预留计入，因为 SDK 不公开暂存正文的精确大小，不能只计捕获/位置映射大小。另计完整计划、筛选计划、Spool 的原始容量与 48 MiB codec 预留、全部磁盘缓冲区、16 MiB source gate 和 1 MiB 日志预留；共享租约可能重复计费。固定数组最多 512 个目标，UI 最多扫描 4,096 个模型的路径元数据。无变化的磁盘 before/encoded 使用同一已验证缓冲区。

这些是保守准入，不是 RSS、峰值内存或响应时限保证。元数据标准化、分配器、操作系统缓存、SDK 阅读恢复仍有额外开销。所有正文准备、哈希、编码和日志/磁盘 I/O 都在工作阶段；没有把本模块接入普通键入或增量分析热路径。完整宿主控制器、压力/延迟验收、持久化恢复、用户确认及最终交付仍需继续完成。

## 验证与材料

真实工作线程依次执行 Prepare、Stage、Apply、Finish，UI 使用真实 XUI/Document 模型发布。覆盖交错的关闭 xlang、打开 C、关闭 xlang、打开 xlang 成员，以及纯关闭/纯打开形态；验证 BOM/EOL、未保存文本、共同模型通知、读取锁与获取失败的前缀撤销、部分写入与逆序恢复、取消、继续输入、宿主拒绝/重入、回调中缓存目标打开、context 关闭、日志冻结和锁释放失败。逐点拒绝可观测的直接 IAT 分配；GUI DLL 内部分配和 GUI 堆统计不在该故障探针范围内。

原生筛选测试另启用并验证真实 XRT 堆统计，观察 8 MiB 未选中正文没有扫描/重建、父计划释放后子计划仍有效，以及构造失败和取消的资源平衡。现有逐文件、Spool、日志和已打开文档回归使用当前生产单元重链；破坏读取隔离、提交结果、重复 UI 检查、逆序恢复和取消后恢复的实现变异必须被实际断言拒绝。精确数量、匹配 SDK 与程序摘要见 `dev/release-materials/provenance/lsp-edit-mixed-20261111.json`，大材料保持在外部开发目录。
