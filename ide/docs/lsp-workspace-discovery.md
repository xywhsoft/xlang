# 后台工作区发现与批量清单解析

M7b6m，2026-11-15。本阶段实现可独立验收的后台发现组件，供下一阶段接入标准服务的工作区加载。它尚未替代 IDE 的显式分析配置，也没有提前宣告自动发现能力；目录、配置和源码的新鲜度仍须在协议结果发布时共同验证。

`services/workspace_discovery` 使用原生 XRT 的一个工作线程和一个排队位置。提交时只保留根快照、复制包路径，目录访问和清单读取都在 worker 执行。复用现有 `.xlw/.xlp` 模型解码器、工程分析上下文工厂与 catalog；不另写项目解析器，不读取源文件正文，不改变工作目录或环境。GUI 的 XGE profile 不需要任务池，组件仅在 compiler-XRT 服务中启用。

发现结果保留不可变目录和清单证据。目录记录排序后的相关名称、类型及 SHA-256，不能用目录时间戳替代成员集合。清单从同一个文件句柄读取原始字节，核对前后身份、长度和时间，再计算原始摘要并解析；BOM 参与摘要。工作区显式引用的外部工程也加载。发布前重新枚举目录、读取清单；身份或字节发生变化即永久失效，恢复旧文件不能复活失效快照。取消不会将快照标记为损坏。源码正文由已有原生分析守卫负责，这些元数据证据不等于完整语义新鲜度或写入许可。

默认上限为 4096 个目录、131072 个枚举项、16 MiB 路径标签和合计 16 MiB 原始清单；清单最多 256 个，分析 catalog 延续 64 个角色、65536 个绑定和 16 MiB 上下文限制。可指定更小限制，后续验证沿用同一限制，超过限制整体失败。DOM、分配器和多个同时持有的快照另占内存，不声称这些限制就是进程 RSS 上限。

默认忽略子目录 `.git/.hg/.svn`、`extlibs`、`node_modules`、`build`、`release`、`release-materials`、`.xlang-ide`、`.xlang-update`、`update_info` 和 `.cache`。显式根与清单引用仍生效。重叠的同一路径根去重；未排除的子目录链接、同一物理目录的不同词法别名，以及不支持的文件类型明确失败，避免悄悄遗漏成员。单独的显式 junction 根只验收元数据读取，未将其称为全部原生语义和路径别名均已支持。

取消是协作式的：文件仍被读取时 future 可以保持 pending。物理 Idle 包含清理和 finalizer，不能以取消请求或 future 状态冒充句柄已关闭。只读结果可保留并交给下一阶段；调用者仍需分别约束根、配置、overlay 修订及发布顺序。

清单解码同时消除了普通文件的两两物理身份探测。解码器使用临时 XRT map 索引显式 ID、精确路径和物理身份，完成后复查身份；不将它变成跨请求文件系统缓存。无法确定物理身份的文件继续执行原有比较策略。缺失路径保留精确字符串规则；显式重复路径、ID 和硬链接仍拒绝，入口、C 源和资源自动加入时复用相同索引。交互式单项模型操作不变。新 options API 提供路径数、标签量、工程数和取消检查，失败时保留调用方原模型。

256 个稳定普通文件的同输入对照中，原实现调用路径比较 32640 次，新实现为 0 次，执行 512 次 stat 和 512 次属性探测。对照在原生 XRT 和匹配 GUI SDK 上分别重编译运行，8 组完整模型/分析上下文结果一致，包括缺失路径、opaque fallback、物理别名和隐式 C/资源成员。该结果证明此场景的探测量下降，不是端到端延迟、所有文件系统或整体性能达标的声明。

验收绑定重新编译的 122 个原生单元、140 个 GUI 单元和 72 个原始核心归档成员。发现测试包含关闭文件的真实原生重命名、Unicode 根、BOM、外部工程、目录增删、原始清单替换、取消与句柄退出、容量限制及 74 个局部失败点。模型测试补充 37 个索引 API 失败点、取消、容量和身份竞争；它们不等于全分配器 OOM 证明。协议和 IDE 回归、实际程序渲染、编译后反例及输入绑定详见材料索引：`dev/release-materials/provenance/lsp-workspace-discovery-20261115.json`。

测试程序仍在根 `release/win_x64` 运行，候选 DLL 与 SDK 严格匹配；因当前默认 DLL 与开发 SDK 不匹配，使用校验后删除的命名别名保护现有运行版本。材料与对象保存在外部 F 盘，仓库只提交源码和小索引。默认程序、SDK、当前交付索引和线上版本未替换。

下一阶段将发现任务接入标准服务状态机，并把成员/清单证据纳入全局结果编码后的发布守卫和分析租约退出屏障，之后才开放自动工作区能力。共享源码捕获、传输等待、完整静态检查与补全、运行资产对齐及整体延迟/RSS/耐久/Linux/sanitizer 验收继续实施；不包含 DAP 或调试态补全。
