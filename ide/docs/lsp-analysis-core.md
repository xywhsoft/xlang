# LSP 常驻分析核心

M3a／M3b 已实现独立 C 分析会话、XRT 后台工作线程和外部 `xlang-ls.exe` 的运行时接入；首个常驻协议查询为结构化折叠范围。补全与诊断的常驻语义后端是下一切片，当前发布目录保持原版本。没有向 `xlc.dll` 添加新代码，也没有新增 DAP 或运行态补全。

## 资产与构建

`tools/build_lsp_core.py` 直接编译指定 xlang 源码目录中的词法器、生成解析器、AST、诊断、补全支持和来源报告模块。语法、词法和 AST 不在 IDE 中复制一份。默认源码目录为仓库的 `demo6`；可明确指定与编译器匹配的不可变源码材料。

```powershell
python -X utf8 -B .\tools\build_lsp_core.py `
  --frontend-root .\build\compiler-c-native-extensions-v1 `
  --output .\build\lsp-next-20261022\core-fresh `
  --cc E:\software\w64devkit\bin\gcc.exe
```

输出目录必须不存在。工具先读取 GCC 实际依赖闭包，记录所有源码／头文件摘要，构建后再次核对，并输出命令、测试记录和 `build-result.json`。新增会话、正文、同步模块和测试使用 `-Wall -Wextra -Werror`；共享前端与单头库采用上游的警告配置，编译日志保留。

所有翻译单元预先包含同一份编译器 `lib/xrt/xrt.h`。`analysis/runtime.c` 是唯一 XRT 实现拥有者；前端的 xruntime 声明继续来自匹配的共享资产。本目标不链接 XGE，也不加载 xlc。产物为 `xlang-analysis-core.a` 及独立验证程序，不能直接链接到由 XGE 拥有 XRT 的 IDE 进程。该归档只包含分析与共享前端；协议、平台与兼容 CLI 服务单独链接到宿主。

增加 `--server` 构建外部宿主，`--skip-tests` 只构建不运行核心检查，`--configuration Debug` 保留调试信息。当前宿主传输／进程适配仍为 Windows；核心构建与宿主平台边界分别记录。IDE 构建脚本已接入该目标：`build_current` 明确传递原工作区的前端材料目录，将原生服务的源码／头文件闭包、输出摘要和构建凭据绑定到整体构建记录。优先选用当前随包编译器的固定源码材料，缺少时选仓库 `demo6`；也可通过 `-FrontendRoot` 显式指定。

IDE 进程仍使用匹配的 XGE/XRT，外部服务通过 `XLS_COMPILER_XRT` 使用编译器 XRT，两个运行时之间只传输 JSON 字节。文本文件层的换行元数据独立于 XUI，编辑器边界用编译期断言核对数值，避免服务链接 GUI 头文件。构建工具核对宿主没有导入 `xge.dll` 或 `xlc.dll`，不允许用 GUI 对象文件与原生分析对象混合链接。

## 会话与快照

`analysis/session.h` 只暴露不透明句柄、正文快照、定长整数和只读诊断视图，不依赖 stdio、XUI 或 IDE 项目模型。调用方先规范化文档键，提供来源路径、文档身份、编辑版本和不可变正文；核心不改变当前目录、不读写文件、不启动编译器进程。

会话用 XRT 哈希表保存文档。更新正文只替换该文档的当前输入，解析在首次查询时发生。后续查询保留解析树；相同内容的新编辑版本继续复用解析结果。不同文档、不同身份和不同来源路径分别管理。身份相同的版本不能倒退，同一版本不能改变正文。容量、编码及版本校验失败保留旧状态。限制由调用方配置，默认 4096 文档、16 MiB／文档、256 MiB 正文总量；这不是 AST 内存上限。

会话由单一 owner 使用。查询返回当前身份／版本／代次及一个需要释放的解析快照引用。快照通过 XRT 原子引用计数拥有正文、来源路径和解析器结果；关闭文档或销毁会话不影响已保留的快照。公开字符串借用快照，最后一个引用释放时在创建方统一销毁。已发布 AST 只读，后续语义阶段不能原地修改它。

解析错误以 `Accepted == 0` 和原生诊断视图返回；不把失败源码解释为成功编译。诊断坐标仍是编译器的一基 Unicode 标量坐标，接入 LSP 时必须转换为协商的位置编码。该切片不执行名称解析、类型检查、导入展开或代码生成。

## 验证与后续

`analysis_session_test` 使用真实共享解析器验证延迟解析、重复查询的实际解析计数、独立文档缓存、同文新版本、身份／路径变化、容量和版本拒绝、快照生命周期、错误结果，以及 500 次函数体编辑；语料中的缓存结果与全新解析的 AST／字面量／范围及诊断逐项对照。既有正文及文档同步测试在同一编译器 XRT 拥有者下重新执行。

2026-10-22，匹配固定编译器材料的 `m3a-core-v3` 构建已通过上述 1,579／1,029／834 项检查；依赖检查确认验证程序没有导入 `xge.dll` 或 `xlc.dll`。摘要与构建记录见 `build/lsp-next-20261022/m3a-result.json`。默认 `demo6` 目录由同一构建工具支持，本阶段的已验收运行使用显式的固定材料目录。

M3b1 增加 `analysis/worker`：用 XRT 单线程任务池拥有整个分析会话，通过 Future 发布只读结果，直接使用 XRT 的有界队列和协作取消。提交时复制路径／身份并保留正文，不复制正文。每次工作使用完整不可变输入集合，先移除关闭文档，再同步当前输入；实际解析与会话中的旧 AST 替换在工作线程执行。外部保留的快照在最后引用释放的线程析构。相同正文的新版本、独立文档缓存和旧快照生命周期沿用会话合同。队列满时拒绝本次提交；目前按任务数限制，排队正文总量及析构时延仍需后续预算验证。

`analysis_worker_test` 验证真实工作线程身份、输入捕获、100 次重复查询的解析计数、跨 Future／工作线程销毁的结果生命周期，以及 20,000 函数文件解析期间的排队、拒绝和取消。取消为协作请求；当前原有解析器尚不能在单次解析内部停止，取消会在进入及离开解析时检查。该限制需在后续容错／增量前端处理中收紧，不能把及时撤销协议回复等同于解析 CPU 已经停止。

## 常驻协议查询

开发服务 0.6 支持 [LSP foldingRange](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/#textDocument_foldingRange)：根据共享 AST 的函数、类、条件、循环等结构返回完整行范围，无需先检查成功，也不调用编译器 CLI。当前只提供结构化范围，不包含注释／导入折叠；解析错误暂返回空列表。结果按开始行／外层优先排序并去重，遵循客户端 `rangeLimit` 提示，服务单次上限为 65,536。

解析与范围收集在工作线程运行，使用 Future Watch 唤醒协议 owner，避免固定轮询延时。回复前检查文档身份、版本和代次；修改、关闭、取消及 shutdown 及时撤销旧请求，晚到结果不发布。取消不代表解析内部 CPU 已停止。读线程退出反复取消同步读取直到线程结束，避免把关闭 stdin 作为退出前提。

实验性 `xlang/analysisStats` 返回最近成功查询的实际解析／命中次数、文档与正文字节数、线程 ID，并附当前队列负载。它用于核实缓存与线程隔离，不代表全工程或语义性能。

后续继续用常驻原生语义后端替换补全／诊断的 CLI 高频路径，再做容错语法与函数边界、声明摘要／导入依赖、语义查询缓存和精确失效。当前改动后的目标文件仍整份解析；这里的缓存复用不能作为函数级增量或语义增量已完成的证明。性能验收继续区分核心查询、stdio 往返和 IDE 显示总时延，见 [长期计划](lsp-development.md)。
