# LSP 常驻分析核心

M3a／M3b 已实现独立 C 分析会话、XRT 后台工作线程和外部 `xlang-ls.exe` 的运行时接入；首个常驻协议查询为结构化折叠范围。M3c 开始接入共享语义前端，当前发布目录保持原版本。没有向 `xlc.dll` 添加新代码，也没有新增 DAP 或运行态补全。

## 资产与构建

`tools/build_lsp_core.py` 直接编译指定 xlang 源码目录中的词法器、生成解析器、AST、诊断、补全支持和来源报告模块。语法、词法和 AST 不在 IDE 中复制一份。默认源码目录为仓库的 `demo6`；可明确指定与编译器匹配的不可变源码材料。

```powershell
python -X utf8 -B .\tools\build_lsp_core.py `
  --frontend-root .\build\compiler-c-native-extensions-v1 `
  --output .\build\lsp-next-20261022\core-fresh `
  --cc E:\software\w64devkit\bin\gcc.exe
```

输出目录必须不存在。工具先读取 GCC 实际依赖闭包，记录所有源码／头文件摘要，构建后再次核对，并输出命令、测试记录和 `build-result.json`。新增会话、正文、同步模块和测试使用 `-Wall -Wextra -Werror`；共享前端与单头库采用上游的警告配置，编译日志保留。

所有翻译单元预先包含同一份编译器 `lib/xrt/xrt.h`。`analysis/runtime.c` 是唯一 XRT 实现拥有者；前端的 xruntime 声明继续来自匹配的共享资产。本目标不链接 XGE，也不加载 xlc。产物为 `xlang-analysis-core.a` 及独立验证程序，不能直接链接到由 XGE 拥有 XRT 的 IDE 进程。该归档只包含分析与共享前端；协议、平台与兼容 CLI 服务单独链接到宿主。

原生 Release 目标在全部翻译单元一致设置 `XRT_EXCLUDE_MEMORY_DEBUG`，保留 `XRT_MODULE_ALL` 及分析、容器、任务池、所有权等功能；Debug 目标保留内存调试构建。`XRT_MODULE_ALL` 默认选择的内存调试指针检查曾让大 JSON 树释放达到秒级，不能把 `-O2` 当作已选中发行分配器。构建会实际预处理运行时、共享 AST 和宿主三个入口，验证功能宏一致，并将 `runtimeProfiles` 写入凭据。SDK／XGE 拥有的 GUI 运行时保持其已核对配置。

增加 `--server` 构建外部宿主，`--skip-tests` 只构建不运行核心检查，`--configuration Debug` 保留调试信息。当前宿主传输／进程适配仍为 Windows；核心构建与宿主平台边界分别记录。IDE 构建脚本已接入该目标：`build_current` 明确传递原工作区的前端材料目录，将原生服务的源码／头文件闭包、输出摘要和构建凭据绑定到整体构建记录。优先选用当前随包编译器的固定源码材料，缺少时选仓库 `demo6`；也可通过 `-FrontendRoot` 显式指定。

IDE 进程仍使用匹配的 XGE/XRT，外部服务通过 `XLS_COMPILER_XRT` 使用编译器 XRT，两个运行时之间只传输 JSON 字节。文本文件层的换行元数据独立于 XUI，编辑器边界用编译期断言核对数值，避免服务链接 GUI 头文件。构建工具核对宿主没有导入 `xge.dll` 或 `xlc.dll`，不允许用 GUI 对象文件与原生分析对象混合链接。

## 会话与快照

`analysis/session.h` 只暴露不透明句柄、正文快照、定长整数和只读诊断视图，不依赖 stdio、XUI 或 IDE 项目模型。调用方先规范化文档键，提供来源路径、文档身份、编辑版本和不可变正文；核心不改变当前目录、不读写文件、不启动编译器进程。

会话用 XRT 哈希表保存文档。更新正文只替换该文档的当前输入，解析在首次查询时发生。后续查询保留解析树；相同内容的新编辑版本继续复用解析结果。不同文档、不同身份和不同来源路径分别管理。身份相同的版本不能倒退，同一版本不能改变正文。容量、编码及版本校验失败保留旧状态。限制由调用方配置，默认 4096 文档、16 MiB／文档、256 MiB 正文总量；这不是 AST 内存上限。

会话由单一 owner 使用。查询返回当前身份／版本／代次及一个需要释放的解析快照引用。快照通过 XRT 原子引用计数拥有正文、来源路径和解析器结果；关闭文档或销毁会话不影响已保留的快照。公开字符串借用快照，最后一个引用释放时在创建方统一销毁。已发布 AST 只读，后续语义阶段不能原地修改它。

解析错误以 `Accepted == 0` 和原生诊断视图返回；不把失败源码解释为成功编译。诊断坐标仍是编译器的一基 Unicode 标量坐标，接入 LSP 时必须转换为协商的位置编码。该切片不执行名称解析、类型检查、导入展开或代码生成。

## 原生语义查询

`analysis/semantic.h` 提供与宿主分离的不透明语义结果，以及候选、类型、符号身份、声明来源和字节范围的只读视图。输入限定为绝对路径及有界的 UTF-8 覆盖，调用返回后不再借用输入；结果拥有独立 AST、导入依赖、来源报告及查询数据。导入展开、标准库注入、类型注册和语义检查直接复用 xlang 已有模块。模块身份通过 XRT 路径工具取得，并保持编译器的名称长度约定。

当前语义查询使用新建的私有树，不修改会话发布的只读 AST，也不声称已实现语义增量。游标投影可以提前终止全文件检查，应以 `available/reached/parsed` 判断候选可用性；不能把检查函数的返回值作为完整编译成功。取消检查在阶段边界执行，共享解析器和语义检查内部尚不能抢占。

所有覆盖在输入边界去除一次可选 BOM，核心字节范围遵守 `utf-8-after-bom`，LSP 边界恢复 BOM 并转换 UTF-16。核心仍保留编译器自己的源码／导入候选报告和输入复核，失败永久使结果失效。兼容服务可通过内存序列化适配器使用已有校验链；其 JSON 来自编译器已有报告函数，不通过 CLI、临时文件、代码生成或项目执行获取。

M3c1 核心完整构建 `build/lsp-next-20261022/m3c-core-v1/build-result.json` 中六组检查通过；模块身份与容量修正后的专项复验为 `m3c-core-fix-v2/result.json`。新增 20 项语义检查覆盖局部变量、遮蔽、成员、未保存依赖内查询、中文／BOM／CRLF、旧结果独立保留、取消及无效输入。该切片只提供核心 API，默认协议接入由 M3c2 完成。

服务 0.7 默认通过该内存适配器处理实际 `textDocument/completion`，继续复用兼容服务的严格来源、字节／UTF-16 范围、候选身份和后台输入守卫。所选执行编译器不再是原生补全的分析输入，因此原生结果复核源码、导入候选和包环境；CLI 结果继续复核外部编译器身份。启动参数仍兼容 `--compiler`，诊断／导航与 C 桥接尚保留 CLI 实现。原生分析失败时不自动切换后端。

宿主通过 `initializationOptions.completionBackend` 接受 `native`（默认）或 `cli`，用实验能力明确返回实际后端。受控编译器响应测试显式选择 CLI，对真实来源的默认查询则执行原生分析。IDE 仍使用相同候选接入和过期验证流程，同时记录协商到的原生能力；旧服务未声明能力时保留原有行为。

补全任务就绪及守卫失效时唤醒协议 owner；等待回收旧守卫线程期间，owner 同时等待协议输入与真实线程完成信号。这样不把下一次请求延迟到 10 ms 定时轮询，仍保留非阻塞退休及当前代次验证。当前兼容服务还会复制输入和序列化／解码内存报告，这些成本及函数／依赖缓存将在后续阶段继续处理。

## 完整静态检查与索引

`analysis/check.h` 提供独立的原生检查结果。解析、导入、标准库、语义检查之后，继续调用编译器已有的 typed XLIR 构建及验证；保留原 `check` 的 IR 阶段覆盖。只有全部检查成功时，才通过共享 `xl6SemIndexJson` 从同一次 AST 和来源报告生成完整索引。编译错误返回实际阶段、有来源和一基 Unicode 标量位置的诊断，以及明确不完整的空索引；索引预算或内存不足属于基础设施错误，不能伪装成源码诊断。核心不执行项目代码，不调用代码生成器，不加载 xlc.dll，也不改变进程当前目录。

结果独立拥有 AST、IR、覆盖、来源报告和索引，提供只读诊断及 IR 类型／节点数量；typed IR 此时尚未填充 lowering 阶段的函数表，不能用该表推断函数数量。调用方输入只借用到创建调用结束。入口可来自覆盖或磁盘；覆盖遵守 64 份、8 MiB／份、32 MiB 合计的已有限制。输入改变使结果永久失效，即使随后恢复相同字节也不重新启用旧结果。

新增共享源文件只有 `xl6_sem_index.c`、`xl6_ir.c` 和 `xl6_ir_class_identity.c`。IR 主文件包含的 literal、ownership、lifetime 和桥接实现不重复编译。取消目前在阶段边界检查，仍需要后续分析内部的协作中断。内存报告适配器继续使用编译器自己的诊断／来源／索引序列化，后续导航缓存将逐步使用常驻的类型化视图。

M3c3a 的 31 项检查覆盖成功及解析／导入／语义错误、同次 IR 与索引、按需关闭索引、未保存依赖、中文／BOM／CRLF、结果所有权、非法输入、取消，以及同字节替换磁盘身份后永久失效。与原有六组核心回归共同通过，记录为 `build/lsp-next-20261022/m3c3-core-v2/result.json`，其链接／输入闭包来自 `m3c3-core-v1/build-result.json` 并重新验证全部源码摘要。该切片先提交核心 API，协议默认检查将在 M3c3b 接入。

服务 0.8 默认用该后端执行 `xlang/check` 的未保存文档快照检查，并为定义、悬停和大纲保留同一次检查的索引。`diagnosticsBackend=native` 为默认，`cli` 为显式兼容／对照路径；实验能力同时报告实际后端。IDE 记录协商能力，旧服务未声明时继续原有兼容行为。`xlang/checkSaved` 的保存后兼容模式与 C 桥接当前仍使用 CLI，不能将这些路径归为已迁移。

实际 3004 行样例暴露了旧索引序列化器的 8 MiB 上限。原生构建仅为该已有模块增加可配置预算的编译保护，并设置 32 MiB 索引／36 MiB 内存报告上限；节点和来源校验继续保留。生成文件位于独立构建目录，构建记录同时绑定原始文件、生成文件和预算参数的摘要，固定编译器源码与 DLL 均不改写。没有另写事实采集或索引算法。这仍是兼容序列化边界，后续类型化常驻索引应减少这部分开销。

大文件回归实际保留超过 8 MiB 的完整索引，并经过协议定义跳转；另一个验证程序将同一共享序列化器编译为极小预算，验证预算失败不生成错误的源码标注。索引资源错误通过服务错误返回，正常类型错误仍是源码诊断。

## 验证与后续

`analysis_session_test` 使用真实共享解析器验证延迟解析、重复查询的实际解析计数、独立文档缓存、同文新版本、身份／路径变化、容量和版本拒绝、快照生命周期、错误结果，以及 500 次函数体编辑；语料中的缓存结果与全新解析的 AST／字面量／范围及诊断逐项对照。既有正文及文档同步测试在同一编译器 XRT 拥有者下重新执行。

2026-10-22，匹配固定编译器材料的 `m3a-core-v3` 构建已通过上述 1,579／1,029／834 项检查；依赖检查确认验证程序没有导入 `xge.dll` 或 `xlc.dll`。摘要与构建记录见 `build/lsp-next-20261022/m3a-result.json`。默认 `demo6` 目录由同一构建工具支持，本阶段的已验收运行使用显式的固定材料目录。

M3b1 增加 `analysis/worker`：用 XRT 单线程任务池拥有整个分析会话，通过 Future 发布只读结果，直接使用 XRT 的有界队列和协作取消。提交时复制路径／身份并保留正文，不复制正文。每次工作使用完整不可变输入集合，先移除关闭文档，再同步当前输入；实际解析与会话中的旧 AST 替换在工作线程执行。外部保留的快照在最后引用释放的线程析构。相同正文的新版本、独立文档缓存和旧快照生命周期沿用会话合同。队列满时拒绝本次提交；目前按任务数限制，排队正文总量及析构时延仍需后续预算验证。

`analysis_worker_test` 验证真实工作线程身份、输入捕获、100 次重复查询的解析计数、跨 Future／工作线程销毁的结果生命周期，以及 20,000 函数文件解析期间的排队、拒绝和取消。取消为协作请求；当前原有解析器尚不能在单次解析内部停止，取消会在进入及离开解析时检查。该限制需在后续容错／增量前端处理中收紧，不能把及时撤销协议回复等同于解析 CPU 已经停止。

## 常驻协议查询

开发服务 0.6 支持 [LSP foldingRange](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.18/specification/#textDocument_foldingRange)：根据共享 AST 的函数、类、条件、循环等结构返回完整行范围，无需先检查成功，也不调用编译器 CLI。当前只提供结构化范围，不包含注释／导入折叠；解析错误暂返回空列表。结果按开始行／外层优先排序并去重，遵循客户端 `rangeLimit` 提示，服务单次上限为 65,536。

解析与范围收集在工作线程运行，使用 Future Watch 唤醒协议 owner，避免固定轮询延时。回复前检查文档身份、版本和代次；修改、关闭、取消及 shutdown 及时撤销旧请求，晚到结果不发布。取消不代表解析内部 CPU 已停止。读线程退出反复取消同步读取直到线程结束，避免把关闭 stdin 作为退出前提。

实验性 `xlang/analysisStats` 返回最近成功查询的实际解析／命中次数、文档与正文字节数、线程 ID，并附当前队列负载。它用于核实缓存与线程隔离，不代表全工程或语义性能。

后续继续用常驻原生语义后端替换补全／诊断的 CLI 高频路径，再做容错语法与函数边界、声明摘要／导入依赖、语义查询缓存和精确失效。当前改动后的目标文件仍整份解析；这里的缓存复用不能作为函数级增量或语义增量已完成的证明。性能验收继续区分核心查询、stdio 往返和 IDE 显示总时延，见 [长期计划](lsp-development.md)。

## 类型化语义索引边界

`analysis/index.h` 定义不依赖 AST、XRT Value、协议或 GUI 的只读节点视图，包含真实 SymbolId／TypeId／ABI 身份、来源及选择范围、规范类型。检查结果保留自己的 AST、IR 和共享采集器事实；视图借用该结果，在验证输入后使用，结果销毁前释放事实及类型文本。失败检查和永久失效结果不提供索引。

固定前端源码保持只读。构建适配仅配置原有索引预算，并在该模块末尾包含 `analysis/frontend_index.inc`，调用原有 `xl6IndexVisit` 及其类型／声明采集规则。未复制事实采集算法，也未对公开的会话语法树运行会修改 AST 的语义检查。

原有 JSON 兼容接口按需序列化；`xlsSemanticCheckReportJson` 仅输出较小的诊断及输入报告，供服务另行读取类型化事实。类型化结果本身不依赖 JSON 树。此边界为常驻索引和后续并入 `xlc.dll` 做准备，单独引入它不代表语义缓存或函数／依赖级增量完成。

默认原生检查已使用 `xideSemanticDefinitionsCreateTyped`，直接由同次检查的事实建立独立导航表；精确输入、Unicode、类型域及重复声明规则与 CLI 兼容构建共用。检查对象保留至发布前的最终验证结束，随后销毁；导航表拥有全部保留数据。`analysis_index_view_test` 在真实语义结果上逐位置比较两条路径，并验证错误输入拒绝及销毁原结果后的导航。

移除 JSON 后的实际分段证据指出 typed IR 构建／验证成为 1000 函数样例的主要剩余成本（单次约 150 ms）。函数／依赖级缓存需要保留该检查覆盖，并审核 IR 中的类型、声明和全模块关系，不能只缓存语法或绕过 IR 后宣称分析完整。

`analysis/check_session` 增加单拥有者的完整检查结果复用，以目标、完整不可变输入集合、路径／身份／正文、索引模式及工作目录确定上下文，版本单独验证。同文新版本复用语义事实，协议版本由适配层重新绑定。命中仍调用共享输入验证，检查磁盘身份及正文、导入候选存在状态和已观察环境；失效会永久标记旧结果。会话仅保留一个有界编译结果，正文使用 XRT 引用，尚无函数体修改后的细粒度复用。

检查对象采用 XRT 原子引用计数。已发布 AST／IR／采集事实不再变化，输入验证和兼容 JSON 缓存使用 XRT 互斥量，失效标记为原子状态。每个读取者持有自己的引用；借用视图不会因会话替换而释放，发布前仍需验证当前输入和文档版本。核心会话不依赖 Windows、GUI 或协议，后续常驻执行器负责线程归属和调度。

## 函数语义事实复用

`analysis/frontend_sem` 在共享检查器的同一编译单元内提供可选的顶层函数缓存。普通／异步／导出函数以当前声明顺序对应条目；类方法与嵌套函数仍由原检查器正常处理。模块声明、导入、标准库、全局检查、最终类型／区域标注，以及完整 typed IR 构建和独立校验继续执行。光标补全路径保持独立，尚未使用这一缓存。

性能优先采用确定性的选择规则：小型直线函数直接运行共享检查器，不复制语义事实。函数含调用、泛型声明、分支／循环、闭包、异常或生成器结构，或至少 64 个词法 AST 节点时，才尝试保留缓存。整份模块没有候选函数时，连模块上下文缓存也跳过。`semanticFunctionsChecked`／`semanticFunctionsReused` 记录真实的顶层检查工作，不能将简单函数旁路算作复用；嵌套／方法工作不单独计数。

上下文键保存完整规范化 AST 的精确二进制表示，只忽略坐标与直接顶层函数体；类、默认值、别名和全局声明完整保留。函数键包含原始函数表示和相关全局状态。键使用变长整数、非零字段掩码和键内精确来源路径字典，避免长路径重复存储，没有以哈希碰撞概率代替一致性。入口路径、正文、非入口覆盖、工作目录、索引模式以及已观察的磁盘／候选／环境均须通过原有验证。

缓存仅接收检查成功、未改变词法树形状且全局／流状态稳定的函数。树形核对只遍历当前存活的节点，原检查器改写并释放的内置方法节点不会被再次读取。局部符号与泛型类型编号的分配起止必须一致，命中时回放两个分配游标；注册表条目数量也必须保持不变。遇到任何编号差异后，模块剩余部分都重新检查，避免后续编号偶然重新相等。全局错误、资源不足、未知坐标或不支持的上下文沿用原检查。每次调用以 C11 线程局部栈隔离，使用 XRT 容器和原子引用计数。缓存数据预算 64 MiB，单键 8 MiB；这些不是进程峰值内存预算。

不可变事实单元拥有独立类型树，版本间共享事实值。每个新条目只持有当前正文和当前坐标表，不持有旧检查／旧缓存／旧正文链。同一函数的类型以一次批量复制共用来源映射，省去逐类型建立复制上下文；无坐标的合成类型不进入坐标表，编辑之前的已知范围直接保留。先为新词法树完整准备私有类型副本，再应用标量事实；任何准备失败都释放未发布副本并正常检查。坐标按本次真实正文变化重定位，覆盖 BOM、CRLF、Unicode 标量和类型来源。没有来源的合成坐标仅在可以证明所有坐标位于编辑之前时原样保留，否则重新检查。

`ast_clone` 默认仍创建独立来源。语义恢复可显式借用本次尚未发布的私有解析树来源；来源池用私有节点固定生命周期，绝不增加旧发布快照中非原子的来源引用。缓存事实本身始终拥有独立来源，不借用该私有解析树。新词法节点、词法范围和输入来源也不会被旧节点替换。

构建保持固定编译器材料只读，在独立输出内加入三处经过审查的薄适配：包含声明、保留原函数体的包装、模块检查开始点。原始语义源码 SHA-256 必须为 `d4f19af32f1732126913b99717a6b1b2d38d92f343b60828786b62d2a7d8183a`；升级时先重新审查跨函数读取、注册、符号分配及副作用，再更新固定值。泛型类型编号回放还固定核对 `xl6_type_registry.c` 的 SHA-256 `a0c37403f28d8a29ac4589e1dd78344a0d5fa2c8051ba2ead0209b9e0a228583`，升级时重新审查编号预留的全部副作用。原始／生成源码和实际包含闭包进入构建凭据，不能只核对替换位置数量。当前开发材料仍是 `build/compiler-c-native-extensions-v1`，随包编译器与发布候选不变。


## 标准库发现的否定名称过滤

`analysis/frontend_stdlib` 只为“源码中完全不存在的拼写”省去类型／成员名称谓词的整树遍历。索引收集当前 AST 子树的短 `text`，并不判断节点是否构成类型或成员使用；名称出现时仍执行编译器原有递归谓词，其他依赖、类存在检查和注入规则也继续执行。原谓词的每个肯定分支都要求某个 AST `text` 与查询名称精确相等，因此这个必要条件不会引入新的肯定结论，也不维护另一套语言规则。

索引在原有引用改写完成后建立，在合并生成声明、修改 AST 之前停用。C11 线程局部栈隔离并发／嵌套展开，XRT 哈希表在本次调用结束后释放，没有跨版本缓存或旧来源引用。复制拼写及保守条目开销预算 8 MiB，名称最多 65,536 个，仅索引 1–256 字节的拼写；构建失败、空／超长查询均沿用原谓词。该预算不是进程峰值内存上限。收集器或其他原有类检测的遍历不能计作已经消除。

固定编译器源码保持只读。构建在独立生成文件中加入六处薄适配，原始 `xl6_stdlib.c` 的 SHA-256 必须为 `bf863afd1bdef637388e6e4198813484f90e4eb8f1399580d75304e70a110919`。升级时须重新审查肯定分支的精确拼写必要条件，以及改写完成至生成声明合并之间的 AST 不变区间；原文件、生成文件和完整包含闭包作为第四组适配进入构建凭据。

`analysis_stdlib_scan_test` 对原始谓词路径、索引路径和极小预算回退的完整展开 AST／诊断逐项比较。覆盖实际类型／成员使用、泛型构造、用户类、同名函数／字面量产生的过滤假阳性、标准库依赖、Unicode／NUL／CRLF及四线程隔离。共 1,191 次断言，包含大样例构造；15 组语料各执行三种真实展开。40 个各含 25 次泛型调用的函数，类型／成员名称谓词访问从 1,937,936 次降为 0，另有一次 12,584 节点的索引收集；索引数据计量为 5,837 字节。完整语义、IR 和其他标准库规则仍保留。


## 退出计划来源候选索引

独立 IR 验证器原先为每个节点枚举所有退出计划，再筛选 `origin`，并为重复检查再次枚举该计划之前的记录。`frontend_ir` 增加按“来源节点、原始记录位置”排序的可选候选数组及反向位置表；只改变这两处循环的候选枚举，原有来源条件、数量、重复的 point／kind、生成器和异常边界等验证全部保留。同一来源中的记录仍按原物理位置递增，之前记录仍严格限制在当前记录之前。

索引延迟到原验证器真正进入该枚举处才建立，因此先前检查已经拒绝的模块不会因索引而提前读取其他 arena。每次 const 验证独立拥有数据，绑定模块、节点和退出计划的指针／数量，结束时释放，不跨构建保留。读取前核对原有拓扑预检、计划数量／容量和指针；非法来源仍保留在候选数据中，由更早的原始计划检查给出相同诊断。数组容量实际计量最多 8 MiB，预算、分配或排序失败立即释放部分数组并执行原线性枚举。原有局部声明候选另有 16 MiB 预算，二者都不是进程内存预算。

构建仍保持固定编译器材料只读。IR 适配现有七处审查位置，原始 `xl6_ir.c` 的 SHA-256 必须为 `6022b348ecb5ec0dc79eac881a4e51cb6dc227daa210f730bcdf27a191aad2d0`；升级时须重新审查候选条件、arena 生命周期、验证期间不变性和顺序／重复诊断，不能只确认替换位置还存在。私有原始验证入口通过同一共享函数体执行完整线性路径；小预算入口仅供验证可选索引回退，正常宿主没有配置开关。

## 单次验证内的成功生命周期证明

## 光标查询语法快照核心（M6b4e7a）

本切片扩展已有 `syntax.c` 声明块与函数体增量机制，新增私有 `xlsSyntaxBuildCursor`，所有光标词元替换和点后零宽词元插入仍委托共享 `xl6ParseSourceWithCompletion`。没有复制语法、词法或补全词元选择规则。普通／光标两种快照不能互用声明块。

当前复用条件是一次文本变化完整落在一个已知函数体内，旧查询范围及新光标也落在该函数体；仅重新解析该函数片段，其他声明保留原不可变节点。跨函数光标移动、其他函数或签名变化、BOM 变化、不确定边界、相同正文和错误来源等条件均走全新共享解析。片段失败时释放局部查询前缀，再让全量解析更新调用者的查询，确保 `parsed` 仍为一次，不带入失败片段的诊断或坐标。
