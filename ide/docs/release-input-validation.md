# 发布目录输入恢复与原生 LSP 联调

2026-10-31。本轮在仓库根 `release/` 重建 IDE，使用同目录的原生 `xlang-ls 0.100`、XGE 和 xlang 引擎进行验证。

## 输入故障的实际结论

用户报告更换 LSP 后，菜单等界面仍可操作，但 C 和 xlang 编辑器均不能输入。保留原程序后，从本轮开始时的已提交源码 `1deedb127` 重新编译全部 107 个 GUI 模块并链接两个 IDE 程序；用户重新启动后确认已经可以输入。后续并行工具栏任务的未提交改动不包含在这套已验收程序中。

本轮没有修改输入逻辑。重建前后 `xlang-ls.exe` 和 `xge.dll` 的 SHA-256 均不变，变化的是两个 IDE 程序。因此，不能将故障直接归因于新 LSP，也不能声称已经修复了一个确定的 LSP 输入缺陷。原故障未在自动化用例中复现，旧进程的精确触发状态仍未知。已确认的验收缺口是：上轮验证了独立服务，却没有对发布目录中的 GUI 与新服务完成配套联调；本轮已补做。

GUI、服务、SDK、引擎与测试记录绑定在 `release/provenance/ide-native-lsp-integration-20261031.json`；原始日志和旧程序保存在 `release/tmp/ide-input-20261031/`。本轮没有推送远端或重新生成发行 ZIP。

## 已通过的验证

- 输入桥：有序字符／按键、事件时修饰键、删除、撤销／重做、C 补全基础行为、中文／非 BMP 组合提交、组合取消、只读预览及浮动编辑器。
- 点击与输入：在真实应用帧中从命令列表点击返回 C／xlang 编辑器，再发送字符，核对焦点、只读／启用状态和文档版本递增。xlang 使用用户报告的同一路径源文件，只修改内存，不保存源码。
- 自动诊断：463 项检查，涵盖打开／编辑、依赖、磁盘与覆盖证明、暂停恢复、385 条真实帧消息下的背压，以及后台阻塞时继续编辑。
- F12：原生定义、重载、类型目标、未保存导入、BOM／CRLF、来源身份、取消与过期结果保护。
- 悬浮与大纲：冷路径、鼠标悬浮、符号跳转、标签页／文档版本和范围守卫。
- 补全帧：49 项断言，普通字符输入与 Ctrl+Space、当前候选／版本／替换范围、真实应用帧和取消。每模式只有一个样本，只作为功能证据。
- 参数提示帧：146 项断言，四模式各两个样本，原生标签、当前参数、文档版本、选择、渲染提交及 Escape。
- 参数窗口：59 项检查，共用原生客户端、手动／自动／IME、重载、拖动／缩放、焦点与过期来源保护。
- Minimap：315 项检查，C／xlang、新建与复用、四种主题、100／125／200% DPI、点击拖动和菜单键盘操作。

这些验证确认相应功能可以使用，不替代完整 IDE 尾延迟、规模、全局内存或整个 LSP 的验收。此前 M101 的 A/A、分析耗时和导航性能失败继续有效，不能据本轮功能测试宣布整体性能达标。

## 并行修改与失败记录

补验期间，另一项工具栏／运行目标任务修改了 `xide_app` 和动作声明。已经编译的对象使用 `context` 偏移 1216，而新头文件使用偏移 1240。随后编译的参数窗口测试因此读错字段，将无效 context 传给 XUI，返回 `INVALID_ARGUMENT`；上层笼统报告为内存错误。

本轮保留该失败，使用匹配已编译对象的 `1deedb127` 两份公共头文件重新编译这一项测试，59 项检查通过。这个编译边界只用于保护并行任务和核对布局，程序仍使用根 `release/` 的真实运行库与服务，没有覆盖另一项任务的源码，也没有创建另一套 IDE 运行环境。它证明了后续测试初始化失败的原因，不能追溯为最初用户输入故障的唯一原因。

最初一次参数帧调用缺少必需的夹具参数，退出码为 2；补齐参数后通过，原记录保留。两个构建脚本调用在 GUI 链接前发生路径错误，107 个模块均已成功编译；本轮按原构建配置和对象完成链接。最初怀疑旧 PowerShell 对注释的解码，但最小对照均通过，此解释未经证明，不作为结论。

另有独立的 C 补全问题：根 `xl.exe` 执行 `c-bridge <最小源文件> --json --c-environment` 返回 `cannot collect bounded native C configuration and builtin headers`。不经过 IDE 或 `xlang-ls` 也能复现；C 补全完整用例因此未通过。本轮没有修改引擎或将它记为通过，C／xlang 的普通文本输入已经恢复。

## 后续默认工作流

日常构建和联调直接使用根 `release/`；中间对象留在 `ide/build/Release/`，日志及临时夹具留在 `release/tmp/`，验证结束后移走根目录中的测试程序。隔离版本对照、故障注入或保护运行中会话时才建立单独环境，并说明原因。

更新 LSP 时必须同时核对 GUI、服务、SDK／DLL 和编译器，补做实际输入及受影响的语言功能。公共结构变化时必须一起重编所有消费者；编译期间输入变化时应停止发布，不能将旧对象与新头文件混用。
