# 长行字节位置与可视列索引

2026-10-11，SDK52 已实现供列计算和可见范围共用的稀疏行索引，并通过原始遍历对照、完整引擎、SDK、编辑器应用及原生窗口检查。交错复测的四组长行对照中，输入、撤销和暖帧耗时均降低；首次布局及绝对耗时仍有明显波动。该源码已作为下一次整应用回归的候选，当前完成完整回归的 SDK48 可运行包继续保留。

问题定位与五条路径的原始计时见[上一轮诊断](large-source-line-paths.md)，当前完整应用和便携包见[集成候选验收](integrated-editor-sdk.md)。本次未替换固定 SDK 或现有便携包，极长行整体性能尚未验收通过。

## 实现与有效性

每个编辑器保留一组成功读取范围的索引点，记录字节偏移和对应的可视列数。文本至少 64 KiB 时启用，点之间至少相隔 4096 字节，最多 4096 点、32 KiB；无需额外复制长行文本。字节目标和列目标使用二分查找，从安全的原文本簇边界继续原有遍历。两条查询路径共用索引，原有的可见范围精确结果缓存继续使用。

点只在文档对象、文档版本、成功读取起点和制表宽度匹配时使用。同一版本、同一起点的较短前缀读取可保留安全的点；输入、撤销、文本替换和制表宽度变化重新建立对应索引。列数仍使用原码点和制表规则，没有缓存字体、字形或像素度量，也没有改变绘制算法。

旧边界判断可能读取下一个 UTF-8 码点，所以点之后四字节必须落在当前查询范围内；截断查询不会直接复用靠近其结尾的点。读取操作在复制前撤销有效状态，成功后才允许使用索引或读取缓存。索引分配失败保留原遍历，在同一有效性条件下只尝试失败一次；此前成功建立的点仍可使用。编辑器销毁时释放点表。

与 SDK48 相比，仅修改 SDK 的编辑器实现文件；241 份源材料及整个 SDK 的严格 O2/Werror 构建均已核对。公开头文件和 5,954 个导出名称／序号保持一致，应用工厂和 DPI 接入沿用 SDK48 的十份替换材料。完整 ABI 和正式 SDK 发布验收仍独立保留。

## 正确性与复现

完整引擎夹具保留 SDK48 的两个原始遍历函数作为参考。原生运行实际退出 0，新增完成 6842 条断言，覆盖 2804 个字节位置、658 个可见范围、43 个状态变化及 4 个失败路径，并直接观察到 1886 次索引恢复。

覆盖包括随机字节位置、UTF-8 与文本簇内部的截断查询、CJK、Emoji／ZWJ、区域旗帜、组合字符、Hangul、制表和零字节，前缀读取、输入撤销、读取起点和文档对象替换，拒绝非法 UTF-8 文档、借用非法输入的原路径、读取失败，以及首次分配和表扩容失败。18 MiB 的独立 SDK 文档达到 4096 点容量上限后，剩余尾部仍与原始遍历结果相同。

既有 585 个布局、2,822 个完整排版、108 组 GPU 像素、52 个布局编辑、78 个绘制、24 个候选收集、495 个 Emoji 匹配、36,964 个原始字形度量等比较继续通过。另有 3 项 SDK 功能检查、6 项编辑器应用检查及导出核对实际退出 0。

首批 C／xlang、2 MiB／16 MiB、多行／长行的旧版和索引版共 16 个原生窗口用例，完成 720 条检查与 8 组零差异截图。因首批最后一个 xlang 长行计时恶化，又按正反顺序交错运行 8 个长行用例，完成 360 条检查与 4 组零差异截图。合计 1,080 条窗口检查、12 组逐像素对照；所有窗口均运行在从未切换的自有 Windows 桌面。

已落盘 [SDK52 补丁包](../third_party/sdk_patches/large-source-experiment-v20/README.md)。[SDK 准备工具](../tools/prepare_row_index_sdk.py)实际生成与已构建源码逐份相同的 241 份材料；[应用准备工具](../tools/prepare_row_index_app.py)生成十份工厂／DPI 替换材料；[完整引擎验证工具](../tools/test_row_index_sdk.py)显式复用经全部材料与参数核对的严格编译产物，重新执行原生检查并退出 0。默认调用仍执行冷编译。

首次准备稿在尚未构建时补充了分配失败后停止重复尝试的条件，原稿保留。首次夹具语法检查发现两个缩进警告；第二次夹具在构造截断 UTF-8 文档时被文档模型拒绝。修正后的夹具构造完整码点，并独立核对非法输入拒绝与借用输入回退；原始失败结果保留，SDK 算法未因这些夹具修正而修改。快速辅助夹具的整文件链接尝试也保留失败记录，逐字提取所需函数的后续辅助检查通过；最终判断使用完整引擎运行结果。
