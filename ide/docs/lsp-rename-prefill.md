# IDE 重命名的语义名称预填

M7b6k，2026-11-15。Ctrl+F2 先调用标准 `textDocument/prepareRename`，将服务返回的实际名称填入输入框。准备阶段不猜词、不生成修改、不申请写入租约；随后仍由原有完整候选、预览、明确确认及异步事务执行重命名。布尔 `renameProvider` 的旧服务继续使用手动输入；只有成功分配接收邮箱才协商 `prepareSupport`。

准备窗口最初为非模态，编辑器仍可输入和切换。共用现有输入同步和磁盘收据流程，即使关闭自动检查也能准备。等待同步有 5 秒上限；请求发出后可以随时取消。收到有效结果且焦点仍在准备窗口内时才转为模态并选择名称；用户已回到编辑器时保持非模态，不抢焦点。停止、Esc、关闭及退出撤销准备请求。

每次请求使用不可复用的字符串 ID。XRT 小邮箱复用原有传输线程，只向界面交付一个范围、名称字符串叶子和短错误。旧回复、重复及取消后的回复在传输线程释放，包含恶意的大对象树；不新增线程，也不把整个 JSON 对象树交给界面清理。服务发来的反向请求不会因相同 ID 前缀被当作回复。名称限制为 65535 UTF-8 字节，回复限制为 512 KiB，并检查坐标类型、UTF-8、范围及代理对边界。

接受结果前验证目标文档、光标、只读状态、文档源 epoch、所有已打开 xlang 文档的版本和路径、客户端/配置身份、源租约及磁盘监控修订。源元数据最多 64 个文档、合计 2 MiB 路径及语言标签。根据发出请求时的 LSP 位置和名称内部的 UTF-16 宽度，将精确范围锚定到原光标字节位置，只复制这段源码并比对，避免额外将两个范围端点从整行重新换算。准备完成后源码变化也会撤销预览资格并保留已输入的新名称。

专项验收包括中文与非 BMP 字符、BOM/CRLF、等长伪造名称、代理对分割、超大坐标、连续请求、取消后迟到回复、配置撤销、关闭自动检查、源暂停/恢复、只读切换及焦点保持。真实 IDE 同时验证 C/xlang 输入、删除、撤销、Unicode/IME、点击聚焦，以及原有完整重命名候选、确认、应用和恢复。通过实际编译的错误实现核对测试确实能识别上述保护被移除的情况。

本轮复用上一阶段已经完整构建并验证的原生服务，不把继承的协议和原生测试计为重新执行；IDE 全量重编译并重新验收。材料入口：`dev/release-materials/provenance/lsp-rename-prefill-20261115.json`。默认运行程序、SDK、交付索引及线上通道保留。

这仍不是整体性能验收：现有共享输入捕获在正文变化时仍有整文复制，发出位置的转换可能扫描当前长行，客户端停止仍存在等待，其他输入及帧处理成本另计。完整静态分析/补全、标准工作区自动加载、资产对齐、其余适用 LSP 及全目标延迟、RSS、耐久和平台验收继续；不包含 DAP 或运行/调试态补全。此前三项旧对话框失败不在本阶段修复或计为通过。
