# 构建输入记录接入

此增量继续阶段 5/6 的递归依赖保护。IDE 任务服务现已读取同次 DEMO6 构建的实际输入记录。上一便携候选仍为 resource-rename-v2；新代码的正式构建及便携验收分别记录，不能用编译器专项代替原生 IDE 验收。

编译器接口和当前边界见 [DEMO6 构建输入记录](../../demo6/docs/IDE构建输入记录.md)。`check --source-report` 是语义分析报告，不能证明稍后 `build` 读取了同一批 C 头、库和资源；构建应使用同次 `build --input-report`。

Windows TCC 自身目录和系统库目录使用 UTF-16 接口读取，再显式转换为 UTF-8；保持非 ASCII 路径的原字节，不用 ANSI 接口或按字节小写处理。这是中文/emoji 目录中的便携编译器生成有效记录所需的修正，迁移验收单独验证。

每个任务保留独立目录、原始日志、清单/配置快照、直接输入基线及工具链指纹。本次 `--help` 的 build 行必须明确声明完整 `--input-report` 选项，才请求任务专用的 `inputs.json`；其他命令行或名称前缀不算声明。声明后缺失、损坏或不完整记录直接失败，不退回旧守护。旧编译器继续构建，任务页明确显示“直接文件与资源守护”；新记录通过发布校验后显示“实际依赖已核验”。

任务服务行为：

- 后台严格解析 schema 1，复核范围、完成标记、字段类型、规范绝对路径、重复/矛盾项、预算、摘要和身份。实际文件在同一 XRT 句柄上读取前后核对元数据，流式 SHA-256 后再核对路径身份；没有在 UI 线程读取整张图。
- 实际文件及缺失候选加入任务守护，发布及运行前再次复核。缺失的 native 搜索项必须仍然不存在，xlang 查询保持编译器实际使用的文件存在谓词。阶段产物匹配原身份和摘要；发布副本匹配摘要及大小，并确认读取过程中身份稳定。
- 未匹配编辑通知保留至任务结束，发现新图后重新核对全部通知。目录外未保存文档、发现前收到的编辑、硬链接别名都可以使任务失效。通知上限 8,192，溢出或内存失败明确中止。
- 配置输出不能覆盖记录、阶段产物、工具链、实际输入或搜索候选，物理别名也受检查。失败保留旧输出，不能运行旧结果。
- 提交时冻结 `XLANG_PACKAGE_PATH`，保留未设置与空字符串的区别；构建子进程显式使用该快照，不受之后 IDE 进程环境变化影响。运行配置的环境覆盖只作用于运行。不同包路径快照不合并请求。

`build-invocation.json` 保存实际 argv、工作目录、编译器/阶段产物/记录路径、包环境及工具链摘要，关联同次构建；任务仍保留 compiler-help/build/run 原始日志。记录不包含完整操作系统访问日志，第三方 loadlib、运行时访问与调试输出仍遵循编译器协议边界。
