# LSP 生命周期计时工具

2026-10-31，M7a2b98。新增工具用于定位分析结果从构建到替换、释放的实际开销。本阶段没有修改服务的正常执行路径，也没有采用本轮的性能原型。此前 M97 的正式性能失败仍保留，整体性能尚未准入。

## 为什么需要覆盖释放路径

检查会话返回后，导航投影仍可能持有旧检查结果。发布下一份投影时，最后一个引用才被释放，因此旧索引、语义备忘、IR 和类型 AST 的销毁会计入新请求的响应耗时。只观察函数体检查，或者只观察外层查询对象的销毁，会漏掉这部分工作。

`build_lsp_lifecycle_profile.py` 接收一个完整、通过原生测试的正常构建，先验证其全部输入和产物摘要，再复制其静态库，私下重编译九个 TU。原语法、语义、IR、运行时和其他宿主对象保持原构建版本；只在私有副本添加计时，最终重新核验原构建和工具输入。工具不安装任何程序。

观察范围包括工作线程的完整执行、会话与函数体各阶段、导入捕获、响应封装、导航构建／发布、最后引用触发的检查结果销毁，以及外层查询退休。工作线程和响应封装使用原函数外的包装入口，原函数内部的成功、失败、签名帮助提前返回和取消路径都能结束外层计时。

每个线程使用有上限的独立计时栈，防止内层退休覆盖外层数据。每条记录包含线程 ID、线程内递增序号和测量单元，以一次 `fwrite` 写出一个 JSON 行。记录格式错误、未知字段、重复键、错误序号、无效测量、深度溢出标记或缺少完成记录均不能通过分析工具的检查。计时栈和输出缓冲不进行动态分配。

父子计时相互包含，不能相加。退休记录的顺序不是请求 ID。范围外的清理、整个进程生命周期、GUI 和其他协议工作量不在这套工具的完整性声明内。插桩、格式化和日志本身有成本。

## 可复现运行

从仓库根目录运行，输出目录必须尚不存在：

```powershell
python -X utf8 -B ide/tools/build_lsp_lifecycle_profile.py --build ide/build/lsp-m97-20261031-e87736be/current-full-v2 --output ide/build/lifecycle-profile
python -X utf8 -B ide/tools/profile_lsp_lifecycle.py --profile ide/build/lifecycle-profile --output ide/build/lifecycle-queries --functions 512 --pairs 3
python -X utf8 -B ide/tools/check_lsp_lifecycle_profile.py --profile ide/build/lifecycle-profile --output ide/build/lifecycle-checks
```

查询工具使用真实 stdio、未保存的编辑器内容、直接文件／导入两种结构，以及字面量／双函数声明两种修改。每个进程执行 14 代和一次精确重复。正常程序与计时程序的顺序按进程对交替，核对标准结果、请求标识、文档版本、退出码和日志完整性，保留全部记录及慢样本。额外检查覆盖真实原生签名帮助的提前返回；同一路径下仅去除必然不同的两个线程 ID，其余结果和分析计数均须一致。

`result.json` 保存输入、命令、进程、结果及状态；`review.json` 保存记录和各场景分布。这些均明确标为 `accepted: false`。可配置的小样本诊断不替代正式性能的 64 项门槛、进程对方案、资源底线或原基线。

## 本轮验证与结论

证据目录为 `ide/build/lsp-m98-20261031-54af4e8d/`。

- `lifecycle-tool-v2`：九个真实 TU 重编译，生成 23 个受摘要保护的文件；原正常构建 740 输入／125 产物在前后核验中一致。
- `lifecycle-tool-run-v1`：512 函数、两对进程、四种场景，共 16 个进程／240 次检查通过，63 个计时标签可解析。较慢的导入声明样本完整保留。
- `lifecycle-tool-check-v2`：8 个真实 XRT 线程生成 1600 条嵌套记录；提前取消和签名帮助通过；覆盖父计时数据、序号归零和遗漏工作线程完成记录的三种实际 C 源码错误变体均被原测试拒绝。共九项检查通过。

初次私有计时运行还保留了 24 进程／360 请求的正常程序对照。它与新工具均表明，导航发布可以包含旧结果最后引用的释放，AST 释放是其中的主要部分。此处是定位证据，不是对此前热 P95 退化原因的完整解释。

空释放规避、池节点批量退休、已有原始 IR 文本所有权预算启用，以及两版后处理候选索引，都做过私有正常结果对照。收益偏小或不稳定，部分场景存在明显慢样本，全部未采用。候选索引的第二版只核对节点形态，仍未完成一般原生构造约束的准入审计，更不能据此替换正常路径。

首次工具构建的严格编译警告，以及首次签名测试因不同路径和线程 ID 导致的对照失败都保留在 `*-v1` 证据中。最终测试使用相同路径，只归一化线程 ID，没有放宽标准签名结果或其他分析计数。

下一步仍是利用现有不可变函数资产推进真正的最终 IR 局部生产，证明类型、符号、依赖、派生表、来源位置和所有权边界；当前完整原生转换和验证保持。完整 LSP、SDK／IDE 对齐、规模、全局内存和界面尾延迟验收仍未全部完成。
