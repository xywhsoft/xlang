# 原生派发关系的源码声明关联

后续[同作用域重载与属性关联](lsp-callable-families.md)已将这些声明关系纳入同一按需查询，并补齐属性使用位置的原生目标读取。本页及原验收索引保留上一阶段的范围记录。

本阶段为后续安全重命名提供按需的声明关联查询：从一个已有精确源码键出发，收集当前成功检查中由类虚方法槽、覆写实现和协议见证表连接的源码声明。关联直接读取原生 Typed XLIR 的 `classDispatchSlots/Impls`、`protocolDispatchSlots/Impls`，不重新按名称或签名推断语言规则。

`analysis/dispatch.h` 暴露原生关系的只读标量视图；每条记录保留声明与实现的编译内 SymbolID、原始零起始槽序号及所有者/契约 TypeId。桥接层检查原生节点与 SymbolID 对应。单条读取为常数成本，不分配内存，也不导出 AST 或 IR 指针。

`xideSemanticReferenceFamilyCreate` 使用现有导航投影将原生 SymbolID 映射到真实源码声明区间，合并同一精确声明区间的身份，再对选中的派发关系求传递连通分量。只保留目标所在分量，继承形成的重复声明只输出一次。相同拼写而没有原生关系的方法不加入；连接中出现缺失源码、生成名称、非 IDENT 或不一致拼写时，拒绝整个捕获。

结果按源码路径和字节区间持有成员，完整源码采用每个贡献文件一份的不可变副本，包含原有 BOM 转换约定。成员键通过保留该结果获得独立租约，不再复制或扫描源码，可交给既有引用分片查询。键、结果均可在原检查、导航缓存和调用者句柄销毁后读取，并可跨独立编译匹配精确源码身份。它们不持有原 AST、检查、工作线程或缓存。

该查询不接入普通导航、补全和引用的热路径。设原生派发记录数为 E、导航声明数为 D，图构建使用有界排序、二分与并查集，成本约为 O(E log E + E log D)，另外包含首次导航投影获取、目标声明验证，以及每个贡献文件的一次复制。默认 32 MiB、最大 64 MiB 的捕获预算同时计入并存图临时内存和最终载荷；借用的原分析/导航、分配器元数据和排序实现内部开销另计。循环定期检查取消，文本复制每 64 KiB 检查；现有导航获取和预算内库排序不可中途抢占。

普通源码键增加一个可空的结果指针（win_x64 上 8 字节）；普通键销毁增加一次空值检查。成员租约只分配键头，其 `KeyBytes` 保守计入整个被保留的关联载荷，避免使用者低估保留内存。尚未据此宣称端到端性能达标。

专项验证涵盖类与两个协议形成的传递关联、继承重复、不同签名排除、跨文件及独立编译、无派发记录、错误检查、精确配额边界、两处真实分配拒绝、每个观测取消位置、Unicode/BOM/CRLF，以及原所有者销毁后四线程读取。故障变体分别丢弃真实派发边、把精确声明误放宽到整个文件，以及漏算并存临时内存；专项均拒绝。

这是当前编译已观测到的派发连通分量，不能作为完整重命名许可。重载和属性组、所有泛型来源、整个工作空间的固定点闭包、物理文件别名与可写性、外部符号策略、冲突及改名后绑定证明、版本化编辑和 IDE 原子事务仍需完成，`renameProvider` 尚未开放。当前引擎对齐、全目标性能与规模准入亦继续保留。

阶段验收通过 173 个原生夹具、11 套协议和 28 个 IDE 夹具，专项执行 914 项检查；三种实际关联实现故障变体均被拒绝。构建绑定 282 个消费者、174 个程序及 core 全部成员，IDE 以同一服务和匹配 SDK 完整编译 116 个对象。C/xlang 输入、删除、撤销、Unicode/IME、焦点和现有语言功能通过，浅色、深色与引用窗格已复核。默认发布程序保持原状，详细验收索引为 `dev/release-materials/provenance/lsp-dispatch-families-20261110.json`。
