# 版本化重命名候选计划

在声明族与全部引用收集之后，工程引用 actor 可以构造不可变候选计划。它从已有提供者图一次建立来源路径索引，匹配各编辑文件的精确正文及来源证明，不重新分析，也不修改文件或编辑器。保留既有图缓存、配置范围、未登记文件拒绝和最终输入防护；未返回引用的范围同样复核。

`rename_plan` 复用 XRT 的存储、JSON、SHA-256、原子引用计数和原生标识符校验。校验原有规范化正文摘要，并对关闭文件额外验证物理原始字节的摘要和大小；BOM 与 CRLF/CR 原样保存。已有引用证明的结构验证提取为共享内联头，引用解码器与计划构造器使用同一实现。

文件和区间排序后，构造器拒绝重复文件、重复或重叠编辑、名称字节/词边界失配及不一致的 UTF-16 位置。每份正文通过既有批量坐标映射器校验全部位置；每个文件的 before/after 正文各复制一次，没有逐个编辑移动整个尾部。计划保留深复制的来源证明，独立于原图、检查、工作线程、输入正文及请求生命周期。

计划中的原始/修改后正文均包含物理 BOM。编辑位置维持来源原有 LSP 约定；用于下一次原生检查的 before/after 字节偏移均不含物理 BOM。二分偏移映射保留未修改部分与编辑端点，拒绝已替换名称内部的位置，供后续绑定保持验证使用。

版本化草稿采用 `WorkspaceEdit.documentChanges` 与每文件 `TextDocumentEdit`：打开文档保留 int32 版本，关闭文档为 null，编辑区间均相对于原版本且互不重叠。依据为 Microsoft 的 [LSP 类型定义](https://github.com/microsoft/vscode-languageserver-node/blob/main/types/src/main.ts#L1750)。可协商附带已有 xlang 来源证明；普通草稿没有扩展字段。输出按组成部分提前计费，并在完整序列化时限制为 7 MiB。

默认及最大 128 MiB 额度计入计划载荷、序列化证明额度、排序/坐标数组与持有的临时路径/URI；DOM、分配器、坐标映射器及哈希实现内部成本额外。工程 actor 的来源索引及输入数组另限制为 32 MiB。额度不是 RSS 限制；库排序、UTF-8 完整验证和 DOM 深复制不可中途抢占。

这仍是候选数据，尚不构成可应用的重命名。名称冲突、所有原生绑定在修改后的保持证明、完整泛型来源和外部符号策略、物理别名/可写性及 IDE 版本化原子应用仍待接入；`renameProvider` 继续关闭。跨提供者源码银行优化、当前引擎对齐与全目标性能/内存/长期稳定性准入保留。

本阶段通过 182 个原生测试程序、12 组协议测试和 29 项 GUI 检查。新增计划专项 1,376 项检查，以既有顺序文本编辑器为独立对照，覆盖增长/缩短与 Unicode 替换、BOM/CRLF 原样保留、全部 int32 版本边界、关闭文件 null 版本、原始及规范化摘要、重复/重叠/坐标失配、最小成功额度与少一字节拒绝、真实分配和深复制拒绝、7 MiB 输出、全部观测取消位置及独立四读者读取。工作空间专项 87 项检查验证完整范围收集、缓存复用、原文件及编辑器快照未修改、最终输入变化/取消和请求及原所有者退出后的结果读取。共享证明解码器的 65,611 项检查同时通过。

忽略原始摘要、跳过坐标校验、丢失打开文档版本、丢失字节位移、移除输出上限、跳过最终输入防护这六个实际实现变异均被测试拒绝；只替换变异测试的生产者 include 选择，逆替换可恢复原测试的完整字节。资格检查绑定 294 个实际编译消费者、183 个程序及 core 的所有成员；配对同一候选服务与匹配 SDK 重编译全部 116 个 GUI 对象，覆盖 C/xlang 输入、删除、撤销、Unicode/IME、焦点及既有语言功能，浅色、深色和属性引用窗格完成复核。
