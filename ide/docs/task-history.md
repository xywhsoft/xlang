# 任务历史与内存保留

实现状态：2026-10-09。任务页限制完成记录和待执行请求，避免连续构建导致任务对象与固定大日志缓冲持续增长。磁盘阶段保留见 [任务阶段目录保留](task-stage-storage.md)。

## 默认行为

- 保留最新 64 项已完成任务，当前选中项和自动跟随项额外保留。两者不同时最多增加两项。
- 排队、执行及取消中的任务另计。最多接受 32 项未完成请求；重复请求在达到上限时仍合并到已有任务。新请求被拒绝时显示队列已满信息。
- 工作线程还在退出的记录暂时保留，直到线程句柄确认退出。不会为了裁剪历史等待活动工作线程。
- 任务 ID 始终递增；裁剪改变列表行号时，选择仍指向原来的任务。历史条目保留状态、耗时、诊断、日志路径、输入路径与工具链信息。
- 日志和终端缓冲分别从 4 KiB 开始，按需增长到 1 MiB。只保留最新字节，读取 API 返回绝对字节游标和丢弃量；原始进程日志继续写入磁盘。界面输出尾部的 256 KiB 限制独立生效。

完成状态不等于线程已退出。任务服务在所属 UI 线程轮询并确认线程退出后，关闭线程句柄、释放请求快照、参数、环境、编辑通知与实际输入校验对象，并收缩没有填满的日志缓冲。诊断与历史元数据保留到该条目被裁剪。

## 服务接口

`xideTasksTrimHistory` 是所属线程上的显式裁剪接口。调用方可提供保护任务数组；删除后原句柄失效，保留句柄及任务 ID 不变。任务页在每次轮询时应用默认 64 项策略。其他服务调用方可以按自己的句柄生命周期选择何时裁剪。

`xideTasksContains` 用于检查所属服务是否仍持有任务。任务页拒绝其他任务服务的句柄；重建树及同步选中行期间抑制程序触发的选择回调，避免行号变化误选任务。

裁剪仅释放内存，不直接删除 `.xlang-ide-build` 目录。独立后台维护具有所有权记录、共享租约、路径身份与内容校验；默认保留最近 64 个完成阶段和七天宽限。跨会话任务历史和按总磁盘大小的淘汰尚未实现，详见 [磁盘阶段保留](task-stage-storage.md)。

## 验证

`tests/task_history_test.c` 已纳入 `tools/build.ps1 -Tests` 与默认 `tools/test.ps1`。测试在独立 Windows 桌面运行真实工作台并生成 C、xlang 和任务列表截图，覆盖：

- 32 项队列、上限时去重、溢出拒绝、取消与活动任务保护。
- 已选择项和自动跟随项分别保留，显式裁剪及外国服务句柄拒绝。
- 400 次实际请求后的记录数量、进程私有内存和列表 ID 更新；裁剪后的指针选择与树行选择一致。
- 3 MiB 原始输出与最后 1 MiB 缓冲逐字节核对，明确检查丢弃游标；输出夹具按块限速，隔离任务缓冲与底层进程队列。
- 完成请求释放后仍可查看输入路径、诊断与日志；内存裁剪后磁盘日志仍存在。
- 构建前保存的 C 文档及随后未保存的修改在压力测试期间保留，C/xlang 语法与既定 dock 布局持续生效。

进程内存测量用于检测任务数量带来的持续增长，允许 Windows/XGE 分配器的短期波动；不等同于全 IDE 内存预算或任意项目规模验收。
