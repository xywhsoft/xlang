# SDK46 剩余排版耗时诊断

2026-10-11，基于已归档的 SDK46；本轮仅增加诊断夹具与记录，没有修改 SDK、应用源码或正式包。16 MiB 单行最长编辑帧仍接近 1.9 秒，性能验收未通过。

## 主线程采样

在从未切换的私有 Windows 桌面中，用同一个 SDK46 原生窗口探针运行 16 MiB xlang 单行输入。GDB MI 第二版明确选择窗口主线程，完成 202 次暂停观察；调试器退出 0，观察到原生正常退出，探针完成 45 条检查。

75 个样本包含整段 `__xgeTextShape`，64 个包含 `xgeInternalTextPaintStream`，26 个包含 Emoji 文本匹配，13 个包含候选收集访问器。此计数来自截断到 15 层的调用栈；包含关系不能相加，也不能换算为无调试运行的时间比例。调试暂停和 Windows 调试堆会扰动结果，退出时出现大量目录内存释放样本。

首轮采样选择了调试器创建的中断线程，在 240 次观察上限终止本轮拥有的诊断 Job；该轮失败，未完成原生验收。保留原始脚本、报告、命令和日志，不能用它的样本证明绘制热点。

## 独立排版计时

使用 SDK46 已导出的 `xuiProxyXgeVisitTextShape` 和 `xgeEmojiPackMatch`，严格 O2/Werror 编译一个不绘制、不创建 GUI 的夹具。实际原生运行退出 0，43.0 秒，完成 16 条观测。SDK 的内部 `xgeInternalTextShapeVisit` 未导出，首版夹具因此链接失败；第二版使用公开接口，但清理代码触发严格缩进警告；第三版在新文件中修正，未降低警告等级。

输入来自已通过原生窗口矩阵的 16 MiB xlang 单行样本，2 MiB 前缀截在完整 UTF-8 边界。主字体为 Noto CJK 20 px。每种模式连续运行两次，字体保持相同，默认 Emoji 包只在此诊断进程内切换。模式之间故意改变排版参数；未预热字形图集，未执行 SVG 绘制。此夹具测量的范围与 GUI 帧不同。

16 MiB 的三种完整排版模式各访问 11,615,000 个聚合文本簇；内建 Emoji 模式与单独匹配均找到 645,277 个 Emoji。两次同模式的访问数量、Emoji 数量及最终宽度一致。关闭 Emoji 和空包得到相同字形模式宽度；Emoji 模式的宽度不同，不能把两种模式相减当作精确的 Emoji 开销。背景负载未隔离，顺序运行可能引入缓存与负载变化。

## 下一步范围

两种诊断支持继续检查整段匹配与度量路径，但尚不足以给各路径分配精确耗时。可以试验有界、单次调用内的短前缀 Emoji 匹配复用，保留完整最终度量与画笔相加顺序；这是待验证的方向，本轮没有实现或验收该缓存。

匹配会读取当前簇以外的字节来处理最长匹配、ZWJ、变体选择符与肤色归一化，不能只用当前码点或已匹配长度作为缓存键。后续实验必须记录实际读取范围与是否触及结尾；超出有界前缀、包修订号饱和或状态不能确定时沿用原路径。检查点恢复也必须保留相同的读取依赖。自定义包替换、默认包自动激活、错误输入、运行时资源失效及原绘制像素仍需完整比较。

原始结果见 `build/editor-paint-profile-mi-v2.json`、`build/editor-paint-profile-mi-v2-analysis.json` 与 `build/editor-paint-profile-timing-v3.json`。夹具源码和驱动在同目录，失败版本保留。上一实现阶段见 `docs/large-source-paint-collect.md`。长期目标 active，sdkInstalled=false，productionChanged=false，formalRelease=false。
