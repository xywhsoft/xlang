# 独立的已检查函数单元

2026-10-28，M7a2b64a / 开发服务 0.94。本阶段补齐原生分析核心的数据所有权接口，没有将它放进每次键入的默认路径。持久语义／类型／最终 IR 局部重建、按需整树物化和整体性能仍未完成；继续使用外部服务，未合并 xlc.dll，无 DAP 或运行／调试态补全。

## 新增能力

`analysis/function_unit.h` 提供不透明的 `xls_function_unit` 和 `xls_function_set`。从成功完成原解析、导入、stdlib、语义、typed IR 构建及完整验证的结果中，可以显式导出一个函数，或一次导出全部函数并共享来源元数据。普通检查、补全和签名帮助不自动创建这些副本。

单元独立拥有完整的检查后函数 AST 与 inferred／declared type 树。复制复用已有 `xlsAstClone`，容器、内存和原子引用计数使用编译器 XRT；没有另建语法、类型系统或检查规则。函数、async／export 函数、方法、嵌套及匿名函数按原 AST 子节点前序枚举。extern 等模块声明、完整类型注册表和最终 IR 不属于该集合的完整交付范围。

读取接口提供节点全部逻辑字段、父子／类型边、文档、显式长度字面量、来源／范围及语义类型／符号／ABI／所有权／区域事实。另有原采集器生成的精确索引行，包括全模块别名上下文中形成的 canonical 类型；没有在一个缩小的临时模块上重新采集类型。所有这些读取均不分配内存、不读文件，也不需要物化另一棵 AST。

原生产检查结果、会话或调用方的 worker／store 引用释放后，已保留的单元仍可读取。私有兼容消费者可显式生成一个独立可变 AST 副本；这只复制原域中的值，不会把 native ID 或类型声明自动绑定到另一次编译。

## 使用与所有权

```c
#include "analysis/check.h"
#include "analysis/function_unit.h"

/* checked 已完成输入验证和完整检查；省略错误处理。 */
xls_function_set* functions = xlsSemanticCheckFunctionsCapture(
    checked, 128u * 1024u * 1024u, NULL, NULL, error, sizeof(error));
xlsSemanticCheckDestroy(checked);

xls_function_unit* function = xlsFunctionSetUnit(functions, 0); /* 一个 owned ref */
xlsFunctionSetRelease(functions);
xls_function_node root;
xlsFunctionUnitNode(function, 1, &root);
/* root 中的文本借用 function，不能单独释放或修改。 */
xlsFunctionUnitRelease(function);
```

集合和单元分别引用计数；取出的单元可以比集合活得更久。集合内只保存一次独立来源元数据，各函数共享该所有者；取消、资源拒绝或来源变化不发布部分集合。构造时保留生产检查结果，在第一次取消回调之前取得该引用，返回的对象不保留生产检查结果。回调可以重新验证／查询生产者，或者释放调用方的生产者引用，内部捕获引用仍保证其构造期存活。

元数据复制路径、来源种类、原始／解码长度与散列、文件身份、负向导入探测和包环境，保留显式空值与未观察值的区别；不向来源记录复制正文。单元另行保留独立 context、module graph 和 entity view。其既有 store 可以继续缓存或淘汰普通语法／正文，因此不能把局部元数据字节数解释为所有间接保留内存。

## 身份与新鲜度

- 节点 ID 从 1 开始，只属于这个单元，0 表示不存在的边。类型边也有节点 ID。
- 原索引行的 id、parent、source、selectionSource 仍属于原完整编译；根行的 parent 可以在函数外，不能当成单元局部 ID。
- SymbolId、TypeId、RegionId 等保持原编译器值。独立 entity view 保存原域中的映射；稳定 entity／接口身份不证明正文、类型或依赖不变。
- 来源记录是历史输入戳，不是自动新鲜度验证。发布当前 LSP 结果或用于另一次分析之前，仍需当前输入／overlay 版本、完整依赖及重绑定证明。不能因为旧单元可读取，就把它当成当前编辑版本的结果。

`check.c` 只增加一个私有的不可变输入行视图；该 report 值排除会被验证过程修改的 complete／error 字段。原始来源行、探测和已捕获文件信息在发布后不修改，构造最后仍由原生产者验证决定是否允许发布。这也避免在持有生产者互斥量时调用用户取消回调。

## 常规路径与资源边界

早期候选在检查结果上增加了惰性来源缓存字段及销毁调用，实际编辑补全出现退化，未接受该实现。修订版将所有导出／集合管理移入独立的 `function_unit.c`。去掉新私有 getter 及其 include 后，完整 `check.c` 与原 0.93 逐字节相同，包含原结果结构、构造、销毁和所有既有函数。

实际默认服务器没有链接 unit／set／origin／capture 管理符号。Windows PE 链接器保留了小的私有输入 getter；完整反汇编未发现其外部 call／jmp 入口。这里证明的是默认路径没有新增单元管理调用，不声称代码体积为零，也不以此替代端到端性能验收。

已知数据的局部限额为每单元 64 MiB、共享来源 16 MiB、集合 256 MiB；集合计入来源一次、全部单元及句柄容量。单元／集合函数数量上限分别为 65536 节点／65536 函数，遍历深度上限 512。独立 store、context、分配器、克隆临时映射等不属于这些局部配额；它们不是全局／进程峰值预算。资源失败返回导出错误，不伪造源码诊断，也不修改已接受的检查事实。

批量导出当前仍遍历原结果、检索原采集器范围并复制函数树；嵌套函数也能独立取出。它是独立数据边界和现有结果的显式导出接口，尚不是每次编辑的持久单元生产器。不能通过把这次导出直接插入键入路径来宣称实现增量或按需物化。
