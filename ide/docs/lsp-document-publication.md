# 打开文档的基线租约与模型发布

M7b5a，2026-11-11。后续 WorkspaceEdit 应用需要在工作线程比较候选正文与已保存基线，还需要在第一个文档通知前发布整组模型状态。`editor/documents` 现在提供这两项能力；它们与已验收的 XUI 批量载荷原语实际联合验证，尚不是完整的 IDE 应用器或协议入口。

原有 baseline.raw/text 由文本编解码器 malloc，保存、重载和关闭会释放。捕获 `xideDocumentRetainBaseline` 时只惰性创建一个小包装，把原缓冲的所有权交给包装，模型保留只读视图；不扫描或复制正文。模型和工作任务复用 XRT 的 checked native reference API，不另外实现引用计数或把 malloc 指针错误交给 xrtFree。包装本身使用 XRT 分配，最后一个所有者通过既有 TextFileClear 释放原 malloc 缓冲。

后续捕获只保留同一包装。保存/重载/关闭先清除模型视图及缓存句柄，再释放模型的一份引用；任务可以继续读取旧原始/规范化字节、BOM 和 EOL。工作线程释放最后引用也安全。`Read` 返回借用的不可变快照，调用者必须持续持有租约；模型和工作任务不能直接修改它。存储估算保守计入包装及两个以 rawLength 为上界的编解码缓冲，不是分配器/RSS 上界。

活着的租约同时是基线身份：正文修订不变也不能省略该检查。用户在任务准备期间保存当前脏正文，XUI 的正文/历史围栏可能仍通过，但已保存基线已经改变，先前算出的 dirty 结果应拒绝。协调器必须把基线租约保留到提交围栏结束，不能仅保留一个可复用的地址值。

`xideDocumentPublishPrepared` 只用于 XUI 的 published 钩子：调用方已验证并固定打开文档、正常修订、基线和预计算 dirty 结果，整组调用完成之后才允许任一通知。它推进正文修订，发布模型及 SDK dirty，并登记该版本的待消费通知；不比较正文、刷新语法或调用应用回调。普通变更回调消费预发布标记，避免重复推进修订或重新扫描已保存基线，然后照常刷新语法和通知 UI。普通输入仍走原有 dirty 计算，仅增加一个常量时间标记分支。

提交返回后必须调用 Finish，包含发布后错误或后续通知被跳过的情况；遇到其他版本的普通通知也会清除旧标记并恢复正常处理。每个文档仍单独撤销，早先的历史保留；该助手不建立全局撤销，不做准入、用户批准或磁盘写入。

新增程序通过 53 项检查：实际 C/xlang 模型、首次捕获分配拒绝、同一指针/原字节捕获、跨保存和关闭的工作线程读取/最后释放、关闭槽复用、真实工作线程 XUI Stage、两文档发布、基线单独变化拒绝、撤销/重做和关闭时跳过通知的清理。通过真实 DLL 导入槽观察 XRT 引用的 1→2→3 及模型/任务释放到 0，避免靠未释放的旧字节碰巧可读来冒称生命周期正确。

第一个实际模型通知能够看到两份文档的正确正文修订、模型 dirty 和 SDK dirty。一个文档被编辑回已保存正文时 dirty 为 false；回调不把预发布修订再加一次。实际 Context 在第一个通知中请求关闭，后一个通知跳过，但已发布状态保持，Finish 清除未消费标记；之后清空模型、完成 Context 关闭，保留的旧基线仍有效。

测试覆盖的模型发布本身无直接 XRT 分配。语法刷新、应用观察者、XUI 通知/缓存以及最后所有者的清理仍有成本，不能称整个 IDE 操作无分配或已通过延迟准入。首次捕获增加一个包装分配，模型增加租约指针和发布标记；普通文件读取/保存仍有原编解码拷贝。

最终重编 119 个 IDE 对象，通过 41 项 GUI/配置回归。九个实际实现变异破坏租约保留、模型引用释放、缓存/视图清除、捕获正文不复制、发布修订、通知单次推进、SDK dirty 发布和通知标记消费，均在预期断言处失败。GUI 运行时没有通用内存统计 API，本阶段明确依靠实际引用转换、同一缓冲地址/字节和专项分配观察验证，不冒称全堆泄漏或峰值内存验收。

构建必须匹配修改后的文档布局，全部 IDE 消费者重编。专项需要 batch-v2 SDK；旧 SDK 下明确返回 77，不冒称通过。最终构建、GUI 回归、实现变异及完整输入/库身份见材料索引 `dev/release-materials/provenance/lsp-document-publication-20261111.json`。默认发布程序、SDK、交付索引及服务镜像保持。
