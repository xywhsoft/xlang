# 原生候选 RPC 与后台协调

M7b5z，2026-11-13。外部服务现在实现 `xlang/renameCandidate`，初始化时以 `experimental.renameCandidate: 1` 表示原生后端支持；CLI 后端为 0。它返回只读候选，不启用标准 `textDocument/rename`、WorkspaceEdit 应用或 IDE 菜单操作。

参数沿用已实现的编辑调用：正整数请求 ID、精确 URI/版本、UTF-16 位置、新名称，以及 `xlang` 中的 schema、16 位小写十六进制令牌、原始 catalog、在线输入回执、独立根列表和范围数量。服务独立保留已经确认的 catalog；后台要求请求副本与之相同，再从该确认配置和独立根重建范围。独立根必须是绝对、未被项目拥有的 `.xl` 路径，不得重复；所有在线 xlang 文档都必须在完整范围内。被选文档按原来的项目选择规则绑定，不能用请求自证项目归属。

后台从捕获的精确 URI 与有符号版本重算原有 SHA-256 输入回执，不扫描或重哈希源码正文。严格拒绝额外字段、错误类型、过期版本、错误回执、重复/遗漏/无效根、超限范围和非法原生名称。解析器已解码的参数、已确认的 catalog 和不可变文本按引用保留；提交只复制最多 2 MiB 标签，最多 64 个在线文档。

`rename_candidate` 是独立 C/XRT 协调模块，借用原有引用服务。单个后台线程、四个排队任务，协议层同时最多四个请求。后台准备元数据、向原有引用协调器提交原生光标分析，并等待它完成全部成员、声明关系、精确引用和假想源码静态复检；两个协调器使用不同的任务池，没有同池嵌套等待。候选和全部原始守卫导出后，在同一后台线程建立绑定外壳并完成 JSON-RPC 帧编码。

成功结果包含 schema、binding 和 candidate。binding 精确回显方法、令牌、实际输入摘要及文档数；candidate 保留既有 schema、scopeCount、WorkspaceEdit 和完整 inputGuards。编码整个外壳后，通过 `xideProjectReferencesRenameValidate` 再扫一次全部原始守卫，覆盖零目标提供者和首次光标提供者。编码失败、变化或取消不发布部分帧。既有 7 MiB 候选和 8 MiB 帧上限继续适用。

协议 owner 只捕获固定文档清单、记录身份/版本/inputSerial/configurationEpoch、检查入站输入队列并写入已经编码的字节。取消、关闭重开、内容变化、配置切换、服务关闭或分析挂起会丢弃原请求结果。分析租约同时检查协调任务池的真实物理静止和原引用服务静止；future 已取消不能冒充工作线程已退出。原始 DOM、候选和原生输入在后台退役；owner 仍使用已有的有界分块、阻塞 stdout 写入方式，没有全链路异步传输或时延资格声明。

验收覆盖 35 个真实 stdio 场景：四范围导入声明与限定名、独立单文件、完整守卫、版本极值、绑定字段、无关错误范围、取消、有效文档变更、同 URI/版本关闭重开、配置 epoch 变化、租约等待/恢复、非法 ID、CLI 后端与标准入口保持关闭。独立原生专项用实际帧编码包装点，验证编码后物理文件身份变化、编码失败、取消和真实静止、后台线程及所有输入释放后的结果所有权。首次协议验收错误地把有意拒绝的无效 didChange 的日志当作失败；最终验收只接受这一条精确预期日志。

IDE 专项沿用完整 owner/worker/stdio 路径，改为真实原生候选正向返回；C/xlang 输入、删除、撤销、IME、焦点和完整时序门槛继续验证，收到候选后源码保持原样。还保留原有 207 项光标候选、来源报告、提供者范围和静态复检回归。八个实际错误实现由断言拒绝，不把编译失败、进程崩溃或未执行变体当作成功。详细实际构建、最终夹具和运行库身份见 `dev/release-materials/provenance/lsp-rename-candidate-rpc-20261113.json`。

完整客户端守卫导入/提供者覆盖/静态结果/WorkspaceEdit 审批、常驻后台控制器、能力协商后的 UI 启用、客户端协议取消发送、物理写入/别名策略、事务/确认/恢复和标准协议启用仍待完成。服务收到候选请求并返回完整原生证据，不等于客户端授权修改。当前引擎资产对齐、完整泛型/非绑定/外部来源覆盖、其他同步读取点、全目标性能/资源/长时间运行、Linux 和 sanitizer 验收仍开放；没有 DAP、运行态或调试态补全。默认发行程序、SDK 和当前交付索引不替换。
