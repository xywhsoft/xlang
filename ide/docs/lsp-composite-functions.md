# 独立原生函数的组合所有权（M7a2b111）

本阶段为普通增量检查省去未变化函数 AST 复制补齐所有权基础。一个新的有类型模块可以同时持有本轮创建的函数和来自多个旧轮的独立函数所有者；不保留旧模块根、检查或报告。该接口不证明语义、输入或原生编号可以复用，普通检查尚未启用借用。

## 构造与退休

`xlsTypedModuleTakeBorrowed` 只接收未发布的模块根和与其直接子槽一一对应的所有者数组。非空槽必须精确指向相应的不可变原生函数；空槽转移本轮独占子树。验证及必要的模块／指针数组分配发生在任何所有权变化之前，失败保持输入原样。

成功时逐槽独立持有借用函数，暂时从根展示中隐藏这些槽，再为新函数建立原有森林所有者，随后恢复展示。可选身份、森林或互斥锁分配失败不改变语义树；新子树仍可随根退休，借用函数仍有独立引用。构造过程中没有发布或回调，最多接受 65,536 个直接槽。

退休时先从展示根移除借用槽，再按原路径释放新树，最后释放各旧函数引用。不会嵌套持有新旧森林的锁；旧函数继续使用其原 XRT 锁，串行处理共享来源记录和池的析构。IR 结果保留组合模块即可拥有完整输入，生命周期无需依赖外层检查。

模块查询按当前直接子槽返回函数句柄。句柄的 `RootSlot` 仍是原森林中的槽；重排后若与当前索引不匹配，原资产查询安全拒绝，显式捕获继续原事实定位／复制路径。本接口不重新解释来源、符号、类型或区域编号，也不允许写入借用函数。

## 集合配额

此前显式函数集合按一个模块只有一个原生森林扣除共享元数据。组合模块打破该假设；现在分别以原生森林和索引来源目录的稳定所有者身份分组，每组已知元数据在集合中计入一次。不同森林绝不因来自同一新模块而合并，同一个当前索引目录也不会因跨森林被重复计入。

构造单个单元之前，只将已计费的相同组容量返还给其可用配额；完成后扣除对应重复量。独立单函数捕获继续完整计入其原生／索引元数据，原 64 MiB 单函数与 256 MiB 集合上限保持。零／不足配额及分配失败拒绝这项显式捕获，不制造源码诊断或部分集合。

新增 XRT 分组表只在显式集合构造时存在，返回前销毁。普通检查不建立此表，也不因此扫描函数体。它与原地址表一样属于临时构造开销。计费是已知保留节点、字符串、容器容量和共享元数据的配额，并非进程物理内存；XRT 分配器、共享池实际 backing 和临时表额外占用继续单独看待。

## 验证与边界

活动目录为 `ide/build/Release/lsp-composite-functions-20261102/`。定向诊断覆盖四个原生森林中的六个函数、共享池、零 AST 克隆、精确配额及少一字节拒绝、四个实际构造分配拒绝点、55 个集合分配／容器拒绝点。真实 xlang 和 C 结构体互操作语义树另验证两个森林共用一个当前索引目录、完整原事实和规范字符串共享，以及旧检查退休后的原始完整 IR 一致性。

早期定向测试的两类夹具错误保留：原 AST 的递归析构不会再次经过公开函数包装器，改为观察实际叶节点分配释放；不缓存的一次性检查不保证提供可导出模块，真实组合测试改用 IDE 实际使用的会话检查。诊断链接还修正了将内嵌 `function_unit.c` 的故障夹具与另一个同名对象重复链接的问题。失败报告与对应输入不改写。

`focused-v4` 的七个诊断程序通过。新增组合测试共 729 项检查；原单元 31,367 项、单元故障 1,020 项、原索引资产 1,871 项、模块 167 项及模块故障 673 项继续通过。组合配额的具体数值随包含源路径的长度变化，测试按本次真实容量验证精确及少一字节边界，不硬编码路径相关容量。

`full-v1` 完整重建 228 个编译单元、131 项原生测试和 136 个私有 AST 消费者，808 项输入／133 项产物闭包通过。私有 AST 头与 M110 逐字节相同。`omissions-v1` 的七个控制／故障案例、19 条命令通过，实际遗漏借用保留、借用摘除、借用槽查询、森林身份和索引目录抵扣分别被确定断言拒绝。摘除检查在原递归析构开始前观察根槽，避免仅以悬空读取崩溃当作证明。

`wire-v1` 的 131 个进程、168 次增量／全新检查、336 项导航和 26 次补全通过。`validation-v1` 连同原 56 套协议共 58 条命令全部通过；808／133 当前闭包、807／132 前一基线的精确历史别名和七项根运行时均核对。此次不重测未变化的普通分析流程来选择通过的性能结果，也不将前一阶段的失败门槛改成通过。

功能接口只补齐组合持有及分组计费。接下来仍需在当前输入、坐标、符号、类型与最终区域证明成功后接通普通函数借用；任何省略后的证明失败都必须丢弃私有尝试并重走原完整路径。普通 AST 物化、最终 IR 局部生产，以及完整 LSP／SDK／IDE／GUI／规模与性能目标继续。

接通跨轮保留前还必须控制实际被固定的共享池容量。单个小函数可能与大模块共享存储，不能仅以逻辑节点大小约束历史保留，也不能让逐轮替换固定无限多份旧池。当前显式捕获的既有计费范围不自动构成跨轮缓存的物理内存上限。
