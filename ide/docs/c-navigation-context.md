# C 导航的项目上下文

F12 从项目源文件打开隐式头文件后，头文件继续使用来源项目当前的宏、包含目录、强制头及桥接声明。之前同一声明可能在源文件中显示为 `double`，打开头文件后却回到默认的 `int`。上下文保存在打开文档中，供诊断、定义、大纲、悬停与补全共同使用。

## 关联规则

- 文件明确属于工程时，沿用已有拥有项目规则：所选拥有项目优先，无法确定的多个归属拒绝分析。
- 未归属的 `.c/.h` 导航目标继承已核验来源的项目 ID、源文件路径及可用的稳定文件 ID。导航来自另一个隐式头文件时继续传递原始来源。
- 从其他项目再次 F12 到同一个已打开头文件会更新上下文。切换右侧当前项目不会擅自改变这个隐式头的来源。
- 来源文件改名后通过稳定文件 ID 查找现有路径。路径相对于项目清单保存，跨卷路径按路径服务规则保留。项目或来源不再可用、来源被删除或类别不再为 C/header 时拒绝沿用；不会悄悄改用独立默认宏。
- 上下文只是编辑器分析关联。隐式头不会被加入工程树、`cSources` 或构建输入，正文、撤销栈和脏状态不变。关闭文档清除关联，重新从文件菜单打开仍沿用通常的文件归属规则。

编译命令由当前来源项目生成，仅替换最后的源文件操作数。当前配置、工作目录、目标、宏和桥接环境保持同一来源；所有打开文档的正文、版本、关联、工程模型及服务器选择一起冻结。关联或配置改变撤销旧批次。

## 会话

原生 `openDocuments` 的可选 `cAnalysisContext` 记录 `project`、`source` 与可选 `sourceId`，随会话恢复。字符串验证 UTF-8、非空及长度，关联对象最多 128 KiB；未知扩展字段保留。非法会话元数据按原有策略保留原文件。该关联不修改原项目的配置格式。

## 验证和范围

`c_header_context_view_test` 在独立 Windows 桌面运行真实 XGE/XUI 和实际 clangd。52 项原生断言覆盖项目宏 F12、配置变更与旧结果撤下、两个项目的共享头上下文切换、未保存头覆盖和撤销、源文件改名、会话恢复、未知字段保留、非法会话关联拒绝、来源删除失效以及关闭清除。保存五张真实界面图和服务器返回的悬停原文。

隐式关闭头文件的首次导航用实验性实际输入观察提供者验证。发行候选继续使用固定官方 clangd，其关闭目标导航仍受已有显式磁盘守卫限制；打开文件的上下文机制不要求实验扩展。普通官方服务器、C/xlang 语法和现有真实语义门继续参与完整回归。该修复不代表完整 C 预处理图、TCC ABI 等价性或正式首版已经验收。
