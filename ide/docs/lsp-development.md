# xlang LSP 长期实施计划

2026-10-22 启动。首版交付物继续为外部 `xlang-ls.exe`，分析核心按可嵌入的 C 模块组织，后续再合并到 `xlc.dll`。本期不将新能力写入该 DLL，不包含 DAP、对象检查或运行／调试态补全。

本期动态补全指基于当前未保存、不完整代码、作用域、接收对象类型及流分析实时查询候选。性能优先于扩展功能数量；协议能力仅在实现与验收完成后声明。

## 架构与复用

- 宿主负责启动、传输和生命周期；协议层负责 LSP；分析核心负责输入、快照、增量计算和原生查询。
- 复用 xlang 的词法／语法、名称解析、类型和模块解析规则。公共模块以共享源码或明确适配接口使用，禁止复制后维护另一套语言规则。
- 优先复用 xlang 配套的 XRT 数据结构、字符串、分配和同步设施。热路径采用有类型数据；JSON 限于协议、配置及兼容接口。
- 当前原型以匹配的 XGE/XRT 运行，迁移到 xlang XRT 时使用独立配置与所有权检查，不在同一进程混用不匹配的容器或分配器。
- 核心头文件不依赖 XUI、IDE 项目模型或 stdio。DLL 迁移以不透明句柄、只读结果视图和创建方释放为边界。
- CLI 检查与现有单次 API 保留为兼容后端和正确性对照；常驻增量核心逐步替换高频路径。

## 里程碑

| 阶段 | 功能切片 | 验收 |
| --- | --- | --- |
| M0 | 可回放的真实 LSP 性能基线与证据 | 关联服务／编译器摘要，区分首次、重复和编辑后查询，校验实际候选 |
| M1 | 可复用文档核心与 UTF-16 增量同步 | 多编辑顺序、Unicode、CRLF、范围／容量、失败原子性；服务兼容全文同步 |
| M2 | IDE 增量发送、能力协商与端到端观察 | 命名文档、重连全文重同步、旧服务回退、版本／候选有效性及原生交互 |
| M3 | 前端／XRT 资产适配与常驻分析会话 | 不修改首版 DLL；明确资产闭包、所有权、会话／快照和输入配置 |
| M4 | 容错语法、声明摘要与增量依赖 | 语法／函数边界复用，改变范围与新鲜全量分析一致 |
| M5 | 语义查询缓存与精确失效 | 作用域、类型、泛型／重载、流分析；接口未变停止传播 |
| M6 | 自动静态检查与动态补全 | 不要求手工先检查；错误／未保存依赖下可查；取消、预算和过期保护 |
| M7 | 工程索引与完整适用协议能力 | 多项目／配置、导航／引用、参数提示、符号、语义高亮、可验证重构及格式化 |
| M8 | IDE、外部客户端与交付 | 默认包、搬迁、兼容、长时间运行、内存预算及完整性能回归 |

每个可独立验收的功能切片完成后提交范围明确的 commit。其他并行任务的工作树和暂存区保持原状。阶段证据保存在 `build/lsp-next-20261022` 或该阶段单独目录；源码和测试纳入 Git，生成程序与运行记录不加入发布目录或提交。

M1 的文本增量同步不等于语法／语义增量分析；M3 的常驻进程不等于已经复用了分析结果。各项以实际重算计数和时延证明。

## 性能与正确性

目标参考环境为现代 8 核 CPU、32 GiB 内存、NVMe，分别测试一万／十万／一百万行工程。初始预算：缓存查询 P95 ≤10 ms，普通编辑后补全到显示 P95 ≤50 ms／P99 ≤100 ms，3000 行局部语法更新 P95 ≤10 ms，局部函数语义更新 P95 ≤50 ms，当前诊断含调度 P95 ≤150 ms，十万行首次完整分析目标 ≤2 s。以上为目标，不是当前成绩；基准须记录硬件和规模，不能用局部就绪时间冒充全量完成。

同时测量队列、CPU、分配量、内存、重算函数／模块数、取消响应和 UI 同步工作。后台索引不能阻塞交互队列；UI 新增同步工作单次预算 ≤1 ms。先记录基线，再优化和收紧门槛。

固定输入上的增量结果必须与全新分析等价，覆盖连续输入、删除、重命名、导入和解析候选变化、配置变化、Unicode、取消、失败恢复及服务重连。同一物理文件在不同配置下分别建立语义上下文。

## 基线命令

```powershell
python -X utf8 -B .\tools\benchmark_lsp.py `
  --server .\release\xlang-ls.exe `
  --compiler .\release\toolchains\xlang\xl.exe `
  --output .\build\lsp-next-20261022\baseline-initial
```

该基线只测真实 stdio 服务与当前编译器的单文件光标查询往返，含客户端 JSON 编码，不测 UI 绘制，也不代表工程全量、语义增量或百万行能力。全部样本逐次验证版本、候选和替换范围，测量失败不能作为成功样本。

## 当前状态

长期目标 active。实施起点为既有 `xlang-ls` 0.4、IDE 提交 `deb1936f8` 及已验证构建 `cb-bd75b462`。原型已具备快照检查、补全、定义、悬停、大纲和失效保护；每次编译查询仍主要走单次编译器进程／编译单元，尚未达到本计划的常驻语义增量目标。

M0 已完成：`benchmark_lsp.py` 使用发布目录的真实服务和随包编译器通过 62 次候选／版本／替换范围检查，4 行与 304 行样例各 15 次重复及 15 次编辑后查询。证据见 `build/lsp-next-20261022/baseline-v2/result.json`。重复查询 P95 分别为 200.052／186.345 ms，编辑后为 296.814／173.298 ms；首次查询分别为 186.396／172.064 ms。这是当前主机的小样例 stdio 基线，尚无 UI、内核 CPU、全工程或语义增量的性能结论。
