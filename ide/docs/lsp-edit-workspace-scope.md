# 完整工作区的编辑请求范围

M7b5w，2026-11-13。编辑请求在已有同步文本、Document 槽位及工程 catalog 之外，捕获完整工作区文件路径清单。尚未打开的独立 `.xl` 文件因此不会遗漏；后台不需要借用 app、工作区或控件指针。

捕获只复制路径元数据，继续共享原有不可变文本和配置。模型部分上限仍为 4,096 槽、1 MiB；工作区部分最多 65,536 槽、2 MiB 指针及字符串，每条 UTF-8 路径最多 262,144 字节。两部分放在同一块 XRT 分配中，总计不超过 3 MiB 已知对象及元数据；同步器元数据、共享正文/catalog、分配器和临时工作另外计算。调用方在两次捕获期间保持模型和路径列表稳定。没有源码正文扫描或文件读取，也不声称整个 IDE 的延迟已经达标。

后台 `xideEditRequestScope` 从捕获的 catalog 复用既有配置解码、全工程成员索引和 `rename_scope`。它纳入未打开的工作区 `.xl` 路径，以及具名、打开且语言为 xlang 的模型。已被工程明确登记的路径保留全部工程角色，不凭打开状态额外添加独立默认配置。其余独立入口按既有原生词法键去重；目录、导入、同名前缀和 C 文件不会成为额外所有者。显式登记的外部工程成员仍沿用原有规则。

范围最多 64 个角色，沿用 128 MiB 完整已知保留收费及 context 上限。临时 catalog、路径键、上下文构建和分配器成本额外；元数据构建及回收在后台执行。取消或请求失效会拒绝整个结果，容量不足也不能截断成部分工作区。结果独立拥有配置，原请求、同步器及 GUI 销毁后仍能使用。

`Current` 在原有发布边界追加完整路径清单比较。普通工作区刷新即使工程 catalog 未变化，也先核对文件清单并不可逆地使旧请求失效；新增后删除、改路径后恢复不能通过两个正常通知来复活旧请求。只改变显示 ID、kind 或工程显示文本不改变这些路径身份。直接绕过所有通知、比较边界且恢复原值的外部写法不属于宿主支持的修改流程。

本阶段只准备独立来源配置；并未证明每个根及成员都已完成原生分析，也未建立方法、ID、令牌、连接或远端响应绑定。把完整独立根发送给服务、来源覆盖检查、编辑事务控制器、用户确认/恢复、标准 rename/applyEdit 启用、其他同步读者、最新引擎对齐和全目标性能/资源验收仍需继续。C LSP 保持关闭，不包含 DAP 或运行/调试态补全。

验收中，新增后台范围专项在独立 XRT 下通过 78 项检查（包括 8 个可观测外部 XRT 分配拒绝），在 GUI DLL 下通过 69 项；均覆盖 23 个取消位置、真实 65,536 路径清单、64 角色及 2 MiB 元数据边界。原有请求专项扩展为同时持有路径清单，通过 58 项及 8 MiB 正文共享/四读者生命周期检查。真实 IDE 请求专项本次通过 140 项，涵盖缺失且未打开的工作区文件、后台构建、路径直接改变、正常刷新下的文件增删 ABA，以及 C/xlang 输入、删除、撤销、IME、焦点和六参与者屏障。

GUI 完整重编 130 单元，另通过 55 组既有回归及各 24 帧的 C/xlang 窗口验证。语言服务沿用上一阶段完全相同的字节及其已验证原生资产，没有重编或替换默认服务；其既有 50 个协议用例证据随继承索引绑定，不作为本阶段新执行的检查。十个实际变体放宽路径快照、成员选择、去重、容量、取消或访问器后均被断言拒绝。构建、测试程序和原始失败日志保存在独立资料包；小型索引为 `dev/release-materials/provenance/lsp-edit-workspace-scope-20261113.json`。原始失败包含首次独立测试缺少同步器链接单元，以及首次 GUI 夹具缺少私有副本的 include 搜索路径；后续均保留完整修正回执，不以编译失败计入变体拒绝数。
