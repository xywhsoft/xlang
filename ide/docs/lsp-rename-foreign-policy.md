# 语义重命名的外部声明策略

后续的 [WorkspaceEdit 准备层](lsp-workspace-edit-staging.md)已提供客户端不可变正文、版本/范围检查及来源证明对接；XUI 原子应用和完整协议入口继续开发。

原生声明族现在单独保存重命名排除标记。普通定义、引用和声明族查询继续返回这些符号；只有重命名候选应用排除策略。

策略直接读取当前受检查索引中的原生 AST kind、flags 和编译包标记，沿原有父节点链检查，不另写词法器、不搜索源码中的名称或注解。读取无分配、无 I/O、不保留 AST；父链最多 256 层，非法索引、非法父链或超限返回不支持。

保守排除 C 外部函数、变量、类型别名、原生记录及成员、带显式 C 链接名的导出声明，以及编译包拥有的声明。排除沿原生声明的祖先生效，覆盖外部声明内的可绑定参数。普通语言 `export func`、类和局部变量不会仅因导出而被排除。即使外部声明已有独立的 C 名称，首版仍排除它：原生契约可能含非引用形式的名称，不能只改普通引用后宣称完整保留了外部 ABI。

直接声明族、独立声明图及多个提供者的组合使用同一策略。标记在声明去重前按位合并，重复来源、继承、重载和跨配置组合都不能使排除标记消失。捕获后的标记由不可变声明族拥有，原检查和缓存释放后仍可读取。

工程 actor 在完整来源防护和声明族组合后检查策略。任何连接成员被排除，整个改名候选失败；不继续收集编辑、构造计划或执行假设正文的原生复核。原有引用查询仍可使用同一个缓存提供者。该策略没有引入新线程、解析器、常驻 AST 副本或普通分析的额外索引遍历；声明族构造中的父链读取和少量标记存储属于按需成本，尚未作端到端速度承诺。

这只是重命名策略的一部分。完整泛型来源、未绑定及生成事实的覆盖、物理别名与写入策略、版本化 WorkspaceEdit 和 IDE 原子应用仍需完成，标准 `renameProvider` 继续关闭。编译包标记的受控注入测试只证明策略传播，不代表已经验收完整编译包加载器。

M7b4t 验证完成 305 个实际编译消费者；189 个原生程序、13 套协议及匹配 SDK 下全部 116 个 GUI 对象重编译后的 29 项 IDE 回归通过。新增策略专项有 1,112 项断言，工程专项共 418 项，覆盖普通引用保留、冷暖缓存拒绝、关闭文件的改名候选及源文件不变。浅色、深色语义颜色和属性引用截图已复核。四个实际实现变异均在相应策略断言处被拒绝。

首次工程测试误向引用接口传入零文档/空触发键；该入口与已支持零打开文档的改名候选入口不同。修正调用参数后只重编译该测试消费者；产品代码、公开头文件、服务程序和 IDE 消费者保持同一批字节。最终原生记录组合前段 155 项未受影响的成功原件和随后 34 项执行结果，不冒称全部重跑。此前误被测试参数拦截的工程变异不计入有效拒绝；最终变异检查先要求正常矩阵通过，并核对具体失败断言。原始失败和继承链接路径适配失败均保留。
