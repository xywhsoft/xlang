# WorkspaceEdit 已固定文件的写入与恢复

M7b5d，2026-11-11。`platform/workspace_edit_write` 从[恢复准备包](lsp-edit-spool.md)构造单个关闭文件的工作线程写入对象，拥有经过验证的原始 before 和编码后 after 缓冲区，沿用准备包固定的源码与祖先句柄。它使后续混合文档事务具备逐文件应用、部分写入证明和显式恢复的基础。本阶段未启用标准重命名或 `workspace/applyEdit`。

## 对象与边界

Prepare 只接受新构造且仍持有源码门闩的准备包；打开覆盖文档及重开后的纯恢复包均拒绝。准备包和门闩必须比写入对象及所有操作活得更久。每正文最大 16 MiB，对象及两份原始缓冲区的默认已知存储额度为 128 MiB、最大 256 MiB；这不包括准备包、计划、多文件组及通用分配器开销，后续协调器还须做整组准入。只有 Prepare 分配这些缓冲区，不在写入循环临时创建正文副本。

内部 `workspace_edit_files_internal` 只向工作线程写入器借用源句柄；不向 UI 或协议暴露句柄，不转移所有权。借用时检查选中目标的普通单链接可写状态、当前路径身份及对应的已固定祖先，不逐文件重复打开所有其他源文件的路径。完整原始 Validate 仍检查整个原始组，不应用于已经变更的成员；后续协调器必须分别管理每个成员的前后状态。

对象不包含 GUI 指针。所有操作顺序执行，同一门闩及其共享文件位置不能由其他工作线程并发读写。状态查询只是复制最近观测的结果，不能代替提交前的物理/模型/请求复核。Destroy 不写入、不自动恢复、不删除准备包或意图记录。

## 应用与恢复

每个对象只允许一次 Apply 和一次显式 Restore。Apply 在宿主回调前后核对完整原始快照，再从已持有的句柄分块写入、截断、flush，明确设置最终写入时间并再次 flush，重读验证 after 长度和 XRT SHA-256。源文件身份保留。原始与待写字节完全相同时不调用源写入、截断、flush 或时间设置，保留混合换行和原时间。

宿主 fence 必须提供，返回 true 的契约是：已建立整组请求、来源、物理别名、项目/配置及注释同意边界，并且在任何源修改之前持久化可恢复的操作意图。一个总返回 true 的回调不等于日志。本模块验证其调用与源围栏顺序；生产事务日志状态机、批准界面和整组协调器仍待实现。测试使用真实状态文件写入的意图回调，不能解释为生产入口已经接通。

取消在开始及写块之间观测。失败可能留下 PARTIAL，调用者须安排已授权 Restore 或明确保留待恢复状态。记录成功写入的已知前缀和本次尝试的最大前缀，区分截断前后长度；不假设 WriteFile 返回失败就没有写入，也不信任短写已经完整完成。

Restore 首先证明当前文件为确切 AFTER，或本次 Apply 可产生的 before/after 前缀组合。部分写入通过完整摘要与流式字节区间证明，拒绝不能解释的内容。源句柄的自动写入时间更新在写入前暂停，部分状态只接受原始或已记录的显式时间，以及原属性或写入可能产生的 archive 属性；其他时间/属性变化拒绝。持久化恢复意图的宿主回调之后再次检查刚才的完整证明，才覆盖回原字节、截断、flush、恢复原属性/写入时间并重新验证原始快照。

恢复开始后不响应取消；恢复失败或来源/宿主围栏失效时保留 IN_DOUBT，不隐式重试。宿主回调期间和检查失败后不把旧快照继续标成已验证当前状态。读取位置和源码固定句柄仍由门闩统一持有，供后续协调器处理。

这里使用原位写入，普通共享读者可能读到中间内容；它不是文件系统原子替换或多文件事务。后续仍需协调文件打开、监视器、构建/运行和语言服务来源，完成多文件回滚、进程退出后恢复、包退役与 GUI 批量发布。已有映射写入、文件系统过滤器、盘符重映射等不由普通共享句柄完全隔离。没有将本路径放进普通输入或增量分析循环，也不宣称完整性能、峰值 RSS、掉电持久性或 Win7 实机认证。

## 验证材料

实际检查增长、缩短、空文件、清空、BOM、CRLF、中文输出和混合换行 no-op；写入后恢复并在句柄关闭后重读原始快照。故障覆盖未报告的部分写入、成功但短写、截断前后返回失败、flush/时间设置失败、取消、宿主拒绝或修改来源、不属于本次操作的字节、恢复本身失败及不可重复执行。原生内存统计用真实分配校验启用，构造器逐点拒绝已观测分配；普通资源检查先初始化基础服务。

独立无 Spool/Write 对照确认：首次替换已有状态文件会产生基础库的懒初始化句柄，之后连续替换稳定。因此测试在资源基线前初始化相同服务，另保留冷启动对照，不能将它解释成整个 XRT 的退出回收认证。相同路径下的新旧文件校验器分配观测一致；深路径逐点拒绝另行保留，避免把路径相关的观测数变化当作删减覆盖。

精确的断言、取消/故障点、变异结果、匹配 SDK 的 GUI 回归、实际编译闭包和发布程序身份记录于 `dev/release-materials/provenance/lsp-edit-write-20261111.json`。以前未重跑的原生/协议程序不计入本轮通过项。默认发布程序、并行源码/索引和用户临时目录保留，运行验证使用根 release 下的临时别名，证据放在发布目录外。

Win32 语义依据：[WriteFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-writefile)、[SetEndOfFile](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setendoffile)、[SetFileTime](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfiletime)。其返回和时间行为不扩展为多文件或掉电事务保证。
