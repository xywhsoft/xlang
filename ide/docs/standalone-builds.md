# 单文件、项目与工作空间构建

2026-10-22 增加 C／xlang 单文件任务。构建运行不要求存在工作空间清单；独立 `.xlp` 原已支持，本次补充真实编译器验收。

| 打开形态 | 构建（F7） | 运行（F5） |
| --- | --- | --- |
| 只有 `.c` 文件 | 构建当前 C 文件 | 构建成功后运行 |
| 只有 `.xl` 文件 | 构建当前 xlang 文件 | 构建成功后运行 |
| 独立 `.xlp` 项目 | 构建该项目的当前配置 | 构建并运行该 exe 项目 |
| `.xlw` 工作空间 | 构建所选项目的当前配置 | 构建并运行启动项目的配置 |

工具栏的“构建／运行”使用上表规则。工作空间没有项目时，也可直接构建当前源文件。已有项目时，可从“项目 → 构建当前文件／构建并运行当前文件”明确选择文件目标；这不会改变所选项目或启动项目。`.h`、纯文本及只读演示页不作为独立可执行入口，DLL 项目仍需要显式宿主。

独立项目使用“文件 → 打开项目”，无需先新建或保存 `.xlw`。也可直接传入路径启动 IDE：

```powershell
.\xlang_ide.exe C:\work\hello.c
.\xlang_ide.exe C:\work\main.xl
.\xlang_ide.exe C:\work\app.xlp
.\xlang_ide.exe C:\work\scene.xlw
```

显式以 `.c`／`.xl` 启动时，进入文件模式，不自动重新打开上次的项目或工作空间；显式指定项目／工作空间并附加 `--open-file` 时仍保留该项目上下文。

单文件使用已配置的 xlang 编译器。当前随包编译器原生支持 C 和 xlang，直接调用 `build <source.c|source.xl>`，不生成或要求项目／工作空间清单。导入、头文件及 xlang 同名 C 辅助源的解析遵循该编译器的规则；运行目录为源文件所在目录。

已命名文件在构建前保存当前编辑，未命名的 C／xlang 文档先通过现有 XUI FileDialog 另存为；取消时不启动任务。源文件实际扩展名决定编译入口，手动切换高亮不会把 `.h` 或 `.txt` 变成可执行文件。其他未保存的依赖会通过实际输入记录拦截发布与运行，在问题页提示处理。

单文件的最终程序位于源文件目录下 `.xlang-ide/single-file/<完整文件名>/program.exe`，任务阶段和原始日志位于其下的 `.xlang-ide-build/<任务 ID>`。不同源文件使用不同输出目录。任务页与输出窗格提供程序和日志位置；源码目录需要可写。取消、构建失败或输入失效时保留旧程序，并禁止作为本次成功结果运行。

自动化仍支持 `--open-file`、`--project`、`--workspace`。`--task build|run` 使用当前上下文，`--task build-file|run-file` 显式指定当前文件；`--task test` 保留项目配置的测试程序语义。

验证覆盖真实 C／xlang 单文件的构建运行、源目录工作路径、头文件和导入、自动保存、错误诊断、旧产物保护、未保存依赖、未命名取消、独立项目及工作空间所选／启动目标、显式文件覆盖，以及七次真实主程序入口启动（含恢复上次工作空间后的文件启动）。精确交付证据以 [当前候选](../CURRENT-CANDIDATE.md) 为准。
