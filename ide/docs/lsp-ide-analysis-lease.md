# IDE 语言功能的源码读取暂停

M7b5j，2026-11-12。在[外部服务分析暂停](lsp-analysis-lease.md)之上，IDE 增加 `ui/language_source_lease.h` 的组合参与者：主语义连接、补全/签名连接，以及 IDE 内实际读取磁盘的诊断校验和符号导航解码线程。两个服务正常恢复时继续使用原进程和缓存；单个服务失败只恢复该连接，不重启健康的另一个服务。

此参与者供完整源码事务宿主组合使用，标准重命名与 `workspace/applyEdit` 仍未启用。文件监视、任务、工具链、已准备/正在打开的文档、其他索引器及完整的来源、物理别名、配置、请求、用户同意与恢复策略，仍需由宿主统一确认。可选 C LSP 开发配置没有对应参与者，组合暂停在该配置下明确拒绝；默认 `XIDE_ENABLE_C_LSP=0` 保持 C 编辑及 xlang 编译运行。

后续[工具链查询暂停](lsp-edit-toolchain-lease.md)提供独立查询的参与者，并修正工具链窗口在结果发布后等待尚未退出线程的问题；完整宿主仍需同时持有各个参与者。

## 所有者接口

仅由同一个 UI 所有者调用，令牌属于当前存活的两个视图，不能跨 Destroy 或复用到新视图。

1. `xideLanguageSourcesSuspend` 返回非零表示已受理；尚不能写源码。已有连接必须初始化完成并声明原生协议版本 1。没有进程的视图也会冻结创建，避免等待期间突然启动服务。
2. 轮询 `xideLanguageSourcesState`。正常写入需要 `quiet`，并同时没有 `invalidated`、`failed`、`resuming`。本参与者静默不能替代其他宿主条件。`quiet` 与输入仍有效分开，方便已经开始的事务在输入失效后按完整策略恢复。
3. 完成写入、回滚或恢复协调后，显式调用 `xideLanguageSourcesResume`。正常路径等待准确的恢复响应；已经失败的连接只在这次显式恢复后异步停止。没有超时自动解锁、自动取消源码事务或主动重启服务。
4. 等待 `resumed` 后调用 `xideLanguageSourcesRelease`，共同开放两条连接。需要重建的连接先等真实 transport worker 结束，再释放元数据并重新初始化；UI 不 join 尚未退出的恢复线程。确认过的正常恢复回执保持有效，避免两个参与者释放之间发生状态变化而陷入部分释放。

编辑、删除、撤销、IME 与聚焦仍由真实 XUI Document 执行；改动将令牌置为失效，即使随后撤销到相同正文也不重新授权旧准备结果。配置、设置或显式停止在持有期间撤销输入有效性并延后连接重建。原有自动诊断/语义着色暂停设置以及持有期间新的停止要求会保留。

## 传输与本地读取

普通发送、批量发送、消费和自动重连立即关闭。已受理的发送仍按 FIFO 完成；暂停/恢复控制消息由传输线程编码，在普通 2,048 条、64 MiB 发送额度之外仅预留两条、各最多 512 字节。控制请求使用保留字符串 ID，避免碰撞原有整数查询 ID。持有期间旧响应在传输线程释放，不进入解码回调；暂停前已经排队的接收正文也在那里退役。

恢复确认之后的新诊断等消息进入原有有界队列，暂不交给解码线程，等共同 Release 后处理。因此不会出现“服务已经发布、IDE 却把恢复后的诊断丢掉”的缺口。恢复前的取消响应、准确/过期令牌、失效通知、异常确认、连接退出和提前放弃分别处理；错误不会放开准入。

诊断流使用新的会话取消旧任务，保留与服务器一致的文档同步、输入序号和模型知识；旧批次、结果及缓存展示被撤销或隔离。符号导航取消原请求和已准备的跳转。两个实际读取线程均增加包含清理尾部的空闲判断：从槽中取走对象不代表清理回调结束，发布完成状态也不能替代物理结束。补全、签名、颜色、引用和文本同步等纯不可变正文/JSON 工作取消旧意图，不把大型处理搬回 UI。

接口没有加入每次键入的正文扫描/哈希。传输 Suspend 及已持有时的拒绝发送观察到零次直接所有者 malloc/calloc/free；这不覆盖 DLL 内部分配。UI 控制器撤销展示、元数据释放、互斥锁、编码及原有同步路径仍有成本；本阶段不是整体 RSS、硬实时或端到端延迟验收。

## 验证和复现材料

`ide/tools/build.ps1 -Tests` 注册两个新夹具。连接测试参数为 `<夹具目录> <匹配的 xlang-ls.exe> <xl.exe>`；IDE 测试参数为 `<夹具目录> <xl.exe>`，并要求程序旁的服务、SDK 与编译器匹配。`language_source_completion_probe.c` 仅用于测试，独占真实补全控制器翻译单元并提供观测/测试自有连接停止；产品没有测试钩子。独立原生的诊断流与符号结果夹具也加强了清理尾部断言。

实际验收在根 `release/win_x64` 使用私有 EXE/DLL 别名，保护原有运行程序并保持匹配的 SDK；对象、日志、数据和截图在独立构建子目录。真实双服务进程暂停后仍保持同一 PID；恢复后诊断完整到达。分别阻塞已经进入的诊断和符号导航磁盘读取，确认服务器均已回复时组合状态仍不是静默；期间执行 C/xlang 输入、删除、撤销、Unicode/IME 与点击聚焦。还覆盖单个补全进程退出、只重建失败连接、过期令牌、无进程参与者和原有停止设置。

额外发现：当前已验收原生服务在导入依赖存在语义错误时返回 `available: false` 的空补全，已用未改动的服务独立复现。此项属于后续编辑态补全能力改进，本阶段只断言错误诊断到达，以及修复依赖后补全恢复，没有把该限制算成已完成能力。上一阶段配置缓存计数回归也仍待单独处理。

精确源文件、SDK、对象、链接与验证摘要以及原始失败记录见 `dev/release-materials/provenance/lsp-ide-analysis-lease-20261112.json`。大型材料保存在外部目录，通过开发材料索引恢复；正式运行程序、SDK 和当前交付索引未替换，长期 LSP 目标仍未完成。
