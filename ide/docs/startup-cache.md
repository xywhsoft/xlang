# 启动副本维护

无可用短名的深安装目录会在用户临时目录创建仅含 IDE EXE 和图形库的副本。新副本使用 `xlang-ide-start-v2-` 加随机 GUID 的目录名，另有 `.xide-startup` 所有权记录；工程、命令目录、字体和用户配置仍读取已核验的原位置。

记录绑定当前用户 SID、临时根与目录身份、记录文件自身身份，以及两份副本的身份、创建/修改时间、大小和 SHA256。父进程持有只读租约及目录句柄，副本子进程重新验证记录后独立持有租约至退出。父进程意外结束不会释放子进程的租约。维护时需取得删除权限；存活租约会阻止这一权限，因此不会只凭 PID 或持久锁文件判断实例已结束。

每次普通启动在图形初始化之前执行有限维护，最多检查 64 个新格式目录，最多摘要读取 128 MiB，逐文件最多 64 MiB。只处理至少七天前创建且所有内容完全匹配的副本。未来时间戳、尚在运行的实例、缺失/损坏/替换的记录、额外文件或目录、修改/替换的二进制、硬链接和重解析点均保留。旧格式及未完成准备而无法证实所有权的目录也保留。维护失败不阻止普通启动；新的副本准备失败仍在图形初始化前报错。

删除前核对完整目录内容并同时固定已验证的文件句柄。只按句柄删除本次匹配的成员，最后移除空目录；不递归删除，也不清理工程或其他临时目录。正常退出继续按本次保存的文件身份立即清理，无需等待七天。

`startup_cache_test` 包含真实 Win32 文件、损坏/替换记录、硬链接、连接点和 65 个副本的分批维护检查。`check_startup_cache.py` 在从不切换的私有桌面创建真实独立父子进程，仅终止自己启动的父进程，验证子进程存活时拒绝清理，子进程退出后才回收。时间边界使用夹具传入的 FILETIME；生产启动使用系统 UTC，不改变系统时钟、卷策略或用户权限。实际深安装 GUI、C/xlang 编辑和混合构建运行另由既有启动和完整回归验证。

这一机制不把无所有权记录的残留推断为可删除。其他用户、完整禁用短名的卷、ReFS/UNC、其他驱动及干净 Windows 设备范围仍需正式发行验收。见[深安装目录启动](startup-paths.md)与[实施进度](progress.md)。

## 实际 GUI 父进程中断验收

`tools/check_startup_cache_gui.py` 将开发产物和便携包中的 GUI 程序、命令目录及字体分别复制到新的自有深安装目录，仅去除这批新目录的短名。每种来源都验证 C 与 xlang，两种语法共四个实际 GUI 场景。每个场景使用独立 Windows 桌面和独立 TEMP/TMP 根，从不切换桌面。

观察器通过实际窗口 PID、父 PID、进程镜像和创建时间确认短副本子进程，然后只对本次启动父进程调用 TerminateProcess，保留测试 Job 至子进程正常结束。子窗口在有界等待中继续响应，子进程独立阻止所有权记录的删除。维护夹具只访问该场景自有缓存根，使用传入的七天后 FILETIME 验证存活时不回收、子进程退出后回收；系统时间不变。

每个实际 GUI 子进程完成 600 帧并返回 0，四张最终原生图保留 C/xlang 高亮、中文正文、定版布局与单栏帮助。原程序、库、目录、字体、设置和源码摘要不变。四次父进程终止、四次 GUI 子进程结束及八次维护进程都有实际句柄、身份和原始日志记录。这项检查补齐真实 GUI 生命周期范围，不扩展到准备未完成、其他用户或设备，也不替代实体输入法验收。

```powershell
python tools/check_startup_cache_gui.py --ide-root release --package-root dist/portable-20261010-startup-cache-final-v1/xlang-ide --fixture release/startup_cache_test.exe --output build/gui-startup
```

省略 `--package-root` 只执行开发来源的两个场景；本轮最终记录明确执行了全部四个。见[实际 GUI 最终核验](../build/startup-gui-final-v3-verification.json)和[原生截图记录](../build/startup-gui-visual-inspection-v1.json)。当前程序与 SDK/工具链字节未改动，沿用已经通过的严格构建和 88 类完整回归，本轮未重复执行该全套。
