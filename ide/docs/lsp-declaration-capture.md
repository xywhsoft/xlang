# 无打开文档的后台声明捕获

工作空间符号索引需要覆盖未打开的工程入口和源文件。原生 worker 已能读取未打开的配置入口，但只有依赖分析完整接通了零个覆盖层的路径，语义检查的接口注释与实际准入不一致；宿主适配层也要求一个打开文档作为触发源。本阶段把这一能力接到已有后台、输入验证及声明投影边界；不创建占位文档，不要求 IDE 为索引打开文件。

`xideLanguageCheckStartDeclarationCapture` 接受不可变分析上下文、现有 compiler-XRT worker 和零到 64 个实际文档覆盖。配置入口可以未打开；入口或依赖若有真实覆盖，仍采用该覆盖的正文／身份／修订号。目录、包配置、解析、导入、语义及 IR 均使用原有实现，不运行项目代码，不调用编译器进程。

捕获针对一个已检查入口及其真实导入，不等于工作空间成员枚举。原编译选项支持、输入规模／路径别名、完整索引及导航准入边界保持。某个成员不能单独形成有效编译时，仍返回原检查诊断，后续调度器需选择真正拥有它的入口；不能据此把错误模块当作成功索引。

声明使用前阶段的紧凑投影及准确点查询证书，结果不持久保留完整导航和引用表；正常点证书路径无需重新物化完整表。可选证书准备未成功时，仍沿用原有完整验证临时表回退，并通过 `fullValidationFallback` 报告，完成声明复制后释放临时表。成功时省略面向诊断 UI 的文档正文、空诊断和详细 JSON 工作统计；真实非空诊断继续经过原坐标及来源验证。CPU、内存及增量工作仍由真实 worker 计数，不把主机减少的哈希等同于编译器完全省去扫描。

新增 `xideSemanticSymbolsRetain`。声明结果使用 XRT 原子引用计数，可跨线程只读，并独立于原检查、上下文、worker 和工具链缓存销毁。`xideLanguageCheckCaptureDeclarations` 仅在该模式、检查成功、当前来源守卫仍有效且未取消时交出保留引用；其他情况清空输出。返回的工作统计直接来自原生 worker 和声明构造，不新增协议能力。

结果生命周期与新鲜度分别验证。零覆盖层也必须启动原有发布守卫并保持实际后台线程存活，捕获后磁盘变更会使旧结果永久失效。索引消费者需同时保留／复核现有 detached input guard，并在发布时比较覆盖层及 catalog 的当前代次；单纯保留声明不会证明输入仍有效。SourceRejected 仅表示原检查提供的、已验证来源诊断；取消、额度或基础设施失败不会归入源码错误。

原生回归使用实际磁盘入口／导入、BOM／CRLF／中文／emoji、零打开入口、一个真实依赖覆盖及 63 个无关大覆盖，比较字段与定义位置、原生精确复用、原文件未改、后台线程、实时磁盘失效、永久失效、真实解析错误及取消。最后销毁整个分析生产者和缓存，再由四个线程读取共享声明。空文档路径不能走 CLI，测试使用不存在的执行编译器。

两个实际 C 遗漏控制分别移除零覆盖层发布守卫和持续磁盘守卫，回归必须拒绝这两种错误实现。完整原生、既有协议及同服务／SDK／真实运行库的 IDE 输入、补全、大纲检查应与该阶段一起验收。

这为后续工作空间索引提供可用输入，不宣称 `workspace/symbol`、文件夹发现、多工程索引、模糊排名、resolve 或 IDE 搜索界面已经完成。全量性能、全局预算、十万行／并发／耐久性仍需继续；DAP 与调试／运行态补全不在本目标中。

首轮全新构建有 142 项原生测试通过，新增捕获测试发现 worker 仍拒绝零文档检查；沿缓存链继续审查，检查会话也仍使用非空输入构造器。已修正 worker 对配置检查的准入，并在检查会话复用原有关闭入口输入构造器；普通输入构造器、语法／游标请求和缺少上下文的空输入仍拒绝。补充直接 worker 的完整新建 AST／索引／IR 对照、两种上下文、精确缓存命中和依赖改变失效。原失败构建、142 项通过及完整源码均保留，未改记为成功。

第二轮原生回归中的旧依赖测试仍断言零文档语义检查必须被拒绝。扩展该能力后，将它更新为检查缺少上下文／错误目标仍拒绝，保持该夹具只执行依赖分析、观测语义／IR 调用为零；有效的零文档检查转由新 worker 用例验证。仅这一测试文件改变，生产源码和公共头文件及其完整对象摘要保持；冻结第二轮失败及前 48 个通过的产物，重编该夹具，以同一对象批次完成后 95 个测试及服务链接。未拿修改后的公共头文件与旧对象混合链接，也未将失败回执改写为成功。

最终一致批次共 241 个完整编译单元加 1 次夹具修正编译、143 个原生测试、147 个私有 AST 消费者，1,412 个输入／145 个产物核对通过。直接 worker 缓存夹具 848 项检查，新增宿主捕获 164 项检查；64 个依赖／无关覆盖场景适配层哈希计数为 143 字节，这不是整个编译器的哈希／扫描总量。两项实际 C 守卫遗漏均被拒绝。22 组协议、9 项真实服务 GUI 和 1 项旧能力兼容通过；113 个 GUI 对象与冻结的 180 文件 SDK、实际发布 DLL 一致。

前阶段的性能校准／尾延迟失败保持，本阶段没有重跑原性能矩阵或改变门槛。默认 IDE／服务／引擎和交付索引未替换，没有推送线上。证据位于 `dev/release-materials/provenance/lsp-declaration-capture-20261109.json`。
