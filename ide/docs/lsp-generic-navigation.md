# 泛型实例的原生声明关联

后续已修复本阶段记录的限定类型实参范围缺口，见 [限定类型名称的原生区间](lsp-qualified-type-ranges.md)。原阶段的验收索引保留其当时记录。

原生语义检查把显式泛型实例的准确目标记录在 `generic_instant` 节点上。此前导航读取其名称子节点的绑定，导致 `Box::<int>()` 的类名可能没有定义与引用结果，泛型函数名也可能停留在非最终的名称符号。这里直接使用原生实例节点的目标，沿用同一次检查的声明表。

只有泛型实例的第一个名称子节点可以使用该目标。类型实参保留各自原生绑定，外层调用的普通参数和成员接收者也不会被重定向。泛型函数调用使用调用节点最终选定的重载；类的构造名称仍指向类声明，不指向 `create`。未找到已核验声明的原生 ID 时继续返回无结果，不按拼写猜测目标。

原生与兼容索引通过同一分类表识别泛型实例，新类别追加在已有类别之后。常驻点查询、完整导航、引用 shard、重命名目标捕获和既有协议处理共用解析声明的实现。没有新增 AST 遍历、解析、文件读取、字符串搜索或持久化符号族缓存。原生前端 AST、IR 与诊断不因导航投影而改变。

专项覆盖不同实参的同一泛型类、带 `create` 的类、泛型函数值与调用、不同参数数量的泛型重载、限定导入、类型实参独立绑定、中文/emoji、BOM/CRLF，以及完整类型索引、兼容 JSON 索引和常驻点查询之间的逐位置等价。stdio 验证未保存依赖、旧绑定拒绝与恢复。IDE 夹具执行真实 Shift+F12、引用窗格及受保护的声明跳转。

同时发现当前选定原生前端为 `Box::<dep.Marker>` 的限定类型实参保留了正确 TypeId，但 tokenRange 只覆盖前缀 `dep`。因此在末端 Marker 上仍无定义/重命名结果，原引用区间也只有该前缀；测试验证没有把 Marker 误跳到外层泛型类，而 `dep.Marker()` 的正常构造名称仍解析到 Marker。这个既有范围缺口须在后续修复，不能据此认定类型实参导航已完整，也不能按拼写补造编辑区间。原生探针的事实与区间原件保留在验收材料。泛型函数夹具使用本地声明，导入场景使用当前语法支持的 `export class`；没有为测试添加语言尚不支持的泛型 `export func`。

这是原生泛型实例与其源声明关联的导航修复，不是完整重命名授权。隐式特化来源、继承/覆写/协议/属性和重载族闭包、冲突与改名后绑定证明、版本化编辑和 IDE 事务，以及全目标性能与规模验收仍须继续；尚未开放 `renameProvider`。

本阶段通过 171 个原生夹具、11 套 stdio 协议测试及 28 个 IDE 夹具；泛型专项包含 2,270 项检查。移除实例来源关联或最终重载选择的两个真实 C 变体均被拒绝。资格检查绑定 279 个实际消费者、172 个程序和 core 全部成员；IDE 完整重编译 116 个对象，配对同一服务与匹配 XGE SDK，验证 C/xlang 输入、删除、撤销、Unicode/IME、焦点以及语言功能。已复核浅色、深色和泛型引用窗格截图。默认发布程序未替换，未进行全目标性能准入或线上推送。材料索引为 `dev/release-materials/provenance/lsp-generic-navigation-20261110.json`。
