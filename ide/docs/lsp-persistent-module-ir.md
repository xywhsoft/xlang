## 所有权与准入

`xls_typed_module` 直接接管语义检查完成的原树，不复制整棵 AST，不保留 check、report、旧模块或旧结果。引用计数、分配和容器使用既有 XRT，释放沿用 `xl6AstFree` 及原 AST/source/pool/intern 契约。公开头文件仅提供不透明句柄的 retain/release；接管与根节点访问为内部 API。句柄本身不能证明当前输入新鲜。

冷分析和普通语义编辑不构造整模块的最终键。既有语义函数输入键提供负向提示，小型直线函数在原本空闲的 `entry.key` 中保存带标记的原始输入键，纳入原语义 memo 容量；保持原 entry 布局，复用一次键比较。缺失、失败或变化都拒绝提示。它不代替最终输入、来源或 IR 的等价证明。

第一次符合条件的编辑才准备前代资产。0/1/2 原子状态表示未准备、正在准备和已发布；一个调用负责准备，其余调用立即走原始路径。失败清理临时键并允许重试。准备不改写前代的 creation work，完成后释放 IR owner 的输入引用。调用方仍须持有结果寿命。

模块 envelope 与每个声明分别使用已有完整非坐标编码器，保留原生符号／类型／region／ABI、路径、doc、literal 和孩子顺序，不归一化 ID，也不用 hash-only 比较。沿用单次 8 MiB 编码守卫。所有权转移前检查 AST preorder、sourceKind、原 span 和节点总数，全部可失败操作完成后才提交转移。

只读存储拥有原始表、单独拥有的节点文本和 raw unit 引用，不保留旧 AST、check、memo 或节点数组。当前结果拥有独立节点数组，保持原生倍增容量形态，只复制活节点并按当前 AST 更新 span。完整原始验证器始终执行；含 lowered instruction/sourceSpan 的模块不进入这一 typed-AST 复用路径。准入、预算、分配或验证失败继续使用原始构建及其诊断。

raw memo 单独持有 raw units 和当前 entity view，后续语义编辑仍能使用既有 raw function 缓存。原始 fresh API 保持独立对照路径。新增 `lastBuildPersistentIr` 与私有 C getter 报告成功 owner 的构建／复用／校验、复制节点、共享表、键／元数据及准备来源；精确命中保留创建记录，不代表本次请求重新执行这些操作。非 owner 路径报告零。

持久预算 **32 MiB 仅覆盖实现计量的共享键与所有权索引保留容量**。固定结果／输入句柄另计；该预算不包含现有模型、节点 arena、raw payload、临时分配、allocator 开销或 RSS，也不是服务全局内存界限。语义与 raw memo 仍有各自原有预算。
