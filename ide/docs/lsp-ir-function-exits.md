# 实验性函数退出计划复用

M7b7o，2026-11-23。`XLS_EXPERIMENTAL_IR_FUNCTION_EXITS` 默认为 0，与旧的整模块退出结果缓存互斥。此阶段实现了从实际构造事件到输入判定、旧产物重定位、新生产和完整组装的通路，仍保留原生完整 verifier。性能观察显示当前实现不适合默认启用，发布目录未替换。

## 构造和输入证明

原始 AST→IR 构造器在新建或恢复顶层函数时记录实际节点区间，复制当时的词法符号表。没有从完整新输出反推旧/新对应关系。处理退出计划前，既有 raw memo 的非函数环境和实体 store/domain 守卫仍然生效。

共享输入比较完整类型池、运行时类型映射、枚举三表、函数和泛型实例元数据，以及原生析构器查询使用的有序候选声明、名称谓词和祖先链。跨函数清理不依赖其他函数的局部变量：有效闭合树中，带路由的退出检查所属 callable，`AFTER_SCOPE` 只访问该块直接绑定子项。此边界依赖完整原生来源、头文件及依赖契约，未知版本停用；不是对任意 C 生产者推断出来的读集合。

每个函数比较已审核的 27 个整数节点字段、五类文本谓词、子节点顺序及声明初始化器首个匹配行是否可能抛出。节点 ID 转为函数内偏移，词法符号转为实际构造的词法槽，全局符号使用同命名空间的实体身份，未知身份保留精确 native ID。region ID 按首次出现建立局部编号，保留相同/不同关系和所有引用。验证单元是完整、无重复边、父子一致、ID 单调的函数子树。坐标和普通文本拼写不作为退出生产输入。

命中不运行该函数的原生 close/plan/route 生产；未命中调用 M7b7n 的区间入口。产物以独立 XRT allocation 保存，节点、符号、region 引用使用局部编码；当前构造中的映射解码后才进入新的原生数组。slice 按当前源顺序重定位。普通 IR 节点和字面量仍来自当前构造，退出缓存不复用旧源文本。

缓存不保留 AST、模块、前一代 memo/result 或结果链。共享上下文与独立单位使用引用计数，当前映射在生产后释放。8 MiB 只限制本缓存的逻辑保留容量，与原始 memo 预算分开；不包含可变 IR 输出、临时区间输出、scratch、分配器开销或 RSS。尚未形成整个服务的全局资源预算。

## 正确性和资源检查

所有 80 个 core 对象先以同一实验配置编译。之后只重编改动的原生 IR 和测试；复用的 79 个对象逐个核对实际依赖在新快照中的字节身份。当前普通夹具通过 398802 个检查，私有契约夹具通过 119 个检查；它们包含既有检查，不能把计数相加解释为独立覆盖率。

- 原有 134 模块、两种节点分区、268 次完整 verifier/IR JSON 对照仍通过；另一次实际复用语料运行观察到 41 次选择性构造和 42 个函数单位命中。
- 32 代在首函数增加作用域和局部变量，后面两函数每代命中，节点、符号、region 编号移动后与独立完整原生结果一致。第 1 代原生 plan 入口处理 36/96 个节点，第 31 代为 396/456；保留数据约 15–45 KiB，前一模型、memo 持续退休。
- 字面量、Unicode、闭包、生成器、异常/循环/匹配形态，以及枚举和函数头变化均有独立原生参考。参考构造显式关闭新复用，避免以新算法给自身提供答案。
- 当前源对应的冷/热检查分别拒绝 268/250 个外部分配或 XRT API 调用点，并检查 223/66 个取消点。接受的结果须通过完整 verifier 和原始 IR JSON；失败不得发布 memo，跟踪的外部分配回到零。API 拒绝包含未必实际扩容的操作，不把它们全称为真实堆 OOM；XRT 内部分配也不是全部可见。
- 契约检查覆盖 27 字段、五类文本谓词、位置忽略、region 双射重命名、初始化器及共享上下文守卫。独立构建的原生缺陷测试和正对照另有原始记录。
- 标准生成流水线和来源变化等 7 项守卫通过。默认配置预处理后，提取到的 1846 个原有函数令牌和两个私有布局与保守基线完全一致；这不是新二进制的端到端性能证明。

首次失败均保留。v1 是生成器重命名误改 `exitKind` 等编译问题；v2 暴露 XRT 数组 `Data` 与 `Allocation` 分离，错误交接后容器释放了输出。实现现改用原生 `xl6IrGrow` 数组组装和同一 allocator 释放。

广泛故障注入还发现，关闭新复用的原生对照也可能在一次类型分配失败后接受缺少函数名称类型的 IR。该对照和 JSON 差异已保留。实验配置对 18 个已审核的必要类型构造/验证函数增加失败锁存，清晰拒绝不完整结果；不把可选缓存/index 的失败锁存为类型失败。默认配置仍展开为原生调用，独立的默认稳定性修复及协议资源错误处理仍需后续验收。

## 性能观察与边界

单进程、同图像、ABBA 顺序的 512 函数原生 IR 构造观察，共 24 帧，预先完成语义分析。关闭/开启复用时冷构造中位约为 **15.22/72.28 ms**；后续帧中位约为 **11.49/12.00 ms**，未观察到收益。结构变化时只进入 29/8205 个节点的退出生产，重复输入只进入 1 个，但总构造成本没有降低。关闭模式的输出计数 0 表示没有记录计数，不代表跳过了原生生产。

这是组件归因观察，样本和范围不足以作为正式端到端门槛。它已经足以阻止当前实现默认启用；不得用更多同图像计时消除这一结果。冷路径逐函数调用区间生产，未继承整模块的索引作用域；判定、分配和搬运也有成本。还未逐项隔离成本，不能仅凭计数把全部退化归因于其中一项。

此实现只复用退出结果，仍完整构造、物化、运行其他最终 IR passes 并验证节点，尚未解决主要的整体成本。后续重点是完整最终函数 IR 的独立持有、构造前失效证明、共享类型/接口上下文和只生产/检查失效函数，减少对未改变函数的解码及物化。类/方法、泛型、C 互操作、持久精确克隆、完整协议/IDE、真实工程、长稳和全局预算仍属于长期目标，不能以本阶段通过代替。
