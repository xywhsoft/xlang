# 工作空间符号搜索的 IDE 接入

2026-11-09，M7a2b126h。接通已实现的 `workspace/symbol` 和 `xlang/workspaceSymbolNavigation`，在 IDE 的“编辑”菜单提供“搜索工作空间符号”，快捷键 `Ctrl+T`。使用 XUI window，支持多个查询词、150 ms 输入防抖、最多 200 项结果、所选文件路径、Enter／双击跳转和 Escape 取消。未打开文件时也可搜索已配置的项目；当前编辑 C 文件时也能搜索 xlang 符号。输入法组合期间不会把 Enter 当作跳转。

搜索复用现有语言服务连接、分析目录、项目配置和后台文档同步，不另起一套工作空间模型。列表与导航都保留项目配置、文档身份／版本、外部文件状态、文件同步修订及连接代次守卫。导航重新请求完整选择行的来源证明；旧请求、取消结果、已改变的磁盘目标和编辑覆盖均不能直接移动光标。多个项目共同引用同一文件时，结果仍保留各自的项目分析上下文。

请求编码、结果解码、来源摘要核对、磁盘内容读取、换行处理及 UTF-16 位置转换由有界 XRT 工作线程处理。一个待处理任务、一个活动任务、一个已完成结果和一个退休结果限制积压；大消息、源码及编码批次在工作线程或最终销毁时释放。小型预留失败结果覆盖工作线程分配失败，避免界面一直等待。结果列表上限为 200，路径／规范键／标签存储合计上限 32 MiB；消息 DOM、源码快照和其他对象另计，不能将此数值当作进程内存上限。

磁盘跳转复用既有来源证明读取器，一次读取保留原始 BOM／CRLF 字节与编辑用 LF 文本，随后交给文档存储接管；未保存文档保持原编辑器、撤销栈及脏状态。两类跳转复用原行号跳转的折叠展开函数并选择完整标识符。界面线程仍执行有界路径元数据核对及编辑器建档／显示，因此本阶段不宣称零界面线程文件操作，也未完成端到端延迟准入。

原生验收审计 248 个已有 GCC 依赖闭包，重编译 31 个受影响消费者及 4 个新增编译单元，实际运行 32 项测试，保留 117 项未受影响测试，共 149 项。新解码器覆盖 304 个检查、6 个实际边界拒绝点及 8 个取消检查点；另以真实 C 编译的版本校验遗漏、摘要校验遗漏验证测试能识别错误。

重新运行 5 套相关协议检查。IDE 用同一候选服务及匹配的 180 文件 XGE SDK 全量编译 115 个对象；12 项真实服务 GUI 用例和 1 项受控旧能力服务用例通过，包含 C／xlang 输入、删除、撤销、Unicode／IME、焦点、补全、自动诊断、分析配置以及工作空间搜索。浅色／深色搜索窗口截图已检查。跳转测试的直接文档槽复用原先绕过共享查找范围注册，现改为先注册复用编辑器、再把焦点交回对话框并派发 Escape；身份和版本拒绝断言保持。生产跳转逻辑只导出原有折叠展开函数。

验收失败的原始日志与输入版本一并保留，包括初期严格编译警告、项目夹具遗漏工作空间引用元数据、包含暂未支持原生构建配置的夹具、测试辅助程序链接／参数错误及跳转夹具生命周期错误。正式性能矩阵未重跑、阈值未改变；既有 A/A 4／64、阶段 A/B 1／64、累计 A/B 0／64 的记录保持，整体性能仍未准入。
