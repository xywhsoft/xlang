## 原因与边界

当前 IR 调用查找修复后，512 函数样例的主要剩余差异位于语义检查。私有诊断记录一次冷检查约 1,598,733 次读取观察，其中 1,486,565 次为类型值比较，实际新增记录为 1,800 项。关闭观察只用于归因，不作为产品优化；减少这些观察会损失声明变化后的依赖证明。

原生类型注册表仍执行每一次查找。新索引只在同一次函数检查的栈帧中，用 32 个位置槽定位已经捕获的值，不保留查找结果或数组元素指针。ID 仅用于定位候选，不能证明相等或有效。初次捕获及回填时先证明原查询名称与拥有型值的名称完全一致，后续才能用这份拥有型名称核对相同查询，减少一次并行记录数组读取。

快速路径仍检查上下文、类型命名空间、256 项记录上限、拥有型名称，以及原有完整值比较。存在性、ID、ABI、名称与 ABI 名称的内容、类型种类、泛型字段和声明变化均继续核对。负向查询、碰撞、不具备证明的名称和不可用的值缓存执行原观察函数；第一次及函数结束时的完整序列化证明保持。

位置不会因 XRT 数组扩容而失效，值缓存释放时清空候选槽。索引没有增加堆分配或持久 memo 字段；新增已知栈字段为 `32 * sizeof(size_t) + sizeof(uint64_t)`，在本机为 264 字节，不代表整个函数栈帧或进程内存预算。旧前端通过条件编译保留原布局、函数名及路径，字节级对象核对另行执行。

正常构建新增 `analysis_semantic_read_front_test`，包含同一次构建实际生成的语义翻译单元，直接比较生产代码保留的慢观察函数和正常入口。该测试对象先于核心归档链接，服务仍使用正常语义对象；测试实现不会进入核心归档或服务链接。

定向 866 项检查覆盖所有原生字段及名称内容变化、负向／正向转换、上下文和命名空间、记录上限、ID 碰撞、向量扩容、值缓存回退、最后一次读取后的变化、嵌套作用域、拥有型快照以及逻辑分配平衡。逐项比较原序列化键、次序、计数和拒绝结果；现有完整程序／新鲜模型对照继续独立执行。

私有诊断还保留了未采用的方案：共享类型模型的别名索引没有收到实际语义查询；按名称前缀定位的原型在负向碰撞场景变慢。细粒度函数计时会影响内联，相关时间仅用于定位。最终 ID 候选方案的原生微测与同程序控制实验均保留全部慢样本，不能代替端到端准入。
