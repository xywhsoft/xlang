# 独立诊断输入守卫

自动检查多个入口时，诊断必须能独立于最近一次导航索引保留。既有 `xide_language_check` 拥有完整结果、导航表、覆盖正文和持续观察线程，不能为每份历史诊断都长时间保留它。`language_check` 新增不透明的 `xide_language_input_guard`，为多入口诊断存储提供轻量输入证明。

`xideLanguageCheckCaptureInputGuard` 仅接受已就绪、仍有效的快照检查，复制已验证的实际输入文件报告、导入候选报告、包环境和后端配置。它不保留 AST、IR、导航表、正文、检查对象、工具链缓存或线程，也不在调用线程执行文件系统访问。原检查取消、销毁后，调用方的守卫引用继续有效；所有持有者使用显式 Retain／Release 和 XRT 原子引用计数。

`xideLanguageInputGuardValidate` 只在后台执行，复用原有 `xideLanguageSnapshotGuard` 的规则，不另写一套磁盘／包解析验证。每次调用使用独立取消视图；并发消费者只读已捕获报告。文件内容／身份、候选存在性、包环境及兼容后端的工具链证明变化会永久失效。取消一次验证不会使证明失效，也不会取消产生它的原检查。覆盖正文的身份和版本仍须由诊断存储／宿主验证，本模块不将后台磁盘守卫冒充打开文档的版本保护。

`xideLanguageInputGuardFiles` 提供实际加载输入的只读报告，区别于整个打开文档捕获集合。后续诊断存储据此避免把未参与分析的文档空组当作该文档的检查结果。守卫本身不创建观察线程；多入口宿主应通过有界后台队列统一验证，不能为每份记录复制一个常驻检查任务。

诊断存储可通过 `Current` 读取原子失效状态、用 `Invalidate` 标记宿主观察到的覆盖变化，并用 `Touches` 查找实际文件及解析候选；这些查询不执行磁盘访问。状态有效不等于刚刚完成了磁盘复核。`ReportBytes` 在后台使用 XRT 流式 JSON 写出接口计量输入报告，既不生成完整计量字符串，也不是进程内存测量。多入口合并与后台执行见 [诊断存储](lsp-diagnostic-store.md)。

专项 `language_input_guard_test` 使用实际原生检查而非伪造报告。它销毁产生方检查／缓存后验证证明，覆盖实际与未使用覆盖文件的区分、320 次有效／失效并发验证、验证前及中途取消、同字节物理替换、内容改变及永久失效、缺失导入变为存在、包环境改变和源码错误证明。原始文件报告保持只读。

这是自动诊断所需的生命周期与输入有效性基础；后台调度和 IDE 自动接入仍须完成。报告数据不含源码正文，没有将其计量宣称为进程峰值内存预算，也没有新增产品时延结论。
