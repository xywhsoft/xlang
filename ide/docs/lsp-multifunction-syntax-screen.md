## 生产边界

本轮独立从已验收的 0.99 开始，没有继承未验收的 M73 函数输入资产。原来的单函数增量路径优先运行；普通代码的差异跨越多个函数时，才尝试新的多函数路径。光标补全和参数提示投影保留原守卫及回退。

未改声明逐字节复用既有不可变单元；所有声明之间的空白、注释、文档及末尾文本必须保持一致。XRT 子串查找只选择候选边界，不代替语法判断。每个变化片段仍交给原 `xl6ParseSource`，要求没有诊断、恰好一个同类完整函数、起止范围精确覆盖片段；不满足时销毁本次构造并回退。非函数变化、歧义锚点及无法证明的边界也回退。后续语义分析、依赖失效、完整最终 IR 和原验证器不变。

搜索最多允许 64 个变化函数、8 KiB 锚点及文档长度四倍／8 MiB 的累计搜索范围。这里约束的是扫描范围，不是服务全局内存预算或最坏 CPU 时间证明。片段单元独立持有 AST 来源；复用单元只增加原子的引用计数，不修改已发布节点。通用错误恢复、任意编辑的增量覆盖、全局预算及整体取消延迟仍未完成。

## 性能筛选

最初的拼接原型筛选在第 532 次请求前检查到可用提交额度仅约 2.834 GiB，低于预定 3 GiB 下限，整轮中止。保留 531 个成功查询、35 个完整进程及一个中止进程的记录，没有计算门槛或选取有利子集作为性能证据。

后续对完整全新构建另行登记独立筛选，执行全部 960 次新查询、64 个进程，保持原门槛。采用 ABBA／BAAB 顺序，覆盖 32／512 函数、独立／导入拓扑、单函数字面量／双函数声明编辑。双函数编辑热请求 P50 至少改善 10%（32 函数）或 15%（512 函数）；普通路径保留 5% 非退化界限和原绝对容差。
