# 文件改名事务恢复

文件名改动沿用原生 F2/菜单操作。启用会话持久化时，先保存当前 C、xlang、资源和未命名正文，再发布改名记录，随后才移动磁盘文件。恢复记录包含目标拼写、文件物理身份与 SHA-256、完整工程模型及磁盘基线、资源补丁和独立会话正文。正文使用分别校验的不可变文件，控制记录最后原子发布。

重新打开同一工作空间或独立项目时，先确认移动是否实际发生。只有文件身份、清单和资源基线均可确认时，才恢复内存中的工程引用及资源草稿；原清单与资源文件仍由开发者显式保存。待应用资源补丁进入可撤销的编辑历史。确认移动尚未发生的准备记录不执行改名或资源补丁。

连续改名累积文件身份和模型状态，第二次移动前仍保留上一次完整记录。后续会话检查点更新模型与正文，因此已检查点保存的资源撤销和进一步编辑不会被最初补丁覆盖。主会话已发布而事务记录更新失败时，启动恢复优先使用有效配对的新会话正文，保留后续编辑和撤销。目标冲突后，原文件身份未变即可取消准备记录并重试。相关工作空间、项目与资源全部保存，并发布当前会话检查点后，记录标记为已完成。未完成或损坏的记录阻止恢复正文清理。

以下情况保留原记录与用户文件，并在状态栏报告冲突：记录损坏、正文摘要不符、同字节文件被另一个物理文件替换、工作空间/项目/资源被外部修改，或记录所属工作空间不同。恢复不会替换用户磁盘上的清单或资源，也不会强制修复损坏的 session.json；记录自有的已校验正文仍可用于恢复。

边界：这是同目录文件名改动的恢复协议，项目清单和整个项目目录迁移仍需独立事务方案；此前文件改名涉及的工程与资源尚未保存时，项目迁移会要求先保存这些改动。显式 `--no-session` 不创建持久记录。同名操作不创建事务。控制记录上限 8 MiB，单份正文 16 MiB，会话正文总量 512 MiB，物理文件检查上限 512 MiB；超限在移动前拒绝。同步摘要计算、存储空间配额、遗留准备正文回收、慢速存储和电源故障仍需进一步验收。

原生验收通过独立 Windows 桌面运行真实 XGE/XUI。父进程只终止自己持有的测试进程句柄，再由新进程实际打开原工作空间；包括日志已发布但尚未移动、第二次移动前后中断、后续编辑、资源撤销、清单先保存、全部保存、主会话写入冲突、重复恢复、恢复后撤销和未完成事务的清理保护。负面验收另覆盖记录/正文损坏、同字节身份替换、清单/资源外部改动及错误归属。

精确本轮输入、原生退出码和证据路径见 [实施进度](progress.md)。本功能不代表长期 IDE 目标或正式发行验收已经完成。
