# 原生重命名候选的客户端数据校验

M7b6a，2026-11-13。IDE 的后台测试路径现在把真实 `xlang/renameCandidate` 回复从原有调用路由交给 `xideEditCandidatePrepare`，建立拥有独立生命周期的候选计划。此阶段完成来源守卫、提供者及成员覆盖、原始编辑意图和 WorkspaceEdit 的数据校验；生产菜单、标准 rename/applyEdit 和事务写入仍未启用。

## 来源与请求绑定

`rename_evidence` 从捕获的本地完整范围独立重建每一个提供者上下文，逐字段核对服务声称的配置，导入所有输入守卫。每个项目的主入口、每个显式 `.xl` 成员和独立文件都必须被相容的提供者覆盖，包含没有编辑目标的项目。共享文件累加所有匹配的归属位，不能以选中项目替代其他归属；同一路径的完整来源报告冲突时拒绝。结果拥有脱离回复 DOM 的守卫、范围和排序路径索引。

候选必须属于同一个实际 `edit_call`，并保持 REPLIED 状态及原始请求有效。打开目标只使用请求时的不可变文本、身份、修订和精确 LSP 版本，不在回复到达后重新捕获编辑器正文。闭合目标必须具有 null 版本，其完整原始输入报告与已导入的来源一致；有界读取并验证原始 SHA-256 后，通过已有文本解码器处理 BOM/CRLF，再交给已有 WorkspaceEdit 位置及正文校验器。

只接受原生 `documentChanges` 的文本替换形式；不接受资源操作、注解或额外编辑形式。目标必须是本地范围明确拥有的 `.xl` 文件。每个替换串必须等于原始请求的新名称，所有被替换区间必须具有相同原文，且至少一个区间包含原始请求的光标、文档身份及版本。全部目标都必须实际变化。准备计划后再次新鲜校验完整来源，包含零编辑提供者。取消及请求失效贯穿导入、正文处理、位置转换和最终校验。

捕获的命名模型如果没有被精确同步为 xlang 输入，或已标记外部变化，只要触及来源文件或解析探测路径，就拒绝操作。因此未同步的 C/隐藏模型正文仍采用保守拒绝策略，本阶段没有宣称已经支持它们的语义覆盖。路径转换失败返回未知状态，调用方必须拒绝，不能误当成“不相关”。

## 批量守卫与成本

新增批量守卫导入和校验接口。每次调用显式拥有一个 XRT map/array memo；键为规范路径，命中还要求完整报告相等及同一个不可变 overlay 文本租约。相同来源在同一次调用中只读取、哈希一次；不同报告必须重新验证。上下文和解析探测仍分别校验；下一次调用建立新的 memo，没有常驻缓存或跨调用复用。

上限为 65,536 个守卫/来源行、7 MiB 编码证明、64 个 overlay、512 个目标、每个文档 65,536 个替换、单个闭合正文 8 MiB、闭合原始正文合计 64 MiB。候选已知保留范围、报告、路径、行容量和准备计划使用合计至多 256 MiB 的预算。memo 的路径键至多 32 MiB，编码前后临时键约至多 64 MiB；DOM、map 桶、分配器、共享租约、解码器及其他临时空间另外存在。这些上限不是进程 RSS 上限，也没有零拷贝或整体时延资格声明。

`Current` 只读取请求和候选失效标记，供 owner 做快速门槛判断；它不检查磁盘。`Validate` 在后台进行新鲜来源校验。`RetainPlan` 允许后续恢复及只读检查独立保留计划；释放原始请求或候选不能破坏已保留的计划。计划准备不是持有文件锁、物理别名裁决、写入许可或事务提交。

## 验收与边界

实际原生和配对 GUI/XRT 的客户端专项各通过 310 项检查，覆盖五个打开/闭合目标、共享归属、独立文件、零目标来源、伪造报告/配置/版本/范围/替换串、遗漏原始光标目标、同字节物理替换、取消、脱离候选的计划所有权、33 个 map 分配拒绝点和来源触及查询的路径分配失败。批量专项通过 1,362 项组合检查，并用实际读取及哈希计数证明同一次操作内的去重和下一次操作的新鲜校验。

真实 IDE 请求专项通过 169 项检查，保持 C/xlang 输入、删除、撤销、IME、焦点和六参与者屏障；完整配对 GUI 回归及有界启动截图另行记录。来源报告、提供者、静态复检、原生光标和实际 stdio 协议回归继续通过。8 个独立编译的错误实现被断言拒绝；编译失败、崩溃和存活变体均不计为已捕获。详细构建、版本化夹具、历史失败和源码/库身份见 `dev/release-materials/provenance/lsp-edit-candidate-admission-20261113.json`。

本次还修复了来源变化而调用方未请求错误详情时，低层验证路径解引用空错误指针的问题。实际失败栈及修复前后运行记录保留在外部材料中。

后续需要完成常驻后台结果控制器、能力协商及客户端协议取消、与 sourceJobs/屏障的物理读取静止协调、命名模型及物理别名策略、事务写入/确认/恢复和标准协议启用。当前阶段不重新运行一套独立编译器来证明任意服务回复的语义完整性；沿用实际绑定原生服务的静态分析契约。完整泛型/非绑定/外部来源资格、当前引擎资产对齐、其他同步读取点和整体性能/资源/长时间运行验收仍开放。C LSP 保持关闭，不包含 DAP、运行态或调试态补全。
