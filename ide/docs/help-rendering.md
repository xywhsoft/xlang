# 长命令文档的正文与代码块渲染

命令集成帮助保持中央底栏内的单栏长文档。Markdown 围栏代码块继续使用原生只读 CodeEdit；C 和 xlang 分别使用现有语言注册、高亮和字体，章节、正文、选区与滚动模型保留。

## 缓存生命周期

主程序在输入、布局、会话阅读位置和控件更新完成后，调用 `xideCatalogViewPrepareRender`。该入口先完成最新布局，再以帮助滚动视口、工作台目标区域和控件的有效可见性核对每个正文标签及围栏代码块。

- 与阅读视口相交的正文标签和代码块恢复创建时的缓存策略，由固定 SDK 正常生成位图并绘制正文及语法颜色。
- 屏幕外正文标签和代码块切换为无位图策略，并清空缓存槽。帮助页签隐藏时也立即释放这些位图，不依赖隐藏子树的后续渲染遍历。
- 清理只影响位图。只读编辑器、正文、语言、版本、选区、章节与布局高度继续存在；重新进入视口时按当前字体、主题与 DPI 重建缓存。

固定 SDK 的 Label 和 CodeEdit 都通过缓存绘制回调输出文字。可见正文和代码块必须恢复原缓存策略；直接禁用正文标签缓存会保留段落布局高度，却不再绘制标题、说明、列表和表格文字，形成大片空白。代码块的外层容器没有独立文字绘制，继续保持无位图策略。独立嵌入工作台而自行调用 `xuiRender` 的开发夹具应在布局后调用 `xideCatalogViewPrepareRender`；正常主程序通过 `xideAppFrame` 自动调用。

## 验收与当前范围

`tests/help_render_test.c` 在未切换到用户桌面的真实 XGE 窗口中验证默认文档和包含 40 个 C/xlang 示例的长文档，遍历全部示例、章节跳转、隐藏/重开、主题、界面字号和 125%/200% DPI。测试读取实际缓存像素检查标题、正文、列表、表格文字及关键字颜色，并要求屏幕外正文与代码缓存均已释放；只检查非空文本或几何尺寸不足以发现正文消失。测试同时保护打开的 C/xlang 草稿、正文版本、选区和真实撤销/重做，保存原生截图。`--baseline` 仅供重新链接历史业务对象后的保留量复现，不进入正常回归参数。

颜色检查允许每个 RGB 通道至多 8 的抗锯齿色差，仍要求多个实际文字像素；细字形未必含有完全等于主题色的像素。将新测试链接到修复前的帮助实现时，正常回归模式必须在正文像素检查处失败。

修改前的固定业务对象在 4K 窗口中为默认长文档的 40 个屏幕外代码块持有 57,511,968 字节逻辑 RGBA 位图。此数值是代码块缓存的统计，不代表整个进程或 GPU 驱动的总内存。新版本的正常检查要求屏幕外围栏代码块没有位图；进入视口的示例仍必须生成真实彩色像素。

## 单个超长代码块

每个围栏块以无位图容器保留完整文档高度，里面的只读 CodeEdit 始终持有完整正文与语言。渲染前按外层阅读视口移动它的显示窗口，缓存高度上限为视口高度加 128 DIP。代码编辑器的垂直偏移抵消窗口位置，行号与跨行语法使用原始全文；不会切分源码或重建选区。短示例仍按自然高度显示。

垂直滚轮作用于外层长文档。只读编辑器的键盘导航与拖动选区沿用原生处理，并将目标光标带入实际阅读视口。水平偏移独立保留；内部垂直滚动条移到容器裁剪范围之外，文档仅使用外层垂直滚动条。全文复制仍使用原生 CodeEdit 的完整文档与选区。章节与阅读恢复以完整容器高度和文本身份记录。

修改前的业务对象实际复现了 2,500 行 C 围栏块：布局高度 46,879 DIP，滚入视口后记录 `XUI_ERROR_INVALID_ARGUMENT (-2)`。这对应固定 DPI 适配器的 32,768 维度上限；原生返回值与错误回调记录均保存在基线证据中。此复现独立于此前的显卡、资源压力和静默退出记录。

`tests/help_viewport_test.c` 验证 2,500 行 C 与 3,200 行 xlang 的完整正文、跨视口多行注释的真实颜色、只读全文复制、外层滚轮、键盘首尾导航、选区保留、章节之后的正文、阅读位置恢复、隐藏释放、字号和 200% DPI。复制检查在应用初始化入口使用私有剪贴板代理，不读取或改写系统剪贴板。测试编译真实应用源，除该初始代理入口外执行生产应用帧；其他测试继续链接独立应用对象。

主目标表面、字体、其他控件、单条命令的短示例及驱动内部资源另有生命周期。更大项目、超宽源码行和外部内存压力继续独立核对。此项不据此宣告此前 DPI 资源失败、最大化内存失败或原生静默失败的原始原因已解决。
