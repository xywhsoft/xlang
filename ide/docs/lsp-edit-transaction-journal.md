# WorkspaceEdit 追加式事务日志

M7b5e，2026-11-11。`platform/workspace_edit_journal` 把[恢复准备包](lsp-edit-spool.md)与[逐文件写入器](lsp-edit-file-write.md)连接起来，记录跨文件操作的意图、观测结果和整组阶段。实际测试已通过日志 fence 应用两个关闭文件并逆序恢复。它仍是工作线程基础模块，尚未启用标准重命名、`workspace/applyEdit` 或生产混合文档协调器。

## 存储与开销

专用恢复作用域内新增 `edit-transaction.log`，用 CREATE_NEW 建立普通单链接文件，不覆盖已有记录。Spool、恢复锁、固定 marker、正文和源码门闩必须比日志对象活得更久。日志和所属 Spool 由一个工作线程顺序使用，查询、追加和销毁不得并发。日志不持有 GUI 对象，不保存源码正文副本，不重新捕获来源。私有 Spool 接口借用目录并从已固定 marker 句柄计算原始 SHA-256；首条事件绑定准确的 marker 字节、包 ID 和文档/关闭文件数量。

文件以 `XLEDTX1\n` 开头；每帧是 4 字节 little-endian JSON 长度、UTF-8 JSON、32 字节 SHA-256。摘要覆盖前一帧摘要、长度和正文，首帧以前全零为前驱。序号从 0 连续递增。摘要链用于关联、损坏和顺序检查，不是签名或用户授权。

每个操作只追加当前事件，不重写完整文件表；内存只保留最多 512 个目标的最新观测，不保留全部历史 JSON。记录上限 4,096 条、JSON 每条 64 KiB、文件共 8 MiB。追加前完成事件/状态验证和编码，写入后 flush，再从同一持有句柄读回精确字节并检查文件身份、长度和属性，之后才承认该事件。临时编码、摘要和 JSON 使用 XRT；通用分配器开销仍另外计算，不宣称整体 RSS 上限。

## 阶段与结果

整组阶段包括 prepared、applying、ready、publishing、committed、rolling-back、rolled-back、in-doubt。关闭文件分别记录 before、apply-intent、after、partial、restore-intent、restored、unknown。文件观测必须匹配包内原始身份/快照、编码后大小/摘要及单次写入器的尝试/前缀信息；after 必须有相应的先行意图与已验证结果，restored 必须匹配完整原始快照。

ready 要求所有关闭成员均已确认 after；rolled-back 要求所有成员处于 before 或 restored。publishing 必须先于 GUI 发布，committed 只能在 publishing 之后。publishing 转入回滚还必须明确提供“GUI 未提交”的结果，不能根据缺少 committed 记录推断。终结阶段不再接受修改。缺少结果记录、未知来源、部分写入均不会被当作成功。

写入器的 fence 必须把完整宿主策略与 `xideEditJournalFileIntent` 组合使用。日志确认并不包含请求/连接/项目/配置/全来源/物理别名检查，也不代替注释同意。`RecordFile` 读取真实写入对象的状态，而不是接受服务器提供的结果 JSON；观测仍是历史记录，不能替代提交前的物理与模型复核。

## 不确定结果与重开

追加一旦进入可能修改文件的阶段，先把对象标成 frozen；只有精确读回通过才解冻。写入返回失败、未报告的部分追加、flush 或读回失败都会阻止继续取得写入确认，保留所有日志和准备包。即使失败实际上已写完一帧，也不把上次确认的前缀当成完整实际结果，不在同一对象隐式重试。

Open 总是恢复为只读且 frozen，哪怕记录完整、同进程仍保有源码门闩。有效 begin 之后的末帧不完整会返回带 incompleteTail 的检查对象；完整帧的摘要、序号、绑定或结构错误则拒绝读取并保留字节。日志检查不重新固定源码、不自动应用/回滚，不把记录的 verified 当作重新打开时仍然有效的物理证明。

后续仍需生产协调器、整组内存准入、源码读者/打开操作/监视器/工具链隔离、GUI 发布结果对接、进程退出后的写回恢复和包退役。映射写入、过滤器及掉电/文件系统持久性不由普通共享句柄与本轮进程退出测试完全证明。日志没有接入普通键入或增量分析热路径；不宣称目标全工程的延迟与内存验收已经完成。

## 本阶段检查

覆盖两文件实际应用与回滚、写前意图、部分源码写入、宿主拒绝、GUI 发布前记录与明确未提交后的回滚、终结状态、未报告/部分日志写入、flush/读回失败、失败构造的保留。重算整条摘要链后再篡改包绑定、序号、阶段、目标、动作、摘要、前缀和验证标志，确保结构/状态检查真正生效；另检查完整帧损坏、36 种末尾截断、硬链接，以及在意图前后、应用后结果记录前后分别退出的独立子进程。

基础进程创建控制保留为独立证据：纯 Win32 控制和匹配原生运行库、仅初始化既有基础服务的控制都显示首次创建子进程的固定启动句柄增量，后续三次稳定。主检查先运行无日志/Spool 操作的暖启动子进程，再核对整个测试的句柄平衡；原生 XRT 统计另以真实分配探针验证启用，并逐点拒绝构造/追加的已观测直接分配。
