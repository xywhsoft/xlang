# 重命名的精确标识符范围

已有原生引用会把限定类型名报告为整个 `dep.Other`，成员访问则通常已是单独的名称。重命名现在在原声明绑定和来源校验完成之后，从该原生 token 的末尾取出声明的完整 IDENT，检查名称字节和两侧的原词法边界，再由已核验的终点减去名称的 UTF-16 宽度。没有全文搜索、第二次语义绑定、AST 遍历或前缀扫描。

原引用 key 在构造时调用现有 `xlsIdentifierValid`，保留名称的 UTF-16 宽度；新读取接口只借用同一 key 的数据，不再重复扫描。key 的新增私有字段计入已有字节预算。引用 shard 和每条记录没有扩容。原 query 仍执行完整声明来源比较；备用路径比较也可能分配。这些原成本没有被忽略，逐条精确范围读取才是不分配、只比较名称字节和固定边界的路径。

`xideSemanticReferenceShardIdentifiers` 沿用原 query 的声明身份、完整 post-BOM 来源和声明包含选项。视图的名称借用 shard 自己的来源副本，不借用 key、AST、check 或调用者的源向量；只要保留 shard，原 check 和 key 销毁后仍可读取。UTF-8 字节偏移与 UTF-16 位置分别计算，保留原捕获器的 BOM 约定。emoji 和中文不按字节数当作编辑列数。

普通引用接口保留原区间。逐工程及全工作区重命名收集改用精确接口，限定名前缀不会进入编辑范围，同名字段仍由原生声明身份区分。无法证明为完整、实际拼写的标识符时拒绝整次收集，不能静默丢掉某个引用。原生可变参数 `...` 有普通引用身份，但不是 IDENT：普通查询继续可用，精确查询返回明确的不支持状态，目标捕获也不把它当作可改名名称。

原生测试覆盖限定类型、中文名称、emoji 字段、BOM/CRLF、跨编译所有者、声明过滤、无效视图、独立生命周期和真实可变参数。工作区测试经原后台 actor 验证精确位置、限定前缀保留、另一类型的同名字段排除、热复用和结果脱离原查询后的存活。原生探针、首次测试缺少路径声明头的编译失败以及后续扩展测试的原件均保留。

这完成了已绑定引用的精确名称投影。继承、重载、泛型特化及构造器等族闭包的完整性仍未证明，不能从局部引用集直接授权改名。物理别名与可写性、完整库/外部符号策略、冲突和改名后绑定证明、版本化 WorkspaceEdit、IDE 原子应用及全目标性能、规模与内存准入仍须继续，尚未注册 `renameProvider`。材料入口为 `dev/release-materials/provenance/lsp-rename-identifiers-20261110.json`。

最终源码完整通过 170 个原生夹具、10 套协议和 27 个 IDE 夹具；名称投影专项 141 项、工作区接入 86 项检查通过。五个实际 C 变体分别退回原区间、混淆 UTF-16 宽度、混淆 UTF-8 字节偏移、忽略来源拼写或略过原生 IDENT 校验，均被拒绝。资格检查绑定 278 个消费者、171 个程序及 core 全部成员，GUI 完整重编译 116 个对象并配对同一服务和匹配 SDK；C/xlang 输入、删除、撤销、Unicode/IME、焦点及相关语言功能通过，浅色与深色帧已复核。默认发布程序未替换，未进行新的正式性能准入或线上发布。
