# 原生编辑的宿主保护策略

M7b6e，2026-11-14。接续 M7b6d 的异步混合事务，新增自动收集宿主保护路径的内部入口 `xideLanguageEditApplyBeginManaged`。公开的符号重命名窗口、交互保存/关闭和恢复操作仍待接入；本阶段没有启用通用 `workspace/applyEdit` 写入权限。

保护集合来自当前进程的原始资源位置、实际选中的编译器、会话存储位置、当前设置、工作空间及全部项目清单。不可用项目的清单也不能跳过。没有工作空间或会话对象时，仍能为单个 `.xl` 文件建立保护集合。路径解析只做词法绝对化，不在 owner 上读取源码或重新加载清单。

IDE 与编译器旁的 `data`、`extlibs`、`include`、`notices`、`option` 是受保护目录；已知运行程序、DLL、设置和清单按精确文件保护。不会把整个发行根目录、`examples`、`projects`、用户工程目录或所有 include 路径一概设为只读。用户显式指定的 `--session-root` 是 IDE 数据存储根，其全部内容受保护；源码应放在该根以外。

集合最多 255 项、1 MiB UTF-8 路径文本和 4 MiB 已知元数据。重复路径使用既有的 Unicode ordinal 比较合并；同一路径的文件/目录角色冲突、缺失项目清单、容量不足或无法分配时拒绝整个操作，不截取前缀。字节数不包括线程栈、分配器及系统内部资源，不是 RSS 上限。

Begin 在会话存储根下分配独立的 `.xlang-ide-edits/edit-<GUID>` 路径，仅复制元数据；用户确认前不创建恢复目录，不取得源码屏障，不执行事务准备和写入。连续操作复用常驻工作线程，但使用不同的恢复目录。原有显式传入保护集合的 API 保留给内部测试和受控调用。

确认时重新捕获完整宿主集合；Capture、Arm 和 Publish 的 owner guard 再次比较。如果设置、会话存储或清单路径变化，确认被拒绝，或在既有恢复许可下回滚已经发生但尚未提交给编辑器的写入。保护集合相等不代替语义 Current、真实六参与者屏障、原始文件身份和正文证明。

物理别名门在目标和祖先句柄全部固定后，还检查句柄返回的规范路径。`.xlang-ide`、`.xlang-ide-build`、`.xlang-ide-edits`、`.xlang-update`、`.git`、`.hg`、`.svn` 任一完整组件均不可作为源码目标。检查覆盖实际目标及其祖先，因此不存在的 overlay 文件也不能通过父目录短名绕过保护。相似但不同的用户目录，例如 `.git-sources`，仍可编辑。检查在后台进行，不读源码正文、不暴露写句柄。

物理保证继续限定为既有的普通本地固定磁盘对象、单链接目标及被持有的名称/身份。它不是对任意内核、卷映射变化或独立外部程序的全系统原子事务保证。IN_DOUBT、丢失的参与者令牌和冻结日志仍按既有规则保留屏障及恢复资料，不自动重放或恢复读者。

验收包含 15 个真实 IDE 场景：原有 9 个场景、自动保护下的连续重命名、确认前存储路径变化、实际写入后宿主路径变化回滚、被设置文件保护命中的 `.xl` 目标、整个指定数据根被保护，以及无工作空间/无会话对象的单文件重命名。C/xlang 的输入、删除、撤销、Unicode/IME、点击焦点仍有实际 XUI 检查。另检查完整保护集合、Unicode 去重、分配失败、容量门槛、物理别名、缺失文件和句柄平衡，并用实际编译的错误实现验证关键断言。

详细的实际构建、测试次数、短路径是否实际可用、失败历史、截图和依赖身份见 `dev/release-materials/provenance/lsp-native-edit-protection-20261114.json`。本阶段重编译全部 GUI 单元，原生服务与前端闭包未改变，复用并重新核验上一阶段同一服务；旧协议测试只作为已提交证据引用，不能算作本轮重新运行。

下一步是符号重命名确认/进度/恢复窗口，以及交互保存与关闭协调。公开标准协议入口、引擎资产对齐、泛型/外部来源资格、其他同步读者、整体时延/RSS/耐久、Linux 与 sanitizer 验收继续开放。C LSP 仍关闭；不包含 DAP、运行态或调试态补全。
