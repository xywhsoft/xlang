# 导入候选报告的调用内索引

本阶段针对 M7b4o 实测的 2,048 条导入候选上限及重复线性扫描。复用 XRT intrusive AVL 和既有原生词法路径键，为一次前端调用中的来源报告建立可选索引；不改导入搜索顺序、首个探测结果、路径身份或文件状态检查。

原生报告仍是事实来源。每个新追加的来源行和候选行只准备一次路径键，索引保留原生首行序号，不保留数组元素地址，因此报告扩容不会留下悬空指针。来源和候选可共用一个键。少于 32 个来源且少于 128 个候选时沿用原扫描，不分配索引。查询结果区分命中、完整未命中及回退；分配、键转换、比较或额度失败均关闭本次调用的加速并执行完整原扫描，不能把资源错误解释为文件不存在。

调用作用域中的所有报告合计最多使用 8 MiB 已知索引存储，包括索引、报告状态、节点和保存的路径键。临时查询键、分配器开销以及原有报告、源码、AST/IR 不计入此数字，不能将它当作 RSS 上限。报告 Init/Free 会从所有外层活动作用域撤销对应索引；调用退出销毁剩余索引。索引不进入常驻历史、磁盘缓存或跨调用复用。统计累计两次原生重试的工作量，peakBytes 取调用内最大值。

候选行上限调整为 65,536，原有 1 MiB 候选路径总字节额度保留，来源数量仍为 512。触及任一额度仍拒绝完整报告。宿主和服务使用同一常量；多个报告合并的防护路径总上限仍为 163,840。宿主对报告的重复路径验证改为一次准备原生路径键、排序、相邻比较，保留每行结构、绝对路径、包环境及实际文件状态验证。原生报告的顺序不变。

测试直接对照原生路径匹配器和首行顺序，覆盖 Unicode、大小写别名、缺失路径、所有校准的节点分配/键转换/比较拒绝、嵌套报告重置、8 MiB 回退及所有权平衡。完整候选检查覆盖 130 来源的裸名称导入、512 来源的裸名称导入和 512 来源的显式路径导入，每种均与完整磁盘原生索引对照。宿主专项覆盖 4,096 个候选及重复、状态变化、相对路径和取消拒绝。

专项性能对比固定解析器、语义/索引、输入、编译选项和容量，只替换来源报告查找实现。两端均执行完整磁盘分析，不使用会话或增量缓存；逐次核对完整索引、来源正文/角色/长度及按序候选路径和首个存在状态的摘要。专项不代替全目标性能、大工作空间、当前引擎资产对齐及长期运行验收。

2026-11-11 本机专项计时包含解析、导入、语义、typed-IR 和索引 JSON 生成，结果摘要与析构在计时之外。原线性实现仅将候选容量调为相同的 65,536，其他条件一致；按原版、候选、候选、原版顺序运行。每组首次分析保留原始样本，但以下中位数排除首次样本；32 来源及以下各有 46 个样本，更大用例各有 10 个样本。文件刚写入，不能把它称为冷磁盘测试。

512 来源用例约为原来的 5.04 倍速度，索引已知峰值 687,174 字节，无额度回退。1 和 16 来源的观测值略慢，8 来源的早期明显退化通过提高门槛消除；不能据此声称小用例零开销。上述是当前简单导入语料的完整单次分析数据，不是 IDE 端到端或热增量延迟承诺。原始样本、完整输出一致性摘要和匹配构建身份随阶段材料保存。

普通 64 个编辑覆盖输入的边界保持原样；来源共享、其他热点、完整重命名策略和 IDE 原子编辑事务仍在长期任务范围内。标准 renameProvider 继续关闭。

阶段验证包含 186 个原生程序、12 组协议测试、29 项配对 GUI 检查及全部 116 个 GUI 对象。索引专项 37,278 项检查、完整来源专项 9,394 项检查、宿主报告专项 4,508 项检查通过；额外实际工程验证 512 来源、3,577 候选及合并防护的完整性和额度拒绝。三个实际实现变异分别破坏首行选择、报告重置撤销和容量，均被测试检出。候选程序在根发布目录加载真实依赖接受验证，默认发布程序保持原样；当前引擎对齐及整项交付仍需后续准入。[阶段材料索引](../../dev/release-materials/provenance/lsp-report-index-20261111.json)记录源码、头文件、对象、程序、原始样本及外部材料摘要。
