# 大源文件编辑性能记录

2026-10-10，长期实现任务仍在进行。本增量保存了原生性能探针、私有 SDK 优化源码和复现工具；当前应用核心、固定 SDK、编译器及便携发布包保持原来的字节。实验版八组原生用例功能通过，但超长单行仍有明显延迟，性能验收未通过。

## 测量边界

使用真实工作台、XUI CodeEdit、窗口消息循环及原生窗口截图。窗口为 1600 × 1000，DPI 覆盖为 1.25。每例在独立且从未切换到前台的 Windows 桌面中创建进程，自己的 Job 从 GUI 初始化前限制进程私有提交为 2 GiB；超时只终止自己的 Job，不调整系统内存设置。

输入为精确 2 MiB 或 16 MiB 的 UTF-8 文件，包含中文、Emoji 和组合字符：一类重复多行注释，另一类为一条很长的注释。每例检查语言识别、打开、真实帧绘制、Ctrl+End、插入一个字符、撤销、Ctrl+Home、重复定位和空闲帧，共 43 项断言。SDK9 八例实际退出码均为 0，共 344 项断言。

探针调用真实 XUI 输入和动作分发，后台窗口另有 10 ms 消息脉冲记录消息处理延迟。它不是实体键盘或 IME 测试。语言服务未配置，16 MiB 编辑通过不代表同尺寸语义分析通过。编辑器的原有 16 MiB 文件限制没有降低。

“打开”只计加载及打开调用，“编辑帧”计打开之后的帧，不包含启动帧。插入和撤销时间不包含随后的绘制，所以不能当成用户所见总响应时间。私有内存是每次操作结束后的采样，表内最大值不是进程真正的峰值提交；`peakWorkingSet` 是 Windows 返回的进程峰值工作集。单次测量没有统计稳定性声明，也没有预先约定的性能通过阈值。

## 实际结果

SDK9 为私有实验构建；以下时间单位为毫秒，内存单位为 MiB。它未进入当前发布包。

| --- | --- | ---: | ---: | ---: | ---: | ---: |
| C | 2 MiB 多行 | 23.3 | 10.5 | 10.1 | 6.4 | 434.6 |
| C | 16 MiB 多行 | 153.8 | 80.4 | 79.3 | 6.1 | 513.5 |
| xlang | 2 MiB 多行 | 19.9 | 7.1 | 6.8 | 6.6 | 436.3 |
| xlang | 16 MiB 多行 | 129.8 | 55.4 | 52.7 | 10.4 | 529.4 |
| C | 2 MiB 单行 | 53.8 | 416.7 | 316.2 | 1090.4 | 479.2 |
| C | 16 MiB 单行 | 492.7 | 3628.2 | 3061.4 | 8836.2 | 964.2 |
| xlang | 2 MiB 单行 | 41.2 | 423.0 | 318.4 | 1069.2 | 480.0 |
| xlang | 16 MiB 单行 | 298.2 | 3336.1 | 2524.5 | 8161.0 | 964.6 |

C 的 16 MiB 单行最高消息脉冲延迟为 11,688 ms，峰值工作集约 1,407.2 MiB。八例完成说明功能在本次进程预算内闭环，秒级延迟仍须解决。

原始发布 SDK 的 C / xlang 2 MiB 单行插入分别约 5,045 / 5,058 ms，最大编辑帧约 10,208 / 10,256 ms。原始 C 16 MiB 单行在 180 秒观察期限内未完成，实际退出码为 1；原始 xlang 16 MiB 单行未运行，不能填充对照结果。多行原始基线及所有失败原始日志均保留。

原始 SDK 来自 GCC 16.1.0，三个私有构建来自 GCC 16.2.0，因此这些时间只展示观察到的差异，不能把差异全部归因于源码优化。中间 SDK7 的 C 16 MiB 单行使用过 GDB 采样，也在观察期限内未完成；该测量受到采样影响，不能作为无干扰性能基准。

## 源码修改与验证

原始大单行采样涉及 Unicode 类别查询、字素遍历、Emoji 匹配和文字整形；SDK7 的采样曾落在行布局的后备绘制路径。旧版本行布局在缓存中占用内存，新版本布局分配受到进程预算影响，是本次实验的解释之一，尚不足以证明历史 GPU 错误的完整根因。

实验依次加入类别只读查表、Emoji 根节点索引、Glyph run 分配与屏幕外绘制优化、文档版本改变时清理过期行布局。公开头没有修改，XRT 仍只由 `xge.dll` 提供。类别查询对全部 1,114,112 个码点值及 5 个额外越界值与旧实现逐个相同；索引的合成等价检查完成 30,010 项。类别等价生成器使用 O0，仅作功能等价证据，不作速度基准。

SDK5、SDK7、SDK9 均由各自完整的 237 个材料冷构建，实际退出码为 0；SDK 构建没有开启 `-Werror`。三个 SDK 的原始 Unicode 与 Emoji 测试分别通过。最初 Emoji 测试缺少工作目录中的 manifest 资源而失败；保留失败，随后复制哈希核对过的原始资源重新执行，两项测试均实际退出 0。

SDK5 与 SDK7 的同一 C 2 MiB 单行截图像素完全相同；原始 SDK 与 SDK5 的截图只有 20 个光标区域像素不同，不是完全相同。人工查看了 SDK9 的 C / xlang 16 MiB 截图：左侧命令列表、中央编辑器和仅在中央的帮助底栏、右侧上下工作空间和属性保持定版布局，中文、Emoji、组合字符与语言状态可见。这些有限截图不证明所有字体越界、SVG 溢出或 DPI 裁剪正确。

原始探针 v1 严格链接失败、v2 的中文 argv 转码失败、类别生成器及索引夹具失败、SDK 链接来源核对失败和两个原生观察超时均保留实际日志，不计入通过项。最终探针 v3 在相同的 83 个当前核心对象上严格链接；这里没有再次执行应用核心构建或标准全量回归。发布版本继承前一增量的验收，并用本次冻结材料验证原始 578 个材料和保存副本、105 个运行输出、83 个核心对象及三个编译器产物保持不变。

## 后续工作

优先优化超长单行的整形、绘制、坐标查询和重复扫描，保持字素、Bidi、字体回退及撤销语义。增加 SVG 溢出、字形边缘、剪裁边界与 DPI 的专门验证，再进行完整 IDE 回归。通过后才替换成套 SDK，并重新执行应用严格构建、标准全量和便携发布验收。

正式首版仍需干净 Windows、实体 IME、混合 DPI、完整 SDK 许可及重链接审查等验收；无 8.3 名称的深工作目录、完整 C 输入依赖图与 ABI、历史 GPU 失败的完整根因也尚未解决。本增量不宣布首版或长期任务完成。
