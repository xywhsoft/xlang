# 编辑请求的同步快照与失效生命周期

M7b5r，2026-11-13。`services/edit_request`、`ui/edit_request_view` 和 `xideSourceBarrierBeginEdit` 连接请求发起前的本地输入捕获与已有六参与者源码屏障。标准重命名与 `workspace/applyEdit` 仍等待完整宿主、来源闭包、回复校验、用户确认及恢复接入。

主语言视图只允许一个未结束的编辑请求。在原生连接初始化、同步批次和真实 `inputState` 确认均完成后，Capture 核对 URI/版本摘要、全部同步绑定的本地身份/修订、当前模型和分析配置，再保留一个请求。它预留同一连接内未使用的正请求 ID 和视图生命周期内不回绕的令牌；尚不发送重命名请求，也不把任意回复当作可应用计划。后续请求控制器必须同时绑定方法、ID、令牌和来源证明。

请求独立持有 `xlsSyncClone` 的不可变条目和文本、生产者的只读配置 catalog，以及完整 Document 槽位的身份、修订、开关状态、dirty、外部状态、路径和语言。模型存储用一块 XRT 分配，最多 4,096 槽、1 MiB 已知模型对象及字符串；两次捕获回调期间调用方保持模型稳定。同步克隆的元数据、共享正文/catalog、分配器和系统资源额外，不是进程内存上限。底层构造器接收调用方完整清单，主视图负责清单与实际同步绑定的一致性。没有保存 app、context、store、widget 或输送客户端指针到共享对象。

UI 视图保留一份请求，调用方取得另一份供 worker 使用。不可变访问器在独立保留期间允许并发读取；原视图、连接、同步器销毁后仍有效。XRT 原子失效原因只累加，不因输入撤销、项目或配置切回、连接重新建立而复原。End 只接受当前视图实际持有的同一请求，解除视图引用并标记结束；调用方将可能释放最后正文/catalog 的引用交给工作线程或最终关闭流程。

普通内容通知、成功保存、磁盘通知、模型元数据变化、语义配置改变和连接重置均通知实际挂接的请求。普通路径增加一次可空指针检查及必要的原子标记，不新建正文扫描、容器或后台任务。语义配置相等的树刷新和显示名称变化继续保留连接及请求。真正的配置变更采用现有完整 canonical catalog 比较，沿用现有分析配置构造器，不以字符串前缀或仅哈希替代。

`Owned` 只做当前视图、请求对象、连接和原子标记检查。`Current` 在准入、Arm、Publish 等明确边界复核全部模型元数据，以及当前 canonical catalog、包环境和所选编译器路径。它有受限的模型扫描、配置构造/比较和路径准备成本，不用于每次键入或屏障轮询。被 suppress 的内容回调依然推进 Document 修订，必须由这个完整 owner 检查发现；工作线程的原子标记不单独证明所有来源仍然有效。

BeginEdit 先执行 Current，再取得已有六个参与者；失败前缀仍需显式 Resume/Release。它为屏障保留请求引用，State 使用 Owned 做轻量失效检查。取消或 End 后 quiet 可以仍成立，ready 永远不能重新成立。End 不提前释放任务、监视器或语言参与者；屏障最终 Release 才释放其请求引用。通用 Begin 保留原有“只证明登记参与者”的用途，不能作为编辑请求准入的替代入口。

新增严格捕获暴露了既有时序缺口：文件通知真正发送时会推进 `sentSerial`，此前的 URI/版本确认即使仍标记 ready，也未确认这个新 serial。`automaticWatchSent` 现在取消并退役旧确认 ID，清除 ready，由现有控制器取得新 `inputState` 回执。已排队的旧响应不能再激活旧 ready。没有放松 serial 匹配，也没有把客户端已排队等同于服务已接受。

专项使用原有同步器实际创建 8 MiB 文本，证明请求持有同一文本租约与 catalog；原所有者释放后，四个真实线程继续读取。覆盖 4,096 模型边界、元数据限额、全部模型字段、捕获回调失败前缀、可观测直接分配拒绝和不可逆失效；DLL 内部分配不在直接故障探针覆盖之内。

真实 IDE 专项使用实际原生 stdio、输入确认和六个参与者，覆盖项目/配置往返切换、显示元数据刷新、直接模型和环境变化、失败准入前缀、取消、提前 End、停止/重建、令牌/请求 ID 耗尽以及 UI 销毁后的工作线程退役。C/xlang 均执行点击聚焦、输入、退格、撤销和 Unicode/IME。真实 watch batch 定向检查旧回执撤销与新的服务确认。

首次输入夹具遗漏物理键 down/up，已修正为已有输入验收的完整事件顺序并保留失败日志。第二次及诊断尝试保留了真实旧回执 serial 落后的证据；修正生产控制器后重新冻结完整 GUI 构建。材料索引为 `dev/release-materials/provenance/lsp-edit-request-scope-20261113.json`，大型源码、对象、原始日志和截图继续放在外部开发资料包。

本阶段没有把请求失效状态当作完整来源/解析候选、物理写权限或用户同意。完整事务宿主、其他同步读者、启动恢复、协议入口启用、全目标性能/资源/长时间运行、当前引擎对齐与默认发行仍需继续。外部语言服务和匹配 SDK 在本阶段沿用已验收身份，C LSP 仍关闭，不含 DAP 或运行/调试态补全。
