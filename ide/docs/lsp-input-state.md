# 在线文档同步确认

服务 0.23 的 `xlang/inputState` 返回协议 owner 已接受的 URI／版本集合摘要及当前输入代次，供 IDE 在发送一批同步通知后建立接收边界。请求不等待分析、合并或文件观察，也不启动分析任务。服务在 `capabilities.experimental.inputState:true` 声明支持。

```json
{ "jsonrpc": "2.0", "id": 20, "method": "xlang/inputState", "params": {} }
```

`params` 可以省略或为空对象；其他类型和非空对象返回 `-32602`。服务完成初始化后才接收请求，响应为：

```json
{
  "jsonrpc": "2.0",
  "id": 20,
  "result": {
    "schema": 1,
    "generation": "12",
    "documents": 2,
    "sha256": "<64 lowercase hex characters>"
  }
}
```

集合只包含当前服务已接受并仍在线的文档。通知按原流顺序处理，非法打开／变化通知不修改文档，也不进入新的摘要。请求位于一批通知之后，响应对应这些通知处理后的状态；读线程此后接收但 owner 尚未处理的通知不被提前计入。它确认 URI／版本绑定，不确认源码分析已经完成。

## 共享实现与开销

`protocol/input_state` 的头文件只依赖标准 C 的类型，GUI 同步模块和独立服务共用实现。URI 按线上原拼写编码，不按物理路径合并；打开时缓存其 UTF-8 SHA-256。每次状态查询仅复制、排序和编码最多 64 份固定大小的 URI 摘要／有符号版本，不扫描或复制正文，不访问文件系统，也不等待后台执行器。摘要复用 XRT 的 SHA-256，临时排序和编码在有界栈内完成。

版本 1 的摘要编码定义为：

1. 固定 ASCII `xlang-input-state-v1` 及一个 NUL 字节。
2. 四字节大端无符号文档数。
3. 按 URI 的 32 字节 SHA-256 升序排列，每项写入该摘要和四字节大端版本；版本为有符号 32 位数的对应位模式。
4. 对以上字节执行 SHA-256，输出 64 位小写十六进制文本。

输入顺序不影响结果。超过 64 项、缺少输入或重复 URI 摘要会失败，输出字符串清空；没有把冲突悄悄合并为一份绑定。空集合的摘要为 `b921fd41e71c0d4301ca5fcff0631d82b415d5216ad0648d155596afd3142067`。摘要采用与既有正文证明相同的密码学哈希假设，不是可逆编码。

`xlsSyncInputState(sync,digest,&documents)` 返回 GUI 同步器成功发送的绑定集合，复用缓存的 URI 摘要。验证或发送失败时不能产生成功状态；发送失败的同步器继续要求连接重建。它本身不代表服务已经接受，客户端必须与真实响应比较。

## 使用边界

客户端应先捕获当前连接、配置和所有参与文档的本地身份／修订；使用现有同步器发完通知，再请求状态。只有响应仍对应这个本地批次，且数量与摘要完全相同，才可建立该连接的输入代次边界。后续新通知的接收还需与 [文件输入证明](lsp-diagnostic-proofs.md) 中的正文、版本、来源和磁盘身份一起验证。

该摘要不包含正文、编辑器文档身份、磁盘输入、解析候选或语义依赖。同步器的身份／修订必须继续精确标识正文；摘要相同不能代替这项约束。关闭后以相同 URI／版本重新打开可以得到相同摘要，即使正文或本地控件已经不同；因此还需连接生命周期、代次和本地模型保护。服务重启后的 generation 重新开始，也不能跨连接直接比较。

当前已提供协议和共享同步接口，IDE 自动诊断控制器尚未接入；主诊断／导航和独立补全客户端继续显式关闭自动诊断，原有批次行为保持。后续接入需保留无关文件的有效诊断，正确处理撤回与新输入等待，不能因为全局清空后服务没有重复发送未变化分组而丢失结果。

`document_sync_test` 对照独立生成的固定向量，验证空集合、顺序、版本、容量、失败输出、身份变化和传输失败。`tools/check_lsp_input_state.py` 使用独立 Python 编码及真实 stdio，覆盖多通知顺序、拒绝／原子变化、关闭重开、64 份文档、有符号版本、非法参数和实际大文件后台分析期间的返回。单次观察时延仅作为该场景证据，不是最终 P95／P99 或 UI 显示时延验收。
