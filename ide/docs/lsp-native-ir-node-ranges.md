# 原生 IR 阶段中的节点区间生产

在分阶段构造器内增加 15 个原生步骤的有序节点区间入口。入口直接执行指定区间的原始循环体，没有先完成全模块生产再过滤结果。普通语言服务继续使用已验收的保守 0.110；本阶段组件仍只用于显式开启的原生验收配置。

覆盖命名调用 ABI、投影域、拥有结果读取、隐式名称 ABI、调用种类归一化、内建调用、调用表、值初始化、原生句柄绑定／投影、运算符、转换、成员、动态调用和隐式转换。每个步骤的完整原生正文均有摘要审核；不能把含多轮依赖扫描的步骤按函数随意交错，因此 INDEX、循环 ABI、退出计划以及其他全局步骤仍保留完整入口。

## 有序推进

`xlsIrNativePipelineAdvanceNodes` 从当前节点游标执行到指定的独占上界。上界必须大于游标且不超过节点总数。该阶段最后一个区间完成后，才能执行必要的阶段收尾、推进阶段编号并清空节点游标。

值初始化表只在第一个区间清空；调用契约和成员阶段的拥有读取收尾只在最后一个区间执行。`Advance` 或 `Finish` 能接续已有区间的剩余部分。`Reset` 清除游标并退休部分模块。非法范围或不支持的阶段不会丢弃已有状态，构造失败及取消仍退休半成品。

未完成的阶段不可能变成 Ready，也不能 `Take`。完整统计和原生 verifier 继续是最终取出模块的必要条件。原始完整函数保持原样，区间入口从审核正文另外生成，并保留本来的错误处理和逐节点取消检查。

当前独立生产过程中原始 memo 及载荷借用仍关闭，外层线程上下文在调用后恢复。此入口没有引入复用资格，也不能凭它跳过未改变函数。后续跨代缓存必须补齐完整输入证明、旧记录插入／重定位及全局上下文处理。

## 验证范围

新夹具通过 49 个完整语义输入和 66,218 项断言，将区间完成后的全部 IR JSON 与原有完整语义检查逐字比较，并保留完整原生验证。三种推进方式各枚举 161 个外部 XRT 分配／API 拒绝点和 77 个取消点。另验证中途重置、非法范围、阶段游标以及 `Advance`／`Finish` 接续行为。

循环中的独立观察点确认实际访问的位置与请求区间一致。计数包含 739,088 次该观察点访问及 13,788 个成功区间；这些是夹具覆盖数据，不是性能收益。额外的 256 函数探针在 f128 的 23／5,902 个原始节点上实际生产一条目标调用，完整检查则包含 256 条该目标调用；范围外节点的所有原始字节保持一致。该探针的部分模块不作最终 IR 使用。

首次探针错误地用函数声明的文本作为函数名，并把 `print` 视为该调用表的生产样例。实际原生表示及独立完整结果推翻了这两个假设。夹具改为按名称节点的父声明识别函数，使用显式用户函数调用，并保留原始失败和诊断程序；没有调整产品实现来迁就探针。

线程上下文夹具新增两个 class／enum 构造器在区间中途交错推进，覆盖主线程和四个工作线程的 2,200 次作用域及 5,714 项断言，验证外层 memo、拥有者、类型索引和失败标记恢复。普通关闭配置、完整来源审核及相关回归另行验收。源码、对象、命令、失败记录和缺陷注入材料放在开发材料包，索引为 `dev/release-materials/provenance/lsp-native-ir-node-ranges-20261123.json`。

这仍不是普通分析中的最终函数 IR 缓存，也没有改变任何既有性能门槛或重新放行失败的实验。下一步需要用这些生产入口完成未命中函数的真实生产，并将经过证明的旧产物接到同一阶段顺序中。
