# 工作区独立文件分析范围

M7b6i，2026-11-15。已解码工作区的独立 `.xl` 文件引用现在进入分析配置，包括尚未打开的文件。标准 prepareRename、rename、私有重命名候选及工作区符号搜索共用这一范围；不扫描目录或重新读取工程清单。

配置包仍是 `{epoch, catalog}`。catalog schema 2 在原有四个字段之外增加 `standaloneRoots` 和布尔 `complete`。无独立 xlang 文件且工程均可用时继续生成 schema 1；服务接受两种 schema。原生服务声明 `experimental.analysisCatalog: 2`，IDE 使用 schema 2 时要求这一能力。IDE 与服务需配套更新；旧服务拒绝新配置时报告不兼容，不降级成缺失文件的范围。C 编辑、语法着色和编译运行保持原有路径，C LSP 默认关闭。

服务先建立原有工程成员索引，再与显式独立文件取并集。工程已有的成员不增加独立角色；独立根用原有 native lexical path key 合并重复和大小写别名。目录相同、恰好被导入或存在于磁盘上，均不构成成员归属。独立根保存不可变上下文，打开别名时复用准确上下文；同根不同配置会被拒绝。工程枚举、工程归属和 selectedProject 规则不变，独立根单独枚举。

原始根列表最多 65,536 项，单路径最多 32,767 UTF-8 字节，路径标签累计最多 16 MiB。去重并扣除工程归属之后，工程与独立角色合计最多 64 个。额外在线独立文件与这些根合并，再检查上限。沿用已有上下文、路径键和重命名保留量限制；超限、非法路径、类型不符及配置冲突均整项失败。已知 payload 计费不代表总 RSS，配置 DOM、临时构造和分配器仍有额外开销。

未加载或缺少入口的工程使模型生成 `complete: false`。当前文件仍可分析，但准备重命名、重命名和工作区符号搜索明确拒绝，不能把缺失工程当作空工程。选择不可用工程仍按原有规则报错。完整配置恢复后可重新执行全局操作；配置变化沿用现有 epoch、取消、输入守卫和租约。IDE 的 catalog 比较包含独立文件列表，移除闭合文件会撤销旧结果。

原生验收覆盖闭合声明及调用文件、零在线文档的符号搜索、工程重叠、别名、完整性拒绝及恢复、配置后旧结果撤销，以及去重前后不同容量边界。C 专项覆盖准确上下文、保留寿命、最高角色位和失败路径。实际编译的错误实现验证漏根、漏完整性检查、重复角色及冲突配置会被测试发现。IDE 专项验证闭合文件搜索和移除后配置失效，同时保留编辑器默认空白页。

IDE 语义名称预填、标准客户端工作区自动加载、通用 workspace/applyEdit、完整性能/RSS/耐久与平台准入继续实施；本阶段只使用客户端已声明的工程和文件集合。配置切换的缓存构建次数断言在候选及上一阶段服务中均失败，原始证据保留，未计为通过；此前三项旧对话框失败也未宣称修复。引擎资产对齐、泛型/未绑定/生成事实与外部来源资格及其余适用 LSP 仍开放。正式运行程序、SDK、active delivery 和线上更新未替换。材料索引为 `dev/release-materials/provenance/lsp-workspace-file-scope-20261115.json`，长期任务保持进行中。
