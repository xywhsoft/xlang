# 同作用域的重载与属性关联

在原生派发关联查询中，增加同一词法所有者内的重载声明，以及同名属性的 GET/LET 声明关联。类方法、协议成员和顶层函数分别保留原生作用域；不同类中的同名方法不会因为拼写相同而关联。查询将这些关系与虚方法槽、覆写和协议见证表放入同一个连通分量计算，避免在遇到协议实现后遗漏其本类中的重载声明。

新增 `analysis/callable.h` 只输出编译内的声明 SymbolID 对和关系类别，`4` 表示重载，`8` 表示属性；既有派发类别 `1/2` 保留。结果独立持有标量，不保留 AST、索引、检查或源码借用。调用方仍须保留、验证原检查，才能解释这些编译内 ID。

判定复用原生 `xl6TextEquals`、`xl6SemFuncName`、`xl6SemIsFuncDecl`、`xl6SemMemberName`、`xl6SemIsClassPropertyMember` 和 `xl6SemMembersShareOverloadGroup`。构建工具从原生源码逐字提取这六个纯函数，生成独立编译单元，记录原件、生成件和每个函数的摘要。它不向常规语义检查器加入调用或额外状态，也避免索引查询反向依赖整个语义检查器。缺失或重复定义时拒绝生成；普通前置声明不计为重复定义。

收集器先按原生父节点、类别和完整原生名称排序，再调用原生判定确认相邻声明关系。名称只用于枚举已声明的候选，不用于绑定引用。GET/LET 仍保留各自原生重载和派发身份；源码重命名的关联将同一所有者、同一原生属性名的读写访问器连接，包括索引属性。特殊名称、生成声明、外部符号和未知来源仍需后续完整可编辑策略。

关系捕获默认及最大预算为 32 MiB，同时计入临时排序记录和最终结果。原先的声明关联查询将此阶段峰值以及后续仍持有的关系载荷计入自己的 32 MiB 默认、64 MiB 最大预算，再计算图临时内存和每文件一份的源码载荷。借用的原分析、导航、分配器和排序实现内部成本另计。循环定期检查取消，库排序不可中途抢占。普通补全、导航和引用不会创建声明关联图。

专项测试还发现并修复了属性使用位置的导航缺口。原生检查器把索引 getter 目标放在 INDEX 节点上，把 setter 放在 ASSIGN 上；名称所在的 MEMBER 不一定有目标。导航现在只沿“属性成员→首个索引接收者→赋值左值”路径读取该原生目标，并核对目标确为对应 GET/LET 声明。接收者、索引参数、右值和外层成员链不会继承它；复合操作中已绑定的 getter 保持其原始身份。

这项修复复用原有节点标量槽保存操作类别，没有扩大每节点持有结构，也没有新增名称推断、源码扫描或堆分配。JSON、完整 typed 导航和驻留 point 导航使用同一判定。现有引用仍按原生选中声明收集；关联查询为后续完整源码操作提供额外关系，不把不同访问器的原生绑定改成一个假想 SymbolID。

全工作空间固定点闭包、所有泛型来源、物理文件别名与可写性、外部符号策略、冲突及改名后绑定证明、版本化编辑和 IDE 编辑事务仍未完成，不能据此开放 `renameProvider`。当前引擎对齐、端到端性能与规模准入继续保留。

阶段验收通过 174 个原生夹具、12 套协议及 29 个 IDE 夹具。重载/属性专项 6,001 项检查，派发关联专项 950 项检查；覆盖跨模块、Unicode/BOM/CRLF、索引及只写属性、原生 getter/setter 目标、JSON/typed/驻留导航逐代码点一致、两处真实分配拒绝、观测峰值的精确配额、全部观测取消位置和脱离原检查的结果读取。六个原生函数逐字复用，七种缺失/重复位置被拒绝；丢弃重载、误并作用域、漏算临时内存和移除属性目标路径这四个实际实现变体均被拒绝。

资格检查绑定 285 个消费者、175 个程序及 core 全部成员。IDE 配对同一服务和匹配 SDK 完整编译 116 个对象，C/xlang 输入、删除、撤销、Unicode/IME、焦点及相关语言功能通过；浅色、深色与属性引用窗格已复核。默认发布程序未替换，未做本阶段全目标性能准入或线上推送。材料索引为 `dev/release-materials/provenance/lsp-callable-families-20261110.json`。
