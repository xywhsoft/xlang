# XUI 批量文档载荷的工作线程准备

后续 [M7b4y IDE 正文修订](lsp-document-revision.md)已补齐快照缓存、同步投影和各查询绑定的独立 64 位正文时钟；事务应用和范围映射继续开发。

M7b4x，2026-11-11。在[批量发布原语](lsp-xui-document-batch.md)上拆出载荷构建，避免把全文复制、完整行索引和撤销字符串构造留在 UI 线程。接口由 XGE 的 Document 生产者实现；IDE 没有复制其私有结构，也没有增加普通输入路径的分支或 Document 字段。

调用流程为所有者线程 `Capture/Describe` → 工作线程 `Stage` → 所有者线程 `Accept/CommitChecked/Destroy`。Capture 只捕获版本、状态、长度和历史数量等有限元数据并登记弱生命周期观察；忽略旧 item 的 Before/After 字段。Describe 返回可复制的普通描述，不含 GUI 指针或租约，也不表示此刻仍新鲜。工作任务只持有这份描述和调用期间不变的 before/after 文本，不能访问活 Document 或捕获票据。

Stage 使用现有 XRT 分配、UTF-8、文档历史及行索引帮助函数，在调用线程构造正文缓冲、快照、完整索引、撤销字符串和历史表。正文和索引数组完整写入，不再先冗余清零；失败时清理部分构造。无变化行也持有原文证明，不能凭长度接受。捕获票据和原文档可以先销毁；工作线程仍能完成并独立释放载荷。调用者负责不可变输入租约、线程间同步及载荷的唯一所有权，接口自身不创建或等待线程。

Accept 只在所有者线程运行，核对饱和不回绕的 64 位捕获序号、文档集合、额度、生命周期、版本/状态、历史数量和精确原文。原文通过 gap buffer 的最多两段 memcmp 核对；不构建快照、不复制正文/索引、不分配载荷。整组验证成功后才移动所有载荷。必须独立检查 `taken`：true 表示载荷已经消费，即使之后的调用范围清理返回错误也不能再次释放。未消费载荷可在任意线程顺序 `PayloadDestroy`。已接收批次仍必须在所有者线程销毁。

CommitChecked 在全部 XUI 预编辑观察者和第一次整组复核之后，允许宿主通过同步 beforePublish 围栏拒绝；然后再次复核整组。所有载荷发布后设置 `committed=true`，调用宿主预分配、不可失败的模型发布钩子，最后才发文档通知。钩子/用户指针只在调用期间借用；published 中不得分配、派发回调或关闭所有者。这为后续 IDE 身份/配置围栏与脏标记、文档存储元数据发布提供顺序，但尚未实现磁盘事务或 IDE 应用器。必须独立检查 committed，不能因发布后错误重复应用。

旧 Prepare/Commit/Destroy 的声明和旧公开类型布局保留，Prepare 是相同拆分管线的同步便捷入口，Commit 转发到无宿主钩子的 CommitChecked。新增六个函数、五个类型；SDK 导入器仅在实际声明存在时登记必需导出。历史 SDK 派生器只接受无批次接口或摘要完全匹配的已验收第一版，预先完成两文件规划后写入，拒绝任意不同的旧实现。共享 ActionInit 只放宽“已提供删除文本时无 live Document”的调用，继续复用原有撤销分配/验证逻辑。

额度沿用最多 512 个文档、8 MiB/正文、before/after 分别合计 64 MiB、默认/最大 128/256 MiB 已知暂存；包含捕获及瞬时载荷元数据。输入、分配器和观察者成本额外，不是 RSS 保证。取消在行及 64 KiB 复制/索引块检查，返回 INVALID_STATE 且输出为空；完整 UTF-8 验证、行数扫描和既有撤销字符串复制仍有不可抢占部分，局部取消点不是端到端延迟保证。

匹配 SDK 完整重编 173 个单元、无对象复用。最终 Document 对象按实际编译选项加 Werror 后逐字节相同；不是声称第三方代码整体 Werror。8,729 个既有公开声明和打包指令保持，新增 11 个声明/6 个导出，DLL 依赖保持，受保护程序的导入可解析。这是限定兼容检查，不是完整二进制 ABI 或正式发布准入。当前 XGE 上游 Document 与匹配 SDK 生产者正文相同，另经严格编译；未验收整个当前上游 SDK。

专项保留 677 项既有主检查及 18 个同步冷态分配拒绝点；最终工作线程程序通过 323 项检查、16 个独立工作线程冷态拒绝点、2 个捕获拒绝点和 12 个观测到的取消点。当前/基线文档回归保持原断言，仅适配生产者 include 与消费其预期文件删除错误。共 40 次最终/继承执行；早期 302 项工作程序的记录单独保存，不冒充最终源码验收。八个真实变异分别破坏捕获身份、gap 前/后段原文、撤销容量、宿主后的复核、模型通知顺序、taken 和取消，均在预期断言拒绝。

实际共享 DLL 的同步及真实工作线程拆分模式各通过 32 项 CodeEdit 缓存/渲染、C/xlang、Unicode、撤销、关闭及模型发布顺序检查。重编全部 118 个 IDE 对象，34 项 GUI/配置回归通过。夹具为确定性而等待工作线程结束；产品接口没有等待，也不能据夹具宣称已验证交互响应。历史 GUI XRT 没有内存统计 API，仅测试观察器按配置省略统计；生产接口/行为没有裁剪。192 个既有原生程序及 13 组协议测试对应未变的语言服务，未在本阶段重跑。

公开 DLL 的 48 次组件成本筛查使用同一新版 SDK，按配对顺序比较同步和拆分路径，每场景各四次。8 MiB 普通文本成功提交时，所有者 SDK 调用成本中位数约 24.78 → 1.55 ms；8 MiB 密集换行时约 46.48 → 1.54 ms。计入测试等待的总耗时分别约 24.78 → 26.51 ms、46.48 → 42.96 ms，不能理解为总工作量必然降低。这不是真实 IDE 输入延迟、LSP 全链路、规模或正式性能验收。

所有者线程仍扫描 before 原文，Commit 复制旧撤销表元数据、释放旧缓冲及重做历史。接收后放弃的载荷仍在所有者线程清理：8 MiB 密集换行的 Destroy 中位数约 8.54 ms，使该路径的所有者 SDK 总成本约 9.47 ms。后续 IDE 调度应尽量在 Accept 前于工作线程丢弃过期载荷，并继续处理接收后清理成本，不能宣称 UI 已无重工作。
