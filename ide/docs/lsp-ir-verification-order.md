# IR 索引遵守原生验证顺序

M7a2b126q，2026-11-10。本阶段修复原生 IR 包装层提前读取尚未就绪存储的问题，并使当前准入组合中的完整验证只执行一次原生拓扑检查。它是正确性修复；组件性能筛选有一项失败，性能与发行准入仍未完成，默认发行程序保持原状。

## 复现与修复

旧 `xlsIrScanInit` 为索引预先验证拓扑，然后才调用原验证器。原验证器本来先检查取消、模块是否就绪及阶段是否合法，再验证拓扑。因此包装层既重复检查有效树，也提前访问原验证器本不应访问的存储。

在独立测试进程中，将一个未就绪模块的节点存储设为 Windows `PAGE_NOACCESS`：原生参考路径正常返回一条诊断，旧索引路径以访问异常 `0xC0000005` 退出。该复现只证明这项内部 API 边界问题，不声称任意错误源码都会触发它。

现在验证作用域只先建立空状态。`native_ir_topology_overlay.py` 在已审核的原验证器拓扑检查成功之后附加观察点，随后才为当前作用域建立可选索引：

- 原来的取消、初始化、阶段、拓扑检查及失败返回保持顺序；没有缓存或跳过原生验证结果。
- 观察点要求正确的验证作用域、等待状态和模块身份；结束时恢复原作用域及参考分类器选择。
- 原生拓扑分配失败时直接保留原诊断，可选索引尚未启动。
- 退出计划生产继续使用其原来的独立拓扑预检。其他原生规则、预算和完整 IR 验证保持。

复用已有扫描 TLS 指针，只增加私有状态字段。当前生成器同时锁定源／头文件及依赖组合，并校验已变换验证函数正文 `c989f2e4…` 的完整 SHA-256 和插入位置。未知组合保留原路径；已审核组合的正文或位置变化则拒绝生成，要求重新审查。该修复的准入范围是当前冻结组合。

## 正确性验证

`analysis_ir_topology_test.c` 自包含实际生成的原生 IR TU，追踪真实拓扑分配调用。三个模块、314 次原／新对照、1,612 项检查覆盖完整诊断、正常单次拓扑检查、拓扑分配失败、逐节点父边／范围破坏、逐子边破坏、作用域准入及恢复。Windows 受保护存储另外覆盖未就绪、阶段错误、根无效和最早取消四条路径；这些路径没有节点读取或可选索引构造。

六个实际编译的 C 破坏对照分别恢复提前预检、移除观察点、将观察点移到拓扑检查前、删除等待状态／模块身份／验证状态准入，全部被同一正常夹具以明确 CHECK 失败检出。未将崩溃或编译失败算作检出。

根据实际依赖闭包重编七个 IR 消费者；156 项原有原生测试全部重新链接并运行。实际落盘生成器重新生成的 C 与私有候选逐字节相同，再用落盘源码运行新增夹具，共 157 项原生测试。常规验收索引包含 259 个实际单元、752 项有效输入，并逐个核对 66 个核心归档成员。前端／私有 AST 仍为匹配的冻结组合，不声称重新准入并行修改的当前引擎工作树。

八套协议及匹配服务的 IDE 全量重建／26 项联调通过；GUI 重编 115 个普通对象、入口及资源，覆盖 C／xlang 输入、删除、撤销、Unicode／IME、焦点、补全、导航、引用、诊断和工作空间搜索。浅色补全、IME 预编辑、深色搜索截图已检查。

## 构建来源核对

准备归因探针时发现，前阶段合并索引的部分 `commands` 来自依赖探测的拟编译命令，沿用对象的实际路径仍在原链接记录中。重新发现全部 258 个单元的实际依赖，逐个匹配归档成员及 157 条链接，形成单独的派生索引；原报告、程序字节和已执行测试不改写、不重跑。

Windows GNU ar 的 `p` 输出会转换换行，不能直接将其输出当成目标文件原始字节。当前核对使用二进制文件提取。新的 `lsp_profile_inputs.py` 将探针配方匹配到实际链接对象和归档字节，支持带摘要前缀的对象名及规范路径；缺失、未链接或字节不符的拟编译输出不能覆盖有效记录。十一项独立工具测试及实际索引正／反预检通过。实际链接的全部 23 个 host 对象必须匹配构建记录中的摘要；缺失、冲突或字节变化在编译前拒绝。常规构建器同时记录全部普通对象摘要。反例在归档对象 `check_session` 处先被拒绝；最初驱动预期更晚的 host 拒绝，错误预期和原日志保留，没有重跑该反例。

`build_lsp_lifecycle_profile.py` 增加 `--preflight-only`，并在实际编译前后核对来源／依赖及沿用链接输入。输出通过 `-o` 参数位置明确指定，路径别名不会造成覆盖正常程序。原生验证顺序修复和这些工具变化分别记录执行范围。

落盘工具已实际重编十个归因对象，三个原生探针回归及 16 进程／240 请求的原版与插桩完整事实对照通过，360 帧全部保留。这是工具正确性及归因验证，不能用来重新判定失败的性能筛选。随后增加的 host 摘要准入只做工具单测与实际索引预检：23 个链接对象、66 个核心成员和所选配方与已完成探针逐项相同；常规构建器新增摘要字段的原表达式在 259 个现存对象上核对。没有重建程序或重复计时；此前工具字节另存保留。
