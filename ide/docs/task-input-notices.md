# 未保存构建输入提示

当任务提交时有已命名的脏文档，IDE 会保留路径快照。若同一任务的直接输入、资源扫描或实际编译输入回执确认该路径属于输入集合，构建会停止；问题页会显示“提交时未保存”及文件名、保存后重建说明和完整路径。关联路径也包括编译器记录的搜索候选，不把所有条目都解释为实际读取的头文件。

这类提示是输入状态通知，没有编译错误的行列位置。双击或选中后按回车，使用普通文档打开流程：已有文档继续使用原编辑器，正文、脏标记、选区、版本和撤销历史保持。物理上相同的路径（例如硬链接）只生成一条提示，并复用已打开文档。长完整路径在列表末尾可能截断；文件名和处理说明优先显示。

保存相关文件后重新构建或运行。保存失败仍保留内存修改和原文件；本次失败不会发布新产物，也不会运行旧输出。IDE 不自动保存所有打开文件；与任务无关的脏文档保持原状。对后续才发生的任意输入变更，既有失效保护继续有效，此增量不保证每种失效都有这类提交时通知。

## 问题页归属

自动发起的任务结束后，若有未保存输入提示，IDE 激活编辑器下方的中央问题窗格。被动语言诊断更新不能立即覆盖这份可操作列表。显式语言检查及任务选择仍可更换显示内容；选择该失效任务后可以再次打开输入通知。过期任务的编译诊断仍拒绝跳转，输入状态通知允许打开文件，不把无效行列应用到编辑器。

C 与 xlang 双语法、三层工程管理和定版 Dock 布局继续沿用。实际构建输入回执不等于完整 C 语言服务预处理图，也不构成全部 ABI 等价证明。完整复杂 C 工程、实体 IME/混合 DPI、干净 Windows 和其他正式发行条件仍在长期任务内。
