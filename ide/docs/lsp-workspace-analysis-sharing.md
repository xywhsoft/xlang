## 共享与所有权

`xlsWorkerCachedCheckInContext` 在原 worker 的所有者线程读取已完成的带索引检查。完整上下文、实际入口，以及所有编辑覆盖的键、路径、身份、版本和不可变文本对象必须匹配。它不会读取磁盘、调用语义检查、更新版本历史、提升缓存位置或清退导航缓存。未命中通过原查询接口返回失败。返回结果只是持有独立引用的历史候选，不能代替来源新鲜度证明。

工作空间主入口保留完整工程上下文和成员清单。后台先尝试候选，再执行原有磁盘、编辑覆盖、工具链、负面导入候选和发布代次核验。缺少候选或候选证明失效时，使用一个临时私有 worker 完成原有分析；独立声明及来源证明捕获后销毁整个临时 worker。不能由导入覆盖的成员继续使用延迟创建的私有成员 worker。借用的前台 worker 从不由工作空间服务销毁。

声明捕获可只读获取精确所有者的导航表；未命中时私有构造，不绑定、清退或发布到前台导航缓存。结果引用与缓存驻留、源码新鲜度分别管理。新增 `analysisSnapshots` 和 `primaryFallbacks` 统计，不把观察快照计为真正的语义检查命中。

同时修复两项生命周期问题：宿主取消直接传递给活动原生查询，销毁前在锁内解除借用；500 ms 空闲窗口从前台真正空闲后开始计时。配置入口从磁盘表示切换到编辑覆盖时，相同实际入口和完整上下文可复用检查会话；已失效的磁盘入口会话被清退，其他关闭入口不受影响。输入身份、版本及完整语义／IR 验证仍保留。

## 性能结果与测量修正

此前原始双进程交替请求的全部失败样本保留。最初完整矩阵 A/A 为 0/64 失败，阶段 A/B 为 5/64、累计对照为 1/64 失败；随后不同代码候选的定向屏分别有 3、4、2、3、4 项失败，没有重复同一屏来择优。最终候选的 512 函数定向屏仍有 4/8 项失败，热查询 P50 为 267.16→288.70 ms，冷检查为 793.35→868.04 ms，不能称为通过。

之后补充了独立诊断，而非替代失败结论：

- 两边显式关闭后台的 240 次请求中，512 函数热 P50 为 234.33→236.53 ms。该诊断不设性能门，不代表默认配置通过。
- 临时分段计时执行 180 次请求／12 个进程，事实与正常候选相同。后台快照等待中位数约 0.49 ms，声明捕获约 9.36 ms；观测到的快照导航准备均复用已有表。它是带探针的包含时间，不能作为正常镜像性能门。
- 对原双进程交替方式记录对侧 CPU：候选热查询期间旧服务的对侧 CPU 中位数为 164.06 ms，反向为 0；48 次候选热请求中 38 次有对侧 CPU 活动，反向为 14 次。证据显示该测量方式会受到不对称的服务间后台竞争，不能单独归因到候选内部开销。

工具因此增加显式 `--isolated-processes`，每个完整进程链结束并回收后才启动对侧；历史默认方式仍保留。增加可选固定停顿节奏，保持产品 500 ms 延时不变。真实非 LSP 编译器作为错误服务的控制确认：初始化失败会关闭并记录该子进程，随后不会启动对侧。

首轮隔离 A/A 为 960 请求／64 进程，1/64 项 CPU 门失败：同一镜像单请求 CPU 中位数 265.625→281.25 ms；这些读数在本机相差一个 15.625 ms 刻度。该场景按整段热查询平均的逐进程 CPU 中位数为 276.69→279.95 ms。原结果没有改判。

再登记独立的交互链 CPU 测量：累计完整改动链的 CPU，包含规定停顿并按改动数归一；每个进程至少累计 1000 ms CPU，32 函数固定 192 个版本，512 函数保持 14 个版本。保留单请求 CPU 门为诊断，延迟、内存及 5% CPU 相对门槛不变。该轮 A/A 执行 6656 请求／64 进程，**2/80 项失败**，均为相同旧镜像的 P95：

| 场景 | 对照／候选 P95 ms | 上限 ms |
| --- | ---: | ---: |
| 512／单文件／字面量改动 | 265.55／306.16 | 278.83 |
| 512／导入文件／字面量改动 | 291.77／337.78 | 306.36 |

CPU 精度和 CPU 相对门通过，但校准仍未通过，因此预登记的后续 A/B、累计对照及停顿节奏对照没有启动。两轮新方法的校准、旧双进程结果及失败日志全部并存；没有将修改后的指标解释为原门通过。宿主非独占，观察到其他编译任务和系统进程活动，但未将两项退化直接归因给它们。
