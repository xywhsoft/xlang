# 分析结果的文本所有权接口

2026-11-01，M7a2b103。新增 `xlsSemanticCheckRetainSourceText`，从已捕获的检查结果取得已有编辑器文本的独立引用。接口使用现有 `xls_text`／XRT 引用计数，不增加文本容器、内存池、缓存或解析器。默认服务暂未消费此接口，根目录 IDE／LS 程序未替换，版本保持 0.100。

接口按原始来源报告序号查找，逐项核对绝对路径、去除可选 BOM 后的长度及全部字节，再保留捕获批次中的文本。输入批次顺序可以与报告顺序不同，未使用的编辑器文档不会成为错误的来源。只读取不可变捕获，不分配、重新解析、计算哈希或访问文件；路径比较和完整字节比较仍有成本。

成功返回一个需要 `xlsTextRelease` 的引用。必填的 `bomBytes` 为 0 或 3；编译器字节偏移相对于 `xlsTextData(text)+bomBytes`，文本位置函数仍针对原编辑器内容。失败清零 `bomBytes`。磁盘来源、原始字符串构造的检查、缺失或不匹配的文本，以及已知失效的检查都可返回 NULL，调用方保留原来的复制／构造路径。不得把 NULL 当作语言错误。

引用可以独立于检查、会话或编辑器输入存活，也可以在检查失效后继续安全读取已有数据。它不证明当前输入仍然有效；消费语义事实、取消处理和发布前仍须执行原有守卫。

验证证据位于 `ide/build/Release/lsp-source-text-20261101/`，摘要固化在 `dev/release-materials/provenance/lsp-source-text-leases-20261101.json`：

- `foundation/result.json`：恢复三个导航实现／fixture 文件为本阶段前的原实现，仅保留新增接口，并加强伪造路径／长度／同长度字节不匹配测试。相同头文件及其余对象经 SHA-256 核对，重新编译三个受影响单元，重链接独立 host；304 项接口、154 项会话、132,357 项原导航检查通过。这是增量复核，不称为第二次全新全量构建。
- `negatives/result.json`：三个实际编译的 C 源码反例分别遗漏字节比较、路径比较和失败输出清零，均被同一 fixture 拒绝。没有把脚本模拟结果当作编译器行为。

测试包含 BOM／CRLF／中文／emoji、报告与输入顺序不同、未使用输入、四线程重复取得与释放、256 次无新增 XRT 块分配的读取，以及会话销毁／检查失效后的存储寿命。无新增块分配不等于整个 LSP 没有额外成本。
