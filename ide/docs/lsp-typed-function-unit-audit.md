# Typed function 单元：词法所有权组合实验

2026-10-27，M7a2b63a。本阶段完成一项私有架构实验，未合入产品功能。已验收产品仍为 M7a2b61a / xlang-ls 0.93；没有建立 0.94 产品构建或更新发布目录。完整函数／类型／最终 IR 单元、语义局部重建和长期任务继续。

## 结论

不合入本轮“将已有不可变词法单元组合到语义 memo，并复制已证明相同的完整函数键”的原型。它建立了独立词法所有权和完整预处理输入边界，也通过实际复用时的原始函数键逐字节对照；但仍完整物化编译器私有 AST。最后的正常构建在两类编辑的检查 P50／CPU 上升，结构编辑的补全和签名也退化。

复制已有键只能节省部分序列化，仍需构造当前树、遍历声明、核验环境和恢复语义视图。这项实验不能替代完整 typed function 单元、只读 typed index 和按需物化。后续不再以新增小缓存或增加复用计数作为主要性能进展。

## 复用的资产和实际边界

实验继续使用实际 0.93 的固定前端 `ide/build/compiler-c-native-extensions-v1`，没有混用正在演进的 demo6 源码。复用已有 syntax unit、语义 facts／读集合／位置视图、原始函数检查器和 raw IR；未另建语法或类型系统。

- 现有不可变 syntax unit 独立引用计数；语义条目只保留该原始词法单元及自己拥有的键，不保留旧结果、旧 typed AST 或旧类型注册表指针。
- 构造线程上的有界 XRT 注册表证明当前私有函数确由该词法单元复制。重复身份、原树自身、来源不符或资源不足时拒绝该捷径。
- 单元新增独立的原子容量测量缓存，采用非阻塞可选拒绝与失败重试；不改变原完成态 syntax cache 的准入字段或 API 行为。
- 当前完整函数头、原始模块语义上下文、状态／类型／符号／读集合／来源／光标／位置守卫继续执行。函数正文是被独立保留的原始词法身份，不能仅用 AST 指针相同作证明。
- 最后的 v9 重新编译或新增七个实现对象：AST、sem、syntax、semantic、check、entry cache 和 lexical registry。原 stdlib、其余核心和宿主对象沿用实际 0.93；AST 公共布局没有改变。原始检查、IR 构建和完整校验器全部保留。

临时词法注册表和待保留词法数据分别至多 32 MiB；原始声明记录、预处理输入缓冲分别有 8 MiB 限额。原始语义 facts／proof／deferred body 优先准入，新增完成态环境和词法数据只能使用原 64 MiB 语义配额的最终余量。这些是局部数据限额，不是整个进程、所有嵌套作用域或瞬时峰值的全局预算。

## 导入改写属于必要输入

早期 v5–v8 试图通过 stdlib 和语义预处理写点围栏证明正文未变。审计发现 `xl6_imports.c` 的命名空间／别名改写也能修改函数正文；这些版本的证明不完整。它们没有合入，不能用已通过的有限测试补足该缺口，也不能选择其较好样本作为最终验收。

v9 取消这些实验性逐节点 stdlib／语义预处理回调，采用完整预处理输入快照：

1. 在导入改写之前，记录每个实际解析模块的原始声明键。只省略直接模块函数的正文；导入／别名、全局声明、类和默认值仍完整保留。同路径重复记录必须逐字节相同。
2. 保存实际路径、输入种类和来源；所有代码来源都必须有原始声明记录。清单保存完整文本、解码／原始散列和长度；路径存在性探测、包路径及其观察状态也进入键。
3. 只有该输入快照、原完整已处理语义上下文、当前完整函数头和独立词法单元均相同时，才复制旧的完整函数键前缀。缺失、冲突、未捕获来源、容量不足或不支持的输入都执行原始完整函数键生成。
4. 原完整 SourceReport 验证仍负责来源新鲜度；输入快照不取代文件／overlay 验证。当前函数开始获得语义事实后，其原始词法构造证明立即失效。

该实现是实验性边界验证，尚未完成所有预处理非局部写入的系统证明、任意分配失败／取消路径与全局资源验收。

## 实际正确性检查

最终 v9 正常构建重跑原有 semantic memo（1291）、semantic（52）、signature（39472）和 IR memo（939）检查。另一个诊断构建在每次实际复制函数键时重新生成原完整函数键，在追加当前状态和允许语义复用之前逐字节比较。

诊断构建重新编译并运行十个原有或增强夹具：semantic memo、incremental check、semantic reads、semantic read values、semantic headers、completion session、signature、IR memo、check materialization 和 syntax storage。共观察到 3587 次实际函数键复制，均与原完整键相同。这是这些实际覆盖路径的证据，不是对所有语言形态的形式证明。严格环境不相同时保留原完整键路径，未降低原语义复用／fresh 对照断言。

独立所有权和环境夹具通过 2091 个检查：源单元在 syntax／旧结果关闭后存活、私有复制、原子容量并发首次发布、四读取线程、极小配额、真实 XRT 数组初始化／扩容／resize 拒绝、嵌套作用域、来源不符、环境排序／重复／冲突／缺失、512 模块上限、清单／探测／包环境变化及未捕获输入拒绝。增强 syntax storage 的 71 个检查还覆盖实际 map 初始化／写入拒绝、容量测量重试与原字段保持不变。

v7 的实际 512 函数测试发现新增词法容量抢占了原语义 proof 的配额：虽有 512 个函数复用，proofHits 只有 493。v8 修复为最后余量准入；原 `proofHits >= 511` 断言保留，v8／v9 正常计时实验均通过。没有降低门槛以接受原型。

## 最终正常构建的性能

v9 使用两个独立的八进程 ABBA／BAAB 实验，分别测量结构编辑与字面量编辑。每组包含 512 个辅助函数，同一路径／文本／版本，保留原冷请求、文档拓扑变化、三次编辑、热查询和全部语义／来源／复用证明断言。每组 240 次计时请求，合计 16 进程／480 次。计时没有启用函数键重生成诊断，也没有本任务构建、QA 或大规模散列。

## 后续实现要求

沿用[最终 IR 审计](lsp-final-ir-incremental-audit.md)的完整单元方向，下一条代表性链路需要先证明减少实际物化／扫描／检查工作：

1. 将已有词法单元、独立语义 facts／读集合、实体／类型域及 raw IR 组织成真正的函数单元版本；类型声明指针和局部 ID 必须有当前结果上的明确映射。
2. 给补全／签名建立单元上的只读 typed index，按当前来源／位置视图查询；完整 AST 留给需要它的旧消费者按需物化。不能通过借用旧 typed AST 或持有整个旧结果实现。
3. 保留未保存／不完整代码、依赖变更、取消和资源拒绝路径；完整物化后继续精确对照独立 fresh AST／类型／索引／来源／报告／IR。
4. 最终 IR 的函数／类型／调用／布局／清理表继续拆分为可独立持有并可证明重定位的单元；全局规则与完整校验在充分增量证明之前继续执行。
