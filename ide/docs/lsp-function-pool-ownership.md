# 函数物化的独立内存池

原有 `xlsAstMaterialize` 在一个作用域内共用节点池。虽然部分函数在增量分析中能够独立保留，但它们引用同一池时，保留收据仍必须计入整个池的 backing。因此，一个函数可能连带保留许多不会复用的兄弟函数的内存。

本阶段改变实际所有权：较大的函数或延迟函数体物化到独立的既有 XRT 节点池，较小的声明仍共用池。没有减少实际 backing 的计费，也没有调高缓存额度。

## 实现边界

只对函数、异步函数、导出函数及块根节点应用这项策略。只读预扫描在遇到 64 个非空节点后停止；不调用源引用回调，不分配内存，不作为语法或语义有效性证明。该计数包含子节点及两种类型边，并沿用深度保护。较小的树沿用公共池，完整模块克隆也保持原路径。

独立克隆复用现有嵌套 materialization scope。子作用域取得父作用域的剩余额度，克隆期间当前池仍可见，结束时将实际分配计费与工作统计合并回父作用域，并释放池的临时 pin。返回节点通过已有的活节点计数持有池，最后一个节点释放后回收 backing。没有新增池类型、分配器、TLS 域或结构布局。

池创建、节点分配或池内克隆失败时，清理半成品并沿用原有堆克隆回退。整个可达池 backing 的去重计量、32 MiB 函数保留额度、64 MiB 默认物化额度、C-owned 无写入证书、区域及符号变化后的完整重试均保持。

## 原生验证

新增 `analysis_function_pool_test` 在既有 1,377 项物化检查之外增加 851 项检查，涵盖：

- 63／64／65 节点边界、独立池及小树共池、完整节点字段／源身份对照。
- 零额度、1 字节、页边界、精确成本及少 1 字节，以及嵌套作用域的完整计费。
- 保留一个函数并销毁模块及兄弟函数后继续读取，最后释放时分配平衡。
- 池创建、177 个节点生产点及克隆入口的实际拒绝，均完整回退并清理。
- 四线程对同一个不可变输入分别重复克隆、释放及独立计费。

`check_function_pools.py` 编译实际 C 错误生产者，分别遗漏池划分、父作用域计费、unpin 或父额度限制，要求同一夹具拒绝它们。原有 `check_native_borrow.py` 另检查精确区域、C-owned 写入保护、完整 backing 计费和失败后完整重试，以及四种实际生产分配拒绝。

匹配的原生 512 函数三代用例中，完整 AST、原生索引事实、IR、来源及诊断对照通过 1,224,006 项检查。原 32 MiB 额度下，可保留／复用的完整函数从 85 个增加至 279 个；首次全量仍复制 97,820 个节点，后续复制从 82,398 个降至 47,090 个。小函数共池的既有 128 函数用例仍保持 27 页及原分配摊销结果。

这些是特定用例的工作量和实际所有权结果，端到端耗时以独立的正式性能矩阵为准。完整模块路径、额度外函数及保守拒绝路径仍可能复制大量节点，不能据此宣称整棵 AST 或全部分析已经完全增量化。

## 构建与 IDE 边界

完整构建为 238 次编译、140 项原生回归、145 个私有 AST 消费者，核对 1,402 项输入与 142 项产物。匹配的前端及旧普通程序输入先冻结并核对，原历史回执和二进制不修改。

GUI 使用已提交的 `9a81d2470` 加本阶段源码完整重编译，防止正在开发的模板界面及 action 布局混入。配对 IDE、服务、编译器及 DLL 在真实 `release/win_x64` 验证，候选使用临时独立文件名，默认程序保留。开发材料放在 `dev/release-materials/`，发行目录不保留测试程序。

19 组协议回归及八项 GUI 检查通过，后者覆盖 C／xlang 输入、删除、撤销、Unicode／IME、焦点、补全、自动诊断、配置及项目上下文。原生分区遗漏控制为五案例／17 命令，原生借用保护控制为九案例／29 命令。
