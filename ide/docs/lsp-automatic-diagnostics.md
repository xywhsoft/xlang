# 自动原生诊断

开发服务 0.21 默认在命名 `.xl` 文档打开和变化后执行原生检查，使用标准 `textDocument/publishDiagnostics` 发布结果，无需客户端先发送 `xlang/check`。检查沿用构建绑定的共享前端、语义和 typed IR 验证，不启动执行编译器，也不写临时覆盖文件。每个打开的文档可作为一个入口，实际导入的未保存文档参与该入口的分析。

这是服务端自动诊断切片。当前 IDE 诊断／导航客户端显式设置 `automaticDiagnostics:false`，保留原显式批次和 500 ms 复查控制，等待后续文件级输入证明与界面策略接入；补全的独立客户端也关闭自动诊断，避免重复后台检查。不能把本阶段记为 IDE 已默认启用自动诊断。

## 初始化与协议

```json
{
  "initializationOptions": {
    "diagnosticsBackend": "native",
    "automaticDiagnostics": true,
    "diagnosticDelay": 75
  },
  "capabilities": {
    "textDocument": {
      "publishDiagnostics": { "versionSupport": true }
    }
  }
}
```

`automaticDiagnostics` 必须为布尔值，默认在原生后端开启，在显式 CLI 后端关闭。CLI 后端同时开启自动诊断返回 `-32602`，不会静默切换后端。`diagnosticDelay` 是 0..2000 的整数毫秒，默认 75；值为 0 表示不增加防抖等待，仍经过异步任务队列。服务通过 `capabilities.experimental.automaticDiagnostics/diagnosticDelay` 返回生效值。

自动模式仅在客户端声明 `publishDiagnostics.versionSupport:true` 时发送可用的版本字段。打开文档使用客户端同步的 URI 拼写及当前线上版本；磁盘文件没有编辑器版本。关闭文档会清除旧 URI 对应结果，后续其他入口实际引用该磁盘文件时可重新贡献诊断。关闭／重开复用槽位以独立文档身份隔离，不以版本号是否相等推断同一份文档。

诊断按文件发送完整列表，空列表撤销该文件的先前结果。同一入口的贡献替换与多个入口之间的合并由服务负责。参见官方 [publishDiagnostics 规范](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/language/publishDiagnostics.md)。

`didSave` 在自动模式下重新安排原生检查，覆盖内容仍取当前同步正文；它不会因为保存事件改走 CLI。显式 `xlang/checkSaved` 继续是保存后 CLI 兼容请求，其响应不覆盖自动原生诊断存储。显式 `xlang/check` 继续返回经验证的完整响应；原生结果同时可作为该入口的自动诊断贡献。关闭自动模式后，原有手动检查、保存策略和批次保护继续生效。

## 调度与有效性

宿主只记录各入口的到期时间、身份、全局输入代次和待失效路径。连续变化重设该入口到期时间，到期入口按最早等待顺序选择；队列中尚有文档／文件变化通知时，先处理输入。普通查询洪流不会以“队列非空”为由持续阻止已到期的检查。

完整检查由既有后台语义执行器运行；前台光标补全使用独立执行器。标准定义／悬停／文档符号请求可以等待同入口已经启动的检查。取消导航等待者不会取消仍被自动诊断需要的任务。改变正文、关闭、文件观察变化或 shutdown 仍会取消／丢弃不再有效的工作；取消当前主要在阶段边界生效，尚未达到细粒度分析内部取消目标。

诊断收集使用一个独立 XRT actor，负责输入验证、贡献替换、合并和发布快照。协议 owner 最多保留一个正在运行的收集操作和一份待提交的检查结果；结果通过独占所有权转移交给收集器。发布快照也直接转移所有权，预先排序的路径键用于线性比较，owner 不复制完整报告、不合并诊断、不访问文件系统，也不为每个入口创建观察线程。

打开／变化／关闭按实际文件及已观察解析候选使有关入口失效。其他入口的有效结果继续保留；共享依赖的相同诊断精确去重。存储中的输入证明与最近导航索引分离，开始分析另一个入口不会清空其他文件的有效诊断。详见 [诊断存储](lsp-diagnostic-store.md) 和 [独立输入守卫](lsp-diagnostic-inputs.md)。

收集操作完成时，即使宿主代次已经变化，实际失效入口仍被安排重查；发布则必须同时满足任务代次当前、没有待处理失效路径／重置及已接收未处理的输入通知。发布前还核对打开文档版本。新入口检查比旧记录的周期观察先发现磁盘变化时，存储返回实际冲突路径；宿主据此撤回受影响贡献并重查，不以资源失败挂起，也不清空无关入口。

## 文件观察、预算和失败

服务接收标准 `workspace/didChangeWatchedFiles`，验证绝对文件 URI 及 Created=1、Changed=2、Deleted=3。当前尚未实现向客户端动态注册文件观察；接受通知不等于已经完成注册能力。标准流程参考官方 [didChangeWatchedFiles 规范](https://github.com/microsoft/language-server-protocol/blob/gh-pages/_specifications/lsp/3.17/workspace/didChangeWatchedFiles.md)。

作为已有输入的后备，收集器每轮 Sweep 完成后等待一秒，复用原有文件身份、内容、包环境及负解析候选验证。它只观察实际报告覆盖的输入和候选，不是完整工程文件索引。多个记录共享输入时仍可能重复验证；尚无十万／百万行规模、CPU 或峰值内存验收。

宿主待失效路径最多 128 项、1 MiB 字符串；同拼写路径合并。超量使用有界重置：撤销已发布结果、清空存储并重新安排当前打开入口，避免无界积累。收集器继续使用 64 入口、32 MiB 保留报告、4 MiB 发布报告等既有上限；这些是编码数据预算，不代表进程堆或 RSS。

源码错误属于有效分析结果，正常保留与观察。资源、读取或基础设施失败通过 `window/logMessage` 和 stderr 报告，每个已观察输入状态最多尝试一次，避免自动重试占满 CPU。下一次打开／变化／保存、文件通知或已有证明观察到失效时可重试。没有有效输入证明的读取失败，外部恢复仍可能需要客户端文件通知或一次文档事件；后续文件观察与类型化失败恢复需要继续完善。

`xlang/diagnosticStats` 用于回归观察，返回待处理输入、脏／失败入口、实际检查提交次数、存储操作及线程身份、队列负载和最近原生分析计数。它不作为产品状态持久化，也不以这些计数代替延迟或内存测量。shutdown 撤销待提交与观察任务，响应后不再推送诊断；最终销毁才等待执行器退出。

## 验证

`tools/check_lsp_automatic_diagnostics.py --server <本次服务> --output <新目录>` 运行真实 stdio 专项，记录程序／源码指纹、完整会话和 stderr。覆盖默认打开、独立贡献、共享依赖／移除导入、版本／URI／槽位、保存、磁盘变化及同字节身份替换、负候选、冲突恢复、21 次编辑合并为一次真实检查、普通请求洪流、有界重置、导航取消、大文件变化／关闭／重开及 shutdown、前台不完整代码补全、资源失败抑制与恢复、版本能力和手动兼容。执行编译器不存在的场景继续执行真实原生分析。

本阶段验收记录见 [长期实施进度](lsp-development.md)。这些检查证明正确性、线程分离和实际重算次数，不代表编辑后的真正 IR 增量、容错语义复用或 IDE 最终显示时延达标。
