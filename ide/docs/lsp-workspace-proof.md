# 发现证据的独立生命周期与重命名发布校验

M7b6n，2026-11-15。延续后台发现组件，为准备重命名和重命名建立外部范围证据的保留及校验。标准服务的自动加载、引用和工作区符号发布接入仍须继续，不提前开放自动工作区能力。

分析 catalog 可在构造时安装可选的不可变证据描述符，明确 retain/release、worker 验证入口和已知保留字节数。构造过程中验证回调完整性、累计字节溢出和 retain 失败；成功后拥有描述符副本。普通客户端 catalog 不安装磁盘证据，保持元数据构造和查找行为。`xideAnalysisCatalogBytes` 计入证据载荷，既有范围预算不会因共享而漏计；不声称这就是分配器或进程 RSS 总量。

发现的目录、原始清单摘要、身份、容量和失效标记改由独立引用计数对象保留。发现快照与 catalog 各持有它，证据不持有 catalog、发现快照或服务，避免形成循环引用。发现服务和快照均释放后，查询仍可通过保留的 catalog 验证范围。多个查询可读同一份不可变元数据，失效标记继续使用原子状态；取消不污染证据。最后释放不访问磁盘；大型配置在主线程上的回收耗时仍待后续接入时处理。

重命名候选 coordinator 在分析前验证 catalog，拒绝已过期的成员集合或清单，避免继续构造昂贵语义结果。标准 rename/prepareRename 与原生候选在响应帧编码完成后，除原有源码守卫外，再验证范围证据。新增关闭文件、原始清单改写、相同字节的清单原子替换都能使旧结果失效。返回的是已编码且通过这次校验的响应，不等于用户同意、磁盘写入许可或原子文件系统快照；根、配置、overlay 与请求修订的发布屏障仍不可省略。

新增真实原生发布测试覆盖 9 个场景：保留 catalog 后销毁发现快照和服务仍能生成完整关闭文件编辑；编码后新增文件、同字节清单替换、仅运行参数改写、prepareRename 的成员变化；编码后的取消；分析前的成员变化和清单替换；实际清单句柄打开期间的取消。最后一项在文件句柄已经打开后暂停 worker，验证取消时 future 仍 pending、物理 Idle 为假，恢复后关闭句柄才完成退出。链接级观察器只用于测试，不替代生产文件读取或原生分析代码。

catalog 单元测试补充描述符独立持有、保留失败、无效回调、字节溢出、证据计量、取消、失效返回和最终释放。发现原有的目录/清单守卫、容量、别名及关闭文件原生重命名测试继续运行，局部失败点增至 75 个；这不是完整 allocator OOM 或泄漏证明。

重新构建 122 个原生单元和 140 个 GUI 单元；协议、IDE 编辑/输入法/焦点及语言功能回归、实际 C/xlang 程序渲染和编译后反例的执行结果见 `dev/release-materials/provenance/lsp-workspace-proof-20261115.json`。候选在根 `release/win_x64` 用匹配 SDK 别名运行，验证后删除别名，保留默认程序、SDK、当前交付和线上通道。材料在外部开发目录归档，仓库只保存源码和小索引。
