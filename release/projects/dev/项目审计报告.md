# dev 项目代码审计报告

> `httpproxy` 因完整 URL 产品边界迁入 `dev/deferred/xhttp/projects`，待 xhttp 语言扩展接入后恢复。

本报告记录对 `release/projects/dev` 全目录的代码审查、改写与验证结果。审计目标不是让项目“勉强能编译”，而是让它们能够作为 xlang 的推荐写法：实现目标明确、代码直接、资源边界清楚、测试可重复，并尽量优先使用 xlang 标准库和 XRT 已提供的能力。

## 3. 主要改进

### 3.1 类型、对象与数据结构

- 将依赖 `var` 字典模拟结构体的热点实现改为 typed class、typed array 或节点池，减少运行时装箱、字符串键查找和错误类型转换。
- `btree`、`trie`、`xpacket` 使用类型化节点池；`xchain` 使用类型化交易；`dataflow` 使用类型化中间表示。
- `raytrace`、`rasterizer`、`gameengine`、`xrobot`、`mlplatform`、`shapes`、`tlshandshake`、`xneural` 按当前 class 引用语义和多态规则重写关键路径。
- `xedit` 删除 class 复制/写回式更新，改为直接操作受管理对象引用。
- `contacts`、`todo` 使用明确的 class 构造，并补齐隔离的持久化往返测试。

### 3.2 函数值、回调与调用边界

- 清理命名函数值、闭包和回调周围的旧绕法，范例直接使用当前函数类型语法。
- `xtest` 的 `assertThrows` 使用明确的 `func() as int` 签名；失败报告包含子进程退出码。
- `xrepl`、`xlint`、`xlsrv`、`xdebugger` 对已知可执行文件使用 `process.runFile`，不再拼接带路径和参数的命令字符串。

### 3.3 并发、任务与共享状态

- `chatroom` 将消息状态改为受锁的不可变 JSON 事件日志，顺序请求复用 `HttpClient`，长轮询使用 `executeAsync()`；POST 路由与状态唤醒分开验证，单轮 44/44 通过。
- `raftsim` 删除“整数槽位 + 全局锁 + 13 组并行数组”的 RPC 传递，改用 `channel<string>` 传递拥有所有权的紧凑消息包，接收端解码为 typed `Rpc`；21/21 断言通过。
- `crawl` 使用动态 future 数组；`portscan` 使用动态并发规模；`logagg` 使用原子快照；`ircserver` 使用内存态会话。
- 修正 actors、生产者消费者、发布订阅和 IPC 范例中已经过时的 channel 能力说明。

### 3.4 文本、JSON 与持久化

- `xblog`、`xmonitor`、`fileserver`、`chatroom`、`webproxy` 统一使用可靠的 JSON 序列化/转义路径，避免手工拼接用户数据。
- `encoding` 增加 UTF-8 BOM 回归；`props` 增加属性直接复合赋值回归；`rxgrep` 增加大小写折叠重复分支回归。
- `xsql2`、`contacts`、`todo` 的持久化测试使用随机临时路径，不再污染工作目录。
- `trie`、`xdistdb`、`procmgr`、`webfw`、`xchain`、`xrepl` 的自测全部改为独立临时文件或目录，可重复、可并行运行，不覆盖项目数据、日志、快照和历史记录。

### 3.5 算法与测试正确性

- `xchain` 的工作量证明断言从“恰好 N 个前导零”修正为协议真实要求的“至少 N 个”，消除合法随机结果导致的概率性失败。
- `genid`、`hashcalc`、`passgen` 将 `uint32` 随机值或哈希值显式拓宽为 `uint64` 后再格式化，既保留无符号语义，也避免安全拓宽造成的重载歧义。
- `radix` 使用 `int.format(code, "c")` 生成字符，删除旧格式化缺陷说明。
- `sortlab`、`stats` 使用类型化数组和标准库数学函数，减少重复实现。
- `xedit` 语法高亮关键字/类型表更新到当前语言口径。
- `xdebugger` 的行映射通过 `xl cgen --emit` 输出到唯一临时文件，不再执行目标程序后扫描多个候选目录。

### 3.6 旧兼容与死重清理

- 删除 `config`、`sudoku` 的 argv 兼容 C 文件，以及 `dupfind`、`psearch` 的临时 shim。
- 删除 `dynobj`、`fstr`、`sudoku`、`tictactoe` 中已经失效的历史 `BUGS.md`。
- `.xl` 源码中已无 `BUGS.md`、旧 BUG 编号、`workaround`、`绕过`、`未修复` 等推荐旧路径的残留。
- 旧问题不作为范例写法保存；当前能力以 demo6 设计文档、功能清单、测试和本目录最新代码为准。

## 5. 当前结论

这一批项目已经从“语言压力样例集合”收敛为可以公开展示的实战范例集：所有应用可检查、可生成原生程序，具备自测入口的项目全部通过，已知旧规避写法和测试副作用已清理。

仍需诚实保留的边界是外部集成验证：真实公网、TLS 对端、邮件/数据库服务、长时间网络压力、GUI 交互和真实大文件数据不属于本轮本机自动回归的证明范围。这些项目的代码和构建链路已审核，但在正式发布前仍建议放入独立的集成测试环境。

`RISK-XRT-HTTP-001`：在额外执行的 `chatroom` 60 次独立进程压力运行中，当前 XRT 网络重构版本出现 4 次 `0xC0000374` 堆损坏退出。单轮 `chatroom` 44/44 与本报告的 114 项完整回归均通过，因此范例逻辑验收成立，但 XRT HTTP client/server 生命周期仍需单独做内存检测与长时间压力收口；在该风险关闭前，不能把“HTTP 长压稳定”列为已证明能力。
