# XML 桥接冷启动错误状态审查

## 修复合同

错误状态按线程保存，因此新进程和新线程都存在首次初始化。此前
DOM/ElementTree 在状态创建失败后清掉 XRT 内存错误，继续执行解析、
加载、序列化或保存；SAX 则在操作完成后才创建状态，可同时返回
有效结果和 `XERR_MEMORY`。这种半成功返回尤其不适合语言端在接管
原生结果前自动检查错误的调用边界。

本轮仅改三份包内 `xml_*_native.c`：

- SAX 在创建解析器、读取事件或关闭前取得状态，并把同一状态直接
  传给发布函数；正常路径没有增加第二次 TLS 查询。
- DOM/ElementTree 的 parse、load、stringify、save 在状态不可用时
  立即失败，不清掉原错误；文本 stringify 入口复用相同检查。
- 初始化失败时，不消费 SAX 事件、不关闭输入、不覆盖保存目标。
  解除故障后可重新操作同一输入。

不改公开 ABI、类声明、解析器、Expat 或冻结 XRT；不新增生产分配、
字符串复制或整文档扫描。未做吞吐基准，不宣称性能提升或整链零开销。

## 聚焦回归

`test_bridge_state.c` 的 15 条路径：

| kind | 入口 |
| ---: | --- |
| 0 / 1 / 2 | SAX open_memory / open_text / open_file |
| 3 / 4 | SAX next / close |
| 5 / 6 | DOM parse / load |
| 7 / 8 / 9 | DOM stringify / stringify_text / save |
| 10 / 11 | ElementTree parse / load |
| 12 / 13 / 14 | ElementTree stringify / stringify_text / save |

门禁为每个 kind/budget 启动独立进程，从预算 0 扫描到首次不再触发
故障，避免把已热的线程槽当作冷状态。每次都检查失败类型、返回值、
副作用边界、故障解除后的新上下文恢复，以及活动分配/字节、非法
释放、双重释放和 UAF 计数。文件场景只使用门禁提供且原先不存在的
独占文件路径，退出前清理，不猜测共享临时文件名。

另有四个 XRT 线程、每线程 12 轮三包错误诊断，共 144 组；先在各
线程触发首次内存故障，再交错发布和读取不同源码行号，确认状态
隔离及恢复。测试宿主因此新增 THREAD 模块，生产清单没有增加依赖。

| 验证 | Windows | Linux 原生文件系统 |
| --- | --- | --- |
| 最终冷启动回归（含各入口最终成功） | 270 场景通过 | 257 场景通过，ASan/UBSan |
| 同一最终夹具，只换回旧三份桥接 | 268 场景中 60 失败 | 259 场景中 60 失败 |
| 四线程 / 144 诊断 | GCC、TCC JIT、独立 AOT 通过 | 同三条路径通过 |
| 实际生成的原型与 C 定义 | 58 条一致 | 58 条一致 |
| 故意把 xsax_next 返回值改为 int | 严格 C 拒绝 | 严格 C 拒绝 |
| 普通独立 AOT | 19 份构建运行通过 | 19 份构建运行通过 |

前后分配顺序和平台文件操作不同，场景总数不要求机械相等；每个入口
都必须完成扫描，不能只选择对新代码有利的预算。旧版失败不是任意
非零退出：要求明确的回归断言诊断，不接受超时、崩溃或 sanitizer
错误冒充先红后绿。源码与工具指纹在对应执行阶段前后核对。

## 门禁与剩余阻断

Windows 最终完整报告有 346 项，前 345 项符合预期（含五个必须被
语义拒绝的私有入口），末项公开 `xml.sax.Reader` 正例仍失败。DOM 的
Node 和 ElementTree 的 Element 也另验失败，均为原 M9，不记作
运行成功或整包绿灯。公开类型还需先满足 M3 原生构造器安全条件，
不在包内增加不安全导出或第二套类型包装。

两门禁改为有界执行并保留失败命令、输出、原始退出码及输入指纹；
Windows 无输出编译器 raw 37 / 外层 1，以及 Linux raw 37 / 缺失
编译器 127 的真实入口控制通过。旧的“任何退出都删除现场”已移除。

首轮新 C 夹具错误地重复启用已开启的内存调试，导致 TCC 拒绝；现按
XRT 合同先检查 Enabled，保留原失败记录后完整复验。Linux 又发现
旧 XML 黄金文件的 CRLF/LF 误差，三文件规范为 LF 并加路径级 Git
属性；Windows 按规范化行尾比较的功能结果未变，Linux 再完整复验。
外围 Windows 旧版控制曾漏去原始 stdout 的 CRLF，修控制后只补
重放，没有修改产品来换绿灯。
