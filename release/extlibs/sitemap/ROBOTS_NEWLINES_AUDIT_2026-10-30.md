# robots 行尾与失败边界审查

## 缺陷与修复

`sitemap_robots.c` 的分行扫描原只识别 LF。合法的 CR 行尾会让后续
`Disallow` 被吞进代理名称或注释中，规则丢失，本应禁止的路径可能被
放行；混合行尾还可能错误合并组或丢失 Sitemap 声明。

[RFC 9309 §2.2](https://www.rfc-editor.org/rfc/rfc9309.html#section-2.2)
定义 CR、LF 和 CRLF 三种行尾。扫描现在同时在 CR/LF 处停止，CRLF
作为一个行尾消费，并在读取第二字节前检查长度。原分组、注释、BOM、
UTF-8、1MiB 限制、匹配算法、API/ABI 和所有权不变。
没有新增缓冲、复制或分配；仍为一次扫描，没有测吞吐，不声称零耗时。
不扩大为完整 RFC 9309 实现，百分号编码规范化等原排除项仍排除。

## 新覆盖

- C：五种行尾布局（LF、CR、CRLF、两种混合序列）× BOM 开关 ×
  最后行尾开关 × 两个解析入口，共40次。每次验证四组代理、两个
  Sitemap 声明与12组决策，分别调用零结尾和显式长度的判定入口。
- `_n` 输入来自精确长度的 CRT 分配块，不额外放 NUL；释放原输入后
  再检查拥有型结果。Linux ASan 可以检查末尾 CR 是否越界读取。
- 两个解析入口逐预算扫描至成功，共162次真实 OOM；检查错误分类、
  不返回半份对象及恢复，活动数/字节/非法释放/重复释放/UAF计数平衡。
- XLang：三种换行、BOM、注释、空行、不同代理组、源字符串改写后的
  结果寿命、MemoryError与恢复；JIT和独立程序均通过。
- 双语 `robots_policy` 同输入/断言/四行黄金输出，C GCC/TCC JIT/AOT
  与 XLang JIT/AOT 通过；原 C XML 全功能例继续通过独立 XML 检查。
- 十条 C 声明强制进入实际实现的严格语法编译；六条实际生成的外部
  声明与头文件核对。错改 parse 返回类型必须以类型冲突拒绝。
- 独立 XML 检查器同时接收两份相同但 URL 被破坏的输出时仍须拒绝，
  不只验证两个生成器打印相同内容。

## 实测

Windows默认门禁45项：前44项符合预期，含必须拒绝的ABI与XML黄金
负例；第45项原中央语言数组生成例仍因M1抛ValueError。107个输入/
工具指纹不变；五份正常独立程序通过。初次强制头文件检查因探针未
提前选择XML Reader依赖宏失败，已补测试命令的IO声明开关后完整重跑；
这不是库BUG，没有修改XML依赖或冻结XRT。

Linux原生文件系统完成同范围ASan/UBSan、JIT/AOT、双语黄金与独立
XML检查，随后同一原中央M1失败。104个复制源和三项工具前后相等。
两平台同一最终C测试对照旧源各26条断言红→0；旧源仅实际进入18个
OOM点，因为错误分行根本没创建应有的组，不能把这18算作新组的覆盖。
这是一处行扫描缺陷，不是26个独立BUG。

Windows静默GCC真实退出37，门禁保留raw37、外层失败1；Linux静默
工具37和不存在工具127均保留首因和现场。独立M1最小源两平台JIT/AOT
都先原生数组生成往返成功，再语言数组失败；没有修改原正例或预期。

`build/test/sitemap_guard_94fcecd3c1fc4b56a055a9549d2eb22e.report.json`，
Linux `/var/tmp/xlang-sitemap-newline-audit-ijcBBhSM`。
编译器、TCC、XML依赖、XRT均未修改，八个冻结发布物/单头库不变。
官网源生成到隔离目录核对，不部署；整包仍为M1，不能签收发布级。
