扩展库 / sharedmem

sharedmem

Windows/Linux 命名共享内存，字节安全的双语接口。

2026-11-02：Windows 61 阶段、Linux 60 阶段完整复验，保留 sanitizer、真实 C 子进程、错误首因、13 条实际生成原型及双语输出对照。新增快照范例在句柄退役后仍可使用读取结果；基础范例等三个顶层 AOT 的退出问题及私有构造器访问控制负例仍失败，本包不签收完整发布级。

API

入口用途
create(name, size) / open(name)创建或打开命名映射，创建不覆盖现有名称
SharedMemory.write/read通过 Buffer 读写原始字节，读取返回独立副本
writeText/readText按明确的 UTF-8 字节长度读写；读取返回独立 cstring，只复制一次
writeInt/readInt / zero小端有符号 64 位整数和清零

重复创建名称在 XLang 中抛 ValueError，打开不存在的名称抛 LookupError；C 侧分别保留 XERR_EXISTS 与 XERR_NOT_FOUND。

分配失败直接保留 XRT 原始首因，不重新构造消息。新增 30 组首因合同、3,367 组全帧小端记录、112 组非法范围、14 组快照生命周期及 64 MiB 上界检查；独立 Python 参照核对完整字节。测试数不代表并发原子性、长时耐久或零开销承诺。

xlang

import sharedmem
auto owner = sharedmem.create("demo_exchange", 128)
auto reader = sharedmem.open(owner.name)
owner.writeText(0, "hello")
println(reader.readText(0, 5))

C 与边界

examples/snapshots.xl 与 examples/snapshots_c.c 演示非对齐整数、内嵌 NUL 的 UTF-8、创建者先退役及读取快照跨所有句柄退役；五种执行形态在两平台按固定输出对照。C 公开头已补齐 xshm_write_text 声明，不要求调用方自行猜测签名。

头文件 include/sharedmem_native.h；C 调用方显式关闭句柄，xshm_read 的缓冲用 xrtBufferDestroy 释放，xshm_read_text 的文本用 xrtFree 释放。名称最长 128 UTF-8 字节，XLang 在进入 C 前拒绝内嵌 NUL；大小 1 至 64 MiB。没有内建进程间锁，应用须自行同步。POSIX 创建者关闭会 unlink；显式 unlink 后同名重建时，旧创建者不会误删新对象，但并发名称操作仍需同步。Windows 名称随最后句柄关闭而消失。Windows 与 Linux 包级门禁覆盖独立 C 子进程、分配故障、语言边界及双语范例；README 记录当前完整签收阻断。
