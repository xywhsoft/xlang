# PO 连续正文优化与验收

## 实现边界

`xgt_decode_po_string` 原对每个普通字节调用追加函数。现在用 CRT `memchr`
定位下一个反斜杠，整段普通正文只追加一次；转义仍走同一个既有分支。
传入范围来自已经定位闭引号的 C 字符串，范围内不会出现 NUL；外部
语言输入的 NUL 拒绝及数字转义的零字节拒绝均保持，未增加宽松入口。

不增加 API、模式或另一套解析器，PO/MO 格式、复数表达式及 ABI 不变。
仍有正文扫描、解析缓冲复制和独立目录值构造，借用/拥有查询合同不变；
这是减少逐字节调用和中间扩容，不是零复制或零分配。
未修改 XRT、TCC、编译器主线或 module manifest 的生产依赖。

## 正确性与所有权

新 `test/po_spans_c.c` 包含六种正文（ASCII、UTF-8、混合转义、密集
转义、十六/八进制 UTF-8、短片段）、13种长度和续行开关，共156份
目录。每份核对普通/上下文/复数查询；释放原输入后查询目录，再释放
目录检查拥有型结果。空译文的原文回退同样验证，不误认成空字符串。

四组逐预算扫描至成功，旧模型102个实际OOM、新模型98个，均零失败；
变化是减少分配，不是删除故障断言。检查 MemoryError、无部分目录及
活动数/字节/非法释放/重复释放/上下溢/UAF指标。新旧使用同一最终测试。
语言回归覆盖长中文正文、续行、结果跨目录释放及OOM，并进入coverage。
原畸形输入、转义、重复键、上下文、复数、MO与64MiB边界继续运行。

共享教学PO把“常规”拆成两个引号续行，原六行黄金输出不变；C/XL
范例继续读取同一文件，GNU msgfmt生成的MO与Python GNUTranslations
也核对了六个结果，避免只用本包自解析证明自身。

## 完整门禁

Windows PowerShell5.1默认59阶段、56个输入/工具指纹，全部通过，输入
变动0；七个真实生成原型和14条普通独立程序路径通过。初次新C测试
返回2，证明门禁把null参数表编码成一个空字符串实参；同一EXE在无
参数时通过、显式空串时返回2。只在本包Run入口将null正规化为空数组，
没有改公共工具或降低测试要求。PS5/PS7对实际Run的null/空数组/显式
空串三种调用均通过，随后重跑完整Windows门禁。

Linux原生文件系统快照通过完整默认门禁，含ASan/UBSan、旧新C/XL
JIT/AOT、十四条普通独立程序及GNU MO专项；另有一条外部MO的语言
AOT构建。55份复制源和四项工具前后相等。Linux验收结束后，仅更新
Windows专用Run的空参数处理和说明文档，Linux执行的实现/脚本/夹具未改。
八个冻结发布物/单头库不变；整包仍只承诺README的UTF-8 PO/MO子集。

## 性能及体积取舍

基准调用公开C解析入口、检查完整正文、释放目录；每个计时样本80次。
四模式分别为ASCII长正文、UTF-8正文、混合转义、密集转义；每组先预热。
GCC用相同`-O2`和共享XRT/plural对象，old/new/new/old两轮共十样本；
TCC直跑各五样本。新旧checksum相等，源码与工具运行中不变。
偶数样本中位数取中间两项平均，不用单一最快值。Linux在WSL2原生
文件系统运行；不同平台/编译器的绝对耗时不可直接横比。

下表为旧/新中位耗时比，大于1为本负载变快：

| 平台与编译器 | ASCII | UTF-8 | 混合转义 | 密集转义 |
| --- | ---: | ---: | ---: | ---: |
| Windows GCC | 2.58 | 1.83 | 1.14 | 1.11 |
| Windows TCC | 2.45 | 2.00 | 1.12 | 1.18 |
| Linux/WSL2 GCC | 3.41 | 2.36 | 1.10 | 1.01 |
| Linux/WSL2 TCC | 2.54 | 1.94 | 0.95 | 0.95 |

Linux TCC两个转义样本本轮约慢5%，不隐瞒、不宣称所有负载都更快；
这是本机固定负载计时，不是统计置信区间或线上吞吐保证。最初尝试
逐字扫描连续片段的版本已撤回，最终使用更简单的CRT memchr。
未为少见样本增加另一条运行时解析/回退路径。

独立native对象的`.text`：Windows GCC为8288→8320（+32B），Linux
GCC为8151→8215（+64B）；不是最终EXE/DLL体积。长正文收益与少量
代码增长、特定转义负载取舍均保留在原始数据，不冒称整个xlang变小。
