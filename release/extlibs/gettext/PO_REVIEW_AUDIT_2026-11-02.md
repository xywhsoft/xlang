# PO 目录头与上下文审核边界

## 根因与唯一修复

`xgt_po_flush` 先前只用 `msgid` 的长度判断是否跳过 fuzzy 或空单数
译文，误把带 `msgctxt` 的空消息也当作目录头。实测会返回尚未审核的
译文，且被跳过的空译文提前占键，后续已审核条目反而报重复。

目录头现在严格要求「没有上下文且 msgid 为空」；`msgctxt ""` 也算
有上下文。只在已有提交分支的条件中增加 `have_context`，不增加
解析器、API、ABI、模式、兼容入口或包依赖。没有修改编译器、TCC、
XRT、IDE 主线或第三方源码。

真正目录头仍可带 fuzzy 标志，用于读取复数规则。普通消息（含空 ID）
的 fuzzy 或空单数译文不占键；实际接纳的重复键仍拒绝。格式与 UTF-8
验证仍先于跳过操作，不能用 fuzzy 隐藏坏输入。

## 同一夹具前后对照

新增 `test/po_review_c.c` 共147项：72个消息组合、72个重复键组合、
3个坏输入/恢复组合。消息组合遍历无上下文/空上下文/非空上下文、
空/非空 ID、四种审核/空译文状态和三种相邻/空行形式。

同一最终 C 夹具在旧实现为53次断言失败，在新实现为659次检查、零失败。
四类存储/查询验证之外，检查拥有结果跨目录释放、七种内存指标、
fuzzy 真目录头的三复数形式及旧错误后的恢复。
24个实际分配失败点、25个预算一直扫描到成功；每个失败均为
`XERR_MEMORY`，无部分目录或内存失衡。旧实现13个故障预算后提前走入
重复键错误，因此不能把24对13解释成正常有效输入的分配回退。

`test/po_review.xl` 直接覆盖24种状态及其重复键对，并验证语言字符串
在目录释放后仍有效。没有为了通过测试绕开全局或私有主线限制。
包 coverage 与 Windows/Linux 门禁均加入新测试。

## 双语与独立格式对照

扩充既有 `test/po_layout.po` 与 `examples/layout.xl/layout_c.c`，
现在核对九行 `layout.expected.txt`：原六种查询，以及空上下文的空
消息、fuzzy 空标签、未翻译空标签。空回退打印为 `[]`，不改变 API。

Linux 实际用 GNU msgfmt 0.23.2 编译该 PO；C sanitizer、XLang JIT、
两种语言的独立 AOT 读取 MO，均与原 PO 九行结果一致。另由 Python
标准库 `GNUTranslations` 独立核对相同九个查询，未复用包内解析器。
这符合 [GNU 对空上下文与无上下文的区分](https://www.gnu.org/software/gettext/manual/html_node/Entries-with-Context.html)。
重复 PO 条目可在被本包跳过后复用键，是本包已声明的目录合同；
没有用它声称 GNU msgfmt 接受重复 PO 源条目。

## 实际门禁

- Windows PowerShell5.1：默认67阶段全部通过，66个输入/工具指纹不变；
  严格 GCC、七个真实生成原型、C/TCC 及 XLang JIT 和16条普通 AOT 路径。
- Linux：独立普通文件复制到原生可执行 `/run` tmpfs；62份冻结文件
  与主目录原始字节相等且前后不变。完整 ASan/UBSan/泄漏检测、旧新边界、
  七原型、16条普通 AOT、另一条 GNU 专项 AOT 与双语黄金输出均通过。
  原始日志和指纹已导回主工作区，不依赖临时 RAM 目录永久存在。
- 第一次完整门禁在旧基准的已移除 `xrtClock` 处真实失败。包内可选
  基准现直接用 `xrtTimer()` 单调秒数换算微秒，两平台实际 `--bench`
  各生成20条有效记录；不保留旧符号或新增计时封装。

本轮没有为正确性修复宣称吞吐提升。相同 GCC `-O2` 及同平台头文件下，
仅 native 对象 text：Windows10108→10172（+64B），Linux10557→10525
（-32B），data/bss均不变，不等于整个程序体积变化。新增条件不引入
额外正文扫描、复制或分配；目录解析/构造和 XLang 独立结果仍有既有开销。

## 交付边界

本轮是100包长期任务中的单包修复，不是所有扩展库或整个语言发布签收。
IDE 命令目录候选刷新、严格绑定检查、官网页生成和最终来源指纹另见
根目录 `docs/reports/extlib-gettext-review-20261102.json`。校验不通过的
候选不安装，不修改主线发布物或伪造绑定来换取绿灯。
