扩展库 / ini

ini

读取、修改和写入 UTF-8 INI 配置，保留节与键的顺序、注释和多行值。

版本 1.0.0 · C / xlang · 无扩展库依赖

快速开始

import ini

auto config = ini.parse("[server]\nport = 8080\n")
config.set("server", "port", "9090")
assert config.getInt("server", "port") == 9090
println(config.stringify())

完整的 C/XLang 对照范例还演示 create、save、load：在独占临时目录中保存配置并读回核对，运行结束即清理。Windows 严格 GCC 与 TCC、Linux ASan/UBSan 的输出均和 XLang 对照。

包内 examples/profiles.xl / profiles_c.c 另成对演示部署配置覆盖、多行值和读取时插值。可直接 xl run，不需要服务或数据文件；写回后可重新按默认严格模式读取。

插值的 ${.scheme} 可读取全局键；首个点分隔节名与键名，其余点保留为键的一部分，如 ${s.a.b} 读取 s 节的 a.b。空键引用报 ConfigError，空值本身合法；缺键、循环与真正的内存失败保持各自错误分类。

接口

入口用途
create / parse / load创建空配置、解析文本或加载 UTF-8 路径。
Config.get / getOr / getInt / getFloat / getBool读取值并按需转换类型；get 直接接管原生分配并返回普通 string，getOr 提供默认值；getInt 严格解析完整十进制值，getFloat 固定点号十进制、不受区域设置影响；失败抛出 ConfigError。
Config.set / remove / removeSection修改键或节。
Config.sectionNames / keys / has / hasSection枚举和查询节、键。
Config.stringify / save直接接管原生文本并返回普通 string，或原子保存到文件；无法无损表示的节名、键名或值会明确报错，不会静默改变数据；写入失败不截断旧文件。
Config.errorCode / errorLine / errorColumn / errorOffset读取最近一次原生操作的错误信息；非法 UTF-8 指向首个错误字节，偏移包含 BOM，首行列号不计 BOM。

可设置大小写敏感、重复键检查、插值和资源限额。${key}、${section.key} 在启用插值时生效。parse(string) 直接传入 UTF-8 数据及字节长度，不另建 XLang Buffer 副本；原生读取器在复制正文前检查输入限额并拒绝内嵌 NUL。set() 可以保留内存值；写出时若值有首尾空白、尾随换行或注释形态的续行等无法无损表示的内容，C 端报 FORMAT，XLang 抛 ConfigError。全局节先于具名节写出。C 端包含 extlibs/ini/include/xrt_ini.h，解析结果由 xrtIniDestroy 释放；xrtIniGet 的结果由调用方用 xrtFree 释放。C 选项须先初始化，顶层与内嵌资源限额的版本和结构长度均会校验，失配报 ARGUMENT。拥有型 Reader/Writer 在退出时关闭，对象与 XRT 错误槽同时保留已有首因；正文成功但关闭失败时区分 MEMORY/IO，借用型流由调用方关闭。

C 配置的顶层及资源限额保留字段必须为零；非零配置在 create/parse 入口报告 ARGUMENT。iMaxEntries 限制所有节的键总数，删除键后恢复额度；不适用的压缩倍率与 iFlags 必须为零，显式设置会报 ARGUMENT。

strictDuplicates=false 时后一次赋值替换旧值，保留键的原顺序和拼写，缩进续行跟随本次更新，不能污染表尾的其他键。默认严格模式仍拒绝重复。首个全局键自身含 U+FEFF 时，写回会按需加一个空行，避免把键的一部分当作文件 BOM；该字节计入输出预算。空键/空节名报 FORMAT，真正的长度超限报 LIMIT。

maxOutput 同时限制拥有型 get 的结果和序列化文本的 UTF-8 字节数，0 表示不限。插值前缀、引用正文与后缀共用累计预算，每次追加/扩容前检查，不先构造超限结果才拒绝。没有插值表达式的值直接按长度复制，不创建插值栈和缓冲。类型化读取复用此取值预算，借用视图 xrtIniGetRaw 不复制或截断存储值；结果限额不是进程总内存上限。
